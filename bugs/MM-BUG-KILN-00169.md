says the file is generated by
`tools/ferrosintesis-samples/gen_crate_lib.py`. That file is only partly
generated: its B1-specific tail-size pin and strict terminal-`b1t ` validator
live at
`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-235149\crates\ferrosintesis-samples-b1-upright\src\lib.rs:238`.

The advertised generator reconstructs the whole Rust file at
`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-235149\tools\ferrosintesis-samples\gen_crate_lib.py:77`
and overwrites it at line 201. Its emitted tests at lines 117–160 cover only

generated marker therefore silently deletes validation of:

- exactly one terminal `b1t ` chunk;
- tail version, rate divisor, reserved field, and entry frame;
- source-frame/payload-length agreement;
- the aggregate `EXPECTED_TAIL_BYTES` pin.

The public regeneration recipes at
`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-235149\crates\ferrosintesis-samples-b1-upright\README.md:36`
and
`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-235149\crates\ferrosintesis-samples-b1-upright\PROVENANCE.md:103`
name only `prepare.py --only=b1upright`. That path rebakes the WAVs but does not
invoke a Rust inventory updater or document how to re-pin
`EXPECTED_BYTES`/`EXPECTED_TAIL_BYTES`. The existing safe region-only tool,
`regen_samples_table.py`, is not named by this crate and does not update those
canaries.

**Expected.** The regeneration workflow named by a generated-file marker
preserves every load-bearing, bank-specific validation and deliberately updates
all derived inventory/canary values.

**Actual.** The named generator erases the semantic tail oracle. The documented
bake path preserves the oracle but leaves legitimate size changes red with no
documented re-pin step.

Current assets are not shown corrupt. The defect is the non-repeatable and
misleading regeneration workflow.

## Fix

Mark only the inventory table as generated. Provide a B1-aware updater, or
extend the region-only updater, so it preserves the bespoke tests and
deliberately reports/updates both aggregate size pins after a verified full-bank
bake. Document the complete bake/update sequence and add a negative regression
proving regeneration retains the `b1_tail` assertions.

As part of correcting the stale generated header, change its nonexistent
`NOTICE` pointer at `src/lib.rs:5` to the packaged `LICENSE-CC0`.
