# 2026.06.26 - HLD - Repository layout and album conventions

This repo (`midi-music`) is a collection of **original, generative MIDI albums**,
each produced by a different language model. This note captures the layout and
the conventions so future additions slot in cleanly. It is descriptive of what
exists today, not a mandate for new structure.

## Top level: one directory per model

Each top-level directory is named for the model that generated its music:

- `gpt5-5/` — contains **two** albums, each in its own title subfolder
  (`Hours After Rain/`, `The Long Turning/`).
- `opus4-8/` — one album at the directory root, plus a nested side-piece
  `amarok/` (`Riverwake`).
- `gpt5-3-spark/` — one album, "The Spark", at the directory root *(added here)*.

So a model directory holds **one or more albums**. An album lives either at the
model-directory root or in a named subfolder — both forms are in use.

## Album anatomy

An album is this self-contained bundle:

| Path | Role |
|------|------|
| `engine.py` | Composition engine + MIDI writer + manifest writer + verifier. Pure Python standard library — no third-party dependencies. |
| `build.py` | Thin entry point: `python build.py` rebuilds, `python build.py --verify` checks the rendered MIDI. |
| `tracks/NN_title.py` | One entry point per track (numbered), delegating to `engine.py`. |
| `midi/NN - Title.mid` | Rendered MIDI output, **committed** to the repo. Named `NN - Title.mid`. |
| `album_manifest.json` | Machine-readable album metadata (tracks, durations, roles). |
| `ALBUM.md` | Human track notes: per-track duration, mood, and role. |
| `README.md` | Overview + regenerate/verify instructions. |

## Conventions

- **Rendered `.mid` files are committed**, not just the generators. They are
  reproducible from source, but tracking them lets anyone listen without running
  Python. Every album in the repo follows this.
- **Regenerate / verify** from inside an album directory:
  `python build.py` / `python build.py --verify`. Verification reports per-track
  duration, track count, and note count, then a total runtime.
- **No runtime dependencies** — engines use only the standard library, so a bare
  `python` interpreter is enough.
- **Ignored artifacts** (`.gitignore`): build/env dirs (`target/ bin/ obj/
  venv/ .venv/ env/`), scratch files (`*.tmp *.log`), and Python caches
  (`__pycache__/ *.pyc` — generated whenever `build.py` runs).

## Adding a new album

1. Create `<model-id>/[<album title>/]` with the album bundle above.
2. Generate and **verify** (`python build.py --verify`) — confirm every track
   renders and the MIDI headers are valid before committing.
3. Commit the whole album bundle as one atomic commit (sources + `.mid` +
   manifest + docs).
