## 1. Intent (one line)

Give GM synth-lead programs **80–87** a dedicated lead voice — fast
velocity-tracked attack, brighter velocity-tracked filter, a band-limited
**square/pulse** oscillator for the square-lead class, plus **CC1 mod-wheel
vibrato** and **CC68 legato** — replacing the current `pad()` fallthrough,
while leaving pads 88–95 and every non-lead render **byte-identical**.

## 2. Problem (as-built)

`voices::make` routes `80..=95 => pad(program)` (`voices.rs:2044`). `pad()`
branches only on `program == 95` (`voices.rs:1625`), so **all eight leads
render byte-identically to the 88–94 warm pad**: five detuned polyBLEP saws,
Q-0.7 lowpass swept 0.13 Hz over 1100–1556 Hz, ADSR **0.6 s attack / 1.4 s
release**, no vibrato, amp 0.42. Consequences:

- Every lead note swells for a fixed 0.6 s regardless of velocity (`pad()`
  skips `vel_attack`); fast lines never reach level — the classic pad-attack tell.
- GM 80 "square lead" plays **saws** — no square/pulse oscillator exists in the
  crate (`BlepSaw` is the only band-limited osc, `dsp.rs:66`).
- CC1 mod-wheel vibrato is inert on 80–95 (`vibrato_family`, `engine.rs:61`);
  CC68 legato silently re-attacks (`SawStack` has no `legato_to`, `voices.rs:36`).
- Default 0.45 chorus send — pad wash — on what should be a focused lead
  (`fx_profile`, `engine.rs:263`).

**This bites a shipped album:** saw-lead **81** is used on two channels each by
*Sub Rosa* (`conductor.py:74,83`) and *Winter Guests* (`conductor.py:95,105`).
Programs 80 and 82–87 are unused by any committed album (verified in the gap
audit's usage census).

## 3. Scope & non-goals

**In scope (this pass):**
1. A `lead(program, key, vel, sr, seed) -> SawStack` constructor: fast
   velocity-tracked attack, short release, velocity-tracked filter cutoff, modest
   detune, no always-on vibrato.
2. A band-limited **`BlepPulse`** oscillator (`dsp.rs`) and a `LayerOsc` enum so a
   `SawStack` layer can be a saw or a pulse. GM 80 (and 82 calliope) use pulse.
3. Per-program differentiation of 80–87 via the cheap knobs the voice already
   exposes (waveform, oscillator count, detune, cutoff, breath) — so leads are not
   eight clones (the sin we are fixing on pads).
4. **CC1 vibrato**: add `80..=87` to `vibrato_family` (`engine.rs:63`) — the
   engine's existing per-block vibrato pushes through `SawStack::set_pitch`
   (`voices.rs:1534`), which already works.
5. **CC68 legato**: implement `SawStack::legato_to` (retune `base_f` in place,
   keep the running envelope) — lights up the slur the engine already wires at
   `engine.rs:699`.
6. `fx_profile`: split `80..=87 => (0.15, 0.25)` (focused, with the delayed-lead
   echo) from `88..=95 => (0.45, 0.0)` (pads, unchanged).
7. Dispatch: `80..=87 => lead(program)`, `88..=95 => pad(program)`.

**Non-goals (deferred to reqs — Wave C backlog):**
- Bespoke per-program DSP: charang (84) drive, voice-lead (85) formant bank,
  **fifths (86) parallel-fifth layer**, **bass+lead (87) sub-octave layer**. This
  pass approximates 86/87 as plain saw leads (flagged; their defining interval is a
  follow-up req). GM 80/82 get the genuine pulse timbre.
- Per-note **filter envelope** (cutoff sweep). Velocity-static cutoff suffices
  for "harder = brighter"; the sweep LFO stays a pad feature.
- True **mono / last-note priority** voice-stealing (an engine change). Leads stay
  polyphonic; glide overlap is mitigated by the short release, and slurs use CC68.
- Any change to pads 88–95, strings/choir 48–54, or other families' *renders*.
  (`legato_to` lands on the shared `SawStack`, but it is opt-in — see §6.)

## 4. Approach & file impact

### 4.1 `dsp.rs` — band-limited pulse
- Extract the existing `BlepSaw::polyblep` associated fn to a free
  `fn polyblep(t, dt) -> f32` (module-private) so both oscillators share it — no
  duplication. `BlepSaw::next` calls the free fn; **bit-identical** output.
- Add `pub struct BlepPulse { phase, inc, duty }` with
  `new(freq, sr, phase, duty)`, `set_freq`, `next`. A pulse is a square wave with
  polyBLEP corrections at **both** edges (the wrap at 0 and the crossing at `duty`):
  ```
  let mut v = if self.phase < self.duty { 1.0 } else { -1.0 };
  v += polyblep(self.phase, self.inc);
  v -= polyblep((self.phase - self.duty).rem_euclid(1.0), self.inc);
  ```
  `duty = 0.5` → a true square (even harmonics ≈ 0). One RNG draw for phase, same
  as `BlepSaw`, so a pulse layer is deterministic and draws identically.

### 4.2 `voices.rs` — lead voice on the `SawStack` engine
- `Layer.osc: BlepSaw` (`voices.rs:1422`) → `Layer.osc: LayerOsc`, a two-arm enum
  `{ Saw(BlepSaw), Pulse(BlepPulse) }` with `#[inline]` `next`/`set_freq` that
  delegate. **The `Saw` arm calls identical `BlepSaw` code — no numeric change.**
- `SawStack::new(...)` (`voices.rs:1397`) keeps its exact body and RNG draw order,
  but delegates to a new `new_wave(..., wave: Wave)` with the `wave` param inserted;
  `new()` passes `Wave::Saw`. Existing callers (`strings`, `choir`, `pad`×2) are
  **unchanged** → bit-identical. `new_wave` builds `LayerOsc::Saw`/`Pulse` per `wave`,
  drawing the same single `rng.white()` per layer for phase.
- `fn lead(program, key, vel, sr, seed) -> SawStack`: reads a `const LEADS: [LeadSpec; 8]`
  table indexed by `program - 80`; builds via `new_wave`. Velocity-tracked cutoff
  `spec.cutoff * (0.55 + 0.45 * vel_amp(vel))`; `Adsr::new(vel_attack(0.010, vel),
  0.06, 0.82, 0.10, sr)`; `vib = (0,0,0)`; `sweep = None`; amp 0.50.
  (Release 0.10 s, not 0.16 — review R1: `Adsr` release is a plain exponential, so
  10 % floor = `release · ln 10`; 0.16 s could never satisfy the release oracle.)
- **`legato_to` is gated to lead instances (external review X2).** `SawStack` gains a
  `lead_legato: bool` field (`false` in `new_wave`; only `lead()` sets it `true`). Added
  to the *existing* `impl Voice for SawStack` block (`voices.rs:1496` — Rust forbids a
  second impl):
  `fn legato_to(&mut self, key, _vel) -> bool { if !self.lead_legato { return false; }
  self.base_f = key_freq(key); true }`
  — retune in place; the layers pick up `base_f` on the next `control_tick`
  (`voices.rs:1465`); the envelope is untouched (no re-attack). Strings/choir/pad return
  `false` exactly as today → the engine re-attacks, **literally unchanged** (not merely
  corpus-safe): byte-identity no longer depends on the CC68 census.
- `LeadSpec { wave, n_osc, detune, cutoff, q, breath }` (Q added — review R5).
  Draft table:

  | prog | name        | wave        | n_osc | detune | cutoff | Q   | breath |
  |------|-------------|-------------|-------|--------|--------|-----|--------|
  | 80   | Square Lead | Pulse(0.5)  | 2     | 0.004  | 3400   | 1.0 | 0.0    |
  | 81   | Saw Lead    | Saw         | 3     | 0.006  | 3000   | 1.1 | 0.0    |
  | 82   | Calliope    | Pulse(0.5)  | 1     | 0.000  | 2200   | 0.8 | 0.015  |
  | 83   | Chiff       | Saw         | 2     | 0.005  | 2800   | 1.0 | 0.05   |
  | 84   | Charang     | Saw         | 3     | 0.012  | 4200   | 1.4 | 0.0    |
  | 85   | Voice Lead  | Saw         | 3     | 0.008  | 2500   | 1.2 | 0.02   |
  | 86   | Fifths*     | Saw         | 2     | 0.006  | 3000   | 1.1 | 0.0    |
  | 87   | Bass+Lead*  | Saw         | 2     | 0.005  | 2400   | 1.0 | 0.0    |

  *86/87 lack their defining interval this pass (deferred req).

- **Exact RNG draw order in `new_wave`** (review R2 — load-bearing for byte-identity):
  the per-layer closure must draw `rng.white()` in the same order and count as today
  (`voices.rs:1422-1428`): **osc phase → `vib_phase` → `vib_rate`**, then `sweep_phase`
  after the loop. Draw the phase once *before* the wave match so both arms consume it
  identically:
  ```
  let ph = rng.white() * 0.5 + 0.5;                 // was BlepSaw::new(..)'s 3rd arg
  let osc = match wave {
      Wave::Saw       => LayerOsc::Saw(BlepSaw::new(f_i, sr, ph)),
      Wave::Pulse(du) => LayerOsc::Pulse(BlepPulse::new(f_i, sr, ph, du)),
  };
  Layer { osc, ratio, vib_phase: rng.white()*PI, vib_rate: vib.0*(1.0+0.15*rng.white()), drift }
  ```
  `Drift::new` takes `seed ^ const` and draws nothing from the shared `rng`.

## 5. Opt-in / byte-identical gate

The only albums whose renders change are those using programs 80–87 = **program
81** (*Sub Rosa*, *Winter Guests*) — an **intended** change (their saw-leads stop
sounding like pads), accepted under Arthur's "dev sandbox / no back-compat / no
feature flags" steer. Everything else is byte-identical *by construction*:

- `pad()` is untouched; `88..=95 => pad(program)` is unchanged → pads (89, 95, used
  by Hollow Hill / Signal Fire / Winter Guests) render identically.
- `SawStack::new`, `strings`, `choir` keep their exact bodies and RNG draw order;
  the `LayerOsc::Saw` arm is numerically identical to today's `BlepSaw`.
- `legato_to` is gated by the `lead_legato` flag (§4.2), so strings/choir/pad return
  `false` and the engine re-attacks exactly as today — byte-identity is **literal**, not
  corpus-dependent (external review X2). (Corroboration: no committed album authors CC68
  on a SawStack channel anyway — gap audit + in-house census.)
- `vibrato_family` adds only `80..=87`; the CC1 branch calls `set_pitch(bend)` with
  `bend == 1.0` when no CC1 is authored — idempotent, as it already is for guitars.
- `polyblep` extraction is a pure code move (same math).

**Proof:** build a baseline binary from `origin/main` in a scratch `git worktree add
HEAD`, render (a) the committed golden-fixture song and (b) a short MIDI exercising
programs 88–95, and `cmp` both against the new binary → byte-identical. The existing
`cargo test` golden/canary suite must stay green.

## 6. Acceptance criteria (machine-checkable oracles — this machine has no ears)

All in `voices.rs`/`engine.rs`/`dsp.rs` test modules, using `testutil::centroid`,
`testutil::peak_locate`, and the engine `render(&song, &test_opts(sr))` harness.

   Envelope is measured as a **short-window RMS** (5–10 ms, like `testutil` t60
   helpers, `testutil.rs:100`), not raw sample peaks — oscillator phase moves raw peaks
   (external review X5).
1. **Fast attack (routing + character) — differential (review R2):** the RMS envelope
   of `lead(81, key, 100)` reaches 90 % of its own plateau in **< 50 ms**, and
   `pad(89, key, 100)` takes **> 5 × the lead's t90** (and > 150 ms absolute). Absolute
   pad thresholds near 300 ms false-fail — `pad(89)` t90 ≈ 283 ms — so the guard is the
   ratio.
2. **Short release (review R1):** after `note_off`, the RMS envelope of `lead(81)` falls
   below 10 % of plateau within **< 300 ms** (release 0.10 s ⇒ ≈ 210 ms from sustain)
   while `pad(89)` is still above 10 % at 300 ms — confirms the lead envelope.
3. **Velocity → brightness:** `centroid(lead(81, key, 120)) /
   centroid(lead(81, key, 40)) > 1.2`.
4. **Square nulls even harmonics — split (review R4 + external review X4):**
   - (a) **raw `BlepPulse`** (dsp.rs test): a duty-0.5 pulse at ~220 Hz has H2/H1
     Goertzel magnitude near zero (≪ a `BlepSaw`'s ~0.5) and mean sample ≈ 0 (no DC).
     Isolates the oscillator from the lead's detune/filter voicing.
   - (b) **routing differential**: over a ≥ 1 s window (spans the detune beat), the
     H2/H1 ratio of `lead(80)` (pulse) is markedly below `lead(81)` (saw) at key 57
     (2f ≈ 440 Hz, well under the ~2.9 kHz cutoff) — proves 80 routes to the pulse.
     Threshold calibrated from observed values (target ≲ 0.35 ×).
5. **CC1 vibrato on leads (review R3):** mirror `cc1_mod_wheel_adds_vibrato`
   (`engine.rs:1712`) with `prog 81`: CC1=127 pitch spread **> 2 ×** CC1=0. The
   detuned stack beats, so `cycle_freq_spread` (zero-crossing) may inflate the CC1=0
   baseline — calibrate thresholds from observed numbers, and if the baseline is
   noisy, track pitch with sliding `peak_locate` windows instead (repo lesson:
   zero-crossing counters lie on bright voices).
6. **CC68 legato slur — engine-level (external review X3):** render through the engine
   with `prog 81`, `CC68 ≥ 64`, two NoteOns on one channel (mirror the guitar legato
   tests). Assert exactly **one voice spawned**, the pitch moves to the second key
   (`peak_locate`), and the RMS across the boundary does **not** collapse (no
   re-attack). Plus assert a `prog 48` (strings) channel with the same CC68 events
   **does** spawn two voices (re-attacks) — guards the `lead_legato` gate (X2).
7. **Byte-identity is regression-guarded by an EXACT check (review R6 + external review
   X1):** the repo's `reference_song` golden is only RMS ±2.5 dB / centroid ±20 %
   tolerance (`testutil.rs:483`) — **not** bit-exact — so a tolerance canary would not
   catch drift. Instead:
   - (a) **`LayerOsc::Saw ≡ BlepSaw`** unit test: a `LayerOsc::Saw(BlepSaw::new(f,sr,ph))`
     emits a bit-identical sample sequence to a bare `BlepSaw::new(f,sr,ph)` over N
     samples — pins the delegation-identity claim at the source.
   - (b) **Exact `to_bits()` hash** test over solo renders of `pad(95)`, `choir(52)`,
     `strings(48)` — the SawStack families this refactor touches. The pinned hashes are
     captured from the **baseline** binary (`origin/main`) during validation, so the
     committed test is a true baseline guard, not a self-referential pin.
   - (c) One-time **baseline-binary `cmp`** on a pads/choir/strings render (validation
     step, journalled).
8. **Leads still bend:** a `lead(81)` note driven by `set_pitch(2^(2/12))` settles at
   the +2-semitone pitch (regression on the shared `set_pitch`).

Criteria 1–6, 7(a), 7(b), 8 become committed unit tests; 7(c) is a validation step
recorded in the journal. Threshold numbers in 4 and 5 are **calibrated by observation**
at implementation (self-verify, then pin with margin).

## 7. Decision log

- **Reuse `SawStack`, no new Voice type.** Leads need the same osc-ensemble +
  filter + envelope + `set_pitch`/`set_vowel` machinery; a lead is a `SawStack` with
  lead-shaped parameters plus pulse-capable layers. Simpler than a parallel voice.
- **`LayerOsc` enum over "two phase-offset saws" for the square.** A dedicated
  `BlepPulse` is clearer and cheaper than faking a pulse from two `BlepSaw`s, and
  isolates the change from the byte-identical saw path.
- **`new` delegates to `new_wave(Wave::Saw)`** so existing callers are untouched —
  byte-identical is structural, not just tested.
- **Pulse only where it matters (80, 82).** 81 — the one used lead — is a saw, so
  the pulse is not on the critical path; it addresses the flagged "square lead plays
  saws" tell for the (unused) namesake program.
- **CC1 via `vibrato_family`, not a new mechanism.** The opt-in, engine-level LFO
  that guitars/winds already use is exactly right; one range added.
- **`legato_to` on the shared `SawStack`, gated by CC68 authoring.** Cross-family
  benefit at zero cost to existing renders (no album authors CC68 on these channels).
- **86/87 defining intervals deferred.** Building per-layer fixed-ratio support is
  scope the used programs don't need; captured as a req rather than half-built here.
- **No mono mode / filter envelope.** Not required to fix "leads sound like pads";
  would add engine state and voice machinery against the lean brief.

## 8. Residual risks

- **`LayerOsc` enum perturbing the saw path.** Mitigated: the `Saw` arm is the same
  `BlepSaw` code and RNG order; §5 `cmp` is the backstop.
- **86/87 knowingly incomplete.** Accepted: unused programs, flagged, req filed.
- **Lead voicing is set by construction, not ear.** All eight balanced by the
  brightness/attack oracles and constant tables; a human listen is the real judge
  (noted, per README convention).
