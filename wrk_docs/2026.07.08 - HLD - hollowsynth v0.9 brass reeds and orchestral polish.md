# HLD — hollowsynth v0.9: brass, reeds & orchestral polish

Date: 2026.07.08 · Baseline: hollowsynth **v0.8.1** (integrated trunk) ·
Target: **v0.9.0** · Status: **design complete, awaiting Arthur's forks (§8)**

This is the **integration authority** for the v0.9 build. It carries the
cross-cutting decisions and the phase plan; the per-family depth lives in seven
companion sections (§10). Where a companion conflicts with the reconciliation in
§4, **§4 wins** — the companions were designed in parallel and three of them
predate the collision resolution.

---

## 1. Summary & recommendation

hollowsynth has a **17-program hole**: GM programs 55–71 (orchestra hit, all
brass, all reeds/saxes) have no voice and fall through to a plucked steel-string
guitar (`voices::make`, `voices.rs:2015`+ `_ =>` arm). A held trumpet or oboe
note measured a sustain ratio of **0.00–0.01** — it evaporates like a pluck. The
roadmap also asks for polish on four families that already work: string
ensemble, solo bowed strings, choir, and drums.

**Recommendation — build v0.9 as one coordinated release, in this order:**
Phase 0 (test scaffolding) → **drums** (independent, own seam) →
**engine55 + brass + reeds + orchestra-hit** (fills the hole) →
**strings + choir** (shared `SawStack`, must co-land) → **bowed**. One
`0.8.1 → 0.9.0` minor bump at finalize. The brass/reed engine is the
highest-impact block and every DSP primitive it needs already exists.

**Two things are genuinely Arthur's call (§8), not the design's:**
1. **Strings ST1** (envelope-coupled brightness on the heavily-used programs
   48/49) is the one max-blast-radius change: default it (re-render six albums
   within measured bounds) or gate it. The design recommends default via a
   two-stage landing but ships a byte-identical floor either way.
2. **Whether `The Iron Tide` is re-rendered** at all — the brass voices for
   French Horn (60) and Brass Section (61) change that one committed file
   regardless of the strings decision.

Everything else is opt-in-safe by construction: it engages only on a channel
that authors a specific control, proven by rendering every committed album
byte-identical against a v0.8.1 baseline binary.

## 4. Cross-section reconciliation (authoritative)

The seven sections were designed in parallel. A completeness critic then found
five places where they touch shared state incompatibly. These are resolved here;
the resolutions **override** any conflicting companion text.

### 4.1 The `SawStack` collision — one unified struct (implementation-blocking)

**Problem.** Strings (48–51) and choir (52–54) are both `SawStack` presets and
both restructure the *same* `SawStack`/`Layer` (`voices.rs:1357–1393`) and
`SawStack::new` (`voices.rs:1395`+). They contradict directly: strings' ST2
`set_vib` writes a **stack-level** `self.vib_depth`, while choir's CH-3
**removes** stack `vib_depth` (`voices.rs:1384`) and moves depth **into
`Layer`**. As written, one deletes the field the other writes. They also both
grow the ctor and rewrite the layer-spread loop. They cannot both land unmodified.

**Resolution — vibrato depth moves to `Layer` (choir's location wins); one
combined field set; one ctor.**

*Unified `Layer`* (`voices.rs:1357`) — v0.8.1 `{osc, ratio, vib_phase, vib_rate,
drift}` plus:
```rust
gain: f32,        // CH-2 register/section weight; v1 = 1.0 (×1.0 is bit-exact)
vib_depth: f32,   // was stack-level; v1 = old stack vib.1 (0.004 choir / 0.003 strings)
vib_delay: u32,   // CH-3 per-layer onset; v1 = old global delay
vib_ramp_s: f32,  // CH-3 per-layer ramp; v1 = 1.0
```

*Unified `SawStack`* (`voices.rs:1378`) — v0.8.1 fields **minus** `vib_depth`,
plus:
```rust
lp_base: f32, lp_q: f32, lp_cur: f32,   // ST1 envelope-brightness filter state
env_bright: Option<EnvBright>,          // ST1; None for choir/pad
last_env: f32,                          // ST1 bow-pressure proxy
ext: Option<ChoirExt>,                  // choir v2; None for strings/pad/choir-v1
```

*`set_vib` (trait method, defaulted no-op).* `SawStack` implements it by writing
**every layer** uniformly: `for l in &mut self.layers { l.vib_depth = depth; }`.
This serves strings ST2 (section vibrato = every player deepens their own,
decorrelation comes from the existing per-layer rate/phase jitter, not depth
variance). It is **only ever called on 48–51** — choir stays out of
`vibrato_family`, so choir voices never receive `set_vib`. No conflict.

*One ctor.* `SawStack::new` grows from **14 → 16** args by adding
`env_bright: Option<EnvBright>` and `sub_layers: usize`; it always sets
`ext = None` internally. Choir v2 is a **separate factory** `choir_v2(...)` that
builds `SawStack` directly with `ext = Some(ChoirExt{..})` and per-section layer
draws. So `voices::make` → `choir()`/`strings()`/`pad()` → `new` (ext None, v1);
the engine's gated spawn → `choir_v2` (ext Some, v2). This matches both
companions: strings' "14→16" count and choir's "make always builds v1".

**Closing the ST1 ctor-init gap** (the strings residual). `control_tick` reads
`self.lp_base`/`self.lp_q`, but these **cannot** be recovered from the passed
`StackFilter::Lp(Biquad)` — `Biquad` exposes coefficients, not cutoff/Q
(`dsp.rs`). The caller `strings()` already knows them (it just built the filter).
So `env_bright` carries them:
```rust
struct EnvBright { floor: f32, ref_level: f32, base_cut: f32, q: f32 }
```
In `new`: `let (lp_base, lp_q, lp_cur) = match &env_bright {
Some(eb) => (eb.base_cut, eb.q, eb.base_cut), None => (0.0, 0.0, 0.0) };`. The
sentinels are never read on the None path (the `StackFilter::Lp` arm gates on
`env_bright.is_some()`). Gap closed with **no** extra ctor arg.

**Byte-safety on the v1 path (both sections depend on this).** The four new
`Layer` fields and the `EnvBright` init are **copied, never drawn** — the v1
layer loop (`voices.rs:1415–1430`) issues the identical `Rng` sequence
(`rng.white()` for phase, `vib_rate`; `Drift::new` seeded arithmetically). The
`sub_layers` branch only alters ratios for `i >= n_osc − sub_layers`, and every
v1 caller passes `sub_layers = 0` (strings 48/49/50, choir-v1, pad) so their
loops are bit-identical; only the **unused** program 51 and choir-v2-54 draw
differently. The removed stack `vib_depth` was a passed parameter, never an `Rng`
draw. Net: `make(48..=54, …)` and `pad()` stay byte-for-byte v0.8.1 on the
un-opted-in path.

### 4.2 `fx_profile` ownership → **engine55**

`fx_profile` (`engine.rs:253–269`) is a single match block that returns
`(chorus_send, echo_send)` per program. Three sections write to it; they must
not. **engine55 owns the entire block** (it also owns the reed and orchestra-hit
arms, and its oracle E55-4a is calibrated to the values below). The authoritative
arms above the `_ => (0.0, 0.0)` fallback:

```
55       => (0.0,  0.0),   // orchestra hit: dry stab, chorus smears the transient
56..=60  => (0.0,  0.0),   // solo brass: orchestral solo brass is dry (via _ arm)
61..=63  => (0.25, 0.0),   // brass section / synth brass: section-width chorus
64..=67  => (0.06, 0.10),  // saxes: lead voice, touch of width + slap echo
68..=71  => (0.0,  0.0),   // double reeds: dry
```

Brass's companion §6.5 (`61 => 0.08`, `62|63 => 0.30`) and reeds' `64..=71 =>
(0.0, 0.12)` are **superseded**. Brass's Iron-Tide waiver text that cites a
"0.08 chorus send" on ch6 is corrected to **0.25** (§4.3). The section-vs-synth
chorus nuance brass proposed (drier 61, wetter 62/63) is recorded as a deferred
mix-taste knob — it does not change the single-owner decision and would require
re-calibrating E55-4a.

## 5. Per-family design summaries

Each points to its companion (§10) for full parameters, per-program tables, and
oracles. Status reflects the two-lens adversarial verification (§6).

### 5.1 Brass 56–63 (companion `design_brass.md` — **M**)
Physics-first synthesis judged the winner over reuse-first and expressivity-first
candidates (decisive criterion: opt-in safety — the reuse candidate folded brass
into `SawStack`, putting every committed album in its blast radius). Chain:
band-limited saw → **lip-buzz waveshaper** (waveshaping index driven by the amp
envelope — the loudness-brightness law) → **envelope-tracked "waa" filter** (a
dedicated `benv` bloom, attack `BR_BLOOM_A = 0.25 s`, decoupled from the ~28 ms
amp attack so the brightness sweep spans the audible onset) → fixed bore/bell
body resonances → pitch scoop + breath. Per-program: solo brass 56–60 differ in
bore peaks and mute (59); section 61 adds per-player scoop/timing scatter; synth
62/63 use swept-formant analog-poly identities. Grafted from the other
candidates: the dry-solo/chorused-section `fx_profile` split (now owned by
engine55, §4.2) and aftertouch growl. **Status:** design sound; residual was an
oracle bug — see §6 (BR-O9 corrected).

### 5.2 Reeds 64–71 (companion `design_reeds.md` — **M**)
New `BlepPulse` oscillator (band-limited pulse, ~60 LOC in `dsp.rs`) → **fixed
per-instrument formant bank** → breath. Clarinet (71) = hollow odd-harmonic pulse
+ its characteristic ~1500/3000 Hz formants; saxes (64–67) = brassy-reedy
formants with register-dependent brightness; double reeds (oboe 68 / english
horn 69 / bassoon 70) = nasal 1–2 kHz formant emphasis. Scoop + CC68 slur.
**Gate:** all eight programs unused → free. **Status:** design sound; residual was
an oracle bug — see §6 (RD-O12 corrected).

### 5.3 Engine wiring + orchestra hit (companion `design_engine55.md` — **S+**, PASS)
Adds 55–71 to `vibrato_family` and `aftertouch_family` (channel aftertouch is
currently **dead** for these — `at_authored` is set but the family predicate is
false), wires CC68 slur, and owns the `fx_profile` arms (§4.2). **Orchestra hit
(55)** is a new one-shot voice: octave-stacked saw ensemble + a Modal thump,
fast decay — a stab, not a pluck (sustain ratio < 0.1). **PASS** (round 2, 6
minor notes applied). Recommends an optional LA sampled-attack phase (VSCO 2 CE
has brass/reed transients) as a *follow-on*, not part of v0.9.

### 5.4 Strings 48–51 (companion `design_strings.md` — **M**)
**ST1** envelope-coupled brightness (SawStack analogue of `Bowed`'s bow-pressure
coupling, tracking each note's `Adsr` level, *not* CC11 — held-note steady timbre
stays cutoff-identical by construction). **ST2** CC1 section vibrato (per-layer,
via unified `set_vib`, §4.1). **ST3** synth-string identities: 50 = Solina string
machine (static filter, no player vibrato), 51 = dark octave pad (sub layers).
**Gate:** ST2 (CC1-authored) and ST3 (50/51 unused) are opt-in-safe; **ST1 on
48/49 is the one Arthur's-fork** (§8). **Status:** design sound; residual was the
ctor-init gap — closed in §4.1 (`EnvBright`).

### 5.5 Bowed 40–45 (companion `design_bowed.md` — **S**, PASS)
**Real pizzicato (45)** — a `Pluck` variant through the violin body (samples
on/off byte-identical, structurally verified). **Per-instrument bodies** — violin
(40) keeps 280/610/1350 Hz; viola (41), cello (42), contrabass (43) get their own
measured-plausible body modes. **Tremolo (44)** — bow-reversal amplitude +
bow-noise retrigger at 6–9 Hz. **Gate:** 41/44/45 unused → free; **42/43 bodies
conditional** on brass co-shipping (§4.3). **PASS** (round 2, 7 minor notes).

### 5.6 Choir 52–54 (companion `design_choir.md` — **M**)
**CC73-gated** "Choir v2" (§4.5). **CH-1** consonant/breath onset (frozen-then-
released formant morph + mouth-opening level/brightness shading + vowel-coloured
breath transient). **CH-2** per-voice pitch scatter → 8 layers = 2×SATB with
section intonation leans and register weighting. **CH-3** vibrato shimmer
(staggered per-layer onset, depth now per-`Layer` — the change that forced the
§4.1 unification). **54** finally splits from 53 (an "eh" vowel). Plus **CH-4**
melisma legato so onsets don't machine-gun. **Status:** design sound; residual was
an oracle bug — see §6 (CH-O6b corrected).

### 5.7 Drums kit v2 (companion `design_drums.md` — **S–M each fix**)
Behind a **Program-Change-on-channel-10 seam** (§4.5): absent = legacy kit,
byte-identical; present = kit v2. Four independently-landable fixes: **crash**
sine-tail → denser late partial field + noise-coupled shimmer (respecting the
ring-time lesson); **tom** 21-semitone pitch-drop → reduced glide depth/time;
**open-hat** static → time-evolving partial amplitudes; **snare** plain-noise
rattle → enveloped, band-passed wire resonance responding to velocity. Fully
independent of the tonal families (own seam; its byte-compare needs a
drum-seam-only binary since the full binary re-renders Iron Tide via brass).
**Status:** design sound; residual was an oracle bug — see §6 (DR-O4 corrected).

## 6. Verification battery

This machine has no ears — **every** claim is a numeric oracle on rendered audio.
Discipline (from `lessons_learnt.md`): pitch via Goertzel `testutil::peak_locate`
(never zero-crossing counts — brightening a voice makes crossing counters lie);
brightness via `testutil::centroid`; tone prominence via `mag_at`. Feature
oracles must **fail on v0.8.1** and pass after their stage (fail-first);
thresholds marked "(cal)" are calibrated against a measured main baseline before
pinning. Full per-section oracle tables are in the companions.

**Three guard layers hold throughout the build:**
1. **Album byte-compare** — build the v0.8.1 baseline binary in a scratch
   `git worktree`, render every committed album old vs new, `cmp`
   byte-identical except the waived Iron Tide (§4.3).
2. **Golden fixture** (`golden_mix_balance_holds`) — green after the single
   recapture; ch7 piano **and** ch14 pad (SawStack) canaries BIT-EXACT (§4.4).
3. **Determinism** — every mini-song renders twice bit-identically (per-binary
   `Rng`).

### 6.1 Corrected oracles (errata — these override the companions)

Adversarial verification confirmed the voice *mechanisms* but found four
oracles that measure the wrong thing. Corrected here:

- **BR-O9 (brass program spread).** *Was:* `centroid/f0` ordered across
  instruments pinned at wildly different pitches (tuba E1, trumpet C5). The
  100 Hz `centroid` floor (`testutil.rs:56`) drops the tuba's fundamental and
  low harmonics, so `centroid/f0` inverts — physically unsatisfiable. *Now:*
  render trumpet (56), horn (60), trombone (57), tuba (58) **all at C3 (≈131 Hz,
  in every instrument's range)** and assert **absolute** `centroid` strictly
  ordered trumpet > horn > trombone > tuba. At C3 every harmonic is ≥ 131 Hz —
  inside the measured band — so the pitch confound is gone and the ordering is
  the true brightness ordering.

- **RD-O12 (reed anti-alias bound).** *Was:* broadband `hp_rms(>10 kHz)` (which
  a band-limited pulse legitimately fills with real harmonics) pinned to the
  bari sax (lowest cutoff = best case). *Now:* (a) measure fold-back on **bins no
  real harmonic can occupy** — a low fundamental (~200 Hz) whose tanh
  intermodulation products land on non-harmonic bins (the same method RD-O0
  already uses); (b) test the **worst case** — soprano sax played high (highest
  LP cutoff ~5200 Hz, least post-shaper suppression). This actually bounds the
  "no oversampling for RD4" decision.

- **CH-O6b (choir shimmer).** *Was:* an FM-sideband grid at `f ± {3…7} Hz` that
  overlaps the **static** detuned-carrier cluster (tenor/bass at ±~2.4 Hz),
  present in both early and late windows, swamping the blooming vibrato → false
  negative on correct code. *Now:* measure the first vibrato sideband at
  `f ± {4.0 … 6.5} Hz` (centred on the 4.6 Hz vibrato rate, clear of the static
  cluster + the Goertzel main-lobe) with a **2 s window** (narrower main-lobe),
  asserting ≥ 6 dB growth early→late. Robust alternative offered: a
  same-seed depth-0 vs depth-on **difference** render isolates the vibrato from
  the identical static cluster.

- **DR-O4 (crash twin field).** *Was:* measured [2.0, 3.5] s where the detuned
  twins (sharing the primary's t60, already −70 dB by 2.0 s) are dead — the
  `env_cv` rise there is the 9 Hz shimmer AM and the 1180/1196 Hz noise pair, not
  the twins. *Now:* measure the twins in their **live window [0.3, 1.2] s** via
  band-autocorr of a twin pair (e.g. 950 Hz vs its detuned partner), isolating
  the twin beat from the shimmer AM and the noise-pair beat that the design had
  conflated with it.

## 7. Phase / build order & version

Dependencies force the order; within a phase, work is parallel.

- **Phase 0 — scaffolding (no shipped code).** New test helpers the oracles
  need: `BlepPulse` calibration guard (RD-O0), `env_cv`/`env_autocorr_peak`
  detrend variants (DR-O0, BW-O0), the `EnvBright`/unified-`SawStack` skeleton
  landed inert. Establishes the byte-identical floor.
- **Phase 1 — drums (independent).** Program-Change-on-ch10 seam + four fixes.
  Byte-compare uses a **drum-seam-only** binary (the full v0.9 binary re-renders
  Iron Tide via brass, so a whole-binary `cmp` would spuriously differ).

   albums). Three endpoints, all on a byte-identical Stage-A floor:

## 9. Risks

|---|---|
| Shared-`SawStack` bit-drift contaminates committed choir/strings renders | §4.1 copied-not-drawn discipline; ch14 pad SawStack canary (§4.4); album byte-compare |
