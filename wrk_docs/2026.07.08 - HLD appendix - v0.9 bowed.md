# Design section: Solo bowed strings 40–45 polish (v0.9 HLD, family BW)

Status: DRAFT design section for the v0.9 HLD. Baseline **v0.8.1** (integrated
trunk). All Hz thresholds assume the default 44100 Hz `Options.sr`; test
renders pin `sr = 44100.0`. Anchors are structural (symbol names) plus v0.8.1
line numbers in `fable5/hollowsynth/src/voices.rs` unless another file is
named.

Assessment findings closed (JRN 2026.07.07, brass/strings/guitar assessment):

- **BW-1** — GM 45 (Pizzicato Strings) renders as a *sustained bow*.
- **BW-2** — all six programs 40–45 share the violin's body resonances
  (280/610/1350 Hz); a cello is a violin with a lower note.
- **BW-3** — GM 44 (Tremolo Strings) has no tremolo.

---

## 1. Goal

Make programs 40–45 six *different* instruments instead of one violin with
six names:

1. **BW-1**: program 45 becomes a real pizzicato — a plucked, decaying note
   through the violin body, not a bow.
2. **BW-2**: programs 41 (viola), 42 (cello), 43 (contrabass) get their own
   measured-plausible body modes, vibrato rates and bow-pressure brightness
   ranges; 40 (violin) keeps today's voice **bit-exactly**.
3. **BW-3**: program 44 gets bow-tremolo — amplitude strokes at 6–9 Hz with a
   bow-noise "bite" retrigger at each stroke reversal, velocity-scaled.

Success is measured, not heard: the oracles in §8 (sustain ratio, per-program
centroid ordering, AM rate detection, byte-compares).

## 3. Design

### BW-1 — Real pizzicato for program 45: a `Pluck` preset through the violin body

The `PluckPreset` struct (`voices.rs:296–322`) already carries everything a
pizzicato needs: key-scaled KS decay (`t60 · (220/f)^0.55`, clamped
0.25..14 s, `voices.rs:777`), a lowpassed excitation (`pick_lp`), a body
peak-EQ chain in exactly the `(freq, Q, gain_dB)` triple form the `Bowed`
body uses, finger noise (`attack_noise`), a soft onset `click`, a
left-hand damp `stop_thump`, fractional-tap bend/legato, and the CC1
vibrato path via `Pluck::set_pitch` (real pizzicato *does* take left-hand
vibrato on the ringing string). So BW-1 is one new preset plus a `make()`
arm split — no new voice type.

New public constant, placed next to `HARP` (`voices.rs:556`):

```rust
/// Shared body-resonance tables (BW-2): (freq Hz, Q, gain dB) peak EQs.
/// BODY_VIOLIN reproduces the v0.8.1 inline values at voices.rs:1824-1828
/// exactly, so program 40 stays bit-identical.
pub(crate) const BODY_VIOLIN: &[(f32, f32, f32)] =
    &[(280.0, 1.2, 5.0), (610.0, 1.8, 4.0), (1350.0, 1.5, 3.0)];

/// Violin pizzicato (BW-1, GM 45): fingertip pluck through the arco body.
pub const PIZZ: PluckPreset = PluckPreset {
    #[cfg(test)]
    name: "PIZZ",
    t60: 0.9,        // at the 220 Hz ref; key-scaling gives ~0.6 s at A4
    bright: 2600.0,  // fingertip on gut/synthetic-core: dark loop damping
    pick_lp: 1600.0, // fleshy, round excitation — no plectrum edge
    pos: 0.30,       // plucked over the end of the fingerboard
    amp: 0.58,       // level-matched to Bowed's early RMS (oracle BW-O9)
    rel_t60: 0.10,   // the left hand damps the string fast
    body: BODY_VIOLIN, // "through the violin body resonator" — literally
    click: 0.6,      // soft fingertip contact tick
    click_hp: 900.0,
    attack_noise: 0.25, // finger brushing the string as it releases
    stop_thump: 0.5, // the damp lands audibly
    ..DEFAULTS
};
```

Physical reasoning for each value:

- `t60 0.9` @220 Hz: a violin pizzicato rings roughly 0.3–0.8 s depending on
  register; the Pluck key-scaling law gives ≈ 0.61 s at A4 (440 Hz) and the
  0.25 s floor at the E-string top — short, but never a click.
- `bright 2600 / pick_lp 1600`: the excitation is flesh, not plectrum, and
  the string is short and stiff; both sit well below STEEL (5200/5000) and
  near NYLON's character but darker, because there is no fingernail option.
- `pos 0.30`: classical pizzicato is plucked around a third of the string
  length (over the fingerboard end) — comb notches near the 3rd-harmonic
  multiples, the "hollow" pizz color.
- `body: BODY_VIOLIN`: the same three peaks `Bowed` uses (see BW-2), so arco
  and pizzicato on the same channel share one instrument body.
- `stop_thump 0.5` + `rel_t60 0.10`: pizz notes end by finger damping — a
  small thud, then silence. (INT-7 note: under CC64 the thump fires at pedal
  lift, block-quantised, same semantics as every Pluck; accepted.)

`make()` change (`voices.rs:1996–2012`): split the `40..=45` arm into
`40..=43` (LA-wrapped `Bowed`), `44` (bare `Bowed` — see BW-3), and
`45 => Box::new(Pluck::new(&PIZZ, key, vel, sr, seed))`. **Program 45 must
NOT be LA-wrapped**: `LA_VIOLIN` is a sampled *bow bite*; crossfading a bow
attack into a pluck is exactly the artefact BW-1 removes (oracle BW-O7
pins this structurally: samples on/off renders byte-identical for 45).

### BW-2 — Per-instrument bodies (violin / viola / cello / contrabass)

Replace the inline biquad array in `Bowed::new` with a program-selected
table. New constants next to `BODY_VIOLIN`, and a selector:

```rust
/// Viola: ~15% larger corpus, a fifth down. Main air mode (A0) ≈ 220-230 Hz,
/// corpus modes ≈ 0.75-0.8x violin, plus the viola's characteristic nasal
/// band just above 1 kHz.
pub(crate) const BODY_VIOLA: &[(f32, f32, f32)] =
    &[(220.0, 1.3, 5.0), (475.0, 1.8, 4.0), (1200.0, 1.6, 3.5)];

/// Cello: A0 ≈ 100-110 Hz, first corpus (B1) cluster ≈ 190-230 Hz, and the
/// bridge/"vocal" formant region around 600-700 Hz that gives the cello its
/// singing mid.
pub(crate) const BODY_CELLO: &[(f32, f32, f32)] =
    &[(105.0, 1.1, 5.5), (220.0, 1.5, 4.5), (650.0, 1.4, 3.5)];

/// Contrabass: A0 ≈ 60-65 Hz, first top-plate modes ≈ 100-120 Hz, mid
/// formant ≈ 350-400 Hz. Slightly hotter low peaks: the saw source is weak
/// down there and a real bass's large plates radiate the fundamental region.
pub(crate) const BODY_CONTRABASS: &[(f32, f32, f32)] =
    &[(62.0, 1.0, 5.5), (115.0, 1.3, 4.5), (380.0, 1.4, 3.0)];

/// BW-2: which body a program owns. 40 violin, 44 tremolo-strings share
/// the violin plates; 45 never reaches Bowed (BW-1).
/// NOTE (§7 gate): the 42/43 arms below are CONDITIONAL. Ship BODY_CELLO /
/// BODY_CONTRABASS only in a v0.9 build that ALSO re-renders The Iron Tide
/// via the brass 60/61 default change. If brass is absent from the build,
/// map 42 and 43 to BODY_VIOLIN (and use violin pressure/vibrato) — otherwise
/// they become the sole ungated change to a committed album. 41/44/45 are
/// unconditional (no committed album authors them).
fn bowed_body(program: u8) -> &'static [(f32, f32, f32)] {
    match program {
        41 => BODY_VIOLA,
        42 => BODY_CELLO,       // §7: BODY_VIOLIN unless brass re-renders Iron Tide
        43 => BODY_CONTRABASS,  // §7: BODY_VIOLIN unless brass re-renders Iron Tide
        _ => BODY_VIOLIN,
    }
}
```

The mode frequencies are the textbook (Fletcher & Rossing-class) measured
ranges for each corpus: each instrument's first peak is its Helmholtz air
mode, the second its main wood/corpus cluster, the third the formant band the
ear names the instrument by (violin brilliance at 1.35 kHz, viola nasality at
1.2 kHz, cello voice at 650 Hz, bass warmth at 380 Hz). All are far below the
`sr·0.45` biquad guard even at `--rate 8000`-class rates? No — guard applies:
`Bowed::new` must skip any body peak with `f >= sr * 0.45` (same Nyquist
guard idiom as `Modal::new`, `voices.rs:103`); at the default 44.1 kHz
nothing is skipped.

**Field-type change (implied by the guard, stated here so it is not inferred):**
because the skip makes the body length variable, the fixed
`body: [Biquad; 3]` field (`voices.rs:1799`) becomes a `Vec<Biquad>`, built by
the same `filter`/`collect` idiom `Modal::new` uses for its modes
(`voices.rs:101–109`):

```rust
body: bowed_body(program)
    .iter()
    .filter(|&&(f, _, _)| f < sr * 0.45)
    .map(|&(f, q, g)| Biquad::peak(f, q, g, sr))
    .collect(),
```

(`Biquad::peak` takes `(f, q, g, sr)`, so the closure passes `sr` — this is the
only deviation from a bare `.map(Biquad::peak)`.) At 44.1 kHz every table has
length 3, so the `Vec` holds exactly the same three biquads as the old array and
program 40 stays bit-identical; the `Vec` only ever shortens at extreme low `sr`.

Two small couplings ride BW-2, because a body table alone does not make a
cello (both are program-keyed constants in the same match, and both fall
under the same regression classes as the body change — §7):

- **Bow-pressure brightness range** (`voices.rs:1861` today:
  `900 + 5200·env` for everyone): heavier strings and bows put the
  "pressure opens the tone" ceiling lower. New per-program law
  `lp.set_cutoff(press_lo + press_span * last_env)`:
  violin/tremolo `900 + 5200·e` (unchanged), viola `800 + 4600·e`,
  cello `700 + 3800·e`, contrabass `550 + 2800·e`.
- **Vibrato rate** (`voices.rs:1831` today: `5.3` Hz for everyone): bigger
  left-hand oscillation is slower. Violin/tremolo 5.3 Hz, viola 5.1 Hz,
  cello 4.8 Hz, contrabass 4.2 Hz (each still × the existing ±10% seed
  jitter; depth 0.0045 and 0.22 s delay unchanged for all).

`Bowed::new` gains the program: `fn new(program: u8, key: u8, vel: u8,
sr: f32, seed: u32) -> Self`. **RNG discipline (map_docs determinism
corollary):** the program lookup draws nothing; the two existing
`rng.white()` calls stay in the same order with the same constants for
program 40, so a program-40 note is bit-identical to v0.8.1. The tremolo
fields (BW-3) are initialised without draws (`trem_phase: 0.0`,
`trem_rate_cur = trem_rate`).

LA wrapping stays as-is for 40–43: `LaVoice::wrap` already falls back to the
bare model when the repitch step leaves `[0.5, 2.05]` (`sampler.rs:266` area),
so most contrabass and low-cello notes never see a violin transient today
and that behavior is unchanged. A down-pitched violin bite on mid-register
cello notes remains a known wart — parked, see §9 (Deferred).

### BW-3 — Bow-tremolo for program 44

Mechanism: a raised-cosine amplitude stroke cycle at 6–9 Hz (velocity-scaled)
plus a bow-noise **bite retrigger** at every stroke reversal — the two
loudest tells of real tremolo: the level pulses, and each direction change
re-excites the noisy Helmholtz-slip transient. No envelope retrigger is
needed (the `Adsr` has none, `map_dsp` gap 4) — the AM and the noise gate do
the work on top of the sustained saw.

New mechanism constants (named + tagged, house style §5 of map_voices):

```rust
// BW-3 bow-tremolo (program 44 only; trem_rate == 0.0 elsewhere)
const TREM_RATE_LO_HZ: f32 = 6.0;   // relaxed tremolo at vel 0
const TREM_RATE_VEL_HZ: f32 = 3.0;  // + up to 3 Hz: 6-9 Hz across velocity
const TREM_DEPTH_LO: f32 = 0.50;    // trough gain 0.50 = -6 dB dips
const TREM_DEPTH_VEL: f32 = 0.15;   // harder bowing is more detached (-9 dB max)
const TREM_BITE_S: f32 = 0.018;     // bow-noise burst after each reversal
const TREM_JITTER: f32 = 0.06;      // ±6% per-stroke rate humanisation
const TREM_AMP_JITTER: f32 = 0.10;  // ±10% per-stroke level scatter
```

New `Bowed` fields: `trem_rate: f32` (base rate; `0.0` = feature absent),
`trem_rate_cur: f32`, `trem_phase: f32`, `trem_depth: f32`,
`trem_stroke_gain: f32` (init 1.0), `trem_gain: f32` (init 1.0),
`trem_bite_until: u32` (init 0).

Construction (program 44 only): `trem_rate = TREM_RATE_LO_HZ +
TREM_RATE_VEL_HZ * vn`, `trem_depth = (TREM_DEPTH_LO + TREM_DEPTH_VEL * vn)`
where `vn = vel/127` — velocity opens both speed and separation, the
family-A doctrine (velocity opens timbre, not just level).

Control tick (inside the existing `is_multiple_of(CTRL)` block,
`voices.rs:1848`), only when `trem_rate > 0.0`:

```rust
self.trem_phase += self.trem_rate_cur * CTRL as f32 / self.sr;
if self.trem_phase >= 1.0 {                       // stroke reversal == amplitude trough
    self.trem_phase -= 1.0;
    self.trem_bite_until = self.t + (TREM_BITE_S * self.sr) as u32; // bite AT the reversal
    self.trem_stroke_gain = 1.0 + TREM_AMP_JITTER * self.rng.white();
    self.trem_rate_cur = self.trem_rate * (1.0 + TREM_JITTER * self.rng.white());
}
let c = (core::f32::consts::TAU * self.trem_phase).cos(); // control-rate only
// phase 0 (the reversal) is the TROUGH; amplitude peaks mid-stroke at phase 0.5.
// Bow speed is zero at the reversal, so the slip-transient bite lands at the
// amplitude minimum — matching real bow-reversal physics (note the `1.0 - c`).
self.trem_gain =
    self.trem_stroke_gain * ((1.0 - self.trem_depth) + self.trem_depth * 0.5 * (1.0 - c));
```

`trem_gain` sits at `1 - depth` at each reversal (phase 0, where the bite
fires — the amplitude minimum: −6 dB at vel 0, −9.1 dB at vel 127) and rises
to 1.0 mid-stroke (phase 0.5). Firing the bite at the trough, not the peak, is
the correction that places the slip-transient at zero bow speed — where a real
bow reverses — so one code cycle (trough → peak → trough) is exactly one bow
stroke between two reversals. A control-rate `.cos()` every 16 samples matches
the SawStack sweep idiom (`voices.rs:1486`); no zipper at these depths.

Render-loop changes:

- Bow-noise gate: **only the boolean condition** of the `voices.rs:1866–1870`
  expression is extended; the trailing vibrato noise-AM factor
  `* (1.0 + 0.4 * self.vib_val)` is preserved verbatim. The full replacement is:

  ```rust
  let noise_amp = if self.t < self.attack_samples * 2
      || self.t < self.trem_bite_until
  {
      0.10
  } else {
      0.028
  } * (1.0 + 0.4 * self.vib_val);
  ```

  Each reversal re-bites at the full attack-noise level for 18 ms. Dropping the
  `* (1.0 + 0.4 * self.vib_val)` tail would change program 40's render and break
  the bit-identity claim (BW-O11 would catch it), so it stays exactly as v0.8.1.
- Output: `*o += s * self.amp * e * self.trem_gain;` (`voices.rs:1876`;
  `trem_gain` stays 1.0 for programs 40–43, so their sample math is
  unchanged — multiplication by exactly 1.0 preserves bit-identity for
  program 40).
- `legato_to` keeps the tremolo running across the slur (no field reset) —
  a slurred tremolo line is one bow pattern over moving fingers.
- `set_pitch` is untouched: tremolo is amplitude-only, so the INT-2/3
  compose-into-every-retune rule has no new pitch term.

RNG discipline: the two per-stroke `rng.white()` draws happen only inside the
wrap branch, which is unreachable when `trem_rate == 0.0` — programs 40–43
draw exactly the v0.8.1 sequence.

Program 44 is **not** LA-wrapped (make() arm `44 =>` bare `Bowed`): the
sampled bow bite is a single sustained onset that would mask the first 2–3
strokes; the retriggered synthetic bite IS the articulation. 44 is unused by
every committed album (§7), so dropping the wrap is free.

## 7. Opt-in & regression safety (grounded in map_albums.md)

The album scan (`map_albums.md` §b, committed albums only) says of 40–45:
**used = 40, 42, 43; unused = 41, 44, 45.** Resolution per program:

- **Program 40 (violin) — bit-identical, by construction.** Used in four
  committed files (Hollow Hill Parts One & Two ch13, The Signal Fire ch15,
  Winter Guests Part Two ch15). The design keeps its constants numerically
  identical (`BODY_VIOLIN` == the old inline array; pressure law and vibrato
  rate unchanged), adds no RNG draws on its construction/render path
  (tremolo fields init draw-free; per-stroke draws unreachable at
  `trem_rate == 0.0`), and multiplies output by a constant 1.0
  (`trem_gain`). Proof: the standard baseline-binary byte-compare (§8
  BW-O11) over all four files.
- **Programs 41, 44, 45 — free.** No committed album authors them (the
  brief's rule: default changes to unused programs cannot alter any
  committed render). The BW-1 articulation fix and BW-3 tremolo are
  default-on for exactly this reason — a "pizzicato that bows" is a defect,
  not a voicing preference, and no authored-CC gate could express "which
  instrument am I" better than the program number already does.
- **Programs 42, 43 — conditional compatibility waiver, one file.** Both
  appear only in `fable5/midi/The Iron Tide.mid` (cello ch4, contrabass ch3,
  CC11 swells, no other bowed-relevant CCs). The waiver's whole premise is
  that *this same file is re-rendered by v0.9 anyway* — its ch5/ch6 use
  programs 60/61, which the brass section is designed to move off the
  guitar-pluck fallback (map_albums §a). **But this section cannot
  unilaterally guarantee that.** The premise holds only if the *same v0.9
  build* actually ships the brass 60/61 default change. If brass is
  descoped, deferred, or lands in a later build, 60/61 stay on the
  guitar-pluck fallback, The Iron Tide is otherwise byte-identical, and the
  42/43 body change would become the **sole ungated change to a committed
  album** — exactly what the opt-in invariant forbids. So the coupling is
  *conditional*, not certain:
  - **Ship the cello/contrabass bodies (BODY_CELLO/BODY_CONTRABASS on 42/43)
    only when the same v0.9 build also re-renders The Iron Tide via the brass
    60/61 default change.** Then this section joins the brass section's single
    waiver rather than minting a second mechanism: *The Iron Tide is declared
    a sanctioned v0.9 re-render* (the 0.8-HLD §1.5 waiver template — no
    compatibility flag; historical sound stays reproducible via the version
    pin in `fable5/README.md` and the tagged v0.8.1 binary; Arthur decides at
    integration whether any rendered artifact is refreshed). Byte-identity is
    claimed for **every committed album except The Iron Tide**, and its diff
    is *expected and bounded*: with `--solo` stems only chs 3, 4 (this
    section) and 5, 6 (brass) may differ; all other stems byte-identical
    (BW-O11).
  - **Default fallback, mandatory when brass does NOT re-render the file:**
    map 42 and 43 to `BODY_VIOLIN` in `bowed_body` (two match-arm lines) and
    keep their pressure/vibrato values at the violin numbers. Then 41/44/45
    still improve, 42/43 stay byte-identical, The Iron Tide is untouched, and
    the cello/contrabass bodies ship in the same build as (or a later build
    after) the brass re-render. This is **not** an optional "if Arthur
    objects" branch — it is the required default whenever the brass 60/61
    change is absent from the build, so the design cannot silently become the
    sole cause of an Iron Tide diff. BW-O11's Iron Tide clause is then
    tightened to *fully byte-identical* (no chs 3/4 diff permitted).
  - **Optional hardening — make the gate mechanical, not procedural.** As
    specified, the gate is a *procedure*: the implementer must select
    BW-O11 case (a) vs (b) *and* set `bowed_body`'s 42/43 arms to match the
    build's actual brass status by hand. A late brass descope with 42/43 left
    on cello/contrabass bodies and case (a) mistakenly run would let an ungated
    Iron Tide ch3/4 diff pass the gate. Bind both decisions to **one**
    compile-time flag — a `const BRASS_RERENDERS_IRON_TIDE: bool` (or a Cargo
    feature), defaulting to `false` = the safe `BODY_VIOLIN` fallback.
    `bowed_body` returns `BODY_CELLO`/`BODY_CONTRABASS` for 42/43 *only* when
    the flag is `true`, and BW-O11 reads the same flag to pick its expected
    case. Then the fallback is the compile-time default, cello/contrabass
    bodies require an explicit opt-in the brass section sets in the same build,
    and the body choice and the byte-compare expectation can never disagree.
    This is a hardening of the mechanism, not a change to the invariant.
- **Determinism:** per-binary determinism (oracle 35) is unaffected — each
  voice still owns one `Rng` seeded per spawn; draw *count* changes only on
  programs 44/45, which no committed album authors.

## 8. Verification oracles (machine-checkable; every §3 claim has one)

All are `cargo test` items in `voices.rs mod tests` (direct voice
construction, the house style) except BW-O11. Feature oracles must fail on
v0.8.1 `main` and pass after; guards hold throughout. Pinned defaults unless
stated: `sr = 44100.0`, `samples = false`, key 69 (A4, 440 Hz), vel 100,
seed = a fixed literal per test, analysis windows start ≥ 50 ms after
note-on.

**Tremolo helper caveat — the existing `env_autocorr_peak` is NOT calibrated
for this band.** `env_autocorr_peak` (`testutil.rs:145–165`) detrends the
rectified envelope with a **15 Hz** complementary highpass (`d = env −
lowpass_15Hz(env)`, lines 148–149). Its *only* calibration test,
`env_autocorr_recovers_am_rate` (`testutil.rs:398–410`), pins it at **60 Hz**
AM with a `[10 ms, 25 ms]` lag window — a decade above the detrend corner, a
different response regime. The BW-3 tremolo sits at **6–9 Hz**, *below* the
15 Hz corner, so that highpass attenuates the AM fundamental by roughly 6–9 dB
(`|H_hp(8 Hz)| ≈ 0.47`, `|H_hp(6.76 Hz)| ≈ 0.37` for a 1st-order 15 Hz HP).
Reusing the helper unchanged at a peak threshold of 0.35 would demand a tighter
peak than the calibrated 60 Hz case delivers, at a rate the detrend actively
suppresses — a flaky/failing oracle on a mechanism that is physically correct.
The repo's oracle-0 discipline (a helper used in a new regime needs a
calibration test first) therefore applies here. Two changes make the tremolo
oracles trustworthy, both **test-only** (no shipped code, no version bump):

1. **A detrend-corner variant.** Add
   `env_autocorr_peak_detrend(seg, sr, lag_lo_s, lag_hi_s, detrend_hz)` —
   the current body with the `15.0` literal replaced by the `detrend_hz`
   parameter — and make the existing `env_autocorr_peak` delegate to it with
   `15.0`, so **oracle-24 and every current caller are byte-unchanged**. The
   BW-3 oracles call it with `detrend_hz = 4.0`, below the 6–9 Hz tremolo band,
   so the stroke AM passes essentially unattenuated while a decaying tail's
   sub-4 Hz trend is still removed.
2. **A calibration test first (BW-O0).** It pins the helper in *this* band and
   sets BW-O5's peak floor empirically rather than by guess.

Note also the 5.3 Hz voice-vibrato noise-AM (period ≈ 189 ms) falls **inside**
BW-O5's `[0.08, 0.20]s` (= 5–12.5 Hz) lag window, so it competes with the
stroke rate. It is a weak competitor — its depth is only `0.4 · 0.028` on the
*noise* term, ~20 dB below the 0.50–0.65 stroke AM on the full signal — but
BW-O0 must demonstrate the stroke peak dominates it, not merely assert it.
