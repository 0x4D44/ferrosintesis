# design_brass — Brass 56–63 (judged synthesis)

Flagship brass section, GM programs 56–63. This is the judged synthesis of
candidates A (reuse-first), B (physics-first), C (expressivity-first). The
**skeleton is candidate B** — an isolated `Brass` voice adjacent to Wind/Bowed
driven by one loudness scalar — with the **CC11+aftertouch expression seam and
growl grafted from C** and the **structural-inertness / opt-in proof rigor from
A**. Baseline is hollowsynth **v0.8.1** (integrated trunk); every anchor is
`fable5/hollowsynth/src/<file>:N` verified against that build. All Hz assume the
default `Options.sr = 44100`; test renders pin `sr = 44100.0`. Control rate
`CTRL = 16` (`voices.rs:62`) ⇒ tick ≈ 2756 Hz, so a per-tick slew coeff `k` has
τ ≈ 1/(k·2756) s.

Mechanism ids (each closes an assessment tell): **BR1** lip-valve nonlinearity,
**BR2** loudness–brightness law (flagship), **BR3** bore formants + bell shelf,
**BR4** mute (prog 59), **BR5** scoop + CC68 slur (trombone slide),
**BR6** breath + tongue chiff (tongued≠slurred), **BR7** section scatter,
**BR8** synth-brass identity (62/63), **BR9** `set_breath` CC11/AT seam,
**BR10** growl (flutter AM + drive bite), **BR11** DC guard.

## 1. Goal

GM 56–63 (trumpet, trombone, tuba, muted trumpet, french horn, brass section,
synth brass 1/2) stop falling through `voices::make`'s
`_ => Pluck::new(&STEEL, …)` arm (`voices.rs:2045`) — where a held note decays
like a picked guitar (measured `sustain_ratio` **0.01**, journal 2026.07.07,
"decays = PLUCK") — and render as sustaining brass with a **complete expression
surface on day one**:

1. **Sustain** — a held note holds (sustain ratio ≥ 0.7, today 0.01).
2. **The "waa"** — the note speaks dark and blooms bright over the onset
   (~0.25 s: a dedicated brightness bloom, deliberately slower than the ~30 ms
   amplitude attack, so the timbre keeps opening after the note is already at
   level — the inverse of a pluck).
3. **Loudness opens timbre, not just level** — hard/loud notes are brassier
   *within* a note and *between* notes (Beauchamp's law).
4. **The lip scoops into the note**; brass sections sound like *several players*,
   not one fat detuned saw.
5. **CC11 is a breath controller** (opens the tone), **aftertouch growls**,
   **pitch bend serves scoops/falls/doits through the release tail**, **CC68 is
   one breath across fingered notes** (trombone glide is an audible slide),
   **tongued vs slurred is an audible dichotomy**.

Success is measured, never asserted (the house doctrine; "sounds better" is not
a definition of done) — the oracle battery in §8. Standing caveat (map_docs
§2.3): every oracle is a numeric proxy; the true acceptance ceiling is a human
A/B listen this machine cannot perform.

Program 55 (orchestra hit — a struck one-shot) is out of scope, owned by
`design_engine55.md`. Reeds 64–71 are `design_reeds.md`. No LA sample bank in
this phase (the `sampler.rs` seam per map_dsp §2.5 stays open; trigger = oracles
pass but a human listen finds the onset weak).

## 3. Design

### 3.1 Why an isolated `Brass` struct (skeleton = B, not A)

Candidate A folds brass into `SawStack` as a fifth preset family by adding seven
new fields. That yields the smallest diff, but `SawStack` is used by `strings()`
(48–51), `choir()` (52–54) and `pad()` (80–95) — **every committed album plays
one of these**, so the blast radius of a mistake in the shared struct is the
entire catalogue. A's own risk table names this "the big one". The synthesis
rejects that coupling: `Brass` is a **new struct adjacent to Wind/Bowed**
(`voices.rs:1662–1906`), the exact architectural precedent for a
sustained-blown/bowed voice, and it **spawns only for programs 56–63**. Every
other program's construction and render path is byte-for-byte untouched — the
regression proof (§7) is therefore trivial and total, not an inertness argument
over shared mutable state. A's reuse insight is honoured differently: `Brass`
*composes* the same shipped primitives, it just owns its own state.

### 3.2 Structs and constants (all in `src/voices.rs`, adjacent to Wind/Bowed)

```rust
/// BR — brass, v0.9. One BrassPlayer per human player: solo programs run 1,
/// section 61 runs 3, synth 62/63 run 5. (Skeleton: candidate B.)
struct BrassPlayer {

    detune: f32,         // fixed per-player ratio (sections)

    decim: [Biquad; 2],  // BR1: 2x->1x decimation cliff, at sr2

    drift: Drift,        // random-walk pitch instability (BR7)

    spec: &'static BrassSpec,

    growl: f32,          // BR9/BR10: engine-slewed aftertouch growl, default 0.0
    growl_cur: f32,      // BR10: voice-side slew of growl (0.05/tick, de-zipper)
    bite: f32,           // BR2: tongue over-blow, decays t60 60 ms

    sweep: Option<Biquad>,// BR8: shared resonant LP, retuned at CTRL rate

    bore: [Biquad; 2],   // BR3: bore/mouthpiece peak EQ (linear, on the sum)

    mute: Option<[Biquad; 3]>, // BR4: prog 59 (HP + 2 nasal peaks + loss)
    breath_filt: Biquad, // BR6: sustained blowing noise, BP at upper bore formant
    chiff: Burst,        // BR6: tongue transient
    flutter: Sine,       // BR10: growl flutter LFO (30 Hz)

    rng: Rng, t: u32, amp: f32, sr: f32,
}

    pub k_min: f32, pub k_max: f32, pub bias: f32,   // BR1/BR2 law

    pub mute: bool,                                  // BR4
    pub synth_sweep: Option<(f32, f32, f32, f32)>,   // BR8: (base, vel0, vel_depth, q)

    pub growl: bool,                                 // BR10: aftertouch growl enabled (naturals yes, synth no)
```

### 3.3 Signal chain (per rendered output sample)

```
per player i  (internal sr2 = 2·sr; two sub-steps per output sample):
  BlepSaw @ f_i ─► OnePole lip_lp(fc) ─► y=(tanh(x·k+b)−tanh(b))/tanh(0.9·k) ─► decim LP ×2
       ▲BR7 scatter      ▲BR2 cutoff law         ▲BR1 lip valve (k from BR2/BR10)   (keep 2nd sub-step)

sum players ÷ n
  + breath_filt(white)·breath·√e            ▲BR6 blowing noise (relatively louder when soft)
  + chiff.tick(rng)                         ▲BR6 tongue transient (Burst, onset only)
  ─► dcb  HP 25 Hz                          ▲BR11 shaper DC guard
  ─► [62/63 only: sweep Biquad LP]          ▲BR8 (replaces per-player lip law)
  ─► bore peak EQ ×2                        ▲BR3 bore/mouthpiece formants
  ─► x + bell_g·(x − bell_lp(x))            ▲BR3 bell HF radiation shelf
  ─► [59 only: HP 750 ► peak 1600 ► peak 4000 ► ×0.40]   ▲BR4 mute
  ─► × (1 − BR_GROWL_AM·growl_cur·(1+sin 2π·30·t)/2)      ▲BR10 flutter AM (growl_cur: same slew as the bite)
  ─► × amp × env.next()   ─► += out
```

Per-player retune at control rate (`self.t.is_multiple_of(CTRL)`), composing
every persistent offset per INT-2/INT-3:

```
f_i = base_f · detune_i · bend · scoop_i · (1 + vib_i + drift_i)
saw_i.set_freq(f_i.min(sr*0.45), sr2)
```

### 3.4 BR1 — lip-valve nonlinearity (per player, 2× oversampled) [from B]

The lip is an asymmetric pressure-controlled valve: soft playing barely modulates
the flow (near-sinusoidal internal pressure); loud playing snaps the lips shut
each cycle and the bore steepens the wave (the "brassy blare"). The polyBLEP saw
supplies the full −6 dB/oct harmonic series; `lip_lp` sets how much the valve
produces this instant; the **bias-referenced tanh** regenerates energy above the
cutoff by intermodulation — what cumulative nonlinear propagation does in the
bore. The bias term (Drive idiom, `engine.rs:222–223`) breaks odd symmetry so
even harmonics appear, as the asymmetric flow demands. Normalisation `÷ tanh(0.9·k)`
keeps the *positive* peak ~k-invariant, so the law changes *slope*, not loudness
(level lives in `amp × env`). Over the shipped range — `k ∈ [0.6, 3.2]`, `bias
0.12–0.45` — the small-signal gain is ≈ 1.0–1.1·x (the `1.11·x` figure holds only
at `bias = 0`, which no preset uses), and the bias-shifted *negative* excursion
grows only to ≈ −1.3 at `k = 3.2` — the ±1.3 per-player peak the INT-6 headroom
bound uses (§7).

The nonlinearity is **per player** — two trumpets do not intermodulate in the
air; a shared shaper over the section sum would be a synthetic tell (this is why B
beats C's summed 1× shaper on section faithfulness). Aliasing: generate the saw
natively at `sr2` (two `next()` per output sample) and decimate through two
cascaded `Biquad::lowpass(BR_DECIM_HZ, 0.8, sr2)` — the "filter cliff as
decimator, keep the aligned sample" pattern of the guitar cab
(`engine.rs:162–170`). −24 dB/oct above 13.5 kHz leaves fold-back ≥ ~22 dB down
plus the source rolloff; bounded numerically by BR-O11. The linear bore/bell EQ
runs **once on the sum** (cheap, identical for same-spec players).

### 3.5 BR2 — the loudness–brightness law (flagship) [from B]

One scalar drives the whole timbre, recomputed every CTRL tick:

```
bloom = benv.next()                                              // BR2 brightness env, sampled at CTRL
L  = bloom · (0.10 + 0.90·vn) · pressure · (1 + bite)            clamped to 1.3
fc = f0 · (h_min + (h_max − h_min)·L^BR_H_EXP)   → lip_lp.set_cutoff(fc.min(sr2*0.24), sr2)
k  = (k_min + (k_max − k_min)·L + BR_GROWL_DRIVE·growl_cur).min(BR_K_MAX)   → kws (BR1 this tick)
```

- **`bloom` is a *dedicated* brightness envelope `benv`, NOT the amp `Adsr`** —
  this is what fixes the "waa"'s timescale. The amplitude attack is only
  `vel_attack(0.03,100) ≈ 28 ms` (`voices.rs:1560`) and the amp `Adsr` peaks at
  ~28 ms then *decays* to sustain `S` — far too fast to read as a bloom, and
  falling (not rising) through BR-O3's `[0.03,0.10]`/`[0.25,0.45]` windows, so an
  amp-coupled brightness would fail that oracle. Instead
  `benv = Adsr(BR_BLOOM_A, 0.05, 1.0, spec.env.3)` gives the timbre its own slow
  attack (`BR_BLOOM_A = 0.25 s`, the harmonic/bore fill time — physically, the
  spectral centroid of a real brass note keeps rising for a few hundred ms at
  constant amplitude), **sustain 1.0** (the sustained timbre is the fully-open
  one), and a release matched to `spec.env.3` so the tone darkens as air pressure
  falls. The centroid therefore keeps climbing for ~0.25 s after the note is
  already at level: the audible "waa", now genuinely spanning BR-O3's early
  (rising) and late (open) windows. Bowed's env→brightness idiom
  (`voices.rs:1861`) is the precedent; here the coupling is to a *purpose-built*
  envelope so the bloom is not hostage to the 28 ms amp attack.
- A crescendo *within* a note brightens through **`pressure`** (authored CC11, BR9)
  and the transient **`bite`**; between notes, **`vn`** opens the timbre. Because
  `fc ∝ f0` while the bore formants (BR3) are *fixed*, high notes read as
  formant-dominated and low notes as slope-dominated — the real register
  behaviour, for free.
- `vn = vel/127` is the timbre-law input; `vel_amp` handles level separately
  (`amp = spec.amp·(0.4 + 0.6·vel_amp)`, sustained-family compression, map_voices
  §4) — velocity opens timbre, not just level.
- `bite` starts at `0.7·vn²` on a tongued attack (super-linear, house onset
  convention `voices.rs:833`) and decays `t60_mul(BR_BITE_T60)` — a short
  over-blow (~−30 dB by 30 ms), briefly brighter than the sustain. Zeroed by
  `legato_to`. It rides *on top of* the slow `bloom`: the onset is a fast bite
  over a slow brightening — dark speak, then bloom, the inverse of a pluck (BR-O3
  is fail-first on main, where a pluck is brightest at onset).

Worked numbers (trumpet, h 2.5→9.0, k 0.8→3.2), at the sustained window where
`bloom = 1.0`: vel 36 → L≈0.36, fc≈4.0·f0, k≈1.65 (round, dark mp); vel 120 →
L≈0.95, fc≈8.5·f0, k≈3.2 (blare, at the `BR_K_MAX` ceiling). Because `benv`
sustains at 1.0 (not the amp `S`), these ARE the values the oracle's sustained
windows measure. That spread is what BR-O2/O9 pin (centroid ratio ≥ 1.30).

### 3.6 BR3 — bore formants + bell radiation [from B]

The mouthpiece cup + bore give the internal spectrum a broad envelope maximum
(the brass "formant"); the bell transmits highs and reflects lows, so the
*radiated* spectrum is the internal one tilted up toward the bell cutoff.

- **Bore**: two `Biquad::peak` per program (values §5) on the player sum, at the
  measured formant regions: trumpet ~1.2 kHz + brilliance ~2.9 kHz; trombone
  ~600 Hz; tuba ~230 Hz; horn ~340 Hz (hand-in-bell, the darkest). Gains capped
  +6 dB (INT-6 bound, §7).
- **Bell**: a first-order high shelf from the existing `OnePole` —
  `y = x + bell_g·(x − bell_lp.process(x))`: unity at DC, `1 + bell_g` above
  `bell_fc`. Trumpet bell_g 1.1 (+6.4 dB above ~1.5 kHz); horn 0.5; tuba 0.4.
  First-order = phase-benign, and **avoids needing a shelf biquad** the crate
  lacks (map_dsp §5.2 gap sidestepped).

### 3.7 BR4 — the mute (program 59) [from B, C values folded]

A straight mute is a cone blocking the bell mouth: transmission below ~800 Hz
collapses, the mute cavity resonates near 1.4–2 kHz (the nasal color) with a
secondary sizzle ~4 kHz, insertion loss ~8 dB. Stage after the bell shelf, only
when `spec.mute`:

```
Biquad::highpass(750, 0.7) ► Biquad::peak(1600, 2.2, +7) ► Biquad::peak(4000, 2.0, +3) ► ×0.40
```

Breath and chiff pass through the same stage — the noise radiates through the
same obstructed bell (physically consistent; keeps the mute identity on soft
notes where noise dominates). The lip law is unchanged: a mute changes what
escapes, not how the lips buzz — which is why 59 shares the trumpet source values
and differs only in transmission. Pinned by BR-O8.

### 3.8 BR5 — pitch scoop, CC68 slur, trombone slide [B + C's slide]

The lip locks onto the bore resonance from below over ~30–60 ms. Per player,
`scoop` starts at `spec.scoop0 + 0.008·vn` (harder attacks start closer / lock
faster, Bowed idiom `voices.rs:1837`) and settles `scoop += scoop_k·(1 − scoop)`
per CTRL tick (Wind/Bowed, `voices.rs:1736/1849`). Composed into every retune
(§3.3), so the engine's per-block `set_pitch` writers cannot snap it back
(INT-2/3). **Falls and doits are free**: a PB ramp authored across NoteOff keeps
steering the release tail because `set_pitch` still lands and the tick still
composes it; releases (§5) are long enough (0.12–0.35 s) to sound.

`legato_to(key, vel)` (trait default `voices.rs:36`) follows Wind
(`voices.rs:1775–1782`): re-aim each player via its scoop —
`scoop_i = (base_f·scoop_i / new_f · j).clamp(BR_SCOOP_CLAMP)` with
`j = 1 + 0.10·rng.white()` (players don't move as one, C's touch); `base_f =
new_f`; kill `chiff` and `bite`; do **not** retrigger `env` (one breath across
fingered notes). Returns `true`. **Trombone (57) is a slide by construction**: its
`scoop_k = 0.008` (τ ≈ 45 ms, ~150 ms glide) makes a slurred interval audibly
portamento, where trumpet's `scoop_k = 0.012` (τ ≈ 30 ms) is a lip slur — C's
"the slide falls out of the settle rate" insight, realized on B's per-player
scoop. The engine's exactly-one-ringing-voice predicate (`engine.rs:698`) works
naturally: a section is ONE `Brass` voice with internal players, so a slurred
section line slurs, but a 3-note chord is 3 voices and correctly refuses. Under
CC64/66 the deferred note_off only delays `env.release()`; brass arms no
release-triggered one-shot, so the INT-7 pedal-pileup concern is vacuous (stated,
not tested).

### 3.9 BR6 — breath noise, tongue chiff, tongued≠slurred [B + C]

- **Sustained blowing noise**: `Biquad::bandpass(upper_bore_f, 1.5, sr)` fed white
  noise, level `spec.breath · e.sqrt()` — the square root makes noise *relatively*
  stronger at low envelope, as soft playing really is breathier. Injected before
  the bore EQ so it is coloured by the same resonances as the tone.
- **Tongue transient ("tuh")**: a `Burst` (`dsp.rs:410`) with
  `bandpass(upper_bore_f, 1.0)`, gain `spec.chiff`, t60 30 ms, triggered at
  `vel_amp(vel)·vn` (super-linear) **on a fresh attack only**. A slur never
  triggers it (§3.8). This is C's tongued-vs-slurred dichotomy, pinned as an
  explicit oracle (BR-O6): pp entries are nearly tongue-less, ff ones spit; a
  slurred note has no second consonant.

### 3.10 BR7 — section scatter (61) and the synth pair [B/C]

Per player: linear detune across ±`detune_cents/2` (SawStack idiom
`voices.rs:1417–1423`); a random onset in `[0, onset_scatter_s]` (player 0 pinned
to 0 so the section has a defined front edge) with a `BR_ONSET_RAMP_S = 15 ms`
smoothstep ramp-in (no step click at a late entry); its own vibrato `Sine` at
`rate·(1 ± 8%)` with independent phase and a 1 s ramp after `delay` (SawStack
:1426, :1451–1455); its own `Drift::new(seed ^ (0x1234 + i·977), depth, 2800)`
(:1427); and ±15% scoop_k jitter. **Solo programs (56–60) get NO autonomous
vibrato** — real solo brass vibrato is a deliberate act, which is what authored
CC1 is for — only a small Drift (0.0015) for lip instability. Every oscillator
gets a random start phase; all presets jittered a few % per note (map_voices §6.7,
seed discipline). Real section entries spread ~20–40 ms; this is the anti-"one fat
saw" tell (BR-O7).

### 3.11 BR8 — synth-brass identity (62/63) [from B]

Analog poly-brass is not a physical instrument; modelling a bore would be the
wrong physics. 62/63 therefore swap the per-player lip law for the classic
machine: near-linear players (`k_min = k_max = 0.6`, `bias = 0.15` — a whisper of
warmth), wider detune, **zero onset scatter** (keyed together), no scoop, no bore
formants, no growl — and one shared **resonant lowpass sweep** on the sum, the
SynthBass idiom exactly (`filt.retune_lowpass(base + fenv·depth, q)` at CTRL rate,
clamped 80..0.4·sr, `voices.rs:1112–1133`): 62 = `fenv Adsr(0.005, 0.22, 0.35,
0.15)` sweeping `260 + (900 + 2600·vn)` Hz at Q 1.8 (bright attack "bwah" that
settles); 63 = slower, darker, longer. Because the synth players are near-linear
(`k = 0.6`), the factory builds them **without oversampling** — the mild `tanh`
generates no alias-worthy harmonics, so the 2× saw-generation/decimation cascade
is skipped and each synth player is one saw-chain, not two (the CPU note in §8).
This finally gives 62/63 an identity of their own (the counterpart to the strings
50/51 "no identity" lesson), machine on purpose, differentiated from 61 by
BR-O10.

### 3.12 BR9 + BR10 — CC11 breath + aftertouch growl [seam from C, onto B]

**Candidate B added `set_pressure(p)`; candidate C added `set_breath(pressure,
growl)`.** The synthesis takes **C's combined seam** — one trait method carrying
both breath pressure and growl — because it buys the growl gesture B lacks for one
extra argument, and both are engine-slewed channel controls:

```rust
/// Breath control (brass): pressure 0..1.3 (CC11, engine-slewed) opens the
/// timbre; growl 0..1 (channel aftertouch) adds flutter and bite. Never scales
/// amplitude — level stays strip-owned. Default no-op on every other voice.
fn set_breath(&mut self, _pressure: f32, _growl: f32) {}   // after set_vowel, voices.rs:47
```

Inside `Brass`: `pressure` (default 1.0) multiplies `L` in BR2 (so a swell opens
`fc`/`k`) and the breath-noise level, with floor
`press = BR_PRESS_FLOOR.0 + BR_PRESS_FLOOR.1·pressure` so CC11=0 is dark, not
silent (the strip already owns level). `growl` (default 0.0) is voice-slewed to
`growl_cur` at `BR_GROWL_SLEW = 0.05`/tick (τ ≈ 7 ms, de-zipper block writes) and
does two things (BR10), **both driven by the same `growl_cur`** so the two halves
of one gesture ramp together (no bite/flutter desync):

1. adds `BR_GROWL_DRIVE·growl_cur` to the shaper index `k`, then clamps the
   composed drive to `BR_K_MAX = 3.2` — the loudest-preset ceiling the alias floor
   is validated at (§3.4/BR-O11). At soft/mid dynamics this is real added **bite**
   (e.g. base `k ≈ 2.1` → clamps at 3.2, +1.1 of drive); at ff, where base `k` is
   already ≈ 3.2, the clamp means growl adds no further brightness and the gesture
   is carried entirely by —
2. a post-filter **flutter AM**
   `×(1 − BR_GROWL_AM·growl_cur·(1+sin 2π·BR_GROWL_HZ·t)/2)` at 30 Hz (flutter-tongue
   rate 25–35 Hz — fast enough to read as roughness, slow enough that
   `env_autocorr_peak` measures it cleanly, BR-O5). Applied at output rate *after*
   decimation, so the ±30 Hz sidebands it adds cannot alias.

The clamp is the aliasing safety story: growl fills the drive up to the ff ceiling
but never past it, so a growled note can never exceed the harmonic content of a
plain ff note — the case BR-O11 measures. The strip's existing CC11 *gain*
(`engine.rs:1127`) is **untouched** — pressure is timbre-only, so the swell's
loudness is applied exactly once (map_docs pitfall 6).

**Aftertouch drives three things, by design.** Enrolling 56–63 in `vibrato_family`
also places them in `aftertouch_family` (the OR at `engine.rs:71`), so an authored
channel-pressure value engages not only the BR10 growl above but the *engine's*
existing aftertouch response too: the `+2.5 dB` `at_gain` lift and the ±25-cent
`at_vib` pitch vibrato (`engine.rs:1050–1062`). This is intended — brass pressure
reads as *louder + vibrato + growl* on one expressive axis — and BR-O5's
differential (AT-110 vs AT-0, same seed) measures the combined effect, so anyone
calibrating it should expect all three, not growl alone. It is opt-in safe: no
committed album authors aftertouch on a 56–63 channel (Iron Tide ch5/6 author
none), and the albums that *do* author AT are on programs 52/89/95 — already in
`aftertouch_family` and unchanged by this edit (map_albums §a).

A channel that never authors CC11 has `expr = 1.0 ⇒ press = 1.0` and `growl = 0`
— velocity alone sets the timbre, no surprise for plain MIDI.

## 7. Opt-in & regression safety (grounded in map_albums.md)

1. **Unused programs 56–59, 62, 63** (map_albums.md §a: "Unused in the range: …
   56, 57, 58, 59, … 62, 63"). The new `make()` arm cannot change any committed
   render for these — verified, not assumed.
2. **Used programs 60, 61 — explicit compatibility waiver** (map_docs §1.6
   template). `fable5/midi/The Iron Tide.mid` ch5 (60 FrenchHorn) and ch6 (61
   BrassSection) **will re-render**: those channels today play a horn fanfare and
   a brass section **as decaying steel-guitar plucks** — the exact defect graded
   "absent" that this build exists to fix. This design deliberately re-renders
   exactly that one file. No compatibility flag. Their authored CCs (CC7×1,
   CC10×1, CC11×96, CC91×1) are all program-agnostic strip paths; the only new
   behaviours are the voice itself, ch6's new 0.08 chorus send, and BR9 making the
   CC11×96 swells open the *timbre* (intended). Historical sound stays
   reproducible at the pre-0.9 tag; Arthur decides the `.opus` refresh at
   integration. Byte-identity is replaced, for this file only, by full regression
   + golden guard + an expected-diff assertion (BR-O12c).
3. **Isolation is the safety story (skeleton advantage).** `Brass` is a new struct
   that spawns **only** for 56–63 (§3.1). No existing voice's construction or
   render path changes — so RNG draw sequences for every non-authoring channel are
   byte-identical (DOC-3 determinism corollary), and the shared-struct
   contamination hazard that candidate A had to argue away simply does not exist
   here. Proof procedure (lessons/README precedent): build the v0.8.1 baseline
   binary in a scratch `git worktree add`, render every committed album with both
   binaries, `cmp` byte-identical — with The Iron Tide as the single documented
   exception, which must differ (BR-O12).
4. **Engine predicate edits** (`vibrato_family`) only activate under
   `mod_authored`/`at_authored`; no committed album authors CC1 or aftertouch on
   any 55–71 channel (Iron Tide ch5/6 author neither) — opt-in safe even for the
   waived file.
5. **BR9 seam** defaults to a no-op on every existing voice; its engine writer is
   program-gated to 56–63, whose only committed occurrence is the waived file.
6. **`fx_profile` arms** touch only 61–63 ⇒ Iron Tide ch6 (inside the waiver) and
   otherwise-unused programs.
7. **INT bounds.** INT-4: no delay lines in `Brass` — 24-semitone RPN bends only
   hit the `min(f, sr·0.45)` clamps (pitch-limit, never corrupt). INT-6: worst
   narrowband stack = bore +6 dB (Q ≤ 1.6) × mute nasal +7 dB (Q 2.2) × authored
   strip wah +18 dB (Q 8) ≈ +31 dB, bounded upstream by the tanh (per-player
   output ≈ ±1.3 — the bias-shifted negative peak at k = 3.2) and downstream by
   peak normalisation (`engine.rs:1255`) — the
   mix ducks rather than clips; bore/mute gains capped +7 dB; untested-by-design
   (authored-wah-on-muted-trumpet is an authorial choice, as wah-on-choir is
   today). INT-7: brass arms no release-triggered one-shot, so pedal-pileup is
   vacuous.
