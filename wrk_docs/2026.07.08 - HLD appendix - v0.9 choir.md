# Design section: Choir 52–54 polish (v0.9 HLD) — mechanisms CH-0..CH-4

Status: DRAFT design section for the v0.9 HLD. Baseline: hollowsynth **v0.8.1**
(integrated trunk). All Hz values assume the default 44100 Hz `Options.sr`;
test renders pin `sr = 44100.0`. All line anchors verified against the current
source (`fable5/hollowsynth/src/voices.rs`, `src/engine.rs`) — structural
anchors (function/struct names) are authoritative if lines drift.

---

## 1. Goal

Close the three "one detuned synth, not thirty singers" tells in the choir
family (GM 52 Choir Aahs, 53 Voice Oohs, 54 Synth Voice), graded *good* in the
roadmap but flagged for polish:

- **CH-1 Consonant/breath onset** — a real choir entry starts closed ("mm" /
  breath) and *opens* into the vowel: lips-closed level shading, HF damping,
  and a breath transient, before the formants travel. Today the formant
  centres morph smoothly from a schwa but nothing else changes — no level dip,
  no darkness, no air.
- **CH-2 Per-voice pitch scatter (fake SATB sectioning)** — replace the
  deterministic symmetric 4-layer detune fan with per-note *random* scatter
  organized into four sections with distinct intonation leans, scatter widths,
  and register weights (low notes read as men, high notes as women).
- **CH-3 Vibrato shimmer** — per-layer *staggered* vibrato onset delays and
  ramp lengths, so the section's vibrato blooms incoherently over the first
  second instead of switching on in lockstep.

Success is measured, never asserted: every claim below carries a numeric
oracle on rendered audio (§8). "Sounds better" is not a definition of done.

## 2. Current state (v0.8.1, code as inspected)

The choir is a `SawStack` preset — `fn choir(program, key, vel, sr, seed)`
at `voices.rs:1588–1622`:

- **4 layers** (`struct Layer`, `voices.rs:1357–1363`), detune 0.009, spread
  *linearly* across ±detune (`voices.rs:1417–1423`): ratios exactly
  {−15.6, −5.2, +5.2, +15.6} cents every note — same fan, every note, both
  hands of a chord. Per-layer vibrato rate jitter ±15% and random phase exist
  (`voices.rs:1425–1426`); per-layer `Drift` depth 0.0045 (`voices.rs:1427`).
- **Formants** (`StackFilter::Formant`, `voices.rs:1365–1376`): program 52
  targets (660, 1120, 2500) Hz "aah"; 53 **and** 54 share (330, 870, 2300)
  "ooh" (`voices.rs:1589–1593`) — program 54 has no identity of its own.
  Qs [9, 10, 9]; band gains fixed [1.0, 0.55, 0.28]; onset starts at the
  closed schwa [500, 1400, 2400] and `control_tick` slews `cur → tgt` at
  0.045/tick (`voices.rs:1478–1483`; CTRL = 16 samples, `voices.rs:62`, so
  τ ≈ 8 ms → the audible travel completes in ~30–60 ms). Only the *centre
  frequencies* morph — gains and level do not, so the "mm" is a mild EQ
  sweep, not a closed mouth.
- **Vibrato**: one global `vib_delay` = 0.30 s and one global 1 s ramp
  (`voices.rs:1450–1455`) — every layer's depth envelope is identical.
- **Breath**: constant white noise `breath = 0.02` added pre-filter
  (`voices.rs:1507–1509`) for the whole note — no onset emphasis.
- Env `Adsr(vel_attack(0.28, vel), 0.3, 0.9, 0.4)`; amp 1.10 with the
  sustained-family compression `×(0.4 + 0.6·vel_amp)` (`voices.rs:1445`).
- **Engine wiring**: CC70 vowel morph is authored-gated to 52–54
  (`engine.rs:744–747` at NoteOn, `engine.rs:1040–1046` per block, anchors
  `VOWEL_ANCHORS` `engine.rs:83–108`). 52–54 are in `aftertouch_family`
  (`engine.rs:70–72`) but **not** `vibrato_family` (`engine.rs:61–64`) — CC1
  on a choir channel is a complete no-op (`engine.rs:1025–1027`). `fx_profile`
  gives choir (0.30 chorus, 0 echo) (`engine.rs:253–269`). `SawStack` has no
  `legato_to` (trait default `false`, `voices.rs:36`) — CC68 retriggers.

## 3. Design

### CH-0 — The gate: "Choir v2" engages only on channels that author CC73

This is the load-bearing decision, driven by `map_albums.md`:

- Program **52** is used by *every* committed album: Hollow Hill 01/02 ch7,
  The Signal Fire ch7, Winter Guests P1 ch7+ch12 / P2 ch7+ch12, Sub Rosa
  ch7+ch8, The Iron Tide ch7. Program **54** is used by Sub Rosa ch14.
  Program 53 is unused. Any default change to 52/54 alters committed renders.
- **CC70 cannot be the gate**: Winter Guests (4 channels) and Sub Rosa
  (3 channels) already author CC70 on their choir channels. **Channel
  aftertouch cannot be the gate**: Winter Guests and Sub Rosa author ChanAT
  on choir channels (and 52–54 are already aftertouch-eligible).
- **CC73 (GM2 Attack Time / "Sound Controller 4") is authored by no committed
  album on any channel** — the full authored-CC inventory across all scanned
  files is {1, 5, 6, 7, 10, 11, 64, 65, 66, 67, 68, 70, 71, 74, 91, 93, 94,
  100, 101} plus PB/ChanAT; 73 appears nowhere (`map_albums.md`, all album
  tables). CC73's standard meaning (attack/articulation time) is also the
  closest GM2 semantic to "consonant onset".

Semantics: the **first CC73 of any value on a channel flips
`choir2_authored`** (the `mod_authored` pattern, `engine.rs:792–797`); the
value maps to consonant intensity `amt = val/127`. `amt` scales the consonant
*duration* and the breath amount, **not** its presence: a short closed onset
is always sung under the gate (the `hum_hold` floor and the `mouth`-driven
dip/darkening are on for every v2 note — see CH-1), so authoring CC73 = 0 still
produces a brief (~30 ms) closed entry, just with the shortest hold and no
extra breath. Sectioning CH-2 and shimmer CH-3 engage regardless of `amt` —
authorship is the switch, value is the onset amount. Subsequent NoteOns on that
channel with `program ∈ 52..=54` spawn the v2 voice; ringing voices are
unaffected (consonant/scatter are per-note construction properties).

**Cross-section reservation (v0.9 build coordination):** CC73 is reserved as
the choir-v2 gate for the whole v0.9 build. The sibling brass (56–63), reed
(64–71), and engine55-wiring sections must pick *disjoint* authored-CC gates
and order their NoteOn spawn arms so none overlaps the choir arm (§6.3) —
otherwise two families race for the same `Strip` state or spawn branch.

A rejected
alternative: making v2 the default for unused program 53 only — free per
`map_albums.md` but leaves 52/54 (the programs the albums actually use)
unimproved and creates an inconsistent seam; and a re-render waiver for
Sub Rosa/Winter Guests is unjustified when a zero-cost authored gate exists.

### CH-1 — Consonant/breath onset ("mm" → vowel)

Physical model: a bilabial hum radiates mostly through the nose — level
6–10 dB below the open vowel, energy above ~1 kHz heavily damped; the lips
open in 20–60 ms; a breath component (aspiration shaped by the same vocal
tract) rides the transition. Consonant duration 40–150 ms, shorter when the
attack is harder. Three coupled mechanisms on the v2 voice:

1. **Hum hold**: the existing formant morph (`voices.rs:1478–1483`) is
   *frozen* for `hum_hold` samples — `cur` stays at the schwa start
   [500, 1400, 2400] — then released to slew to `tgt` exactly as today.
   `hum_hold = HOLD_BASE(prog) · (1 + HOLD_AMT·amt) · (1.3 − 0.6·vn)` seconds
   (soft notes hold the consonant longer, the `vel_attack` doctrine,
   `voices.rs:1560–1562`).
2. **Mouth opening** (level + brightness shading): a scalar `mouth` (0
   closed → 1 open) starts rising when the hold ends:
   `mouth += CHOIR2_MOUTH_RATE·(1 − mouth)` per control tick
   (0.030/tick → τ ≈ 12 ms, ~90% open in ~28 ms — lips are faster than the
   formant travel). It drives (a) an output gain factor
   `CHOIR2_HUM_GAIN + (1 − CHOIR2_HUM_GAIN)·mouth` (closed = ×0.45,
   −6.9 dB), and (b) a dedicated `OnePole` lowpass post-formant-sum whose
   cutoff is retuned per control tick:
   `900 + 7100·mouth²` Hz (closed lips kill F2/F3 radiation; the square
   keeps it dark until the mouth is well open). Both exist **only** on the
   v2 voice — v1 render path untouched.
3. **Breath transient**: reuse the existing pre-filter breath injection
   point (`voices.rs:1507–1509`) so onset air is *vowel-coloured* by the
   same formant bank: `breath_now = breath + breath_env`, with
   `breath_env` initialized to `0.10·amt·(0.3 + 0.7·vn)·BR_MUL(prog)` and
   decaying at `t60_mul(0.09, sr)` per sample (t60 = 90 ms). The sustain
   breath floor stays 0.02.

Interaction with CC70 (Winter Guests / Sub Rosa style authoring, if a v2
channel also authors it): `set_vowel` (`voices.rs:1539–1551`) keeps its exact
v0.7 semantics (instant `tgt`/`qs`/`gains` overwrite, engine-slewed per block
at `engine.rs:1040–1046`); the hum hold merely delays when `cur` starts
travelling — the consonant precedes whichever vowel the wheel chose. NoteOn
vowel snap (`engine.rs:744–747`) is unchanged.

### CH-2 — Per-voice pitch scatter: fake SATB sectioning

Replace the 4-layer linear fan with **8 layers = 2 per section** (S, A, T, B)
for programs 52/53 (54 differs, §5). Each layer's ratio is drawn per note:

```
ratio_i = 2^((sec.off_cents + white()·sec.scatter_cents) / 1200)
```

so no two notes — and no two layers — ever land on the same micro-tuning
(the round-robin doctrine, `voices.rs` §4 conventions). Sections encode the
real choral tells (Ternström-style section dispersion is ~±5–13 cents, worse
in low voices; tenors systematically lean sharp, basses sag flat; low voices
drift more and wobble slower):

- **Register weighting** — the "sectioning" half: each section has a
  full-weight key range; outside it the section's gain fades linearly over
  `CHOIR2_REG_FADE = 7` semitones down to a floor `CHOIR2_REG_FLOOR = 0.25`
  (never fully mute — an 8-layer voice must not collapse to 2). A key-45
  pedal note is bass/tenor-dominated; a key-76 line is soprano-dominated.
  Gains are **renormalized at construction** so mean gain = 1
  (`g_i ← g_i·N/Σg`), which keeps the existing render normalization
  `s /= layers.len()` (`voices.rs:1506`) bit-identical for v1 and level-flat
  across the keyboard for v2.
- **Beat audibility check** (the CYM-1 lesson, recomputed): scatter sources
  are sustained oscillators, not ring-limited resonators, so the ring-time
  constraint is trivially satisfied; two bass layers ±10 cents apart at
  key 48 (130.8 Hz) beat at ≤ ~1.5 Hz — a slow section undulation, present
  for the whole held note. Δf at the widest spread (soprano pair, key 79,
  784 Hz, ±4 cents) ≈ 3.6 Hz — still choral, not chorus-pedal.

Implementation: `Layer` gains a `gain: f32` field (v1 constructor writes 1.0;
render becomes `s += l.osc.next() * l.gain` — multiply by 1.0 is bit-exact).

### CH-3 — Vibrato shimmer: staggered per-voice onset

Move `vib_delay`, the ramp length, **and the vibrato depth** off the stack
(`voices.rs:1384–1385`, `1450–1455`, and `self.vib_depth` at `voices.rs:1384`
used at `voices.rs:1459–1460`) **into `Layer`**: `vib_depth: f32`,
`vib_delay: u32`, `vib_ramp_s: f32`. Depth must be per-layer because the §4
`vib_depth_mul` column and the §5 program-54 depth (0.005) demand a *different*
vibrato depth per section/program — a single stack-level field cannot express
that. `control_tick` reads `layer.vib_depth` (not `self.vib_depth`) at
`voices.rs:1459–1460`. The v1 constructor copies the current stack globals into
every layer — depth = the old stack `vib.1` (0.004 for choir), delay/ramp =
the old globals — with **no new RNG draw** (identical arithmetic →
bit-identical output). The v2 constructor draws per layer:

- `vib_delay ~ U(sec.vib_delay.0, sec.vib_delay.1)` seconds (section-scaled;
  singers settle onto the note before wobbling, basses last);
- `vib_ramp_s ~ U(0.5, 1.2)` (v1 is fixed 1.0);
- rate = 4.6 Hz × sec.vib_rate_mul × (1 ± 15%) (existing jitter,
  `voices.rs:1426`); depth = 0.006 × sec.vib_depth_mul (v1 0.004; 0.006 →
  ±10.4 cents peak — modest choral vibrato, deliberately small because the
  chorus bus already adds 0.30 send width, `engine.rs:253–269`).

Net effect: the ensemble's aggregate FM incoherence *grows* through the first
~1.5 s — the shimmer bloom — instead of a synchronized switch-on at 0.30 s.

### CH-4 — Melisma legato (small, closes a CH-1 interaction)

`SawStack` gets a `legato_to(key, vel)` implementation that returns `true`
**only when the choir extension is present** (v1 stacks keep the trait
default `false`, `voices.rs:36`, so CC68 behavior on strings/pads/v1-choir is
untouched): it sets `base_f = key_freq(key)` (layers keep their scatter
ratios; `control_tick` retunes next tick via `voices.rs:1465–1468`) and does
**not** re-trigger the consonant or breath. Rationale: without this, CC68 or
fast repeated notes on a v2 channel would machine-gun the "mm" onset; a real
choir sings a melisma on one vowel. Engine eligibility already exists
(`engine.rs:694–704`).

### New symbols (all in `voices.rs`, adjacent to `choir()`, house style §5)

```rust
/// CH-2: one SATB section. Cents are relative to the written pitch.
pub(crate) struct ChoirSection {
    pub off_cents: f32,        // systematic intonation lean
    pub scatter_cents: f32,    // ± uniform per-note draw
    pub drift: f32,            // Drift depth for this section
    pub vib_rate_mul: f32,     // × 4.6 Hz base
    pub vib_depth_mul: f32,    // × 0.006 base
    pub vib_delay: (f32, f32), // s, per-layer uniform draw range (CH-3)
    pub reg: (u8, u8),         // full-weight key range (CH-2 register)
}
pub(crate) const CHOIR2_SECTIONS: [ChoirSection; 4]; // S, A, T, B — §4
const CHOIR2_REG_FADE: f32 = 7.0;    // semitones of gain fade outside reg
const CHOIR2_REG_FLOOR: f32 = 0.25;  // a section never fully mutes
const CHOIR2_HUM_GAIN: f32 = 0.45;   // −6.9 dB closed-lips level (CH-1)
const CHOIR2_MOUTH_RATE: f32 = 0.030; // mouth-open slew per CTRL tick
const CHOIR2_HUM_LP: (f32, f32) = (900.0, 8000.0); // closed→open cutoff Hz
const CHOIR2_BREATH_T60: f32 = 0.09; // onset breath decay, seconds

struct ChoirExt {              // Option<ChoirExt> on SawStack; None = v1
    hum_hold: u32,             // samples: morph frozen, mouth closed
    mouth: f32,                // 0 closed → 1 open
    hum_lp: OnePole,           // CHOIR2_HUM_LP sweep, post-formant
    breath_env: f32,           // one-shot extra breath amplitude
    breath_mul: f32,           // t60_mul(CHOIR2_BREATH_T60, sr)
}

pub fn choir_v2(program: u8, key: u8, vel: u8, sr: f32, seed: u32, amt: f32)
    -> SawStack               // the factory the engine calls when gated in
```

`SawStack` changes: `ext: Option<ChoirExt>` field; `Layer` gains
`gain: f32`, `vib_depth: f32`, `vib_delay: u32`, `vib_ramp_s: f32` (v1 values:
1.0, the old stack `vib.1` = 0.004, the old global delay, 1.0). The stack's own
`vib_depth` field (`voices.rs:1384`) is removed — its value now lives per layer.
`#[cfg(test)] kind()` returns `"choir2"` when `ext.is_some()`, else
`"sawstack"`. `voices::make` always builds v1 (`ext = None`), so its routing
pin stays `"sawstack"` (`testutil.rs:552–597`); the `"choir2"` discriminant is
reached only through the engine's gated spawn (CH-O1).

## 4. Parameters table

`CHOIR2_SECTIONS` (S, A, T, B):

| section | off_cents | scatter ±cents | drift | vib_rate_mul | vib_depth_mul | vib_delay (s) | reg full range (key) |
|---|---|---|---|---|---|---|---|
| Soprano | +3 | 4 | 0.0035 | 1.12 | 1.00 | 0.20–0.55 | 60–84 |
| Alto | −2 | 6 | 0.0040 | 0.97 | 0.95 | 0.30–0.60 | 53–74 |
| Tenor | +5 | 8 | 0.0045 | 1.05 | 0.90 | 0.28–0.58 | 47–69 |
| Bass | −6 | 10 | 0.0055 | 0.85 | 0.70 | 0.35–0.80 | 36–62 |

Reasoning: offsets ≤ 6 cents keep the *centre* of the cluster on pitch
(harmony intact) while giving each section a recognizable lean; scatter grows
toward the low voices (pitch matching degrades with register); vibrato slows
and shallows toward the basses (physiology). The delay ranges are deliberately
spread soprano-earliest (0.20 s low) to bass-latest (0.80 s high): with 2 draws
per section the expected onset span across the 8 layers is E[max bass] −
E[min soprano] ≈ 0.65 − 0.32 = 0.33 s, comfortably clearing CH-O6's 0.25 s
stagger bound with seed margin (the pre-widening 0.25/0.70 ranges gave only
≈0.23 s — below the bound and seed-fragile).

CH-1 onset (base values, before per-program multipliers of §5):

| parameter | value | physical reasoning |
|---|---|---|
| `hum_hold` | `(0.035 + 0.075·amt)·(1.3 − 0.6·vn)` s | 35–143 ms consonant; harder sung = shorter closure |
| `CHOIR2_MOUTH_RATE` | 0.030/tick (τ ≈ 12 ms, ~90% in 28 ms) | lips open in tens of ms, faster than the ~40 ms formant travel already in `control_tick` |

## 6. Engine integration

All engine work is one CC handler, two `Strip` fields, and one NoteOn branch:

1. **`Strip` fields** (`Strip`, `engine.rs:481–532`; defaults in
   `Strip::new`, `engine.rs:534–585`): `choir2_authored: bool` (false),
   `choir2_amt: f32` (0.0).
2. **CC73 handler** in the event-time CC match (insert near the CC71 arm,
   `engine.rs:892–902`): `73 => { s.choir2_amt = val as f32 / 127.0;
   s.choir2_authored = true; }` — stored for all channels, *effect* gated on
   program at NoteOn (the CC67/CC70 eligibility pattern, `engine.rs:707–714`,
   `744–747`). A mid-song CC73 change affects subsequent NoteOns only
   (construction property, like velocity) — documented semantics, no slew.
3. **NoteOn spawn branch** (`engine.rs:726–737`): after the ch-9 arm, before
   the generic `voices::make`:
   `else if strips[ch].choir2_authored && matches!(strips[ch].program, 52..=54)
   { Some(Box::new(voices::choir_v2(program, key, vel, sr, seed,
   strips[ch].choir2_amt))) }`. The existing post-spawn writes — `set_pitch`
   for bend (`engine.rs:741–743`), `set_vowel` for authored CC70
   (`engine.rs:744–747`), portamento origin (`engine.rs:750–762`) — apply
   unchanged (v2 is a `SawStack`; `set_pitch` stores the composed multiplier,
   `voices.rs:1534–1537`, satisfying INT-2/3/5).
4. **Family predicates**: no change. 52–54 stay in `aftertouch_family`
   (`engine.rs:70–72` — Sub Rosa / Winter Guests ChanAT keeps working on both
   v1 and v2) and stay **out** of `vibrato_family` (`engine.rs:61–64`) — the
   shimmer is voice-internal; CC1 on choir remains a no-op. `fx_profile`
   (`engine.rs:253–269`) unchanged.
5. **Legato**: no engine change — CC68 eligibility is channel-level
   (`engine.rs:694–704`); CH-4 lives in the voice.
6. **Stereo/Haas disposition** (required statement, mono-collapse lesson):
   this design touches no panning, no Haas, no new bus. Choir width continues
   to come from the chorus send (0.30) and per-layer decorrelation. The Haas
   micro-delay stays authored-CC10-only (`engine.rs:838, 1131–1148`).
7. **INT-6 (wah × internal resonance) bound**: v2 adds no resonant peak — the
   hum filter is a first-order `OnePole` lowpass and formant Qs are unchanged
   (max 12, from `VOWEL_ANCHORS[0]`) — so the worst-case series stack with an
   authored CC71 wah (Q ≤ 8) is exactly today's, already shipped.
8. **INT-7 (pedal-deferred note_off)**: the only release path is the existing
   `env.release()` (`voices.rs:1526–1528`); CH-1/CH-2/CH-3 are onset/sustain
   mechanisms, so simultaneous pedal-lift releases stay benign. No release
   consonant is designed (deliberate non-goal: a release "m" would fire in
   unison for pedal-held chords — the INT-7 trap).

## 7. Opt-in & regression safety

- **The gate**: v2 engages only when a channel has authored CC73 *and* the
  program at NoteOn is 52–54 (CH-0). Grounded in `map_albums.md`: **no
  committed album authors CC73 on any channel** (authored-CC inventory across
  Hollow Hill, The Signal Fire, Winter Guests, Sub Rosa, The Iron Tide — §
  "Safety answers" plus every per-file table). Therefore every committed
  render — including the choir-heavy Winter Guests (52 on four channels, with
  CC70 + ChanAT) and Sub Rosa (52 on ch7/ch8, 54 on ch14, with CC70 + ChanAT
  + RPN) — takes the untouched v1 path.
- **RNG discipline** (map_docs §2.2 corollary): the v1 construction path is
  code-identical — `choir()`/`strings()`/`pad()` still call the existing
  `SawStack::new`, which draws exactly the same `Rng` sequence. All new draws
  (scatter, per-layer vibrato delay/ramp) happen only inside `choir_v2()`'s
  own constructor. New `Layer`/`SawStack` fields are *copied* values (gain
  1.0, the old global delay/ramp), never drawn, and the v1 render arithmetic
  is bit-preserved (×1.0 multiply; `s /= len` untouched; the morph-freeze
  test is `ext.map_or(true, …)`).
- **Proof at integration** (doctrine, map_docs §1.6): build the v0.8.1
  baseline binary in a scratch `git worktree add`, render **all committed
  albums** with old and new binaries, `cmp` byte-identical — with the six
  choir-authoring files called out explicitly as the high-risk set.
- **Fixture**: `reference_song()` (`testutil.rs:188–269`) authors no CC73 —
  the `GOLDEN` table (`testutil.rs:440–467`) needs **no recapture**; ch7/ch8
  canaries stay bit-exact by construction. v2 oracles use local mini-songs in
  `engine.rs`/`voices.rs` tests (the CC70-test pattern, `engine.rs:2055`).
  If the eventual v0.9 build recaptures the fixture for *other* families
  (brass channels), the choir rows become canaries for this design — record
  BIT-EXACT status in the table comment as usual.
- **Version/integration**: rides the single v0.9 task branch and its one
  0.8.1 → 0.9.0 bump; no separate bump for this section.

## 8. Verification oracles (machine-checkable; this machine has no ears)

All oracles are `cargo test`s using existing calibrated helpers
(`testutil::rms/band_rms/hp_rms/mag_at/centroid/peak_locate/flatness`,
`testutil.rs:17–179`; no new helper → no new oracle-0 calibration). Every
*feature* oracle is fail-first *by construction*: on v0.8.1 `main`, CC73 does
not exist, so the "v2" render equals v1 and the assertion fails. Standard
probe note unless stated: program 52, key 60 (C4, 261.6 Hz — inside every
section's fade reach), vel 96, CC73 = 96 at t = 0, held 3.0 s, solo render at
44100 Hz, `wet = 0` (dry stem; presence-in-MIDI ≠ audibility lesson).

- **CH-O1 (guard) v1 path untouched.** Two seams, at the two layers that own
  the routing decision:
  - `gm_routing_pins_voice_kinds` (`testutil.rs:552–597`) keeps its existing
    `(52, "sawstack")` pin **unchanged**: `voices::make` always builds v1
    (`ext = None`), so a direct `make(52, …)` can never yield `"choir2"` — the
    pin proves the un-gated path is still the v1 SawStack.
  - The `"choir2"` discriminant is an *engine* property (it needs authored
    CC73), so it is checked in an engine mini-song test in the
    `cc70_vowel_morph_opens_formants` style (`engine.rs:2055`): a two-channel
    song where channel A (program 52, no CC73) spawns a voice whose
    `kind() == "sawstack"` and channel B (program 52, CC73 authored before its
    NoteOn) spawns one whose `kind() == "choir2"`. This is the direct test of
    the gate; the album byte-compare of §7 is the cross-binary proof that the
    un-authored render is bit-identical.
- **CH-O2 (feature) consonant darkness.** On the probe note, spectral
  `centroid` over [20, 90] ms < **0.55 ×** centroid over [500, 900] ms.
  Fail-first: v1's schwa morph plus its slow attack leaves the early/late
  centroid ratio ≳ 0.8 (calibrate the exact main-baseline value when
  building; threshold sits below it with margin).
- **CH-O3 (feature) consonant level shading + breath, differential.** Render
  the probe note twice, same seed, CC73 = 127 vs CC73 = 0 (both v2 → same RNG
  stream; only `amt` differs). The difference signal's RMS over [0, 200] ms
  ≥ **6 dB** above its RMS over [1.0, 1.2] s (the consonant is an onset
  phenomenon), and `flatness([20, 90] ms, 800–4000 Hz)` for amt = 127 is
  ≥ **1.5 ×** the amt = 0 value (breath is noise). Fail-first: on main CC73
  changes nothing → difference signal ≈ 0 → the ratio is undefined/fails.
- **CH-O4 (feature) scatter, structural.** Expose `pub(crate)` layer
  inspection (`#[cfg(test)] fn layer_ratios(&self) -> Vec<f32>` on `SawStack`):
  for two different seeds at key 60, (a) every ratio is within
  ±(|off| + scatter) of its section spec, (b) the tenor-pair mean ratio > 1.0
  and the bass-pair mean < 1.0 (the systematic ±cent leans), (c) the two seeds'
  ratio sets are disjoint (round-robin — no shared micro-tuning).
  **No spectral cluster-width sub-oracle** (an earlier draft asserted v2's
  band-energy cluster is *wider* than v1's — it is not): by the §4 numbers v2's
  total dispersion is std ≈ 6 cents (systematic ≈ 4.3 + per-note scatter
  ≈ 4.2, widest pair bass ±10 / soprano ±4 cents), *tighter* than v1's fixed
  ±15.5-cent 4-layer fan. A narrow/wide `band_rms` ratio would therefore move
  the **opposite** way to "more singers", so it is the wrong probe. The
  structural ratio bounds above are the sound test of scatter; the audible
  ensemble width comes from the decorrelated per-layer vibrato and drift
  (verified by CH-O6), not from a wider static pitch cluster.
- **CH-O5 (feature) register weighting, structural.** The ratio test must run
  on the **pre-renormalization** register weights, *not* the post-renorm
  `layer_gains()` — because renorm forces Σg/N = 1, a key that floors the
  tested section also floors most others, inflating the renorm factor and thus
  the floored section's *absolute* gain (e.g. soprano key-40 renorm ≈ 2.29 vs
  key-72 ≈ 1.37 makes the post-renorm ratio ≈ 0.42, which would *fail* a
  "≤ 0.35" bound that the design's own construction is meant to satisfy).
  Expose a second accessor `#[cfg(test)] fn layer_reg_weights(&self) ->
  Vec<f32>` returning the raw register weight per layer (1.0 in-range, linearly
  faded to `CHOIR2_REG_FLOOR` = 0.25 beyond `CHOIR2_REG_FADE`). Assert: soprano
  reg-weight at key 40 ≤ **0.35 ×** its key-72 weight (0.25 / 1.0 = 0.25 —
  passes with margin); bass reg-weight at key 79 ≤ 0.35 × its key-50 weight
  (also 0.25). Separately, on the post-renorm `layer_gains()`: Σgains/N =
  1 ± 1e-4 (level flatness, the invariant that keeps `s /= len` bit-safe) and
  every gain ≥ `CHOIR2_REG_FLOOR` × renorm-factor. Audio-level register colour
  is deliberately untested-by-design: the formant bank dominates the centroid,
  so a spectral check would measure the wrong thing.
- **CH-O6 (feature) shimmer.** (a) Structural: the 8 drawn `vib_delay`s span
  ≥ **0.25 s** (max − min) and are not all equal; ramps span ≥ 0.3 s.
  (b) Audio: FM sideband growth — with a 1.0 s Goertzel window, the maximum
  of `mag_at` over the grid f ± {3.0 … 7.0} Hz (0.5 Hz steps), relative to
  `mag_at(f)`, rises by ≥ **6 dB** from window [0.1, 1.1] s to
  [1.8, 2.8] s (vibrato absent early, blooming late; carrier leakage at
  ±4.6 Hz with a 1 s window is ~−23 dB, well under the expected
  ~−10 dB sidebands, so the measurement resolves).
- **CH-O7 (guard-of-design) level match.** v2 probe-note RMS over
  [0.5, 2.5] s within **±1.5 dB** of the v1 render of the same note/vel —
  this oracle *pins* the provisional amps (1.55 / 1.35); tune the constant,
  not the tolerance.
- **CH-O8 (feature, INT-2/3/5) pitch completeness under modulation.** v2
  note with authored pitch bend +2 semitones and ChanAT pressure:
  `peak_locate(seg[1.0, 2.0] s, sr, f·2^(2/12)·0.94, f·2^(2/12)·1.06)` lands
  within ±1.5 % of the bent frequency (`peak_locate`, never zero-crossings —
  lessons file). Proves scatter ratios compose with `bend` rather than being
  snapped back by the per-block writers (`engine.rs:1049–1074`).
- **CH-O9 (feature) CC70 interplay.** v2 + CC70 = 127 ("eh") authored before
  NoteOn: sustain window `band_rms(1900 Hz, Q 8)` > `band_rms(1120 Hz, Q 8)`
  (the wheel still steers the vowel), *and* CH-O2's early-window darkness
  still holds (the consonant precedes the vowel).
- **CH-O10 (feature) melisma legato.** CC68 + CC73 authored, two overlapping
  NoteOns C4→D4: exactly one voice spawns (poly stat), sustain pitch after
  the slur = D4 ±1 % via `peak_locate`, and the difference-vs-retrigger
  render shows **no** second consonant: `hp_rms([slur, slur+100 ms], 1500)` ≤
  1.3 × the adjacent sustain value (no fresh breath burst).
- **CH-O11 (guard) determinism.** Two identical renders of the CH-O2
  mini-song are bit-identical (per-binary determinism, `Rng` per spawn —
  extends oracle 35's coverage to the v2 path).

## 9. Size & risks

**Size: M (lower half).** ~300 lines in `voices.rs` (`ChoirSection` consts,
`ChoirExt`, the `choir_v2` constructor, ~40 lines of branch code in
`control_tick`/`render`, `legato_to`), ~25 lines in `engine.rs` (2 Strip
fields, CC73 arm, NoteOn branch), ~300 lines of tests. **No new DSP
primitives** — reuses `OnePole`, `Drift`, `Biquad::bandpass`, `t60_mul`, the
existing formant machinery. No sample bank, no fixture recapture.

| Risk | Where | Mitigation |
|---|---|---|
| Bit-drift on the v1 path from shared-struct edits (the real killer) | `SawStack`/`Layer` field additions, render loop | Copied-not-drawn fields, ×1.0 multiplies, `ext.map_or(true, …)` guards; CH-O1 + album byte-compare + golden canaries |
| CPU ×2 per choir note (8 saws + 8 Drifts + OnePole) | Sub Rosa-scale choir polyphony, future songs | Bounded (~2× one family); `render_budget_advisory` (oracle 38) re-run; only opted-in channels pay |
| 8-layer averaging changes perceived level vs v1 | `choir_v2` amp | CH-O7 pins ±1.5 dB; amp constants are the tuning knob |
| Consonant machine-guns on fast repeated notes without CC68 | CH-1 × dense authoring | Velocity shortens the hold; CH-4 covers slurred lines; authoring guidance (low CC73 for fast passages) — accepted residual |
| `amt = 0` semantics surprise (authoring CC73 = 0 still engages scatter/shimmer and a short closed onset) | CH-0 | Documented as the feature's definition (authorship = switch; value scales consonant *duration*/breath, not presence — a ~30 ms closed entry is always sung under the gate); CH-O3 encodes the amt-driven part |
| Sub-octave layers muddy low 54 chords | §5 program 54 | Subs disabled below key 48; 54 is used only on Sub Rosa ch14 (8 note-ons) and only under the gate |
| Scatter widens unison collisions when two v2 channels double the same line | CH-2 | Bounded by ±10 cents worst case (< the existing chorus bus depth); accepted, note for composers |
| Oracle thresholds mis-calibrated (the ORC-3/-5 class of failure) | §8 | Each threshold states its main-baseline expectation; calibrate CH-O2/CH-O4 against measured v1 values before pinning, per the fail-first discipline |

Honest caveat (standing): every oracle is a measurable proxy; the true
acceptance ceiling is a human A/B listen of an opted-in render, which this
machine cannot perform.
