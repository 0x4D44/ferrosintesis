# Design section: Drums — kit v2 behind an opt-in kit-version seam (DR0–DR4)

Target: hollowsynth v0.8.1 → v0.9. All line anchors are exact for v0.8.1
(`fable5/hollowsynth/src/…`); structural anchors (fn/struct names) are given
alongside so the section survives drift. All Hz/time thresholds assume the
default 44100 Hz `Options.sr`; test renders pin `sr = 44100.0`.

Mechanism ids: **DR0** (the seam), **DR1** crash sine-tail, **DR2** tom
pitch-drop, **DR3** static open hat, **DR4** plain-noise snare rattle. Each
closes the correspondingly-numbered tell in `map_drums.md` §4 (T1–T4).
Oracles are labelled DR-O1… (renumber into the assembled HLD's global
catalogue at merge time).

---

## 1. Goal

Fix the four loudest synthetic tells of the channel-10 kit — the crash's
lone-sine tail, the toms' 21-semitone "pew", the gated-static open hat, and
the filtered-static snare rattle — **without changing a single committed
render**. Every fix engages only when a MIDI file *authors* a kit selection
(Program Change on channel 10); a file that never does renders byte-identical
to the v0.8.1 binary. Success is measured, not heard: each fix has a
differential numeric oracle on rendered audio (this machine has no ears).

## 2. Current state (what exists, precisely)

- Every hit is a `Drum` (`drums.rs:33-42`): `Vec<Tone>` pure-sine partials
  with exponential decay and optional downward glide floored at
  `min_freq = 0.3 × start` (`drums.rs:81-86`), plus `Vec<NoiseBand>` fixed
  biquads all consuming **one shared white draw per sample**
  (`drums.rs:164`). Extensions: `with_band_ext` delayed onset/swell
  (`drums.rs:127-136`), `with_bursts` re-triggers (`drums.rs:116-122`),
  `choke()` (`drums.rs:192-201`).
- `drums::make(key, vel, sr, seed)` (`drums.rs:331-675`) builds per-key
  voices; the engine spawns via `if ch == 9 { drums::make(...) }`
  (`engine.rs:726-727`) and **never reads `strips[9].program` on that path**.
  `EvKind::Prog` on ch 10 is stored but render-inert today
  (`engine.rs:938-955`; it zeroes chorus/delay sends which the D9 drum pass
  never taps, `engine.rs:1201-1209`). Bank select CC0/CC32 falls through the
  CC match's `_ => {}` (`engine.rs:919`).
- The four tells (measured detail in `map_drums.md` §4):
  - **T1 crash 49|57**: 6 sines t60 2.6→1.0 s outlive the wash+pairs
    (t60 1.9 s); decay rates 23.1 dB/s (950 Hz partial) vs 31.6 dB/s (wash)
    → the tail collapses to a stationary 950 Hz line (`drums.rs:462-481`).
  - **T2 toms 41–50**: glide 10 oct/s (D1-scaled 6–14) to the 0.3× floor =
    −20.9 semitones over ~125–290 ms (`drums.rs:403-426`, `tom_tones`
    :243-249). Real toms overshoot 1–3 st and settle in 30–80 ms.
  - **T3 open hat 46**: one fixed HP-6000 band, one scalar exponential
    (t60 0.28 s), `swell:false, pairs:false` — character at 20 ms equals
    character at 600 ms, only quieter (`drums.rs:445-461`).
  - **T4 snare 38|40**: "wires" = white through a broad HP 2800 Q 0.7 slope,
    smooth t60 0.19 s; no granularity, no wire resonance, no coupling to the
    186 Hz head (`drums.rs:370-391`).
- Album exposure: every committed album plays exactly these keys (crashes,
  open hat, toms, snares — `map_albums.md` per-file "Channel 10 detail"),
  so **none of these fixes may change the default path**.

## 3. Design

### DR0 — the kit-version seam (land first; everything else depends on it)

**Gate**: a Program Change authored on channel 10 (engine ch index 9) —
GM2 kit-select semantics. `map_albums.md` §(c) confirms: **no committed
album (nor any local demo) sends Program Change or Bank Select on channel
10** — this is a never-before-authored, fully inert signal today.

**Semantics**: gate on *event seen*, not value. Any `Prog` event on ch 10
selects kit v2 for all subsequently spawned hits; a file that never sends
one gets kit v1 forever. Rationale: `Strip::new` defaults `program = 0`
(`engine.rs:534-585`), so a value test cannot distinguish "authored PC 0"
from "never authored" — the authored *flag* can. Deliberate GM2 deviation,
documented: GM2 PC 1 (0-based 0) means "Standard Kit"; hollowsynth reads
any ch-10 PC as "give me the current best kit". The PC value is stored in
`strips[9].program` as today, reserved for future named kits (Room/Power);
v0.9 defines exactly two: v1 (legacy) and v2. Kit is read at NoteOn spawn
time, so a mid-file PC switches subsequent hits; already-ringing voices are
untouched.

**Mechanic** (exact edits):

1. `drums.rs`: `#[derive(Clone, Copy, PartialEq, Eq)] pub enum Kit { V1, V2 }`.
2. `engine.rs` `Strip` (struct at :481-532): new field `kit: drums::Kit`,
   default `Kit::V1` in `Strip::new` (:534).
3. `EvKind::Prog` handler (`engine.rs:938-955`): line 941 is a
   value-producing expression (`let (cho, del) = if ch == 9 { … };`), not a
   statement block, so nothing can be added *inside* it. Instead add a
   separate guarded statement immediately after `s.program = prog;`
   (`engine.rs:940`): `if ch == 9 { s.kit = drums::Kit::V2; }`. No other
   handler changes — Bank Select stays ignored (non-goal, §3 note below).
4. Spawn site (`engine.rs:727`):
   `drums::make(key, vel, sr, seed, strips[9].kit)`. Signature of
   `drums::make` gains the trailing `kit: Kit` parameter; in-crate test
   call sites updated mechanically with `Kit::V1` so all existing oracles
   (20–33, `drums.rs:677-1045`) keep pinning the legacy kit. The out-of-crate
   caller `crate::drums::make(38, 100, SR, 7)` at `testutil.rs:587` gains the
   same trailing `Kit::V1` (see §6).
5. Inside `make`, only the arms for keys 49|57, 41|43|45|47|48|50, 46, and
   38|40 branch on `kit`; every other key ignores it.

**Bit-identity discipline** (the load-bearing constraint, from
`map_docs.md` §2.2 determinism corollary): on the `Kit::V1` path the
constructed `Drum` must be field-for-field identical to v0.8.1 — same
tables, same builder calls, and **the same number and order of RNG draws**
(`Drum::new` draws edge/jf/jd + per-tone/per-band jitter from the seeded
`Rng`, `drums.rs:58-103`). All v2 mechanisms below therefore (a) live in
`Option<…>` fields that are `None` on v1, and (b) consume only the
**already-drawn** shared per-sample white (`drums.rs:164`) — zero new draws
on either path at render time. Construction-time draws for v2-only jitter
happen strictly inside `if kit == Kit::V2` blocks *after* all v1 draws, so
the v1 sequence is untouched.

**Interactions preserved** (the D9 minefield, `map_docs.md` §2.2): kit
selection changes voice *construction* only. The D9 stereo drum pass with
strip parity — CC7/CC11 gain, CC10 pan offset on the `drum_pan` table,
CC74/71 stereo wah pair, CC91 hall + fixed `ROOM_SEND 0.35`
(`engine.rs:1164-1211`) — is untouched and applies identically to both
kits (`drum_strip_parity_preserved`, `engine.rs:1375-1421`, stays green
unmodified). The hat mutual-choke group (`engine.rs:717-724`) is
key-driven, kit-agnostic; every v2 mechanism must honour `choke()`
(DR-O9). Pitch bend reaches ch-9 voices (`engine.rs:929-931` has no ch
guard) but `Drum` keeps the trait's no-op `set_pitch` default in v2 — the
latent seam stays latent, stated deliberately.

**Non-goals**: Bank Select gating (CC0=120+PC is GM2-correct but is two
events and a new CC handler for zero added safety — a bare ch-10 PC is
equally unauthored; a file that sends CC0 120 *then* PC still works, the
CC0 being ignored). Multiple named v2 kits (Room/Power/Jazz). New drum
keys. Any change to ride 51|59, china 52, splash 55, bell 53 (they have
tells too, but they are not the four loudest — deferred, trigger: a v2
listen flags them).

### DR1 — crash sine-tail (keys 49, 57) — closes T1

A real crash tail stays stochastic to silence; the fix inverts the decay
ordering (no tonal partial may outlive the wash), densifies the partial
field, and couples a slow noise shimmer onto everything.

**(a) Decay-order inversion.** v2 crash 49: tone `t60_first 2.6 → 1.7 s`,
`t60_last 1.0 → 0.9 s`; wash `t60 1.9 → 2.6 s` **with amp `1.0 → 0.85`**
(`CRASH_WASH_AMP_V2`, the crash level knob — see (e)); beat pairs get their
own `t60 2.8 s` (decoupled from the wash via a new `CymSpec` field
`pairs_t60: Option<f32>`, default `None` = share wash t60 as today,
`drums.rs:265-284, 301-317`). Crash 57: `t60_first 1.6`, same wash/pairs.
Numeric consequence: every tonal partial now decays ≥ 60/1.7 = 35.3 dB/s
while the wash decays 23.1 dB/s and the pairs 21.4 dB/s — the wash starts
~17 dB above the 0.13-amp fundamental (map_drums §4 T1) and *never*
crosses below it. The tail is stochastic for the entire 4.2 s life.
Physical reasoning: in a real crash the low bell modes are strongly
coupled into the high-mode chaos and bleed energy out fast; the long tail
is the mid/high stochastic shimmer.

**(b) Denser late partial field — detuned twins.** Each of the 6
`METAL_RATIOS` partials gets a twin at `f + CRASH_TWIN_DF_HZ[i]` with
`CRASH_TWIN_DF_HZ = [5.6, 7.9, 9.3, 11.7, 14.2, 17.5]` Hz — 12 partials
total, pairwise beating at 5.6–17.5 Hz (shimmer range, below the ~20 Hz
roughness border). Ring-time check (the CYM-1 lesson): these are *sine*
pairs, not noise-fed resonators — each pair's coherence time is its
amplitude t60 (≥ 0.9 s), ≥ 50× the longest beat period (1/5.6 = 179 ms),
so the beats survive trivially; stated for completeness. Twin amp
= 0.7 × primary; primary renormalised × 0.82 so summed pair power matches
the v1 single partial: 0.82² + (0.82·0.7)² = 1.002 — level-neutral by
construction (DR-O10 bounds it).

**Slice ordering (deterministic).** The 12 tones are laid out **interleaved,
each twin immediately after its primary**: `[p0, t0, p1, t1, …, p5, t5]`.
This is load-bearing, not cosmetic: `Drum::new` computes each tone's edge
tilt from `modal = i/(n_tones−1)` (`drums.rs:72-87`), so a primary and its
twin — adjacent indices — land at near-identical `modal` and receive
near-identical tilt, keeping each pair's summed power at the level-neutral
0.82²+(0.82·0.7)² the `CRASH_TONE_NORM` derivation assumes. A blocked
`[6 primaries, 6 twins]` layout would push each twin to a different `modal`
than its primary, skewing the per-pair tilt and desynchronising the parity
the DR-O10 calibration relies on. The v2-only per-partial phase/amp jitter
draws for the twins therefore also occur in this interleaved order, strictly
after all v1 draws (bit-identity discipline, DR0).

**(c) Low-mid noise pair where the old sine tail lived.** Add a third
CYM-1 pair at **1180 / 1196 Hz** (Δf = 16 Hz → 62.5 ms beat), Q 800, amp
4 × wash, t60 = pairs t60 2.8 s. Both beat constraints hold numerically:
Δf 16 Hz > f/Q = 1.5 Hz, and ring time Q/(πf) = 800/(π·1180) = 216 ms
spans the 62.5 ms beat period (the lesson: Q/(πf) must span any beat
period relied on — 3.5× margin). This puts beating *noise* into the
700–1500 Hz region exactly where the stationary 950 Hz line used to be
the last survivor.

**(d) Noise-coupled shimmer AM.** New optional per-voice modulator:

```rust
struct Shimmer { lp: OnePole, depth: f32, norm: f32 }   // drums.rs, new
```

Built as `Shimmer::new(rate_hz, depth, sr)`:
`lp = OnePole::lowpass(rate_hz, sr)` (`dsp.rs:109-130`), and
`norm = ((2.0 - a) / a * 3.0).sqrt()` — the analytic 1/σ of a
one-pole-filtered uniform white in [-1,1) (variance a/(2−a) · 1/3), so
`depth` is in true modulation-index units. **`a` cannot be read off the
constructed `OnePole`**: it is a private field (`dsp.rs:110`, no accessor)
and `Shimmer` lives in `drums.rs`. Recompute it locally from the same public
formula `OnePole::lowpass` uses (`dsp.rs:116`):
`let a = 1.0 - (-2.0 * PI * (rate_hz / sr).min(0.49)).exp();` before forming
`norm`. (Alternative: add a `pub fn coeff(&self) -> f32` accessor to
`OnePole`; the local recompute is preferred as it touches only `drums.rs`.)

Render hook in `Drum::render` (`drums.rs:140-182`): after the
shared `white` draw at :164, `let am = if let Some(sh) = &mut self.shimmer
{ (1.0 + sh.depth * sh.norm * sh.lp.process(white)).clamp(0.0, 2.0) } else
{ 1.0 };` and the whole sample sum is multiplied by `am`. **Reuses the
existing shared white draw — zero extra RNG draws**, so v1 (shimmer
`None`, multiply-by-1.0 skipped via the `Option`) stays draw-identical.
Crash setting: `Shimmer::new(9.0, 0.35, sr)` — a ~9 Hz random-walk flutter,
matching the irregular 5–15 Hz surface-mode chatter of a real crash tail;
noise-coupled, not an LFO (a fixed-rate LFO is itself a synthetic tell).

Field: `shimmer: Option<Shimmer>` on `Drum` (`drums.rs:33-42`), default
`None`; new builder `fn with_shimmer(self, rate_hz, depth) -> Self`.
Import `OnePole` into `drums.rs` (currently only `vel_amp, Biquad, Rng`,
`drums.rs:7`). Choke interaction: shimmer is a multiplier; `choke()`
collapses the underlying decays — unchanged behaviour (DR-O9).

**(e) Crash level budget — the real DR-O10 knobs.** DR-O10 bounds v2-vs-v1
`rms(seg[0,1 s])` to ±2 dB, and the crash has almost no natural margin, so
the level-controlling terms must be named explicitly. **`CRASH_TONE_NORM` is
*not* one of them**: it only power-matches each twin pair to its v1 single
partial (a per-partial invariant), and the tonal partials are ~2.5 % of the
[0,1 s] energy — it cannot move the broadband RMS. The energy in [0,1 s] is
dominated by the **wash** (HP-4200, the loudest component), so the crash
level knobs are, in order of leverage: **wash amp**, **wash/pairs t60**, and
**shimmer depth**. Budget for crash 49 (mean-square integral
`I(t60) = t60/(6 ln10)·(1 − 10^(−6/t60))` over [0,1 s]):

- Wash t60 1.9→2.6 s alone raises the wash's own [0,1 s] energy by
  `I(2.6)/I(1.9) = 0.1873/0.1374 = 1.363` → **+1.34 dB**. Trimming wash amp
  `1.0 → 0.85` (`CRASH_WASH_AMP_V2 = 0.856 = √(0.1374/0.1873)`) holds the
  wash's [0,1 s] contribution level-neutral despite the longer tail — this
  is the primary offset.
- Shimmer AM (depth 0.35, unit-variance modulator) multiplies broadband RMS
  by `√(1+0.35²) = 1.0595` → **+0.50 dB**.
- Pairs t60 1.9→2.8 s and the new 1180/1196 pair add [0,1 s] energy, but the
  pairs are ~5 % of the total, so their `I(2.8)/I(1.9)=1.46` extension
  contributes only ≈ **+0.1–0.3 dB** to the broadband RMS.
- Shorter tonal t60 (2.6→1.7 s) slightly *lowers* tonal energy — a small
  negative offset.

**Expected v2-vs-v1 `rms(seg[0,1 s])` ≈ +0.6 to +0.8 dB** — inside the ±2 dB
ceiling with ~1.2 dB margin. If the measured value exceeds budget, the
implementer trims `CRASH_WASH_AMP_V2` further (each −1 dB of wash is −0.87 dB
broadband) or reduces shimmer depth — **not** `CRASH_TONE_NORM`. Crash 57
takes the identical wash-amp trim (same wash structure). Freeze the exact
`CRASH_WASH_AMP_V2` against the measured v1 baseline before locking DR-O10,
per the fail-first calibration rule.

### DR2 — tom pitch-drop (keys 41, 43, 45, 47|48|50) — closes T2

Reduce the sweep to measured-plausible values: real toms overshoot 1–3
semitones and settle within 30–80 ms (tension modulation), mostly on the
fundamental's early cycles.

**Mechanism**: v2 toms start **+2.5 st sharp and glide down to the table
pitch**, instead of starting at table pitch and diving 20.9 st to the 0.3×
floor.

- `TOM_OVERSHOOT: f32 = 1.155` (= 2^(2.5/12)); v2 builds
  `tom_tones(f0 * TOM_OVERSHOOT, t60, TOM_GLIDE_V2)` so all three membrane
  modes keep the 1 : 1.59 : 2.14 ratios and share the glide (as today,
  `tom_tones`, `drums.rs:243-249`).
- `TOM_GLIDE_V2: f32 = 4.0` oct/s. With the D1 velocity scale
  `glide × (0.6 + 0.8·vn)` (`membrane_velocity`, `drums.rs:215-236`) the
  effective rate is 2.4–5.6 oct/s, so the 0.208-octave drop completes in
  0.208/5.6 = 37 ms (vel 127) to 0.208/2.4 = 87 ms (vel 1) — squarely the
  30–80 ms physical window, and velocity still modulates attack character.
- **Glide floor**: `min_freq` is hardwired to `0.3 × start` in `Drum::new`
  (`drums.rs:86`). New builder `fn with_glide_floor(mut self, ratio: f32)
  -> Self` rewriting `min_freq = freq * ratio` for every tone
  (post-construction, freq already carries the jf jitter so the floor
  tracks it). v2 toms call `.with_glide_floor(1.0 / TOM_OVERSHOOT)` —
  settled pitch = the original table pitch (100/140/190/240 Hz), so the
  kit's tuning is unchanged; only the strike transient changes.
- t60s, noise bands, life, gains: unchanged from v1 (the tom *body* was
  never the tell). Kick 35|36 keeps its 28/3 oct/s glides — there the deep
  sub drop is the design (map_drums §4 T2); congas/bongos untouched.

### DR3 — static open hat (key 46) — closes T3

Three additions, all inside the key-46 arm (`drums.rs:445-461`) and the
shared `cymbal()` builder (`drums.rs:286-328`), gated on kit:

**(a) Two-band wash with divergent decay (spectral motion).** Replace the
single wash `(0.8, 0.28 s, HP 6000)` with:
- body: `(0.55, 0.30 s, HP 6000)`
- sizzle: `(0.55, 0.16 s, HP 10000)`

Both corners keep the velocity scale ×(0.85 + 0.35·vn) (`drums.rs:297`).
Decay-rate difference 60/0.16 − 60/0.30 = 175 dB/s: 200 ms in, the >10 kHz
region has fallen ~35 dB relative to the 6–10 kHz body, so the spectral
centroid *falls through the decay* — the missing evolution (a real hat
loses HF fastest). Both bands consume the shared white draw (correlated
source, differently coloured — same as every existing multi-band hit,
`drums.rs:164-177`). Implementation: `CymSpec.noise` becomes the body
band; new optional field `noise2: Option<(f32, f32, f32)>` (amp, t60, HP
corner), `None` for every v1 spec and all non-hat v2 cymbals.

**(b) Wider tonal decay spread.** Metal-stack t60 `0.30→0.18` becomes
`0.45→0.10`: the 3300 Hz fundamental rings while the 8–14 kHz partials die
fast — tonal centroid falls too, and the late tail keeps a faint pitched
ring under the body wash (real open hats do).

**(c) Sizzle wobble.** `with_shimmer(45.0, 0.45)` — the DR1 `Shimmer`
reused at chatter rate. A noise-driven ~45 Hz AM is the two-cymbal sizzle
chatter (rough 30–100 Hz modulation, map_drums §4 T3(b)); noise-coupled so
no repeating LFO period. Zero extra RNG draws (shared white).

Life 0.95 s, gain 0.40, no click, `swell:false` all unchanged. `choke()`
must still kill it in ~10 ms/30 ms — shimmer multiplies, bands' decays are
choked as today (DR-O9). Closed/pedal hats 42|44 are untouched in v2
(their 0.14 s life is too short for any of this to read; non-goal).

### DR4 — plain-noise snare rattle (keys 38, 40) — closes T4

Replace the broad-HP "wire" band (band idx 1, `drums.rs:379-382`) with an
enveloped, bandpassed, head-coupled wire resonance. New struct:

```rust
struct WireRes {                       // drums.rs, new
    bands: [Biquad; 3],                // bandpass wire-mode clusters
    gains: [f32; 3],                   // velocity-shaped per-band gains
    amp: f32,                          // overall level (own exponential)
    decay: f32,                        // own t60 (0.19 s, as v1)
    onset: u32, env: f32, atk: f32,    // D5 delayed onset (1.5 ms / 0.5 ms), as v1
    head_amp0: f32,                    // tones[0].amp at build time
    head_track: f32,                   // exponent on head-envelope tracking
    am_depth: f32,                     // wire-slap AM depth at full head level
}
```

Field `wire: Option<WireRes>` on `Drum`, `None` for v1 and every non-snare
key. Per-sample render (inside the existing loop, after the noise bands,
consuming the same shared `white`):

```text
head  = tones[0].amp / head_amp0                    // 186 Hz head envelope, 0..1
track = head.powf(head_track)                       // re-excitation by the ringing head
slap  = 1.0 + am_depth * head * max(0, sin(tones[0].phase))  // wire lift-off AM
s    += (Σ bands[i].process(white) * gains[i]) * amp * envD5 * track * slap
amp  *= decay
```

**Parameter choices with the physics:**

- **Wire-mode clusters**: bandpass centers **[3400, 5100, 7300] Hz**,
  Q **[6, 7, 8]** — resonant coloration (comb-like clusters of the ~20
  wire partials) instead of a featureless HP slope. These are *not*
  beating pairs: adjacent Δf ≈ 1.7 kHz is far beyond beat range, and at
  Q 6–8 the ring time Q/(πf) = 0.56–0.35 ms is deliberately tiny — no beat
  is relied on, so the ring-time lesson imposes no constraint here (stated
  per the CYM-1 rule: the constraint binds only beats you *rely* on).
- **Velocity**: per-band gains `[1.0, 0.55 + 0.45·vn, 0.30 + 0.70·vn]` —
  ghost notes (vn→0) rattle darkly in the 3.4 kHz cluster; rimshot-hard
  hits open the 5–7 kHz clusters. Rides on top of the D1 overall noise
  scale (0.5 + 0.5·vn²) which continues to apply (the transform maps the
  *tables*; WireRes takes its post-D1 amp). Make-up gain
  `WIRE_MAKEUP: f32 = 2.9`: the v1 HP-2800 band passed ~19 kHz of
  equivalent noise bandwidth, the three BPs pass Σf/Q ≈ 2210 Hz →
  amplitude ratio √(19250/2210) ≈ 2.95; initial value 2.9, final value
  calibrated by the level-parity oracle DR-O10 (±2 dB).
- **Head coupling**: `head_track = 0.4`. The head fundamental decays at
  60/0.10 = 600 dB/s (t60 0.10 s, `SNARE_TONES[0]`, `drums.rs:254-259`);
  the tracking factor therefore decays at 0.4·600 = 240 dB/s, multiplying
  the wire's own 316 dB/s (t60 0.19 s) → combined ≈ 556 dB/s, which reaches
  −60 dB at 60/556 = **~110 ms** (not the ~250 ms an earlier draft claimed —
  that figure ignored the 316 dB/s wire term). So the bright wire clusters
  *sputter out with the head* by ~100–120 ms instead of running their own
  0.19 s clock. This short, head-coupled bright rattle is the intended
  physics — the re-excitation model inverted into a tractable form: the
  wires can only be as loud as the head that throws them. The **longer**
  snare tail is deliberately carried by the retained dark-tail band (idx 2,
  HP 1800, t60 0.35 s, amp 0.22), which sustains a darker residual to
  ~350 ms; the bright granular rattle is *meant* to be the short component.
  If a genuinely ~200 ms bright rattle is later wanted, lower
  `WIRE_HEAD_TRACK` toward 0 (removing the head coupling shifts cessation to
  the wire's own ~190 ms) — but that trades away the sputter that motivates
  DR4.
- **Granular slap AM**: `am_depth = 0.6`. Half-wave-rectified 186 Hz
  modulation, depth proportional to the *current* head level — early
  rattle is granular at the head rate (wires leave and re-strike the head
  once per cycle), late rattle smooths as the head dies. Reuses
  `tones[0].phase` — no extra oscillator, no extra draws.
- **Dark tail band** (idx 2, HP 1800, t60 0.35 s): amp 0.35 → **0.22** in
  v2 — the wire clusters now carry the sustained rattle energy the tail
  band was over-supplying.
- **Key 40 (electric snare) differentiation**: centers × 1.15
  ([3910, 5865, 8395] Hz), `am_depth 0.48` — brighter, tighter wires; v1
  renders 38 and 40 identically, v2 gives 40 a first identity of its own.
- Shell-slap band 0, `SNARE_TONES` head modes, D5 onset (1.5 ms + 0.5 ms
  ramp), life 0.6 s, gain 0.68: all unchanged.

## 7. Opt-in & regression safety

- **The gate**: kit v2 engages only when a file authors a Program Change on
  channel 10. **`map_albums.md` §(c): no committed album — Hollow Hill 1&2,
  The Signal Fire, Winter Guests 1&2, Sub Rosa, The Iron Tide — nor any
  local demo sends Program Change or Bank Select (CC0/CC32) on channel 10.**
  Therefore every committed render takes the `Kit::V1` path unconditionally.
- **Why the gate is mandatory, not optional**: the committed albums play
  exactly the keys these fixes touch (49/57 crashes, 46 open hat, 41–50
  toms, 38/40 snares — per-file "Channel 10 detail" rows in map_albums.md),
  so an ungated version of any fix would alter every committed album.
- **Bit-identity mechanism**: v1 constructs field-identical `Drum`s (v2
  state lives in `Option` fields = `None`); render-time v2 math reuses the
  existing shared per-sample white draw — no RNG draws added, removed, or
  reordered on the non-authoring path (the determinism corollary,
  map_docs §2.2).
- **Proof procedure** (doctrine, map_docs §1.6): the album byte-compare is
  only unconfounded against a binary whose **only** delta from v0.8.1 is the
  drum seam (DR0–DR4). A *full* v0.9 binary also carries the brass/reed/
  strings work, and per `map_albums.md` §(a) that legitimately re-renders
  `fable5/midi/The Iron Tide.mid` (ch5/ch6, programs 60/61) — so comparing
  the full binary would show The Iron Tide differ for reasons unrelated to
  drums and prove nothing about this seam. Therefore: build the v0.8.1
  baseline binary in a scratch `git worktree`, build a **drum-seam-only**
  binary (v0.8.1 + DR0–DR4, no other family changes), render all committed
  albums with both, `cmp` byte-identical across **all** albums. The primary,
  always-available proof is the in-crate suite — golden fixture + canary
  comment (the drum row must stay bit-exact), determinism oracle 35,
  `drum_strip_parity_preserved`, and drum oracles 20–33 all green with zero
  edits — which isolates the drum seam regardless of what else ships in the
  same v0.9 build.
- No compatibility waiver is needed — nothing default-visible changes.

## 8. Verification oracles (all `cargo test`, numeric, no ears)

Feature oracles are **fail-first** (fail on v0.8.1 behaviour = on a
`Kit::V1` render, pass on `Kit::V2`); guards hold throughout. Renders pin
`sr = 44100.0`, seed 7 (matching the existing `render_drum` harness,
`drums.rs:700-706`); band windows use Q ≤ 5 so the ±3 % per-strike `jf`
jitter cannot walk a partial out of a probe band.

## 9. Size & risks

**Size**: DR0 seam **S**; DR1 crash **M**; DR2 toms **S**; DR3 open hat
**S–M**; DR4 snare **M**. Total **M** (~250–350 new lines incl. tests, two
files). Each of DR1–DR4 is independently landable once DR0 is in; land
order DR0 → DR2 (smallest, proves the seam end-to-end) → DR3 → DR1 → DR4.
One version bump for the whole integrated v0.9 task (this section adds
none of its own).

| Risk | Where | Mitigation |
|---|---|---|
| RNG-order drift breaks byte-identity for non-authoring files | `Drum::new` construction draws (`drums.rs:58-103`) | v2 state in `Option`s; v2-only construction draws strictly after all v1 draws inside `if kit == V2`; render-time math reuses the shared white (:164); DR-O1 byte-compare is the backstop |
| `make` signature change churns tests | `drums.rs` tests, engine render tests | mechanical `Kit::V1` at existing call sites; oracles 20–33 semantics untouched |
| Oracle flakiness from per-strike jitter (±3 % jf, ±10 % jd) | DR-O3/O5/O8 probe bands | pinned seed 7, Q ≤ 5 probe bands, differential v2-vs-v1 forms instead of absolute floors; v1 baselines measured on main before thresholds are frozen |
| Shimmer AM reads as level pumping on short crashes | DR1/DR3 | depth in true σ units (analytic `norm`), clamp [0, 2]; DR-O10 bounds broadband RMS ±2 dB |
| WireRes make-up gain mis-estimated → snare level jump on opted-in files | DR4 | `WIRE_MAKEUP` is explicitly oracle-calibrated (DR-O10), not trusted from the bandwidth estimate |
| Mid-file PC flips the kit mid-song (mixed v1/v2 hits ringing together) | seam semantics | documented spawn-time semantics (§3 DR0); GM2-consistent; no state carried between hits so mixing kits is safe |
| Future kit names collide with "any PC = v2" | seam semantics | PC value is already stored in `strips[9].program`; a later named-kit table reads it without touching the authored-flag gate |
