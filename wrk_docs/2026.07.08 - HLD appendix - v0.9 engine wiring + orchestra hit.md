# design_engine55 — Engine wiring for programs 55–71 + the Orchestra Hit (55) voice

Design section for the hollowsynth v0.9 HLD. Baseline: v0.8.1 (integrated
trunk). All line anchors are exact for that build; structural anchors
(function/struct names) are given alongside every line number per the
map_docs pitfall-1 rule. Companion sections own the brass voice
(`design_brass.md`, programs 56–63) and the reed voice (`design_reeds.md`,
64–71); this section owns everything the **engine** must do so those voices
behave like first-class citizens — plus the one voice nobody else covers,
the Orchestra Hit at program 55.

Mechanism ids: **E1–E5** (engine wiring), **OH1–OH5** (orchestra-hit voice).

---

## 1. Goal

1. Programs 55–71 currently sit in **no** engine family: CC1 vibrato is a
   silent no-op, channel aftertouch is stored but never applied, and
   `fx_profile` gives them zero chorus/echo. Wire 56–71 into the vibrato and
   aftertouch families and give 55–71 sensible per-program send profiles, so
   the new brass/reed voices answer the same expressive controllers every
   other sustained family does.
2. Define where "slow speak at low velocity" timing realism lives for these
   programs (answer: in the voices via `vel_attack`, not the engine) and its
   one exception (the stab).
3. Specify a simple **Orchestra Hit** voice for program 55 — a one-shot
   layered orchestral stab (octave-stacked saw ensemble over a timpani-like
   thump, fast decay), *not* a pluck and *not* a sustained voice.
4. Decide whether an LA attack-sample phase (VSCO 2 CE brass/wind
   transients) should be specified now: **recommended as an optional
   follow-on phase with a measurable trigger, not mandated** (§9).

Success is measured, not asserted: every claim below carries a numeric
oracle in §8 (this machine has no ears).

## 3. Design

### E1 — `vibrato_family`: add 56–71, exclude 55

`engine.rs:61–64` becomes:

```rust
/// Melodic sustained families that take the engine-level CC1 vibrato:
/// plucks (except palm-mute 28), bowed strings, brass, reeds, winds.
/// Drums, organs, modal (piano/bells), and one-shot stabs (55 orchestra
/// hit, 47 timpani) are left alone — vibrato on a struck note is a no-op.
fn vibrato_family(program: u8) -> bool {
    matches!(program, 24..=27 | 29..=46 | 56..=71 | 72..=79 | 104..=107)
}
```

(`56..=71 | 72..=79` may be collapsed to `56..=79`; keep the two ranges
split so the brass/reed addition reads as its own decision and the diff
stays reviewable.)

Physical reasoning: brass and reed players *add* vibrato as an expressive
act (lip/jaw), which is exactly the CC1 = "player intent" model. The shared
engine LFO (`VIB_RATE_HZ = 5.3`, `VIB_DEPTH_CENTS = 35`, `engine.rs:24–25`)
is in the right range for both (brass vibrato ~4.5–6 Hz, sax ~5–6 Hz);
depth rides the wheel, so subtle-to-lush is authored per file, not baked in.

**55 stays out**, deliberately and symmetrically with **47 timpani** (also
excluded — the range `29..=46` ends before it): the orchestra hit is a
struck one-shot; a 5.3 Hz pitch LFO on a 0.4 s stab is inaudible at best and
a synthetic warble at worst. With 55 excluded, a CC1 event on a prog-55
channel keeps hitting the else-arm (`engine.rs:1025–1027`,
`mod_engaged = false`) — a complete, documented no-op.

**Interaction rule for the voice designs (INT-2/INT-3, map_docs §2.2):** the
CC1/aftertouch/glide writers call `set_pitch` per block on every ringing
voice, including released ones, with the *composed* multiplier. The
brass/reed voices must therefore store any internal pitch offset (attack
scoop, fall-off) as state composed into every retune
(`f = base_f · internal · bend`), and must NOT carry an always-on internal
vibrato deeper than ~5 cents, or authored CC1 stacks a second wobble on top
(the Wind/Bowed precedent: their internal vibrato depths are 0.004–0.006,
i.e. ≤ ~10 cents, and CC1 at 35 cents dominates cleanly). That constraint
is stated here because the engine owns the composition; the voice designs
own their internal depths.

### E2 — `aftertouch_family`: comes free, plus nothing

`engine.rs:70–72` already ORs `vibrato_family`, so E1 alone enables
aftertouch (gain lift `AT_GAIN_DB = 2.5` dB + 25-cent/5 Hz vibrato,
`engine.rs:54–56`, applied at `engine.rs:1049–1062`) for 56–71. **No
explicit range is added.** 55 is excluded by the same logic as E1 — the
existing doc comment ("pressure cannot swell a struck string",
`engine.rs:66–69`) applies verbatim to a stab; extend that comment to name
55 alongside piano/bells. Pressure-swell on brass ("crescendo inside a held
note") is precisely what the aftertouch feature was built for — it is the
single cheapest realism win in this whole section.

### E3 — `fx_profile`: explicit arms for 55–71

`fx_profile` (`engine.rs:253–269`) gains four arms above the `_` fallback
(values justified in §4/§5):

```rust
55 => (0.0, 0.0),         // orchestra hit: dry stab; chorus smears the transient
56..=60 => (0.0, 0.0),    // solo brass: hall (CC91) is the space, no ensemble fake
61..=63 => (0.25, 0.0),   // brass section / synth brass: section width
64..=67 => (0.06, 0.10),  // saxes: lead voice, a touch of width and slap
68..=71 => (0.0, 0.0),    // double reeds / clarinet: orchestral, dry into the hall
```

The `55` and `56..=60` and `68..=71` arms return the same value as `_` —
they are behavior-neutral but are added anyway so the table documents a
*decision* rather than an accident, matching the file's existing style
(every voiced family has an arm). Reverb intentionally stays the
CC91-authored 0.3 default (`engine.rs:252`, `Strip::new` `engine.rs:574`).

**Prog-handler ordering caveat (existing behavior, unchanged):** the Prog
event overwrites `chorus_send`/`delay_send` from `fx_profile`
(`engine.rs:938–947`), clobbering any CC93/94 authored *before* the Prog.
The new arms inherit this; composition code already orders Prog before CC93
(this is the shipped convention, not a new risk).

### E4 — legato & portamento: zero engine change (verified)

The CC68 slur path (`engine.rs:694–704`) and CC5/65 portamento
(`engine.rs:750–762`, `1063–1074`) are already program-agnostic. The work is
entirely in the voices: `Voice::legato_to` (`voices.rs:36`, default
`false` = retrigger) must be implemented by the brass/reed voices — the
Wind/Bowed scoop-glide (`Wind::legato_to`, `voices.rs:1775–1782`;
`Bowed::legato_to`, `voices.rs:1894–1900`) is the stated pattern (one
breath/one column of air across several valve changes, no fresh tongue
attack). The Orchestra Hit keeps the default `false`: a stab retriggers,
always (§6). This section adds the *oracle* (E55-3, §8) that proves the
end-to-end wiring, since the engine map warns the trait default silently
eats the feature (INT-5).

### E5 — timing realism (slow speak at low velocity): voice-level, one rule

"Sustained families speak slower at low velocity" is implemented per voice
via `vel_attack(base, vel) = base · (1.45 − 0.65·vn)` (`voices.rs:1560–1562`)
feeding the `Adsr` attack — the engine has no attack-time seam and gets
none. Applicability ruling for this program range:

- **56–63 brass, 64–71 reeds: YES, mandatory.** The voice designs must pass
  their attack base through `vel_attack` like every sustained family
  (Organ/SawStack/Wind/Bowed all do — map_voices §4). Physical reasoning:
  a gently blown note genuinely speaks late — the lip/reed takes longer to
  reach oscillation threshold at low pressure; this is one of the strongest
  "played, not sampled" cues the crate has.
- **55 orchestra hit: NO, explicitly.** A stab's identity is its instant
  tutti attack at any dynamic; velocity scales level and brightness (§6),
  never speak time. Attack is a fixed `ORCH_ATTACK_S = 0.004` s. Oracle
  E55-10 pins this (attack-to-90% time differs < 5 ms between vel 30 and
  vel 120).

## 6. The Orchestra Hit voice (OH1–OH5)

New `pub struct OrchHit` in `voices.rs`, placed after `Bowed` and before the
factory, ~120 lines. It is a **decaying-family** voice (Modal idiom), not an
`Adsr` voice — see the trap in OH3.

### OH1 — structure

```rust
pub struct OrchHit {
    saws: Vec<(BlepSaw, f32)>,   // (osc, ratio) — ORCH_RATIOS, random phases
    lp: Biquad,                   // lowpass(ORCH_LP_BASE + ORCH_LP_VEL*vn, ORCH_LP_Q)
    thump: Modal,                 // timpani-like reinforcement (below)
    bite: Burst,                  // massed-attack noise transient
    base_f: f32,
    bend: f32,                    // composed channel multiplier (set_pitch)
    att: f32, att_env: f32,       // linear 4 ms ramp (Modal idiom)
    dec_env: f32, dec_mul: f32,   // t60_mul(ORCH_T60_S, sr)
    rel_env: f32, rel_mul: f32,   // t60_mul(ORCH_REL_T60_S, sr), engaged by note_off
    released: bool,
    rng: Rng,
    amp: f32,                     // ORCH_AMP * (0.4 + 0.6*vel_amp(vel))
    t: u32,
    sr: f32,
}
```

Constructor `orch_hit(key, vel, sr, seed) -> OrchHit` (factory-fn idiom 2,
map_voices §2): five `BlepSaw`s at `key_freq(key) · ORCH_RATIOS[i]`, each
with `rng.white()`-random phase and a per-note ±0.15 % ratio jitter
(round-robin discipline, map_voices §4); saw frequencies Nyquist-guarded at
`< sr·0.45` like `Modal::new` (`voices.rs:103`).

**Thump** (OH2): a `Modal` built inline (Modal::new is module-visible,
`voices.rs:91`), timpani-flavored but shorter than program 47's
(`timpani()`, `voices.rs:269–290`): fundamental
`f_th = (key_freq(key) * 0.5).clamp(ORCH_THUMP_F_LO, ORCH_THUMP_F_HI)`,
partials `[(f_th, 1.0·v, 0.30), (f_th·1.5, 0.5·v, 0.20)]` (t60 seconds —
half the timpani's ring: reinforcement, not a solo timp note), noise
`(0.9·v, 0.04, Biquad::lowpass(250.0, 0.8, sr))` (the mallet/bass-drum
front), attack 0.001, release_t60 0.15, gain `ORCH_THUMP_GAIN`. Clamping
`f_th` to 50–110 Hz keeps the weight in the chest register whatever key the
stab is played at — a C5 stab still lands on a low drum, which is what the
classic sampled hit does.

### OH2 — render chain

Per sample: `s = mean(saws) → lp.process(s)` then
`out += s·amp·att_env·dec_env·rel_env + bite.tick(&mut rng)`; the thump adds
itself via `thump.render(out_block)` once per block. **Ordering (thump before
or after the saw loop) is irrelevant** because both writes are additive into
the same `out` buffer — the saw loop does `*o += …` and `Modal::render` does
`*o += s·gain·att_env·release_env` (verified `voices.rs:149`), so they commute.
Pick one order for the pseudocode: **call `thump.render(out)` first, then run
the saw+bite accumulation loop** (thump's `bool` return is captured for the
`thump_alive` aliveness term below). Control work (retunes) every `CTRL = 16` samples
(`voices.rs:62`). Alive =
`dec_env·rel_env·amp > 2e-5 || thump_alive || t < 0.05·sr` where
`thump_alive` is `Modal::render`'s own return — the decaying-family
threshold convention (map_voices §1).

### OH3 — the Adsr trap, avoided by construction

An `Adsr` with `sustain = 0.0` never reaches stage 4 without `note_off`:
stage 1 parks at stage 2 with level ≈ 0 (`dsp.rs:372–378`) and `alive()`
stays true forever (`dsp.rs:401–403`) — a held stab would be an inaudible
zombie voice rendering five saws until NoteOff. OrchHit therefore uses the
hand-rolled Modal-idiom envelope (linear attack ramp × `dec_mul` exponential
× `rel_mul` after note_off), whose aliveness is a level threshold, not a
stage machine. This is the one non-obvious implementation constraint in the
whole voice; it is called out so the implementer does not "simplify" into
the bug.

### OH4 — controller behavior

- `set_pitch(mult)`: store `bend = mult`; at control rate retune each saw to
  `base_f · ratio · bend` (`Sine`/`BlepSaw::set_freq` is phase-continuous).
  The **thump is deliberately not retuned** — a drum does not follow a
  string bend; a bent stab keeping its percussive anchor static is
  physically right and INT-5-compliant (bend audibly works: oracle E55-9
  measures the saw bed above the thump band).
- `legato_to`: default `false` (trait default, `voices.rs:36`) — every stab
  retriggers, even under CC68. Stated, not accidental.
- `note_off`: engages `rel_mul` **and forwards to `thump.note_off()`** so an
  early release chokes the whole voice — saw bed and thump — together;
  idempotent (flag). Forwarding is deliberate: `ORCH_REL_T60_S` is described
  as "early note-off chokes the stab faster, drum-damp style", and the
  thump's own `release_t60` (0.15 s, OH2) is set equal to `ORCH_REL_T60_S`
  (0.15 s) precisely so the one forwarded choke governs both layers at the
  same rate. Not forwarding would leave the thump ringing through its own
  decay while the saws choke — an inconsistent tail on an early note-off. The
  thump is bounded either way (its Modal mode-decay crosses the aliveness
  threshold in ~0.3–0.4 s regardless, so an un-forwarded thump would not
  zombie the voice); we forward it purely so the `ORCH_REL_T60_S` choke
  governs the whole voice consistently. Under CC64/CC66 the engine defers
  note_off (INT-7) — semantics: a pedal-held stab simply finishes its own
  ~0.4 s decay; the deferred note_off then hits an already near-silent voice.
  No special casing.
- `set_trem`/`set_vowel`/`choke`: trait defaults (no-ops).
- `#[cfg(test)] fn kind() -> &'static str { "orchhit" }` — required for
  oracle 36 routing (`gm_routing_pins_voice_kinds`, `testutil.rs:552–597`);
  the crate does not compile under `cargo test` without it.

### OH5 — factory registration


## 7. Opt-in & regression safety (grounded in map_albums.md)

Three change classes, three different safety arguments:

1. **Predicate additions (E1/E2) — opt-in safe *by construction*.** The CC1
   pass only runs when `mod_cur > 1e-3 || mod_engaged || authored_organ`
   (`engine.rs:965–970`); aftertouch only when
   `at_authored && aftertouch_family` (`engine.rs:1050`). A channel that
   never sends CC1/AT is untouched whatever the predicate says.
   `map_albums.md` closes the residual hole ("does any committed album send
   CC1/AT on a 55–71 channel, silently no-op today?"): the only committed
   channels carrying programs in 55–71 are The Iron Tide ch5 (prog 60) and
   ch6 (prog 61), whose authored CCs are **7/10/11/91 only** — no CC1, no
   aftertouch, no CC68, no CC5/65. Therefore E1/E2 change **zero** committed
   renders, including The Iron Tide's.
2. **`fx_profile` arms (E3) — program-gated, NOT authorship-gated**
   (`engine.rs:941–947` fires on every Prog event). Safe for 55–59 and
   62–71 because no committed album uses them (map_albums §(a): "Unused in
   the range: 55, 56, 57, 58, 59, 62, 63, 64, …, 71"). Program **60** is
   used, so its arm is pinned to `(0.0, 0.0)` — identical to today's `_`
   arm, hence bit-neutral even on The Iron Tide. Program **61** gets
   `(0.25, 0.0)`, which does change The Iron Tide — covered by the waiver
   below, and deliberately bundled with the voice swap so that file changes
   **once**, in one release.
3. **The voice swap itself (OH5 + the brass/reed arms) — the headline
   non-opt-in change.** `map_albums.md` §(a) answers the brief's
   must-verify: programs 60 and 61 ARE used, by exactly one committed file,
   `fable5/midi/The Iron Tide.mid` (ch5 FrenchHorn, ch6 BrassSection).
   **Compatibility waiver (the 0.8 HLD §1.5 template):** re-rendering The
   Iron Tide's two brass channels is not collateral damage, it is the
   *purpose of the build* — that file currently plays its horn line and
   brass fanfares on a plucked steel-string guitar. The HLD must declare
   this a sanctioned re-voicing: byte-identity is waived for this one file;
   every other committed album (Hollow Hill ×2, The Signal Fire, Winter
   Guests ×2, Sub Rosa) must render **byte-identical** old-binary vs
   new-binary (oracle E55-6), since none touches 55–71. Whether The Iron
   Tide's rendered/`.opus` artifact is refreshed or pinned to its old
   version is Arthur's call at integration, per the map_docs §1.6
   convention. Program 55's new voice changes no committed render at all
   (unused everywhere).

Golden-fixture mechanics: `reference_song()` (`testutil.rs:188–269`) has no
55–71 channel. Adding brass/reed/orchhit test channels is a **fixture
recapture event** — the `GOLDEN` table (`testutil.rs:440–467`) is
regenerated in the same commit (`cargo test print_golden_fixture --
--ignored --nocapture`) and the recapture comment must assert the existing

## 9. LA attack-sample phase for brass/reeds — recommendation (not mandated)

VSCO 2 CE (CC0) carries usable trumpet/trombone/horn/oboe/clarinet/bassoon
sustains whose onsets can be trimmed exactly as `samples/prepare.py` did for
violin/flute (map_dsp §2.5 gives the complete recipe: trim ~0.63 s, measure
roots by autocorrelation, `bank!` embed, `LaVoice::wrap` in the new `make`
arms with a level-matched `LA_TRUMPET`-style const).

**Recommendation: specify as an optional follow-on phase, deferred with a
trigger — do not build it in v0.9's main line.** Reasoning:

- *For:* the crate's own LA thesis (README: "the ear judges an instrument
  mostly by its onset") applies to brass more than anything — the bite
  (lip buzz forming into tone) is the hardest brass feature to synthesize,
  and precedent (piano/violin/flute) shows the wrap is ~20 lines per family
  plus assets, structurally free later (`--no-samples` and the repitch
  fallback already exist; a model-only voice gains the bank with zero
  architectural change — map_dsp §2.5 point 6).
- *Against doing it now:* it adds ~0.5 MB binary per 5-zone×2-layer bank
  (~1.5–3 MB for a brass+reed set), a `prepare.py` asset pipeline round, and
  two more level-continuity/pitch-agreement test families — all before we
  know the synthetic attack (brass design's envelope-tracked filter "waa" +
  Burst bite) actually falls short.

**Trigger condition** (map_docs §1.4 deferral convention): build the phase
only if, after the model-only brass lands, EITHER (a) the brass attack fails
a bite-credibility differential check — e.g. hp_rms(0–60 ms)/hp_rms(steady)
of the model vs the VSCO trumpet forte sample differs by more than a factor
to be calibrated — OR (b) Arthur's listen flags the onsets. Priority order
inside the phase if fired: trumpet, trombone, horn (most exposed, hardest
to fake); oboe/clarinet/bassoon second (reed chiff is easier synthetically
and design_reeds' Burst chiff may already suffice); saxes are absent from
VSCO 2 CE orchestral set and stay model-only regardless.
