# Design section: Reeds (GM 64–71) — `Reed` voice family

v0.9 HLD contribution. Family prefix **RD** (mechanisms RD1–RD8, oracles RD-O0–RD-O13).
Baseline: hollowsynth **v0.8.1**; all line anchors are against that build (structural
names given alongside per map_docs pitfall 1). All Hz values assume the default
44 100 Hz `Options.sr`; every filter build clamps its frequency to `≤ 0.4·sr`.

---

## 1. Goal

Give the eight GM reed programs — 64 SopranoSax, 65 AltoSax, 66 TenorSax,
67 BaritoneSax, 68 Oboe, 69 EnglishHorn, 70 Bassoon, 71 Clarinet — a real
sustaining reed voice. Today all eight fall through `voices::make`'s `_`
fallback arm (`voices.rs:2045`) to `Pluck::new(&STEEL, …)`: the assessment
journal measured a held oboe note's sustain ratio at **0.00** and prog 61 at
**0.01** (decays like a pluck; real sustained families measure 1.1–1.4).

Success is *measured*, not "sounds better":

- A held reed note sustains: late/early solo-stem RMS ratio ≥ 0.6 (RD-O2).
- The clarinet is spectrally hollow (odd harmonics dominate) and the eight
  programs are pairwise distinguishable by formant-band energy and centroid
  (RD-O3, RD-O5, RD-O6).
- Velocity opens the timbre, not just the level (RD-O7).
- Bend, CC1 vibrato, aftertouch, portamento, and CC68 slur all act on the new
  voice (RD-O9, RD-O10 — closing the INT-5 trap).
- Zero committed renders change (Section 7; grounded in `map_albums.md`).

Non-goals (with reasons):

- **No LA sample bank for reeds in v0.9.** The sampler seam (`sampler.rs`,
  `LaVoice::wrap`) allows adding one later with no structural change
  (map_dsp §2.5-6); shipping model-only first keeps this section S/M and the
  binary small. Trigger to revisit: RD-O13's attack-plausibility check can't
  be met synthetically.
- **No growl/flutter-tongue or key-click mechanics.** No committed or demo
  MIDI authors anything that would drive them; premature surface area.
- **No new engine control seam** (no `set_reed()` trait method). Everything a
  reed needs already flows through `set_pitch`/`legato_to`/velocity/program.

## 2. Current state (what exists to build on)

- **Fallback hole.** `voices::make` (`voices.rs:1918–2047`) has no arm for
  55–71; `_ => Box::new(Pluck::new(&STEEL, key, vel, sr, seed))` at
  `voices.rs:2045`. Engine-side, 64–71 are in **no** family: `vibrato_family`
  (`engine.rs:61–64`) ends at 46 and restarts at 72, so CC1 is a complete
  no-op (`engine.rs:1025`); `aftertouch_family` (`engine.rs:70–72`) is false;
  `fx_profile` gives `(0.0, 0.0)` (`engine.rs:267`). CC68 legato and CC5/65
  portamento are already program-agnostic at engine level (`engine.rs:694,
  750`) — the work is voice-side.
- **Wind is the structural template** (`voices.rs:1662–1788`): sustained
  `Adsr` voice, `CTRL = 16` control tick, scoop multiplier settling toward
  1.0 (`voices.rs:1736`), breath = bandpassed white riding the vibrato
  (`voices.rs:1753`), chiff one-shot through the same filter, `legato_to`
  slur via scoop re-aim (`voices.rs:1775–1782`). The Reed voice reuses this
  skeleton wholesale.
- **Bowed contributes the envelope→brightness coupling**
  (`lp.set_cutoff(900 + 5200·last_env)`, `voices.rs:1861`) and the
  fixed-body peak-EQ idiom (3 × `Biquad::peak`, `voices.rs:1824–1828`).
- **SawStack's `StackFilter::Formant`** (`voices.rs:1365–1376`) proves the
  bandpass-formant pattern, but it *sums only the bands* — correct for a
  vocal tract, wrong for a reed, whose full bore spectrum survives with
  resonant peaks on top. Reeds therefore use **peak EQs** (Bowed idiom), not
  a bandpass sum. This also avoids the low-fundamental starvation a
  bandpass-only bank causes when a low note's harmonics fall between bands.
- **DSP gap: no pulse oscillator.** `dsp.rs` has `BlepSaw` only
  (`dsp.rs:66–105`); map_dsp §5.1 flags this and names the fix. RD1 adds
  `BlepPulse`.
- **Velocity conventions** (map_voices §4) to honour: `vel_amp` +
  `0.4 + 0.6·vel_amp` sustained compression, `vn` timbre laws,
  `vel_attack(base, vel)` (`voices.rs:1560–1562`), per-note seeded jitter.

## 3. Design

### 3.1 Signal path

```
BlepPulse(width = f(program, register))          ── RD1
   │  ×osc_norm (width-loudness compensation)    ── RD8
   ▼
[if drive_vn > 0]  s = tanh(s·d)/d,  d = 1 + drive_vn·vn   ── RD4 (saxes)
   ▼
3 × Biquad::peak — FIXED per-instrument formants ── RD2
   ▼
OnePole lowpass, cutoff = lp·(0.35+0.75·vn)·(0.55+0.45·env) ── RD3
   ▼
 + breath (bandpassed white × env × (1+0.4·vib)) + chiff    ── RD5
   ▼
 × amp × (0.4 + 0.6·vel_amp) × Adsr
```

Pitch per control tick (every `CTRL = 16` samples, Wind idiom):
`f = base_f · bend · scoop · (1 + vib)` — the scoop and vibrato are persistent
state **composed into every retune**, so the engine's per-block `set_pitch`
writers (bend, CC1, aftertouch, portamento — `engine.rs:930, 1011–1074`)
cannot snap them back (INT-2/INT-3 compliance).

### 3.2 RD1 — `dsp::BlepPulse` (new primitive, `src/dsp.rs`)

```rust
/// Band-limited rectangular pulse (polyBLEP), duty cycle `width` ∈ (0, 1).
/// Zero-DC by construction: the signal sits at level w−1 for the fraction w of
/// the period and at +w for the remaining 1−w, so the two areas cancel (mean = 0)
/// for any width. Only the harmonic MAGNITUDE spectrum is load-bearing
/// downstream (tanh is odd; every oracle measures magnitudes), so the sign and
/// phase of the two levels are immaterial.
pub struct BlepPulse { phase: f32, inc: f32, width: f32 }

impl BlepPulse {
    pub fn new(freq: f32, sr: f32, phase: f32, width: f32) -> Self;
    pub fn set_freq(&mut self, freq: f32, sr: f32);   // phase-continuous
    pub fn next(&mut self) -> f32;
}
```

`next()` is the difference of two naive saws with polyBLEP step corrections at
both discontinuities (`t = 0` and `t = width`), reusing the existing
`polyblep(t, dt)` kernel (`dsp.rs:84–94`, hoisted to a free
`pub(crate) fn` so both oscillators share it):

```
p2   = frac(phase + 1.0 − width)
out  = 0.5 · ( (2·phase − 1 − polyblep(phase, inc))
             − (2·p2    − 1 − polyblep(p2,    inc)) )
```

- Output levels after ×0.5: `w−1` (held the fraction w of the period) and `+w`
  (held the remaining `1−w`); the level *magnitudes* are `{w, 1−w}`, RMS is
  `√(w(1−w))`, and the Fourier amplitude of harmonic n is
  `2·|sin(πnw)|/(πn)` — width 0.5 is an exact square (all even harmonics
  null), narrow widths give the bright, even-rich buzz of a double reed's
  short pressure pulse. This is the physical justification for the width
  choices in §5: a single reed on a cylindrical bore closes ~half the cycle
  (square → hollow odd spectrum, the clarinet); a conical-bore single reed
  spends less of the cycle open (w ≈ 0.3, full harmonic series, the saxes); a
  double reed opens only briefly (w ≈ 0.14–0.16, fundamental-light and buzzy).
- **Width guard**: `set_freq` clamps the effective width to
  `[2·inc, 1 − 2·inc]` so the two BLEP corrections never overlap at extreme
  `f/sr` (safety net only — the highest preset key, clarinet 94 ≈ 1 865 Hz,
  gives `2·inc = 0.085 < 0.12`, the narrowest preset width minus jitter).
- Width is **fixed per note** (chosen at spawn from program + register +
  jitter); dynamic timbre comes from RD3/RD4, so no mid-note width modulation
  and no re-phasing complexity.
- Calibration test in `dsp.rs` per the oracle-0 discipline (RD-O0) before any
  feature oracle may rely on it.

### 3.3 RD2 — fixed per-instrument formant bank

Three `Biquad::peak(f, q, gain_db, sr)` in series, built once at spawn from
the preset's `formants: [(f32, f32, f32); 3]` table (§5), each frequency
clamped to `min(f, 0.4·sr)` and jittered ×(1 ± 2%) per note (seeded). A slot
with `gain_db == 0.0` builds an identity biquad (RBJ peak with A = 1 is a
pass-through) — uniform cost, no `Option` branching. Unlike choir's morphing
bandpass sum, these are **fixed for the life of the note and fixed per
program** — the roadmap's "FIXED per-instrument formant bank". Gains are
capped at **+8 dB, Q ≤ 2.6** (see INT-6 stacking bound, §7).

### 3.4 RD3 — register- and velocity-dependent brightness

- **Register**: `reg = ((key − range.0) as f32 / (range.1 − range.0) as f32)
  .clamp(0.0, 1.0)` computed once at spawn from the preset's playable range.
  Effects: pulse width interpolates `width → width_hi` (clarinet
  0.50 → 0.44: the clarion register admits even harmonics, exactly what a
  real clarinet does above the break); breath scales ×(1.3 − 0.6·reg) (low
  notes breathier — the sax subtone).
- **Velocity + envelope**: output `OnePole` cutoff, retuned at control rate
  (state-preserving `set_cutoff`, `dsp.rs:121`):
  `cut = lp · (0.35 + 0.75·vn) · (0.55 + 0.45·env_last)`, clamped to
  `[500.0, 0.4·sr]`. Harder blowing = more harmonics (the "sampled at one
  dynamic" tell, doctrine oracle 1), and the note's own swell opens the tone
  (Bowed precedent `voices.rs:1861`). At vel 127 / full envelope the factor
  is 1.10·lp; at vel 32 / attack it is ~0.35·lp.

### 3.5 RD4 — sax reed grit (velocity waveshaping)

For presets with `drive_vn > 0` (the four saxes 0.9, double reeds 0.35,
clarinet 0.0): `d = 1.0 + drive_vn·vn; s = (s·d).tanh()/d` — the inline
SynthBass shaper (`voices.rs:1246`), zero-mean input so no bias/DC handling
needed (unlike `engine::Drive`). This is the "brassy-reedy" edge that
separates a fortissimo sax from a mezzo one beyond mere LP opening. Placed
**before** the formant bank so the added harmonics are voiced by the
formants, and before the RD3 lowpass so the LP trims shaper products.
tanh is an odd function, so it cannot break the clarinet's odd-harmonic
null even if enabled later; clarinet still ships with 0.0 (purity, one fewer
tanh per sample). No oversampling: max gain 1.9 on pre-LP'd pulse content is
far gentler than the 2×-oversampled `Drive` (gain 7.0); RD-O12 bounds the
residual alias energy numerically.

### 3.6 RD5 — breath and tongue chiff

Wind pattern (`voices.rs:1750–1756`): one `Biquad::bandpass` at
`min(2.5·f, 5000.0)` Hz, Q 1.2, fed white noise, added post-LP as
`breath·env·(1 + 0.4·vib_val)` (air moves with the pitch wobble) plus a
one-shot tongue chiff `chiff_amp` decaying at `t60_mul(0.020, sr)`.
`chiff_amp = 0.30 · vn · vel_amp(vel)` — super-linear in velocity like
Pluck's onset bursts (`voices.rs:833`): a hard-tongued forte attack spits,
a soft entrance barely speaks. Breath amounts are per-program (§5): saxes
breathiest, clarinet driest.

### 3.7 RD6 — scoop and CC68 slur

Scoop multiplier starts at the preset's `scoop` value (saxes lowest, 0.966–
0.972 — the jazz under-scoop; double reeds and clarinet nearly straight,
0.985–0.990) and settles `scoop += 0.045·(1 − scoop)` per control tick. Each
tick is `CTRL/sr = 16/44100 ≈ 0.363 ms`, so the per-tick decay `0.045` gives a
time constant `τ ≈ 0.363/0.045 ≈ 8 ms`. From the saxes' ~50-cents-flat start
(0.966–0.972) that reaches within 6 cents in `ln(50/6)·τ ≈ 17 ms` (~47 ticks)
and fully settles by ~35–40 ms — an audible onset bloom. Note this scoop is
*deeper* and marginally *slower per tick* than Wind's flute, not faster: the
saxes start at 0.966–0.972 (≈ −49 to −60 cents) vs the flute's 0.984
(≈ −28 cents, `voices.rs:1713`), and step 0.045 < the flute's 0.05. The reeds
bloom from further under; they do not speak faster than the flute.
`legato_to(key, vel)` is the
Wind slur verbatim (`voices.rs:1775–1782`): re-aim via
`scoop = (base_f·scoop/new_f).clamp(0.85, 1.18)`, update `base_f`, kill the
chiff, return `true` — one breath across several fingered notes. The engine's
CC68 path needs nothing (`engine.rs:694–704` is already program-agnostic).

### 3.8 RD7 — vibrato and pitch composition

Single vibrato `Sine` per voice, per-program `(rate, depth, delay)` (§5),
rate jittered ×(1 ± 8%) per note, 0.2 s ramp-in after the delay (Wind idiom
`voices.rs:1739–1744`). `set_pitch(mult)` stores the composed channel
multiplier; the control tick applies `base_f·bend·scoop·(1 + vib)`. INT-5 is
closed by implementing `set_pitch` at all; INT-2/3 by the composition rule.

### 3.9 RD8 — loudness normalisation across widths

A pulse's RMS is `√(w(1−w))`: 0.500 at w = 0.5 but 0.347 at w = 0.14 — left
uncorrected, double reeds would be ~3 dB quieter than the clarinet before
voicing even starts. `Reed::new` computes `osc_norm = 0.5 / (w·(1−w)).sqrt()`
so every program's raw source lands at RMS ≈ 0.5, and the per-program `amp`
constants (§5) then differ only for formant-gain and register reasons.
Final level: `amp · (0.4 + 0.6·vel_amp(vel))` — the house sustained-family
compression (map_voices §4).

Physical reasoning per program:

- **Clarinet 71** — cylindrical bore closed at the reed: only odd harmonics
  resonate in the chalumeau register, so the source is a width-0.5 square
  (even harmonics exactly null; per-note ±2% width jitter leaves a realistic
  trace of evens, h2/h1 ≤ ~0.03). Above the break (`width_hi = 0.44`) evens
  creep in (h2/h1 ≈ 0.15 at the range top) — the clarion register really is
  less hollow. Formants at 1.55 kHz and 3.1 kHz are the instrument's
  bell/bore resonances — modest gains, because the hollowness is the source's
  job, not the filter's. Minimal vibrato (0.0015 ≈ ±2.6 cents): classical
  clarinet is played nearly straight.
- **Saxes 64–67** — conical bore, single reed: full harmonic series
  (w ≈ 0.3), bright "cutoff" formants that descend with bore length. F1
  descends 1100 → 900 → 650 → 480 Hz (roughly by fourths, mirroring the
  instruments' pitch offsets), with F2/F3 tracking; `lp` descends
  5200 → 3800 Hz. RD4 grit (drive_vn 0.9) supplies the brassy edge at high
  velocity; deepest scoops (0.966–0.972) and the breathiest sustain — the
  idiomatic sax articulation set.
- **Oboe 68** — narrow conical double reed: very short duty (w = 0.14 ⇒
  fundamental-light, h1 amplitude 0.27 vs the clarinet's 0.64 before
  normalisation) and a strong nasal formant at 1050 Hz (+8 dB, Q 2.4) with a
  secondary at 2.7 kHz — the classic penetrating "duck" band at 1–3 kHz.
  Fastest attack (35 ms): oboes speak almost instantly.
- **English horn 69** — the oboe's alto with the famous covered ~930 Hz
  formant (the pear-shaped bell resonance); everything slightly darker and
  slower than the oboe (lp 4200, attack 40 ms).
- **Bassoon 70** — long conical double reed: main formant near 500 Hz (the
  "vocal baritone" band) plus 1.22 kHz; darkest ceiling (lp 3200), slowest
  attack (80 ms — the big reed takes time to speak), slowest/deepest-delayed
  vibrato.

Concrete differentiation guarantees (each is an oracle in §8): the four
saxes' centroids strictly order bari < tenor < alto < soprano at a shared
key (RD-O6); oboe vs clarinet differ by both formant-band prominence at
1050 Hz (RD-O5) and even-harmonic content (RD-O3); english horn vs oboe
differ by F1 band ratio at 930 vs 1050 Hz (RD-O5b); bassoon is separated

## 7. Opt-in & regression safety

**Gate: the eight programs are unused by every committed album — verified,
not assumed.** `map_albums.md` §(a) scanned all committed fable5 MIDI
(Hollow Hill ×2, The Signal Fire, Winter Guests ×2, Sub Rosa, The Iron Tide)
and reports the unused list in 55–71 as **55, 56–59, 62–63, and all of
64–71**. The only 55–71 programs in use are 60 (FrenchHorn) and 61
(BrassSection) in `fable5/midi/The Iron Tide.mid` — **both outside the reed
range**, and that exposure belongs to the brass section's safety argument,
not this one. The local `demos/orchestral_demo.mid` does author program 68
(oboe), but it is untracked and explicitly outside the byte-identical
baseline set (map_albums.md scope note) — it is the *demonstration* vehicle,
expected to change.

Therefore:

- Replacing the fallback for `64..=71` changes **zero committed renders** across
  the byte-identical baseline set. **Scope of that set — do not silently widen
  it:** the seven committed *fable5/hollowsynth* albums enumerated above (Hollow
  Hill ×2, The Signal Fire, Winter Guests ×2, Sub Rosa, The Iron Tide).
  Committed `.mid` elsewhere in the repo (`gpt5-3-spark/`, `gpt5-5/`,
  `opus4-8/`) were **not** scanned (map_albums.md:9–12 — outside the brief's
  fable5 scope) and are **not** rendered by hollowsynth's album pipeline, so
  "every committed album" here means the fable5 set only. If a future
  implementer ever wires one of those directories into a hollowsynth render,
  they must re-scan it for programs 64–71 before assuming byte-identity — the
  gate as stated does not cover them.
  Proof procedure (map_docs §1.6): build the v0.8.1 baseline binary in a
  scratch worktree, render every album in that fable5 set with both binaries,
  `cmp` byte-identical. This is the integration gate, not an assumption.
- The `vibrato_family`/`aftertouch_family` additions are opt-in **by
  construction** (`mod_authored`/`at_authored` gates, `engine.rs:965–970,
  1050`) — and doubly safe here: no committed album even has a 64–71 channel
  to author CC1/AT on.
- The `fx_profile` arm is not authorship-gated but is covered by the same
  unused-programs fact.
- **Determinism corollary** (map_docs §2.2): the new `make()` arm adds no
  RNG draws on any non-reed path — `Reed`'s `Rng` is voice-local, and the
  engine's per-spawn seed (`engine.rs:725`) depends only on spawn count,
  which is unchanged for songs without 64–71 notes. The byte-compare holds
  at identical settings.
- **Untouched-family canaries**: ch7 piano / ch8 strings rows in `GOLDEN`
  (`testutil.rs:440–467`) must stay bit-exact through the fixture recapture;
  the full pre-existing suite (all `cargo test` at v0.8.1) is the regression
  gate, with `bowed_scoop_settles` and the CC74=127 bypass test called out
  as nearest-neighbour high-risk tests.
- **INT-6 stacking bound**: reed formant peaks (max +8 dB, Q 2.6) in series
  with an authored CC71/74 wah (up to Q 8, ~+18 dB) give a worst-case
  narrowband lift of ~+26 dB feeding `stats.peak` normalisation. This is
  *milder* than the shipped choir (bandpass sum, Q 9–10) under the same wah,
  so no new mechanism is added; the bound is stated and the gain/Q caps in
  §3.3 are load-bearing (do not raise them without revisiting this
  paragraph). Untested-by-design beyond the caps: same exposure class as
  every shipped formant voice.

## 8. Verification oracles (machine-checkable; this machine has no ears)

House style: every oracle is a `cargo test` on rendered audio via
`testutil` helpers; **feature** oracles must fail on v0.8.1 `main` and pass
after; **guard** oracles hold throughout. Pitch is always `peak_locate`
(Goertzel), never zero-crossings (lessons file). Pinned: `sr = 44100.0`,
seeds fixed, keys/velocities/windows as stated.

**Guards**

- **RD-O0 (guard, `dsp.rs` tests)** — `BlepPulse` calibration, before any
  feature oracle trusts it. Three checks, all over 1 s at `sr = 44100`:
  **(i) spectrum** — at f = 1000 Hz, w = 0.30, `mag_at` of harmonics 1–5 match
  `2·|sin(πnw)|/(πn) · osc_norm` within ±10%.
  **(ii) zero-DC** — |mean| of the raw signal < 1e-3.
  **(iii) alias floor** — measured at a LOW fundamental so fold-back is
  spectrally *separable* from the pulse's real harmonics. At f = 200 Hz,
  w = 0.30 the real harmonics sit exactly on the 200-Hz grid; with sr = 44100
  every above-Nyquist image folds to an **odd** multiple of 100 Hz
  (`200k − 44100m = 100(2k − 441m)`, which is odd whenever m is odd) — bins
  that can never hold a real 200-Hz harmonic and sit 100 Hz clear of the
  nearest one (a Goertzel sinc-null over the 1 s window, so no harmonic
  leakage into them). Require
  `rms{ mag_at(seg, sr, b) : b ∈ 100, 300, 500, …, 21900 } / mag_at(seg, sr, 200) < 0.02`.
  This isolates *genuine* fold-back; a naive (BLEP-less) pulse fails it by
  several×, a correct polyBLEP pulse passes with margin.

  > Why not the obvious broadband `hp_rms(seg, sr, 15_000)/rms(seg)`: a
  > band-limited pulse has *real* harmonics all the way to Nyquist (h11 of a
  > 2 kHz pulse is at 22 kHz, amplitude ≈ 0.04), so any high-pass floor also
  > captures legitimate harmonics — ~15 % of a 2 kHz pulse's RMS is genuinely
  > above 15 kHz. No physically correct oscillator can pass a `< 0.01`
  > broadband threshold; it conflates harmonics with aliasing. The inharmonic
  > odd-100-Hz probe above measures fold-back *only*.
- **RD-O1a (guard)** — `golden_mix_balance_holds` (`testutil.rs:487`) with
  the recaptured table; ch7/ch8 canaries documented bit-exact.
  **RD-O1b (guard, manual gate)** — baseline-binary byte-compare of the fable5
  committed-album set only (§7 scope note; committed `.mid` outside fable5 is
  out of scope for this gate). **RD-O1c (guard)** — `determinism_bit_identical`
  (`testutil.rs:536`) still holds with a reed channel in the fixture.

**Features** (each fails on `main`, where 64–71 render as a STEEL pluck)

- **RD-O2 — sustains, not plucks.** Solo render, prog 66 key 55 vel 100,
  note held 2.0 s: `rms(1.45–1.85 s) / rms(0.15–0.45 s) ≥ 0.6`. On `main`
  this ratio is ≈ 0.01 (assessment journal). Repeat for prog 68 and 71.
- **RD-O3 — clarinet hollowness (differential).** Prog 71 key 50
  (D3, f = 146.83 Hz) vs prog 66 same key, vel 100, sustain window
  0.5–1.5 s: `mag_at(2f)/mag_at(f)` < 0.12 for the clarinet AND > 0.30 for
  the tenor sax (theory: ≤ 0.03 vs ≈ 0.54; thresholds leave 2.5–4× margin
  for jitter and formant tilt). Also `mag_at(3f)/mag_at(f) > 0.15` for the
  clarinet (odd harmonics present — hollow, not a bare sine).
- **RD-O4 — clarion register admits evens.** Prog 71: `mag_at(2f)/mag_at(f)`
  at key 86 > 2.5 × the same ratio at key 50 (width law 0.50 → 0.451 at
  reg 0.82 predicts 0.15 vs ≤ 0.03).
- **RD-O5 — double-reed nasal formants.** Same key 64 (E4), vel 100,
  sustain window; formant prominence `P(f) = band_rms(stem, sr, f, 2.5) /
  rms(stem)`: `P_oboe(1050) > 1.4 · P_clarinet(1050)` and
  `P_bassoon(500)` at key 45 `> 1.4 · P_tenor_sax(500)` at key 45.
  **RD-O5b** — `P_english_horn(930) / P_english_horn(1900)` >
  `P_oboe(930) / P_oboe(1900)` at key 64 (the EH's low-formant dominance).
- **RD-O6 — sax family ordering.** Key 60 vel 100 (inside all four ranges),
  sustain window: `centroid` strictly increasing bari < tenor < alto <
  soprano, with soprano/bari ratio ≥ 1.3.
- **RD-O7 — velocity opens timbre.** Prog 66 key 55: `centroid(vel 120) ≥
  1.25 · centroid(vel 40)` (RD3 law predicts a cutoff ratio of ~2.2);
  and RMS(vel 120) > RMS(vel 40) (level law sanity).
- **RD-O8 — breath and chiff.** (a) Differential, same seed: a
  `#[cfg(test)]` construction path with `breath = 0` (ORC-12-style seam —
  `reed()` stays thin over a parametric `Reed::from_preset`) vs the preset:
  `hp_rms(sustain window, sr, 5000)` ratio ≥ 1.8, full-band RMS within
  1 dB (breath is quiet, not a level change). (b) Chiff: prog 65 vel 120,
  `hp_rms(0–20 ms, sr, 3000) / hp_rms(200–220 ms, sr, 3000) ≥ 2.0`; and
  chiff energy(vel 120)/chiff energy(vel 30) > 10 (super-linear law
  `vn·vel_amp` predicts ~(4)^2.6 ≈ 37).
- **RD-O9 — scoop then true pitch.** Prog 65 key 64 vel 100:
  `peak_locate(0–90 ms) ≤ 0.994 × peak_locate(0.4–0.9 s)` and the late
  window within ±0.5% of `key_freq(64)`. Fails on `main`: a pluck is at
  target pitch from the first cycle. (Mirrors `bowed_scoop_settles`.)
- **RD-O10 — slur + pitch-control completeness (INT-5/INT-2), engine-level.**
  (a) CC68 = 127, key 64 then key 67 overlapping at 0.4 s on a prog 66
  channel: `stats.max_polyphony == 1` and `peak_locate(0.8–1.3 s)` within
  ±0.5% of `key_freq(67)`; same song with CC68 = 0 has max_polyphony 2.
  (b) With CC1 = 96 authored AND pitch bend +2 semitones on a held prog 71
  note: `peak_locate` in a late window within ±3% of the bent target —
  re-asserted **under the active modulator**, per INT-2. (Depends on the
  `vibrato_family` edit; oracle lives in `engine.rs` tests.)
- **RD-O11 — level matching.** For each of the 8 programs at its pinned
  comfort key (64:72, 65:67, 66:60, 67:50, 68:76, 69:69, 70:46, 71:62),
  vel 100 solo stem: sustain-window RMS within ±3 dB of the 8-program mean,
  and within ±3 dB of the Wind flute stem (prog 73 key 72). This oracle is
  the arbiter for the §5 `amp` column — the table values are calibrated
  starting points, adjusted at implementation with the reason in the commit.
- **RD-O12 — RD4 alias bound.** Prog 67 key 69 (bari's top) vel 127:
  `hp_rms(seg, sr, 10_000) / rms(seg) < 0.02` — the un-oversampled tanh's
  fold-back products stay ≥ 34 dB down (the RD3 LP at ≤ 4.2 kHz does the
  suppression).
- **RD-O13 — housekeeping.** `gm_routing_pins_voice_kinds` rows 64–71 →
  `"reed"` (fails on `main`: routing returns the STEEL pluck); `Reed` added
  to `voices_decay_and_die` (`voices.rs:2569`) and
  `sustained_voice_needs_note_off` (`voices.rs:2582`) lists; 1 s render
  |mean| < 1e-3 and all samples finite (oracle-43 style).

Honest caveat (house rule): every oracle is a measurable proxy; the true
acceptance ceiling is a human A/B listen this machine cannot perform.

## 9. Size & risks

~290 LOC `voices.rs` (`ReedPreset`, 8 consts, `Reed`, `reed()`, `make()`

recapture. The engine edits (§6 items 2–3) are counted under
