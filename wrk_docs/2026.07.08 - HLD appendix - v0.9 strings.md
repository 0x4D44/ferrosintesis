# design_strings.md — String ensemble 48–51 polish (v0.9 HLD section)

Baseline: hollowsynth v0.8.1. All line anchors verified against the current
source (`fable5/hollowsynth/src/voices.rs`, `src/engine.rs`); structural
anchors given alongside. Mechanism ids: **ST1** (envelope-coupled
brightness), **ST2** (CC1 section vibrato), **ST3** (synth-strings 50/51
identity). All Hz values assume the default 44100 Hz `Options.sr`; test
renders pin `sr = 44100.0`.

---

## 1. Goal

1. **ST1** — the ensemble tone opens as a note swells and closes as it dies
   (the SawStack analogue of Bowed's bow-pressure coupling,
   `Bowed::render` at `voices.rs:1861`:
   `self.lp.set_cutoff(900.0 + 5200.0 * self.last_env, ..)`). Today the
   strings lowpass is built once and never moves (`strings()` at
   `voices.rs:1564`), so a pp pad and an ff tutti have identical spectra —
   the "sampled at one dynamic" tell. **Scope of the coupling (read before
   §7):** ST1 tracks each note's own `Adsr` level — velocity → attack rise →
   release fall — NOT CC11 expression swells. Every committed strings part
   crescendos via CC11 (Expr ×128–×382 on the 48/49 channels, map_albums.md),
   and CC11 scales strip gain *post-env*; it never drives `last_env`. So on
   the committed repertoire — long, CC11-swelled held pads — ST1's audible
   reach is each note's attack rise and release fall, not the sustained
   swell. Coupling brightness to CC11 was **rejected**: it would move the
   cutoff throughout every held sustain, breaking the held-note steady-timbre
   stability the §7 waiver bound rests on. So "section swells open the tone"
   means per-note dynamics (and new velocity-dynamic writing), not the
   CC11-swelled sustains that dominate the existing albums.
2. **ST2** — make CC1 do something on 48–51. Today CC1 on a strings channel
   is a **complete no-op**: `vibrato_family` (`engine.rs:61–64`) excludes
   48–51, so the CC1 per-block pass falls into the else-branch
   (`engine.rs:1025–1027`, `mod_engaged = false`). The design is *section*
   vibrato — the wheel deepens each layer's own decorrelated vibrato, not a
   coherent channel LFO.
3. **ST3** — give 50 (SynthStrings1) and 51 (SynthStrings2) their own voices.
   Today `strings()` (`voices.rs:1564–1586`) branches only on
   `program == 49`; 50 and 51 render exactly as 48.

Success is measured (oracles §8), never "sounds better".

## 2. Current state (what the code does now)

- `voices::make` routes `48..=51 => strings(program, ...)`
  (`voices.rs:2015`) returning a `SawStack` (`voices.rs:1378–1393`):
  5 `BlepSaw` layers spread ±0.007, per-layer vibrato rate
  `5.1 Hz·(1 ± 0.15·seed)` and phase, per-layer `Drift` (0.0035, 2800 ticks),
  through `StackFilter::Lp(Biquad::lowpass(4200 or 3200, 0.7, sr))`, then
  `× amp × env.next()` (`render`, `voices.rs:1497–1524`). Program 49 gets
  the 3200 Hz cutoff and the slow envelope
  `Adsr(vel_attack(0.45), 0.3, 0.85, 0.8)`; 48/50/51 get 4200 Hz and
  `Adsr(vel_attack(0.07), 0.3, 0.85, 0.35)`. Amp const 0.22 with the
  standard `0.4 + 0.6·vel_amp` compression (`voices.rs:1445`).
- The Lp cutoff is retuned only by the pad sweep LFO
  (`control_tick`, `voices.rs:1485–1491`); strings pass `sweep = None`, so
  for 48–51 the filter is static for the life of the note.
- `set_pitch` stores the composed bend multiplier (`voices.rs:1534–1537`);
  applied at control rate (`voices.rs:1465–1468`). `CTRL = 16`
  (`voices.rs:62`).
- Engine: 48–51 **are** in `aftertouch_family` (`engine.rs:70–72`, explicit
  `48..=54`), so channel aftertouch already swells gain and adds vibrato via
  `set_pitch` (`engine.rs:1049–1062`). They are **not** in `vibrato_family`,
  and must stay out of it (a coherent ±35-cent channel LFO on a 5-layer
  section sounds like a warble on tape, and adding them there would also
  double-write `set_pitch`). `fx_profile` gives 48–51 (chorus 0.35, echo 0)
  (`engine.rs:253–269`) — unchanged by this design.

## 3. Design

### ST1 — envelope-coupled brightness (SawStack, Lp variant only)

Physical model: a string section playing louder bows harder; Helmholtz
stick-slip generates proportionally more upper-harmonic energy, so the
ensemble's spectral rolloff slides up roughly an octave from pp to ff. We
reuse the note's own `Adsr` level as the bow-pressure proxy, exactly as
`Bowed` does with `last_env`.

Mechanism, in `SawStack`:

- New fields: `lp_base: f32`, `lp_q: f32`, `lp_cur: f32`,
  `env_bright: Option<(f32, f32)>` (= `(floor, ref_level)`),
  `last_env: f32`.
- `render` records `self.last_env = e` each sample (the value already
  computed at `voices.rs:1520`).
- `control_tick` (`voices.rs:1450–1493`), in the `StackFilter::Lp` match arm,
  when `env_bright = Some((floor, ref_level))`:

  ```
  let open = (self.last_env / ref_level).min(1.0);
  let cut  = self.lp_base * (floor + (1.0 - floor) * open);
  if (cut - self.lp_cur).abs() > 1.0 {        // formant-morph idiom, :1479
      b.retune_lowpass(cut, self.lp_q, sr);   // state-preserving, dsp.rs:225+
      self.lp_cur = cut;
  }
  ```

- `ref_level` = the preset's Adsr sustain level, so `open` clamps to 1.0
  from end-of-attack through the whole sustain: **a held note's steady-state
  cutoff is exactly the current static value** (4200/3200 Hz). The audible
  change is confined to the attack rise and the release fall. This is the
  load-bearing property behind the regression bound in §7.
- `debug_assert!(sweep.is_none() || env_bright.is_none())` in
  `SawStack::new` — the pad sweep LFO and ST1 both retune the same Lp and
  must never coexist (pads keep `env_bright: None`).
- Choir uses `StackFilter::Formant` — structurally untouched. Pads pass
  `None` — their control path is literally unchanged (zero new retune
  calls, zero new RNG draws), preserving the untouched-family guarantee.
- Cost: at steady sustain `cut == lp_cur` ⇒ zero retunes; during
  attack/release ≤ 1 `retune_lowpass` per 16 samples per voice — the same
  budget `SynthBass` already spends (`voices.rs:1112–1133`).
- INT-6 note: the authored CC74/CC71 strip wah stacks in series *after* the
  voice Lp, same as today; ST1 only ever moves the voice cutoff **below**
  its current static value, so the worst-case series peak cannot exceed the
  v0.8.1 case.
- INT-7 note: CC64/CC66 defer `note_off`, so pedal-held notes stay at full
  brightness until pedal lift, then all darken together through their
  release — stated and accepted (committed albums author no pedals on
  strings channels).

### ST2 — CC1 section vibrato

Real section vibrato = every player deepens their own wobble; the pitches
stay decorrelated and the section reads as widening/shimmer, not a warble.
The per-layer vibrato machinery already exists (`Layer.vib_phase/vib_rate`,
`voices.rs:1357–1363`, applied at `voices.rs:1459–1468`); the wheel only
needs to drive `vib_depth`.

- **New trait method** (defaulted no-op, next to `set_trem` at
  `voices.rs:42`):

  ```rust
  /// CC1 section vibrato (SawStack strings): absolute per-layer vibrato
  /// depth target (fractional pitch deviation), engine-slewed.
  fn set_vib(&mut self, _depth: f32) {}
  ```

  `SawStack` implements it as `self.vib_depth = depth;`. The engine's
  existing 30 ms `expr_smooth` slew on `mod_cur` (`engine.rs:964`,
  `engine.rs:669`) removes zipper; depth is an amplitude on continuous
  per-layer sine phases, so per-block jumps are click-free.
- **New engine branch** in the CC1 per-block pass (`engine.rs:959–1028`),
  after the organ branch, structured exactly like the `vibrato_family`
  branch at `engine.rs:1011–1024`:

  ```rust
  } else if matches!(strip.program, 48..=51) {
      let base = voices::strings_vib_base(strip.program);
      let depth = base + (ST_CC1_VIB_DEPTH - base) * m;
      for a in active.iter_mut().filter(|a| a.ch == ch) {
          a.voice.set_vib(depth);
      }
      strip.mod_engaged = on;
  }
  ```

  with `const ST_CC1_VIB_DEPTH: f32 = 0.012;` (fractional deviation
  ≈ ±20.7 cents per layer at wheel = 127 — inside the ±20–50-cent range a
  violinist actually plays, and still decorrelated across 4–6 layers so the
  aggregate reads as shimmer). `voices::strings_vib_base(program) -> f32`
  is a new `pub` fn in voices.rs (the `organ_trem_base` precedent,
  `voices.rs:1279–1285`, called from `engine.rs:983`) returning the
  per-program base depth from the §5 table, so wheel-return-to-0 restores
  the exact program default on the final engaged pass (the
  `mod_engaged = on` pattern guarantees one last write at m = 0, as at
  `engine.rs:1024`).
- The existing skip predicate (`engine.rs:965–970`) gates the branch: a
  channel that never authors CC1 (`mod_authored` false, `mod_cur` 0) never
  enters, so `set_vib` is never called — opt-in **by construction**.
- The per-note vibrato onset (delay 0.22 s + 1 s ramp,
  `voices.rs:1451–1455`) is deliberately kept: a raised wheel deepens
  vibrato that still fades in per note, like players do. A voice spawned
  mid-block picks the depth up on the next block (≤ 64 samples).
- Pitch-control completeness (INT-2/3/5): ST2 never touches `set_pitch`;
  bend, RPN fine-tune, aftertouch vibrato and portamento compose exactly as
  today (`engine.rs:1058`, `engine.rs:1069`). Oracle ST-O9 re-asserts pitch
  under simultaneous bend + wheel.
- Do **not** add 48–51 to `vibrato_family` (`engine.rs:63`). No change to
  `aftertouch_family`, `fx_profile`, or `needs_drive`.

### ST3 — synth strings 50/51 identity

`strings()` becomes a 4-way match. Both programs are unused by every
committed album (map_albums.md §b: "Unused in committed albums: 41, 44, 45,
**50**, **51**, 53"), so their default re-voicing cannot change any
committed render.

- **50 — SynthStrings1, the string machine** (Solina character): electronic
  oscillators, not players — wider static detune (0.013), near-zero drift
  (0.0012), **no player vibrato** (depth 0.0, but `vib.0 = 5.5 Hz` so the
  per-layer rates exist and CC1/ST2 can still raise depth from zero),
  brighter and slightly resonant Lp (5200 Hz, Q 0.9 — the "phasey" sheen),
  fast attack, and **`env_bright: None`**: a divide-down string machine's
  filter genuinely does not track dynamics, and the static filter is itself
  part of the 50-vs-48 identity contrast. The program-profile chorus send
  0.35 (`engine.rs:262`) supplies the ensemble swirl.
- **51 — SynthStrings2, the dark octave pad**: 6 layers of which the last 2
  are dropped one octave (**sub layers**), dark Lp (2600 Hz, Q 0.6), the
  deepest ST1 range (floor 0.45 — from ~1170 Hz closed to 2600 Hz open),
  slowest attack/release, slow shallow vibrato. New `SawStack::new`
  parameter `sub_layers: usize`: for `i >= n_osc - sub_layers` the layer
  ratio is `0.5 * (1.0 + 0.004 * s)` with `s = ±1.0` alternating (its own
  small detune instead of the main spread), and the `BlepSaw` is
  constructed at that final ratio. Low-key guard: if `key < 40` (E2,
  82.4 Hz — sub would fall below 41 Hz), sub layers revert to ratio-1
  spread members, so a low divisi never turns to mud.
- Ctor plumbing: `SawStack::new` (`voices.rs:1395–1448`) gains
  `env_bright: Option<(f32, f32)>` and `sub_layers: usize`. That takes the
  argument count from 14 to 16 (`#[allow(clippy::too_many_arguments)]`
  already present, `voices.rs:1396`). Existing call sites `choir()`
  (`voices.rs:1588`) and `pad()` (`voices.rs:1624`) pass `None, 0` — their
  construction, including **RNG draw order**, is byte-for-byte unchanged
  (the determinism corollary in the v0.7 reconciliation: an ungated
  construction path must not add/remove/reorder draws). For 48/49 the layer
  count and draw sequence are also unchanged; only 51 draws differently,
  and 51 is unused by committed albums.

## 7. Opt-in & regression safety (grounded in map_albums.md)

**ST2 (CC1) — opt-in safe, by construction and by scan.** The engine branch
sits behind the `mod_authored`/`mod_cur` skip (`engine.rs:965–970`).
map_albums.md shows **zero committed albums author CC1 on any 48–51
channel**: every strings channel (Hollow Hill P1/P2 ch6, Signal Fire ch6,
Winter Guests P1/P2 ch6, Sub Rosa ch6, Iron Tide ch2) authors only
CC7/CC10/CC11/CC91. The CC1 authors in the corpus are organs (Signal Fire
ch5, WG P2 ch5, Sub Rosa ch13), distorted guitars (Signal Fire ch13/14),
and shakuhachi (Sub Rosa ch5) — all outside 48–51.

**ST3 (50/51) — default change to programs no committed album uses**
(map_albums.md §b). Cannot alter any committed render. (The untracked
`demos/` use 48 only.)

**ST1 on 48/49 — a maximum-blast-radius default change: the explicit
default-vs-gated fork.** Every committed album has a 48 or 49 channel (six
files: Hollow Hill P1 [48+49], P2 [49], Signal Fire, Winter Guests P1/P2,
Sub Rosa [48 ch6 each], Iron Tide [48 ch2]), so a *default* ST1 re-renders
all six — the largest blast radius any change in this design carries.
map_albums.md §(b) is explicit that a default change to a *used* 40–54
program "MUST be gated (opt-in via an authored CC or a **kit/voice-version
seam**)" — or explicitly waived. The brief's invariant permits the waiver
route but wants both paths costed and the choice surfaced. Both seams §(b)
names are genuinely viable here; this section costs each, then recommends,
and leaves the activation choice as Arthur's fork at integration.

**Either way the build lands on a byte-identical floor — Stage A.** Ship
ST2 + ST3 + all ST1 plumbing with 48/49 passing `env_bright: None` (inert).
Proof: build the v0.8.1 baseline binary in a scratch worktree, render **all
committed albums** with both binaries, `cmp` **byte-identical** (CC1 unused
on strings channels, 50/51 unused, plumbing adds no RNG draws or retunes on
the inert path). This pins every mechanism except ST1-on-48/49 as
regression-free. ST1 activation is one isolated commit on top of this floor;
the fork below is only *how that one commit is scoped*.

**Option G — gated ST1, byte-identical on all six committed albums (no
waiver).** The authored-CC seam §(b) names is available and I verified it
against the scan: every committed strings channel (HH P1/P2 ch6, Signal Fire
ch6, WG P1/P2 ch6, Sub Rosa ch6, Iron Tide ch2) authors only
CC7/CC10/CC11/CC91 — **none authors CC74 (Brightness), CC71 (Resonance), or
CC1**. So gating ST1 behind CC74-authorship on the channel (a new
`strip.bright_authored` flag mirroring `mod_authored`; `env_bright` engages
only once the channel has sent CC74) keeps every committed render
byte-identical, and lets any *new* channel opt in. This path fully honours
the v0.6+ opt-in invariant with no waiver. Its cost:
- **Existing albums gain nothing.** None author CC74, so ST1 never fires on
  committed material — and per §1's scope note, even the *default* ST1 barely
  fires there (sustain pinned, CC11 ≠ `last_env`). So the benefit Option G
  forgoes versus a default is only the small attack/release brightening on
  committed pads; the large new-music benefit is unaffected (new channels
  author CC74).
- **No natural author for a baseline timbre.** CC74 already drives the strip
  wah cutoff in series *after* the voice (INT-6), so overloading it as the
  ST1 gate is semantically muddy (authoring CC74 to get envelope-brightness
  would also engage the wah); a brand-new dedicated CC is cleaner but is a
  control no composer would think to author for what is really the *baseline*
  timbre of a string section. The engine already treats envelope→cutoff as
  baseline, not an authored effect: `Bowed` couples brightness to `last_env`
  **ungated** (`voices.rs:1861`) on used bowed programs (40/42/43). Gating ST1
  makes strings the lone family where that coupling must be switched on.
- **The voice-version seam is worse here.** §(b)'s other named option — a
  build-wide `Options` flag (the shape the drum kit-version seam takes) — is
  not a per-channel author at all; it fits the "authored channel" model least,
  and would force every album to set it to benefit. All cost, none of the
  opt-in cleanliness. It suits the drum-kit rework (a whole-kit swap) far
  better than a per-note timbre property.

**Option D — default ST1 + sanctioned re-voicing waiver (two-stage
landing).** Per the 0.8 HLD §1.5 template, made concrete as a **measured
bound** rather than a hand-wave, building on the Stage-A floor above:
- **Stage B** (one commit on top of Stage A): flip 48/49 to
  `Some((0.52, 0.85))`. The only possible album delta is ST1 on 48/49.
  Measured impact bound, checked file-by-file against the Stage-A renders
  (which equal v0.8.1): per-strings-channel `--solo` stem RMS delta ≤ 0.7 dB;
  stem sustain-window centroid delta ≤ 5 % (the sustain-matched design
  predicts ≈ 0; attacks and releases carry the intended change); full-mix RMS
  delta ≤ 0.3 dB and peak-normalisation gain delta ≤ 0.3 dB (guards the master
  normaliser at `engine.rs:1255–1267` against level pumping). **If any bound
  fails, ship Stage A only** — the retreat is deleting one commit, not a
  redesign.
- Acceptability of the waiver: (a) steady-state timbre of every held note is
  cutoff-identical by construction (§3 ST1), so the change is confined to
  attack/release transients; (b) Iron Tide already re-renders under the v0.9
  brass fallback (map_albums.md §a), so one of the six files changes
  regardless; (c) historical sound stays reproducible via per-album version
  pins in `fable5/README.md` and tagged renders. No compatibility flag, per
  the 0.8 precedent.

**Recommendation — Option D (default), surfaced as Arthur's call.**
Envelope→cutoff is a baseline timbre property, not an effect: it should
require no author, exactly as `Bowed` already ships it ungated, and it should
reach new music automatically without a composer wiring up a CC. The two-stage
landing bounds Option D's blast radius (measured deltas above) and makes
retreat a one-commit revert, and §1's scope note shows the *committed*-album
delta is small either way — so the architectural case favours default. But
this is the max-blast-radius change in the build, so it is **not** landed
silently: ship Stage A unconditionally (byte-identical, delivers ST2 + ST3),
then Arthur picks one endpoint at integration —
  1. **Stage A only** — no ST1 anywhere, byte-identical;
  2. **Stage A + Option G** — byte-identical on all six committed albums, ST1
     available to any new CC74-authoring channel (the invariant-pure path if
     byte-identity is required *and* new music should still get ST1);
  3. **Stage A + Stage B (recommended)** — default ST1, all six re-render
     within the measured bounds above; contingent on those bounds passing.
The default-vs-gated decision, and whether `.opus` renders are refreshed
(`render_opus.py`) or kept pinned, is resolved with Arthur at integration —
it is not dismissed by the design.

Golden fixture: ch8 strings is currently an untouched-family **canary**
(`testutil.rs:440–467`); this task flips it to a feature channel. The
recapture commit must state that ch7 piano and the guitar/bass channel rows
stayed **BIT-EXACT**, preserving the canary discipline that caught the
Drive DC leak.
