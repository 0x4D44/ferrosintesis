# MM-REQ-KILN-00011 - Fretless Bass Mwah

- **Status:** Draft
- **Requirement:** `MM-REQ-KILN-00011`
- **Date:** 2026-07-09

## Confirmed Intent

Implement GM 35 fretless bass as a fretless bass with a dynamic mid "mwah" bloom, not just a darker fingered-bass pluck.

## Scope

- Add the fretless-specific dynamic formant inside `fable5/hollowsynth/src/voices.rs`.
- Add the named oracle `fretless_bass_35_mwah_blooms`.
- Update hollowsynth docs and any golden fixture values that move because GM 35 deliberately changes.
- Bump hollowsynth version once with the implementation.

## Out Of Scope

- `MM-REQ-KILN-00008` and all other heavy reqs.
- Reworking the shared Karplus-Strong core beyond the small hook needed for GM 35.
- A new CC-gated feature flag or broad CC70 vowel routing for basses.
- Album composition changes.

## Approach

Use the existing `Pluck` voice rather than adding a new voice family.

1. Add a small fretless-only `MwahSpec` to `PluckPreset`, disabled by default. Initial target values:
   - start center: 460 Hz;
   - bloom center: 820 Hz;
   - Q: 1.4;
   - bloom time: 120 ms;
   - decay time: 450 ms;
   - mix gain: tuned by the oracle, starting around 0.30.
2. Enable it only on the `FRETLESS` preset.
3. In `Pluck`, add one parallel bandpass formant path with exact signal placement:
   - tap the main string after pickup, onset-pre, body EQ, and cab EQ;
   - process that tapped signal through the dynamic mwah bandpass;
   - run the normal main string through the preset output lowpass;
   - sum the mwah path after the output lowpass, before sub injection and before the shared amp / attack / release envelope.
4. Drive that formant with an envelope follower plus a bloom envelope:
   - follower input is the rectified tapped string signal, so the formant follows the note's real speaking envelope rather than a fixed gain-only timer;
   - the follower uses a fast attack and slower release to avoid zippering;
   - attack/bloom reaches its peak around 120 ms;
   - center frequency opens from a lower mid value to a higher mid value during the bloom;
   - gain decays after the bloom so it is a vocal onset, not a static EQ.
5. Keep the path deterministic and pitch-safe:
   - no random source beyond the existing per-voice seed;
   - no extra oscillator;
   - no pitch retune interaction except reading the already-rendered string signal.

This deliberately changes default GM 35 rendering. The req statement says the fretless bass must have the signature bloom, and the ledger rationale says the design must choose between default-on re-rendering and a gated opt-in. I choose default-on because a hidden CC gate would leave ordinary GM 35 still wrong.

Default-on is therefore a deliberate freeze break for GM 35. It needs Arthur's sign-off at this HLD gate. Known direct GM 35 users from the source tree include `fable5/Winter Guests`, `fable5/The Signal Fire`, `fable5/Hollow Hill`, and `gpt5-5/The Long Turning`; implementation must re-check this list from current source before validation.

## Acceptance Criteria

- `cargo test fretless_bass_35_mwah_blooms --manifest-path fable5/hollowsynth/Cargo.toml` proves:
  - same-key / same-velocity / same-seed differential: render GM 35 with mwah and a `FRETLESS` clone with `mwah: None`;
  - use at least two bass pitches, initially key 31 and key 38, so the oracle is not one lucky harmonic alignment;
  - measure the residual `with_mwah - no_mwah`, not raw program energy;
  - use fixed windows: early body 35-70 ms, bloom 105-155 ms, late 280-420 ms;
  - use the same formant bands named by `MwahSpec`: low band around 460 Hz, high band around 820 Hz, Q around 1.4;
  - bloom-window residual around the moving formant band is at least 2.0x the early residual and at least 1.6x the late residual;
  - the residual opens upward: high-band / low-band residual ratio in the bloom window is at least 1.25x the early-window ratio;
  - pitch is checked with `testutil::peak_locate` around expected f0, not zero crossings, and remains within the existing bass tolerance.
- Existing pluck/bass guards still pass, especially:
  - `gm_routing_pins_voice_kinds`;
  - `finger_noise_speaks_then_dies`;
  - `bass_articulations_distinct`;
  - `bass_sub_shaped_and_phase_random`;
  - `golden_mix_balance_holds`.
- The golden fixture update is confined to the fretless channel and master peak unless measured evidence shows a direct mix-level consequence. Piano and strings canaries must remain bit-exact or the change is wrong.
- Baseline/new binary validation:
  - render at least one prior album or fixture with no GM 35 and prove byte-identical output with `cmp`;
  - render affected GM 35 users or representative solo stems and record that the intentional change is confined to GM 35 material.
- Affected album source oracles are re-run where present:
  - `fable5/Winter Guests`: `python build.py --verify`;
  - `fable5/The Signal Fire`: `python build.py --verify`;
  - `fable5/Hollow Hill`: documented build/check command if available;
  - `gpt5-5/The Long Turning`: documented build/check command if available.
- Full hollowsynth validation passes after implementation:
  - `cargo fmt --check`;
  - `cargo clippy --all-targets -- -D warnings`;
  - `$null | cargo test --manifest-path fable5/hollowsynth/Cargo.toml`.

## Decision Log

- Default-on GM 35 change, not CC-gated: the requirement is about ordinary GM 35 sounding fretless; a CC gate would preserve the current wrong default.
- Reuse `Pluck`: fretless already has the right string, pickup, sub, noise, and release behavior; the missing part is a dynamic mid resonance.
- Parallel bandpass path rather than changing loop damping: it targets the "mwah" formant without destabilizing pitch or decay math.
- Sum the mwah path after the fretless output lowpass: the feature must be audible as a mid formant; the main string still keeps the existing fretless muffle.
- One focused oracle before implementation: the named ledger oracle is absent today, so the first code step should add it red, then make it green.

## Adversarial Review

Three internal reviewers inspected the draft HLD.

Survived refutation and folded in:

- Default-on GM 35 has real album blast radius. The req explicitly says default-on re-renders GM 35 album tracks, and source search found existing GM 35 users. The HLD now treats this as the sign-off decision and adds affected-album validation.
- The initial oracle was too vague. It could have passed a delayed static band boost. The HLD now requires a differential residual, fixed windows, two pitches, explicit bloom/decay, and upward motion.
- The first 30 ms window was confounded by existing attack noise and the 12 ms attack ramp. The HLD now starts the early comparison at 35 ms.
- Pitch safety needed the repo's Goertzel peak helper. The HLD now requires `testutil::peak_locate`.
- The signal insertion point was underspecified. The HLD now defines tap and sum points exactly.
- Golden fixture tolerance alone cannot prove containment. The HLD now adds baseline/new `cmp` validation for unaffected material and an affected GM 35 render check.

Rejected:

- Keep the new oracle's GM 35 route assertion out entirely. The new test can still assert routing cheaply, but the authoritative routing guard remains `gm_routing_pins_voice_kinds`; this is not a blocker either way.

## External Review

Claude Opus reviewed the folded HLD once in read-only plan mode.

Significant items folded in:

- The formant must be envelope-following, not only a fixed delayed bloom. The HLD now requires a rectified string envelope follower plus the bloom envelope.
- The oracle needs concrete bands co-designed with `MwahSpec`. The HLD now names 460 Hz / 820 Hz / Q 1.4 initial targets and measures those bands directly.
- The affected-album blast radius needs validation at the gate. The HLD now requires affected album source oracles/check commands in addition to render containment.

## Residual Risks

- The exact formant thresholds may need tuning after the red oracle lands because existing fretless partials already carry some low-mid energy.
- The golden fixture will move for the fretless channel by design; the important containment proof is unchanged canaries and no unrelated channel drift.
- Affected committed `.opus` files may need a later render/update decision. This HLD covers the synth behavior and validation; it does not automatically rewrite album audio.
