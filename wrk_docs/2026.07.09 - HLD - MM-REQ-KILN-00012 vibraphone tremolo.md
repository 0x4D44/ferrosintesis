# MM-REQ-KILN-00012 Vibraphone Tremolo HLD

Status: SIGNED-OFF

## Intent

GM 11 vibraphone should render as a vibraphone: a metal-bar body with an audible motor-fan amplitude tremolo, not a static bell preset.

## Scope

- Add default-on amplitude tremolo to the GM 11 vibraphone voice.
- Keep other Modal programs byte-stable unless their own code path changes in tests.
- Update ferrosintesis docs and version metadata for the shipped synth change.
- Validate committed MIDI that uses GM 11.

Out of scope:

- A full CC1 motor-speed model.
- Changing generic CC1 pitch vibrato routing.
- Reworking the existing VIBES partial table.

## Current Code Read

- `crates/ferrosintesis/src/voices.rs` builds GM 11 with `bell(... VIBES ...)`.
- `Modal::render` sums partial/noise output, then applies one gain/envelope multiplication.
- `Modal` does not implement `set_trem`; only organ voices do.
- `crates/ferrosintesis/src/engine.rs` keeps modal bells out of generic `vibrato_family`, which avoids accidental pitch vibrato.
- Committed MIDI scan found GM 11 in four files:
  - `albums/fable5/Seven Kinds of Sunlight/midi/01 - Seven Kinds of Sunlight.mid`
  - `albums/fable5/Tuxedo Noir/midi/01 - Tuxedo Noir.mid`
  - `demos/synth_feature_showcase/midi/02 - Cathedral Mechanica.mid`
  - `demos/synth_feature_showcase/midi/05 - Atlas of Unbuilt Machines.mid`

## Approach

- Add a small optional `ModalAmpTrem` state to `Modal`.
- Add `Modal::with_amp_trem(rate_hz, depth)` and enable it only in the GM 11 constructor.
- Apply the tremolo as the existing organ-style gain factor in `Modal::render`, after attack/release envelopes:
  - `gain_factor = 1.0 + depth * sin(phase)`
  - Clamp depth to a conservative range so the motor cannot invert or mute the voice.
  - Advance phase per rendered sample using `sr`.
- Use a modest default, approximately 6 Hz and 35% depth, to make the motor measurable without turning the voice into an obvious effect.
- Leave engine CC1 wiring unchanged for this req; GM 11 should not pick up pitch vibrato or Leslie behavior.
- Add a focused voice test named `vibraphone_11_motor_tremolo_modulates_amplitude`.
- Keep existing wood-bar tests as canaries for GM 12/13 behavior.

## Decision Log

- Default-on motor tremolo: accepted because the req says GM 11 must carry the defining motor-fan pulse. CC1-only would keep plain GM files static and fail the musical intent.
- Voice-local implementation: accepted because the motor is a property of GM 11, not a generic Modal behavior.
- No engine CC1 change: accepted for scope. CC1 speed/depth control is useful later, but it is not needed to make GM 11 correct and it risks colliding with existing CC1 vibrato/Leslie semantics.

## Adversarial Review

Reviewer A finding: Default-on tremolo changes existing renders for four committed MIDI files.

Refutation check: ran a structured MIDI program-change scan over committed `.mid`/`.midi` files. The finding survives. Mitigation: call this out as a deliberate render change, run corpus validation on affected albums/demos, and refresh committed listening artifacts only if the repo keeps any derived audio for those paths.

Reviewer B finding: Adding tremolo inside `Modal` could accidentally affect every bell/bar voice.

Refutation check: inspected `Modal::new`, `bell`, `make`, and current GM 11 routing. The finding does not survive if tremolo is represented as `Option<ModalAmpTrem>` defaulting to `None` and enabled only by `.with_amp_trem(...)` in the GM 11 arm. Keep this as an implementation constraint.

Reviewer C finding: A low-rate amplitude oracle may confuse natural modal decay with motor tremolo.

Refutation check: existing tests include `low_rate_am_depth`, but its fixed 5.5 Hz band is narrow and may miss the selected motor rate if changed. The finding survives. Mitigation: make the test measure both autocorrelation/rate around the expected motor period and relative AM depth versus neighboring static metal/wood-bar programs.

## Survivors Folded Into Design

- The change is default-on and intentionally render-affecting for four committed MIDI files.
- `Modal` tremolo must be opt-in per voice instance, not a new behavior of all Modal instruments.
- The oracle must detect periodic motor modulation, not just a decaying envelope.

## Residual Risks

- Perceptual taste is still a listening question: 6 Hz / 35% depth may need later tuning.
- A future CC1 motor-speed extension will need engine-level design so it does not fight existing CC1 semantics.

## External Review Triage

Claude Opus read-only review ran once. It incorrectly reported the HLD as missing; rejected because the file existed in this worktree before invocation and the review still provided code-grounded feedback from the prompt/spec.

Accepted:

- Name the GM 11 blast radius more specifically. The two affected albums with committed listening outputs are Seven Kinds of Sunlight and Tuxedo Noir; the synth-feature demo also uses GM 11.
- Preserve byte-identity for non-GM11 Modal voices by keeping tremolo state optional, defaulting to `None`, and not touching RNG draw order.
- Use `testutil::env_autocorr_peak_detrend` for the low-rate motor oracle, because the default 15 Hz detrend corner attenuates 6 Hz AM.
- Add inverted canaries for neighboring/static modal programs so the test proves the motor did not leak into wood bars or other bells.

Rejected/deferred:

- CC1 speed/depth routing: useful later, but deferred to avoid expanding CC1 semantics in this req.
- Rerendering all possible GM 11 outputs before implementation: validation belongs after the code path exists and can be compared.
