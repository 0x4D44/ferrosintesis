# 2026.07.09 - HLD - MM-REQ-KILN-00015 Keyboard Voices

Status: SIGNED-OFF

## Intent

GM 4-7 should stop rendering as the same acoustic-piano voice: GM4/5 become distinct electric pianos, GM6 becomes a plucked near-constant-loudness harpsichord, and GM7 becomes a percussive clavinet.

## Scope

- In scope: ferrosintesis default-bank programs 4, 5, 6, and 7; their LA acoustic piano sample wrapping; engine behavior that currently treats all `0..=7` as acoustic pianos.
- In scope: tests and documentation proving GM0-3 acoustic piano behavior remains unchanged and GM4-7 are distinct.
- In scope: Heliopause render containment and refreshed committed Heliopause listening copies if `ropusenc` is available. A MIDI scan found both committed Heliopause tracks use GM4 on channel 0, so this req is not byte-identical-safe for every committed album.
- Out of scope: composition changes, third-party samples, new dependencies, and redesigning the full modal/pluck architecture.
- Out of scope: changing GM3 honky-tonk piano. It remains in the existing acoustic-piano group for this req.

## Approach

- In `crates/ferrosintesis/src/voices.rs`:
  - Add `pub(crate) fn is_acoustic_piano(program: u8) -> bool`, returning true for GM0-3 only. Use this classifier in both default-bank dispatch and engine acoustic-piano gates.
  - Rename/split the current `piano()` helper as the acoustic program path.
  - Add small program-specific constructors:
    - GM4 Rhodes-style tine EP: modal fundamental plus tine/bell partials, gentler velocity brightness, longer singing tail.
    - GM5 FM/DX-style EP: brighter, more inharmonic bell partials, shorter glassy decay than GM4.
    - GM6 harpsichord: custom plucked harmonic modal table with a deliberately narrow velocity-to-level law, target max:min amplitude <= about 1.5 across low/high velocities, and no acoustic hammer noise/sample layer. Do not reuse `bell()` or `Pluck` unchanged, because both apply the broad `vel_amp()` scaling this req rejects.
    - GM7 clavinet: a short, bright `PluckPreset` with pickup/comb character, click, and quick decay.
  - Change dispatch so only GM0-3 use the acoustic piano constructor and LA piano sample bank. GM4-7 render modeled-only even when `samples` is enabled.
- In `crates/ferrosintesis/src/engine.rs`:
  - Use `voices::is_acoustic_piano()` for CC67 una-corda velocity scaling and piano sympathetic-string send, instead of `program <= 7`.
  - If needed for a direct test, add a private test-only or `pub(crate)` piano-sympathetic toggle analogous to the existing guitar-sympathetic/drum-room bus toggles. The toggle must gate `self.symp.process(...)`, not only the send feed. Do not expose a user option.
- In `crates/ferrosintesis/README.md`, update the Modal/Pluck family table to describe the new GM4-7 routing.
- Bump both ferrosintesis crate versions and `Cargo.lock` once for the shipped synth change.

## Acceptance Criteria

- `programs_4_7_do_not_use_acoustic_piano_voice` fails before implementation and passes after:
  - GM0-3 acoustic renders keep frozen matched-pitch hashes.
  - GM4-7 renders are not bit-identical to GM0 or each other at matched pitch.
  - GM4 and GM5 show different electric-piano spectra at mid and high registers, with GM5 brighter/more bell-forward than GM4 using within-clip band ratios rather than raw loudness or centroid alone.
  - GM6 has a max:min velocity loudness ratio <= about 1.5, remains audible at low velocity, and has a plucked decay profile.
  - GM7 has a short percussive decay and routes structurally through the clavinet pluck preset (`kind()` plus measurement).
  - GM4-7 render the same with `samples=true` and `samples=false`, proving they do not use the acoustic piano LA layer; GM0 is the positive control and must differ across the sample flag at a live sample-zone key/velocity.
- Engine tests prove acoustic-only behavior:
  - CC67 una corda still softens GM0.
  - CC67 does not scale GM4-7 velocity.
  - Piano sympathetic resonance is present for GM0 and absent for GM4-7, either via a private bus-toggle test seam or a direct routing-helper test plus review of the only send site.
- The acceptance command runs every new voice and engine proof, not just the voice test. Use a shared test-name prefix such as `keyboard_voices_`.
- Existing canaries remain green:
  - `cargo test --workspace`
  - `cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo fmt --check`
  - `cargo build --release -p ferrosintesis-cli`
- Album containment:
  - A read-only MIDI program scan is recorded; currently only Heliopause Part One and Part Two use GM4 among GM4-7.
  - Heliopause `python build.py --verify` passes as a MIDI/source sanity check.
  - Current-vs-baseline Heliopause channel 0 stems change.
  - At least one unrelated Heliopause non-GM4 stem per part remains byte-identical.
  - `python render_opus.py --album "Heliopause"` refreshes the two committed listening copies if `ropusenc` is available; if unavailable, record the exact blocked command and create/append a tracked follow-up rather than leaving it implicit.

## Decision Log

- Keep GM3 acoustic for now. The requirement targets GM4-7, and changing GM3 would widen the render surface without a specific acceptance oracle.
- Prefer small constructors over a new keyboard abstraction. `Modal` and `Pluck` already cover most needed behavior; a new trait/voice family would add indirection before there is stable complexity.
- Use Modal for GM6 even though a harpsichord is plucked, because the existing `Pluck` engine bakes in the broad velocity law this req rejects. Use Pluck for GM7 because clavinet is velocity-responsive and benefits from the pickup/comb machinery.
- Treat Heliopause as an affected committed album. The req rationale said GM4-7 were unused, but a binary MIDI scan found GM4 on Heliopause channel 0 in both parts.

## Adversarial Review

Three sequential reviewers were used because no separate subagent harness is available here.

- Reviewer A, DSP/oracle: warned that reusing `bell()` for harpsichord would preserve the rejected `vel_amp()` loudness law. Reviewer B agreed; Reviewer C agreed because the req specifically calls out near-constant harpsichord loudness. Survives. Design changed to require a custom GM6 velocity law.
- Reviewer A, DSP/oracle: warned that GM4-vs-GM5 brightness checks can accidentally measure level rather than spectrum. Reviewer B agreed, citing the repo lesson about matched-pitch/timbre oracles; Reviewer C had no refutation. Survives. Acceptance now requires RMS-normalized spectral comparisons.
- Reviewer B, engine/regression: warned that GM0-3 unchanged behavior needs direct proof, not just "we did not edit that match arm." Reviewer A agreed because dispatch/sample wrapping is being split; Reviewer C agreed because program 0 is heavily used. Survives. Acceptance now requires frozen matched-pitch hashes for GM0-3.
- Reviewer B, engine/testability: warned that "piano sympathetic absent for GM4-7" is not directly A/B-testable with the current public options. Reviewer A agreed that tail measurements would be noisy; Reviewer C agreed a private test seam is preferable to a broad user flag. Survives. Design now allows a private bus-toggle seam, or at minimum a helper test plus review of the single send site.
- Reviewer C, album containment: warned that the req rationale's unused-program assumption is false because Heliopause uses GM4. Reviewer A and B both agreed after the MIDI scan output. Survives. Acceptance now includes Heliopause changed-channel and unrelated-channel stem checks.

## External Review

Claude Opus reviewed the HLD in read-only plan mode. Significant items accepted and folded in:

- R1: Heliopause's committed listening copies become stale because channel 0 is authored as electric piano and currently mis-rendered as acoustic. Accepted: refresh them in this task if `ropusenc` is available; otherwise create an explicit tracked follow-up with the exact command.
- R2: The req's original `Satisfied-by` command would only run one voice test and skip engine tests. Accepted: use a shared test prefix or broader command that runs every new proof.
- R3: `samples=true == samples=false` for GM4-7 is vacuous without a GM0 positive control. Accepted: add a GM0 sample-layer positive control at a live sample-zone key/velocity.
- R4: "narrower than GM0" is too weak for harpsichord velocity. Accepted: pin GM6 to a concrete max:min loudness ratio and audible-low-velocity guard.
- R5: The acoustic-piano boundary should have one source of truth. Accepted: add `voices::is_acoustic_piano()` and consume it from engine routing.

Useful suggestions accepted:

- Treat Heliopause `build.py --verify` as MIDI sanity, not audio containment.
- State that the red oracle must be observed after the test is written; a nonexistent cargo-test filter can pass with zero tests.
- Cover mid/high registers for GM4/GM5 and use band ratios.
- Include GM5 in the CC67 no-scale test and pin GM3 as the boundary canary.
- Make GM7 routing structural with `kind()`.

Rejected or bounded:

- No user-facing piano-sympathetic feature flag. If needed, only a private test seam is allowed.
- Aftertouch for GM4-7 remains opt-in through the existing family route; no committed Heliopause GM4 channel authors aftertouch, and the voices already support pitch updates.

## Residual Risks

- Numeric timbre oracles can overfit. Keep them comparative, matched-pitch, and broad-band rather than exact spectral fingerprints.
- Heliopause channel 0 will audibly change; this is accepted as a fidelity fix because the album authors channel 0 as electric piano.
- Refreshed listening copies depend on local `ropusenc`; if unavailable, the task must leave an explicit tracked follow-up rather than a silent stale artifact.
