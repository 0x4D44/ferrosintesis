# HLD - ferrosintesis drum kit v3 as the default

Status: SIGNED-OFF

## Intent

Make ferrosintesis channel-10 drums default to the best available kit, with
especially less synthetic cymbals, and let existing album renders improve audibly
instead of preserving old drum byte identity.

## Scope

In scope:

- Replace the current drum default (`Kit::V1`) with a new best-current kit
  (`Kit::V3` / `Best`) for channel 10.
- Make MIDI with no channel-10 Program Change and MIDI with Program Change 0 both
  use the new kit.
- Improve cymbals first: crash, ride, ride bell, open/closed hats, china/splash.
- Improve bass drum, toms, and snare enough that the whole kit reads as one
  recorded-ish instrument family.
- Add a small, curated CC0 drum/percussion sample overlay where synthesis is
  weakest, controlled by the existing `samples` option (`--no-samples` keeps a
  modeled-only fallback).
- Produce before/after WAV stems for listening checks.
- Refresh only committed listening Opus files affected by channel-10 drums after
  the synth change lands green; do not create new listening files for MIDI-only
  albums.

Out of scope:

- No compatibility guarantee for old drum renders.
- No new command-line feature flags or migration controls.
- No hosted CI.
- No broad album recomposition or MIDI rewriting.
- No attempt to build a complete named GM2 kit matrix. Program Change values on
  channel 10 all select the best current standard kit for now.
- No hi-hat samples in this pass. Hats remain modeled so sample tails cannot
  evade choke behavior.

## Current State

- `crates/ferrosintesis/src/engine.rs:571` initializes channel strips with
  `drums::Kit::V1`.
- `crates/ferrosintesis/src/engine.rs:1098` switches channel 10 to `Kit::V2`
  only when a non-zero Program Change is received.
- `crates/ferrosintesis/src/drums.rs` currently has `Kit::V1` and `Kit::V2`.
  `V2` improves crash tails, tom pitch drop, open-hat motion, and snare wire
  rattle, but many cymbal keys still use the older six-partial-plus-noise model.
- `crates/ferrosintesis/src/sampler.rs` embeds piano, violin, and flute attack
  samples only. The existing sample switch is already default-on and disabled by
  `--no-samples`.
- `crates/ferrosintesis/samples/prepare.py` already downloads VSCO 2 CE assets
  under CC0. For this task, pin VSCO 2 CE `master` at
  `440300901dfe9275fd84e0b7763af1f8443ae62e` and use only exact source paths
  listed in this HLD.

## Approach

### 1. Default-policy change

Keep the old kit code as internal test references, but remove it from the normal
render path.

- Add `Kit::V3`.
- Change `Strip::new` to initialize `kit: drums::Kit::V3`.
- Change channel-10 `program_change` so every Program Change value, including 0,
  keeps/selects `Kit::V3`.
- Update comments and README text to state that the default kit is the current
  best kit and old renders are expected to change.
- Retain direct `drums::make(..., Kit::V1/V2, ...)` access in tests for
  differential oracles only.

Acceptance:

- Engine-to-engine dry render test: no channel-10 Program Change, Program Change
  0, Program Change 8, and Program Change 16 produce the same V3 crash render
  under identical dry options.
- Engine-to-engine dry render test: the V3 default crash differs materially from
  a test-only legacy/V1 render of the same hit.
- Existing non-drum routing tests still pass.

### 2. Cymbals: new `MetalPlate` path

Do not stretch `CymSpec` into a second instrument. Add a dedicated cymbal voice
for `Kit::V3`, while leaving `CymSpec` for legacy and V2 tests.

Mechanism:

- `MetalPlate` voice with 32-48 deterministic modes per default hit. Higher
  counts are an experimental ceiling only, not the shipped default.
- Use `dsp::Sine` rotation oscillators rather than calling `sin()` per mode.
- Seeded mode frequencies are clustered around per-key profiles, not a single
  six-ratio table.
- Frequency-dependent decay: high modes die fastest, mid/noise wash survives,
  and no single tonal line dominates the late tail.
- Seeded per-hit mode balance and slight frequency scatter.
- Noise wash uses multiple colored bands plus slow noise-coupled AM. Any
  relied-on beat pair must satisfy the repo lesson: ring time spans the beat
  period.

Key profiles:

- 49/57 crash: sampled/colored onset, swelling dense wash, no stable sine tail,
  3-5 s life.
- 51 ride: persistent wash plus short ping; repeated hits must articulate
  without becoming a small crash.
- 53 ride bell: short clang with sharper stick attack and less wash.
- 42 closed hat: short stick tick plus bright metal burst.
- 44 pedal hat: the foot "chick" — shorter, duller and a shade quieter than 42, and
  with **no** stick tick. (Superseded 2026-07-26. This line originally read
  "42/44 closed/pedal hats: short stick tick plus bright metal burst", giving both
  keys one profile. That was wrong: a pedal hat is closed by the foot, so nothing
  strikes it and it cannot have a stick attack. The two keys shared a `CymSpec`
  until the split; `drums::tests::pedal_hat_is_not_a_closed_hat` now holds them
  apart. Recorded here rather than silently edited, because this document is
  SIGNED-OFF and the change is a correction to what was agreed.)
- 46 open hat: body plus fast sizzle, falling centroid, and strong choke.
- 52 china and 55 splash: dedicated profiles, not crash aliases.

Acceptance:

- Render key 49 crash, velocity 100, seed 7, 44.1 kHz, 4.0 s in both
  `samples=false` and the shipped default `samples=true` paths. In windows
  [0.50, 1.50] s and [1.50, 3.50] s, spectral flatness over 700-12000 Hz must
  be at least 1.5x V2 and >= 0.18 in both paths; the samples-on value must not
  regress below the modeled value after fail-first calibration.
- For the same crash, narrow-line dominance must be bounded in both samples
  modes across 700-1500 Hz, 1500-4000 Hz, and 4000-12000 Hz windows: strongest
  Goertzel/bin peak divided by band RMS <= 0.45 in [0.50, 1.50] s and <= 0.35
  in [1.50, 3.50] s. These exact numbers may only be tightened after fail-first
  calibration.
- Crash bloom: rectified 400 Hz-lowpassed >6 kHz envelope has non-zero impact in
  [0, 5] ms, but its maximum wash level occurs after 12 ms and before 90 ms.
- Ride key 51, velocity 110, seed 7: >7.5 kHz RMS in [0, 30] ms is at least 4x
  [150, 300] ms; broadband RMS in [1.20, 1.80] s is > 5e-6.
- Ride bell key 53, velocity 110, seed 7: [0, 40] ms >7 kHz energy is at least
  3x the [120, 260] ms value, and at least four inharmonic peaks above -24 dB
  relative to the strongest peak are present below 9 kHz.
- Open-hat key 46, velocity 100, seed 7: centroid([20,120] ms) /
  centroid([300,500] ms) >= 1.30 and >= V2 ratio.
- Hat choke test runs the normal engine path, `samples=true` and `samples=false`,
  even though V3 does not sample hats; open-hat tail after a closed-hat hit must
  be < 5% of the unchoked tail after 30 ms.
- Cymbal level guard: V3 RMS for each changed cymbal key over its musical life
  stays within +/-3 dB of V2 in both samples-off and samples-on modes, unless a
  specific key has a documented musical reason and the album spot checks still
  pass.
- Performance guard: V3 cymbal mode constants are capped at <= 48 modes per hit
  by default; a dense 30 s drum-pattern render is timed and recorded in the
  journal, with a target of <= 1.75x the V2 modeled render on the same machine.

### 3. Bass drum, toms, and snare: `MembraneDrum` cleanup

The current `Drum` membrane path is already serviceable. For V3, keep the model
small and improve the loud tells.

Mechanism:

- Add a V3 membrane table path, not a generic physical simulator.
- Kick 35/36: preserve sub drop, add a clearer click/body separation and a short
  low-mid punch. Avoid DC and keep sub centered through existing drum pan.
- Toms 41/43/45/47/48/50: keep V2's plausible settle behavior, add one or two
  shell/body bands and slightly longer low-mode sustain for large toms.
- Snare 38/40: keep V2's wire cluster, add a short sample/overlay crack when
  samples are enabled and a model-only crack when disabled.

Acceptance:

- Kick hard-vs-soft normalized click ratio still increases with velocity.
- Kick sub energy is present in the 40-90 Hz band without DC offset.
- Toms settle near table pitch using `peak_locate`, not zero crossings.
- Snare wire-cluster oracle still passes and 38/40 remain distinguishable.
- Auxiliary GM percussion smoke: side stick 37, clap 39, tambourine 54,
  cowbell 56, congas/bongos 60-66, shakers 69/70/82, and triangles 80/81 remain
  non-silent, finite, and within +/-4 dB of their current RMS. They need not be
  redesigned in this pass, but they must not become obvious level outliers
  beside the V3 core kit.

### 4. Sample overlay

Use samples only where they buy realism that the model struggles to fake. Do not
turn drums into a static one-shot player.

Implementation shape:

- Extend `sampler.rs` with unpitched `HitBank` / `SampleOverlay` helpers.
- Add a small drum sample set to `crates/ferrosintesis/samples/`, built by
  `prepare.py` from VSCO 2 CE raw WAVs:
  - `drum_crash_mf_rr1.wav` from
    `Percussion/susCymb1-hit_mp_rr1.wav`;
  - `drum_crash_mf_rr2.wav` from
    `Percussion/susCymb1-hit_mp_rr2.wav`;
  - `drum_crash_f_rr1.wav` from
    `Percussion/cymbal-crash1_ff_rr1.wav`;
  - `drum_crash_f_rr2.wav` from
    `Percussion/cymbal-crash1_ff_rr2.wav`;
  - `drum_kick_rr1.wav` from
    `Percussion/BDrumNewhit_v3_rr1_Sum.wav`;
  - `drum_kick_rr2.wav` from
    `Percussion/BDrumNewhit_v3_rr2_Sum.wav`;
  - `drum_snare_rr1.wav` from
    `Percussion/Snare2-HitSN_v5_rr1_Sum.wav`;
  - `drum_snare_rr2.wav` from
    `Percussion/Snare2-HitSN_v5_rr2_Sum.wav`.
- Samples are mono 16-bit 44.1 kHz, short, normalized, and faded by
  `prepare.py`.
- Duration/gain policy:
  - crash samples keep at most 2.2 s, with the last 0.35 s faded to zero;
  - kick and snare samples keep at most 0.45 s, with the last 0.08 s faded;
  - overlay gain is keyed by drum type and velocity, with a target sample-only
    contribution of -10 to -4 dB below the modeled hit RMS over [0, 300] ms;
  - sample onset is aligned to the modeled hit at sample 0 after a short
    pre-onset trim, so no flam is introduced.
- `drums::make` gains a `samples: bool` argument. `engine.rs` passes
  `self.opt.samples`; direct tests can choose on/off.
- With `samples == false`, V3 still uses the modeled `MetalPlate` and membrane
  improvements.
- With `samples == true`, V3 overlays a sample transient/wash on top of the
  modeled voice, with deterministic round-robin selection from the existing
  seed.
- `SampleOverlay` forwards `note_off`, `set_pitch`, `legato_to`, and `choke` to
  the wrapped model. V3 does not use hat samples, but forwarding `choke` keeps
  the wrapper safe if a future chokeable drum ever uses it.

Acceptance:

- Sample bank parse/prewarm test covers drum banks.
- `--no-samples` render of a V3 drum demo still produces non-silent, passing
  modeled drum oracles.
- Engine-level render test: channel-10 crash/kick/snare with `Options.samples =
  true` differs from `Options.samples = false`; the same test through
  `ferrosintesis --no-samples` is exercised by a before/after stem command.
- `RealtimeSynth::prewarm_samples()` reaches the new drum banks without panic.
- Samples-on vs samples-off direct drum tests also differ for crash/kick/snare,
  proving the layer is actually engaged below the engine.
- No sample overlay clips or creates non-finite samples.
- Regenerating the sample bank is deterministic: after `python
  crates/ferrosintesis/samples/prepare.py`, `git diff --exit-code --
  crates/ferrosintesis/samples crates/ferrosintesis/src/sampler.rs` passes.

### 5. Before/after listening artifacts

Create a short deterministic MIDI under `target/drum-kit-v3/drum_check.mid`.
Use a tiny stdlib Python helper and record the exact helper source or command in
the journal; commit it under `demos/` only if it proves broadly useful rather
than a one-off validation fixture. The MIDI contains kick/snare/tom, closed/open
hats, ride, ride bell, crash 49/57, china, and splash.

Reproducible commands:

1. Before: create a temporary baseline worktree from `origin/main`, build
   `ferrosintesis-cli`, and render `drum_check.mid` to
   `target/drum-kit-v3/before-origin-main.wav`.
2. After: build this task worktree and render the same MIDI to
   `target/drum-kit-v3/after-v3-samples.wav`.
3. Fallback: render this task worktree with `--no-samples` to
   `target/drum-kit-v3/after-v3-no-samples.wav`.

These WAVs are verification artifacts, not committed source. Report their paths
in the implementation result.

### 6. Album refresh

After Rust validation is green:

- Build `ferrosintesis-cli --release`.
- Inventory committed listening files before rendering:
  `git ls-files listening > target/drum-kit-v3/listening-before.txt`.
- Scan source MIDIs for channel-10 note events and produce
  `target/drum-kit-v3/drum-listening-targets.txt`, mapping only already
  committed listening files to their source MIDI.
- Render only those target files/albums. Do not run a blind all-album
  `python render_opus.py`, because `render_opus.py` would create Opus files for
  MIDI-only albums (`VIGIL`, `RIVERWAKE`, `The Long Turning`).
- After rendering, assert no new listening files:
  `git ls-files --others --exclude-standard listening` must print nothing.
- Expect committed `listening/*.opus` files that contain drums to change.
- Do not regenerate album MIDI unless an album builder is explicitly touched
  later, which this design does not require.
- Run a small full-mix spot-check set before accepting the asset refresh:
  `Sub Rosa`, `The Burning Meridian`, `The Ninth Bell`, `Tuxedo Noir`, and
  `Synth Feature Showcase / Ignition Court`. For each, compare before/after
  peak and integrated RMS; peak must stay finite and RMS shift should be within
  +/-3 dB unless documented in the journal after listening.

## Decision Log

- Defaults beat compatibility for drums. The old authored-channel invariant is
  intentionally waived for this task because the product goal is better sound by
  default.
- Keep `V1`/`V2` internally for differential tests, not as user-facing
  compatibility paths.
- Add a small sample overlay rather than a large drum ROM. The model still owns
  sustain, dynamics, and `--no-samples`.
- Do cymbals first because they are the most audible synthetic tell.
- Refresh listening Opus files after the synth lands because old tracks are
  expected to improve.

## Internal Adversarial Review

Three reviewers examined the draft, then each ran a refutation pass over the
combined findings. Surviving findings folded into this revision:

- Cymbal oracles were too vague. Added seeds, velocities, windows, ratios, and
  band coverage including the audible 1500-4000 Hz clang region.
- Sample overlay needed gain, velocity, alignment, and deterministic
  regeneration rules. Added exact VSCO source files, revision, generated names,
  duration/gain policy, and no-diff `prepare.py` acceptance.
- Sample-on tests needed to go through the engine and realtime prewarm, not only
  direct drum construction. Added engine-level and prewarm acceptance.
- The default-policy test compared direct drum output to full engine output.
  Replaced with engine-to-engine no-PC/PC0/PC8/PC16 comparisons.
- Album refresh was too broad. Replaced blind `render_opus.py` with a
  committed-listening and channel-10 target inventory, plus a no-new-files guard.
- Full-mix audio guard was missing. Added peak/RMS spot checks for drum-heavy
  albums.
- Performance was only a residual risk. Added mode-count cap and dense-pattern
  timing requirement.
- Stale Synth Feature Showcase v2-kit assumptions needed an acceptance gate.
  Added rebuild/verify/manifest freshness.
- Before/after WAVs were not reproducible. Added a baseline worktree command
  shape and exact output paths.

Refuted or downgraded:

- Sample-on hat choke was partially refuted because V3 deliberately does not
  sample hats. The design still requires `SampleOverlay::choke` forwarding as a
  defensive wrapper rule.
- Enumerating every `drums::make` call site was considered unnecessary by one
  reviewer because the compiler catches signature fallout; the design still
  names `testutil.rs` because it is a known direct caller.

## External Review

Claude Opus ran one read-only fresh-eyes pass. No critical findings survived.

Folded:

- The major finding was that the original cymbal timbre bars mostly proved
  `samples=false`, while the shipped default is `samples=true`. The cymbal
  flatness, narrow-line, and level guards now explicitly cover the samples-on
  default as well as the modeled fallback.
- Mode-count wording contradicted the performance cap. The design now says
  32-48 modes by default.
- The deterministic before/after MIDI generation was under-specified. The
  journal must now record the exact helper source or command, with a committed
  helper only if it becomes generally useful.

Noted but not expanded:

- Dense ride patterns are the likely CPU worst case because ride hits overlap
  frequently. The existing dense-pattern timing guard covers this; if it fails,
  reduce ride mode count before adding broader machinery.
- The sample overlay could be split into a follow-up because modeled V3 is
  independently gated. Rejected for now: Arthur asked for the end-to-end sound
  improvement, and the overlay remains a small, testable layer.

## Residual Risks

- VSCO percussion is orchestral, not a close-mic rock kit. It may improve crash,
  snare, and bass-drum attacks but still need careful gains to avoid sounding
  like an orchestral percussion section in all genres.
- More cymbal modes cost CPU. Dense ride patterns are the likely worst case
  because overlapping ride hits multiply mode count by polyphony. Keep mode
  counts bounded, use `dsp::Sine`, and reduce ride modes first if timing fails.
- Album normalization can hide or exaggerate drum improvements. Use solo stems
  and full-mix spot checks.
- `listening/*.opus` refresh is a large binary-artifact change.
