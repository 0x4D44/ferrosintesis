# HLD: ferrosintesis repo restructure

Status: DRAFT

## Intent

Promote the current `fable5/hollowsynth` synthesizer into the first-class
`ferrosintesis` Rust product: a publishable library crate, a separate CLI for
offline rendering, and album files arranged as the corpus that proves the synth.

## Scope

In scope after sign-off:

- Replace the placeholder `crates/ferrosintesis` package with the real synth
  library now living at `fable5/hollowsynth`.
- Add a root Cargo workspace with `crates/ferrosintesis` and
  `crates/ferrosintesis-cli`.
- Keep the core library focused on synthesis and PCM output. It must not depend
  on Opus encoding.
- Move the existing command-line WAV renderer into `ferrosintesis-cli`.
- Add Opus output to the CLI through the published `ropus` crate plus the
  small `ogg` container crate, with the CLI owning file-format and tagging
  concerns.
- Move album directories under `albums/` and update repo scripts/docs to match.
- Update `render_opus.py` so it no longer hardcodes
  `fable5/hollowsynth/target/release/hollowsynth`.
- Preserve current audio behavior unless a code rename mechanically changes
  paths. This is a restructure, not a new voicing pass.

Out of scope:

- New synth voices, balance changes, controller behavior changes, or album
  recomposition.
- Published crates.io release beyond local package verification. Publishing a
  real `ferrosintesis` version remains a separate explicit release action.
- Backwards-compatible wrapper paths for the old `fable5/hollowsynth` location.
  This is a development sandbox; docs and scripts move to the new layout.
- Moving or rewriting per-album Python architecture beyond path updates needed
  for the `albums/` move.

## Current Facts

- The real synth package is `fable5/hollowsynth`, currently version `0.9.2`.
- The published `ferrosintesis v0.0.0` placeholder already exists under
  `crates/ferrosintesis`.
- The post-restructure package version is `0.9.3`: one patch bump from the
  current real synth because this is shipped-code packaging work, not a voice
  or API-breaking change.
- Current public library surface:
  - `offline::{load, parse, render, write_wav, normalize_to_i16, Options, Stats}`
  - `live::{RealtimeSynth, RealtimeOptions, RealtimeError}`
- The CLI currently lives in `fable5/hollowsynth/src/main.rs`, renders WAV only,
  and imports `hollowsynth::offline`.
- `render_opus.py` renders with the hardcoded binary path
  `fable5/hollowsynth/target/release/hollowsynth(.exe)`, then shells out to
  `ropusenc`.
- The sample bank is embedded with `include_bytes!(concat!("../samples/", ...))`.
  It is about 9.56 MB on disk. `cargo package --no-verify` for the current synth
  produced a 6.9 MiB compressed package, below crates.io's package limit.
- `ropus v0.12.18` is published, BSD-3-Clause, Rust 1.88, and has no default
  features. It produces raw Opus packets; its own examples use the `ogg` crate
  for RFC 7845 Ogg-Opus container pages.
- `ogg v0.9.2` is published, BSD-3-Clause, Rust 1.61, and is sufficient for
  the CLI-only container-writing dependency.
- The current album batch has 15 album entries and 53 MIDI files.

## Approach

1. Create a root Cargo workspace.
   - Workspace members:
     - `crates/ferrosintesis`
     - `crates/ferrosintesis-cli`
   - Workspace/package version is `0.9.3`.
   - The root owns `Cargo.lock`. Remove member `Cargo.lock` files.
   - Keep release profile settings at the workspace root if Cargo accepts them
     cleanly for both packages.

2. Promote the library.
   - Move all real synth source and samples from `fable5/hollowsynth` into
     `crates/ferrosintesis`.
   - Remove the placeholder `src/lib.rs`.
   - Rename crate references from `hollowsynth` to `ferrosintesis`.
   - Keep internal modules private as they are now. Do not expose DSP internals
     during the restructure.
   - Do not add `Options::Default` in this pass. Current CLI defaults derive
     echo delay from `Song::initial_bpm()`, while `Options` stores a concrete
     `delay_s`; a static default would be misleading and risks changing renders.
   - Error types can remain `String` for this move unless the implementation
     already needs a typed error.

3. Split the CLI.
   - Move the old `src/main.rs` behavior into `crates/ferrosintesis-cli`.
   - Binary name: `ferrosintesis`.
   - Library dependency: local path `ferrosintesis`.
   - CLI outputs:
     - `.wav` via existing `write_wav`.
     - `.opus` via `ropus` packet encoding and `ogg` page writing, selected by
       output extension or an explicit `--format wav|opus` flag.
   - Preserve existing options: input, `-o/--out`, `--rate`, `--wet`,
     `--delay`, `--tail`, `--no-samples`, `--solo`, `-q/--quiet`.
   - For WAV, preserve the current default sample rate: 44,100 Hz.
   - For Opus, use 48,000 Hz by default because Opus encoders accept only
     8/12/16/24/48 kHz input. If the user passes `--rate` for Opus, accept only
     those rates and fail fast otherwise. Do not add resampling.
   - Add only the smallest Opus options needed for current repo use:
     `--bitrate` defaulting to `96000`, standard Vorbis comments via repeated
     `--comment KEY=VALUE`, and convenience tag flags only if they keep
     `render_opus.py` simpler than its current `ropusenc` call.

4. Move albums under `albums/`.
   - Move `fable5`, `gpt5-3-spark`, `gpt5-5`, and `opus4-8`.
   - Update `render_opus.py::ALBUMS`, README links, CLAUDE.md layout/commands,
     `.gitignore` sample exceptions, and reqs ledger command/path references.
   - Preserve committed `midi/`, `audio/`, manifests, and album docs.

5. Update repo rendering.
   - Build command becomes `cargo build --release -p ferrosintesis-cli`.
   - `render_opus.py` locates the CLI at
     `target/release/ferrosintesis(.exe)`.
   - For the repo batch path, prefer the new CLI's Opus output once it carries
     the existing tags. If the CLI tag surface grows beyond the lean scope,
     keep `render_opus.py`'s existing `ropusenc` call and only switch the synth
     binary path in this task.

6. Delete the old synth package path.
   - No duplicate `fable5/hollowsynth` package remains.
   - All docs point to `crates/ferrosintesis`.

## Decision Log

- Use `ferrosintesis` as the public library crate name because it is already
  reserved and separates the synth product from the album that birthed it.
- Keep Opus out of the core library. The synth is reusable for games, emulators,
  and offline tools; Opus is a file-output concern.
- Add `ogg` only to the CLI. `ropus` owns Opus packets; Ogg-Opus files need
  Ogg pages, `OpusHead`, `OpusTags`, granule positions, and EOS handling.
- Keep `render_opus.py` at root for this pass. It is repo-specific orchestration,
  and moving it to `tools/` adds another path churn without improving the
  product boundary.
- Move albums under one `albums/` directory. This makes root ownership obvious:
  product crates at `crates/`, corpus at `albums/`, work docs at `wrk_*`.
- Do not add feature flags for "no samples" or "opus". The user explicitly asked
  for a lean process and to avoid feature-flag sprawl; runtime CLI options are
  enough.
- Do not preserve `hollowsynth` as a compatibility crate or binary. This repo is
  still in a development sandbox; duplicate names would make future docs and
  package ownership less clear.

## Review Findings

Internal adversarial review used two reviewers and one refutation pass. Surviving
or accepted findings folded into this HLD:

- **Final version must be explicit.** Both reviewers found that the design named
  `hollowsynth 0.9.2` and placeholder `ferrosintesis 0.0.0` but did not state
  the post-restructure version. Resolved by pinning `0.9.3` and adding metadata
  acceptance.
- **Package verification must build the package.** `cargo package --no-verify`
  is too weak for a publishable crate with `include_bytes!` samples. Resolved by
  requiring verifying `cargo package`.
- **Do not add `Options::Default` blindly.** The current delay default is
  song-derived. Resolved by preserving CLI-derived defaults and not adding a
  static `Options::Default` in this pass.
- **Path validation must cover all albums.** One rendered album can miss stale
  paths. Resolved by requiring every album key to contain MIDI and the total to
  remain 53.
- **Native Opus needs a container dependency.** `ropus` produces raw packets;
  Ogg-Opus needs container pages and tags. Resolved by adding `ogg` to the CLI
  scope and making `OpusHead`/`OpusTags` part of acceptance.
- **Audio preservation needs a real oracle.** Non-empty WAV output is not enough.
  Resolved by requiring old/new byte comparison for a representative WAV render.
- **Workspace lockfile ownership matters.** Resolved by moving lock ownership to
  root and removing member lockfiles.
- **Reqs ledger paths must move too.** Resolved by adding `reqs/*.md` to file
  impact and search acceptance.

Reviewer B marked the Opus sample-rate finding unverified from repo/design facts
alone. A main-agent follow-up checked local `ropus 0.12.18` examples, which accept
only 8/12/16/24/48 kHz and explicitly do not resample. The HLD now defaults Opus
output to 48 kHz and rejects unsupported explicit Opus rates.

## Residual Risks

- Native Ogg-Opus writing may still take more code than expected even with
  `ropus` and `ogg`. If it grows beyond a small CLI helper, pause before
  implementation and rescope rather than hiding a codec/container project inside
  the restructure.
- Moving album directories creates broad path churn. The implementation must use
  focused search/replace and should avoid touching generated MIDI/audio content.
- Crates.io package size is close enough to the limit that `cargo package` must
  stay in the validation gate.
- Existing long-lived worktrees may still reference old paths. That is acceptable
  for this development sandbox, but the final message should call it out.
