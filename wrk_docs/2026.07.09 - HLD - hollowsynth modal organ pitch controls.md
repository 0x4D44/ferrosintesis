# HLD - hollowsynth Modal/Organ pitch controls

**Status:** DESIGN COMPLETE, awaiting Arthur compatibility fork (section 7). Not signed off.
**Author:** Codex GPT-5
**Date:** 2026.07.09
**Req:** `MM-REQ-KILN-00008`
**Crate:** `fable5/hollowsynth` (baseline v0.8.12)

---

## 1. Intent

Make `Modal` and `Organ` voices obey the pitch multiplier the engine already
writes for pitch bend, RPN bend range/fine tune, CC5/CC65 portamento, and
channel-aftertouch vibrato, without changing any channel that never authors
those controls.

## 2. Problem

The engine already composes pitch controls into one multiplier and calls
`Voice::set_pitch` in all the right places:

- note-on bend and portamento origin: `engine.rs::note_on`
- RPN bend range / fine tune recomposition: `engine.rs` RPN handling
- live pitch-bend events: `engine.rs` pitch-bend handling
- per-block aftertouch vibrato and portamento glide: `engine.rs` strip loop

The endpoint is broken: `Voice::set_pitch` defaults to a no-op, and neither
`Modal` nor `Organ` overrides it. That makes roughly these programs ignore
written pitch movement:

| Family | Programs | Current endpoint |
|---|---:|---|
| Piano / EP / harpsichord / clavinet | 0-7 | `Modal` via `piano()` |
| Celesta / glock / music box / vibes / marimba / xylo / tubular bells | 8-15 | `Modal` via `bell()` / `wood_bar()` |
| Organs / accordions / harmonica | 16-23 | `Organ` |
| Timpani | 47 | `Modal` via `timpani()` |
| Crystal family subset | 96, 98, 100, 102 | `Modal` via `bell(CRYSTAL)` |
| Kalimba | 108 | `Modal` via `bell(KALIMBA)` |

Programs 97, 99, 101 and 103 are not Modal today; they route to `SawStack`
pad variants and already have a different pitch-control path.

## 3. Recommended Path

Implement this as a voice-side pitch-retune fix plus one engine-family addition
for Modal aftertouch:

1. Store unbent pitch identity inside `Modal` modes and `Organ` pipes.
2. Override `set_pitch(mult)` for both families.
3. Retune existing oscillators phase-continuously with `Sine::set_freq`.
4. Add Modal programs to `aftertouch_family` so the existing aftertouch vibrato
   writer reaches them.
5. Keep organ CC1 semantics unchanged: CC1 controls the Leslie/tremulant via
   `set_trem`, not pitch vibrato. Organ aftertouch supplies the pitch-vibrato
   path.

This honours the requirement directly. The cost is that existing tracks which
already authored these controls will now sound different. That is correct
musically, but it needs an explicit compatibility waiver (section 7).

## 4. Voice Design

### 4.1 `Modal`

Change `Mode` from:

```rust
struct Mode {
    osc: Sine,
    amp: f32,
    decay: f32,
}
```

to:

```rust
struct Mode {
    osc: Sine,
    base_freq: f32,
    active: bool,
    amp: f32,
    decay: f32,
}
```

Add `sr: f32` and `bend: f32` to `Modal`.

Construction stores the exact unbent frequency already used to create each
`Sine`. `set_pitch(mult)` stores `bend = mult` and retunes every still-usable
mode:

```rust
let f = mode.base_freq * self.bend;
mode.active = f < self.sr * 0.45;
if mode.active {
    mode.osc.set_freq(f, self.sr);
}
```

The render loop skips inactive modes but does not zero their amplitudes. If a
wide upward bend temporarily pushes a high partial beyond the construction guard,
a later bend back down restores that partial with its current decay state. This
prevents a transient bend from permanently deleting the sound.

The noise/transient filters do not retune in this requirement. Piano hammer
noise, bell strike noise, marimba click, timpani thump, and kalimba contact are
struck exciters, not the sustained pitch-bearing body. Chasing them every block
would create zipper risk and is not needed for the audible pitch oracle.

### 4.2 `Organ`

Change the harmonic bank from:

```rust
harms: Vec<(Sine, f32)>
```

to:

```rust
struct Pipe {
    osc: Sine,
    ratio: f32,
    amp: f32,
    active: bool,
}
harms: Vec<Pipe>,
base_f: f32,
bend: f32,
sr: f32,
```

Construction stores `base_f = key_freq(key)` and each stop ratio. `set_pitch`
retunes each active pipe to `base_f * ratio * bend`, with the same temporary
inactive handling for out-of-band upward bends.

Retune the organ chiff bandpass only at note construction. Chiff is a key-on
transient; retuning it during a glide would make old attack noise follow a note
that is already ringing. The click highpass and tremulant LFO stay independent.

## 5. Engine Design

`vibrato_family` stays unchanged for Modal and Organ.

Reason: CC1 already means different things by family. It is pitch vibrato for
guitars, bowed strings, winds, leads, strings and choir. It is Leslie/tremulant
speed for organs. Modal programs are struck or percussive, and CC1 vibrato on
piano or glock would be a broad semantic change beyond this req.

`aftertouch_family` expands from:

```rust
vibrato_family(program) || matches!(program, 16..=23 | 48..=54 | 80..=95)
```

to include the Modal programs listed in section 2:

```rust
vibrato_family(program)
    || matches!(program, 0..=23 | 47 | 48..=54 | 80..=95 | 96 | 98 | 100 | 102 | 108)
```

This lets channel pressure do what the engine already defines for aftertouch:
a modest gain bloom plus pitch vibrato. That is the only engine eligibility
change needed for `MM-REQ-KILN-00008`.

## 6. Oracle Plan

The acceptance oracle is the existing req command:

```powershell
$null | cargo test modal_organ_pitch_controls_move_sustained_notes --manifest-path fable5/hollowsynth/Cargo.toml
```

It should be an engine-level rendered-audio test in `engine.rs`, not a direct
voice unit test, because the requirement covers the whole controller path.

Use:

- `test_song`, `test_opts`, `render`, `left`
- `testutil::peak_locate`
- the existing `pitch_spread` helper style
- the RPN, portamento and aftertouch test templates already in `engine.rs`

Recommended fixtures:

- Modal: program 98 (Crystal), A4. It has a long near-fundamental component and
  avoids piano sample-layer ambiguity.
- Organ: program 19 (church organ), A3 or A4, with CC93/CC94 zeroed so send
  effects do not blur the pitch read.

Assertions:

1. **Sustained pitch bend:** render an already-ringing note, apply a +2-semitone
   bend mid-note, assert pre-window peak near 440 Hz and post-window peak near
   493.88 Hz for both Modal and Organ.
2. **RPN range / fine tune:** adapt `rpn_bend_range_and_fine_tune` so the same
   half-wheel bend and +50-cent fine tune move Modal and Organ, not only Pluck.
3. **Portamento:** adapt `portamento_glides_from_previous_pitch`; A4 origin, A3
   target, CC65 on, CC5 around 109. Assert `voices_spawned == 2`, the second
   note starts near A4, and it settles near A3.
4. **Aftertouch vibrato:** render plain versus channel pressure 127. Assert a
   `peak_locate`-based pitch spread increase, not zero crossings.
5. **No authored control, no change:** render a short Modal phrase and Organ
   phrase without pitch/aftertouch/portamento controls on old and new binaries;
   `cmp` must be byte-identical.

Do not use zero-crossing pitch counters here. Bright Modal spectra can make the
second harmonic win, which is already a repo lesson.

## 7. Compatibility Fork

The usual authored-channel invariant still holds narrowly: a channel that never
authors pitch bend, RPN fine tune, portamento, or aftertouch will render exactly
as before because `bend == 1.0`, no glide is active, and aftertouch is absent.

It does not provide whole-album byte identity for this req. A scan of every MIDI
listed by `render_opus.py::ALBUMS` found existing Modal/Organ tracks that already
author these controls:

| MIDI | Channels | Authored controls |
|---|---|---|
| `fable5/The Burning Meridian/midi/03 - Meridian.mid` | ch10 program 18 organ | 10 pitch-bend events |
| `gpt5-3-spark/midi/01..12 - *.mid` | ch0 program 0 piano, ch6 program 8 celesta | pitch bend, RPN 0, channel aftertouch |

That leaves three real choices:

1. **Recommended: waive byte identity for those 13 tracks.** They already asked
   for pitch motion; the synth ignored it. The implementation makes the authored
   score audible. Gate all other `render_opus.py::ALBUMS` tracks with old/new
   `cmp`, and sanity-check these 13 with finiteness, no clipping, and bounded
   peak-normalised RMS shift.
2. **Add a new never-authored opt-in seam.** For example, make Modal/Organ pitch
   control live only after a new CC is seen. This preserves every old render, but
   it does not satisfy the requirement as written and forces composers to author
   a synth-private switch before standard MIDI pitch controls work.
3. **Narrow the protected corpus.** Treat `gpt5-3-spark` and the one Burning
   Meridian track as eligible for re-render. This is effectively option 1 but
   with less explicit evidence; prefer the waiver.

Arthur needs to choose section 7.1, section 7.2, or section 7.3 before
implementation starts.

## 10. Risks

| Risk | Mitigation |
|---|---|
| Phase reset clicks when retuning | Use `Sine::set_freq`, never reconstruct oscillators. |
| High partials exceed the band guard under upward bends | Temporarily skip inactive modes/pipes; preserve amplitude state for bend-back. |
| Modal aftertouch creates a broader musical change than pitch alone | The change is authored-only, but section 7 requires an explicit waiver for already-authored tracks. |
| Organ CC1 meaning gets muddled | Keep CC1 as tremulant/Leslie only; use aftertouch for organ pitch vibrato. |
| Oracle measures timbre instead of pitch | Use `peak_locate` at fixed expected bands and matched windows; avoid centroid and zero crossings for pitch. |
| Piano LA attack masks Modal sustain | Use program 98 Crystal for the primary Modal oracle; add a smaller no-samples piano check only if needed. |
