# HLD — LA attack layers for guitars, brass, reeds

2026.07.10 · batch item 3 of task/20260709-DEV-HUM-gm-synth-realism-batch ·
design for extending the LA-synthesis sampled-attack layer
(`crates/ferrosintesis/src/sampler.rs`) beyond piano/violin/flute.

## 1. Goal and shape

Same D-50 trick already shipping: a short real PCM transient supplies the onset
(the pick scrape, the lip bite, the reed chiff — what the models fake worst),
then a smoothstep crossfade (`sampler.rs::smooth`, `LaVoice::render`) hands
over to the modeled sustain, which keeps all CC expressiveness (vibrato, growl,
vowels, bends — `LaVoice` already forwards `set_pitch`/`legato_to`/`set_trem`).
No new mechanism is needed: **this HLD adds banks and wrap points, not a new
voice architecture.** Per the synth-change policy (CLAUDE.md §Synth-change
policy), this is a *timbre improvement*: **default-on**, with the render-diff
inventory defining exactly which `listening/*.opus` to refresh in-task.

VSCO 2 CE has no guitar. Candidates, in preference order:

1. **FreePats project guitars** (freepats.zenvoid.org) — *Spanish Classical

modelled in v1** (§5); if guitars land well, VSCO's `Strings` contrabass
pizzicato is a natural v2 candidate for GM 32.

## 3. Zone maps and size budget

Current committed payload: **82 WAVs, 10.5 MB** (`samples/`, embedded via
`include_bytes!`). A mono 16-bit 44.1 kHz zone costs ≈ **86 KB per second**;
the standard 0.62 s trim (`prepare.py::KEEP_S`) is ≈ 55 KB.

| Family | Zones | Dyn layers | RR | Keep | Files | Size |
|---|---|---|---|---|---|---|
| Brass (tpt, mute-tpt, tbn, tuba, horn) | 4–5 per instr, ~M3-spaced across each range | 2 (p/f where VSCO has them, else 1) | 1 | 0.62 s | ~40 | ~2.2 MB |
| Reeds (oboe, clarinet, bassoon) | 4–5 per instr | 2 where available | 1 | 0.62 s | ~25 | ~1.4 MB |
| Guitars (nylon, steel) | 6 per instr (E2–E5, ~m6-spaced) | 2 (mf/f) | 2 | 0.9 s (plucks decay; keep more real body, like the piano rationale) | 48 | ~3.7 MB |

**Budget: ≤ 8 MB added, total payload ≤ 19 MB.** Rationale: the binary is an
offline renderer, not a distributable plugin; 20 MB is well inside reason, and
each family loads lazily via `OnceLock` so unrendered families cost only file
size, not RAM. Round robins only where repetition is idiomatic (guitar
strums/repeated picking); brass/reed phrases rarely machine-gun the identical
note, and the modeled sustain differs per seed anyway.

Zone spacing follows the existing repitch quality rule: nearest zone chosen by
log distance (`sampler.rs::nearest`), and zones spaced so no note repitches
more than ~±3 semitones — comfortably inside the credible range, far from the
0.5–2.05 `step` fallback limits.

## 4. Per-family crossfade design

All via the existing `LaVoice::wrap(model, bank, key, vel, sr, gain, fade)`;
each family adds one `(gain, fade)` constant next to
`voices.rs:3113` `LA_VIOLIN`/`LA_FLUTE`/`LA_PIANO`, level-matched by the
`la_level_continuity` oracle:

| Const | gain (start) | fade (start, end) s | Handover rationale |
|---|---|---|---|
| `LA_GUITAR` | ~0.45 | (0.05, 0.20) | `Pluck` (Karplus-Strong) excitation + `attack_noise` burst live in the first ~10–30 ms (`voices.rs:1618` noise burst, `attack_s` ≤ 12 ms). The sample owns the pick/finger transient and early body knock; by 200 ms the KS string is fully credible and must carry the decay (it responds to bends/damping). |
| `LA_BRASS` | ~0.35 | (0.10, 0.32) | `Brass` env attack is 30–90 ms with chiff + scoop (`BrassSpec::env`, `chiff`, `scoop0` — `voices.rs:3816` `BR_DEFAULTS`). The sample masks the synthetic lip-bite through the scoop region; the model must own everything past ~300 ms (BR2 loudness→brightness law, vibrato, BR10 growl are sustain-time features). |
| `LA_REED` | ~0.45 | (0.06, 0.24) | Same shape as `LA_FLUTE`: `ReedPreset::attack` is 45–80 ms with a chiff (RD-O8b); the sampled tongue/reed onset covers it, handing over before RD7 vibrato delay expires. |

Details, all inherited from the existing mechanism (no code divergence):
- **Repitch out of range** → `LaVoice::wrap` returns the bare model exactly as
  today (`sampler.rs:339`, step outside 0.5–2.05). With §3 zone spacing this
  only triggers at the extreme ends of GM key range — graceful, silent.
- **Pitch coherence during overlap**: the brass/reed models scoop up to pitch
  while the sample is at true pitch — the same overlap the violin already has
  (`Bowed` scoops; the violin layer masks it, verified by `la_pitch_a4`). Per
  lessons_learnt, the per-family pitch oracle measures with Goertzel
  (`testutil::peak_locate`), not zero crossings.
- **Legato/slur**: `LaVoice::legato_to` already retires the transient (~60 ms
  T60) on a slur — correct for brass/reed tongued-vs-slurred (BR-O6) with no
  change.
- **Velocity**: dynamic layer picked bank-side like `violin_bank(vel)`
  (threshold ~80); overall gain already tracks `vel_amp` inside `LaVoice`.
- **Muted trumpet (59)**: its own straight-mute bank; mute identity (BR-O8) is
  attack-critical, so a repitched open-trumpet attack would be wrong.
- **Brass section (61)**: wrap only with the trumpet bank at reduced gain
  (~0.6×`LA_BRASS`); the section's `onset_scatter_s` players keep their
  modeled scattered onsets underneath, so the ensemble does not sound like one
  sampled player.

## 5. GM program coverage in v1

| Layered in v1 | Stay pure-model | Why |
|---|---|---|
| 24 nylon, 25 steel (licence permitting, §2.2) | 26–28 clean/jazz/muted electric | Electric character is pickup+amp, not an acoustic attack; pasting an acoustic transient on the `CLEAN`/`MUTED` presets would *reduce* realism. |
| — | 29–30 overdrive/distortion | Distortion is nonlinear on the whole signal; a clean sampled attack outside the drive path is audibly wrong. |
| — | 31 harmonics | Flageolet attack is the retuned-loop trick (`voices.rs:1004`); a normal pluck sample would mask it. |
| — | 32–39 basses | `Pluck` bass attacks (`attack_noise` thud) are already serviceable; revisit (VSCO contrabass pizz for 32) in v2. |
| 56 trumpet, 57 trombone, 58 tuba, 59 muted trumpet, 60 horn, 61 section (trumpet bank) | 62–63 synth brass | Synth brass owns its resonant sweep (`synth_sweep`, BR-O10); a real lip attack contradicts the instrument's identity. |
| 68 oboe, 69 english horn (oboe bank, repitch), 70 bassoon, 71 clarinet | 64–67 saxes, 72–79 pipes (flute already layered), 109 bagpipe, 111 shanai | No clean CC0 sax in VSCO (§2.1); bagpipe/shanai are drone/folk voices whose reedy model onset is idiomatic, and no matching source exists. |

## 6. Opt-outs and invariants

- `--no-samples` keeps working for free: every wrap sits behind the same
  `if samples` guard in `voices.rs::make` as the three existing families;
  the new banks join `sampler::prewarm`.
- This **does change committed albums' sound** (default-on, §1). The
  authored-channel invariant does not apply — this is the timbre regime;
  byte-identity waivers are explicit and enumerated by the render-diff (§7).
- The `Voice` trait, engine, and mix are untouched; `LaVoice` forwards all
  controls, so brass growl (aftertouch), reed vowels, and CC2 breath (batch
  item 2) keep working through the wrapper.

## 7. Verification and rollout

Per family (each its own commit, in this order — clean-licence families
first): **brass → reeds → guitars**.

1. `prepare.py`: add the family's `SOURCES` entries (+ `KEEP_FAM` for the
   guitar 0.9 s trim), run, paste printed roots into the new `sampler.rs`
   bank fns; commit the WAVs as source (never regenerable-at-build).
2. Oracles (in `sampler.rs::tests` and family test sections):
   - extend `banks_parse` (length, root range, normalisation) to new banks;
   - **pitch integrity**: per family, one `la_pitch_*` at a mid-range note via
     Goertzel `peak_locate` through the crossfade window (±12 Hz as today);
   - **level continuity / no clicks**: add the new programs (24, 25, 56, 57,
     58, 59, 60, 68, 70, 71) to `la_level_continuity`'s program table
     (adjacent-100 ms-RMS ratio < 2.4), plus a `testutil` click scan across
     the fade window;
   - **attack sharpness**: samples-on vs samples-off render of the same note;
     assert first-50 ms high-band energy (or spectral flux) is materially
     higher with the layer — the oracle that proves the feature is audible,
     not just present (lessons_learnt: presence ≠ audibility);
   - regression: `--no-samples` render of a layered program is byte-identical
     to baseline.
3. **Render-diff inventory** (once per family commit, per CLAUDE.md): baseline
   binary from a throwaway `git worktree add <path> HEAD`, render every
   `render_opus.py::ALBUMS` MIDI with both, `cmp`. Expected diffs = albums
   authoring the family's programs = the refresh list; any diff in an album
   *not* using those programs is a bug (canary discipline). Remember
   `ALBUMS` covers demo/listening-only entries too (lessons_learnt
   2026.07.09).
4. **Listening refresh**: after the last family lands, one pass of
   `python render_opus.py --album …` over the union of the three diff lists;
   commit refreshed `.opus` separately from code, per repo convention. Expect
   the fable5 albums (brass/reeds since v0.9) and any guitar-using tracks to
   dominate the list.
5. Gates per commit: `cargo fmt --check`, `clippy --workspace --all-targets
   -- -D warnings`, `$null | cargo test --workspace`. One ferrosintesis
   version bump for the whole batch at integration (journal convention).
