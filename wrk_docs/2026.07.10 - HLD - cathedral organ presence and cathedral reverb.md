# HLD — GM19 cathedral-organ presence, anti-"harpsichord", and deeper cathedral reverb

**Date:** 2026-07-10
**Author:** Claude (lead) — core design consulted from **Claude Fable 5** (on-call specialist), verified-by-understanding and owned by the lead.
**Scope:** `crates/ferrosintesis` — `CathedralOrgan` voice (`voices.rs`), `CathedralReverb` (`reverb.rs`), engine send scaling (`engine.rs`), audio oracles (`testutil.rs`, album `analyze.py`).
**Trigger:** user report — "the new church organ… doesn't have the presence of a real church organ… add more reverb as if in a real cathedral… it sounds a bit harpsichordy, particularly for sustained higher notes."

## 1. Diagnosis (verified against the code)

The `CathedralOrgan` (GM19 default) is a **static additive-wavetable** voice. Each `RankPipe`
(`voices.rs:2491`) bakes a 1024-sample table of exactly-integer, phase-locked harmonics and reads
it at a constant `phase_inc` (`voices.rs:2609`). Once past the ~4–22 ms attack and speech→steady
crossfade, **every pipe is a perfectly periodic, unchanging oscillator.** The only sustain-time
modulation is the channel-global, coherent tremulant + wind ramp (`engine.rs:1449-1488`), applied
in lock-step to all pipes; inter-rank `static_tune` (±1.5 cents) gives only **constant-rate**,
never-changing beats.

A phase-locked, bright, buzzy periodic tone with a fast onset is the textbook "harpsichord/reed"
percept. It is worst on **sustained high notes** for two reasons:
1. Pedal foundation ranks cut out above key ~50 (`pedal = ((50-key)/4).clamp(0,1)`, `voices.rs:2477`),
   leaving only bright upper structure.
2. The `organ_anchor` tables actually **brighten** the treble (Principal h6 `[-24,-18,-15]` at
   key 84 vs 60) — backwards relative to real pipe scaling, where treble flues are *purer*. At key 84
   an 8' Principal carries ~23 harmonics at ≈ −7 dB/oct (near-sawtooth) plus a near-flat reed and a
   4 ms attack with a 2.2 kHz chiff below the octave — a plucked-string recipe.

**Refinement over the first diagnosis:** decorrelate **per pipe**, never per harmonic. A flue pipe is
one air column; its partials are physically locked to one oscillation. Per-harmonic decorrelation
produces electronic chorus-mush and would destroy the wavetable. The missing ingredient is that each
*pipe* rides its own slow, independent wind-pressure fluctuation, so every pairwise beat rate wanders
instead of being parked.

## 2. Design

Three prongs matching the three user asks. All changes are **default-on timbre improvements**
(synth-change policy) — affected `listening/*.opus` are re-rendered in the same task.

### 2a. Per-pipe wind-wander (presence + anti-harpsichord — the crux)

Each `RankPipe` gets its own slow random walk `w(t)` (local wind-pressure deviation) driving pitch
**and** amplitude with positive correlation (pressure up ⇒ slightly sharp + slightly loud — matches
the existing `retune` sign convention). One walk, two scale constants.

- **Primitive:** reuse `dsp::Drift` (`dsp.rs:294`) — `new(seed, depth_cents, hold_ticks)`, retargets
  to `white()*depth` every `hold` ticks, one-pole slew 0.015/tick.
- **Tick rate:** every **64 samples** of the voice's own render loop, keyed off the per-sample `age`
  counter already in `RankPipe::next` (`self.age`). This is **caller-chunk-independent** and, crucially,
  **not** hooked into `retune`/`set_organ_pressure` — voice unit renders (`render_program`) call
  `render()` once on the whole buffer and never retune, so a retune-driven wander would be silently
  absent in exactly the oracle renders. Control rate ≈ 689 Hz, τ ≈ 97 ms (well above the walk band).
- **Depths:** pitch **±2.5 cents × sensitivity** (peak); amplitude **±0.4 dB × sensitivity**, same walk.
  `sensitivity` (Principal 1.0, Reed 1.2, Mixture 0.35, Pedal 0.25) already means "response to wind" —
  reused so pedals stay stately and mixtures (±0.9 cents) still animate against Principals (±2.5).
  Rationale: ±2.5 cents is commensurate with the ±1.5-cent static spread so pairwise detunes **sweep
  through zero** (beats 0–~2.5 Hz, chorus-rank territory, célestes are 4–8) yet stays under the ~5-cent
  slow-drift JND — reads as *motion*, never mistuning.
- **Correlation time:** retarget every ~0.45 s **jittered ±25% per pipe** (stable-seeded), plus a
  staggered initial counter phase — otherwise all 14 pipes lurch on the same tick. Motion band
  0.15–2.5 Hz: below 0.1 Hz reads as tuning drift, above ~4 Hz smears into the 5.5 Hz tremulant.
- **Mechanics (invariant-preserving):** in `retune`, store the computed increment into a new
  `base_phase_inc`. On each wander tick compute `wander_ratio = 2^(w/1200)` and
  `wander_amp = 10^(0.16·w/20)`. `next()` reads `phase_inc = base_phase_inc * wander_ratio` and
  multiplies `wander_amp` into the output alongside `amp_mod`.
  **The wander NEVER touches `self.frequency` or `harmonics`** — so no table regeneration, and the
  `debug_composed_frequencies`/`debug_all_pipe_bounds_hold`/settling tests pass byte-identically.
  Alias margin: worst case reed +3 cents → top partial ≈ 19.9 kHz, 2 kHz under Nyquist; safety bound
  is depth·max-sensitivity ≪ 66 cents (20× margin) — clamp anyway.
- **Seeding:** draw the wander seed + hold-jitter from the existing `stable` Rng in `RankPipe::new`
  **after** `attack_var` (so `tune_cents`/`level`/`attack_var` draws are undisturbed). Stable per
  (rank-id, key), **independent of `event_seed`** → `pipe_identity_ignores_event_seed` and byte-identical
  rebuilds both hold.

### 2b. High-key voicing correction (anti-harpsichord on sustained highs)

Organ-builder strategy: **treble unison ranks get purer; brightness lives in the mixtures** (musical
1.5/2/3/4× slots, not the dense integer series of the unison ranks).

1. **Harmonic cap by key (primary):** `organ_harmonic_cap(family,key)` — Principal/OpenWood 24 at
   key ≤ 48 → **7 at key 96** (clamp 7..24); ChorusReed → **12 at 96**; Mixture uncapped. Applied as
   `harmonics = alias_limit.min(cap)` in `retune`. The per-table energy normaliser
   (`scale = 0.65/energy.sqrt()`) re-deposits removed energy into survivors, so level tracks smoothly.
2. **Anchor correction (secondary):** reverse the treble brightening — Principal h3 `[-11,-9,-14]`,
   h6 `[-24,-18,-26]`; ChorusReed h6 `[-10,-11,-16]`. Mid-organ (key 60) values unchanged, so the
   plenum keeps its brightness; only the 60→84 gradient flips.
3. **Reed taper:** reed gain `0.18 × anchor([1.0,1.0,0.6], key)` → 0.108 at key ≥ 84 (smooth in key).
4. **Attack/chiff:** raise attack floor with key — `clamp(4.0 + 6.0·((key-60)/24).clamp(0,1), …, 22.0)`
   ms → 10 ms floor at key ≥ 84; chiff centre `(2.7·f0).max(2200).min(5000)` (keys ≲74 stay 2.2 kHz).

**Anti-dulling guard:** the existing ≥4 kHz mixture-sheen clause (`hp_rms ≥ 0.04·rms` at key 84,
`voices.rs:6562`) MUST stay green. If flue purification drops it, lift mixture gains 0.05 → up to 0.07
on a smooth key-ramp (72→96); the registration pin test checks ratios/counts/pedal gains, not mixture
gains. Weakening the clause to 0.03 is last resort, with a comment.

### 2c. Cathedral reverb deepening (more room)

| Knob | Now | Target |
|---|---|---|
| low RT60 (<180 Hz) | 6.2 s | **8.2 s** |
| mid RT60 | 6.25 s | **7.0 s** |
| high RT60 | 3.5 s | **4.2 s** |
| high crossover | 3.5 kHz | **2.8 kHz** |
| predelay | 40 ms | **55 ms** |
| earlies | 48–117 ms, 0.40→0.13 | ×1.25 time, ×0.85 gain |
| FDN line lengths | 2087–5813 | ×~1.3, pairwise co-prime (verify at impl) |
| wet | shared `opt.wet` | `opt.wet × CATHEDRAL_WET_SCALE`, **1.30** (named engine const) |

Keep untouched: 10 Hz return highpasses, input/output sign matrices (mono/width), dormant-until-send
bypass, wet==0 exact bypass. **Coupling:** a wandering source feeds the FDN a time-varying spectrum, so
the 7 s tail integrates ~14 s of slightly different organ and the tail itself shimmers — this
interaction is most of "real church-organ presence."

## 3. Oracles (deterministic; box has no ears)

Write each metric first, **calibrate against the pre-change (baseline) binary/code**, cite both numbers
in the test comment, then confirm the change moves it across the threshold.

- **A — steady state alive & aperiodic** (`render_program(19,76,96,12.0,seed)`, steady 1.5–11.5 s).
  Envelope: rectify → LP 10 Hz → decimate ×64 → mean-subtract (a **new decimated helper**; the existing
  `env_autocorr_peak_detrend` runs full-rate and is far too slow at multi-second lags, and its 15 Hz
  detrend would erase the wander band). **A1** shimmer floor `std/mean ≥ 0.02`; **A2 (discriminator)**
  max normalized autocorr over lags 1.5–4.5 s **≤ 0.35** (static organ ≈ ≥0.55, wander ≈ ≤0.15);
  **A3** second event seed matches A1/A2 within 5% (proves stable-seeded, not event-seeded).
- **B — high keys left harpsichord territory** (`render_program(19,{84,96},96,4.0,seed)`, 0.8–3.5 s).
  **B1** integer-buzz `20log10(sqrt(Σ mag(k·f0)²)/mag(f0)) ≤ −16 dB` over k∈{5,7,11,13} with k·f0<0.45·sr
  (these slots are reachable only by unison-rank upper harmonics — the mixture sheen is deliberately
  excluded); **B2** attack rise-to-90% ≥ 8 ms at key 88; **B3** keep the ≥0.04 sheen clause green.
- **C — room got bigger.** Update `cathedral_decay_is_long_but_treble_clears_sooner` (RT ranges from
  *measured* values ±1 s), `cathedral_predelay_and_first_reflection_are_pinned` (~60 ms); add an
  engine-level "organ is wetter" tail-vs-sustain check (≥ −20 dB provisional, ≥3 dB separation from old).
  `cathedral_organ_low_chord_and_pedal_keep_mix_headroom` (return peak < 1.0) stays byte-identical — it
  is the level contract bounding the RT+wet knobs.
- **analyze.py** mirrors on rendered audio (album side): envelope-autocorrelation aperiodicity, buzz
  ratio at the known f0, and a post-note-off RT60 line-fit.

## 5. Tripwires (stop-and-re-escalate)

1. Headroom: if the return-peak test hits ≥1.0 — cut `CATHEDRAL_WET_SCALE` (1.30→1.15) then early gains;
   never weaken the test. If even 1.0 can't hold, the FDN loop gain is off — re-escalate.
2. A2 separation: if the **old** code measures < 0.45 on the A2 signal, switch to envelope-spectrum
   `flatness`; if old/new overlap within ~2×, the metric family is unsound — redesign before re-thresholding.
3. Treble still static (mixture sensitivity 0.35 under-animating once flues purified): try
   `sensitivity.sqrt()` depth law.
4. Budget > 3×: drop to 128-sample tick + linear approximations for the powf's.
5. Density/width regressions from longer lines: adjust line-length *spread* (keep co-prime), don't lower bars.
6. Crossfade smoothness breaks at 72/84: flatten the local key-ramp slope, keep the global tilt.
7. Anyone proposes per-pipe stereo spread for width: **refuse** — organ is pan-64; width comes from the
   reverb return only (repo mono-collapse/Haas-comb lesson).
8. Aliasing margin valid only while depth·max-sensitivity ≪ 66 cents.

## 6. Deferred (documented, not in this task)

- **Sustain air-noise (Fable §1b):** one shared per-*voice* bandpassed noise bed at ≈ −44 dB, the thing
  the reverb tail breathes on. Separable and higher-risk (touches every organ note's render-diff, DC,
  and velocity tests); land the three prongs above first, then A/B this. Parked to keep scope minimal.

## 7. Judgment calls (ranges, not asserted)

Pitch depth 2.0–3.0 cents; mid RT 6.8–7.5 s; wet scale 1.2–1.45 (bounded above by the headroom gate);
sensitivity-linear vs sqrt wander scaling; harmonic-cap-floor 7 vs anchor-only darkening (cap chosen as
the physically-true mechanism, gets ~70% of the effect alone).

## 8. Implementation outcome (what actually shipped — 0.13.3)

Oracle-first calibration changed the plan in one significant way. Measured, not assumed.

**Prong 1 (wander) — shipped as designed.** Per-pipe `Drift` at ±2.5 cents × sensitivity, ±0.4 dB,
0.45 s hold ±25%, 64-sample tick. Oracle A: the steady-state envelope autocorrelation dropped from
**0.44 (static) → 0.25 (wander)** at key 76, seed-stable to ±0.01. Threshold 0.35. (Tripwire 2 note:
the old value 0.44 is < Fable's 0.45 trip line and the separation is ~1.8× rather than a larger factor,
but the two clusters are clean, non-overlapping and seed-stable, so the autocorr metric was kept rather
than switching to envelope-spectrum flatness.) One pinned test legitimately relaxed its *measurement*, not
its bound: `cathedral_organ_mixture_crossfades_are_smooth` now averages a 2.5 s window so the zero-mean
wander doesn't read as a registration jump; the 2.0 dB continuity bound is unchanged.

**Prong 2 (high-key voicing) — DROPPED after measurement refuted its premise.** Fable's design assumed
high notes were integer-buzzy (est. −10.5 dB) and plucky. Measured reality: integer-buzz is already
**−26.9 dB at key 84 and −16.0 dB at key 96**, and the onset already rises over **143 ms** — neither is
harpsichord-like. The genuine high-note artefact is a *weak fundamental* at some keys (upper partials run
**+7 dB over the fundamental at key 72**), but this is inherent to the plenum mixture registration
(mixtures land on and reinforce the upper harmonics) and is *uneven* across keys (72 thin, 84 grounded, 96
thin), so no monotonic key-ramp fixes it. A foundation-boost attempt (lift 8'/16' into the treble) moved
upper/fund by < 1 dB (the RSS normaliser re-absorbs a fundamental boost) *and* regressed Oracle B, so it
was reverted. Conclusion: the "harpsichordy" percept is dominated by static-ness (prong 1 fixes it) and
exposed dry brightness (prong 3's long diffuse tail wraps it); an aggressive re-voicing was neither
warranted by the data nor safe against the sheen/crossfade contracts. Oracle B is retained as a **margined
regression guard** (buzz ≤ −14 dB, onset ≥ 8 ms, sheen ≥ 0.04·rms) so future changes can't make the treble
buzzy or plucky. A deliberate treble re-voicing remains available as future work if a human listen still
finds the highs too bright.

**Prong 3 (reverb) — shipped as designed.** Measured RT60 (deterministic estimator): 31.5 Hz **8.63 s**,
500 Hz **6.82 s**, 8 kHz **4.80 s** (treble clears first). First reflection at **60 ms**. Wet scale 1.30
makes the organ's tail **−20.8 dB** below sustain 1–2 s after note-off vs **−23.1 dB** at scale 1.0 — a
2.2 dB wetter room (Oracle C3, exactly the 20·log₁₀1.30 wet-return gain). The headroom contract
(`..low_chord_and_pedal_keep_mix_headroom`, return peak < 1.0) held byte-for-byte, so tripwire 1 never
fired. Density, width, low-frequency-route and 31 Hz tests all stayed green.

**Gate:** full workspace `cargo test` 289 passed / 0 failed; `fmt --check` and `clippy -D warnings` clean.
No golden-fixture refresh needed (the reference song does not exercise GM19). Render-diff: expected diffs
confined to GM19 albums; all others byte-identical — affected `listening/*.opus` refreshed in the same task.
