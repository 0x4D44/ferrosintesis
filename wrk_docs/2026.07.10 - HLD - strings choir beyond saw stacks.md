# HLD — Strings (GM 48–51) and Choir (52–54) beyond detuned saw stacks

**Status: SIGNED OFF (Arthur 2026.07.10)** — direction approved: options A + C
staged, option B deferred; synth strings 50–51 stay pure model. This is item 4
of the GM synth realism batch.

## 1. Problem

Strings 48–51 and choir 52–54 are the last big orchestral families still voiced
as `SawStack` (`crates/ferrosintesis/src/voices.rs`, ~L2378–2702): 4–5 detuned
polyBLEP saws per note, per-layer vibrato + drift, through either a static
lowpass (strings) or a 3-band formant filter with a schwa→vowel morph (choir).
That design has a hard realism ceiling, for two distinct reasons:

- **Onset.** A saw stack has no bow bite, no breath/consonant onset. The LA
  attack-layer work (piano, violin solo, flute, brass, reeds, nylon guitar)
  showed the onset is where synthesis fakes worst and where a short real
  transient buys the most realism per byte.
- **Sustain spectrum.** A saw's static harmonic recipe through one biquad is
  not a string-section body (no bow-noise floor, no body resonances, no
  per-player spectral independence) and not a vocal tract (three fixed-Q
  bandpasses can't do singer's-formant sheen, breath mix, or inter-vowel
  transitions beyond one morph).

Constraints that shape every option:

- **Authored-channel / frozen-album invariant.** Alt-bank 48–54 must stay the
  frozen v0.9 voices (`altbank.rs` L1007–1008 routes them to its own frozen
  copies — any new default-bank voicing needs the same `samples=false`-style
  guard pattern the brass/reed/guitar phases used). Default-bank changes are
  *audible* changes to committed albums, so they carry a render-diff inventory
  and an explicit listening-refresh waiver list, exactly as in item 3.
- **Binary budget.** Embedded payload is ~16 MB of the approved 19 MB → **~3 MB
  headroom** unless Arthur re-approves a higher cap.
- **Offline renderer.** CPU cost matters for render time, not real-time
  deadlines; a 2–3× per-note cost on two families is tolerable, 10× is not
  (string pads are the densest sustained polyphony in the fable5 albums).

## 2. Candidate architectures

### Option A — LA attack layers on the existing SawStack (strings), per the item-3 pipeline

Wrap `strings()` in `LaVoice::wrap` (sampler.rs L652) with section-sustain
onsets trimmed from the **same pinned VSCO 2 CE revision**
(`prepare.py::VSCO_REV = 4403009…`). VSCO 2 CE has full **string sections**
(violin, viola, cello, contrabass section sustains, plus solo strings already
used for the fiddle), so zone coverage for the 48/49 ensemble range is real and
CC0-clean. Program 50 (synth strings 1) and 51 (synth strings 2) arguably stay
pure model — they are *synth* strings; layering a real section onto them is a
taste call (default: leave 50–51 pure, guard-tested).

- **Realism gained:** the bow-onset "section swell into focus" — the single
  most recognisable section cue. Sustain remains the saw stack, so vibrato,
  CC1 section vibrato, legato slur (`legato_to` retunes base_f) all keep
  working unchanged; `LaVoice` already retires the transient on slurs.
- **Choir:** **VSCO 2 CE has no choir.** Option A alone cannot touch 52–54;
  a CC0 choir source (e.g. FreePats voice sets — licence per-set verification
  mandatory, cf. the steel-guitar GPL surprise) is an open sourcing question.
- **Size:** ~1.5–2.5 MB for 5–6 zones × 2 dynamics × 2 sections (high/low
  split), inside the 3 MB headroom. **CPU:** negligible (linear-interp PCM +
  crossfade).
- **Risk:** low — fourth run of a proven pipeline (prepare.py, banks_parse,
  pitch-integrity/attack-sharpness/level-continuity oracles, alt-bank guard,
  diff inventory). Ceiling: it does nothing for the sustain spectrum; a long
  pad still sounds like filtered saws after ~300 ms.

### Option B — Waveguide/bowed ensemble modelling (physical, no samples)

Replace the strings sustain with an ensemble of per-player **bowed-string
models**: N (3–5) independent players per note, each a `Bowed`-derived voice
(voices.rs L2990 — sawtooth through a modal violin body with scoop and bow
attack, already proven for the fiddle) with per-player detune, vibrato phase,
onset-time scatter (10–40 ms), and a shared section-body filter. Optionally a
true digital-waveguide bow (stick-slip friction + delay line) instead of the
saw-through-body shortcut.

- **Realism gained:** the sustain itself improves — bow-noise floor, body
  resonance, per-player independence that a detuned saw stack only gestures
  at. Expression scales naturally (pressure→brightness, per-player legato).
- **Choir:** does not apply; needs a companion vocal model (see C).
- **Size:** zero bytes. **CPU:** the big cost — 3–5 full `Bowed` instances per
  note (each with modal body biquads) vs 5 cheap saw layers; estimate 4–8× per
  string note. Dense fable5 string beds would multiply render times
  noticeably.
- **Risk:** highest. Bowed-ensemble tuning is a long expedition (the brass
  section work took several iterations *with* a reference); "almost right"
  physical strings sound worse than frank saws. Hard to oracle beyond gross
  spectral/level checks — the failure mode is aesthetic, and this box has no
  ears.

### Option C — Spectral/additive vocal modelling for choir (formant engine v2)

Keep the ensemble-of-sources idea but rebuild the choir's *tract*: per-singer
source (glottal-ish pulse or kept saw) into an upgraded formant stage —
4–5 formants with singer's-formant cluster (~2.8–3.2 kHz), per-singer formant
scatter, vowel *sequences* (not just one onset morph: schwa→ah→oo over a
phrase, driven by the existing CC70 vowel authoring path in `set_vowel`),
breath-noise mix shaped by the same formants, and soft consonant onsets
(the alt-bank `hum_hold` consonant mechanism in altbank.rs L791 is prior art
to generalise, not copy). This is DSP-only: no samples, modest size.

- **Realism gained:** attacks *and* sustain for 52–54; also reusable for the
  synth-voice programs. Fixes the actual ceiling (three static bandpasses).
- **Strings:** does not apply.
- **Size:** zero bytes. **CPU:** ~2× current choir (a few more biquads per
  singer) — cheap.
- **Risk:** medium. Formant synthesis is well-charted (we already run a morph
  and CC70 vowels); the oracles can measure formant centre frequencies,
  singer's-formant energy ratio, and breath fraction directly (Goertzel +
  band-RMS in testutil.rs). Less aesthetic risk than B because the target is
  spectral and measurable.

## 3. Comparison

| | A: LA string attacks | B: bowed ensemble | C: formant engine v2 |
|---|---|---|---|
| Covers | strings 48–49 (50–51 optional) | strings 48–51 | choir 52–54 |
| Fixes | onset only | onset + sustain | onset + sustain |
| Binary | +1.5–2.5 MB | 0 | 0 |
| CPU/note | ~1× | 4–8× | ~2× |
| Source risk | none (pinned VSCO, CC0, sections verified present) | n/a | n/a |
| Oracle-ability | proven suite | weak (aesthetic) | good (spectral targets) |
| Effort | small (4th pipeline run) | large | medium |

## 4. Verification strategy (any option)

1. **Frozen-album guards first:** alt-bank 48–54 arm pinning the old voice
   (extend the existing guard oracles — `sawstack_v1_canary_frozen`,
   altbank CH-O1); `--no-samples` renders byte-identical to baseline for A.
2. **Baseline diff inventory:** scratch worktree at HEAD, render all
   `render_opus.py::ALBUMS` MIDIs with both binaries, sha256 — the diff list
   *must* equal the pre-scanned GM 48–54 default-bank users; that list is the
   listening-refresh waiver set. (Strings/choir are heavily used in fable5 —
   expect a much larger waiver list than item 3's; this is the main blast
   radius and a reason to stage per-family.)
3. **New-voice oracles:** pitch integrity (<45 cents, Goertzel), attack
   audibility (diff-RMS on/off, direction measured not assumed — the reed
   inversion lesson), level continuity vs neighbour programs (2.4× cap), and
   for C: formant-centre and singer's-formant band-RMS targets, breath
   fraction bounds, CC70 vowel-tracking.
4. **Full gate + one version bump** per integrated task, listening refresh of
   the waiver list at the end.

## 5. Recommendation

**A + C, staged; defer B.** A is a small, proven, low-risk step that gives
strings the same onset lift the rest of the orchestra just got, inside the
existing 19 MB budget. C attacks the choir ceiling at its true layer (the
formant stage) with measurable targets and no size cost. B is the only route
to better string *sustain*, but its cost/risk profile (4–8× CPU, weak oracles,
high aesthetic-failure risk) says: only attempt it after A lands and only if
the sustain still bothers the ear — and then prototype one exposed solo-cello
line before committing to sections.
