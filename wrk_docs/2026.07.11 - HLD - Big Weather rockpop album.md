## 1. Goal (one line)

Compose, verify, render, and commit a new 10-track original rock/pop album for
`albums/fable5/` — upbeat and catchy, with melodic bass guitar, stereo-spread
drum features, layered choral "vocals", distorted/overdriven guitars, piano,
clear verse/pre-chorus/chorus/middle-8 song forms, builds & drops, and
orchestral elements (strings, brass, timpani) entering as tracks grow — that
sounds great on ferrosintesis and is proven by structural + audio oracles.

### Non-goals / out of scope

- **No ferrosintesis (Rust) changes.** Pure composition-layer task; the synth
  is consumed as-is (v0.13.x). No version bump needed anywhere.
- No changes to other albums, demos, or the shared render pipeline beyond the
  one required `render_opus.py::ALBUMS` registration line.
- No sung lyrics synthesis — "vocals" are the ChoirV2 choir programs (52–54)
  used as layered wordless voices; lyric text ships as `lyrics/*.txt`
  sidecars and 0x05 lyric events (the repo's established "displayed humming"
  convention, `engine.py:585`).

### Acceptance criteria (the definition of done)

1. `python build.py` (album dir) writes `midi/NN - Title.mid` × 10 +
   `album_manifest.json`; a rebuild is byte-identical (fixed per-track seeds).
2. `python build.py --verify` exits 0: all generic checks (structure,
   programs, pan, ranges, gaps, overlaps, bend hygiene, movement bounds) plus
   the album's shared song-oracles (§6) and each track's own `oracles()` pass.
3. `python analyze.py` exits 0 against **fresh** ferrosintesis renders
   (stale-render guard, §6.2): generic click scan (max step ≤ 22000) and
   mono-compatibility (≤ 2 dB loss) pass for all 10 tracks, plus per-track
   `audio_checks` (chorus lift, drop re-entry, feature audibility) pass with
   measure-then-assert thresholds.
4. Song forms: **every track has a clear chorus**; at least 7 tracks carry
   the full verse / pre-chorus / chorus / middle-8 grammar as named movement
   markers; the remaining tracks declare bespoke feature-forms (§4). Track
   durations 3:00–5:30; album total 36–46 min.
5. The six brief pillars are oracle-enforced per §6: melodic bass, drum
   stereo spread (two drum-feature tracks, three solo passages), layered
   choir (on the declared choir tracks), driven guitars, piano presence,
   orchestral-build gating.
6. `python render_opus.py --album "Big Weather"` produces 10 tagged `.opus`
   under `listening/Claude Fable 5/Big Weather/`, committed. The `ALBUMS`
   registration line lands **in the same commit** as the MIDI bundle
   (unclaimed MIDIs abort every render sweep, `render_opus.py:88-99`).
7. Docs complete: `ALBUM.md`, `README.md`, lyrics sidecars (stems exactly
   matching MIDI stems — mismatches abort the sweep), HLD, journal. All
   committed on the task branch.

**Stereo discipline (mono-collapse lesson + review B6/C1):** all *sustained*
beds (choir, strings, organ, timpani, bass) sit at pan 64 in
`CENTERED_CHANNELS`. Width comes from transient-dominant sources: guitars at
moderate split (~48/~80, not hard-panned — continuous chug off-centre costs
mono energy via the Haas delay; the review pinned a hard-panned continuous
stream near 3 dB mono loss), piano hammers, the kit's built-in pan table, and
CC94 ping-pong echo (verified mono-safe). **Residual risk:** guitar-forward
passages (t05 riffs) may still stress the ≤ 2 dB full-mix mono gate; the
per-track lever is narrowing that track's guitar pans and/or making chug
genuinely gapped (true transients), applied at measure time.

**Drum-stage reality (review A1/C3/B7):** the kit's genuinely wide voices are
crash-1/splash (0.25), high tom 50 (0.32), hats (0.33), floor toms
(0.55/0.62), ride/bell (0.70), china/crash-2 (0.75); **mid toms 47/48 (0.42)
and low tom 41 (0.55) are only mildly off-centre, and kick/snare/claps/
tambourine sit centred.** Solo orchestration must therefore foreground the
wide voices — cymbal conversations, hat/ride trades, high-tom↔floor-tom and
china↔crash antiphony — with mid-tom runs as connective tissue, not the
headline. (Pan values hand-copied from `engine.rs::drum_pan` (~:172-184);
the synth is frozen at v0.13.x for this task — pin the copy with a comment.)

**Low-end discipline:** bass and kick centred; no sustained notes below C2
on any string/bass channel.

## 5. Advanced-MIDI realism budget (per track)

Every track must author at least **6 distinct on-target features** — a
feature only counts when authored on a channel whose **active program honors
it** (review A4/C2). The menu, annotated with honoring scope:

| Feature | Honored by |
|---------|-----------|
| RPN0 bend-range ≠ 2 + wide bends | any pitched voice |
| Pitch-bend gestures (dives, slides, vibrato ramps) | any pitched voice |
| CC1 vibrato | sustained melodic families (leads, winds, bowed, brass, choir; NOT piano/EP/pluck) |
| CC1 Leslie | organs 16–18 only |
| CC68 legato (hammer-on / slur) | guitars, bass, strings, winds, choir |
| CC74 brightness/wah (+CC71 resonance) | any (filter insert) — audible-by-design on gtr/lead |
| CC64 sustain / CC66 sostenuto | piano and ringing voices |
| CC67 una corda | acoustic piano only |
| CC11 expression swells | any |
| CC2 breath (second lane) | brass/reeds/winds (gain lane) |
| Channel aftertouch (growl/swell) | brass, organs, timpani, sustained families |
| CC5/65 portamento | leads, bass, winds |
| CC70 vowel morph | choir 52–54 (and pad 91) only |
| CC94 echo throws | any (mono-safe ping-pong) |
| Scheduled program changes (e.g. 29→30 lift, EP→organ) | — |

Each track additionally names **2 headline features** in its brief (e.g. t05:
Leslie ramp + wah lead) which get **audio-side probes** in its
`audio_checks` (solo-stem or measured-direction full-mix ratio,
measure-then-assert) — presence in MIDI ≠ audibility (house lesson).
Baseline humanisation everywhere: default `jt`/`jv`, ghost snares, velocity-
shaped hats, strum spreads.

**Boundary rule (T16 lesson):** emitters that land notes exactly on a
section boundary use `jt=0`; held section-final chords end inside their
section or get a declared `BOUNDS_WHITELIST` seam entry.

## 6. Oracle plan (write these before the music)

### 6.1 Shared, data-driven checks (new, in the album's `verify.py`)

Beyond the 8 generic Through-Lines checks, five album-level checks driven by
per-module config (a module omitting an attr skips that check — used
deliberately, e.g. non-choir tracks omit `CHOIR_SPEC`):

- `check_song_energy` — **duration-weighted** section energy
  `E = Σ (vel × min(dur_beats, 2.0)) / bars` over named movements (plain
  Σvel is a density proxy that a busy quiet verse could game — review B1;
  duration weighting counts held power chords and pads honestly; the §6.2
  RMS mirror remains ground truth). Module declares `ENERGY_RULES` as
  explicit pairwise inequalities with factors, e.g.
  `("chorus1", ">=", "verse1", 1.2)`, `("middle8", "<=", "chorus2", 0.8)`,
  `("drop", "<=", "chorus2", 0.3)`. **No global "max" rule** (review B2):
  the final-chorus claim is `("final_chorus", ">=", X, 1.0)` for each other
  chorus X explicitly — tolerance lives in the factors, and feature windows
  (drum solos) are simply not compared against choruses.
- `check_late_channels` — `LATE_CHANNELS = {ch: first_beat}`; orchestral
  layers must be silent before their entry beat. (Verified compatible with
  `check_gaps`, which scans the union of channels.)
- `check_bass_melody` — per verse/chorus: ≥ 5 distinct pitches, ≥ 2 non-root
  pitch classes vs the declared `BASS_SPEC` roots, whole-track span ≥ 12
  semitones, **plus ≥ 40 % stepwise motion (≤ 2 semitones) among verse bass
  intervals and ≥ 1 declared bass-hook section where the bass carries a
  countermelody** (review A5/B8 raised the floor). Still partly
  self-certified (composer authors `BASS_SPEC`) — accepted: the oracle
  pins shape, craft does melody (§6.3).
- `check_choir_layers` — on **declared choir tracks** (`CHOIR_SPEC` present;
  ≥ 6 of 10 tracks incl. t07, per review A3 the choir is not forced onto
  every chorus of every track): in each declared choir section ≥ 2 choir
  channels simultaneous, ≥ 3 concurrent distinct pitches held ≥ 2 beats
  (choir chords at section bounds use `jt=0` — T16 lesson), CC70 authored
  somewhere in the track.
- `check_feature_coverage` — counts only **on-target** features per the §5
  honoring table (program active on that channel at that beat must honor the
  CC — review C2/C7); asserts ≥ 6; failure message names the missing/off-
  target ones. **Program-timeline contract (Codex-2):** verify.py derives a
  deterministic per-channel timeline from Score events — the `channel()`
  setup program plus scheduled `program()` changes sorted by beat; a change
  at beat b governs events at beats ≥ b; a feature event straddling a
  program boundary counts only if its onset beat is on-target.

**Drum-feature checks** (t03, t09; `DRUM_SOLO_SPEC` with explicit windows):
within each solo window — non-drum channels silent except a declared
accompaniment whitelist (t09 trading bars, drone under the produced drop);
≥ 6 distinct percussion keys spanning ≥ 5 pan groups; **≥ 12 hits/bar
average with ≥ 2 bars ≥ 20 hits (32nd-note bursts)** (review A1 raised the
floor); **≥ 8 hits per 4 bars on the WIDE key set, named exactly (Codex-4):
{49, 55 (0.25), 50 (0.32), 42, 44, 46 (0.33), 51, 53, 59 (0.70), 52, 57
(0.75)} — the keys with |pan − 0.5| ≥ 0.17. Mid/floor toms (41 @0.55,
43/45 @0.62, 47/48 @0.42) are only 0.05–0.12 off-centre: they count toward
pan-group diversity and L/R alternation, not the wide quota**; ≥ 4
alternations between left-of-centre and right-of-centre groups. Pan values
are a pinned copy of `engine.rs::drum_pan` (comment cites file/lines; synth
frozen in-scope — review B4 accepted as latent).

**Gap discipline:** any intentional full silence > 1.5 beats (t09's drop
core) is declared in `GAP_WHITELIST` — but t09's drop is *produced* (drone +
cymbal swell), so the true-silence core is ≤ 1.5 beats by design (review
B5/A9).

### 6.2 Audio oracles (`analyze.py` + per-track `audio_checks`)

Generic (template): click scan ≤ 22000; mono loss ≤ 2 dB. **Added generic:
stale-render guard** — a WAV older than its `.mid` is reported as
`STALE-RENDER FAIL`, not silently analyzed (review B9; the known
iteration-losing trap).

Per track, measure-then-assert with an explicit **freeze rule (Codex-1)**:
the "first full render" is the assembled-album render of the committed
`.mid` set at phase D (all 10 tracks final), by the release-built
ferrosintesis in this worktree; each frozen constant is written as
`measured value − slack` (slack ≥ 1.5 dB for RMS checks, ≥ 25 % of the
measured margin for ratios) and annotated in the module with the measured
value, date, and synth version. Thresholds measured on earlier per-track
renders are provisional and re-pinned at phase D. Bus-glue compression will
squash MIDI-domain lifts, so expect post-glue numbers (review B10-note):

- **Chorus lift:** final-chorus RMS ≥ verse-1 RMS + N dB (N per track,
  measured; expected 2–4 dB post-glue).
- **Drop + re-entry** (t05, t09): drop-window RMS ≤ chorus RMS − 10 dB
  **and** (t09) re-entry slam — first final-chorus bar RMS ≥ drop window
  + 12 dB (review A9: prove the drop *lands*, not just that it got quiet).
- **Orchestral entry** (04, 10): reframed from the unimplementable stem
  counterfactual (review B3): (a) `check_late_channels` proves structural
  gating; (b) audio asserts an RMS **rise across the entry boundary**
  (2 bars post-entry ≥ 2 bars pre-entry + N dB, N measured); (c) where a
  clean register void exists, a Goertzel probe on an
  orchestra-only pitch — only with a verified-clear measurement band
  (house lesson).
- **Drum-solo spread** (03, 09): **within-window side/mid ratio** —
  |L−R| RMS / (L+R) RMS over the solo window ≥ threshold (measured on the
  first render, then frozen). No verse-baseline comparison (review B7/C3:
  panned guitars confound a cross-section baseline; the mono-fed drum room
  reverb dilutes side energy, so the threshold is measured, not guessed).
- **Headline-feature probes** (§5): one measured-direction assertion per
  headline feature (e.g. t05 Leslie window HF-flux ratio; wah window
  centroid sweep), on solo stems (`ferrosintesis --solo`) where the mix
  confounds direction.

### 6.3 What stays subjective

"Amazing/catchy" can't be fully oracled. The oracles pin the *shape*
(energy contours, layering, spread, entries, feature audibility); melody and
hook quality are the composer's craft + Arthur's ears at the end. Known
residual risk, accepted.
