# HLD — Waveguide bowed-string family (default) + Codex set → alt bank

**Date:** 2026.07.11
**Author:** Claude (Opus 4.8, 1M)
**Status:** DRAFT — for Arthur sign-off before Stage 1 code
**Base:** `origin/main` @ `8118570`

## 1. Problem & history

Arthur reported the **GM43 contrabass** sounded bad — "a low buzzing." Root cause:
the shared subtractive `Bowed` voice (polyBLEP **sawtooth → static body-EQ**),
voiced for a violin, collapses into a **"transformer hum"** two-plus octaves down
(at ~65 Hz the fixed formants + bow noise stop tracking the note and the ear splits
them into separate tones).

Two solutions were built **in parallel** (a multi-agent collision):

- **Codex** (landed on trunk): *program-specific bowed identities* — per-program body
  resonances / brightness / vibrato on the same saw+EQ model (`386290f`), plus a
  bounded contrabass low end (`6c7d70f`), with acceptance tests (`5449617`). This is
  now the **default** bowed voice; the older **v0.9** voicings sit in the **CC0 alt
  bank** (`altbank.rs`).
- **This task** (stale branch `task/20260710-TSK-HUM-contrabass-low-string-voicing`):
  a **bowed-string waveguide** (delay-line string + stick-slip friction) for the
  fused, living sustain, under a **real cello-section arco LA sampled attack**.

**A/B outcome (Fault Lines, Arthur's ear):** the waveguide+LA contrabass **won**
clearly over the trunk (Codex) contrabass.

## 2. Decision

1. **Waveguide+LA becomes the default** bowed voice, extended across the family **in
   ear-gated stages** (§4) — not committed blind.
2. **Codex's per-program bowed set moves to the CC0 alt bank** (the "second
   instrument set").
3. **The v0.9 alt voicings are discarded.**

## 3. Architecture

- **Default bank (CC0 = 0)** — `BowedString` waveguide + LA sampled attack, per program:
  - *Sustain:* bowed-string digital waveguide (two-section delay-line string +
    stick-slip bow friction), register/program-tuned body, per-note bow character
    (force/grit/vibrato from the note seed), bow noise **integrated through the
    friction** (grain, not a layer), human pitch drift.
  - *Attack:* LA sampled bow-bite via `LaVoice::wrap`, per instrument:
    | prog | instrument | LA sample source (measured roots) |
    |---|---|---|
    | 43 | contrabass | cello-section arco, low `celens` zones (C1≈65 Hz…) |
    | 42 | cello | `celens` zones (cello section) |
    | 41 | viola | `celens` / `violin` by register (TBD by measured roots) |
    | 40 | violin | `violin` arco bank |
    | 44 | tremolo | keep bow-tremolo articulation (per current routing) |
    | 45 | pizzicato | already routes to `Pluck` — unchanged |
- **Alt bank (CC0 ≠ 0)** — Codex `BowedPreset` per-program set, **moved** from the
  `voices.rs` default into `altbank.rs`.
- **v0.9 bowed voicings removed** from `altbank.rs`.
- **Samples:** use the post-split crate API (`ferrosintesis_samples_core::get` /
  `_orchestral::get`), **not** `include_bytes!` — the stale branch's `sampler.rs`
  approach is obsolete.

## 4. Staged rollout (ear-gated)

A program becomes **default** only after it passes the gate for its stage.

- **Stage 1 (now):** contrabass **43** → waveguide default (already A/B-won). Codex →
  alt. v0.9 removed. Reconcile onto trunk. Render-diff + refresh GM43 assets.
- **Stage 2:** cello **42** → build waveguide+LA, A/B; default if it wins (**expected**
  — still a low register where fusion helps).
- **Stage 3:** violin **40** / viola **41** → build, A/B **against Codex**; keep
  whichever wins. **May stay Codex-default** — the waveguide's advantage is
  register-dependent and Codex already carries a real LA bow-attack up there.

**Per-stage acceptance gate:** (a) Arthur's ear prefers it; (b) measured — complete
harmonic series / no isolated inharmonic tones, level-matched to the prior default,
no clipping, audible per-note variation; (c) render-diff clean (only the intended
program(s) change audibly); (d) local gate green (`fmt`, `clippy -D warnings`,
`test`, `build --release`).

## 5. Reconcile approach

Start **fresh off current `origin/main`** and **re-apply** the waveguide voice + LA
wiring into the new structure, rather than rebasing the 8-commit stale branch through
Codex's same-family refactor + the samples-crate split. The `BowedString` voice ports
directly (self-contained); only the LA sampler bank is rewritten to the crate API.

## 6. Blast radius & asset refresh

Bowed strings (40–45) are used across **most albums** (GM43 alone: 43 tracks incl. all
of The Spark, Hours After Rain, Atlas, VIGIL). Each stage that changes a default
program's render requires the **render-diff inventory** against the base binary +
refreshing the committed `listening/*.opus` for genuinely-affected albums (VIGIL /
RIVERWAKE / The Long Turning ship MIDI-only → no refresh).

**FP-drift caveat:** adding code shifts LTO codegen and can byte-change *other*
bowed-using tracks sub-perceptually (peaks identical, RMS to ~3 figs). Distinguish
real changes (target program, audible delta) from drift. **Open policy call:** refresh
only audibly-changed assets, or every byte-changed asset? (Recommend: audibly-changed,
to avoid churning the discography for inaudible bit-flips — confirm with Arthur.)

## 7. Tests & versioning

- **Tests:** retarget Codex's solo-strings acceptance guards to describe the **alt**
  voicing (they now guard the alt bank), and add **waveguide default** guards:
  fused harmonic series, pitch lock, level-match, no-clip, per-note variation.
- **Version:** one bump per integrated stage; base is trunk `0.13.x` → **`0.14.0`**
  for the new default bowed family (minor: new voice model). Keep `Cargo.toml` +
  `Cargo.lock` lockstep.

## 8. Risks

- **Blind tuning:** the box has no ears; each new instrument needs an ear-in-the-loop
  A/B (Arthur). Costly for the high strings — hence staging.
- **Register-dependent advantage:** violin/viola may not beat Codex; be willing to
  keep Codex-default there (Stage 3 is a genuine A/B, not a foregone conclusion).
- **Moving trunk / multi-agent:** the bowed family is actively worked by the fleet
  (this collision). This doc + the claimed task branch are the coordination signal;
  re-check `origin/main` before each integrate.
