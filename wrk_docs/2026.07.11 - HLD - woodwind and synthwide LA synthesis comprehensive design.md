## 0. What this is, and the decisions already made

This design started as a woodwind audit (the pipe family, GM 72–79, is the worst-served family in the
synth) and was escalated by Arthur to a synth-wide direction:

> "Switch to using LA synthesis for all the instruments, with unique samples and synthesis for each …
> as close to SoA as we can get."

Two scope decisions are **locked** (Arthur, 2026-07-11):

1. **Staged comprehensive.** Design the whole architecture once (this document); deliver it **worst-family-first**
   in independently-shippable, oracle-gated, opus-refreshed stages, so each stage ships audible value and we
   can stop when returns flatten.
2. **Grow the CC0 sample layer ~3×.** Wire in VCSL + additional FreePats CC0 sets; embedded samples grow from
   ~16.7 MiB to ~45–55 MiB, pinned and provenance-tracked exactly like the current VSCO/FreePats sources.

This document is **design-only**. It commits on a docs branch; it changes no shipped code and bumps no version.
Each *build* stage below is a separate task that needs its own worktree, gate, version bump, and integration go.

## 1. Executive summary

**The architecture the directive asks for already exists in this codebase and is proven — it is just unfinished
in four families.** ferrosintesis is already an LA-synthesis engine: ~10 excitation models (bounded by physics,
not by program count) × per-program **preset tables** × a **sampled attack layer** (`sampler.rs`). The reeds
(GM 64–71), brass (56–63), bowed strings (40–47) and plucks prove the pattern works, each with green per-program
oracles. The job is **promotion, not invention**: bring the starved families up to the standard the reeds set.

Three reframes drive the whole design:

- **"Unique synthesis for each" = ~10 models × per-program preset tables, NOT 128 bespoke voices.** 128 hand-tuned
  voices would be unmaintainable, musically false, and would force fake differences between programs GM itself
  defines as near-identical. The only hard boundary a preset cannot cross is the *excitation mechanism*
  (you cannot preset a reed into a flute), which is exactly why the ~10-model count is right.
- **"Unique samples for each" is not achievable as literally stated, and we should not chase it.** Under the hard
  CC0 constraint, real distinct sampled attacks top out at **~40 instrument identities (~45–65 GM programs)** —
  the recordings for the rest do not exist under a compatible licence. So attack *sourcing* is **tiered**:
  real CC0 sample where one exists → bespoke *synthesized* attack where none does → repitch-share a sibling.
  ~24 synthetic programs (leads/pads/FX 80–103) should get **no** sample — a sampled attack there is *wrong*.
- **True SoA (physical waveguide models) is the wrong target for a fixed-event renderer.** Almost all a
  waveguide's advantage is continuous-breath expressivity a MIDI file structurally cannot feed it; we would pay
  its instability + oracle-burden tax for realism no note-sequenced render can exploit. The achievable ceiling
  is the additive-ladder + shaped-noise + sampled-chiff approach — which *is* the LA architecture already here.
  Arthur's two instincts (comprehensive design; LA everywhere) converge on the same answer.

Delivery is worst-first: **Stage 0** (a synth-wide anti-clone oracle harness, test-only) → **Pipe** → **Pad** →
**Synth FX** → **Ensemble** → **minor collapses**, with a **parallel CC0-sample-sourcing track**. Every timbre
stage is default-on and therefore owes a render-diff inventory + an opus refresh + one version bump.

### 2.1 The pipe family in detail (audit findings, verified against current `main`)

- **8→2 collapse.** `Wind::new(matches!(program, 72|78|79), …)` (`:6537`). `whistle=true`: 72 piccolo, 78 whistle,
  79 ocarina. `whistle=false`: 73 flute, 74 recorder, 75 pan flute, 76 blown bottle, 77 shakuhachi — **five
  programs render byte-identically**. The recorder is literally the concert flute, transposed.
- **Degenerate voice.** `Wind` is 3 sines (`fund`, `h2`, `h3`; `:4227–4229`) with **no 4th+ harmonic generated
  at all** (an absolute cliff, worse than a −55 dB shelf). Harmonic balance is set *only* by the `whistle` bool;
  **zero velocity or register coupling** — the spectrum is invariant across the whole keyboard and dynamic range.
- **Vibrato bug (confirmed 3 ways).** `:4280` builds the LFO's phase increment at full `sr`, but render steps it
  only every `CTRL`=16 samples (`:4295`) → a labelled 5 Hz vibrato renders at **~0.31 Hz** (inert). `Reed`
  (`:5379–5382`, with an explanatory comment) and `Bowed` (`:4521`) already build theirs at `sr/CTRL`; `Wind` is
  the lone holdout. Fix is one substitution. (Engine-level CC1 vibrato is a *separate, working* path — the
  broken one is the always-on internal vibrato that should give every sustained note life without a controller.)
- **One flute sample across all eight.** All 8 pipe programs call `flute_bank()` (`sampler.rs:586`) — a 5-zone
  concert-flute multisample rooted C5–C7 — at `LA_FLUTE = 0.55` gain (`:4865`), the **hottest sample gain in the
  file**. Below C4 no zone applies, so samp/nosamp renders are byte-identical there (the bare 3-sine model).

## 3. Current-state map (baseline)

The full 128-program coverage matrix lives in the investigation transcript; the load-bearing counts:

- **Voice models today (~10, all built):** `Modal` (struck→modal bank), `Pluck` (Karplus-Strong), `Bowed`/
  `BowedString` (bowed friction), `Reed` (pressure-pulse+formants), `Brass` (lip-valve+bore), `Wind` (air-jet
  edge-tone), `Organ` (drawbar additive), `CathedralOrgan` (pipe-rank additive), `SawStack` (subtractive
  ensemble — leads/pads/synth-strings), `ChoirV2` (formant/vowel), plus `SfxNoise` + `drums.rs`.
- **Sampling today:** only **28 of 128** programs touch a sample; only **7 own a unique bank** (24 nylon,
  57 trombone, 58 tuba, 59 muted-tpt, 60 horn, 70 bassoon, 71 clarinet). **100 programs are pure-model.** The
  whole orchestral middle-and-up (leads, pads, FX, ethnic plucks, mallets, saxes, most guitar/bass) is 100% modeled.
- **Preset-table pattern already proven 5×:** `ReedPreset` (13 fields, 10 consts), `BrassSpec` (~27 fields, 8),
  `BowedPreset` (9 fields), `PluckPreset` (~20 presets), `LeadSpec` (6 fields, `LEADS[8]`).

**Interpretation:** the synth is not short of models (the ~10 excitation models are the correct, holdable set).
It is short of *finished preset tables* on four families, and short of *attack samples* almost everywhere the
CC0 pool allows one. Both gaps are addressable without new DSP topology (with one possible exception — §7.1.4).

## 4. Design thesis

### 4.1 Identity = (model, preset) + optional LA attack

Every program's identity is one **excitation model** + one **preset** (data, not code) + an **optional sampled
attack transient** crossfaded into the modeled body (classic Roland-D50 "linear arithmetic"). This is already the
design; we are completing it. Two axes, very different costs:

- **Model preset** — cheap, fully in our control, provenance-free. *This is the load-bearing identity mechanism.*
  Pursue aggressively for every collapsed family.
- **LA attack sample** — expensive, provenance-bound (CC0 only). A *finishing* layer, not the identity carrier.
  The preset table must stand on its own; samples make an already-distinct voice more real.

### 4.2 Why NOT 128 bespoke voices (the pushback, kept in the design on purpose)

1. **Unmaintainable.** 128 hand-tuned DSP voices violate the "hold the architecture in your head" rule. ~10
   models × preset tables is holdable; 128 is not.
2. **Musically false.** Most within-family programs are the *same instrument* with a different bore/body/reed —
   that is a parameter, not new DSP. Bespoke DSP for trumpet-vs-cornet would encode a distinction that isn't there.
3. **Some family-sharing is correct.** GM defines Synth Strings 1/2 (50/51) as near-identical; several
   Sound-Effects (120–127) are foley noise beds. An anti-clone oracle with too-tight a threshold would *force us
   to manufacture fake differences* — worse music. The distinctness oracle therefore ships with an **allowlist**
   (§9.1).

### 4.3 The excitation-boundary rule (where a preset genuinely cannot go)

A preset parameterizes one oscillator's geometry; it cannot change the oscillator. You cannot preset a
Karplus-Strong loop into a sustaining bowed tone, a subtractive saw stack into a formant-shaped reed, or —
critically for §7.1 — a reed into a flute (pressure-controlled valve vs air-jet edge-tone have different overblow
laws and harmonic templates). So the model count is bounded by **distinct excitation physics (~10–11)**, and any
proposal to "fix a family" is first checked against this rule: if the fix is a new *parameterization*, it's a
preset (cheap); if it needs a new *excitation*, it's a new model (rare, justify explicitly).

## 5. Attack-source tiers (what "LA for all instruments" concretely means)

Reframe the directive as: **every pitched program gets a per-instrument-unique attack transient, with the
*source* of that transient tiered by what CC0 allows.**

- **Tier A — real, unique CC0 sample (~40 instrument identities).** Where a licence-clean recording exists.
  Keep the current 15 banks; add from VCSL/FreePats (§6).
- **Tier B — bespoke *synthesized* attack, per-instrument-unique (no CC0 source).** Give each its own synthetic
  transient (a short shaped noise/chiff burst + fast partial swell), *not* a shared generic one. Covers the flue
  exotics (pan flute 75, blown bottle 76, shakuhachi 77, whistle 78), most ethnic (sitar 104, koto 107, shamisen
  106, bagpipe 109, shanai 111, steel drum 114), and the odds (accordion, music box, dulcimer, clavinet, e-pianos).
- **Tier C — repitch/share a sibling's real sample (documented, not accidental).** fiddle 110←violin, English
  horn 69←oboe, piccolo 72←flute, piano variants 1–3←grand, brass section 61←trumpet, string-ens halves←sections.
  Already how the synth works; the design just makes each sharing *explicit and commented* (per the excitation rule
  a shared attack is fine only within one instrument family).
- **Tier D — no sample by design (synth-by-identity, ~24 programs).** Leads 80–87, pads 88–95, synth-FX 96–103,
  synth-strings 50–51, synth-brass 62–63, orchestra-hit 55. Their synthetic attack *is* the correct identity.

Honest split across 128: **~40 real CC0 / ~30 bespoke-synth / ~24 synth-by-identity / rest sibling-shared.**
"128 unique recordings" is impossible on licence grounds; this tiering delivers unique *identity* for all of them.

### 6.4 Provenance discipline & size budget

- **Every FreePats set is licence-checked individually** (the library is mixed-licence — steel-string is GPL).
  Only CC0 sets are ingested. Each new source is added to `prepare.py` with a commit-hash or SHA-256 pin and a
  provenance line in `tools/ferrosintesis-samples/README.md`, matching the existing discipline.
- **Why CC0 specifically, not "free":** committed raw PCM shipped in a binary rules out CC-BY, Sampling-Plus
  (Sonatina), and Philharmonia's "no as-is resale" terms. The clean pool is far smaller than web "free orchestral
  samples" lists suggest — hence the ~40-bank ceiling, not "hundreds."
- **Size:** ~40 real banks at current density ≈ 44 MiB pitched + ~5–10 MiB full CC0 drum kit ≈ **45–55 MiB
  embedded** (~3×). Still inside the offline-renderer + lazy-`OnceLock`-load reasoning of the LA-layer HLD.
  These WAVs are **source, not output** — never `.gitignore`d, never "regenerable" (per repo policy).

## 7. Per-family designs

### 7.1 Pipe 72–79 — the flagship stage (8→8)

Promote `Wind`'s boolean to a `WindPreset` table indexed by `wind(program)`, mirroring `reed()`/`ReedPreset`
exactly (self-contained pure consts + a `match program` lookup dropped into the `72..=79` dispatch arm; the reed
work proves this needs **zero engine changes** — CC1/CC2/CC11/aftertouch/pan/sends already cover 72–79).

#### 7.1.1 `WindPreset` fields (by analogy to `ReedPreset`, plus what cures the audit defects)

| field | purpose / defect cured |
|---|---|
| `harmonics: &[f32]` (or `a2..a6`) | per-partial amplitudes; **adding ≥h4 kills the absolute cliff**; carries per-instrument identity |
| `bore: Bore` (Open / Stopped / Helmholtz) | the one-line switch that does most identity work (§7.1.2) |
| `breath: f32` + `breath_tilt` | sustain breath level *and* spectral tilt (§7.1.3) |
| `breath_vel_exp: f32` | velocity→noise coupling exponent (>1; §8) |
| `vib: (f32,f32,f32)` | (Hz, depth, delay) — **built at `sr/CTRL`, fixing the vibrato bug** |
| `bright_reg`, `bright_vel` | register/velocity brightness law (ends the spectrum's current invariance) |
| `scoop`, `scoop_k` | onset pitch-scoop start + settle |
| `attack`, `chiff_amp` | onset transient (recorder soft, whistle sharp, shakuhachi breathy) |
| `range: (u8,u8)` | register normalization span |
| `amp` | output trim |
| `#[cfg(test)] name` | oracle label |

#### 7.1.2 The bore switch (physics that separates the 8)

- **Open pipe → full harmonic series:** flute 73, piccolo 72 (flute transposed, fewer partials, higher centroid),
  recorder 74 (purest — few harmonics, near-zero breath), shakuhachi 77 (full ladder weighted to h2/h3 + a broad
  **>8 kHz breath shelf** — the "muraiki" tone).
- **Stopped pipe → odd harmonics only:** pan flute 75 (zero the even partials — the hollow/woody signature) +
  loud tracked-noise halo + strong chiff.
- **Helmholtz resonator → single dominant partial, NOT a ladder:** ocarina 79 (one strong sine + weak h2),
  blown bottle 76 (near-overtoneless sine + prominent shaped breath), whistle 78 (near-pure sine + light air).
  *Getting this right is what stops ocarina/bottle from sounding like a dull flute.*

#### 7.1.3 Breath character (the decisive cue for this family — more than the ladder)

Per the flue-synthesis literature, the *turbulent breath* and the *chiff onset* carry identity more than the
harmonic ladder for this family (the opposite of strings/brass). Design rules:

- Breath is **filtered, pitch-tracked, formant/comb-tilted noise gated by the amplitude envelope** (SMS-style
  deterministic+stochastic), **never flat static white noise**.
- Per-instrument level from near-zero (recorder, ocarina) to dominant (pan flute, shakuhachi).
- **Chiff** = a short filtered-noise burst at onset preceding the tonal swell — the ideal home is the LA sample
  layer (Tier A/B attack), not the sustain.
- Numbers (recorder −30 dB … pan flute/shakuhachi −6…0 dB relative to tone) are **engineering gut-feel to be
  tuned by ear + oracle**, not cited measurements — flagged honestly.

#### 7.1.4 The one possible new-model exception

Blown bottle 76 and ocarina 79 are Helmholtz resonators, arguably a different excitation than an edge-tone jet.
**Default: make them extreme `WindPreset` entries first** (single-partial-dominant, high breath ratio). Only split
a small Helmholtz sub-model if a Stage-1 oracle proves a preset *physically cannot* reach the timbre. Do not fork
DSP speculatively (the "on-ramp to nowhere" rule).

#### 7.1.5 Sample policy for pipes (tiers)

- Tier A/C real sample: piccolo 72←flute-up, flute 73 (have), recorder 74 (VCSL Baroque recorder), ocarina 79 (VCSL).
- Tier B bespoke-synth attack: pan flute 75, blown bottle 76, shakuhachi 77, whistle 78 (no CC0 source — confirmed).
- Swap the program-blind `flute_bank()` for a program-aware `pipe_bank(program)` so non-flute pipes stop borrowing
  the transverse-flute attack.

#### 7.1.6 Vibrato fix rides *inside* this stage

Change `voices.rs:4280` `Sine::new(vibr.0, sr, 0.0)` → `Sine::new(vibr.0, sr / CTRL as f32, 0.0)`. It is default-on
and would trigger the exact same 34-track opus refresh on its own, so fixing it standalone would pay that cost
twice — fold it into the pipe stage.

### 7.2 Synth Pad 88–95 (3→8)

Add `PadSpec` ×8 (new-age, warm, polysynth, choir, bowed, metallic, halo, sweep) over the existing `SawStack`.
Fields are knobs `SawStack`/`pad()` already exposes: waveform mix, detune spread, cutoff/Q, envelope (esp. attack),
sweep rate/depth, optional vowel. No new model. Tier D (no sample).

### 7.3 Synth FX 96–103 (3→8, all currently borrowed)

Split the shared crystal bell (96,98,100,102) and base pad (97,99,103,101): give rain 96, crystal 98, atmosphere
100, echoes 102 (and brightness/sci-fi 103) distinct `Modal`/`pad` voicings + light motion/noise layers. These are
semi-tonal textures — modest parameterization, not new models. Tier D.

### 7.4 Ensemble 48–51 (~2→4)

Give the four string-ensemble programs an `EnsembleSpec` (ensemble size, attack time, brightness, synth-vs-acoustic
character) so they stop collapsing via the lone `slow = program==49` boolean (`:3638`). Small but audible. 48/49
keep the `strsec` real sample (Tier C share); 50/51 stay synth-by-identity (Tier D).

### 7.5 Minor collapses & polish (lowest priority, do last / opportunistically)

- **Guitar 26/27, 29/30** and **Bass 33/34** — now have **CC0 samples** (§6.3); differentiate + sample.

- **Bass 36/37**, **Piano 0–3** — differentiate presets (piano already carries the richest sample layer, so this is
  model-side voicing only).
- **Lead 86 (fifths), 87 (bass+lead)** — the two deferred interval features (`:4174`, `:4183`).

## 8. SoA calibration — what "as close as we can get" means for a renderer

**Recommendation: additive/subtractive ladder + shaped-noise bed + sampled-chiff, NOT a physical waveguide.**

- The genuine state of the art for flue instruments is a jet-drive digital waveguide (McIntyre–Schumacher–Woodhouse
  framework; Cook/Smith models): a bore delay line + a short jet delay + a saturating-cubic jet nonlinearity +
  a pressure-scaled turbulence source. Its emergent behaviours (tone growing out of breath, pressure→pitch
  coupling, octave overblow) are genuinely superior — **but they are responses to continuous breath/embouchure
  control a GM file does not provide.** Driving an unstable feedback loop from discrete note events to reproduce a
  spectrum we could specify directly buys ~nothing in realism and adds an instability + pitch-lock oracle burden.
- The **80%-for-20% knee** is squarely the additive+noise+sample approach: harmonic template per instrument
  (the §7.1.2 bore switch), register/velocity brightness tilt ("brighter not louder" when blown harder), a
  stochastic noise bed with **gain ∝ velocity^(2–3)** (aeroacoustic dipole/quadrupole scaling is strongly
  super-linear), a >8 kHz shelf for shakuhachi, a chiff onset, and 5–6 Hz delayed vibrato. This reproduces every
  cue the perceptual literature flags as *defining* and is fully checkable by the existing Goertzel/RMS oracle kit.
- Revisit the waveguide **only if** we later add a continuous breath/expression lane (per-sample CC2/CC11→pressure)
  and *want* emergent overblow as a feature. Absent that lane it's a premature abstraction.

## 9. Oracle plan

Mirror the repo's MIDI-oracle / audio-oracle split at the synth unit-test layer (`voices.rs #[cfg(test)]`, using
`testutil` primitives `centroid`, `band_rms`, `spectral_band_rms`, `hp_rms`, `env_autocorr_peak`, `peak_locate`).

### 9.1 Stage 0 — the anti-clone distinctness MATRIX (new headline suite, test-only)

Built **first**, so it protects every subsequent stage from accidental regression.

- For all 128 programs, render a fixed probe (a few keys spanning registers, fixed velocity, fixed seed, samples
  **off and on**), reduce each to a **feature vector** (spectral centroid, ~6-band energy ratios, attack time,
  harmonic-vs-noise ratio, odd/even harmonic ratio, formant peaks).
- **Intra-family distinctness:** within each GM family, assert no two programs' vectors sit within ε. *This is the
  exact guard that would have caught 72–79 collapsing to 2.* It lifts today's one-family precedents
  (`reed_o6_sax_ordering`, `brass_o9_program_brightness_spread`, `default_bowed_bodies_and_onsets_are_distinct`,
  `sitar_shamisen_koto_have_distinct_pluck_presets`) into one table-driven matrix over all 16 families.
- **Threshold discipline (load-bearing):** ε encodes "distinct enough to *hear*." A curated **allowlist** names the
  pairs GM intends to be near-identical (synth strings 50/51; several SFX 120–127) so the oracle never forces fake
  difference (§4.2).
- **Regression freeze:** a golden per-program feature-vector (or `render_hash`) table freezes the current sound;
  any *unplanned* drift trips it — the render-diff inventory expressed as a fast unit test.

### 9.2 Per-family spectral oracles (physics-specific "what correct looks like")

The matrix only checks mutual *distance*; each collapsed family also needs physics oracles, e.g. for pipes
(mirroring reed_o3/o5): odd-only signature for pan flute; single-partial dominance for ocarina/bottle/whistle;
breath-fraction bands per instrument (via a `breath=0` differential seam); a >8 kHz shelf for shakuhachi; monotonic
brightness ordering piccolo>flute>…>bottle; octave placement for piccolo/whistle. Analogous small sets for pad/FX/
ensemble (attack-time ordering, cutoff ordering, vowel presence where authored).

### 9.3 Integration cross-check (keep, do not replace)

The matrix is a fast in-crate *unit* oracle. It does **not** replace the **render-diff inventory** (baseline binary
in a throwaway `git worktree add <path> HEAD`, render all `render_opus.py::ALBUMS` with both binaries, `cmp`) —
that stays the integration guard that a family change touched only the intended albums (a **report, not a gate**).
And per the repo's `analyze.py` doctrine, mirror the key distinctness claims against the **rendered audio**:
presence of a preset field in the model is not audibility in the mix.

### 9.4 Anti-patterns to bake in (from `lessons_learnt.md`)

- No zero-crossing pitch counters (they lie when a change legitimately brightens a voice — use Goertzel).
- Presence-in-model ≠ audibility — mirror in audio.
- A distinctness ε so tight it manufactures difference is a bug — hence the allowlist.
- Put a **canary in the golden matrix** so a global mix tweak shifting every program *equally* can't silently pass
  the *relative* distinctness check while changing the absolute sound.
- Fix spread/distinctness oracles at matched pitch / worst-case register (the v0.9 lesson: an unfixed-pitch spread
  oracle measures pitch, not timbre).

## 10. Staging & delivery plan

Every timbre stage is **default-on** → each owes: (1) the render-diff inventory, (2) an opus refresh of the albums
that use those programs, (3) exactly **one** version bump, (4) an explicit integration go from Arthur. Deliver each
via `loop-build` if it exceeds one context. Stages are independently shippable; **stop when returns flatten.**

## 12. Risks & open questions

- **R1 — Flute-preset ubiquity.** Because 73 is nearly universal, the pipe stage's audible change is large and
  catalogue-wide. Mitigation: tune the *flute* preset to stay close to the current (accepted) flute sound and put
  the big changes on the currently-wrong programs (recorder/pan-flute/shakuhachi/etc.). The oracle golden freeze
  makes "how much did flute move" measurable before commit.
- **R2 — CC0 licence drift.** FreePats is mixed-licence; every set verified individually at ingest, pinned by hash.
- **R3 — Helmholtz sub-model temptation (§7.1.4).** Resist unless an oracle proves a preset can't reach the timbre.
- **R4 — Bespoke-synth attacks (Tier B) are the least-specified part.** Pan flute / shakuhachi / whistle / bottle
  attacks are hand-tuned synthetic transients with no reference recording — budget ear-time and lean on the
  breath-fraction + chiff oracles to keep them honest.
- **Q1 — Naming/threshold of the distinctness ε.** Needs one calibration pass on the current (green) families to
  set ε so today's *intended* distinctions all pass with margin before it gates new work.
- **Q2 — Drum kit expansion scope.** VCSL has a large CC0 percussion set; a full GM kit upgrade is out of this
  document's family scope (channel-10, not a GM program) — flag as a possible follow-on, not part of stages 1–5.

## 13. Non-goals

- No physical-modeling waveguide engine (§8).
- No 128 bespoke voices (§4.2).
- No new hosted-CI; validation is the local gate + render-diff inventory as today.
- No change to the shared mix/bus architecture (chorus/reverb/compression) — this is a per-voice/per-preset design.
- No backward-compat freeze of old renders — the repo policy is explicitly "timbre improvements are default-on with
  a diff-driven asset refresh," which stages 1–5 honor.
