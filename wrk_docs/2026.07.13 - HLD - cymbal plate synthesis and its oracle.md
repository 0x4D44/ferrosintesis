# HLD — cymbal plate synthesis, and the oracle that can detect a bad cymbal

**Date:** 2026.07.13
**Author:** Claude Opus 4.8 (lead), with a Fable 5 consult on the oracle + architecture
**Scope:** ferrosintesis `MetalPlate` — channel-10 keys 49, 51, 52, 53, 55, 57
**Status:** PROPOSED. Not implemented. Blocked on one decision by Arthur (§6).

---

## 1. The problem

Arthur auditioned the GM kit and reported the cymbals "aren't great". Every one of the
named keys (49 crash, 51 ride, 52 china, 53 ride bell, 55 splash, 57 crash 2) is used in
committed albums, so this is the highest-value defect in the synth.

The cymbals are not naively broken. `MetalPlate` (drums.rs:453-580) is elaborate: 44 sine
partials, detuned beating pairs, a 3-stage "bloom" cascade, a shimmer AM, and — for 49/57
— a real recorded crash mixed in as an overlay. The tests are green. And it still sounds
wrong. **That combination is the actual problem: the voice is sophisticated, the tests
pass, and the sound is bad.** So the first question is not "what is the fix" but "what
measurement would have caught this".

## 2. The root cause (measured, two independent paths)

**One architectural fact explains every cymbal defect:**

> The wash is a `Biquad::highpass` **constructed once** (drums.rs:539) and decayed by a
> **single scalar** (drums.rs:628). A time-invariant filter with one exponential cannot
> produce a time-varying spectrum. Full stop.

And the modal layer, which is where a plate's identity lives, is **17 dB below that noise**
(modal RMS ≈ 0.098 vs wash RMS ≈ 0.698 at vel 100; `tone_amp` 0.028 vs `wash_amp` 1.25).

So the crash *is* a filtered noise burst with an inaudible ring on top. Measured against
the real recorded crash we already own
(`ferrosintesis-samples-orchestral/samples/drum_crash1_ff_rr1.wav`, a genuine 2.21 s strike):

| feature | REAL crash | MODEL today |
|---|---|---|
| t60, 400-630 Hz | 4.5 s | 2.84 s |
| t60, 6.3-10 kHz | 1.7 s | 3.01 s |
| t60, 10-14 kHz | 0.99 s | 2.97 s |
| spectral tilt d/dt, 0.08-0.8 s | **−11.0 dB/s** (darkens) | **+1.8 dB/s** (brightens) |
| centroid c(0.9 s)/c(0.06 s) | 0.41 | 1.01 (flat) |
| tail tonal fraction | 0.50-0.62 | 0.11-0.13 |
| salient peaks 250-1500 Hz in tail | 11-13 | 2-4 |

**The model's t60 is flat at ≈3.0 s across every band from 200 Hz to 14 kHz** — the single
exponential owns the whole spectrum. A real cymbal *darkens* as it decays (damping rises
with frequency); ours does not, so the top end never dies and the result is a persistent
bright hiss. The model crash's centroid (7253 Hz) is within 8% of our own **closed
hi-hat's** (7887 Hz): a 16" crash and a closed hat occupy the same spectral slot.

The **ride** — the most-repeated cymbal in any album — actually gets **brighter** as it
decays (tilt +10.3 dB/s). That is backwards physics.

Two further defects, independent of the wash:
- **The plate is not the same plate twice.** The modal skeleton is re-jittered from the
  per-hit seed (`seed = 0x9E37 ^ voices_spawned·2654435761`, engine.rs:1130 → drums.rs:473-475),
  so every strike is a *different cymbal*. On a repeated ride pattern this is audible as
  wandering. A real cymbal's mode frequencies are fixed; only the excitation changes.
- **The real crash recording is played at gain 0.055** (drums.rs:1158) — i.e. discarded.

## 3. Why the tests didn't catch it — and why the obvious oracles can't

This is the load-bearing part of the design, and it cost the most to learn.

**Sixteen candidate oracle clauses were proposed and then MEASURED. Eleven were worthless**
— they already passed on today's broken code, or were unsatisfiable by a physically correct
fix, or rejected the real recording as a reference. Examples:
- "pitch prominence ≥ 4.0" scored **9.7-12.0 today**. Peak-over-band-mean is a line-vs-floor
  detector; it fires on any set of sines.
- splash "flatness ≤ 0.70× the crash" **already passes at 0.65**.
- a centroid clause **already passes at 1.13** — the centroid of highpassed white is pinned
  near (fc+Nyquist)/2 and is structurally blind to the defect.
- a "two cymbals differ" ratio **passed by accident** because the harness pins seed = 7 and
  both specs walk the same RNG stream.

**The principle that explains all of it:**

> Every cheap scalar — flatness, centroid, kurtosis, peak prominence, band ratios — is a
> **spectral SNAPSHOT**, i.e. a time-marginal. The wash's filter corner is free to sit
> anywhere, so it **dominates every snapshot**. Snapshots cannot see this bug.
>
> **Measure decay RATES and STRUCTURE, never spectral snapshots.**

The empirical proof: the two real crash round-robins (rr1, rr2 — same cymbal, different
strike) **agree to the decimal on decay features** (tilt −11.0 dB/s both; t60 profiles within
±20%) while **disagreeing by ~30% on snapshot features** (flatness 0.52 vs 0.67; first-frame
centroid 5034 vs 6452). Decay rates are a property of the **plate**; snapshots are a property
of the **strike**. An oracle built on snapshots is measuring the wrong noun.

A corollary that also matters: a **differential** oracle against the recording is right, but
only **in the decay domain**. t60(f) *shape* comes from thermoelastic + radiation damping —
material physics — so a Zildjian and a Sabian share it even though their mode frequencies
differ. Snapshot features do not transfer between cymbals; decay rates do.

### Also discovered: every existing drum oracle tests the wrong voice

`render_drum` (drums.rs:2313) hardcodes `Kit::V1`. The shipped kit is **V3**
(engine.rs:1384-1389 forces it). So the "V3 cymbal" oracles — `china_splash_crash_are_distinct`,
`crash_blooms_hat_does_not`, `ride_ping_over_wash` — are all measuring the **dead legacy
`cymbal()` voice the engine never selects.** That is how the cymbals got this wrong with a
green suite. Any new drum oracle written in the house idiom will inherit the same trap.

## 4. The oracle (the deliverable)

Crash key 49, vel 110, dry, voice-level render. Estimators use only what the crate has
(`Biquad::bandpass` + windowed RMS + Goertzel sweeps — no FFT library). **Run the identical
estimator over the embedded rr1/rr2 WAVs inside the test and assert differentially**; the
absolute columns are the sanity net.

| # | feature | estimator | today (FAIL) | real | fixed (PASS) | threshold |
|---|---|---|---|---|---|---|
| **F1a** | high/mid t60 ratio | t60(6.3-10 k) / t60(1-2.5 k), from a 20 ms-hop banded RMS, LSQ slope peak+50 ms → −30 dB | **1.02** | 0.62 | 0.60 | **≤ 0.80** |
| **F1b** | top-octave t60 ratio | t60(10-14 k) / t60(1-2.5 k) | **1.01** | 0.31-0.36 | 0.30 | **≤ 0.55** |
| **F1c** | body outlives wash | t60(400-630) / t60(1.6-2.5 k) | **0.99** | 1.65-1.88 | 1.50 | **≥ 1.25** |
| **F2** | spectral tilt rate | LSQ slope over t ∈ [0.08, 0.8] s of 10·log10(E(6.3-14k)/E(1-2.5k)) per 20 ms frame | **+1.8 dB/s** | −11.0 | −18.5 | **−30 ≤ S ≤ −6** |
| **F3** | centroid decay | banded centroid over 9 bands, 120 ms frames; C(0.84-0.96 s)/C(0-0.12 s) | **1.01** | 0.41-0.48 | 0.27-0.32 | **0.20 ≤ r ≤ 0.75** |
| **F4a** | tail modal salience | Goertzel 250-1500 Hz @5 Hz over the 0.35-1.35 s tail; count maxima ≥10 dB over a ±150 Hz running median | **2-4** | 11-13 | 12-13 | **≥ 7** |
| **F4b** | tail tonal fraction | same sweep 200 Hz-4 kHz; fraction of swept power in bins >7 dB over the median floor | **0.11-0.13** | 0.50-0.62 | 0.66 | **0.30 ≤ f ≤ 0.85** |
| **F5** | skeleton stability | build the voice twice with different seeds; ≥6 of strike-A's top-8 tail peaks (250-1500 Hz) must recur within ±0.5% in strike B | **1/7** | (n/a) | 8/8 | **≥ 6/8** |

**Why these cannot be fooled.** F1/F2/F3 are pure decay-domain: a time-invariant filter with
one exponential yields R ≡ 1.0, S ≡ 0, r ≡ 1.0 *whatever its corner is*. No choice of static
spectrum can pass them. F4 is measured at 250-1500 Hz, **below the wash's reach** (its HP
corner is ≥1.9 kHz on every key, and a 12 dB/oct skirt cannot manufacture 10 dB-prominent
*lines* down there), so it directly enforces "the body is audible" — it kills the 17 dB
deficit. F5 is structural and immune to everything spectral.

**The upper bounds bind.** S ≥ −30, r ≥ 0.20, f ≤ 0.85 exist so a fix cannot over-rotate into
a dull gong. The first prototype of the architecture below failed *exactly there*
(S = −37, r = 0.24) — evidence the guards are load-bearing, not decoration.

Per key: full table for 49/57. Ride (51): relax to S ∈ [−20, −2] (today **+10.3 fails**),
F1a ≤ 0.85, F4a ≥ 5, F5 unchanged. China (52) / splash (55): **no ground truth exists**, so
apply only the structural/sign clauses (F5; F2 upper bound only, "must not brighten"; F1b;
F4a re-baselined to 500-2500 Hz) and mark the calibration provisional.

## 5. The architecture

The wash becomes **multiband with a per-band decay law**, and the plate becomes **fixed**.

**Crucially, this needs NO change to `NoiseBand` and NO change to `MetalPlate::render`.**
Verified in code: `NoiseBand` (drums.rs:40) already carries per-band `amp/decay/filt/onset/
env/atk/floor`, and `render()` (drums.rs:613-629) already draws **one** shared `white` per
sample and loops it over an arbitrary number of bands. So 8 wash bands instead of 3 adds
**zero RNG draws**, preserves determinism bit-for-bit elsewhere, and cannot touch `Drum`
(which shares `NoiseBand` and builds every other percussion voice). The change is confined
to `MetalSpec`, `MetalPlate::new`, and `metal_spec_for`. This dissolves the shared-struct
collision risk that `lessons_learnt.md` warns about.

**The decay law is TWO-SEGMENT, not a single exponent.** Measured on our own recording:

```
t60(f) = t60_ref · (f/500)^−alpha_lo          for f ≤ knee     (alpha_lo ≈ 0.32)
       = t60(knee) · (f/knee)^−alpha_hi        for f > knee     (alpha_hi ≈ 1.5, knee ≈ 7 kHz)
```

A single global alpha ≈ 0.6 (the intuitive first guess) was **prototyped and rejected**: it
gives tilt −37 dB/s and centroid ratio 0.24 — a *differently-wrong* cymbal, too dead on top.
The knee is real.

Three further corrections to the intuitive design:
- **`lo` = 300 Hz, not 220.** The real crash's lowest strong tail mode is ~330 Hz; 220 buys
  gong boom the recording does not have.
- **The darkening must come from the decay law, not a static tilt.** The real attack *is*
  bright (first-frame centroid 5-6.5 kHz). Keep the noise near white-per-Hz with only
  ≈−1.5 dB/oct above 4 kHz, and let t60(f) do the darkening. Tilting the static spectrum
  makes it dark from frame 0, which is wrong.
- **Keep the click band.** It supplies the early >8.5 kHz energy the multiband wash won't.

**Skeleton from the key, excitation from the hit:**
```rust
skel_rng = Rng::new(0x51E1_A7E5 ^ (key as u32).wrapping_mul(2654435761));
```
supplies the index jitter, the ±1.8% frequency jitter and the pair detunes; the per-hit rng
keeps phases and a per-mode excitation jitter widened to ±3 dB. Per-hit variation survives;
the plate stops mutating.

**Energy budget** (validated in the prototype): at vel 110, **35% modal : 65% stochastic** of
total hit energy — i.e. `tone_amp` 0.028 → **0.11**, `wash_amp` 1.25 → **0.9**, then
recalibrate `gain` so total hit RMS matches today's or the kit balance shifts. The evolution
falls out of the law with no extra mechanism: attack ≈ 25-30% modal, the 0.5-1.5 s window
≈ 55-70% modal, the final second ≈ 80%+ modal. Target centroid: ≈4.5-6.5 kHz in the first
120 ms, through ~2 kHz by 0.9 s, ~1.5 kHz by 1.5 s.

Per-key starting constants (52/55 provisional — no ground truth):

| key | modal lo-hi | t60_ref@500 | alpha_lo | knee | modal:wash | life |
|---|---|---|---|---|---|---|
| 49 crash | 300-10 k | 4.3 | 0.32 | 7 k | 35:65 | 5.0 (was 4.2) |
| 57 crash 2 | 280-9.5 k | 4.6 | 0.32 | 7 k | 35:65 | 5.4 |
| 51 ride | 400-9 k | 5.5 | 0.25 | 8 k | 55:45 | 4.5 |
| 52 china | 400-12 k | 1.6 | 0.45 | 5 k | 20:80 | 1.6 |
| 55 splash | 600-12 k | 1.3 | 0.40 | 8 k | 30:70 | 1.0 |

Key 53 (ride bell) is a separate deterministic 6-partial `d(...)` voice whose skeleton is
already fixed; it needs only its noise bands moved onto the law (or a MetalPlate spec with
bell-ratio singles at 70:30 tonal).

CPU: 8 biquads + 44 modes per hit vs today's 3 + 44 — negligible over ~100 tracks.

## 6. The honest call — and the ONE decision for Arthur

**The model is worth fixing, and it is engineering, not research.** The defect is not
"modal synthesis can't do cymbals"; it is one architectural fact (§2), the target features
are now measurable (§4), and a prototype of §5 lands every feature inside the real cymbal's
envelope. Multiband-decay noise + a fixed modal skeleton is the well-trodden spectral-modelling
cymbal recipe. Days of work, bounded by the oracle.

**What the model will never give us: the first 50-150 ms of a hard crash.** That regime is
genuine wave turbulence (the Föppl–von Kármán cascade that the `bloom` only sketches).
Simulating it properly is a research project that ends in a differently-wrong cymbal at
great expense. A crash heard *solo* will keep a faintly synthetic attack no matter how well
§5 is tuned.

**But we already own the answer to that:** two real crash round-robins, currently played at
5.5% gain. Promote them to **attack-leading** for keys 49/57 (gain ~0.35-0.5, crossfaded over
~150-300 ms into the fixed model's multiband tail). This is exactly the LA-synthesis pattern
the repo already ships for melodic instruments — a sampled attack crossfaded into a modelled
body — so it does **not** retire the "from-scratch synth" identity; it applies the house
style to the one voice that needs it. **No new source material is required.**

The boundary, drawn explicitly:
- **Sample-led attack:** keys 49, 57 (assets already owned).
- **Fully modelled:** keys 51, 53, 55, and 52 provisionally. The ride is the *easiest*
  cymbal to model well (coherent ping + shimmer, weakly chaotic) — and the fixed skeleton
  matters most there, because ride patterns repeat.

> **DECISION REQUIRED (Arthur):** approve the sample-led attack for 49/57, or insist on
> pure-model everywhere. Everything else in this HLD is independent of that choice.

## 7. Tripwires (come back and re-escalate if these trip)

1. The real low-band t60s (4.4-4.5 s) are slope-**extrapolations** from a 2.21 s file. Valid as
   rates, but re-derive F1c's threshold with our own Rust estimator before freezing. If it
   reads real R_body below ~1.4, **lower the bar — do not stretch the synth to meet it.**
2. **Estimator identity is load-bearing.** Two correct centroid estimators disagreed 2× on the
   same file (2818 vs 6452 Hz); only the *ratios* agreed. If the Rust oracle does not compute
   real and model through the same code path, F3's absolute thresholds are unsafe. The
   differential form is the guard.
3. The "today" numbers came through the full engine (dry, peak-normalised). If the tests drive
   the voice via the `render_drum` harness instead, **re-baseline** (and remember that harness
   hardcodes Kit::V1 — see §3).
4. Raising `tone_amp` 4× exposes the detuned pairs' 5-20 Hz beats as audible AM. No oracle
   above guards flutter depth. If Arthur reports "warble", add an envelope-crest guard **then**,
   not preemptively.
5. `life` 4.2 → 5.0 s truncates later; if a truncation click appears, point the existing
   click-detection oracles at the new tail.
6. The sample→model splice (~2 s) for 49/57 is a new audible seam. Add a spectral-continuity
   check across the boundary when building it.
7. **China/splash thresholds are structure-only and uncalibrated.** If they pass the oracle and
   still fail Arthur's ear, that is the signal to **acquire references**, not to tune further.
8. If the wash band count/edges change, re-verify the wash contributes no 10 dB-prominent lines
   below 1.5 kHz, or F4a's premise breaks.
