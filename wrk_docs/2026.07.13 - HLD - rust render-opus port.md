# 2026.07.13 — HLD — Rust port of `render_opus.py`

**Status: DRAFT (awaiting sign-off)**

## Goal (one line)
Replace the Python render orchestrator (`render_opus.py`) with a Rust binary in the
`midi-music` workspace that discovers album MIDIs, renders each to a
loudness-normalized WAV, and encodes it to tagged Ogg Opus — so producing the `.opus`
listening copies needs **no Python**.

## Scope
**In:** a new binary crate `crates/render-catalog`; retire `render_opus.py` **and**
`build.py`; update the current-guidance docs (root `CLAUDE.md`, root `README.md`,
`listening/README.md`, `.gitignore` comment) to the new command. Preserve the CLI
surface: default = render all, `--album <title>`, `--only-list <file>`, `--jobs <n>`.

**Out:** the per-album *composition* engines (`albums/**/build.py`, `verify.py`,
`analyze.py`) — separate stdlib Python that stays. No change to `ferrosintesis` the
synth, to `ropusenc`, or to the committed MIDI/audio. No new album metadata. No
history rewrite of journals/HLDs that mention the old scripts.

## Acceptance criteria
- **AC1 — full render.** `cargo run --release -p render-catalog` renders every album's
  MIDIs to `listening/<artist>/<album>/<stem>.opus`, identical tree to today. Exit 0
  iff every track succeeds; per-track failures print `[FAIL] …` and force a non-zero
  exit (matching the Python).
- **AC2 — selection + errors.** `--album "<title>"` renders only that album (Arthur's
  explicit ask); `--only-list <file>` and `--jobs <n>` match the Python semantics.
  Fatal pre-render errors (unknown album, unmatched `--only-list` path, unclaimed MIDI
  under `albums/`, an `ALBUMS` key with zero MIDIs, orphan or invalid lyrics sidecar)
  print a clear message and **exit 1**; a malformed CLI flag / `--jobs` value prints
  usage and **exits 2** (argparse parity); `-h/--help` prints usage and exits 0.
- **AC3 — parity with the Python pipeline.** The port drives the synth with the exact
  parameters render_opus.py causes `ferrosintesis-cli` to use (sr 44100, wet 0.32, tail
  6.0, default echo `clamp(0.75·60/bpm, 0.20, 0.62)`, samples on, all channels, −18
  LUFS, **−4.5 dBTP**) and emits the exact same `ropusenc` argv + Vorbis comments
  (TITLE/ARTIST/ALBUM/ALBUMARTIST/COMPOSER/GENRE/DATE/TRACKNUMBER/TRACKTOTAL/
  ENCODER_SETTINGS/R128_TRACK_GAIN/R128_ALBUM_GAIN + optional multiline LYRICS).
  Verified by the oracle below.
- **AC4 — no Python in the opus path.** `render_opus.py` and `build.py` deleted; docs
  point at the cargo command.
- **AC5 — clean + zero-dep.** Workspace stays free of third-party crates (hand-rolled
  args, std-only threading). `cargo fmt --check`, `cargo clippy --workspace
  --all-targets -D warnings`, `cargo test --workspace` all green.

## Approach

### New crate `crates/render-catalog`
```
crates/render-catalog/
  Cargo.toml          # [[bin]] render-catalog; deps: ferrosintesis (path) only
  src/main.rs         # everything: pure fns (catalog table, discovery, filename
                      #   parse, ropusenc argv builder, lyrics validation, repo-root
                      #   finder) up top; thin main(); `#[cfg(test)] mod tests` below
```
Single file, mirroring `ferrosintesis-cli` (no `lib.rs` — a binary crate's inline
`#[cfg(test)] mod tests` can already reach every private item, so a lib split is pure
ceremony here). Added to the root `Cargo.toml` `members`.

### Render one track (in-process synth — D1)
```
let song = offline::load(&midi)?;                 // String error → this track fails
let delay_s = (0.75 * 60.0 / song.initial_bpm() as f32).clamp(0.20, 0.62);
let opt = Options { sr: 44100.0, wet: 0.32, tail: 6.0, delay_s,
                    samples: true, solo: 0xFFFF, verbose: false };
let (buf, _stats) = offline::render(&song, &opt);
let pcm = offline::normalize_loudness(&buf, 44100.0, -18.0, -4.5); // Vec<i16>
offline::write_wav(&temp_wav.path, 44100, &pcm)?;
```
These are `ferrosintesis-cli`'s exact calls under render_opus.py's flags, so the WAV
matches today's. The per-track body runs inside `std::panic::catch_unwind` so a synth
panic fails only that track (the isolation the Python got free from subprocesses). The
captured types (`Song`, `Options`, `(Vec<f32>,Stats)`) are `UnwindSafe`, so no
`AssertUnwindSafe` is needed provided the closure captures no `&mut` local.

### Encode (subprocess — D2)
`create_dir_all` the `listening/<artist>/<album>/` output parent (Python does
`opus.parent.mkdir(parents=True, exist_ok=True)` — the tree is absent on a clean
checkout), then `ropusenc --bitrate 96000 --music --vbr --comp 10 --title … --artist …
--album … --genre … --date 2026 --tracknumber … --comment KEY=VALUE … -o out.opus
temp.wav`, built by the pure `ropusenc_argv()`. A track is a **failure** if `ropusenc`
exits non-zero **or** the `.opus` file is absent afterward (both checks, like Python);
likewise the in-process `write_wav` error fails just that track. A **pre-flight**
`ropusenc --version` probe at startup (like render_opus.py's synth pre-check) gives a
clear exit-1 error if it is missing, instead of a mid-run failure.

### Parallelism (std-only — D4)
`std::thread::scope` with a shared `AtomicUsize` cursor over the selected-MIDI slice;
each of `jobs` workers `fetch_add`-grabs the next index and returns its own
`Vec<Outcome>` through the scoped `JoinHandle` — no `Arc`, no `Mutex` (so no lock
poisoning, no cross-worker stderr interleave on the results path). `jobs` defaults to 6;
validated `>= 1`. **No custom panic hook:** the per-track `catch_unwind` already yields
the tidy `[FAIL] <track>` line; a blanket `set_hook` that swallowed the default message
would also hide a genuine *orchestrator* bug, so it is not worth the trade (a panicking
track may additionally emit the default one-line panic message to stderr — cosmetic).

### CLI parsing (hand-rolled — D4)
Accept both `--key value` and `--key=value` (argparse parity). Filters apply in order —
`--album` narrows first, then `--only-list` intersects the narrowed set (so
`--album X --only-list <path-in-Y>` reports the path as unmatched, exactly as Python).
`--jobs` validated `>= 1`; unknown flag / bad `--jobs` → usage on stderr, **exit 2**;
`-h/--help` → usage, exit 0.

### Tags / lyrics (ported 1:1)
`R128_*_GAIN = round(256·(−23 − (−18))) = −1280` (Q7.8), track == album gain.
**TRACKTOTAL is the count of *selected* tracks in the album**, computed over the render
subset — so a partial `--album`/`--only-list` run tags the partial count, faithfully
reproducing render_opus.py (`total_by_album` is summed over `midis`, the filtered set,
not the album's full size). Lyrics from `<album>/lyrics/<stem>.txt`: UTF-8 (Rust
`read_to_string` enforces), **CRLF *and lone-CR* → LF** (both of render_opus.py's
`.replace`s), strip trailing newlines, reject blank / NUL, read only for *selected*
tracks. Orphan check over the **full** MIDI set (a partial run must not mistake a
not-selected track's sidecar for an orphan) — as the Python.

### Discovery (ported 1:1)
Iterate the `ALBUMS` table order; each key's `<key>/midi/*.mid` sorted; **error if a key
has zero MIDIs**. The "unclaimed MIDI" guard scans **`albums/**` only** (not `demos/`,
exactly as the Python) and errors on any `.mid` no `ALBUMS` key owns. Path matching
mirrors Python's `PurePath.as_posix()`: normalize the *repo-relative MIDI path* to
forward slashes and compare it against the `--only-list` file lines **verbatim** (do not
rewrite the user's lines). On Windows a raw `Path` yields `\`, which without this
normalization would make every `--only-list` entry miss.

### Repo-root discovery (D6)
Walk up from `current_dir()` to the first dir containing both `albums/` and the
workspace `Cargo.toml`; clear error if none. (Chosen over the one-liner
`env!("CARGO_MANIFEST_DIR")` because that bakes the *build-time* worktree path into the
binary — in a multi-worktree fleet a stale binary would silently render into a different
worktree's tree. The walk-up anchors on where you actually are and forgives running
from a subdir.)

### Temp WAV (D5)
`std::env::temp_dir()/render-catalog-<pid>-<idx>.wav`, unique per track, wrapped in a
tiny **RAII drop-guard** whose `Drop` unlinks it — so cleanup runs on the happy path,
the encode-failure path, and a caught panic alike (std has no auto-temp; this is the
zero-dep stand-in for Python's `TemporaryDirectory`). Avoids adding a stream-to-`Writer`
API to `ferrosintesis`.

## Verification (AC3 oracle)
The two reviews established that (a) `ropusenc`'s Ogg serial is the fixed constant
`0xC0DE_C0DE` (`ropus .../container/ogg.rs`), so `ropusenc` is byte-reproducible, but
(b) the workspace uses fat LTO (`lto = true`) and the repo's own `lessons_learnt.md`
records LTO reordering float ops — so a byte-compare of WAVs produced by two
*separately-linked* binaries (the `ferrosintesis` CLI vs the `render-catalog` binary)
is **not guaranteed** and cannot be the standing regression guard. Therefore:

1. **Parameter parity (durable, same-binary).** Production reads the synth parameters
   from ONE source — a `synth_options(&Song) -> Options` builder plus named constants
   `TARGET_LUFS = -18.0`, `TP_CEILING = -4.5` — and the unit test asserts on *that same*
   source (the returned `Options` and the constants), so the test observes exactly what
   production uses (not a re-typed copy). Note the echo delay is computed in **f32**
   (`(0.75*60.0/bpm as f32).clamp(0.20,0.62)`) precisely because that is what
   `ferrosintesis-cli:115` does — an f64 calc would *diverge*. Audio then follows
   deterministically from identical inputs through identical (same-binary) `offline::`
   code; any residual difference is pure codegen, not behavior.
2. **argv/tag parity (durable golden).** `ropusenc_argv()` for a lyrics-bearing and a
   plain fixture track equals a golden captured from the **actual render_opus.py run
   before deletion** (a stub `ropusenc` on PATH that echoes its argv to a file). The
   two volatile slots — the `-o <opus>` output path and the `<wav>` input path — are
   normalized/ignored; every other argument is compared byte-for-byte **and in order**.
3. **Discovery invariants (durable).** Every catalog MIDI maps to exactly one album; no
   unclaimed MIDI under `albums/`; the work-cursor partitions `0..N` exactly once across
   `J` workers (incl. `J > N`); `--only-list` matches an as-posix repo-relative path on
   Windows; `--album`/`--only-list`/intersection filtering and TRACKTOTAL-over-subset.
4. **Empirical bring-up (informational, one-time).** Render one track through the old
   Python path and the new binary and `cmp` the `.opus`/WAV. Byte-identical is the happy
   outcome; otherwise confirmed benign via aggregate features with **pre-declared
   absolute tolerances** (integrated-LUFS within ±0.1 LU, true-peak within ±0.1 dBTP;
   linear RMS within a small relative epsilon — dB values are already logarithmic, so a
   "relative" epsilon on them is meaningless) and attributed to cross-binary codegen —
   recorded in the journal, done before `render_opus.py` is deleted.

Parser table-tests (part of the durable suite): `--key value` vs `--key=value`, unknown
flag, missing value, `--jobs 0`/negative, repeated flags, `-h/--help`, and the exact
exit codes (2 for usage, 1 for render failure, 0 for success).

## Decision log
- **D1 in-process synth** (Arthur): one self-contained binary; no "is the CLI built?"
  check; `catch_unwind` per track restores the Python's per-track panic isolation.
- **D2 keep `ropusenc` subprocess:** linking `ropus-tools-core` would pull
  symphonia/rubato/ogg/rodio/crossterm into a zero-dep repo — wrong trade to remove one
  subprocess; the ask was to remove *Python*, not `ropusenc`.
- **D3 retire `build.py`** (Arthur): `cargo run --release -p render-catalog` builds +
  renders in one step.
- **D4 std-only, single-file:** hand-rolled args + `thread::scope`/`AtomicUsize` keep
  the workspace third-party-free and match `ferrosintesis-cli`; no `lib.rs`.
- **D5 RAII temp WAV**, **D6 cwd walk-up root** (not `CARGO_MANIFEST_DIR`, for fleet
  safety), **D7 parameter-equality + captured-golden oracle** (not cross-binary byte
  cmp) — all as argued above.
- **D8 pin `panic = "unwind"`** in the root `[profile.release]` (a no-op vs today's
  default, but D1's `catch_unwind` isolation silently dies if anyone later sets
  `panic = "abort"`; the explicit line + comment documents the dependency).
- **D9 no custom panic hook:** `catch_unwind` alone yields the `[FAIL]` line; a blanket
  `set_hook` would also hide a real orchestrator panic (Codex), and dropping it is
  simpler — the cosmetic default panic message on a failed track is acceptable.

## Open points for sign-off
- **Crate/binary name** `render-catalog` vs `render-opus` (the latter keeps grep
  continuity with `render_opus.py` and the `.opus` output). Bikeshed — Arthur's call.
- **Versioning:** the synth is unchanged, so **no `ferrosintesis` version bump**; the
  new crate starts at `0.1.0`. The `panic = "unwind"` pin is a documentary no-op, not a
  synth behavior change. Confirm this reading of the one-bump policy.

## Risks
- **R1 memory:** in-process peak per track ≈ ~2–2.5× one song f32 buffer
  (`normalize_loudness` does a `to_vec` copy while the render buffer is still live, then
  the i16 PCM) ≈ ~750 MB for a 15-min song, so ~4–5 GB at `jobs=6`; plus up to `jobs`
  `ropusenc` processes each buffering the whole WAV. Fine on a dev box (Python already
  ran 6 concurrent subprocess renders); lower `--jobs` if it bites.
- **R2 cross-binary codegen** (LTO float reorder): handled by the parameter-equality
  oracle (D7), not a byte cmp.
- **R3 isolation is panic-only:** `catch_unwind` contains panics (the realistic mode —
  the lib has no `process::exit`/`abort` and `#![forbid(unsafe_code)]`), but **not**
  stack-overflow/OOM-abort, which would still kill the whole run. Accepted limitation of
  the in-process choice (D1); the subprocess Python contained those too.
- **R4 `ropusenc` absent:** pre-flight probe → clear exit-1, better than the Python's
  mid-run traceback.

## Adversarial review — survivors folded
Three independent reviewers (parity, simplicity, testability) + a cross-refutation pass.
Folded survivors: false serial-nondeterminism premise corrected → oracle reworked (D7);
lone-CR lyrics fold; demos-scope + zero-MIDI discovery guards; Windows path-sep
normalization; single-file crate (no lib.rs); `thread::scope` (no Arc/Mutex); RAII temp
guard; exit-2 usage / `--help`; `ropusenc` pre-flight; `--jobs >= 1`; work-cursor test;
`panic = "unwind"` pin; residual isolation gap documented; R1 memory corrected.
Refuted (not applied): `CARGO_MANIFEST_DIR` root (fleet stale-path hazard); end-to-end
`.opus` byte-compare as the durable guard (cross-binary LTO). Affirmed: D1/D2 sound;
zero-dep honored; `catch_unwind` types are `UnwindSafe`.
