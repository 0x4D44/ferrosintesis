# PLN — Purge committed `.opus` from git history

**Status:** ready to run. This is the **destructive** half of the "stop committing
rendered audio" change. The safe half (git-ignore `*.opus`, un-track the 81 files,
add `build.py`, fix the docs) is already committed on the task branch. This runbook
rewrites history to delete the opus blobs from *every* commit and force-pushes the
rewritten trunk to `origin`.

**Run it manually, when the repo is quiescent** (see Preconditions). It is a
force-push with fleet-wide blast radius — do not automate it, and do not run it while
other agents have live worktrees on this repo.

## Why

`.git` is **5.9 GB**; the live tree is 569 MB. `.opus` accounts for **3,135 MiB across
650 blobs** (~93 % of tracked bytes) — the current 81 tracks re-rendered and re-committed
~8× over. Un-tracking them going forward does not shrink `.git`; the blobs stay in
history and every clone still downloads them. Only a history rewrite removes them from
future clones. Estimated result: `.git` drops from **5.9 GB to ~100–150 MB**.

Nothing else is worth stripping: the 202 sample-bank `.wav` (16 MiB) are synth *source*,
and `.mid` (8 MiB, every album) is the committed source of truth. The filter targets
`*.opus` only.

## Preconditions (this is what "quiescent" means)

1. **No live worktrees.** `git -C D:/language/midi-music worktree list` shows only the
   main clone. The rewrite orphans any branch built on old SHAs, so all task branches
   must be integrated or intentionally abandoned first, and their worktrees reaped
   (see the `worktree-hygiene` skill). At the time this runbook was written there were
   3 active task branches + 3 remote feature branches — all must be resolved first.
2. **Origin trunk is where you want it.** `git -C D:/language/midi-music fetch origin`,
   confirm `origin/main` is the intended pre-rewrite tip. (At authoring time:
   `6de11af`.)
3. **Other machines/agents idle.** Every other clone must re-sync afterward (step 6);
   tell the fleet a rewrite is coming so no one pushes into the gap.

## Procedure

All commands assume the harness Git Bash. `<TMP>` is any scratch dir **outside** the
`D:\language` scan-root, e.g. `D:/tmp`.

```bash
ORIGIN=https://github.com/0x4D44/ferrosintesis.git
MIRROR=D:/tmp/ferrosintesis-purge.git

# 1. Fresh MIRROR clone from ORIGIN (filter-repo requires a clean clone; this is also
#    your backup — keep it until the fleet has re-synced and you're happy).
git clone --mirror "$ORIGIN" "$MIRROR"

# 2. Locate git-filter-repo (installed as a Python module here, not a git subcommand).
FR="$(python -c 'import git_filter_repo,sys; sys.stdout.write(git_filter_repo.__file__)')"
python "$FR" --version    # sanity check

# 3. (Optional) Dry-run report of the biggest paths — changes nothing.
python "$FR" --analyze --source "$MIRROR"
#   report lands in <cwd>/filter-repo/analysis or $MIRROR/filter-repo/ — read blob-shas-and-paths.txt

# 4. Rewrite: strip every *.opus from ALL history and ALL refs in the mirror.
cd "$MIRROR"
python "$FR" --path-glob '*.opus' --invert-paths --force

# 5. VERIFY before pushing anything.
git rev-list --objects --all | grep -c '\.opus$'   # expect 0
du -sh "$MIRROR"                                    # expect ~100-150 MB
git log --oneline -5 main                           # history intact, opus gone
#   Also spot-check a MIDI still exists:
git cat-file -e "main:albums/fable5/Sub Rosa/midi/01 - Sub Rosa.mid" && echo "MIDI OK"
```

**Only once step 5 is clean:**

```bash
# 6. Force-push the rewritten history to origin. This rewrites main AND every server
#    branch present in the mirror (main + the remote feature branches), and rewinds
#    their SHAs. --mirror also deletes any origin ref absent from the mirror (none here).
git push --force --mirror "$ORIGIN"
```

## After the push — re-sync every clone

The old SHAs are gone from `origin`. Any existing clone/worktree still points at them
and must be reset. Force-push does not update them for you.

**The main clone** `D:/language/midi-music` (its local `main` is now divergent from the
rewritten `origin/main`; the deltic reference-transaction guard blocks a non-ff move, so
this needs the Arthur-only recovery escape):

```bash
cd D:/language/midi-music
git fetch origin
DELTIC_ALLOW_TRUNK=1 git reset --hard origin/main   # recovery escape — Arthur only
git reflog expire --expire=now --all
git gc --prune=now --aggressive                     # reclaims the 5.9 GB locally
du -sh .git                                          # confirm the shrink
```

If that feels fiddly, the clean alternative is to **delete and re-clone** the main clone
(only safe once its worktrees are all removed): `git clone "$ORIGIN" midi-music`.

**Every other machine's clone:** `git fetch origin && git reset --hard origin/main`
(or re-clone). Any un-integrated task branch elsewhere must be rebased onto the new
main: `git rebase --onto origin/main <old-main-sha> <task-branch>`.

## Caveats

- **GitHub retains unreachable objects server-side** for a while, and any open
  PR `refs/pull/*` can keep old opus blobs reachable on the server even after the
  force-push. Clone *size* for fresh `git clone` drops immediately (no ref points at the
  old history); full server-side reclamation may lag until GitHub gc's, or needs a note
  to GitHub support. Close/rebase any open PRs first.
- **This is irreversible on `origin`** once pushed. The `$MIRROR` clone (pre-step-4 you
  could re-clone) and every un-reset existing clone still hold the old history until you
  delete/reset them — that is your rollback window. Keep `$MIRROR` until the fleet has
  re-synced.
- **Do not `git rebase --skip`** or otherwise drop commits during any branch rebase —
  the rewrite must preserve every non-opus commit.
