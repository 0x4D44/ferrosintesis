**Status:** COMPLETE (root causes adversarially verified; awaiting Arthur's scope/decision calls before build).
**Mode:** Read-only investigation → plan. No synth code changed.
**Method:** built `ferrosintesis.exe` 0.19.0 from this worktree; rendered the 4 melodic

## GM numbering

`GMxxx` = the raw MIDI program byte 0–127 (`programs.py::GM_NAMES[xxx]`). GM004 = Electric
Piano 1, GM029 = Overdriven Guitar, GM074 = Recorder, etc.

## Verified findings + smallest fix + oracle

Each row: root cause (measured + code-confirmed) → smallest fix at the right layer → the
machine-checkable oracle that fails-before/passes-after. "Ears" = a target/amount only

### GM004/005 electric pianos — clean sine stack, no "bark" (A)
- **Cause:** `electric_piano_1/2` are additive `Modal` (sum of ~6 pure `Sine`s + a noise
  burst). Verified: **zero harmonic-generating nonlinearity** anywhere in the Modal path →
  measured flatness 0.003–0.004. A real Rhodes/Wurly gets its bark from the pickup
  nonlinearity (dense, velocity-growing harmonics). The bell partials exist but are pure
  sines, so they don't fill between partials either.
- **Fix:** add an **optional** velocity-scaled asymmetric pickup shaper to `Modal` (an
  `Option` field branched *outside* the sample loop, like `amp_trem`/`strike_glide` — so every
  other Modal voice stays byte-identical), + a one-pole DC blocker on the shaped signal. Call
  it only from EP1/EP2. Render-diff-clean (only GM4/5 channels change).
- **Oracle:** ratio `mag_at(4f)/mag_at(f)` at a harmonic **absent** from the EP1 table (4f):
  `<0.01` before, `>~0.03` at vel120 *and* rising with velocity, after; + a DC guard.

### GM001/002/003 — aliased to GM000 (B, decision)
- Deliberately collapsed onto Acoustic Grand by `make()` arm `0..=3`. Not a bug — that's
  "what happened to them." Making Bright Acoustic / Electric Grand / Honky-tonk distinct is a
  **scope choice** (honky-tonk = detuned unison, electric grand = CP-ish, bright = brighter EQ).

### GM014 [alt] tam-tam — "weird, maybe remove" (B, decision) ⚠ correction
- **Not a defect and not spare.** The alt is a deliberately-modelled tam-tam/gong that folds
  keys into MIDI 36–47 (~65–124 Hz); a sub-500 Hz wash is correct for a gong. It is the
  **composed climax** ("the tam-tam splash") of `albums/fable5/Through Lines/"Ten Metres of
  Air"`, authored + oracle-guarded. **Deleting it would break that album** (render-diff would
  show it) and needs the track recomposed first.
- **What actually reads as "weird":** the audition A/Bs the gong directly against tubular
  bells at a folded-down register. **Minimal, album-safe fix (demo only):** drop `ALT_BANK[14]`
  in `programs.py` so the gong isn't inlined as tubular bells' twin (optionally give it its own
  standalone audition slot). No synth change, no album impact.

### GM019 church organ — swap default to the Leslie (B, directive) ⚠ 3 edits, not 1
- **Cause:** default = `CathedralOrgan` (pipe model routed through a cathedral wind-chest
  block); alt (CC0) = drawbar `organ()` **with a CC1 Leslie ramp**. Crucially the "Leslie"
  lives in **engine.rs**, keyed on the spawn-time `alt` flag — `organ_leslie_family` and
  `cathedral_organ` predicates — not in the voice. So a one-line dispatch swap gives a *static,
  Leslie-less* drawbar.
- **Fix (3 coordinated edits):** (1) `voices.rs` make() → route 19 to `organ()` (fold into the
  `16..=18|20|21|23` arm); (2) `engine.rs organ_leslie_family` → include 19; (3) `engine.rs
  cathedral_organ` → false for 19. Leave the CC0 alt path byte-identical (The Ninth Bell
  authors CC0-GM19 intentionally). Invert the two pinning tests. Run render-diff (every
  default-GM19 album moves to the drawbar Leslie).
- **Oracle:** default-bank (no CC0) GM19, sweep CC1 0→127, assert the tremulant AM rate ramps
  up (late > early + 2.5 Hz, late ≥ 5.5 Hz) — fails now (CathedralOrgan has no ramp), passes
  after. Plus flip `organ_leslie_family(19,false)` / `!cathedral_organ(19,false)`.

### GM029/030 overdriven/distortion guitar — clean, dark sustain (A) ⚠ cause corrected
- **Cause (verified, my first guess refined):** the Drive is a **static** waveshaper whose
  clipping is level-dependent. On a held note the e-bow sustainer (`SusDrv`, capped
  `SUS_K_MAX=0.12`) holds the string as a **moderate-level pure fundamental** (upper partials
  killed by the `bright=4800` damper). That near-sine through stage-1 tanh at `g1=2.5`
  (prog29)/`4.5` (prog30) barely clips — regenerating only a ~−25 dB 2nd harmonic. So the
  sustain is a warm fundamental with no distortion edge (measured `hf>2.5k`=0.000). My
  "post-drive cabinet rolls it off" sub-claim was **refuted** (tilt is interstage; the cabinet
  even boosts 300–2500 Hz) — the harmonics are simply never generated.
- **Fix:** raise the **static preamp gain** `g1` for 29/30 in `Drive::new`
  (e.g. 29: 2.5→~6–8, 30: 4.5→~8–10 — **ears**), re-match `post` for loudness. Keeps the
  intentionally-static architecture (does *not* re-introduce the deleted sag hack). Guarded by
  the existing `drive_alias_floor` (−40 dB).
- **Oracle:** `driven_sustain_stays_distorted` — held E2, deep-hold window, THD of harmonics
  2–16 vs f0 ≥ −12 dB (fails now at ~−20, passes after ~−8; floor calibrated with margin).

### GM041 viola — muddy default vs sampled alt (B) ⚠ two causes
- **Cause:** (1) default `make()` routes `41|44 → plain Bowed` with **no sample layer**, while
  violin/cello/bass (and the *alt* bank's 40..=43) are LaVoice-wrapped — so program 41 is
  uniquely the only bare bowed default, and its "alt is better" is largely the missing sampled
  bowed attack (measured `lo<500` 0.433 vs violin 0.028, alt-viola 0.037). (2) commit `d36b878`
  raised `BODY_VIOLA[0]` from +5.0 to +7.5 dB (the alt keeps +5.0) — a real but smaller (~1.3×)
  extra low boost.
- **Fix (minimal):** revert `BODY_VIOLA[0]` 7.5→5.0 (one constant, matches the preferred alt).
  Optionally bump `press_span` 4200→4600. **Larger (Arthur):** also give default-41 the LA
  bowed sample layer (route it out of the bare `41|44` arm) — this is what fully closes the gap.
- **Oracle:** `band_rms(220,Q1.3)/rms` for `Bowed(41)` ≤ 2.5× that of `Bowed(40)` — fails now
  (~15×), passes after the EQ revert (~1.3×).

### GM044 tremolo strings — redundant alt (B) ⚠ tremolo IS implemented
- **Cause (my "no tremolo" claim refuted):** program 44 implements a full bow-tremolo in
  **both** banks (`trem_rate=6+3·vn`, depth, per-reversal rebite; green oracle
  `default_bowed_articulations_and_sample_routing` already pins it). main==alt because **both
  banks ship the same violin-bodied tremolo** — the CC0 alt offers nothing.
- **Fix:** **decision** — drop the redundant 44 alt, or author a genuinely distinct alt
  voicing. The tremolo itself needs no code change.

### GM046 harp — too dark (B)
- **Cause:** `HARP` preset — `pick_lp` 1800 (dull attack) + body EQ all ≤400 Hz (low-mid lift,
  no air) + loop-damper `bright` left at the default 3000 (kills shimmer). `bright` is the
  shimmer lever (it sets the KS loop damper), not `pick_lp`.
- **Fix:** raise `bright` 3000→~4500–5000 (single best lever) + `pick_lp` 1800→~2600–2800;
  optionally add one ~2.5–3 kHz air body mode. **Oracle:** sustain centroid > ~700 Hz (fails at
  ~294 now).

### GM047 timpani — boomy tail (A) ⚠ cause corrected
- **Cause (refined):** *not* "pitch buried" — the pitch mode is the loudest (amp 1.0) and the
  thump is already 0.5·v. The boom is round-1's **uniform 3× T60 lengthening** applied to that
  already-longest/loudest fundamental (T60 now 3.0 s), so the tail collapses into a sustained
  isolated low hum once the faster upper modes fade.
- **Fix:** shorten just `partial[0]` (ratio 1.0) T60 3.0→~1.8–2.0 (leave the 0.5·v thump and
  `TIMPANI_RELEASE_T60` alone). **Ears:** how tight the kettle should ring (round-1 lengthened
  it to stop it reading as a tom; round-2 says too boomy — opposite pulls). **Oracle:** in the
  0.5–1.0 s tail, `(mag@1.504f0+mag@1.742f0+mag@2f0)/mag@f0` ≥ 0.25 (fails now → pure hum).

### GM048/049 string ensembles — synthy sustain (B) ⚠ not a divide-down machine
- **Cause:** `strings()` = 5 detuned `BlepSaw`s through one lowpass, **`breath=0.0`, no chorus,
  no body/formant** (the divide-down machine is `synth_strings()` 50/51, a different voice). The
  sample layer supplies only the onset and is **contractually zeroed after 0.40 s**, so a held
  note is pure saw for its whole audible life — hence synthy. No sample-gain change can warm the
  sustain.
- **Fix (minimal, existing path):** give `strings()` a small bow-noise `breath` 0.0→~0.012–0.02
  (filtered bow-hiss = the aperiodic "air" it lacks). **Larger (Arthur):** add a resonant
  low-mid body formant + richer detune. **Oracle:** inter-harmonic noise/harmonic ratio N/H in
  a between-harmonics band, measured **past 0.40 s** (model-only), rises above a calibrated
  threshold (≈0 before).

### GM052/053 choir & voice — thin, no body (B, fresh) ⚠ cause corrected
- **Cause (refined):** `ChoirV2` is a **parallel bandpass bank** — output = sum of 5 bandpasses,
  lowest at F1 = 660 Hz (aah) / 330 Hz (ooh), Q≈9, + a ~3 kHz singer's cluster. There is **no
  band spanning the fundamental and no source/voicing bypass**, so the sung fundamental
  (100–400 Hz, below F1) is filtered out (~−27 dB) → measured `lo<500`=0.003 = thin, nasal,
  formant-only. (My "output highpass" guess was wrong — `hum_lp` is a *lowpass*; and it's not a
  gain-balance issue.) Round-1 only fixed the *rig* (CC70 vowel), never this.
- **Fix:** add a **Klatt-style voicing bypass** — a lowpassed (~500–650 Hz) copy of the dry
  pre-tract source blended in parallel (pitch-tracks automatically). Default-on timbre change →
  render-diff + one version bump. **Oracle:** low choir note (A2≈110 Hz), sustain
  `band_rms(80–500)/rms` > ~0.05 (fails at 0.003, passes after). **Ears:** how much body
  (`chest_gain`) — affects every choir album.

### GM064–067 saxes — distorted from mezzo-forte up (A)
- **Cause:** the RD10 rasp drive is **linear in pressure** (`g = g0 + g_press·p`,
  `g_press=15.5`, no bloom gate). At vel~96 → p~0.71 → **g~11.6**, nearly as hard as ff (g~16),
  so the bias-tanh is a near-rectangle and injected turbulence intermodulates into broadband
  skirts on ordinary notes (measured flatness 0.17–0.32, alto `hf>3k`=0.34). The brass rasp
  already solved this with a smoothstep bloom gate; the sax drive has none. **Constraint:** the
  shipping gate `reed_g3_sax_rasp_skirts` deliberately pins the **ff** skirt near the −40 dB
  audibility floor (measured −38.5 dB), so a flat `g_press` cut would break ff.
- **Fix (preserves ff, cleans mf):** make the drive **convex in pressure** —
  `g = (g0 + g_span · p^2.5) · der` (one const + one line). At p=1 g is unchanged (ff/G3
  intact); at p=0.71 g falls 11.6→~7.1; at pp→~0.5 (clean).
- **Oracle:** "rasp blooms with pressure" (mirrors `brass_o12_rasp_blooms`): ff skirt ≥ −40 dB
  (G3 preserved) **and** mf skirt ≤ 0.5× ff — fails now (mf≈ff), passes after.
- **Ears:** whether ff sax rasp is wanted at all, and where the clean→raspy knee sits.

### GM074 recorder — near-pure sine (A) ⚠ cause corrected
- **Cause (refined):** it is an **open** pipe with a full harmonic series, but `RECORDER.harm =
  [0.09,0.05,0.012]` is the weakest low ladder of any Wind voice (h2 at −21 dB vs flute 0.32,
  piccolo 0.22) + `breath=0.055` near the floor → the body collapses toward the fundamental
  (crest 1.73). My "odd-harmonic hollow" framing was **wrong** — that's a stopped pipe (clarinet
  /pan-flute); it would mis-model the recorder.
- **Fix:** raise the low ladder keeping evens present and staying below the flute: `harm`
  0.09→~0.16, 0.05→~0.08, 0.012→~0.02 (preset constants only; touches no existing recorder
  oracle). **Oracle:** `h2 ≥ 0.14` **and** `h2 < flute h2` **and** `h2 ≥ h3` (the last clause
  pins the open-pipe mechanism so a wrong "odd hollow" fix fails). **Ears/decision:** raising
  audible breath is a bigger change (WD-O5 caps recorder breath below the flute).

### GM076 blown bottle — airy (decision)
- **In-spec:** a deliberately-engineered, oracle-locked Helmholtz vessel; the measured 0.888
  breath fraction is inside its design band. Not a bug. **Leave as-is** unless the airy timbre
  isn't what Arthur wants (taste).

### KEY 065/066 High/Low timbale — same drum (B) ✔ CONFIRMED
- **Cause:** `drums.rs` — `65 | 66 => dm(&[(430.0,…)],…)` share one arm at a **fixed 430 Hz**,
  never reading `key`. Rendered pitch ratio 1.000. (Same bug class as the tom-ladder collapse
  already pinned by `tom_ladder_is_six_distinct_drums`.)
- **Fix:** split into two arms — keep 65 at 430 Hz, add `66 => …320 Hz…` (a ~4th below, tracking
  the noise-band centre 1600→~1200), mirroring the bongos (60/61). **Oracle:**
  `render_drum_kit(65)` and `(66)` must be **not bit-identical** (the un-foolable clause) and
  `f_hi > f_lo·1.12`. **Ears:** exact interval.

### Lyrics-field timing — the "extra note" broke scrubbing (rig defect) ✔
- **Verified:** the reference audition's lyrics match the render to ±10 ms *numerically*, but the
  failure is real: timestamps are **floored to whole seconds** and sit at each slot's silent
  start; the round-1 **soft-tag note plays at t0+4.2 s — 0.6 s before the next slot's marker**.
  So a floored label of slot *i* lands on slot *(i−1)*'s soft note. Concrete: GM005 labelled
  "0:09" (marker 9.6 s) but GM004's soft note plays at 9.01 s → scrubbing the label plays the
  *previous* instrument. Before the soft note that instant was silent.
- **Fix:** anchor the marker (and hence the lyrics timestamp) to the **audible onset**
  (`t0 + _ONSET`) in `audition.py::emit_slot`, then rebuild the audition and re-verify. Demo-only.

## Cross-cutting

- **Sax vs guitar are mirror images:** the sax has *too much* nonlinearity engaged too early
  (linear-in-pressure drive, no bloom gate); the guitar has *too little* surviving the sustain
  (static tanh sees a moderate pure fundamental). Both are "where in the note the nonlinearity
  lives." Both fixes are a handful of constants + one oracle each.
- **Two "alt" complaints are routing asymmetries, not voicings:** GM041 (default uniquely lacks
  the sample layer) and GM044 (both banks are the same voice) — same class as round-1's rigged
  GM43 A/B.
- **Fable retainer:** the two "hard" items (choir, sax) now have verified fixes *and* oracles
  from the verification pass — I do **not** expect to need the Fable budget. I'll reserve it only
  if a build-phase correctness subtlety appears that the oracles miss.
- **Every synth change** goes through the render-diff inventory (baseline vs new binary over all
  album MIDIs) per the repo's synth-change policy; expected diffs only on the intended programs.
  One version bump for the integrated task.
