## 0. Bottom line up front

Arthur's hypothesis — *"perhaps lack of LA synthesis?"* — is right for a **minority** of the twelve
complaints, and even there the ideal sample source is **blocked by CC0 licensing**. The dominant story,
across 6 of the 7 investigated clusters, is different and more important:

> **Model/preset defects that were "fixed" in round 2, went green on a numeric oracle, and still sound wrong** —
> because the oracles measure *presence, routing, loudness, and decay*, not *timbre* or *audible distinctness*,
> and several render through a path the ear never hears.

So the single highest-leverage deliverable is **not any one voice** — it is a class of **differential /
timbre / sustain-window oracle that fails on today's code**, so that "green" finally means "audibly right."
Two of the twelve complaints are **decisions for Arthur, not fixes** (the tam-tam most sharply — de-pitching
it would break a committed album). Everything else is buildable now, in waves.

Every load-bearing claim below was independently re-opened by an adversarial verifier; where the verifier
corrected the investigator, the corrected version is taken and flagged. Two keystones were also re-checked
by hand: the clavinet dead-code bug (`voices.rs:3434/3439`) and the distinctness matrix rendering
`samples=false` (`testutil.rs:1365`).

## 2. Two throughlines

### 2.1 The LA-synthesis reframe (Arthur's hypothesis, honestly graded)

The LA layer, *as architected*, is an **attack-only transient**: a sampled onset crossfaded *out* by
~0.2–0.4 s, handing the rest of the note to the model (`sampler.rs` `LaVoice`). That one fact decides the
section. **LA can only ever fix onset identity; it structurally cannot fix a complaint whose identity lives
in the sustain — and most of these do.**

| Cluster | Is "missing LA" the cause? | Reality |
|---|---|---|
| **A — GM0/1/3 pianos** | **Inverted** | All three *already have* the LA layer, sharing one 1.8 s upright sample at one gain. The dominant shared sample is the *cause* of the sameness; the model differentiators live in the `[0, 0.18 s]` window `LaVoice` multiplies by **zero**. Fix = DSP the *existing* sample per-program; **zero new assets.** |
| **B — GM4/5 e-pianos** | **True in spirit, asset-blocked** | EP identity genuinely lives in the attack. But there is **no CC0 Rhodes/Wurlitzer/DX** source; VSCO 2 CE's only keyboard is the acoustic upright, which would drag GM4/5 *toward* GM0. Ship the model fix. |
| **C — GM6/7 harpsi/clav** | **True in spirit, asset-blocked** | A sampled quill/tangent attack is the natural carrier. But CC0 harpsichord is plausible-but-unconfirmed, and CC0 clavinet is effectively **non-existent** (Hohner Clavinet is proprietary). Fix the excitation model now. |
| **D — GM19/21/23 organ/accordion** | **Wrong** | Both defects are *sustain-timbre / registration* (musette shimmer, reed formant, 16′ foundation). An attack sample reaches ~50 ms and stops. Reject LA regardless of sourcing. |
| **E — GM25 steel** | **Diagnoses *why* GM24 wins; literal fix blocked** | GM24 beats GM25 precisely because it has a sampled pick transient (the part synthesis fakes worst). But the ideal steel source is licensing-blocked and staying that way (FreePats = GPL-with-exception; Philharmonia = CC-BY-NC; VCSL = CC0 but has *no* steel-string). The one license-clean move: borrow the in-repo **nylon** bank as a pick-attack layer with a brightening pre-tilt — real, but nylon-coloured. |
| **F — GM29/30 drive** | **Wrong** | No CC0 electric-guitar source, *and* any sample would be program-keyed → lands on default and alt bank identically → cannot make main ≠ alt. Pure preset convergence. |
| **G — GM14 tam-tam** | **Wrong** | Outside the sampler; the alt path builds the voice directly. A tam-tam's identity *is* its sustain, which the attack layer never reaches. Only a *full one-shot* would help — a new asset + new player path + a requirements call. |

**Honest verdict:** missing sampled attacks explain a minority of the weakness, and where a sample *would*
be ideal, CC0 licensing blocks every ideal source. **Confirmed CC0 already in-repo:** upright piano (VSCO 2),
nylon classical guitar (FreePats), orchestral (VSCO 2), drums (Virtuosity/Big-Rusty) — none of the missing
families. **Asset routes worth a later decision (each violates the current "no new asset crates" non-goal):**
harpsichord (maybe FreePats/Freesound), accordion (Versilian VCSL *is* CC0 and has one), gong one-shot
(VSCO 2 CE percussion *may* contain one — a 10-minute check before assuming).

### 2.2 The "green-but-wrong" throughline (the real prize)

Six of the seven clusters are textbook instances of the repo's named failure mode: a distinct code arm, a
green numeric oracle, and a sound the ear rejects. This is systematic — a property of the oracle *regime*:

| Cluster | How the oracle went green while the sound stayed wrong |
|---|---|
| **A pianos** | Distinctness matrix renders `samples=false` (`testutil.rs:1365`). It proved the *models* differ; the audible signal is model+shared-sample, where they don't. **Wrong layer measured.** |
| **B e-pianos** | Distinctness score is a **MAX over 5 features after skipping the first 50 ms**. One bright early-body outlier saturates it while the shared attack and shared near-sine sustain — which drive identity — are ignored. **Wrong window + wrong aggregator.** |
| **C harpsi/clav** | Oracles check "not too quiet," velocity spread, quick decay, `kind()=="CLAVINET"`, loop stability. **None looks at spectrum** — which is why two live *bugs* went unnoticed. |
| **D organ/accordion** | Musette oracle asserts a 3–8 Hz *global amplitude wobble*. A coherent tremolo satisfies it trivially; a real accordion needs per-harmonic inter-reed *beating*. **Measures that AM exists, not what kind.** |
| **E steel** | Only oracle is a ff/pp centroid *ratio* > 1.4 — a velocity-brightness law, not a steel-vs-nylon check. Timbre was never in scope. |
| **F drive** | `driven_sustain_stays_distorted` renders the default bank only, never compares main vs alt, and by *demanding* a distorted 6 s tail it **requires the e-bow hold — the very mechanism that erases the main/alt contrast. The oracle enforces the defect.** |
| **G tam-tam** | Oracles literally **encode the wrong target**: one asserts a clean 98 Hz pitch, another requires the shimmer front-loaded and *absent* from sustain. (Contested — the pitch may be intentional; see §4.) |

**The class of oracle needed** — three kinds, each **fail-first (RED on today's code)**, each rendered through
the *same path the ear hears* (full engine, samples ON where the voice is sampled, sustain window not just
the skipped onset):

1. **A-vs-B differential / distinctness oracles that measure TIMBRE in the sustain window** (0.4–0.8 s). For
   any "they sound the same" pair, require a real harmonic-vector / spectral-distance margin. Meta-fix for
   **A, B, F**. F's form: a **MAIN ≠ ALT** oracle rendering *both banks* and asserting a sustain-index or
   attack-shape gap.
2. **Absolute instrument-identity oracles** encoding what the target physically *is*, with a contrasting
   positive control (e.g. harpsichord persistent high-centroid + 2×f0 choir energy vs GM0 piano as
   fundamental-dominant control; accordion per-harmonic beating sidebands where Δh scales with h — a
   signature a coherent tremolo physically cannot fake; steel inharmonicity `fₙ≈n·f0·√(1+B·n²)` with nylon's B
   materially lower).
3. **Anti-defect / bug-catch oracles** that would have caught the live bugs no perceptual oracle looked at
   (dead `attack_noise`; near-linear grit at sustain).

**One infrastructure reform worth its own slice:** flip the distinctness *matrix* itself to samples-on for
LA-wrapped programs, use a sustain window, and drop the raw-MAX aggregation. That stops it green-lighting
near-clones synth-wide, not just for these clusters.

### 3.1 GM0/1/3 acoustic pianos — "sound the same" · verdict CONFIRMED / fix sound

- **Root cause.** All three call the identical `piano_bank(vel, seed&1==0)` at the identical `LA_PIANO` gain
  (`voices.rs:10067–10081`; `LA_PIANO=(0.90,(0.18,0.85))` at `:7444`). The 1.8 s sample carries the
  perceptually-loud part of the note. The round-2 differentiators are **discarded or relegated**: the
  bright/honky *hammer strike* lives in a 12 ms noise burst that is fully spent inside `[0,0.18 s]`, exactly
  where `LaVoice` multiplies the model by `u=0` (`sampler.rs:816`) — so GM1's 4800 Hz vs GM0's 3800 Hz hammer
  band **never reaches output**; the brightness/detune differences only reach full weight after the
  crossfade ends at 0.85 s, by which point the onset (where the ear decides "piano identity") is over. And
  the oracle that "proved the split" renders `samples=false` — it measured the models, which *do* differ,
  not the model+shared-sample, which doesn't.
- **LA verdict.** **Inverted.** They already *have* LA; the shared sample is the cause. Fix DSP-processes the
  existing sample — **zero new assets**.
- **Fix (M / moderate / high).** Put per-program identity **into the sample-owned window**, inside `LaVoice`,
  via two default-inert parameters: (a) a one-pole high-shelf "tilt" on the interpolated sample readout
  (GM1 Bright ≈ +4 dB above ~1.8 kHz); (b) one or two extra detuned interpolated reads of the same sample
  (GM3 Honky ≈ ×1.007 / ×0.993, mixed ~0.4, so beating begins at onset). GM0 and every other wrapped program
  pass tilt=0/detune=off → **byte-identical**. *Do not* touch `fade_start` (doubled-attack risk) and *do not*
  just cut LA gain for 1/3 (only makes them quieter — the model strike is still discarded).
- **Oracle.** Differential, **sampled**, early-window: (1) GM1/GM0 hp_rms(>2.5 kHz)/rms over `[0,0.4 s]` ≥ ~1.25;
  (2) GM3 AM modulation depth in the 1–6 Hz band over `[0.05,0.8 s]` exceeds GM0's. Both **must render
  samples=true** — the current matrix doesn't, which is the whole flaw.
- **Watch.** GM3's dual-read of *identical* PCM at ~7 cents can comb/flange rather than beat — may need per-read
  phase decorrelation. Exact tilt-dB and detune-mix are ear-tuning calls.

### 3.2 GM4/5 electric pianos — "very similar" · verdict CONFIRMED / fix needs-adjustment

- **Root cause.** The B1 infrasound bug *is* fixed at HEAD (both fns now do `.map(|(r,a,t)|(f*r,a,t))`). The
  real reasons they still converge: (1) the distinguishing energy lives only in the first ~250 ms; both
  sustains collapse to a near-pure fundamental sine (measured GM4 sustain h2/h1=0.027, GM5=0.076, uppers≈0),
  and a held key note spends most of its energy there; (2) GM4 does not *bark* — the Rhodes tine/bell partial
  is ~16 dB too low at onset; (3) round-2 answered "no bark" by giving *both* the same tanh `PickupShaper`
  over the *same* additive `Modal` sine stack, which pushes them **together**. The distinctness oracle reads
  0.363 (> the sax 64/65 pair) and passes because it is a MAX over features computed after skipping the onset.
- **LA verdict.** **True in spirit, asset-blocked** — no CC0 Rhodes/DX; the acoustic upright bank would drag
  them toward GM0. Ship the model fix; keep a sampled EP attack as a future, source-gated enhancement.
- **Fix (M / moderate–high / medium).** **Split the synthesis method so they cannot re-converge:** GM5 → a
  genuine 2-operator FM voice (new `dsp.rs`; glassy bell attack + a residual index tail so the *sustain* stays
  glassy); GM4 → keep `Modal` but raise the bell partials so it barks (tine/bell to ~0.4–0.6× the fundamental
  at onset, short T60 so it knocks-then-blooms).
- **Oracle.** (1) sustain-window (0.4–0.8 s) pairwise distinctness margin (FAILS today); (2) GM4 bark
  magnitude+bloom (onset bell/f0 ≥ ~0.4, decayed by sustain); (3) GM5 FM-sheen persistence in the sustain.
- **Verifier corrections (fold in).** GM4 **is** used in committed albums (fable5 *Big Weather*, *Heliopause*,
  *Through Lines*; gpt5-6 *Bright Matter*) → the loudness re-check is **mandatory, not optional**. The FM GM5
  must keep the existing `electric_piano_pickup_bark_grows_with_velocity` test (which asserts on **prog 5**)
  green, or revise it in the same change. Onset-window harmonic oracle needs a higher probe key / windowing to
  resolve h2/h1.

### 3.3 GM6 harpsichord / GM7 clavinet — "not a harpsichord / clavinet" · verdict CONFIRMED / fix sound

- **Root cause.** Both are the *same* noise-excited Karplus-Strong string as every guitar/bass, re-parameterized;
  the instrument identity (bright buzzy quill *pluck* + 4′/8′ octave choir; percussive *tangent strike* +
  sustained metallic pickup buzz) lives in the **excitation and string topology**, which the presets don't
  change. Two are **live bugs**: (1) the clavinet's tangent-scrape `attack_noise:0.22` is **dead code** —
  `onset_post` is `if p.click>0 && p.click_post {…} else if p.attack_noise>0 {…}` (`voices.rs:3434/3439`) and
  CLAVINET sets *both*, so the first branch always wins and the scrape never fires *(hand-verified)*; (2) `grit`
  = `(y*2.0).tanh()*0.5` is near-linear at sustain amplitude, so it softens the onset transient but adds **no
  sustained metallic buzz**. The oracles check only loudness/decay/routing — none looks at spectrum.
- **LA verdict.** **Asset-blocked** — no CC0 harpsichord/clavinet in reach (clavinet effectively unavailable;
  harpsichord plausible-but-unconfirmed). Park an asset route as a scratchpad decision; fix the model now.
- **Fix (M / moderate / medium).** At the **excitation + string-topology layer, per-preset** (opt-in shape on
  `PluckPreset`, default = today's noise burst — *not* the global K2 displacement IC that was correctly
  reverted). Harpsichord: blend a bright buzzy quill pulse into the excitation; optional 4′ octave choir
  (second KS loop — *keep optional*, it doubles voice cost and 8′-only still reads as a harpsichord). Clavinet:
  make the excitation a struck impulse; **fix the dead param** so `click_post` and `attack_noise` coexist;
  drive/relocate the grit (post-pickup or harder/earlier) so the buzz survives into the sustain.
- **Oracle.** Harpsichord: persistent high-centroid + 2×f0 choir energy (vs GM0 piano control). Clavinet:
  pickup shelf ~4.5 kHz + **odd-harmonic grit energy in the sustain** (0.2–0.5 s) + broadband onset from the
  resurrected `attack_noise` (compare forced-off). All FAIL today.
- **Sequencing note (verifier).** The two clavinet bugfixes are **undeniable wins independent of any ear pass**
  — do them first (Wave 1). The quill reshape + 4′ choir is the perception-dependent phase (Wave 2).

### 3.4 GM19 organ presence / GM21·23 accordions — verdict PARTLY / fix sound

- **Root cause.** **Accordions (CONFIRMED):** they are church-organ `organ()` voices with a *fundamental-only*
  detune. Three of four defining cues are absent — full-spectrum reed **beating** (the detune triple sits only
  on H1; H2/H3/H4 are single static sines), reed **brightness/buzz** (`drive=0.0`, so no waveshaping;
  rolloff to 0.05 at H4), and a bellows **chiff** onset (`chiff=0, click=0`) — while a competing *coherent*
  global tremolo cheats the weak `low_rate_am_depth` oracle. GM23 is **backwards**: it's given a *wider*
  musette (±22 c) than GM21 (±16 c), where a bandoneon/tango box is *drier* and reedier. **GM19 (PARTLY):** the
  drawbar arm has **no 16′ foundation partial** — GM16/17/18 all carry a `(0.5, ~0.5)` sub-octave, GM19
  uniquely lacks it — and no upper mixture ranks; it is already bright (centroid ~1189 Hz), so it sits thin/back.
- **LA verdict.** **Rejected** regardless of sourcing — both defects are sustain-timbre / registration, which
  an attack transient never reaches.
- **Fix (M / moderate / high).** **In-place enrichment in `organ()`** (smallest correct change; no new voice).
  Accordions: spread the musette across harmonics (detuned pairs on H2/H3/H4); add reed brightness (`drive`
  0→~0.15–0.3 + formant tilt); add a bellows-chiff onset; **remove the coherent global tremolo** (the oracle
  cheat); differentiate GM23 as a *drier, sharper* bandoneon. GM19: **add the missing 16′ foundation partial**
  (safe structural fix) — hold mixture ranks/level pending an ear A/B (see §4).
- **Oracle.** Replace the global-AM musette check with a **per-harmonic beating-sideband** oracle (sidebands at
  f0·h ± Δh where **Δh scales with h** — a coherent tremolo cannot fake it; needs a >0.5 s window to resolve
  2–9 Hz sidebands); GM23 asserts a *drier* musette + sharper onset than GM21; GM19 asserts a 16′ foundation
  (band_rms at f0/2, absent today), with the existing Leslie-ramp oracle kept green.
- **Decision flag.** "Presence" is ambiguous (low-end foundation vs upper sparkle vs forward level), and the
  voice is *already* bright — adding mixture ranks could work *against* it. Ship the 16′ foundation now; the
  lever is a §4 ear decision. Fallback if in-place enrichment can't hit the reedy formant: split 21/23 into a
  dedicated free-reed voice (effort L).
- **Album exposure.** GM19: Amarok, *The Ninth Bell*, *Architecture of Air*, *Big Weather*. GM21: Amarok folk,
  *Atlas of Becoming*.

### 3.5 GM25 steel acoustic — "not very good" · verdict CONFIRMED / fix needs-adjustment

- **Root cause.** (1) The only prior steel work (commit `0568683`) was **sustain-only** — it changed `t60`
  3.5→4.5, `bright` 5200→5600, added let-ring `rel_t60` 1.1, and touched *no* timbre lever (pick_lp, pos, body
  EQ, click all unchanged); round-2 never mentioned steel. The timbre complaint was **never in scope.** (2) The
  KS loop has **no dispersion** (`voices.rs:3162` states it: "Pure arithmetic — no allpass … deferred"), so
  every partial is exactly harmonic — steel and nylon differ only in a lowpass corner and a few body peaks, and
  the model **structurally cannot sound metallic** (the "zing" is string-stiffness inharmonicity). (3) No pick
  sample, unlike GM24 nylon.
- **LA verdict.** GM24 wins *because* of its sampled pick transient, but the ideal steel source is
  licensing-blocked and staying that way (FreePats = GPL-with-exception; Philharmonia = CC-BY-NC; VCSL = CC0 but
  no steel-string). The one license-clean sample move: **reuse the in-repo nylon `guitar_bank()`** as GM25's
  attack layer with a brightening pre-tilt — real pick transient, no new asset, but nylon-coloured.
- **Fix (M / moderate / high) — reordered by the verifier.** **Do the cheap, certain levers first, demote the
  headline.** (a) **S levers:** re-voice `STEEL.body` for a dreadnought (low-mid scoop ~350 Hz; presence 2800 Hz
  +1.5→+3–4 dB; add ~4.5 kHz sparkle); sharpen the flatpick (`click_hp`→~2500; small `attack_noise` ~0.05–0.08).
  (b) A/B the **license-clean nylon-bank pick-attack layer.** (c) The **stiffness-dispersion allpass** is the
  least perceptually-certain, highest-effort, highest-risk lever — it touches the *shared* `Pluck` path (basses
  32–37 etc., must default B=0) and its group-delay comp must hold through live bends/vibrato — so build it as a
  **spike**, A/B it, keep only if audibly worth the semver/shared-path risk.
- **Oracle.** Inharmonicity oracle (partial n stretched sharp per `fₙ≈n·f0·√(1+B·n²)`, steel B in target band,
  nylon B materially lower — FAILS today at B=0); a 3–5 kHz sparkle-presence oracle above nylon; keep the ff/pp
  centroid-ratio. **Widen the analysis window beyond 0.25 s** (or peak-interpolate) or the few-Hz stretch won't
  resolve.
- **Verifier flag.** GM25 **doubles as a tremolo mandolin** in *Hollow Hill* and *The Signal Fire* — render-diff
  *count* is false comfort; those uses need per-part **listening**.

### 3.6 GM29/30 overdriven/distortion — "main & alt sound the same" · verdict CONFIRMED / fix needs-adjustment

- **Root cause.** Round-2 **converged the presets**: `DRIVE` and `DRIVE_LEAD` now share `t60=8.0`,
  `pick_lp=6000`, `pos=0.12`, `pickup=0.10`, `pickup_rlc=(3300,1.5)` **and both arm the e-bow** (sustain 0.7 vs
  0.6). The intended contrast — a decaying pluck vs a soaring e-bow hold — was erased. The e-bow drives **only
  f0**, so the held landing note (which dominates the ~2 s audition tail) collapses to the same warm near-sine
  for both banks *and* both programs. The oracle `driven_sustain_stays_distorted` renders the **default bank
  only**, never compares main vs alt, and by demanding a distorted 6 s tail **requires the e-bow hold that
  erases the contrast — the oracle enforces the defect.**
- **LA verdict.** **Rejected** — a program-keyed sample lands on both banks identically; cannot make main ≠ alt.
- **Fix (M / moderate / high).** Restore the decay-vs-sustain contrast at the **preset layer:** cut `DRIVE`'s
  e-bow so main is a *decaying* overdriven pluck (hard pick, richly-clipped attack); keep `DRIVE_LEAD` as the
  sustaining e-bow lead and give it a soft *swelling* onset (small `attack_s`). Main and alt then diverge on
  onset-shape and sustain-length — the two dimensions the ear reads through the shared Drive insert.
- **Oracle.** A **MAIN ≠ ALT** differential oracle (the invariant round-2 lacked): render both banks for prog 29
  and prog 30; assert the sustain-index (late/early RMS) gap is ≥ ~6 dB larger for `DRIVE_LEAD` than `DRIVE`, plus
  an onset-transient gap. Move the distorted-tail THD floor onto `DRIVE_LEAD`.
- **Verifier correction (size the scope).** Dropping `DRIVE.sustain` to 0.0 makes `20*log10(0) = -inf` and breaks
  `sustain_holds_high_notes` **plus orphans three more `&DRIVE`-pinned sustainer oracles**
  (`sustain_survives_bends_and_slurs`, `sustain_release_decays_naturally`, `sustain_never_self_oscillates`) —
  migrate all ~5 to `DRIVE_LEAD`, or floor sustain at ~0.15. Also: the two holds aren't identical today
  (`DRIVE` is 6.6 dB hotter, since `Drive::post` is program- not preset-keyed) — but both are f0-dominated, so
  the diagnosis stands. Fixing main≠alt should simultaneously sharpen 29≠30 by shrinking the shared held tail —
  verify both clear together.

## 8. Licensing architecture — the optional GPL / NC crate pattern

**Why CC0 was the bar.** Samples are `include_bytes!`-compiled into the binary (**incorporation**, not "mere
aggregation"), and the code is MIT/Apache. Bundling copyleft (GPL) or restricted (NC) data *into* that permissive,
published artifact would contaminate it — which is why only CC0 was safe in the default build.

**What CC-BY-NC is, and why it's a trap.** Creative Commons **Attribution-NonCommercial**: you must (BY) credit the
author *and* (NC) use it only non-commercially. The **NC** is the problem — it's a field-of-use restriction, so it
can't sit inside an MIT/Apache crate, and a crates.io dependency reaches commercial users who'd become violators;
"non-commercial" is also legally vague. Plain **CC-BY is fine** (attribution via a `NOTICE` file); the *NC* suffix
is the blocker, never the *BY*.

**The optional-GPL/NC pattern (what makes Tier 3 legal).** Quarantine the encumbrance:
- Core `ferrosintesis` (MIT/Apache) + core samples (CC0) stay clean — the **default build is commercial-safe**.
- Encumbered samples live in **separate, honestly-licensed, opt-in crates** (`…-samples-steel` GPLv3; a `…-nc`
  crate if ever wanted) behind **default-off Cargo features**.
- **The user who enables the feature accepts the terms** — their binary becomes GPL-encumbered (their choice); the
  builder takes the obligation, not us.

**Three caveats (engineering-informed, not legal advice — read exact texts before shipping):**
1. GPL "instrument exceptions" typically free the **rendered audio**, not the **embedding software** — so the
   sample crate must be honestly GPL; only album renders are freed.
2. `include_bytes!` pulls copyleft harder than a separate file would. If we want the weakest pull, ship the GPL
   samples as **runtime-loaded external files**, not compiled in — an architecture choice worth making for the
   steel crate.
3. crates.io hosts any license; the `license` field just has to be truthful.
