# HLD — GM 109 sampled bagpipe: looped drone + chanter

**Status: SELF-APPROVED** (adversarial + external review complete; NOT human SIGNED-OFF)
Date: 2026-07-17
Author: Claude (Opus 4.8, 1M)

## 1. Goal (one line)

Give GM 109 a plausible real bagpipe by sampling the whole instrument — looped
drones + looped chanter — from the CC0 FreePats set, and move today's
fully-modeled bagpipe to the CC0 alt bank (MIDI Bank Select, CC0≠0).

## 2. Scope

**Goal / acceptance (see §7 for the testable form):** with samples enabled and
the default bank, a GM 109 channel renders a sampled looped chanter over a
sampled looped drone stack. With CC0≠0 (alt bank), or with samples disabled, it
renders exactly today's fully-modeled bagpipe, byte-identical.

**Non-goals (deliberately not built in v1):**
- Slow drone *wander* over minutes. A baked ~1.5 s loop repeats; under a chanter
  this is inaudible and still far less static than the pure-oscillator model.
  Residual risk, not a feature (§8).
- Runtime loop DSP (crossfade-at-wrap, loop-point metadata in `Zone`). The loop
  is baked seamless offline; the runtime player is a plain modulo wrap. The
  measurements (§4) show this is sufficient, so the machinery is not built.
- Any GM program other than 109.
- The LA *onset* layer. This is its opposite — sustain, not attack. A bagpipe
  has no per-note onset (proven 2026-07-16: the FreePats "attack" is an editing
  de-click ramp; the drones show the identical ramp, and a drone cannot have an
  attack). So chanter and drone are **both** pure looped steady-state.

**Out of scope:** squidpipes (its "drones" are fake — keyswitched SFZ regions
reusing `long_clean`; zero `drone_*.wav` exist). Migration / back-compat (dev
sandbox). Feature flags, new env vars (quality brief).

## 3. Source (verified 2026-07-17, measured from the downloaded archive)

FreePats Bagpipe, `https://freepats.zenvoid.org/Ethnic/Bagpipe/`. **CC0 1.0**,
`cc0.txt` (full legal code, 7048 B) bundled; dedication by the FreePats project
publishing Gilles Sadowski's recordings.

- **Take the WAV archive** `Bagpipe-SFZ-20221204.7z` (18,887,910 B, sha256
  `6f25f232065ebc51ab9d3b54aaedc8a29e59e454ec31d3f1b4a03b3d04256066`) — 44.1 kHz
  **24-bit** mono, decodes with stdlib `wave` (no FLAC decoder needed; `prepare.py`
  `read_wav` already handles 24-bit). NOT the FLAC archive.
- 26 audio files = 24 chanter + **2 drones**: `drone_G2_1.wav` (98.19 Hz, 2.42 s)
  and `drone_G3_3.wav` (196.18 Hz, 8.58 s). Each a single mono drone (one
  fundamental + harmonics), recorded separately — the instrument's bass + tenor,
  an octave apart. It is a **G pipe** (Flemish/Low-Countries, one bass + one
  tenor), not a Highland pipe in B♭ with a tenor pair.
- Chanter: 13 keycenters **F4→G5** (recorded; SFZ maps up to A5). ~30–50 cents
  flat of ET; roots come from measurement, not the label (as steel).
- Sustains are stable (drift < 6 cents 25%→75%), dry (inter-harmonic floor 63–99
  dB down), no reverb, no note-off tail.

**This is a G pipe, not a Highland pipe.** Accepted: a real-sounding G pipe beats
an implausible modeled Highland one, and the drone stays key-relative (§4) so it
tracks whatever key an album writes. GM 109 idiom is "a bagpipe"; this is one.

## 4. Approach — bake the loop offline, trivial runtime

The whole design rests on one measured fact: **a plain modulo wrap over a
correlation-placed loop region is seamless** (seam click −2.6 to +2.1 dB over
local median, ρ 0.98–1.00 for 25/26 files; a 20 ms crossfade moves this < 1 dB
and is not needed). So:

**Offline (`prepare.py`), new `extract_loop()` — distinct from `trim_to_onset`,
which is an attack extractor and actively hostile to loops (it seeks the onset,
fades the tail to zero, and peak-normalizes):**
1. Skip the ~20–30 ms fade-in ramp; work in the steady interior.
2. DC-remove (the two drones carry −35 / −41 dB DC; chanter is clean).
3. Place `loop_start` at a period boundary in the steady region; correlation-
   search `loop_end` near `loop_start + target_len` for the best period-aligned
   match. **Do our own search — do not import the SFZ loop points** (one, `D#5`,
   is broken upstream; and this avoids an SFZ parser entirely).
4. **Validate ρ > 0.95 at the seam per file** (acceptance gate; §7). A file that
   cannot meet it fails the build loudly rather than shipping a click.
5. Emit the loop region as the WAV. **The whole emitted file loops** — so `Zone`
   needs no loop metadata, `bank!` and `parse_wav` are untouched.
6. Normalize each family to a **common RMS** (not per-file peak) so a `nearest()`
   zone switch does not jump in level — which, for a sustained voice, is audible
   in a way it never was for a 200 ms transient.

Target loop lengths: **drones ~1.5 s** (bass/tenor, low freq), **chanter ~0.4 s**.
Zones: **2 drones** (G2, G3) + **6 chanter** (F4, G4, A4, C5, D5, G5,
~2.5 semitone spacing, ≤ ~1.5 st repitch within the recorded span). Cut from 8
after review: 8 was tighter than the ±3 st tolerance needs and every zone is
shipped bytes in a default-feature crate. Not cut below 6 — the chanter is the
exposed melody, where the nasal double-reed's fixed formants smear most audibly
under repitch, so tighter-than-guitar spacing is defensible. ≈ 450 KB added to
`-orchestral` (≈ +5%). Sized deliberately (§8).

### 4a. Drone pitch mapping and the step clamp

The sampled drone (§4, below) is repitched per the chanter key it latches to.
The modeled drone **branches** (`voices.rs:8321`): a drone-control note
(`key ≤ BAGPIPE_DRONE_CONTROL_MAX = 54`) sounds the tenor **at** `key_freq(key)`;
any other (chanter) note sounds it an octave below, `key_freq(key)·0.5`. The
sampled formula **must replicate that branch** — omitting it plays a drone-control
drone an octave low.

Even with the branch, the *chanter*-spawned drone tracks the chanter register:
tenor = `key_freq(key)·0.5` from `drone_G3` (196.18 Hz). At a high spawn key this
exceeds the guard — key 81 (A5) → step 2.24, key 84 (C6) → 2.67. The `[0.5, 2.0]`
`step` clamp bounds this to a defined pitch error (the drone sits slightly low of
its ideal octave rather than smearing or reading past the buffer). Bagpipe drones
sit in a fixed low register in reality, so a clamped drone under a high chanter
phrase is *more* authentic than a faithfully-tracked one, not less — a happy
accident of the clamp. Tested at chanter keys 55 / 81 / 84 (§7).

### 4b. Levels — explicit gains, not just common-RMS

Common-RMS normalization matches zones *within* a family (so a `nearest()` switch
doesn't jump) but says nothing about the **drone-vs-chanter balance**. The modeled
path sets this deliberately: `BAGPIPE.amp = 0.154` chanter vs
`BAGPIPE_DRONE_AMP = 0.075` (≈ half) with `BAGPIPE_DRONE_MIX` shaping the stack
(`voices.rs:8277, 8033`). The sampled path needs the same: an explicit
`SAMPLED_CHANTER_GAIN` and `SAMPLED_DRONE_GAIN` mirroring the ≈2:1 chanter:drone
ratio. Pinned by a drone/chanter RMS-ratio oracle (§7).

**Runtime — a new `LoopVoice` (~45 lines) in `sampler.rs`:**
- `render`: read `data[j]`/`data[(j+1) % len]` linear-interp (`j = floor(pos)`),
  `pos += step`, wrap `pos -= len` when `pos >= len`. **The wrapped `(j+1) % len`
  neighbour is load-bearing** — both existing players (`SampledDrum:1304`,
  `LaVoice:905`) are one-shot and *stop* at `j+1 >= n`; copying that idiom into a
  loop reads out of bounds or a wrong neighbour once per loop and clicks at the
  loop rate. **Adds** into the buffer (never assigns).
- Why repitch is free: the baked seam is waveform-**continuous**
  (`data[len-1] → data[0]` matches in value and slope, by the offline correlation
  search). That continuity is a property of the *data*, independent of playback
  rate — so any `step` wraps across the same continuous seam. (Not a period-
  integer argument; fractional `step` is fine.)
- **Clamp the PITCH RATIO, then apply sample-rate conversion — not the whole
  step.** The assets are 44.1 kHz; output `sr` is arbitrary (CLI `--rate`,
  `RealtimeOptions::with_sample_rate` documents 48 k, and 96 k is legal). So:
  ```
  ratio = clamp(target_hz / root_hz, 0.5, 2.0)   // coverage guard, pitch only
  step  = ratio * 44100.0 / sr                    // SRC, unclamped
  ```
  `LaVoice` clamps the *combined* `f/root * 44100/sr` (`sampler.rs:853`) and falls
  back to its model when out of range — tolerable there (short onset, model
  underneath), but for a model-free `LoopVoice` clamping the combined value pitches
  a unison note **147 cents sharp at 96 kHz** (unison step 0.459 → clamped 0.5).
  The ratio-then-SRC order is mandatory. Pitch-tested at 44.1 k / 48 k / 96 k (§7).
  The ratio clamp is the coverage guard (no model fallback exists); see §4a for
  where it bites (the drone at high chanter keys).
- **Gain**: an explicit output gain per use (chanter vs drone) — see §4b. The
  sample is normalized to a common RMS at bake, so the gain sets the *mix* level.
- Amplitude: an `Adsr { attack: ~10 ms, decay: 0, sustain: 1.0, release }` — as
  `BagpipeDrone` uses. This gives correct `released()` (stage ≥ 3) **and**
  `alive()` (stage < 4) by construction, so the engine's reap + drone-latch
  machinery works unchanged. `render` returns `env.alive()`; `released()` returns
  `env.released()`; `note_off()` → `env.release()`.
- **Velocity ignored for amplitude** (constant bag pressure) — this is what makes
  BP-O1 (constant-amplitude chanter) hold by construction on the sampled path.
- **Does NOT implement `set_pitch`** — falls through to the no-op. 109 is in
  `vibrato_family`, and the engine calls `set_pitch` on every voice on the
  channel; the modeled drone is immune only by this omission. The sampled voices
  must preserve it or CC1/bend would warble the drones. **Precision:** for the
  *chanter* this is a deliberate sampled-vs-model divergence — the modeled chanter
  is a `Reed`, whose `set_pitch` *does* set `bend` (`voices.rs:8858`), so the model
  follows pitch-bend while the sampled chanter is intentionally bend-inert. Bagpipe
  idiom is fixed-pitch (grace-note articulation, not bends), so this is accepted,
  not a regression — but it is a real difference, not "identical to the model".
- Coverage: `nearest()` always returns a zone; with F4–G5 chanter zones the whole
  modeled range 60–84 repitches within `step ∈ [0.5, 2.05]` (worst case ~5 st →
  step 0.75/1.33). So the model-free `LoopVoice` never hits `LaVoice`'s
  "return the bare model" escape hatch, because it never needs it.

**The sampled drone** (`BagpipeDroneSampled`, wrapping two `LoopVoice`s — as
`BagpipeDrone` wraps three `ReedPulse`s): bass = `drone_G2` repitched to
`tenor_f·0.5`, tenor = `drone_G3` repitched to `tenor_f`, where `tenor_f` follows
the §4a branch (`key_freq(key)` for a drone-control note, else `key_freq(key)·0.5`).
This is the real instrument's bass+tenor octave stack. Lifecycle composition:
`alive()` = either loop alive, `released()` = both released — which holds because
both receive `note_off` in lockstep from the one wrapper. Its release matches the
model's **0.22 s** (`voices.rs:8349`) so the phrase-boundary overlap and level are
identical to today. **There is no tenor pair and no beat** — the real G pipe has
one tenor, so BP-O2 (tenor-pair beat) is a *model* property that does not hold
here; it stays aimed at the model on the alt bank, and the sampled drone gets its
own oracle (octave-stack presence + continuity, §7.6).

## 5. Dispatch — two decisions that must agree

There are two independent spawn paths, and getting them to disagree is the main
correctness risk.

**Chanter** — `voices::make(109, …, samples)`. Split 109 out of the
`64..=67 | 109 | 111 => reed(…)` arm:
```rust
109 => if samples && crate::embedded_samples_available() {
    Box::new(sampler::bagpipe_chanter_loop(key, vel, sr, seed))
} else {
    Box::new(reed(109, key, vel, sr, seed))
}
```

**Drone** — `engine.rs::ensure_bagpipe_drone` (the only call site of the drone
factory; it never goes through `altbank`). It already has `&mut self`, so
`self.strips[ch].alt_bank` and `self.opt.samples` are in scope. Dispatch there:
```rust
let sampled = self.opt.samples
    && crate::embedded_samples_available()
    && !self.strips[ch as usize].alt_bank;
let voice: Box<dyn Voice> = if sampled {
    Box::new(voices::bagpipe_drone_sampled(key, vel, self.opt.sr, seed))
} else {
    Box::new(voices::bagpipe_drone(key, vel, self.opt.sr, seed))
};
```
`bagpipe_drone` stays **concrete and modeled** (so BP-O2 keeps testing the model);
`bagpipe_drone_sampled` is the new factory. Do not change `bagpipe_drone`'s
signature.

**The alt-bank arm is REQUIRED, not optional.** `altbank::make`'s fall-through is
`_ => voices::make(program, key, vel, sr, seed, samples)`. Today it is harmless
because `make`'s 109 arm ignores `samples`. The instant the chanter arm above
exists, the fall-through forwards `samples: true` and **CC0≠0 silently becomes
sampled — the modeled bagpipe becomes unreachable, the exact opposite of the
goal, with no test to catch it.** So add:
```rust
109 => crate::voices::make(program, key, vel, sr, seed, false),
```
This is the same idiom as the module's existing `24..=25`, `56..=61`, `68..=71`
freeze arms ("pin samples off so the default LA layer cannot reach alt-bank
channels"); it fits the charter, does not strain it.

The two decisions agree by sharing one rule: **sampled ⇔ (samples enabled ∧ not
alt-bank)**, applied to chanter (via `make`/`altbank::make`) and drone (at
`ensure_bagpipe_drone`) alike.

## 7. Acceptance criteria (the design's definition of done)

**Testing reality: no committed album writes GM 109** (verified — 0 of 99 MIDIs).
So the render-diff inventory (criterion 10) will show **zero diffs**, and cannot
validate this change. Acceptance rests on **direct voice/engine oracles** plus a
**synthetic 109 test MIDI** rendered through the engine — not album diffs. This is
the load-bearing consequence of the review, called out so the empty inventory is
read as *expected*, not as "not reached".

1. **Runtime seam** (operationalize the old "without clicking"): render a held
   sampled chanter and drone for ≥ 2 loop lengths **at fractional pitch ratios
   0.5, 1.37, 2.0** (not just near-unity — the wrap must hold under repitch);
   assert flat RMS (no decay) and a max sample-to-sample delta below the
   `testutil` click threshold across the wrap. Runtime counterpart to the offline
   gate (3).
2. **Alt bank (CC0≠0) and samples-off** match a **pre-change golden**: capture a
   hash of today's modeled-109 render *before* any code change; both the alt-bank
   and samples-off renders must equal that golden (not merely equal each other —
   two post-change modeled routes agreeing proves nothing about drift from what
   shipped). Guards the model against bit-rot and the mandatory alt-bank arm.
   Achievable because seeds are threaded args, so a new match arm can't shift them.
   Plus a **routing matrix**: only `samples-on ∧ default-bank ∧ embedded-assets`
   differs from the golden; every other cell (alt-bank, samples-off, and the
   `--no-default-features` no-embedded build) equals it.
3. **Offline seam**: every baked loop wraps with correlation ρ > 0.95 **and** a
   direct value+slope check on the final normalized, quantized WAV — the wrap
   increment `|data[0] - data[len-1]|` and first-difference continuity below
   threshold. (Pearson ρ is offset/scale-insensitive and can pass an anomalous
   boundary step; check the increment itself.) Build-time gate in `extract_loop`.
4. **Constant amplitude** (BP-O1 sampled sibling, `samples=true`): the sampled
   chanter is velocity-independent in amplitude. (Construction-guaranteed —
   `LoopVoice` ignores velocity — so this only catches a regression that *adds*
   velocity scaling. Kept, but not load-bearing.)
5. **Pitch** (`o_pitch_melodic_programs_sampled`, 109 added to `LA_PROGRAMS`): the
   sampled chanter holds f0 within ±30 cents at 0.5–1.6 s into a held note — a real
   test of loop pitch stability.
6. **Drone character** (sampled sibling of BP-O2): (a) energy at both the tenor and
   the octave-below bass; (b) a **drone-control note (key ≤ 54) sounds the tenor at
   the absolute key pitch**, not an octave below (guards the §4a branch); (c) the
   sampled **drone/chanter RMS ratio** sits near the modeled ≈1:2 (guards §4b
   balance); (d) continuous across chanter note boundaries — reuse the existing
   engine continuity test **run with `samples=true`** (today it is samples-off, so
   the sampled path must be explicitly exercised).
7. **No `set_pitch` warble**: CC1 on a 109 channel does not modulate drone pitch
   (Goertzel at drone f0 under CC1).
8. **Coverage extremes**: chanter and drone render finite, in-band audio at spawn
   keys **55, 81, 84** (the step-clamp path) and at output rates **44.1 k / 48 k /
   96 k** (the ratio-then-SRC order) — no panic, no silence, no wild pitch.
9. **Synthetic 109 fixture** (retained, committed): a small MIDI exercising
   sustained notes, zone boundaries, note release + retrigger, a drone-control
   note, and both bank states. Rendered through the engine, it is the substrate
   for criteria 1/2/6/8 — the replacement for the absent album coverage.
10. **Gate**: `cargo fmt --check`, `clippy --workspace -D warnings`,
    `cargo test --workspace` all green; `test_prepare` green.
11. **Render-diff inventory**: run for the record; **expected to be empty** (no 109
    album). Any non-109 album diffing would be contamination — a bug.

**Human gate (cannot self-verify — no ears):** one audition of the synthetic
fixture against the FreePats source recordings and the old model, to confirm the
"plausible real bagpipe" goal. The numeric oracles prove correctness; they cannot
prove *plausible*. Carried to Arthur at integration, not blocking implementation.

## 8. Residual risks

- **Loop repetition audible on an exposed solo drone** — mitigated by ~1.5 s
  length; if it bites, lengthen or add offline micro-variation. Not built in v1.
- **Repitch formant smear** beyond ~±3 st for an album far from G — bounded by the
  6-zone chanter spacing and the G2/G3 octave drone pair. An album in, say, D
  (chanter +7 from G) pushes chanter repitch to ~2–3 st off the nearest zone —
  acceptable; a truly distant key is a known limit, documented not solved.
- **Drone at a high chanter register** is `step`-clamped (§4a), so it sits slightly
  low of its ideal octave rather than smearing. Bounded pitch error, and arguably
  more authentic (real drones don't chase the melody up). If a future album makes
  it audible, fold the drone target into a fixed low octave instead — deferred.
- **Mid-phrase CC0 (bank) flip** on a live 109 channel leaves the latched drone on
  its spawn-time bank while the chanter switches — sampled drone under a modeled
  chanter, or vice versa. No album does this and back-compat is out of scope;
  documented constraint: **set CC0 before the channel's first 109 note.**
- **Chanter-loop repetition** at ~0.4 s — idiomatic chanter notes are short
  (grace-note articulated), so a held note long enough to reveal the loop is rare;
  if it bites, lengthen the chanter loop. Same class as the drone-wander non-goal.
- **Size**: +~550 KB in a **default-feature** embedded crate hits every consumer,
  including modeled-only-minded ones. Judged worth it for a whole new instrument;
  the `default-features = false` build is unaffected.
- **24→16-bit** at bake: source floor −63 dB (drone) is well above 16-bit dither;
  fine.

## 9. Decision log

- **Bake the loop offline, runtime = modulo wrap.** Because a plain wrap over a
  correlation-placed seam measured seamless (§4). Kills the report's "biggest
  structural gap" (`Zone` has no loop metadata) — we never need it. The
  alternative (runtime crossfade-at-wrap + loop points in `Zone`, touching every
  `bank!` site and `parse_wav`) is more code for no audible gain.
- **~~Our own correlation search, not the SFZ loop points.~~ REVISED after testing
  against the real files (2026-07-17):** a self-search — even a wide one — clears
  ρ>0.95 on only ~2 of 6 zones (drone_G3, F4, C5, G5 fail), because chanter reed
  cycle-to-cycle variation accumulates over a self-cut loop. Upstream's SFZ loop
  points, by contrast, give ρ 0.98–1.00 on 25/26 files (verified). So **parse the
  SFZ `loop_start`/`loop_end` (~10 lines of regex), use them, re-validate ρ per
  file, and self-search ONLY the one broken file (`D#5`).** The SFZ parser the
  original decision avoided is cheaper than a search good enough to beat expert
  points. `extract_loop` takes the SFZ points as its seed, not a blank search.
  (Alternative considered: much shorter chanter loops (~0.15 s, fewer periods →
  less accumulated drift) — but that trades loop quality for repetition audibility
  and still underperformed the SFZ points; rejected.)
- **Drone = bass+tenor octave stack from the two real drone files**, key-relative
  by repitch. Matches the real instrument and the model's structure; keeps the
  drone tracking the album's key.
- **BP-O2 stays on the model; sampled drone gets a new oracle.** The real G pipe
  has no tenor pair, so the beat is a model-only property — asserting it on the
  sampled path would be asserting a defect.
- **Alt-bank 109 arm is mandatory** (§5) — without it the goal inverts.
- **Equal-GAIN, not equal-power, if any crossfade is baked.** The loop material is
  phase-aligned, so equal-power sums coherently to a +2 dB bump; equal-gain
  measured transparent. (Likely moot — no crossfade needed — but recorded so it is
  not "fixed" wrongly later.)
- **`LoopVoice` has no model underneath** (unlike `LaVoice`). So it owns
  `released()`/`alive()` via its own `Adsr`, and guarantees zone coverage rather
  than relying on `LaVoice`'s model fallback.
