# HLD — XG drum-kit bank routing (CC0 = 127)

**Status: SELF-APPROVED**
(Adversarial review: 2 reviewers, survivors folded. External review: Codex
gpt-5.6-sol, refinements folded. No critical findings, no architectural fork.)
Date: 2026-07-18
Task: `task/20260718-TSK-HUM-xg-drum-bank-routing`
Author: Claude Opus 4.8 (1M)

## Goal (one line)

Make ferrosintesis honor the Yamaha-XG convention **bank MSB (CC0) = 127 → this
channel is a drum/rhythm part**, so extra XG drum channels render as percussion
instead of a misrouted melodic voice.

## Problem (evidence)

Reference file `test-corpus/reference-midi/mike-oldfield/04-incantations-part-iv-xg.mid`
(a gitignored XG fan-transcription) sounds correct until **2:42**, then degrades badly.

Root cause, confirmed from the MIDI stream and a render:

- At **t=162.4 s**, channel 14 (index 13) sends `CC0=127` then `program=16`. In XG
  that means "drum kit 16 (Rock kit) on this channel". The transcriber uses ch14 as a
  **second percussion part** — congas/bongos/vibraslap/shaker — alongside the main kit
  on ch10 (index 9). Note keys after 2:42 are `{58,61,62,63,64,82}` = exactly those
  GM/XG percussion instruments.
- ferrosintesis hardwires drums to **`ch == 9` only** (`engine.rs` note-on + both mix
  passes). It also treats **any non-zero CC0 as the "alt orchestral bank"**
  (`engine.rs:1615`, `alt_bank = val != 0`).
- So ch14's `CC0=127` sets `alt_bank`, program 16 has no alt-bank arm, and it falls
  through to `voices::make(16,…)` = **GM Drawbar Organ**. The conga hits on keys
  62/63/64 become a sustained organ hammering a **D4/Eb4/E4 semitone cluster**.

Render proof (built 0.21.20): ch13-solo at 2:48 shows sustained pitched energy at
Eb4/D4/D3 (organ, not percussion); the full mix jumps **+6 dB RMS** at the 2:40 break
and stays there, dragging the −18 LUFS balance toward the dissonant section.

## Scope

**In scope**
- Route a channel to the drum path when it selects an XG drum kit (`CC0 == 127`),
  not only when it is MIDI channel 10.
- Give such a channel its own dynamics (CC7/CC11/aftertouch) and pan, sent to the
  shared drum room — because the reference channel authors 435 CC11 expression events
  (range 46–127) that deliberately shape the congas.
- Keep the existing `ch == 9` drum channel and every committed album **byte-identical**.

**Out of scope (non-goals)**
- **Roland GS** rhythm-part assignment (done via SysEx `F0 41 .. 40 1x 15 F7`, not
  bank select). Different, larger change; note as possible follow-up.
- **Exact XG kit selection.** The XG kit program (16=Rock, 8=Room, 40=Brush…) is not
  mapped to a distinct ferrosintesis kit; XG-drum channels use the default V3 kit
  (ch9 today only distinguishes program 40 = Brush). Faithful-enough; a nicety, not
  the bug.
- **XG bank-LSB variations (CC32)** and XG effect SysEx — timbre nuance, already
  ignored, unchanged here.
- The reference file is gitignored test corpus: **no committed audio changes**; it is
  a manual before/after listening check only.

## Approach (chosen: "A2 — independent XG-drum sub-path")

Two hardwired rules must bend, and one must NOT:

1. **Which notes are drums** — currently `ch == 9`. Add: a channel is a drum part if
   `ch == 9` **or** its strip has `xg_drum` set (from `CC0 == 127`). Decided per note
   at spawn time and frozen on the voice (like the existing `alt` flag).
2. **CC0 handling** — `CC0 == 127` sets `xg_drum = true` and leaves `alt_bank` off
   (it is a drum-kit select, not an orchestral-bank select). Every other CC0 value
   keeps today's behavior exactly (`1`/`2` = alt bank; `0` = default).
3. **The ch9 drum-bus gain path stays literally untouched.** ch9's channel gain is
   baked into the bus master `g9 = strips[9].{vol·expr·at·breath}·DRUM_FORWARD`, with an
   optional drum-wide wah. Refactoring that to be per-channel (the "cleanest" option B)
   would change ch9's math and risk every album's render. Instead, **XG-drum voices
   take a small parallel path**: rendered in the drum pass, scaled by **their own**
   channel gain and pan (+ per-key `drum_pan`/`kit_balance`), and summed **directly into
   the master mix** with `DRUM_FORWARD`, their own CC91 reverb send, and the shared
   `ROOM_SEND` drum room. They do not pass through ch9's bus master or wah.

Why this shape: it fixes the catastrophic bug, preserves the reference channel's
authored conga dynamics/pan, and keeps ch9 + all albums byte-identical **by
construction** (their code path is unchanged; no album sends `CC0=127`, so the new
branch is never taken for album renders).

### File impact (all in `crates/ferrosintesis/src/engine.rs`)

- **Strip state**: add `xg_drum: bool` (init `false`).
- **`Active` state**: add `is_drum: bool` (set at spawn).
- **`cc()` CC0 arm (~1614)**: branch on `val == 127` → `xg_drum = true; alt_bank =
  false; alt_bank_value = 0`; else `xg_drum = false` + existing alt-bank behavior.
- **`note_on()` (~1487)**: compute `let is_drum = ch == 9 || self.strips[ci].xg_drum;`
  spawn `drums::make(key, vel, sr, seed, self.strips[ci].kit, samples, rr)` when
  `is_drum` (kit indexes by `ci`, which is `9` for ch9 → identical); set
  `Active.is_drum`; set the `program` sentinel to `128` when `is_drum` (~1554) — which
  also keeps poly-AT off it (`aftertouch_family(128) == false`).
- **Mix pass 1 (~2213)**: skip `a.is_drum` (was `a.ch == 9`).
- **Mix pass 2 / drum pass (~2361)**: gate on `a.is_drum` (was `a.ch != 9`); inside,
  keep the existing raw-accumulate-into-`drum_l/r` path for `a.ch == 9`, and add the
  parallel own-gain/own-pan → master-mix path for XG-drum voices.
  - **Borrow restructure (required):** the block currently holds `let s9 = &mut
    self.strips[9]` across the retain closure and derives `pan_off = s9.pan - 0.5` from
    it. The XG branch must read `self.strips[a.ch]` (shared) inside the closure, which
    conflicts with that live `&mut`. Fix: pre-copy `let pan_off = self.strips[9].pan -
    0.5;` (scalar, borrow ends immediately) **before** the closure, and take the
    `strips[9]` mut-borrow for the wah/`g9` **after** it. The closure's captures
    (`strips` shared; `scratch`/`drum_l`/`drum_r`/`mix_l`/`mix_r`/`send_rev`/`send_room`
    mut; `active` via `retain_mut`) are disjoint fields → compiles under 2021 capture.
  - **FP-association (required for the `assert_eq!` oracle):** ch9 forms `(scratch·ul)`
    into `drum_l`, then `·g9` into the mix. The XG branch must emit the **same tree** —
    accumulate `scratch·ul` then `·gc` — not a folded `ul·gc` coefficient, or bit
    equality with the ch9 path is lost (IEEE-754 non-associativity). `gc =
    strip.{vol·expr·at_gain·breath}·DRUM_FORWARD`, the same shape as `g9`.
- **Channel-aftertouch loop (~2116)**: add `&& !a.is_drum` to the `set_pitch` filter.
  Today it is inert on drums only because their `set_pitch` defaults to a no-op; the
  guard makes "a drum channel is a drum channel" real and restores symmetry with ch9
  (which skips the whole block). Byte-identical for albums (their non-9 voices have
  `is_drum == false`). The `at_gain` computation above it still runs, so XG-drum
  channels keep their aftertouch dynamics.

Everything else stays `ch == 9`: the hi-hat choke (main kit only), the melodic
pre-spawn features (legato/porta/tremolo/bagpipe — all gated by program/CC conditions
a drum channel never satisfies, hence inert), and the per-strip melodic loop (an
XG-drum channel's `ch_buf` is empty, so it contributes silence automatically).

## Acceptance criteria

1. **XG-drum routing (new unit test).** For a **single isolated hit** (so the
   compared paths don't diverge on FP associativity or overlap), key 62 on a non-9
   channel with `CC0=127`+`program 16` renders **byte-identical** to the same single
   hit on ch9 (`assert_eq!` — proves it takes the drum path at the same level/pan),
   AND differs from the same note+program without `CC0=127` (`assert_ne!` vs the
   Drawbar Organ). The bug-proof: a Goertzel probe at D4 (≈293.7 Hz, key 62) in the
   note's **late tail** shows the XG-drum render has ≪ the organ's sustained-pitch
   energy — the discriminator is *sustain*: the organ holds the tone, the conga
   decays (Codex's refinement; a raw D4 magnitude is weaker because a conga has some
   D4 attack energy too). Both `assert_eq!` renders use **separate `render()` calls**
   (two fresh engines), so seed/round-robin state can't cross-contaminate. Pin a
   comment: single hit only;
   `scratch·ul·g` association mirrors ch9 — do not fold, do not extend to overlapping
   voices (the byte-equality is deliberately association-sensitive).
2. **Alt bank intact.** `CC0 ∈ {1,2}` on a non-9 channel still selects the alt bank
   (existing alt-bank tests remain green — they are the regression guard for that path).
3. **Byte-identical albums.** The render-diff inventory over every `ALBUMS` entry
   (baseline = fresh `origin/main` build, vs this branch) reports **0 diffs**.
4. **Real-file check.** Rendering the Incantations reference: the 160–266 s region no
   longer holds a sustained organ; ch13-solo pitch energy at D4/Eb4 drops sharply and
   the region reads as percussion. (Manual/numeric; not committed.)
5. `cargo fmt --check`, `clippy --workspace --all-targets -D warnings`, and
   `cargo test --workspace` all green.

## Decision log

- **XG drum select = `CC0 (MSB) == 127`.** The XG standard drum-kit bank. `126` (SFX
  kit) is a note-mapped effects bank, *not* GM drums — routing it through `drums::make`
  would be wrong, so it stays melodic for now (add a dedicated path later if a corpus
  file needs it). Confirmed the default V3 kit voices every percussion key the reference
  channel uses — 58 vibraslap, 61 bongo, 62/63/64 congas, 82 shaker (`drums.rs` match
  arms) — so the fix produces real percussion, not silence/fallback.
- **CC0=127 commits immediately**, not deferred to the next Program Change (strict
  MIDI/XG commits Bank Select on the following PC). This matches the codebase's existing
  `alt_bank` convention (`CC0` toggles the bank the instant it arrives, `engine.rs:1615`),
  keeps the two bank paths consistent, and is correct for real files (they order
  `CC0 → PC → notes`, as the reference does). Deferring would add state for no practical
  gain (Codex noted this as pragmatic-but-not-strict; accepted).
- **Chose A2 (parallel XG-drum sub-path) over:**
  - **A (share ch9's bus):** simplest, but scales ch13's congas by `g9 =
    strips[9].{vol·expr·at·breath}·DRUM_FORWARD` — so ch9's fader **modulates, and at
    `expr→0` momentarily silences, ch13's congas**, while ch13's own CC7/CC11/AT do
    nothing. That is audio on one channel controlled by another channel's fader — a
    correctness smell, not merely lost fidelity (and ch13 authors 435 CC11 events).
    Rejected.
  - **B (de-entangle channel gain from the bus for all drums):** conceptually cleanest
    (removes the ch9 special-case), but rewrites ch9's gain path; byte-identical only
    if no album pairs a ch9 drum-wah (CC71/74) with ch9 expression variation — a
    guarantee traded for a "verify". Rejected: A2 keeps ch9 untouched and provably safe.
- **Per-note freeze of `is_drum`** (mirrors the existing `alt` flag): a mid-note CC0
  change affects only later notes — correct MIDI channel-mode semantics, and it avoids
  reclassifying already-ringing voices.
- **No new env vars / feature flags** (per brief): the behavior is unconditional and
  opt-in purely by the file's own `CC0=127`.

## Risks / residual

- XG-drum channels use the V3 kit regardless of the XG kit number (documented non-goal).
  Corollary: their per-channel aftertouch *gain* is gated on `aftertouch_family(kit
  number)` — true for kit 16 (Rock), false for kit 40 (Brush), so a Brush-kit channel's
  authored AT gain is ignored. Fidelity-only, matches the "kit not mapped" non-goal.
- **XG-vs-ch9 semantic divergences (accepted, documented):** an XG-drum channel is
  `ch != 9`, so unlike ch9 it (a) obeys CC64/CC66 sustain/sostenuto — a pedal would
  *defer* its drum note-offs (bounded: the voice decays and is reaped regardless, so no
  stuck/leaked voice), and (b) gets no hi-hat choke group (keys 42/44/46). Percussion
  channels author neither, and the reference file doesn't — not worth widening the diff
  to four more sites to gate on `is_drum`.
- If a real XG drum channel authored legato/porta/tremolo CCs, those melodic pre-spawn
  paths would still run (but are capability-gated — `legato_to`/`retrigger` default
  `false`, drums don't override — so they no-op on a drum voice). Not seen in practice.
- `drum_rr` round-robin is keyed by drum-key only, so ch9 and an XG-drum channel hitting
  the *same* key (here: 58 vibraslap, 82 shaker) share one variation counter. Benign
  (just interleaved sample variation); noted for awareness.
- Borrow-checker: confirmed feasible — pre-copy `pan_off` and move the `strips[9]`
  mut-borrow after the drum-pass closure (see File impact). Verified at implementation.
