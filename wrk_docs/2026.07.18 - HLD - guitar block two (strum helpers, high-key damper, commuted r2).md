## 2. Item 1 — strum/idiom helpers (composition side, Python)

**Landscape (scout-verified).** `strum()` exists (linear spread, ~40 call
sites); albums hand-roll stroke TABLES — Big Weather
`movements/t10_big_weather.py:288-300` drives strum() from `(beat, dur,
down, dv)` tuples with non-uniform beats AND per-stroke durations; hammer-ons
are `run(..., legato=True)` (CC68 bracket + overlap + velocity ramp —
diatonic-only); no playable-voicing logic exists anywhere.

**Home (D1, review-arbitrated).** `albums/fable5/The Remaining/engine.py` +
oracles in its `test_verify.py`, demo in `demos/guitar_idiom_demo.py`.
The panel's demo-local alternative was withdrawn in refutation: oracle-first
is load-bearing here and a demo file cannot host the unittest oracles. The
surviving condition is that this is a **stated seeding decision**: The
Remaining's engine.py is hereby designated the canonical copy-source for
future guitar-leaning albums — the helpers are deliberately unused there
(dead code with oracles, byte-identity pinned), an owned trade, not a silent
bet. (Evidence the copy chain needs the designation: the existing demo
imports the *older* Signal Fire engine; fixes have historically been fanned
across engine copies by hand.)

**API (additive, stdlib-only, times in beats):**

- `strum_seq(sc, ch, chord, t0, strokes, vel, sweep_span=0.10, rake=1.6,
  vel_up=-10)` — `strokes` = list of `(beat, dur, dir, dv)` with `dir` ∈
  `{'D','U','x'}` (down, up, muted chuck: very short, −25 vel). A first-class
  superset of the hand-rolled tables (per-stroke beat/duration/velocity are
  the axes the review proved a pattern-string loses — S-F2/D-F5-scope).
  Per-string onsets: `offset_i = sweep_span · (1 − (1 − t_i)^rake)`,
  `t_i = i / max(n−1, 1)` — concave for rake>1, so **gaps shrink toward the
  sweep's end** (strings bunch late, like a real pick sweep); reversed for
  up-strokes; per-string velocity taper as today's strum; n=1 guarded
  (I-M5). The concave form replaces v1's convex `t^rake` (S-F1/D-F7 —
  unanimous). **Unit note (Codex C7):** the parameter is deliberately named
  `sweep_span` — the WHOLE sweep duration — because the existing `strum`'s
  `spread` means the adjacent-string gap (Big Weather's `spread=0.025` = a
  0.10-beat sweep over 5 strings); duration law is explicit:
  `note_dur_i = dur − offset_i` (note-offs align, as today's strum).
- `voicing(root, quality, shape=None)` — playable 6-string voicings from a
  shape table over EADGBE. **Precise spec (Codex C6):** `root` = a MIDI
  pitch class 0–11; `quality` ∈ {"maj", "min", "7"}; shapes are stored as
  six-entry fret/mute vectors over EADGBE (−1 = muted string): open
  E/A/D/G/C forms plus E- and A-shape barres transposed by fret;
  `shape=None` auto-picks the playable form with the lowest bass note.
  Returns low→high MIDI pitches (4–6 strings) built from a valid
  one-note-per-string mapping.
- `run(..., pitches=None)` — one new optional parameter on the EXISTING
  legato helper: a chromatic pitch-list override for the diatonic
  base/mode/degrees path. Covers the hammer-on idiom the demo hand-rolls,
  without a second helper (S-F3 as modified: `run` was diatonic-only; a
  parallel `hammer_run` was ~90 % overlap).

**Oracles** (unittest, The Remaining's `test_verify.py`, fixed Score seed):
- `strum_seq` reproduces Big Weather's `_gtr_strum` table stroke-for-stroke
  (same onsets/durations/velocity deltas), with the equivalence call pinned
  explicitly (`sweep_span=0.10, rake=1.0, vel_up=0` — Codex C7) — the
  review's put-up-or-shut-up test for "supersedes the hand-rolled tables".
- Rake: offsets strictly increasing AND consecutive gaps non-increasing for
  rake>1; n=1 no crash, offset 0; `note_dur_i = dur − offset_i` law pinned.
- Direction: up-strokes reverse string order + apply `vel_up`; 'x' chuck is
  short (+quiet); per-stroke `dv` lands on every string of that stroke.
- `voicing` (tightened per Codex C6): every OPEN shape pinned exactly
  (expected fret vector and pitches); **all 12 barre roots** swept for both
  barre shapes asserting: 4–6 notes, pitch-class SET EQUALITY with the chord
  spec (no missing third — a vacuous subset cannot pass), valid
  one-note-per-string mapping, fret span ≤ 4, E2 floor, and low→high order;
  auto-pick octave pinned for the adversarial roots (Eb, F#) (S-F5).
- `run(pitches=...)`: CC68 bracket + overlaps + the exact pitch list; the
  diatonic path byte-unchanged when `pitches=None` (regression pin).
- Determinism: two builds → identical events.

## 3. Item 2 — high-key damper fix (synth side, Rust)

**Mechanism (scout-computed, review-refined).** Damper share of decay at
vel 100: steel E4 22 % → E5 61 % → E6 89 % (nylon 74 %/94 % at E5/E6);
per-trip loss × f0 grows ~f³. Fix: hold the damper *corner* up with key.

**The law (D3, insertion corrected per I-M1):** one new preset field,
default-inert:

```rust
/// Anchor Hz for the high-key damper hold (0 = off): above it the damper
/// corner grows as (f/anchor)^1.5 — derivation review-confirmed (one-pole
/// small-loss ≈ ½(f/fc)² ⇒ damper dB/s ∝ f³/fc², so fc ∝ f^1.5 holds the
/// DAMPER share flat; the max(1,·) kink is C0/rate-continuous — benign).
pub treble_hold_hz: f32,
```

Implementation point (the v1 spec was unimplementable — the sr·0.45 clamp
sits before `f` exists): fold the factor into the wound re-scale line
(`voices.rs:3640`), which gains a re-clamp:
`bright = (bright · (1−0.30·wound) · hold_factor).min(sr*0.45).max(300.0)`
with `hold_factor = max(1.0, (f/p.treble_hold_hz).powf(1.5))` behind a
`treble_hold_hz > 0` guard (unauthored presets take no branch →
bit-identical; GM56 FNV pin frozen). (Refutation note: the v1-feared tuning
drift from an unclamped corner was REFUTED — both `delay_for` and
`OnePole::lowpass` clamp internally at 0.49·sr — but the explicit re-clamp
keeps the corner semantics consistent anyway.)

**Authoring:** NYLON + STEEL at 500.0 Hz. **Honest post-fix numbers (D-F1
corrected):** the *damper share* is held ~flat; the *total* still climbs with
the t60 key-scale — steel k76/k88 ≈ −40/−49 dB/s, nylon ≈ −65/−67 dB/s at
vel 100 (inside the oracle band; real-guitar treble decay). **Known limits
(documented, review D-F2/D-F3/D-F4):**
- *Velocity:* the corner scales with the velocity law, so the fix's reach
  shrinks at low velocity (nylon k88 vel40 ≈ −160 dB/s persists). The decay
  oracle carries a vel-40 canary row with honest (wide) bounds so the limit
  is measured, not hidden; fully fixing velocity-coupling is out of scope.
- *Window:* bright saturates the sr·0.45 clamp at ~steel k86 / nylon k91;
  above that the f³ cliff resumes and the velocity→timbre law flattens. The
  working window (anchor ~k71 → ~k86, the top of a 24-fret neck) is
  accepted; the dry-out test keeps its `skip(1)` (D-F3 supports it).

**OUD authors an explicit 0.0** (inherits `..NYLON`; warm character);
**UKULELE inherits the hold** (same physics; its ratio tests probe key 60 —
below the anchor, unaffected). Inheritance graph verified exact: only
UKULELE/OUD use `..NYLON`. **Codex C4 additions:** `altbank.rs`'s frozen
`PIZZ` preset spells out EVERY field without `..DEFAULTS` — it will not
compile without an explicit `treble_hold_hz: 0.0` (file added to §5 impact);
and the authoring is pinned by cheap const asserts
(`OUD.treble_hold_hz == 0.0`, `UKULELE.treble_hold_hz == 500.0`,
NYLON/STEEL == 500.0) plus one active-range behavioral check (a high-key
OUD render must be bit-identical to a `treble_hold_hz:0` twin — proving the
opt-out where it matters, not just at key 60).

**Release-darkening scope decision (Codex C5):** `note_off` engages G6 —
the released damper glides toward its 600/700 Hz floor (~36 ms) — which
deliberately overrides any treble hold in release. That is G6's shipped
design (let-ring darkening) and this fix does NOT constrain it: the hold
governs the HELD note; released high notes stay G6-governed. Stated here so
"short strummed high notes still darken after note-off" is a documented
behavior, not a surprise; the audition stems include a short-note line to
judge it by ear. The decay oracle is correspondingly specified as
**model-only, HELD note** (no note_off in the measured window): f0-band
(±¼-octave bandpass) frame-RMS slope over 0.10–0.60 s, keys 76/88, seeds
{5, 21, 99} averaged, vel 100 band −80…−15 dB/s + the vel-40 canary row
with measured honest bounds.

**New coverage (I-M6: ADD, not restore — these rows never existed):**
(24,76) and (25,76) rows in `guitar_low_velocity_seam_continuity` and
`la_level_continuity` — vel-40 sub-rows measured first and scoped honestly if
the residual *physics* (not the wrap) trips them; new decay-band oracle:
steel+nylon keys 76/88 vel 100 within −80…−15 dB/s, plus the vel-40 canary
row. Close the scratchpad cliff entry.

**Rejected:** 1/|H| loop-gain compensation (DC-unstable lesson); global law
change; damper redesign; a no-field static bright bump (refutation A1: the
correction must be frequency-dependent — a static bump over-brightens the
fine low keys while still losing to f³ on top).

## 4. Item 3 — commuted excitation round 2

**Re-land (Codex C3 — the "one git apply" plan is dead):** Codex ran

**The corrected seed (D-F5 — the round's critical find).** v1's `(1−g)`
normalizer was wrong twice: it omits the in-loop damper (per-trip is
`g·|H(f0)|`, and the tail in the same function already models `|H|`), and a
truncated 0.12 s fold never converges — `(1−g)·Σ = 1−g^K`, which the lead
computed at ≈ 0.17 (−15 dB) at the PROBED key 52 (a refutation attempt using
g≈0.87 was arithmetic error; g at k52 is 0.9906). The fix, numerically
validated in refutation (`|H|` shifts the weight sum −0.03 dB at k52 but
−11.05 dB at k88, and makes the fold CONVERGE at high keys where plain g^k
is truncation-dependent):

**Upgraded in v3 to an OPERATOR fold (Codex C2):** a scalar `(g·|H(f0)|)^k`
weight is still not the loop's true per-trip operator — each harmonic m sees
`g·|H(m·f0)|`, and the failed round-1 metric was precisely the partial-
PROFILE. The fold therefore applies the loop's ACTUAL per-trip filter
(gain `g` × the same `OnePole::lowpass(bright)`) per fold pass, Horner-style
over the blocks (cost ~K·N one-pole taps at voice/cache build — trivial):

```
acc = 0
for k in (K-1 .. 0):  acc = S(acc) + block_k     // S = g · OnePole pass
period[i] = acc[i] / Σ_k (g·|H(f0)|)^k           // f0-level normalization
```

— the numerator carries each harmonic at its physical relative weight; the
scalar denominator sets the fundamental's level (validated in refutation:
converges at high keys where plain g^k is truncation-dependent). The fold
remains an approximation of the full plant (no fractional-delay/coupling
terms) — **explicitly classified a heuristic; the frozen gates are the
validator** (C2's alternative). The note-domain re-cancelled tail (round
1's working iteration) is unchanged.

**Gate population expanded, thresholds untouched (Codex C1):** round 1's
gates probed key 52 only while authorizing every zone/key. The UNCHANGED
parity/profile thresholds now also run at each bank zone's nearest MIDI key
(nylon 7 + steel 8 zones) plus key 88 — more rows, same preregistered bars.

**Gates — FROZEN, from round 1, unmodified and all RELATIVE** (verified: no
absolute thresholds; all probe key 52): 3-band seam parity ±2 dB; sustain
partial-profile strictly closer than burst; restrike re-excites +
byte-determinism; residual gate −12 dB; every guitar oracle; alt-bank
bit-identity; `--no-samples` builds. Budget: the normalizer above + at most
ONE nudge of `COMMUTED_GAIN` — **a scalar-only change; any mechanism change
is out of budget** (refutation A3's bright line). The refutation's honest
caveat stands: the weight-sum normalizer removes the dominant error by
construction but ±2 dB across zones is data-dependent (zone-to-zone envelope
variation) — that is precisely what the gate is for. Ship-or-repark; a
second park costs items 1–2 nothing.
