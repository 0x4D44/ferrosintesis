# 2026.07.19 - HLD - modeled synth drum kit (ch-10 Program Change 24)

## Problem
Three-Sixty-One (Through Lines T16) sounded better on the older **synth'd** drum
kit than on the newer **realistic (sampled)** kit that became the ch-10 default on
14 Jul 2026 (`ferrosintesis-samples-drumkit`). Arthur wants that track back on the
synth kit, added as a **selectable alternate** so the default is unchanged for every
other album. Reference point he named: the kit as it stood on Sun 12 Jul 2026.

## Why not a byte-exact 12-July restore
On 12 Jul the kit was modeled V3 voices **plus a light sampled *attack* overlay** on
kick/snare/crash. Reproducing those exact bits is disproportionate: the 3 orchestral
drum WAVs all changed since, `dsp.rs` drifted (+230 lines), and the old
`drum_kick_bank`/`SampleOverlay` machinery was **removed**. It would mean vendoring a
frozen copy of the old drum subsystem — duplicated shared DSP, permanent maintenance
cost. Measurement (Three-Sixty-One's drum channel, diff-signal RMS) shows the
**modeled path already recovers almost all of the character**: July-12 kit sits
~4 dB from today's sampled kit (huge) but only ~11 dB from today's modeled path.
Arthur chose the modeled synth kit.

## Design — `Kit::Synth`, selected by ch-10 PC 24
- **`Kit::Synth`** (crate-private `enum Kit`, no semver impact — `pub(crate) mod
  drums`) is the V3 modeled voicing with the **sampled drum-kit replacement layer
  switched off**. It is realized in `drums::make` by two lines at the top: force
  `samples = false` for the synth kit, then collapse the kit to `V3`. Every modeled
  arm is therefore shared with V3 and byte-identical to
  `make(.., Kit::V3, samples = false, ..)` — no `matches!` site can be missed, and
  the three `match kit` arms carry a grouped `| Kit::Synth` only for exhaustiveness.
- **Melodic LA sample layers are untouched** — they are gated by GM program on the
  melodic channels, not by `Kit`, so `--no-samples`'s blunt "kill everything" is
  avoided. Only the whole-mix drum-kit sample replacement is suppressed.
- **Selection**: ch-10 Program Change **24** (the GM2 Electronic slot) →
  `Kit::Synth`, mirroring the existing `40 → Brush`. `engine.rs` maps
  `match prog { 40 => Brush, 24 => Synth, _ => V3 }`. PC 24 is free: the keep-V3 test
  pins {0, 8, 16}, and a proper-parse scan of all 114 committed album MIDIs shows
  ch-10 authors only {0, 1, 16, 40} — none use 24. Any GM/GM2 file that requests the
  Electronic kit now gets the modeled synth kit, which is a reasonable (synthesized)
  reading of that slot.

## Three-Sixty-One
`t16_three_sixty_one.py` `program_changes` `(CH_KIT, 0.0, 1)` → `(CH_KIT, 0.0, 24)`;
`.mid` rebuilt. End-to-end proof: the rebuilt MIDI rendered with samples ON (as
`render-catalog` does), soloed to ch-10, is **byte-identical** to the same notes
rendered `--no-samples` — i.e. it now plays exactly the modeled synth kit.

## Verification
- `drums::tests::synth_kit_is_modeled_v3_never_sampled` — Synth == V3+no-samples for
  every key T16 plays; Synth != V3+samples for kick/snare/hats/crash (opts out).
- `engine::tests::channel_10_program_24_selects_the_synth_kit` — PC 24 differs from
  the sampled default and equals the samples-off modeled path.
- keep-V3 test unchanged (0/8/16 still V3).
- Album `build.py --verify`: all T16 oracles green.
- Inertness, proven two ways: (1) a running-status-aware parse of all 114 committed
  album MIDIs shows ch-10 authors only programs {0, 1, 16, 40} — none use 24, so no
  other album reaches the changed path; (2) a baseline-vs-new-binary solo-9
  render-diff confirms T16 changes (prog 24 → Synth) while its drum-heavy sibling
  T10 (prog 1 → V3) stays byte-identical. The `keep-V3` unit test independently
  pins programs 0/8/16 to unchanged V3 output.

## Not done (deliberately)
No version bump on the branch — the integration step owns the single bump. The
`.opus`/`.wav` renders are git-ignored build output; anyone who re-renders after this
change simply hears T16 on the synth kit.
