### The `--solo 8` saga — the best engineering in the window

Three commits, and the arc is the lesson. `85d215c` flushed any magnitude below `1e-20` and won
the 10.3× speedup (456 s → 44 s). The byte-transparency sweep caught it over-reaching into
shared primitives where near-unity-gain Karplus-Strong loops recirculated a 1-ulp delta into a
24-LSB drift, so `a2e6700` narrowed the flush to bus-owned state. That still left a 4.8 s,
≤2-LSB, −84 dBFS burst on one track that nothing explained — and the session **held**:

> *"no available mechanism accounts for it. Inaudible beyond doubt (−84 dBFS peak delta, 63 dB
> under the music), but un-understood ⇒ per the preregistered decision rule the unit stops here
> for Arthur's call."*

The resolution (`90f43f2`): **`1e-20` is a perfectly normal f32** — subnormals only begin at
~1.18e-38 — so flushing there zeroes ~14 orders of legitimate state and is not byte-transparent
however small it looks. Every f32 add's round-to-nearest is a discontinuity with one threshold
per ULP; the first exact sum straddling a boundary within the seeded δ≈1e-19 makes δ teleport to
a full 1-ULP jump, which `BusGlue`'s transient-displaced atk/rel branch then amplifies. The
journal names its own earlier error precisely: *"the amplifier is not a DSP feedback loop — it
is the rounding function itself."* Dropping the floor to `1e-34` keeps the perf win and cuts the
per-add tie hazard ~1e-12 → ~1e-26. The argument now lives as a doc comment at
`crates/ferrosintesis/src/dsp.rs:313-330`, with the guard-test floor pinned in lockstep at
`reverb.rs:431-432`.

Localisation method, worth copying: flush-site bisect on the **raw pre-normalizer f32 dump**,
not the WAV — the true-peak limiter smears a sub-LSB difference into a visible span and misleads
you.

A meta event (`0xFF`) or SysEx overwrites `status`. The next running-status data byte is then
