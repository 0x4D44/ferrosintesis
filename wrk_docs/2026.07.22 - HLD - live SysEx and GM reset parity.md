# HLD — live SysEx and GM reset parity (MM-BUG-KILN-00035)

**Status: SELF-APPROVED**

## Goal and scope

Make supported GM, XG, and GS System Exclusive messages mean the same thing
whether they arrive in a Standard MIDI File or through `RealtimeSynth`.

- Give GM System On its own decoded event and full GM-reset semantics offline,
  matching the existing live hard reset.
- Let the live parser recognize every fixed-shape SysEx event the SMF parser
  models: GM On, XG On, XG Effect1, GS Reset, and GS Rhythm Part.
- Share one payload decoder. Keep live capture bounded and allocation-free.

### Non-goals

- GM2/GM Off, more GS/XG parameters, checksum validation, or a public SysEx API.
- Sample-accurate live timing or the specification's post-reset wait.
- Changing the established XG-effects-only or GS-rhythm-only reset scopes.
- Assembling SysEx split across SMF `F0`/`F7` continuation events. Decode only
  complete `F0` events; continuation support is separate from entry-point parity.
- Preserving voice, channel, effect, or synth-clock state across GM On. Public
  whole-render statistics are preserved across the reset.

## Diagnosis

`midi.rs` aliases GM On to `EvKind::XgReset`, whose engine arm clears only XG
effects. `live.rs` emits `Reset(GmSystemOn)` for the same message and calls
`hard_reset()`. Its four-byte SysEx buffer overflows on every supported XG/GS
message. MIDI Association guidance describes GM On as restoring the full GM
initial state, so the existing live hard reset is the semantic anchor.

## Approach

### Shared payload decoder (`midi.rs`)

- Add `EvKind::GmReset`; retain the existing XG/GS event types.
- Factor `decode_sysex_payload(&[u8]) -> Option<EvKind>`. Its input excludes `F0`
  and `F7`. The SMF parser calls it only for a complete `F0` event whose payload
  ends in `F7`; standalone `F7` escape/continuation events stay ignored.
- Match an explicit shape table: GM On = 4 bytes, XG On = 7, XG Effect1 = 7 or
  8, and GS Reset/Rhythm = 9. Reject other lengths, missing required values,
  extended prefixes, and any high-bit payload byte.
- Sort `GmReset` before every other event at the same tick, then retain original
  sequence order. Format-1 track layout must not let a later-track GM reset erase
  simultaneous bank/program/controller setup.

### Bounded live routing (`live.rs`)

- Use a named nine-byte capacity, the longest modeled payload excluding `F0/F7`.
  Mark longer messages overflowed and ignore them at termination.
- At `F7`, call the shared decoder once and route every decoded event, including
  `GmReset`, as `Channel(EvKind)`. Only raw `0xFF` remains a live-only Reset
  command; GM now converges on `EngineCore::handle_event` by construction.
- `F8..FE` remain transparent inside SysEx. `FF` emits System Reset and clears the
  partial message. Any other status aborts malformed SysEx and is reprocessed as
  the new status, so channel traffic cannot be swallowed or form a false reset.

### One GM semantic (`engine.rs`)

- Add `EngineCore::gm_system_on()` which saves cumulative `Stats`, delegates to
  `hard_reset()`, then restores `Stats`. This retains constructor-backed coverage
  of all synth state while honoring the public whole-render statistics contract.
- Decouple deterministic seed position from public `Stats::voices_spawned` with a
  private counter that follows the existing seed-consumption sites. It resets with
  the constructor, preserving current live GM-reset audio semantics, while public
  totals remain cumulative across an offline render.
- Route `EvKind::GmReset` through `gm_system_on()`. Raw System Reset and public
  `RealtimeSynth::reset()` remain direct hard resets.
- The offline render loop owns the SMF event cursor independently, so a mid-file
  reset restarts synth-local state without rewinding file playback.

## Acceptance criteria

1. Complete SMF `F0...F7` events yield `GmReset`, `XgReset`, `XgEffectParam`,
   `GsReset`, and `DrumMode`; unterminated, standalone-`F7`, high-bit, malformed,
   and extended near-misses yield none. In format 1, GM reset precedes all other
   same-tick events even when stored in a later track.
2. The same wire payloads yield corresponding live commands, including XG
   Effect1 and GS rhythm on/off. `F8..FE` are transparent; `FF` resets; another
   status aborts malformed SysEx and is processed normally.
3. GM On from either entry path stops voices and restores fresh GM programs,
   controllers, bend/RPN state, GS rhythm flags, and XG effects while preserving
   cumulative `Stats` (total voices, peak, and maximum polyphony).
4. XG On remains effects-only; GS Reset remains GS-rhythm-state-only.
5. Unsupported/overlong SysEx stays bounded, emits nothing, and recovery is green.
6. The required render-diff inventory is a no-regression check expected to be
   fully byte-identical because the catalog has no modeled GM-reset use; synthetic
   parser/core/render fixtures provide the behavioral evidence.
7. `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
   and `cargo test --workspace` pass with stdin closed and bounded runtimes.

## Decision log

- **Dedicated `GmReset`:** GM and XG reset scopes differ; the alias is the defect.
- **Reuse hard reset but preserve `Stats`:** constructor-backed reset cannot omit
  newly added synth state, while diagnostics still describe the whole render.
- **One `GmReset` event route:** only raw System Reset needs the live-only reset
  lane. Shared `handle_event` routing prevents this semantic split recurring.
- **Separate private seed position:** GM reset keeps current live reseeding while
  `Stats` continues to describe the complete offline result.
- **GM reset wins same-tick ordering:** reset establishes defaults; simultaneous
  authored setup must then override them regardless of format-1 track order.
- **Nine bytes, not `Vec`:** modeled payloads are fixed and live state stays bounded.
- **Exact shapes:** prefix matching can turn corrupt manufacturer data into resets.
- **No SMF continuation assembler:** recognizing complete modeled messages fixes
  this bug. Correctly ignore standalone `F7` data; defer multi-event assembly to a
  separately scoped parser change.

## Adversarial review record

Three independent reviewers critiqued reset semantics, parser safety, and test
altitude, then each received the combined findings for refutation.

Surviving findings folded above:

- Preserve cumulative public `Stats` around GM reset; continuous
  `voices_spawned` deliberately keeps seed chronology continuous.
- Decode only complete SMF `F0...F7` messages and never standalone `F7` data;
  reject high-bit payload bytes.
- Abort and reprocess a non-realtime status inside malformed live SysEx.
- State the `F8..FE`/`FF` distinction explicitly.
- Use lean regression strata: shared decoder tables, one table-driven live
  routing/recovery test, one direct core state-and-Stats reset test, and one
  offline mid-file parse/render case.

Partially rejected: a full SMF `F0`/`F7` continuation assembler is correct future
work but not required for fixed-message parity. It would broaden this low-severity
bug into new parser state and tests; incomplete/standalone packets are safely
ignored instead.

## Cross-family review record

One fresh Claude Opus review ran read-only in plan mode with no subagents.
Significant/useful findings folded above:

- prioritize GM reset before same-tick setup across format-1 tracks;
- converge live and offline GM on the same `EvKind`/`handle_event` path;
- preserve public `Stats` without coupling post-reset seeds to diagnostic totals;
- spell out XG Effect1's 7-or-8-byte shape and update contradictory XG/GM comments;
- describe render-diff honestly as inertness evidence, with synthetic behavior
  oracles carrying the change;
- record the intentional hard-cut and live allocation risks.

Rejected with rationale:

- Clearing offline running status around SysEx is valid hardening for malformed
  files but predates and does not cause bug 35; keep this fix scoped to modeled
  SysEx recognition/reset parity.
- Replacing constructor-backed live reset with an in-place, allocation-free reset
  is a broad realtime-engine redesign. GM On already takes the hard-reset path
  today, so this change does not introduce that callback allocation.
- A seam-click oracle conflicts with the established hard-reset contract: voices
  and effect tanks stop immediately. The hard cut is recorded as intentional.

## Residual risks

- GM On will now change any SMF that sends it after mutating state. That is intended,
  but the catalog inventory must expose the exact blast radius.
- New modeled SysEx shapes may require increasing the named capture capacity.
- Live GM On and raw System Reset rebuild the engine inside `fill_ring`, including
  allocations. This is pre-existing realtime behavior and remains a deadline risk.
- GM On intentionally hard-cuts voices and effect tails; a mid-stream sender may
  create a discontinuity and should observe the normal post-reset quiet interval.
- Complete-message-only SMF decoding narrows two malformed/non-modeled cases the
  old prefix parser accepted: unterminated `F0` and standalone `F7` payloads.
