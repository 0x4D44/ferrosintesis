# 2026.07.22 — M-CAL v3 reference-PANEL derivation report

Supersedes the single-reference report of the same date for ship decisions.

A single reference cannot tell you whether IT or ferro is the outlier. This run adds a
second, independent reference — the Yamaha S-YXG50 (software wavetable) alongside the Roland
SC-55mkII (ROM sampler) — chosen because their patch-level quirks should be uncorrelated
(different vendor, era and synthesis). The repo already trusts this pair: the velocity-law
calibration fit k=1.997 on the SC-55 and 1.981 on the S-YXG50 independently.

**Gate:** a trim is auto-shipped only where the two references AGREE with each other (within
3 dB) AND the guards are clean on both. Where they disagree there is no consensus GM answer
for that patch, so it goes to a listening decision instead.

**Why this matters concretely:** on single-reference evidence GM11 vibraphone was heading for
a +6 dB boost. The panel splits 10.8 dB on it (SC-55 +6, S-YXG50 -2), so it is now withheld.
GM38 synth bass (-6) likewise. Auto-ship dropped from 8 programs to 5.

Reproduce with:

    /c/apps/mdmidiemu.exe _cal/probe_chunkN.mid --wav _cal/yxg_chunkN.wav --synth syxg50 \
        --dll /d/language/mdsc55/mdmu80-syxg50-helper/assets/syxg50.dll
    ./target/release/examples/calmeter.exe _cal/yxg_chunkN.wav _cal/plan_chunkN.tsv syxg50
    python tools/instrument-balance/derive_trims.py _cal/ferro_full.levels.tsv \
        _cal/sc55_full.levels.tsv _cal/yxg_full.levels.tsv

`int_F` is where ferro places the program in ferro's OWN balance (self-referential, so blind
to a uniform whole-synth offset — a third, weaker signal, useful for spotting defects the
panel cannot see, e.g. GM7 clavinet at -18 dB).
