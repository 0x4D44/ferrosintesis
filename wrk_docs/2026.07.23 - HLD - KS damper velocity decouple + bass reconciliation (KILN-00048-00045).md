# HLD — decoupling velocity from the KS loop damper (KILN-00048) and reconciling the bass family (KILN-00045)

Consultant: Fable (DSP specialist). Read-only consult; all decisions and implementation remain with the lead. Line numbers refer to trunk `aadcd57`.

## 1. Diagnosis — confirmed, with the mechanism

The primitive is right, and dimensionally it's the only one that works.
- The in-loop damper (`KsLoop.damp`, OnePole at `bright`, voices.rs:3472) is applied ONCE per round trip, and the loop makes `f` trips/s. Its corner sets a RATE: loss ≈ 4.343·(f_partial/fc)² dB/trip × f trips/s. Any factor on `fc` is a factor on dB/s — a TIME property.
- The excitation lowpass (`pick_lp`, applied once to the one-period burst, voices.rs:4096-4112) and `out_lp` (outside the loop) are applied ONCE. Their corners set a SPECTRUM — a LEVEL property, zero effect on decay rate.

Velocity is physically level/spectrum (how hard the string is displaced), never rate (string/bridge/air do the damping). Today `bright` (voices.rs:4033) serves both, so velocity leaks into rate. Measured GM35 key60: 661 dB/s @vel32 vs 144 @vel127; once KILN-00042 lets those notes sustain, the rate leak becomes level slope in the LUFS fit window and bends GM33/35 to k=2.38/2.62.

Composition with KILN-00042: the decoupling COMPLETES the hold. Today `fc = V(vn)·J·B_w·max(min_corner(f,A)/B_w, 1)` with `V(vn)=0.22+0.98·vn`, `J`=±8% jitter, `B_w`=static post-wound bright, `A`=60/t60_static. The hold multiplier is derived from the STATIC corner but multiplies the VELOCITY-scaled corner — so at vel40 the realized corner ~0.53×min_corner, damper decay share ~3.5× the KS_DAMP_BUDGET=0.30 (the documented vel-40 canary). After decoupling the budget holds at EVERY velocity, crossover is exact, and `min_corner()`/`corner_scale()` need ZERO changes — only the base they multiply changes from velocity-scaled to static.

Honest cost: the COMPOUNDING character (soft note dulls faster in its ring) is a genuine loss of one velocity-timbre mechanism; today's `velocity_opens_pluck_timbre` contrast (STEEL 1.30 vs floor 1.25 — 0.05 margin) is partly supplied by it. Compensation must be calibrated, not assumed (§2, Tripwire 1).

## 2. Decoupling design (KILN-00048)

### 2.1 Anchor the loop corner at the vel-100 value, per preset
Replace voices.rs:4033:
```rust
// today
let bright = (p.bright * (0.22 + 0.98 * vn) * (1.0 + 0.08 * rng.white())).min(sr * 0.45);
// proposed
let vn_anchor = if p.vel_sense >= 1.0 { KS_ANCHOR_VN }
                else { 1.0 - p.vel_sense * (1.0 - KS_ANCHOR_VN) };
let v_timbre  = 0.22 + 0.98 * vn;          // velocity→timbre factor, unchanged
let v_anchor  = 0.22 + 0.98 * vn_anchor;   // …at the anchor velocity
let bright = (p.bright * v_anchor * (1.0 + 0.08 * rng.white())).min(sr * 0.45);
```
`pub(crate) const KS_ANCHOR_VN: f32 = 100.0 / 127.0;`

Anchor at vel100 (not 1.0): every vel-100 render becomes BIT-IDENTICAL (`v_anchor` is the same IEEE f32 expr the old code computed for vn=100/127, incl. the `vel_sense` branch per compressed preset). Keeps green without re-pinning: `damper_hold_preserves_instrument_identity`, `sustain_holds_high_notes` (00049 constraint, §2.4), `v2_untouched_pluck_signatures_are_stable`, both KILN-00042 oracles at vel100, every vel-100 golden. Only non-100-velocity renders move — exactly the intended set. Keep rng draw order (pos → bright-jitter → t60-jitter) so seeds stay aligned. The hold computation (voices.rs:4081-4084) is byte-unchanged; retrigger's spawn_bright restore inherits the static corner (physically right).

### 2.2 Transfer the removed factor onto the excitation
```rust
let t = v_timbre / v_anchor;                       // ≡ 1.0 exactly at vel100
let pick_lp = (p.pick_lp * (0.10 + 1.30 * vn) * t.powf(KS_EXC_VEL_TRANSFER)).max(200.0);
let out_lp  =  p.out_lp  * (0.30 + 0.95 * vn) * t.powf(KS_OUT_VEL_TRANSFER);
```
γ=`KS_EXC_VEL_TRANSFER`, δ=`KS_OUT_VEL_TRANSFER`, both initial 1.0. At γ=δ=1 the product of all velocity-scaled corner factors is preserved (pick ratio ff/pp 3.26→8.29, replacing damper's lost 2.54), so first-order spectral tilt vs velocity (what centroid oracle + K-weighted LUFS slope see) is preserved; only the defective rate coupling is deleted.

Two floor interactions:
- Wound basses pick_lp-floor-pinned at pp: BASS vel30 → 200 floored to 300, so pick_lp transfer is INERT for BASS pp. The pp darkening must come from OUT_LP transfer (604→275 Hz @δ=1) — why δ is separate. Fallback: lower wound floor 300→~150 for pp (physically fine), but try δ first.
- Unwound (STEEL/NYLON, no out_lp): γ is the only knob. STEEL pp: pick_lp 2442→1111 Hz @γ=1, clear of floors.

Calibration (measured, never picked — the `velocity_census` pattern): add an `#[ignore]` dev test printing, per ALL_PLUCK_PRESETS member, the `velocity_opens_pluck_timbre` centroid ratio (vel120/30, 0.25s window, 3 seeds) at γ,δ∈{0.8,1.0,1.2,1.4}. Pick smallest γ/δ giving STEEL≥1.28 and bare-BASS≥1.15 (0.03 over the 1.25/1.12 floors). If γ≤~1.6 can't reach → Tripwire 1.

Everything else velocity-scaled stays (all once-applied): sub weight (1.25−0.5·vn), kick 0.4+0.6·v, clicks/attack-noise, SynthBass depth sweep.

## 4. Oracle designs

### 4a. Decay-rate velocity invariance at fixed key
1. Structural: `ks_loop_corner()` takes no velocity (§2.3).
2. Rendered (guards loop_gain, coupling, drive):
```
for p in {BASS*, FRETLESS*, STEEL, NYLON}:   // *sub/kick/mwah/attack_noise-stripped twins
  for key in {34 (basses) | 60, 76 (guitars)}:
    r(vel) = mean over seeds {5,21,99} of band-slope, where
      band-slope = 20·log10( band_rms[0.90..1.05s] / band_rms[0.45..0.60s] ) / 0.45
      band = f0 ± ¼ oct
    for vel in {32,64,127}: assert |r(vel) − r(100)| ≤ max(0.15·|r(100)|, 1.5 dB/s)
    // second clause where old defect was 4.6×:
    same with band = 3·f0 ± ¼ oct, tol max(0.20·|r(100)|, 2.5 dB/s)
```
Why not single-slope: ferro's plucked decay is FRONT-LOADED (vertical polar dies at 0.42·t60; damper eats HF early; one-shots salt onset) so a whole-note fit LIES. Both windows past 0.45s (settled). Band-limit to f0 (and 3f0) removes "which partials died" confound; energy-average across seeds BEFORE the log. STRIP `sub` via a test twin (sub:0.0): the sub is an f0-locked sine with velocity-dependent weight decaying at t60·0.8 — unstripped it manufactures the exact vel-dependent f0-band slope the oracle forbids. Exclude DRIVE/DRIVE_LEAD (engine Drive tanh makes decay legitimately level-dependent). Fail-first: red today for STEEL key60 (11.9 dB/s @127 vs 20.8 @32 = 1.75× f0-band spread) without touching a preset; green with §2.

### 4b. Within-family level-spread bound (~9 dB)

    render make(p,key,vel,sr,seed,true) held 1.35s (no note_off);

## Implementation amendments (2026.07.23, post-implementation — lead: Opus, with two Fable mid-flight corrections)

The §2 design landed, but two bugs in the transfer formulation surfaced during
implementation and were corrected by Fable on re-escalation. Recording them so the
design above is read WITH these.

**A. §2.2's "product preserved at γ=δ=1" claim is FALSE for dual-filter presets.**
Applying `t^γ` to `pick_lp` AND `t^δ` to `out_lp` in series is `t²`, one extra factor
of `t` of pp darkening. Correct for STEEL/NYLON (no `out_lp`) and the wound basses
(pick floor-pinned, only δ live) — which is why the first suite checks were green — but
WRONG for koto/shamisen (both filters active, neither floored), over-darkening their pp
and over-flattening their windowed velocity law. **Mechanism correction:** `out_lp` is a
post-loop OUTPUT filter on an already-amplitude-normalized signal, so it is primarily a
LEVEL term (opening it raises transmitted K-weighted level, amplified by the +4 dB BS.1770
shelf), not a pure timbre term. The double-application's out-swing was ACCIDENTALLY feeding
the level metric in the passing direction; removing it (correct for timbre) makes the honest
windowed law flatter, needing MORE compensation — the opposite of the §2.5 "toward 2.0"
prediction. Fix: **single-application transfer** — route `t` onto `pick_lp`, spill only the
floor-truncated share onto `out_lp`.

**B. The shortfall denominator must also be floored at 300.** A pre-decouple clip (the dark
wound basses, whose no-transfer pp pick already sits below 300 and were voiced around that)
must not be double-counted onto `out_lp`. Fix: `delivered_t = pick_want.max(300) /
pick_base.max(300)`, `out_lp *= (tᵞ / delivered_t)ᵟ`. Verified: unfloored→out×1; fully
floored→out×t (the wound-bass behaviour); partial→only the truncated share; bit-identical at
vel 100.

**C. Tripwire 2's 2.2 red line → a machine-checked [1.5, 2.35] bound.** A Pluck's excitation
is level-exact (∝v), so `e−2` is the onset-law distortion the compensation buys; 0.35 = the
reference hardware's own worst per-patch spread. `pluck_vel_level_exp_within_anti_papering_
bound` (velocity_law.rs) enforces it. Past the bound, fix the voicing, never the table.

**D. Koto (item 4) landed.** `KS_PICK_F0_FLOOR` = 2.2: `pick_lp.max((c·f0).min(pick_base))
.max(300)` — the c·f0 truncation NOT routed to out_lp. Lifts koto census k60 1.223→1.351,
shrinks spread 0.269→0.141; bound-capped e=2.35 lands it k48 1.93 / k60 1.79 (documented
Pareto-frontier residual). No other preset moved off-law at c=2.2 except PICK's low-vel pp
(a minor generic-physics brighten, folded into §3).

**E. The §2.6 bass flip is DEFERRED to §3 (KILN-00045), not landed in 00048.** Flipping
BASS/FRETLESS to `Derived` (tried) makes them ring long enough to expose a velocity-KEY-
dependent sub/mwah LEVEL bend a scalar `VEL_LEVEL_EXP` cannot fit — FRETLESS spread 0.58,
no exponent lands both keys in ±0.25. That bend is §3's exact domain (Tripwire 2's sub
suspect), and the final landing sequence groups the flip WITH §3. So 00048 delivers the
DECOUPLE — proven directly by `ks_decay_rate_is_velocity_invariant` (the rendered decay-rate
oracle, which covers BASS/FRETLESS and is green with them `Off`) — and the flip + §3
key-dependence fix land together in KILN-00045. The KILN-00048 defect (velocity coupled into
decay rate) is fixed regardless of the hold state.
