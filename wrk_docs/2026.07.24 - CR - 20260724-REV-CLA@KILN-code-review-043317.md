## Confirmed findings

### CR-1 — Realtime prewarming omits both CC-BY banks

- **Severity:** High
- **Confidence:** High
- **Where:** `crates/ferrosintesis/src/sampler.rs:660-707` and `:2421-2469`;
  `crates/ferrosintesis/src/live.rs:207-213`; call sites
  `crates/ferrosintesis/src/voices.rs:12170-12182` and `:12415-12427`
- **Tracked as:** `MM-BUG-KILN-00059`
- **Problem:** `RealtimeSynth::prewarm_samples()` promises to decode lazy attack
  banks off the audio thread, but `sampler::prewarm()` calls neither
  `rhodes_bank()` nor `dulcimer_bank()`. The first sampled GM 4 or GM 15 NoteOn is
  handled inside `RealtimeSynth::fill_ring()` and initializes the omitted
  `OnceLock<Vec<Zone>>` there.
- **Concrete impact:** Rhodes parses 11 WAVs into 440,462 `f32` samples
  (1,761,848 heap bytes); dulcimer parses 9 into 358,442 samples
  (1,433,768 bytes). That one-time decode and allocation occurs on the
  deadline-bearing callback despite an explicit API contract intended to prevent
  it. The exact dropout duration is unmeasured because this review did not run the
  app; the contract breach and callback work are statically confirmed.
- **Fix:** register both banks in `prewarm()`. Replace or strengthen the
  no-panic-only test at `live.rs:885-888` with a coverage oracle that proves every
  lazily decoded, realtime-reachable bank was initialized. A central registry is
  preferable because the hand-maintained list has drifted more broadly.
- **Effort:** Small–medium.

### CR-2 — The shipped consumer licence guide omits this required CC-BY notice

- **Severity:** Medium
- **Confidence:** High
- **Where:** dependency wiring at `crates/ferrosintesis/Cargo.toml:32-37` and `:72`;
  incomplete licensing inventory at `crates/ferrosintesis/README.md:191-221`;
  required credits at `crates/ferrosintesis-samples-ccby/NOTICE:4-15`
- **Tracked as:** `MM-BUG-KILN-00060`
- **Problem:** the default `ferrosintesis` feature embeds
  `ferrosintesis-samples-ccby`, and the asset crate says consumers normally reach
  it through `ferrosintesis`. The parent README presents an inventory of non-CC0
  banks and their required notices, but omits the Rhodes/dulcimer crate and both
  credited authors. The parent package includes only its own README and
  MIT/Apache licences; it does not carry the dependency's `NOTICE`.
- **Impact:** a downstream binary distributor following the shipped parent
  documentation can miss required attribution. This is a compliance risk, not a
  claim that the current asset crate's own notice is invalid.
- **Fix:** add this bank, its authors, and its CC-BY notice to the parent licensing
  guide. Explicitly tell binary distributors which third-party notices they must
  reproduce; a consolidated generated third-party notice would reduce recurrence.
- **Effort:** Small.

### CR-3 — Login-gated licence evidence is cited but not retained

- **Severity:** Medium technical/compliance debt
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-ccby/PROVENANCE.md:3-4` and `:11-19`
- **Tracked as:** Draft requirement `MM-REQ-KILN-00029`
- **Problem:** `PROVENANCE.md` says the CC-BY status was confirmed in each
  Freesound pack's bundled `_readme_and_license.txt`, while also documenting that
  downloads require a login. No such manifest is tracked anywhere in the
  repository; `tools/ferrosintesis-samples/freesound-src/` contains only WAVs.
  Maintainers therefore cannot audit the cited evidence offline.
- **Fix:** retain the two original licence manifests, or immutable metadata
  snapshots carrying sound/pack IDs, authors, licence, source URL, and a content
  hash, then link them from `PROVENANCE.md`.
- **Effort:** Small.

### CR-4 — Generated asset tests do not bind filenames to content

- **Severity:** Low
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-ccby/src/lib.rs:101-134`; filename-specific
  roots at `crates/ferrosintesis/src/sampler.rs:660-707`
- **Disposition:** CR report only; no bug or requirement.
- **Problem:** the generated tests pin the filename set, aggregate bytes, and
  RIFF/WAVE magic. Nineteen files have the same byte length, so swapping two valid
  payloads preserves every crate-local assertion while the consumer continues to
  pair each filename with its old measured root. Existing sampled-render tests
  exercise only a subset of zones semantically.
- **Fix:** have `tools/ferrosintesis-samples/gen_crate_lib.py` emit an independently
  pinned per-file content manifest or digest, and validate it by filename. The same
  generated test should validate the complete PCM/chunk contract.
- **Effort:** Medium across the generated asset-crate family.
