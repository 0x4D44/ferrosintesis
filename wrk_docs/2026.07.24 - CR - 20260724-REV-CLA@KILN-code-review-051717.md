## Confirmed findings

### CR-1 — Realtime prewarming omits both electric-bass banks

- **Severity:** High
- **Confidence:** High
- **Where:** `crates/ferrosintesis/src/sampler.rs:617-657` and `:2421-2469`;
  `crates/ferrosintesis/src/live.rs:207-213` and `:272-289`;
  `crates/ferrosintesis/src/voices.rs:12520-12576`
- **Tracked as:** existing Open bug `MM-BUG-KILN-00059`
- **Problem:** `RealtimeSynth::prewarm_samples()` promises to decode lazy sample banks
  away from the audio callback, but `sampler::prewarm()` calls neither
  `finger_bass_bank()` nor `pick_bass_bank()`. First use initializes them while a pending
  NoteOn is handled inside `fill_ring()`.
- **Concrete impact:** first GM 33/35 use parses six WAVs into 240,252 `f32` samples
  (961,008 heap bytes); first GM 34 use parses seven into 280,294 samples
  (1,121,176 bytes). Both banks together allocate 2,082,184 PCM bytes, plus metadata,
  inside a deadline-bearing path. The exact dropout duration is unmeasured.
- **Fix:** add both banks immediately, then replace the drifting hand list and
  no-panic-only test at `live.rs:885-888` with coverage proving every
  realtime-reachable lazy bank is initialized.
- **Effort:** Small for the calls; medium for the durable registry/oracle.
- **Dedup decision:** `MM-BUG-KILN-00059` explicitly requires complete bank coverage
  and warns of other later-bank omissions. A bass-specific file would duplicate its
  root cause and fix.

### CR-2 — The repitch guard includes sample-rate conversion

- **Severity:** Medium
- **Confidence:** High
- **Where:** `crates/ferrosintesis/src/sampler.rs:2762-2766`; correct sibling order at
  `:2320-2326`, `:3145-3151`, and `:3407-3413`; public rate builders at
  `crates/ferrosintesis/src/engine.rs:1708-1731` and
  `crates/ferrosintesis/src/live.rs:58-78`
- **Tracked as:** `MM-BUG-KILN-00061`
- **Problem:** `LaVoice::build()` checks
  `(target/root) * (44100/output_rate)` against the musical repitch range
  `0.5..=2.05`. Output rate therefore shifts the sample's active key window.
- **Concrete impact:** at 96 kHz the GM 33/35 E1 root note computes about `0.459` and
  silently becomes model-only; GM 34 E2 does the same. Conversely, an E3 repitch from
  the E2 pick zone can engage despite exceeding the intended musical range. The default
  voice identity changes solely because a caller selects a common professional audio
  rate.
- **Fix:** validate `ratio = target/root`, then apply source-rate conversion when
  calculating playback step. Add samples-on/off engagement and pitch checks for GM
  33–35 at 44.1, 48, and 96 kHz.
- **Effort:** Small.

### CR-3 — A warm extracted cache bypasses the documented archive hash

- **Severity:** Medium
- **Confidence:** High
- **Where:** `tools/ferrosintesis-samples/prepare.py:1095-1119`, `:1128-1133`,
  `:2493-2495`, `:2653`, and `:2680`;
  `crates/ferrosintesis-samples-bass/PROVENANCE.md:9-14`
- **Tracked as:** `MM-BUG-KILN-00062`
- **Problem:** `ensure_archive_sources()` returns when every extracted member path
  exists, before the SHA-256 check. The stable OS-temp cache is also keyed by the
  unrelated VSCO revision, so a changed bass pin with unchanged member names can reuse
  old bytes.
- **Impact:** a stale or altered but wave-valid cached member can be rebaked into the
  tracked crate while provenance still claims the pinned archive. A truncated member
  aborts later rather than self-healing.
- **Fix:** make the cache content-addressed; validate the archive or a trusted
  per-member manifest before returning, invalidate/refetch mismatches atomically, and
  test valid-content drift plus truncation.
- **Effort:** Medium.

### CR-4 — Tracked WAV output is replaced non-atomically

- **Severity:** Low
- **Confidence:** High
- **Where:** `tools/ferrosintesis-samples/prepare.py:1802-1811` and `:2680`;
  durable download precedent at `:1067-1077`
- **Tracked as:** `MM-BUG-KILN-00063`
- **Problem:** `write_wav_mono()` opens the final tracked asset in `wb` mode before
  completing the new file. An interruption can leave source state empty or partial.
- **Fix:** write and close a same-directory temporary WAV, then use `os.replace()`.
  Add a failure-injection regression proving the old final bytes survive.
- **Effort:** Small.

### CR-5 — Sampled-program coverage omits GM 33–35

- **Severity:** Low coverage gap
- **Confidence:** High
- **Where:** `crates/ferrosintesis/src/voices.rs:24624-24627` and `:24847-24860`;
  `crates/ferrosintesis/src/testutil.rs:2805-2808`;

- **Problem:** inventories described as covering every LA-wrapped program omit all

- **Effort:** Small.
