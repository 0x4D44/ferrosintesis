### CR-1 — Every sampled GM76 NoteOn repeats a 67-million-operation loop search

- **Severity:** High
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-065916\crates\ferrosintesis\src\sampler.rs:3308-3413`,
  `:3524-3531`;
  `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-065916\crates\ferrosintesis\src\live.rs:207-213`,
  `:272-289`
- **Tracked as:** `MM-BUG-KILN-00064`
- **Problem:** `BottleLoopVoice::new()` rediscovers the same static loop bounds for
  every NoteOn. The committed asset produces 764 starts, 15,280 candidates, exactly
  67,384,800 sample-square accumulations, and 30,560 square roots. The code searches
  before checking pitch range, so out-of-window notes pay the full cost and then
  discard it.
- **Realtime amplification:** pending NoteOns are constructed inside `fill_ring()`
  before the voice cap runs. A burst can repeat the cost many times in one callback.
- **Prewarm breach:** `sampler::prewarm()` initializes the retired
  `bottle_bank()`, not `bottle_loop_bank()`. First sampled use additionally decodes
  72,765 PCM frames and allocates 291,060 bytes despite the public prewarm promise.
- **Fix:** reject pitch range first; cache decoded PCM plus loop bounds in one
  initializer; prewarm that initializer; prove post-prewarm construction does no
  decode/allocation/search.
- **Effort:** Small–medium.
- **Dedup decision:** `MM-BUG-KILN-00059` overlaps only the prewarm-list drift. A new
  bug is required because prewarming cannot remove the repeated loop search.

### CR-2 — Bottle regeneration has no valid ownership or routing path

- **Confidence:** High

### CR-3 — A long-held bottle note overflows its sample clock

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-065916\crates\ferrosintesis\src\sampler.rs:3375-3489`
- **Tracked as:** `MM-BUG-KILN-00066`
- **Problem:** the indefinitely sustaining voice increments a `u32` once per sample.
  It overflows after 27.05 hours at 44.1 kHz or 6.21 hours at 192 kHz.
- **Impact:** overflow-checked builds panic in rendering. Ordinary release builds
  reset the vibrato clock, causing a 0.2-second loss followed by a 0.35-second
  re-bloom, plus a drift-schedule discontinuity.
- **Fix:** use a `u64` clock or split saturating onset time from a deliberately
  wrapping scheduler. Add a near-boundary unit regression.
- **Effort:** Small.
