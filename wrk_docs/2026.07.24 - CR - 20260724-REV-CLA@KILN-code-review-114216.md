### CR-3 — MIDI scheduling is callback-quantized, not frame-accurate

- **Severity:** Medium
- **Confidence:** High
- **Where:** `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-114216\crates\amp-lab\src\seq.rs:170`;

### CR-5 — Safe code can violate the ring's unsafe SPSC contract

- **Severity:** Medium
- **Confidence:** High
- **Where:** `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-114216\crates\amp-lab\src\ring.rs:35`;
  `:58`; `:64`; `:73`; `:97`
- **Tracked as:** `MM-BUG-KILN-00080`
- **Problem:** `unsafe impl Sync for Ring` makes both endpoint wrappers
  automatically `Sync`. Non-Clone does not stop safe sharing via `&Producer` or
  `Arc<Producer>`; concurrent callers can claim and write/read the same
  `UnsafeCell` slot, causing data-race undefined behavior. Current amp-lab usage
  remains true SPSC, which limits present exposure but does not make the safe
  API sound.
- **Concrete fix:** make endpoints `Send + !Sync` or require mutable endpoint
  methods; add compile-time auto-trait assertions.
- **Effort:** Small.

### CR-8 — Ring saturation silently desynchronizes UI and synth state

- **Severity:** Medium
- **Confidence:** High for failure semantics; trigger requires a stall
- **Where:** `D:\worktrees\midi-music\20260724-REV-CLA@KILN-code-review-114216\crates\amp-lab\src\ring.rs:61`;

  `:94`; `:222`; `:226`; `:229`
- **Tracked as:** `MM-BUG-KILN-00083`
