## Confirmed findings

### CR-1 — Input/output alias can destroy the source MIDI

- **Severity:** High
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/src/main.rs:102-105,161`;
  `crates/ferrosintesis/src/wav.rs:15-16`
- **Tracked as:** `MM-BUG-KILN-00097`
- **Problem:** `-o` may name the input itself. The CLI loads the MIDI, renders,
  then opens the output with truncating `File::create`, replacing the source
  with WAV bytes. A MIDI file already named `.wav` also collides with the
  derived default output without an explicit `-o`.
- **Concrete fix:** reject same-file identity before rendering, including
  canonical/symlink/hard-link aliases where supported; write through a
  same-directory temporary file and atomically replace only after success.
- **Effort:** Medium.

### CR-2 — Unchecked render dimensions can hang, abort allocation, or emit invalid audio

- **Severity:** High
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/src/main.rs:43-81,113-115,133-160`;
  `crates/ferrosintesis/src/engine.rs:3894-3896`;
  `crates/ferrosintesis/src/loudness.rs:124-140`;
  `crates/ferrosintesis/src/wav.rs:17-20`
- **Tracked as:** report-only; this is the still-unfixed CR-8 from the
  2026-07-18 CLI review, promoted prominently here but not duplicated in the
  bug ledger after devil's-advocate deduplication.
- **Problem:** numeric parsing checks syntax but not finiteness or domain.
  `--rate 0` can write a zero-rate WAV; rates 1–4 make the loudness hop round to
  zero and never advance; negative tails can truncate the render; extreme rate,
  tail, or non-finite values can request pathological allocations. Independently,
  an accepted multi-hour MIDI can exceed classic RIFF's 32-bit data length; the
  writer narrows it with `as u32`.
- **Concrete fix:** extract a validated CLI configuration; reject non-finite and
  out-of-range controls; checked-compute frames, working bytes, and final RIFF
  size before render; reject unsupported sizes (or implement streaming/RF64).
- **Effort:** Medium to Large.

### CR-3 — MIDI sequence names can inject terminal controls

- **Severity:** Low
- **Confidence:** High for display spoofing; terminal-specific OSC effects
  unverified
- **Where:** `crates/ferrosintesis-cli/src/main.rs:117-130`;
  `crates/ferrosintesis/src/midi.rs:257-273`
- **Tracked as:** report-only.
- **Problem:** track-zero meta event `0x03` is accepted as lossy UTF-8, which
  preserves valid ASCII escape/control bytes. The verbose CLI prints that title
  verbatim to stderr. An untrusted MIDI can therefore rewrite or spoof terminal
  and captured-log output. No command execution was demonstrated.
- **Concrete fix:** escape C0/C1/control characters in untrusted titles before
  terminal/log output while preserving printable Unicode.
- **Effort:** Small.

### CR-4 — A 1–4 Hz WAV makes `calmeter` nonterminating and memory-growing

- **Severity:** Medium
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/examples/calmeter.rs:102-145,182-213`;
  `crates/ferrosintesis/src/loudness.rs:124-140`
- **Tracked as:** `MM-BUG-KILN-00098`
- **Problem:** the WAV reader accepts a positive low sample rate. The loudness
  meter's 100 ms hop rounds to zero, so its block loop never advances and keeps
  appending output.
- **Concrete fix:** reject unsupported rates in `calmeter`, and make the public
  loudness primitive fail safely when block/hop geometry rounds to zero.
- **Effort:** Small.

### CR-5 — `measure_wav` ignores WAV format, channels, and declared sample rate

- **Severity:** Medium
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/examples/measure_wav.rs:14-40`
- **Tracked as:** `MM-BUG-KILN-00099`
- **Problem:** the example finds only `data`, decodes every two bytes as signed
  16-bit samples, and always meters at 44.1 kHz. A valid 48 kHz CLI output gets
  wrong K-weighting and time geometry; mono/non-PCM layouts produce plausible
  but meaningless values.
- **Concrete fix:** parse and validate RIFF `fmt ` and `data`, pass the declared
  supported rate, and share the reader with `calmeter`.
- **Effort:** Small to Medium.

### CR-6 — `calmeter` clipping includes filter pre-roll, contrary to its contract

- **Severity:** Low
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/examples/calmeter.rs:178-201`
- **Tracked as:** report-only.
- **Problem:** the `clipped` count scans the slice beginning 0.4 seconds before
  note onset, although the function says it counts samples inside the note
  window and `peak_abs` correctly narrows to that window. The current generated
  probes leave the pre-roll silent, so no current derived trim was shown wrong.
- **Concrete fix:** count clipping over the same `note_lo..hi` span as
  `peak_abs`; add a rail sample in pre-roll as a negative fixture.
- **Effort:** Small.

### CR-7 — The CLI/catalog/raw-render default parity oracle cannot observe the CLI

- **Severity:** Medium design debt
- **Confidence:** High
- **Where:** `crates/ferrosintesis-cli/src/main.rs:28-37,112-140`;
  `crates/ferrosintesis-cli/examples/raw_dump.rs:65-80`;
  `crates/render-catalog/src/main.rs:26-39,264-280,911-931`
- **Tracked as:** Draft requirement `MM-REQ-KILN-00032`
- **Problem:** three entry points copy the render profile. The test named
  `synth_options_match_ferrosintesis_cli_defaults` checks only catalog-local
  constants and literals, so a CLI-only mutation leaves it green. Current
  values match; this is not a present audio mismatch.
- **Concrete fix:** consume one shared typed profile and tempo-derived echo
  formula, or build a derived oracle that genuinely observes every entry point.
- **Effort:** Medium; proposed heavy flow because it crosses shipped crates and
  may affect public configuration design.

## Test coverage assessment

`src/main.rs`, `raw_dump.rs`, and `measure_wav.rs` have no tests.
`calmeter.rs` has three tests, all limited to `onset_blocks`; none covers WAV
parsing, measurement bounds, clipping, twin comparison, TSV arguments, or
flags. The catalog parity tests do not consume CLI configuration.

The highest-value missing oracles are:

1. a pure, table-tested CLI argument/config parser with finite/range cases;
2. same-file input/output rejection;
3. low-rate WAV rejection plus a library zero-hop guard;
4. 44.1/48 kHz WAV format/rate fixtures;
5. a shared-profile or genuinely cross-entry-point parity oracle.

## Not reported as defects

- **Output equals input is ordinary overwrite semantics — refuted.** Overwriting
  an existing output may be ordinary, but silently replacing the input artifact
  is distinct and can also happen through a default extension collision.
- **NaN reaches `partial_cmp().unwrap()` in `calmeter` — refuted.** Non-finite
  blocks are filtered before comparison.
- **WAV chunk walking performs a demonstrated out-of-bounds read — refuted.**
  The loop guard keeps the chunk body within the loaded buffer and data ends
  are clamped. Semantic validation remains weak, as CR-4/CR-5 describe.
- **Whole-WAV buffering is itself a scale defect — refuted for this workflow.**
  Calibration inputs are deliberately chunked; no supported-scale failure was
  established.
- **Large TSV plans cause a practical memory failure — refuted.** Generated
  plans are bounded at roughly 1,536 rows.
- **Malformed `--latency-frames` and short TSV rows.** These can silently become
  zero or be skipped, but only malformed generated-tool inputs were shown.
  They remain report notes, not independently filed defects.
- **`calmeter --vs` twin compatibility.** The source does not require equal
  sample rates or lengths, so mismatched twins can misclassify sample use. The
  documented raw-dump twin workflow fixes both at 44.1 kHz; broader reach was
  not established, so this remains unverified outside that contract.
- **`--help` exits 2.** Confirmed but treated as a low-impact CLI convention,
  not a defect worth tracking.
