## Confirmed findings

### CR-1 — Two soft low-piano round robins replay identical onsets

- **Severity:** Medium
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis-samples-core\src\lib.rs:33-38,153-158`;
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\tools\ferrosintesis-samples\prepare.py:60-63`;
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis\src\sampler.rs:937-947,3046-3057`
- **Tracked as:** `MM-BUG-KILN-00112`
- **Problem:** the C2/pp and G2/pp RR2 files are byte-for-byte clones of RR1.
  The generator intentionally substitutes RR1 because the pinned source lacks
  those takes, but the package and sampler promise two round robins that prevent
  cloned repeated notes. GM0 alternates them by seed parity while the sample
  exclusively owns the first 180 ms, so the machine-gun-sensitive onset remains
  identical.
- **Concrete fix:** source or deliberately derive defensible alternate takes
  and recalibrate them; add a derived RR-distinctness oracle. If no suitable
  alternate exists, model these two zones as documented single-take exceptions.
- **Effort:** Medium.

### CR-2 — Packaged provenance assigns the upright bank to the wrong GM program

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis-samples-core\PROVENANCE.md:12`;
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis\src\voices.rs:12962-12992`
- **Tracked as:** `MM-BUG-KILN-00113`
- **Problem:** the table labels `piano_*` as GM1 while its neighbouring rows use
  zero-based program numbers and current dispatch routes this bank to GM0.
  Program 1 uses the separate Kawai bank. The published package therefore gives
  auditors and maintainers a false asset-to-program mapping.
- **Concrete fix:** identify it as the GM0 default onset bank, or omit mutable
  consumer routing if provenance should describe only the source recording.
- **Effort:** Trivial.

### CR-3 — The provenance oracle does not enforce provenance rows or counts

- **Severity:** Medium guard defect; current rows are present
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis-samples-core\PROVENANCE.md:3-14`;
  `D:\worktrees\midi-music\20260725-REV-CLA@KILN-code-review-212250\crates\ferrosintesis\src\inventory.rs:182-280`
- **Tracked as:** `MM-BUG-KILN-00114`
- **Problem:** the package says a missing family row fails the build. The oracle
  instead accepts a bare family substring anywhere in README, PROVENANCE, or
  NOTICE, and derives no per-family count. Removing a core provenance row still
  passes because the README names every family; adding another `piano_*` file
  leaves the documented count of 54 untested.
- **Concrete fix:** parse `PROVENANCE.md` independently, require one canonical
  row per derived family, compare derived counts, and pin the adversarial
  README-still-mentions-it case.
- **Effort:** Small–Medium.

## Test coverage assessment

The crate-local tests correctly bind the 71 filename inventory to the embedded
table, pin aggregate bytes, check RIFF/WAVE signatures, verify each lookup, and
cover a missing-name lookup. Read-only byte inspection confirmed all current
assets are regular PCM format 1, mono, 44.1 kHz, 16-bit WAVs with exact RIFF
extent, bounded chunks, nonempty even-sized data, and the expected aggregate
9,555,776 bytes.

The highest-value missing oracles are:

1. distinctness for every advertised round-robin pair;
2. per-family provenance-row and count coverage;
3. complete WAV-contract validation or per-file content digests in the shared
   generated sample-crate tests.

Item 3 remains report-only. Current assets are valid, and previous sample-crate
reviews already recorded the same cross-crate future-regression gap.

## Not reported as defects

- **A non-WAV file currently leaks into the package — refuted.** The manifest's
  `samples/**` include is broader than the crate test's `.wav` filter, but the
  current directory contains exactly 71 regular lowercase WAVs and no other
  entries. Narrowing it to `samples/*.wav` is sensible hardening, not a current
  payload defect. The release runbook also requires packaging from a clean
  `origin/main` checkout.
- **Malformed committed WAVs — refuted.** All 71 files satisfied the consumer's
  PCM/mono/44.1-kHz/16-bit contract and declared exact container sizes.
- **Current cross-crate filename shadowing — refuted.** No duplicate WAV
  basename exists across the sample crates, so the consumer's first-match lookup
  does not currently select the wrong package.
- **Linear `get()` lookup harms realtime scale — refuted.** Seventy-one string
  comparisons occur only during one-time cache initialization/prewarm, not per
  audio sample.
- **The package exceeds crates.io's 10 MiB compressed limit — refuted.** Raw WAV
  bytes total 9,555,776 and the repository's latest recorded package measurement
  remains below the compressed cap. This review did not rerun `cargo package`.
- **GM1 could be one-based notation — refuted.** The same provenance table calls
  violin GM40 and flute GM73, which match zero-based runtime programs; only the
  piano row is inconsistent.
