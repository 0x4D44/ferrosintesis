## Scope and method

The pass read every file in the assigned crate:

- `Cargo.toml`
- `src/lib.rs`
- `README.md`
- `PROVENANCE.md`
- `NOTICE`
- all eleven `samples/clavinet_*.wav` assets

Adjacent generator, consumer, licensing, and workspace files were read only to
confirm the package's claims and call contracts. Six bounded lenses covered
correctness, security/licensing, performance/scale, reliability,
maintainability, and test coverage. A standing devil's advocate then tried to
refute the retained findings and identify missed assumptions. The team lead
re-read every cited source and deduplicated against `bugs/`, `reqs/`, and prior
code-review reports.

Static asset inspection confirmed that all eleven committed files are tracked,
unique RIFF/WAVE PCM files: mono, 44.1 kHz, 16-bit, 70,560 frames (1.600
seconds), and 141,164 bytes each. Their aggregate is 1,552,804 bytes, matching
the crate canary. RIFF and chunk lengths agree with each file's actual length.
This inspection did not assess sound or pitch by running the synthesizer.

## Confirmed findings

### CR-1 — The licence summary implies every other sample crate is CC0

- **Severity:** Low
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-clavinet/README.md:13-14`;
  counterevidence at `crates/ferrosintesis/README.md:194-220`
- **Tracked as:** `MM-BUG-KILN-00121`
- **Problem:** the phrase “unlike ferrosintesis's other, CC0, sample crates”
  makes `CC0` describe the other banks as a group. The authoritative inventory
  says ten default banks require attribution, including nine other MIT or CC BY
  crates. A distributor can therefore infer that only this bank needs a notice.
- **Concrete fix:** say “unlike ferrosintesis's CC0 sample crates,” or explicitly
  note that other banks also use MIT/CC BY, and link the authoritative
  distribution table.
- **Effort:** Extra small.

### CR-2 — Equal-sized assets are not bound to their filenames

- **Severity:** Low test/provenance debt
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-clavinet/src/lib.rs:77-118`;
  filename-specific roots at `crates/ferrosintesis/src/sampler.rs:4889-4901`
- **Tracked as:** report-only; already recorded as a generated asset-crate family
  gap in `wrk_docs/2026.07.24 - CR - 20260724-REV-CLA@KILN-code-review-043317.md:91-106`
- **Problem:** the tests pin the filename set, aggregate bytes, RIFF/WAVE magic,
  and lookup results. All eleven WAVs have the same length, so swapping two
  payloads preserves every crate-local assertion while the consumer assigns
  each filename its old root. No current container corruption or duplicate
  payload was found, and no current filename/root swap was demonstrated; this
  is a future-regression gap, not a confirmed current audio defect.
- **Concrete fix:** solve once across generated asset crates by validating an
  independently pinned per-filename digest or measured-root manifest, plus the
  full PCM/chunk contract.
- **Effort:** Medium across the asset-crate family.

### CR-3 — Sampled clavinet note-off damping has no direct oracle

- **Severity:** Low test debt
- **Confidence:** High
- **Where:** contract and implementation at
  `crates/ferrosintesis/src/sampler.rs:4878-4881,4937,4974-4989`; current
  clavinet routing test at `crates/ferrosintesis/src/sampler.rs:8167-8200`
- **Tracked as:** report-only
- **Problem:** no clavinet-specific test calls `note_off()`. Making
  `ClavinetSampled::note_off` a no-op or removing the release envelope would
  leave short notes ringing toward the 1.6-second baked tail while the current
  routing and waveform-distinctness checks remain green. Source inspection
  confirms the present 60 ms T60 implementation is correct.
- **Concrete fix:** render a held sampled voice, call `note_off()`, assert
  `released()`, verify decay near the configured T60, and require bounded reap.
- **Effort:** Small.

## Test coverage assessment

The target crate tests genuinely cover:

- disk filenames against the embedded table;
- file count through a fixed-size array;
- aggregate byte count;
- RIFF/WAVE magic;
- every successful exact-name lookup and one missing-name lookup.

Adjacent tests cover default sampled routing, modeled fallback routing, sampled
versus modeled waveform distinction, prewarming, manifest shape, and
licensing/NOTICE inclusion. They do not bind each filename to its payload or
exercise sampled note-off damping. Sampled held-decay calibration is separately
tracked by blocked bug `MM-BUG-KILN-00043`; it was not duplicated here.

## Not reported as defects

- **`--no-samples` removes the crate from a binary — refuted.** The README first
  says the default feature pulls the crate in, then describes GM7 runtime voice
  selection. “This crate is not used” is accurate in that runtime context; it
  does not claim that the embedded bytes or attribution obligations disappear.
- **Literal `FILE_COUNT` can silently drift — refuted.** The fixed-size
  `SAMPLES` array makes row-count disagreement a compile error, while the
  inventory test derives the packaged filename set from disk.
- **Current WAV corruption or root mismatch — refuted for container integrity,
  unverified for pitch.** Static inspection found valid, bounded current
  containers and eleven unique payload hashes. No authorized audio/pitch oracle
  ran, so pitch correctness is not claimed.
- **Linear lookup is a scale defect — refuted.** Eleven entries are searched
  only during bounded one-time bank initialization, not per render frame.
- **Missing package notice or floating source — refuted.** `Cargo.toml` packages
  `NOTICE` and `PROVENANCE.md`; the notice contains the MIT terms and credits;
  the generator pins the source commit and verifies its SHA-256.
- **Adjacent stale “two asset crates” comment — out of scope.**
  `crates/ferrosintesis/src/sampler.rs:6-9` is stale against the current
  twenty-five-crate inventory, but it is outside the assigned area and another
  instance of already-known count drift. It was not filed from this bounded
  pass.
