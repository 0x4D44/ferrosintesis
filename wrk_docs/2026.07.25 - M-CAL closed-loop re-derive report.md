### The two programs that still propose a change — and why that is not a bug

    GM8   ChromPerc          +2 -> +3 dB   (consensus +1.1, refs agree to 0.9 dB)

**GM5, GM14 and GM119 are closed** — no proposal on either reference under the panel gate.

GM8 and GM110 re-propose, and the 07.22 journal called any proposal on a just-trimmed program
"a sign or linearity bug". **That reading is measurably wrong here.** The derivation applies
`DAMP = 0.70` to the *change*, so one iteration only ever removes 70% of the gap:

* GM110: consensus residual was -7.5 dB; the applied trim was `round(0.7 x -7.5) = -5`. The
  remaining gap **must** be -2.5 dB — measured -2.6. A damped controller cannot land inside a
  1.0 dB dead-band from 7.5 dB out in one step; it needs three.
* GM8: consensus was +3.14; `round(0.7 x 3.14) = +2` (the *rounding*, not the damping, is what
  matters here — the exact damped value was 2.20). Remaining gap +1.14, measured +1.11.
  That sits just over the 1.0 dB dead-band, so it re-proposes by 0.14 dB of margin.

Both predicted gaps match measurement to 0.03 dB. **The pass condition should have been
"every post-trim residual equals `old_residual - applied` to within the anchor shift",
which is what this run demonstrates**, not "no proposals" — the latter is unattainable for
any program whose original residual exceeded ~3.3 dB.

### GM85 (Lead 6, voice) lost 16 dB — the one real regression

Four independent readings agree:

* SC-55 residual **+1.74 -> +17.82** (+16.05 after the anchor shift)
* S-YXG50 residual **-1.87 -> +14.08** (+16.04) — the two references agree to **0.01 dB**
* ferro's own internal placement `int_F` **+7.1 -> -8.5** dB relative to ferro's 128-program
  median: self-referential, so blind to a whole-synth offset, and therefore an *independent*
  confirmation that this is GM85 moving, not the frame
* pitch tilt **0.9 dB -> 10.6 dB** (SC-55; 13.0 on the S-YXG50): the level is now strongly
  register-dependent, so a single scalar cannot correct it

**Correlation with voice work: yes, and it is attributable to a single commit.** `ec8bfd7`
(2026-07-25, "give GM 84, 85 and 93 their defining characters") is the only commit since
2026.07.22 that touches `StackFilter` in the lead voice, and the only one that ever
introduced `StackFilter::Formant` there.

The mechanism is visible in the source. `crates/ferrosintesis/src/voices.rs` (the lead
builder, around line 7592) replaces the velocity-tracked lowpass with a three-band formant
bank for GM85 only:

```rust
let filt = match spec.vowel_cc {
    Some(pos) => { ... StackFilter::Formant { bands: [Biquad::bandpass(..) x3], gains, ... } }
    None => StackFilter::Lp(Biquad::lowpass(cutoff, spec.q, sr)),
};
```

Three bandpasses keep only the energy near F1/F2/F3 of a broadband saw stack and discard the
rest — a large, unavoidable broadband loss — and **no make-up gain is applied**. Its
sibling in the same commit, GM84, *did* get make-up: `s.drive_norm = (spec.drive *
LEAD84_NOMINAL).tanh() / LEAD84_NOMINAL`, and GM84's measured drift is +0.17 dB, i.e. nil.
The fixed formant frequencies also explain the tilt: how much of the harmonic series lands
inside a fixed band depends on f0, so the loss is register-dependent and no single trim can
correct it.

This is the exact failure the lesson at the top of `lessons_learnt.md` describes — *"a tanh
drive normalised by `tanh(g)` is a VOLUME knob — solve make-up at the level the voice really
runs at (`voices.rs:LEAD84_NOMINAL`)"* — solved for GM84 in that commit and not applied to
GM85 in the same commit.

Note also that GM85 carries a shipped **+5.5 dB** boost, so the audible error is the 16 dB
loss on top of a program the table already believed was quiet.

### Why certificate 2 did not catch it

The residual oracle only inspects programs that are **not** guard-excluded
(`derive_trims.py:run`, the `vetted` filter). The GM85 regression is large enough to trip the
pitch-tilt guard, so it removes itself from the oracle's view. **The oracle's blind spot is
exactly the class it exists to catch.** Only the cross-run drift comparison found it — which
argues for keeping a per-program residual baseline in the repo and diffing against it, rather
than reading each run standalone.

## 5. Tooling defect found: `derive_trims.py`'s `SHIPPED` table is stale

`tools/instrument-balance/derive_trims.py` carries a hand-copied 128-entry `SHIPPED` table
documented as "current shipped table (engine.rs PROGRAM_TRIM_DB)". `fc1ef10` applied five
trims to `engine.rs` and **did not update it**. Verified by parsing both tables:

```
GM5 +0.0 -> +1.0, GM8 +0.0 -> +2.0, GM14 +0.0 -> -6.0, GM110 +0.0 -> -5.0, GM119 +0.0 -> +1.0
```

Nothing ties the two together — no oracle, no test, no generator. This is the repo's standing
defect class (hand-maintained lists that drift) reappearing *inside the calibration tool*.

It is not cosmetic. Run against today's identical data, the committed tool and the
`SHIPPED`-synced tool disagree about what to do (S-YXG50 reference shown; SC-55 behaves the
same way):

| | committed (stale) | synced to engine.rs |
|---|---|---|
| GM14 | `+0 -> -5 dB` | *(no proposal — correct)* |
| GM110 | `+0 -> -2 dB` | `-5 -> -6 dB` |
| GM119 | `+0 -> +2 dB` | *(no proposal — correct)* |

Anyone applying the committed tool's output literally would have **removed** GM14's shipped
-6 dB and replaced it with -5, and **removed** GM110's -5 and replaced it with -2 — a +3 dB
move in the wrong direction on a program that had just been correctly trimmed. The two
proposals that survive under the synced table (GM8, GM110) are +1 dB refinements; the stale
table turns them into 3-6 dB reversals.

The anchor is unaffected (percussive programs never enter the cohort), so certificates 1, 3
and 4 are untouched. Certificate 2 *is* affected: with `shipped = 0.0` those five programs
fall out of the "ear-vetted" set and stop being watched.

**The fix should be derived, not re-copied**: have the tool parse `PROGRAM_TRIM_DB` out of
`engine.rs` (about eight lines — `_cal/derive_synced.py` does exactly this), or add an oracle
that fails when the two disagree. A second hand-written copy would inherit the same defect.
