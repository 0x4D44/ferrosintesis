### CR-1 — Published selector and A/B baseline name the wrong instruments

The crate tells users to select GM0 bank-select MSB CC0=5 and compare it with
the default/raw Salamander. Shipping routing maps raw Salamander to CC0=1,
dark-Salamander to CC0=4, B1 upright to CC0=5, and the VSCO upright to the
default bank:

- `crates/ferrosintesis/src/altbank.rs:1041-1058`;
- `crates/ferrosintesis/src/voices.rs:13122-13142`.

A MIDI author following the packaged README therefore hears the unrelated B1
upright, and the documented bank-0 A/B compares two different uprights rather
than the same Salamander recording before and after EQ.

The mapping is intentional, not a historical compatibility ambiguity. Commit
`0281dcd` introduced dark-Salamander at CC0=4 while introducing the incorrect
bank-5 prose; `0a47568` later assigned CC0=5 to B1.

Concrete fix: keep routing unchanged; update all crate-facing selector/default
claims to raw CC0=1 versus dark CC0=4; correct the stale consumer and generator
comments; add a source-derived routing/documentation guard.

### CR-2 — The documented rebake is not convergent

`_bake_darkened_grand` writes outputs for the current grand inputs but never
checks for obsolete owned `darkgrand_*.wav` files. A removed or renamed source
therefore leaves its old derived payload in the destination. Cargo packages the
whole directory, and `gen_crate_lib.py` republishes whatever WAVs it finds.

Current payloads are clean: the source-derived and destination inventories each
contain the same 54 names. The defect is the deterministic stale-file path, not
present corruption.

Concrete fix: derive the expected target set, fail closed with an explicit list
of extras before writing, and add an extra-file regression. Do not silently
delete tracked sample-source assets.

### CR-3 — The bank's defining transform has no durable oracle

Current generated checks prove inventory names, aggregate size and minimal
RIFF/WAVE signatures. They do not prove that each output is the high-shelf
transform of its paired raw-grand source or that the transform actually
attenuates treble. A same-length payload replacement or a broken 0 dB shelf can
remain green.

This is not a current-payload defect. The review statically confirmed all 54
files are unique, canonical PCM mono/44.1 kHz/16-bit, and byte-distinct from
their paired raw sources. Draft requirement MM-REQ-KILN-00033 captures the
durable invariant and a non-mutating rebake plus spectral oracle for Gate 1.

## Not reported as defects

- **Security surface — refuted.** The crate has no dependencies or build script,
  forbids unsafe code, embeds fixed bytes, and performs a bounded exact-name
  lookup. The packaged NOTICE and provenance carry the CC-BY identity,
  attribution, modification and source.
- **Asset omission/corruption — refuted for the current tree.** The 54 packaged
  names match `SAMPLES`; RIFF extents match file lengths; every WAV is PCM format
  1, mono, 44.1 kHz, 16-bit; no two payloads share a SHA-256.
- **Excessive runtime lookup — refuted.** The 54-entry linear scan happens only
  during bounded one-time bank initialization; decoded zones are cached.
- **Embedded/decode memory — by design.** The fixed asset payload and opt-in
  prewarm trade memory for realtime note-on safety. Modeled-only builds can omit
  the bank.
- **Missing package/provenance coverage — refuted.** The manifest includes
  samples, NOTICE and provenance; the workspace inventory oracle derives family
  counts and package-document presence.
- **Current acoustic effect — unverified.** The pass did not render or measure
  audio because this review contract forbids application/test execution. No
  claim is made that the current bank meets a particular audible or spectral
  darkness threshold; MM-REQ-KILN-00033 exists because that must become
  machine-checkable.
