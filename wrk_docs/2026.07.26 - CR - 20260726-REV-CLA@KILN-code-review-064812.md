## Confirmed findings

### CR-1 — `--local-only` also rewrites the bottle bank

- **Severity:** Medium
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\crates\ferrosintesis-samples-gong\README.md:15`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\crates\ferrosintesis-samples-gong\PROVENANCE.md:119`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\tools\ferrosintesis-samples\prepare.py:2846`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\tools\ferrosintesis-samples\prepare.py:3104`
- **Tracked as:** `MM-BUG-KILN-00128`
- **Problem:** `--local-only` skips the fetched-bank block but leaves
  `only=None`. `want("bottle")` therefore remains true after the gong bake, and
  the command replaces the unrelated tracked bottle output.
- **Impact:** a maintainer following the gong package's documented isolated
  recipe can dirty another bank. The bottle parity test explicitly says its
  recovered recipe is not byte-identical to the committed asset. The exact diff
  was not measured because running this mutating generator is outside the review
  contract.
- **Concrete fix:** normalize `--local-only` to a gong-only family selection, and
  add a stubbed command-selection regression covering gong-only, bottle-only, and
  full runs.
- **Effort:** Small.

### CR-2 — Packaged provenance says “crossfade”; shipping code hard-switches

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\crates\ferrosintesis-samples-gong\PROVENANCE.md:95`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\crates\ferrosintesis\src\sampler.rs:4650`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\crates\ferrosintesis\src\sampler.rs:4688`
- **Tracked as:** `MM-BUG-KILN-00129`
- **Problem:** provenance claims velocity crossfades the soft and loud
  recordings. The implementation deliberately chooses exactly one take at
  velocity 84, with a comment explaining that summing them would comb-filter.
- **Impact:** the packaged design record misleads maintainers about a deliberate
  discontinuous selector. No runtime bug was found in the selector itself.
- **Concrete fix:** document the hard switch and its threshold/rationale. Add a
  boundary oracle for velocities 83 and 84.
- **Effort:** Extra small for prose; Small including the regression.

## Not reported as defects

- **Current asset corruption — refuted.** RIFF extents match physical lengths;
  both current files are PCM format 1, mono, 44.1 kHz, and 16-bit. Sizes and
  rounded durations agree with provenance.
- **Runtime lookup/per-note allocation — refuted.** The two-name linear lookup
  occurs during one-time decoding. Voices borrow cached static PCM and do not
  clone it per note.
- **Unbounded gong lifetime — refuted by source.** Rendering stops at the finite
  selected sample boundary. Existing runtime execution remains unverified
  because tests did not run.
- **Package or attribution omission — refuted.** The package includes its WAVs,
  NOTICE, and provenance; the parent crate carries the same credit and licence
  link. The official CC BY 3.0 deed requires credit, a licence link, and an
  indication of changes, all present in the shipped notice.
- **Immutable upstream licence evidence — not duplicated.** The sound-page claim
  could not be rechecked directly in this pass and is **UNVERIFIED**, not a pass.
  The residual evidence gap is already recorded in
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-064812\reqs\MM-REQ-KILN-00029.md:71`.
- **Stale owned outputs — duplicate.** The gong bake does not reject obsolete
  `gong_*.wav` files, but the same non-convergent generator defect is already
  tracked by `MM-BUG-KILN-00123`; no duplicate bug was filed.
- **Whole-bank atomic replacement — not a current defect.** Per-file replacement
  is atomic, but failure between the two writes can leave a mixed-generation
  pair. No whole-bank transaction is promised and no current mixed pair was
  found. Source-to-output verification in CR-3 is the proportionate next step.
- **Current duplicate sample basenames — refuted.** A static inventory found
  none across the default sample crates.
