## Confirmed findings

### CR-1 — Salamander's warm cache bypasses its pinned SHA-256

- **Severity:** Medium
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\crates\ferrosintesis-samples-grand\PROVENANCE.md:27`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\tools\ferrosintesis-samples\prepare.py:1386`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\tools\ferrosintesis-samples\prepare.py:3119`
- **Tracked as:** `MM-BUG-KILN-00134`
- **Problem:** `ensure_salamander_sources()` returns when all 54 cached
  filenames exist. The archive hash below that return is unreachable on a warm
  cache, and no member manifest binds those files to the current pin.
- **Impact:** a stale, altered-but-valid, or wrong-pin cached member can be
  transformed into the tracked grand bank while packaged provenance continues
  to name the pinned archive. A truncated member fails late instead of
  self-healing.
- **Concrete fix:** wrap the custom tar.bz2 extraction with the existing
  pin-plus-per-member-hash manifest contract. Reject incomplete or unproven
  caches, self-heal a corrupt archive once, write the manifest atomically, and
  add altered/truncated/changed-pin cache regressions.
- **Effort:** Medium.

This is a missed sibling of closed `MM-BUG-KILN-00062`, whose shared
`ensure_archive_sources()` fix covers five 7z-backed callers but not the bespoke
Salamander helper. The current packaged WAVs are not shown to be altered.

### CR-2 — Grand-specific regeneration invokes every sample-bank recipe

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\crates\ferrosintesis-samples-grand\README.md:19`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\crates\ferrosintesis-samples-grand\PROVENANCE.md:66`;

- **Tracked as:** `MM-BUG-KILN-00135`
- **Problem:** both crate-specific documents prescribe the bare generator. With
  no family selector, the generator traverses unrelated families and external
  prerequisites even though the prose presents the Salamander path as pure

- **Impact:** a maintainer can fail on unrelated 7z/ffmpeg prerequisites or

- **Concrete fix:** document
  `python tools/ferrosintesis-samples/prepare.py --only=grand` in both files,
  identify the bare command as the full-bank workflow, and pin the selector with
  a small regression.
- **Effort:** Small.

### CR-4 — Filename-to-payload binding remains blind

- **Severity:** Low test/reproducibility debt
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\crates\ferrosintesis-samples-grand\src\lib.rs:251`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-125503\tools\ferrosintesis-samples\gen_crate_lib.py:80`
- **Disposition:** report only; this is the already-reported cross-family
  generated-asset gap, not a new grand-specific requirement.
- **Problem:** generated crate tests pin names, total bytes, RIFF/WAVE magic, and
  lookup. Because all 54 files have the same length, swapping two valid payloads
  under their names preserves every crate-local assertion.
- **Concrete fix:** bind every filename to an independently generated SHA-256 or
  measured-root manifest and compare the consumer's root table against it. Do
  not derive both the expected identity and the embedded table from the same
  destination directory.
- **Effort:** Medium as a shared asset-family change.
