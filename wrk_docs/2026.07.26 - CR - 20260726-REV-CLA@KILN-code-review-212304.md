## Confirmed findings

### CR-1 — The standalone package omits required upstream MIT text

- **Severity:** Medium
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis-samples-musescore-grand\Cargo.toml:10`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis-samples-musescore-grand\NOTICE:8`
- **Tracked as:** `MM-BUG-KILN-00148`
- **Effort:** Small

The package allowlist ships source, samples, README, NOTICE, and provenance.
None of those packaged files contains the MIT permission grant. The crate's
NOTICE also abbreviates the upstream copyright block: it names the Collins
adaptation and vaguely attributes FluidR3 to Frank Wen, but omits the complete
FluidR3/FluidR3Mono copyright notices and Michael Cowgill attribution.

The upstream MuseScore_General licence says derivative distributions must carry
the acknowledgements and copyright notices, and its MIT grant requires the
copyright and permission notices to accompany copies. This source fact was
looked up once on the
[official MuseScore licence page](https://musescore.org/en/comment/1064663).
The repository's two sibling MuseScore-derived sample crates reproduce the
complete grant and notices; this independently publishable crate does not.

The parent `ferrosintesis` distribution happens to reproduce a full MIT grant
for the combined default-bank notice. That does not repair a consumer receiving
`ferrosintesis-samples-musescore-grand` by itself.

Concrete fix: package the complete upstream MIT grant and required copyright
block in this crate. Extend
`D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis\src\licensing.rs:541`
so an MIT bank's own packaged documents cannot pass with only a licence name and
one licensor-owned signal.

### CR-2 — Parent documentation assigns the bank to the wrong GM program

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis\README.md:233`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis\NOTICE:26`;
  `D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis\src\altbank.rs:1046`
- **Tracked as:** `MM-BUG-KILN-00149`
- **Effort:** Small

The parent README and NOTICE both call this asset a GM0 grand. The shipping
router selects it only for GM program 1 (Bright Acoustic Piano), bank-select
MSB CC0=2. GM0 CC0=2 selects the Salamander bank instead.

The assigned crate's module docs, manifest, README, provenance, generator, and
sampler all state GM1 CC0=2 correctly. The stale claims are limited to the
parent distribution surfaces, so this is not an ambiguous numbering convention.

Concrete fix: change both parent references to “GM 1 Bright Acoustic, CC0=2.”
Add a source-derived GM1 alternate-bank documentation guard covering YDP at
CC0=1 and MuseScore grand at CC0=2. The current guard at
`D:\worktrees\midi-music\20260726-REV-CLA@KILN-code-review-212304\crates\ferrosintesis\src\altbank.rs:1317`
iterates only `GM0_SOURCES`, which explains why the parent drift stayed green.
