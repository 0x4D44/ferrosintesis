# Code review — `crates/ferrosintesis-samples-musescore/`

- **Date:** 2026-07-27
- **Baseline:** Deltic-supplied fresh `origin/main` worktree
- **Mode:** Read-only review; docs and ledgers are the only outputs
- **Result:** One High-severity defect filed; two related Low-severity documentation
  drifts confirmed; one test-hardening gap retained in this report

## Scope and method

The primary scope was exactly `crates/ferrosintesis-samples-musescore/`. Review lenses
covered correctness, security/licensing, performance/scale, reliability,
maintainability, and test coverage. A separate devil's-advocate pass tried to refute
each candidate.

The pass read the crate's Rust API, manifest, packaged documents, all 26 WAV headers
and payload bounds, its generator calls, consumer bank keys, derived inventory and
licensing oracles, relevant bug records, and the licence document at the source commit
pinned by `PROVENANCE.md`. It did not run the application, tests, builds, package
commands, generators, renders, or the exploratory-test harness.

## Confirmed findings

### High — Packaged NOTICE omits two mandatory upstream acknowledgements

- **Confidence:** High
- **Location:** `crates/ferrosintesis-samples-musescore/NOTICE:3`
- **Tracking:** `MM-BUG-KILN-00150`
- **Evidence:** The local notice says the upstream acknowledgements are reproduced,
  but names only FluidR3, FluidR3Mono, and the MuseScore_General adaptation. The
  [`MS Basic_License.md` at the pinned source commit](https://github.com/musescore/MuseScore/blob/d307a2bd899f15bf650efc3c2891211af5cb78b5/share/sound/MS%20Basic_License.md)
  also names the Temple Blocks instrument by Ethan Winer and Drumline Cymbals by
  Michael Schorsch, then explicitly requires all acknowledgements above to accompany
  derivative works.
- **Impact:** A published crate or binary assembled by concatenating the asset-crate
  notices carries incomplete attribution text and may not meet the pinned source's
  redistribution condition.
- **Concrete fix:** Add both omitted lines, sweep every notice transcribed from the
  same pinned source, and strengthen the licensing oracle so selective transcription
  cannot pass. Prefer a committed verbatim upstream notice as the oracle source.
- **Effort:** Small

### Low — The packaged NOTICE still omits the embedded celesta family

- **Confidence:** High
- **Location:** `crates/ferrosintesis-samples-musescore/NOTICE:14`
- **Tracking:** Related evidence in `MM-BUG-KILN-00150`; exact unfixed portion of
  closed `MM-BUG-KILN-00069`, so no duplicate ID was minted
- **Evidence:** The sentence enumerates GM 104 sitar and GM 75/76/77 pipes.
  `crates/ferrosintesis-samples-musescore/src/lib.rs:63` embeds eight GM 8 celesta
  WAVs. The closed bug explicitly reported the NOTICE omission, but its recorded fix
  lists changes only to README, Cargo description, and PROVENANCE; git history confirms
  this NOTICE has not changed since its original creation.
- **Impact:** The attribution file gives distributors a false inventory and makes the
  earlier bug closure incomplete, although the generic licence text still applies to
  the celesta bytes.
- **Concrete fix:** Add GM 8 celesta to the sentence or remove the partial instrument
  inventory. Extend the inventory oracle to inspect the canonical NOTICE statement
  rather than accepting coverage in a different packaged document.
- **Effort:** Extra small

### Low — The crate README directs maintainers to a stale regeneration authority

- **Confidence:** High
- **Location:** `crates/ferrosintesis-samples-musescore/README.md:26`
- **Tracking:** Related evidence in `MM-BUG-KILN-00150`; same documentation-drift
  remainder as `MM-BUG-KILN-00069`
- **Evidence:** The README says the pin and recipe live in
  `tools/ferrosintesis-samples/README.md`. That guide's two MuseScore inventory
  passages omit celesta, its regeneration block is the unscoped full workflow, and it
  calls clavinet the only non-CC0 bank. The crate's own packaged
  `PROVENANCE.md:7-20` has the complete five-family selector and exact source pin.
- **Impact:** A maintainer following the linked guide can rebuild unrelated banks or
  omit celesta from a targeted MuseScore refresh.
- **Concrete fix:** Point the crate README to its own packaged `PROVENANCE.md`. Replace
  the tool guide's duplicated exhaustive inventory with that authority, or derive and
  guard the duplicated list.
- **Effort:** Small

### Low — The crate-local WAV test does not enforce the documented audio contract

- **Confidence:** High
- **Location:** `crates/ferrosintesis-samples-musescore/src/lib.rs:142`
- **Tracking:** Report only; no current malformed asset and no standalone requirement
  warranted
- **Evidence:** The test checks length plus `RIFF` and `WAVE` signatures, but the crate
  promises PCM, mono, 16-bit, 44.1 kHz. A wrong-rate, stereo, truncated, or empty-data
  file can satisfy the local assertions. Direct static parsing confirmed every current
  asset is structurally consistent PCM16 mono at 44.1 kHz, and parent bank tests exercise
  live decoder paths.
- **Impact:** A future bad rebake may pass this crate's focused test and fail only when
  the parent consumer initializes the affected bank.
- **Concrete fix:** In the test, walk RIFF chunks with padding and bounds checks; require
  PCM format 1, one channel, 44,100 Hz, 16 bits, block alignment 2, and a nonempty
  even-length data chunk. Add malformed byte fixtures for each rejection.
- **Effort:** Small

## Not reported as defects

- **Linear `get()` lookup:** Refuted as a scale issue. It performs at most 26 string
  comparisons during lazy bank initialization.
- **Duplicate payloads:** Refuted. All 26 sample files have distinct SHA-256 hashes.
- **Malformed current WAVs:** Refuted. Every file has consistent RIFF length and chunks,
  PCM format 1, mono 44.1 kHz/16-bit data, and a nonempty payload.
- **Inventory or consumer-name drift:** Refuted. The 26 embedded names exactly match the
  26 tracked WAVs and all consumer keys.
- **Stale source pin:** Refuted. `prepare.py` and packaged `PROVENANCE.md` carry the same
  commit and SHA-256.
- **Retired `bottle_C6.wav` is accidental dead weight:** Refuted. Its retained public
  compatibility status is explicitly documented in the consumer.
- **Path traversal or filesystem exposure:** Refuted. `get()` exact-matches static names
  and returns compile-time byte slices.
