## Confirmed findings

### Medium — Direct sample cache ignores pinned source revisions

- **Confidence:** High
- **Location:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\tools\ferrosintesis-samples\prepare.py:1242`
- **Tracking:** Filing blocked; no bug ID was created
- **Evidence:** `ensure_source()` keys a cache entry by only `src` plus destination
  filename. An existing file is accepted whenever `read_wav()` can parse it; the
  requested URL and content identity are never checked. The main path puts all direct
  downloads under `%TEMP%\vsco2ce_src\<VSCO_REV>` at line 3165, then sends VSCO,
  steel, and VCSL sources through the helper at lines 3168–3176. `STEEL_REV` and
  `VCSL_REV` are independent pins, so advancing either one leaves the cache path
  unchanged. Changing a source-map URL under a stable destination has the same result.
- **Impact:** A warm rebake can overwrite 134 of this package's 158 tracked WAVs from
  stale or locally substituted valid audio while the package still claims the current
  immutable source revision. Clean and warm machines can produce different output
  from the same source tree. Static review did not find evidence that today's
  committed WAVs are wrong.
- **Concrete fix:** Give each direct cache entry an atomic sidecar containing the exact
  URL and fetched-file SHA-256. Reuse only when both match; refetch legacy, changed, or
  altered entries. Add regressions for a valid-WAV substitution, a URL/revision change
  with stable destination, and a good-cache no-refetch control. Extend the derived
  warm-cache oracle to include commit-URL-pinned helpers.
- **Effort:** Small–Medium, approximately 2–4 hours

### Medium — Archive cache does not bind a destination to its selected member

- **Confidence:** High
- **Location:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\tools\ferrosintesis-samples\prepare.py:1271`
- **Tracking:** Filing blocked; no bug ID was created
- **Evidence:** `cached_members_match()` validates the archive SHA-256, destination
  keys, and each cached destination's digest at lines 1288–1296, but never reads
  `member_map` values. `write_member_manifest()` at lines 1336–1346 stores only
  `{destination: digest}`. Changing a bagpipe or nylon destination to select another
  member under the same archive pin leaves every checked field unchanged, so the warm
  path returns at lines 1361–1362 without applying the new recipe.
- **Impact:** A source change such as selecting a different `_31`/`_32` chanter take
  can work on a clean machine and be silently ignored on a warm one. The existing
  tests cover changed pins, keys, and bytes, but not a same-key member-path change.
- **Concrete fix:** Version the manifest and record the exact
  destination-to-archive-member mapping, or a canonical digest of that mapping.
  Require exact equality before warm reuse and reject legacy manifests. Add a
  regression that changes only a mapping value and proves the new member is extracted.
- **Effort:** Small, approximately 1–2 hours

### Medium — Archive rebuild can attest stale extraction leftovers

- **Confidence:** High
- **Location:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\tools\ferrosintesis-samples\prepare.py:1324`
- **Tracking:** Filing blocked; no bug ID was created
- **Evidence:** `rebuild_archive_cache()` extracts with `7z x -y` into the persistent
  `src/<extract_subdir>` directory at lines 1328–1330 without making it empty. It then
  copies requested paths from that directory. A member absent from a new pinned
  archive can survive from an older extraction, be copied successfully, and receive a
  fresh manifest bound to the new archive SHA-256 at lines 1336–1346.
- **Impact:** A missing-member failure can become false provenance: stale bytes are
  positively attested as output from an archive that did not contain them. This
  affects this package's nylon-guitar and bagpipe rebuilds. The current refetch test
  cannot see the defect because its extraction stub always creates the requested
  member.
- **Concrete fix:** Extract every rebuild into a fresh temporary directory. Validate
  every selected path there, stage the complete output set, then atomically replace
  cache destinations and update the manifest. Add a regression that pre-seeds an old
  extraction member, omits it from the new extraction, and requires failure with no
  cache or manifest change.
- **Effort:** Small–Medium, approximately 2–4 hours

- **Locations:**

  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis-samples-orchestral\README.md:76`,
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis-samples-orchestral\PROVENANCE.md:13`,
  and
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis-samples-orchestral\src\lib.rs:1`
- **Tracking:** Filing blocked; no bug ID was created
- **Evidence:** The README says “six” chanter WAVs at line 76, while its own summary,
  `PROVENANCE.md`, and the generated inventory agree on 15: ten primary and five RR2.
  Lines 15–16 also say every recording is an onset crossfaded into a model, but the
  bagpipe `LoopVoice` at
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis\src\sampler.rs:2689`
  uses the looping sample as the entire sound. The crate rustdoc repeats the broad
  attack-transient claim. Separately, `PROVENANCE.md` maps `celens_*` to “GM 42

  inventory, playback, and GM-routing information.
- **Concrete fix:** State “two drones and 15 chanter takes (ten primary, five RR2)”;
  exempt bagpipe loops from the onset/crossfade description; describe the rustdoc as
  attack transients plus whole-voice bagpipe loops; and map `celens_*` to the low split
  of GM 48–49 string sections.
- **Effort:** Extra small, under 30 minutes

## Report-only observations

### The crate-local WAV test does not enforce the complete published format

`D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis-samples-orchestral\src\lib.rs:535`
checks aggregate size plus `RIFF`/`WAVE` signatures, not each file's PCM tag,
channel count, rate, bit depth, chunk completeness, or identity. All 158 current
files were statically parsed and are consistent PCM format 1, mono, 44.1 kHz,
16-bit WAVs with valid RIFF/chunk bounds and nonempty data. Downstream bank tests
also decode and prewarm every reachable sample. This is worthwhile focused-test
hardening, not a present defect.

A future change could make the asset crate's test self-contained by walking RIFF
chunks with bounds/padding checks and asserting the promised PCM format. Per-file
output hashes would also detect same-length substitution, but the generator cache
fixes above are the correct first layer.

### Package metadata is incomplete

`D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-074202\crates\ferrosintesis-samples-orchestral\Cargo.toml:6`
describes strings, brass, reeds, and guitars, but omits the harpsichord and
whole-voice bagpipe families. This affects discovery only and can be corrected with
the Low-severity documentation sweep.
