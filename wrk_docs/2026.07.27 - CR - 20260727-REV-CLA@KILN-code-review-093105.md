## Confirmed findings

### Medium — Direct sample cache ignores pinned source revisions

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00151
- **Location:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\tools\ferrosintesis-samples\prepare.py:1242`
- **Evidence:** `ensure_source()` accepts any existing file that `read_wav()` can
  parse. It records neither the requested URL nor the file digest. The shared
  cache directory at line 3165 is keyed by `VSCO_REV`, while 45 assigned-crate
  WAVs are independently pinned by `VCSL_REV`; advancing the latter reuses old
  bytes. All 81 direct URL-sourced WAVs accept a locally substituted valid WAV.
- **Impact:** Warm and clean machines can rebake different assets from the same
  source tree while published provenance names the current revision. No evidence
  says the current committed WAVs are wrong.
- **Concrete fix:** Bind each entry to exact URL plus SHA-256 in an atomic
  sidecar. Reject legacy, altered, or revision-mismatched entries. Add
  substitution, revision-change, and good-cache controls.
- **Effort:** Small–Medium, approximately 2–4 hours

### Medium — The packaged banjo regeneration command is a successful no-op

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00152
- **Locations:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\crates\ferrosintesis-samples-orchestral2\PROVENANCE.md:7`
  and
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\tools\ferrosintesis-samples\prepare.py:3216`
- **Evidence:** Packaged provenance advertises
  `prepare.py --only=<family>` for every row. The script advertises banjo as a
  selector, then explicitly excludes it and has no later banjo writer. The
  actual producer is `banjo_extract.py`; selected control flow otherwise reaches
  an empty report and returns success.
- **Impact:** A maintainer can mistake stale or missing banjo assets for a
  completed 24-file rebuild.
- **Concrete fix:** Publish banjo's real command, narrow the generic recipe, and
  reject unsupported or non-producing selectors. Add command-to-writer contract
  tests.
- **Effort:** Small, approximately 30–60 minutes

### Low — Banjo regeneration destroys the old bank before replacement is ready

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00153
- **Location:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\tools\ferrosintesis-samples\banjo_extract.py:174`
- **Evidence:** The script unlinks every tracked `banjo_*.wav`, then writes final
  files sequentially and directly. Its output set comes from decoder/QC results;
  the promised 24 names are never asserted.
- **Impact:** A kill, disk error, or QC change can leave a missing, partial, or
  reduced tracked bank. Compilation catches missing `include_bytes!` targets, so
  this is recoverable worktree damage rather than a silent release-corruption
  path.
- **Concrete fix:** Generate into a sibling staging directory, validate the exact
  24-file plan and WAV contract, then atomically replace final files. Add
  injected-failure and missing-zone controls.
- **Effort:** Small–Medium, approximately 2–4 hours

### Low — Published inventory omits nine of fourteen shipped families

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00154
- **Locations:**
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\crates\ferrosintesis-samples-orchestral2\README.md:13`,
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\crates\ferrosintesis-samples-orchestral2\Cargo.toml:6`,
  and
  `D:\worktrees\midi-music\20260727-REV-CLA@KILN-code-review-093105\crates\ferrosintesis-samples-orchestral2\src\lib.rs:8`
- **Evidence:** The README and Cargo description name five families and 50 WAVs.
  The complete packaged provenance and embedded inventory contain 14 families
  and 132 WAVs. Nine families and 82 assets are omitted. Crate rustdoc points
  readers toward the incomplete README/tooling rather than packaged
  `PROVENANCE.md`.
- **Impact:** crates.io consumers and auditors receive a false primary content
  inventory, although the complete provenance file is packaged and correct.
- **Concrete fix:** Make packaged `PROVENANCE.md` the named authority. Derive the
  README inventory or label it non-exhaustive, and remove the exhaustive-looking
  Cargo family list. Guard every surface that claims completeness.
- **Effort:** Small, approximately 30–60 minutes
