## Confirmed findings

### Medium — Sax regeneration trusts unauthenticated warm-cache inputs

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00157
- **Locations:**
  `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\tools\ferrosintesis-samples\prepare.py:3040`
  and
  `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\tools\ferrosintesis-samples\prepare.py:3129`
- **Evidence:** `_mtg_region_keys` accepts cached SFZ region text whenever the
  file exists. `_bake_mtg_sax` accepts cached source FLACs and decoded WAVs on
  the same existence-only predicate. It then measures and writes their
  derivatives at lines 3143–3160. These paths call raw `fetch` and ffmpeg, not
  the authenticated `ensure_source` or decoded-source-manifest helpers. The
  revision-keyed directory prevents cross-revision reuse, but it cannot detect a
  substituted file under the current revision or a stale decoded WAV after the
  recipe changes.
- **Impact:** A valid warm-cache substitution can become a tracked, published
  sax bank while
  `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\crates\ferrosintesis-samples-sax\PROVENANCE.md:27`
  still claims the pinned MTG revision. Warm and clean hosts can therefore
  produce different assets from the same source tree.
- **Concrete fix:** Authenticate SFZ and FLAC cache entries by exact URL and
  digest. Bind decoded WAVs to the FLAC digest, decode-recipe revision, and
  decoded digest; stage replacements atomically. Add poisoned SFZ, FLAC, WAV,
  changed-recipe, interrupted-decode, and good-cache controls. Extend the
  derived cache oracle to catch bespoke bake helpers that call raw `fetch`.
- **Effort:** Medium, approximately 4–8 hours
- **Deduplication:** Closed MM-BUG-KILN-00151 fixed the shared
  `ensure_source` route. The sax helper bypasses that route, so this is a
  distinct residual rather than a duplicate.

### Medium — Published sax crate omits the CC BY 3.0 licence URI

- **Confidence:** High
- **Tracking:** MM-BUG-KILN-00158
- **Locations:**
  `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\crates\ferrosintesis-samples-sax\NOTICE:4`
  and
  `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\crates\ferrosintesis-samples-sax\Cargo.toml:7`
- **Evidence:** The crate declares `CC-BY-4.0 AND CC-BY-3.0` and is separately
  publishable. Its packaged notice links the 4.0 licence but only names 3.0.
  No packaged file supplies the CC BY 3.0 licence text or canonical URI.
  Section 4(a) of the official legal code requires every distributed copy to
  include a copy of, or URI for, that licence:
  <https://creativecommons.org/licenses/by/3.0/legalcode.en>.
- **Impact:** A redistributor following only this package's shipped notice can
  redistribute 74 CC BY 3.0-derived recordings without the licence copy or URI
  required by those terms. The parent synth's notice has the URI, but this
  sample crate can be distributed independently.
- **Concrete fix:** Add
  `https://creativecommons.org/licenses/by/3.0/` to the sax notice. Preserve
  the exact upstream Freesound pack links where practical. Strengthen the
  licensing oracle so every declared CC-BY operand requires its canonical URI
  or packaged legal text, with a negative sax control.
- **Effort:** Extra small to small, approximately 30–90 minutes
- **Deduplication:** Closed MM-BUG-KILN-00068 corrected the compound SPDX
  declaration and named both licence layers. It did not supply the missing 3.0
  licence URI.

## Report-only hardening

`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-032703\crates\ferrosintesis-samples-sax\src\lib.rs:329`
calls `EXPECTED_BYTES` an accidental re-cut guard, but every current WAV is
55,432 bytes and the fixed-duration generator preserves that length. The local
test therefore cannot see a same-length content substitution and validates only
RIFF/WAVE magic, not full PCM fields.

This is not a separate defect or Draft requirement. All current assets satisfy
the complete format contract, downstream `parse_wav` validates mono/44.1
kHz/16-bit PCM, and prewarm coverage reaches all eight sax banks. The confirmed
cache-authentication bug is the correct layer for preventing untrusted source
content from becoming a same-length output. A future family-wide oracle may
still add bounded RIFF parsing and content digests.
