## Actionable findings

### Low — Public metadata and regeneration omit the GM32 pizzicato family

- **Confidence:** High
- **Tracked as:** `MM-BUG-KILN-00160`
- **Primary locations:**
  - `crates/ferrosintesis-samples-strings/README.md:24-25`
  - `crates/ferrosintesis-samples-strings/Cargo.toml:6`
  - `crates/ferrosintesis-samples-strings/src/lib.rs:1-12`
  - `crates/ferrosintesis-samples-strings/README.md:3-7`
  - `crates/ferrosintesis-samples-strings/PROVENANCE.md:16-19`
- **Evidence:** The crate packages 40 WAVs: 16 `cellosolo_*`, 16 `dbass_*`, and
  8 `pizzbass_*`. The README's public command selects only `cellosolo,dbass`.
  `tools/ferrosintesis-samples/prepare.py:3339-3347`, `:3394-3402`, and
  `:3535-3547` prove that `--only` processes exactly the named families, so that
  recipe rebuilds 32 files and leaves all eight GM32 outputs untouched. The
  Cargo description, crate rustdoc, and README introduction also describe a
  bowed GM42/43-only package even though `src/lib.rs:149-179` embeds GM32
  pizzicato samples.
- **Impact:** A maintainer can complete the documented rebake successfully while
  20% of the package remains stale. crates.io, docs.rs, and README summaries
  materially misstate the package's contents and GM32 behavior.
- **Root cause:** Incomplete remediation of closed `MM-BUG-KILN-00069`. Commit
  `96e2a47` added the missing table row and a correct command to PROVENANCE, but
  left the README command and public summaries unchanged. The bug and
  `PROVENANCE.md:16-19` nevertheless say they were corrected. Commit `23f648b`
  only changed the interpreter spelling; it did not introduce the omission.
- **Concrete fix:** Add `pizzbass` to the README selector. Correct or canonically
  delegate the Cargo description, crate rustdoc, README introduction, and stale
  PROVENANCE claim. Extend the source-derived inventory checks with adversarial
  cases for (a) a complete table plus an incomplete `--only` selector and (b) a
  two-of-three public family summary.
- **Effort:** Small for metadata; Small–Medium including durable oracle coverage.

## Not reported as new bugs

- **Current WAV corruption or format drift — refuted.** Static RIFF inspection
  found all 40 assets internally length-consistent, nonempty PCM, mono, 44.1 kHz,
  and 16-bit. The 40 filenames in `samples/` exactly match the 40 embedded names,
  and their SHA-256 values are unique.
- **Asset/package inventory drift — refuted.** `src/lib.rs:202-224` checks exact
  filesystem/table equality, `FILE_COUNT` derives from the table, and
  `Cargo.toml:10` includes the intended source, samples, README, provenance, and
  CC0 legal text.
- **Linear `get()` lookup is a scale problem — refuted.** `src/lib.rs:188-193`
  performs allocation-free lookup over a fixed 40-entry table. No source evidence
  showed it on an audio-rate hot path.
- **Minimal crate-local WAV assertions — not a present defect.**
  `src/lib.rs:226-235` checks only RIFF/WAVE signatures, but every current asset
  satisfies the fuller documented format and the consumer validates that format.
  Strengthening this test is prevention debt, not a current failure.
- **Obsolete-output validation on the shared generator path — not split here.**
  The current `main()` validation call appears scoped to `headroom`, so a future
  removed string source could leave a family-owned WAV behind. No stale string
  WAV exists today, and open `MM-BUG-KILN-00156` already owns the behavioral
  enumeration gap that should force every packaged writer, including `main()`,
  through complete output-inventory validation. This is supporting evidence for
  that open bug, not a duplicate ID.
- **Separate tickets per misleading surface — refuted.** The README recipe,
  Cargo description, rustdoc, README introduction, and false PROVENANCE claim all
  omit the same intentional family and share one correction/oracle sweep.
