## Actionable findings

### Low — Kawai rebakes can retain and republish obsolete WAVs

- **Confidence:** High
- **Tracked as:** `MM-BUG-KILN-00163`
  (`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\bugs\MM-BUG-KILN-00163.md`)
- **Primary locations:**
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\prepare.py:727`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\prepare.py:5324`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\prepare.py:5526`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\gen_crate_lib.py:30`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis\src\inventory.rs:171`
- **Evidence:** `KAWAI_SOURCES` is written by the generic main loop, but main
  validates only the `headroom` family before writing. Removing or renaming a
  Kawai mapping therefore leaves its old WAV in the package directory.
  `gen_crate_lib.py` scans that directory and re-embeds the leftover. The
  source-derived guard models validation as one unscoped boolean, so
  Headroom's conditional, family-specific validation incorrectly satisfies
  the guard for every later family.
- **Impact:** Retiring a bad Kawai source or zone can appear successful while
  the obsolete timbre remains embedded and published. The current 48-file
  inventory is internally consistent; this is a confirmed regeneration
  failure mode, not a claim that a stale file exists today.
- **Concrete fix:** Validate `("kawai", KAWAI_SOURCES)` before any selected
  Kawai write. Make the guard associate validation with its family and expected
  set. Add a negative control that removes one Kawai mapping while leaving its
  old WAV on disk.
- **Effort:** Small–Medium.

### Low — Logical layer aliases duplicate one-third of packaged and decoded PCM

- **Confidence:** High
- **Tracked as:** `MM-BUG-KILN-00162`
  (`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\bugs\MM-BUG-KILN-00162.md`)
- **Primary locations:**
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\prepare.py:731`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis-samples-vcsl-kawai\src\lib.rs:12`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis\src\sampler.rs:326`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis\src\sampler.rs:3170`
- **Evidence:** SHA-256 grouping found 16 byte-identical pairs. For every zone,
  `pp_rr2` equals `mf`, and `mf_rr2` equals `f_rr2`, exactly as the deliberate
  adjacent-velocity source map predicts. The duplicate files consume
  2,128,768 bytes. The six independent Kawai caches parse each logical entry
  into a fresh `Vec<f32>`, so prewarm also retains 4,256,128 avoidable decoded
  bytes and performs 1,064,032 redundant sample conversions.
- **Impact:** The default embedded bank pays 33.3% unnecessary package and
  decoded-memory overhead. The musical mapping is intentional and correct; the
  defect is materializing logical aliases as duplicate physical and decoded
  payloads.
- **Concrete fix:** Preserve exact-name behavior through declared aliases,
  canonicalize the packaged bytes, share the two duplicate decoded-bank pairs,
  and reject undeclared duplicate payloads with a source-derived oracle.
- **Effort:** Medium. Public exact-name lookup and generated-inventory
  compatibility must remain intact.

### Low — Packaged provenance names the wrong sources for 12 WAVs

- **Confidence:** High
- **Tracked as:** `MM-BUG-KILN-00161`
  (`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\bugs\MM-BUG-KILN-00161.md`)
- **Primary locations:**
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis-samples-vcsl-kawai\PROVENANCE.md:38`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\tools\ferrosintesis-samples\prepare.py:723`
  - `D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\crates\ferrosintesis\src\sampler.rs:1373`
- **Evidence:** The packaged table says sounding A2 comes from source label A0
  and sounding A3 comes from A1. The generator uses A2 from A1 and A#3 from
  A#2. Embedded names and measured roots around 109 Hz and 232 Hz corroborate
  the generator. The contradictory table and generator mapping entered in the
  same original commit, so this is not an inference from later drift.
- **Impact:** The separately published crate gives auditors and maintainers a
  false exact-source identity for 12 of 48 WAVs. Runtime audio and the CC0
  licence are unaffected.
- **Concrete fix:** Correct the rows to `A2 → A1` and `A#3 → A#2`. Add a
  derived comparison between `_KAWAI_ZONE_LABEL` and the packaged table, with
  an intentionally wrong-row negative control.
- **Effort:** Small.

## Draft requirement

- `MM-REQ-KILN-00164` — Kawai sample assets must be independently verifiable
  against pinned inputs
  (`D:\worktrees\midi-music\20260728-REV-CLA@KILN-code-review-201002\reqs\MM-REQ-KILN-00164.md`).
  The current generated test checks aggregate bytes and container magic. All
  48 WAVs have the same byte length, so same-length silence, note swaps, or
  altered PCM can pass. The Draft calls for a non-mutating pinned-input rebake
  and independent format/root comparison. It is prevention debt; no current
  PCM corruption was found.

## Not reported as new bugs

- **False round-robin semantics — refuted.** VCSL supplies one recorded RR and
  the bank deliberately borrows adjacent velocity layers for variation.
  Within each selected dynamic, the two alternatives remain distinct. The
  performance finding concerns physical storage and decoding only.
- **Current WAV corruption or inventory drift — refuted.** Static inspection
  found 48 tracked, nonempty, internally length-consistent PCM16 mono 44.1 kHz
  RIFF/WAVE files. Their names exactly match the 48 embedded entries and the
  pinned 6,386,304-byte aggregate.
- **Runtime bank misrouting — refuted.** Zero-based GM program 1 selects
  `kawai_bank`, and all six layer/RR inventories use the expected packaged
  names and measured-root tables.
- **Missing legal/package files — refuted statically.** The manifest declares
  CC0-1.0 and includes source, samples, README, NOTICE, PROVENANCE, and
  LICENSE-CC0. The crate has no dependencies and forbids unsafe code.
- **Linear `get()` lookup as an audio hot path — refuted.** The fixed 48-entry
  exact-name search runs during one-time cache initialization, not per rendered
  sample.
- **Missing prewarm coverage — refuted.** Prewarm reaches every Kawai
  velocity/round-robin cache. Lazy decode is a documented setup-time tradeoff.
- **Separate bug for the missing provenance-map oracle — refuted.** It is the
  enabling test gap for `MM-BUG-KILN-00161` and belongs in that defect's fix.
