## Not reported

- **Refuted — current asset corruption or wrong inventory:** every current file is structurally coherent, uniquely hashed, embedded once, and named by its consumer zone. Acoustic identity was not claimed from structure alone.
- **Refuted — unsafe caller-controlled parsing:** the public crate performs exact-name lookup over compile-time bytes. The B1 runtime parser uses checked chunk arithmetic and validates RIFF size, format/data cardinality, padding, terminal-tail position, and metadata.
- **Refuted — linear lookup is a scale defect:** B1 lookup occurs during cached bank initialization; NoteOn uses predecoded zones. Decode cost dominates the fixed 52-name search.
- **Refuted — repeated prewarm calls create repeated caches:** velocity sweeps reach only two `OnceLock` banks, so normal and hard decode once each.
- **Refuted — memory use is accidental:** approximately 9.80 MiB embedded plus 25.98 MiB decoded storage is the documented self-contained/realtime-prewarm trade-off, and embedded samples remain feature-gated.
- **Refuted — partial-bank replacement violates the accepted design:** the B1 HLD explicitly accepts per-file atomic replacement with Git as recovery rather than a 52-file filesystem transaction.
- **Report-only wording:** the claim that equal-tempered playback "keeps Railsback stretch" can mean retained inharmonic partial spread rather than a stretched fundamental; intent is ambiguous, so it is not filed.
