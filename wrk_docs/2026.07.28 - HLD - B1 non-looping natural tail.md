# B1 non-looping natural tail

Status: SELF-APPROVED

## Intent

Keep the accepted Yamaha B1 attack and body, then continue with the same note's
real recorded decay in a compact non-looping representation. Remove the synthetic
handoff and the audible periodicity of a sustain loop.

Success means the GM0 default B1 sounds like one continuous recorded piano note,
keeps its two captured velocity layers and felt-damper release, stays within the
sample package ceiling, and changes no alternate piano or samples-off behaviour.

## Scope

- Preserve each current 44.1 kHz PCM16 B1 body and its exact first 30 ms.
- At source frame 59,535 (1.35 seconds), begin the contiguous natural tail from
  the same processed and normalized recording.
- Low-pass and decimate the tail by four to 11.025 kHz, then store one
  logarithmically companded byte per sample with mu=255.
- Crossfade from the current body to the decoded tail over the body's remaining
  approximately 150 ms. Play the tail once and apply an 80 ms terminal taper.
- Decode all tail bytes during the existing bank prewarm. The audio callback only
  interpolates already-decoded `f32` data.
- Retain the existing velocity split, zone selection, repitch bound, pitch bend,
  gain, and register-dependent felt-damper release.

Out of scope:

- Any loop, modal/additive handoff, granular continuation, new recording, third
  velocity layer, round robin, or generic codec for other sample banks.
- Changes to GM0 alternates, CC0 ordering, modeled-only builds, or other programs.
- Extending notes beyond the end of their captured 3.7–8.0 second recordings.

## Approach

### Asset bake and format

The B1 baker will construct the existing body and the full onset-aligned archival
note from the same high-pass, resample, onset, and peak-normalization path. It
will keep writing the body as ordinary PCM16 mono 44.1 kHz.

Each WAV will gain one RIFF chunk with FourCC `b1t `. Its body is:

1. version `u8` (`1`);
2. source-rate divisor `u8` (`4`);
3. reserved `u16` (`0`);
4. tail-entry source frame `u32` little-endian (`59_535`);
5. the remaining bytes, one companded tail sample each.

The tail starts at the encoded entry frame in the same normalized archival note.
The transform is pinned to the accepted probe implementation:

- filter only the tail beginning at source frame 59,535;
- construct 63 taps indexed `0..62`, centred at tap 31, with
  `fc = 4_800 / 44_100`, the ordinary symmetric sinc, and the symmetric Hamming
  window `0.54 - 0.46*cos(2*pi*n/62)`;
- divide every coefficient by their sum;
- convolve at centres `0, 4, 8, ...`, treating every out-of-tail input index as
  zero, so the decimation phase is anchored to tail frame zero; and
- emit `ceil(tail_frames / 4)` values.

For each filtered sample `x`, clamp it to `[-1, 1]`, then:

`y = sign(x) * log1p(255 * abs(x)) / log1p(255)`

`(y + 1) * 127.5` is rounded to the nearest integer with ties to even, then
clamped to `[0, 255]`. Runtime decoding maps `q` to `z = q / 127.5 - 1` and
returns `sign(z) * expm1(abs(z) * log1p(255)) / 255`.

The probe then linearly expands the tail for comparison: for output frame `i`,
`p=i/4`, interpolate samples `floor(p)` and `floor(p)+1`, and repeat the last
tail value past its final neighbour. During the overlap, frame `j` uses
`t=(j-entry)/(body_frames-entry)`, `body*(1-t)+tail*t` while `j<body_frames`,
then tail alone. The final `floor(0.080*44_100)` expanded frames are multiplied
by `1-i/fade_frames`. Runtime implements the same equations without materializing
the expanded tail.

These details define the representation Arthur found indistinguishable from the
44.1 kHz natural tail in the hard A4 and hard C7 probes. Their accepted PCM16 WAV
digests are pinned as end-to-end validation controls:

- hard A4 natural:
  `4F209D8A0E27179F35F81265FAC5E751F1E1808B0299685BE6CC453CF1BF70E9`
- hard A4 companded:
  `943ADB4A83F63FBD411D6E2DE515DDDFD2086AAADEDD13986D9597E906E61DDE`
- hard C7 natural:
  `AD92BDF6C88170EC06B31B781029D7C9703BC8DB89F0F4D49B06CF4D1112A178`
- hard C7 companded:
  `EE909F0F4D7EF920BF85B979D35D3172565547FB2AAA8DB0310BF6F148CF6C51`

The writer includes the extension in RIFF's size field, records the unpadded
`b1t ` body length, and appends one zero pad byte when that length is odd. The
strict validator bounds traversal by the declared RIFF end, uses checked offset
arithmetic, requires one sufficiently long PCM16/mono/44.1 kHz `fmt ` chunk, one
`data` chunk, and exactly one terminal `b1t ` chunk, and rejects truncation,
overflow, duplicates, bytes beyond RIFF, nonzero reserved fields, unsupported
versions/divisors, empty payloads, or an entry outside the PCM body.

The baker stages and validates all 52 complete files under unique same-directory
temporary names before publishing any of them. Each destination replacement is
atomic; the 52 replacements are deliberately not described as a bank
transaction. A failure cannot leave a truncated WAV, and Git remains the
recovery mechanism if publication stops between files. Inventory remains exactly
25 normal and 27 hard WAVs. Python's standard `wave` reader must still read each
unchanged PCM body.

### Runtime

`Zone` gains an optional B1 tail. The ordinary `bank!` macro always sets it to
`None`; a B1-only macro requires and decodes the `b1t ` chunk while constructing
the existing normal and hard caches. This keeps all allocation and logarithmic
decode work inside the prewarmed `OnceLock` path. A test-only tail-decode counter
proves that real note-ons after prewarm do not parse, allocate a tail buffer,
filter, or decode companded data. The existing `Box<dyn Voice>` note-on allocation
is unchanged and is not part of that claim. Prewarm documentation records the
approximately 13.4 MB decoded-tail memory increase.

`B1Sampled` keeps one source-domain 44.1 kHz read position:

- before frame 59,535, read only the body with the existing cubic interpolation;
- from frame 59,535 to body EOF, linearly crossfade that body read with a linear
  read from the 11.025 kHz tail;
- after body EOF, read only the tail;
- during the last 80 ms of the tail, multiply by a linear terminal taper; and
- stop at the natural tail end.

Pitch and pitch bend advance the shared source-domain position exactly as today.
Note-off continues multiplying the held recording by the existing felt-damper
exponential. Modeled-only builds still return the existing modeled piano.

The accepted filter attenuates a 5.6 kHz tone by about 25 dB and a 6 kHz tone by
about 55 dB relative to 2 kHz before their energy can fold across the 5.5125 kHz
decimation boundary. Tests pin those boundary-relevant values rather than only a
remote 7 kHz stop-band point. Low-output-rate pitch shifting retains the generic
sample reader's existing interpolation behaviour; the compact tail does not
widen the B1 body's source bandwidth or claim to repair that separate resampler.

### Package and rendering

The 52 tail payloads are expected to add about 3.36 MB before package compression.
The actual `cargo package` archive, not the unpacked source tree, is the
crates.io limit-bearing artifact. The build is accepted only if that archive is
at most 9.5 MiB, leaving at least 5% below the 10 MiB limit.

The first implementation unit generates all 52 real payloads, appends them to
staged copies of the assets, and measures the real package before any runtime
work. If the combined archive misses the margin, the unchanged `b1t ` bodies move
to a second first-party B1-tail asset crate. That fallback changes packaging
only: the bytes, decoder, interpolation, and accepted signal remain identical,
while each asset crate remains independently below crates.io's 10 MiB cap.

The mandatory render-diff inventory will use the branch base commit as its
baseline. Every changed render must be explained by GM0 usage; tracks without
GM0 must remain byte-identical.

## Acceptance criteria

1. Baking from the two committed Opus sources is deterministic and produces the
   exact existing 25-normal/27-hard WAV inventory. Every WAV has exactly one
   valid version-1 `b1t ` chunk; malformed, duplicate, unsupported, empty, or
   out-of-range chunks fail closed. Odd/even chunk padding, RIFF bounds, and
   standard-reader compatibility have positive and negative controls.
2. Each baked PCM `data` chunk is byte-identical to the current sample-only PCM
   body; only RIFF metadata and the appended chunk differ. The existing
   parent-first-30-ms runtime parity oracle remains green. Two clean rebakes
   produce the same SHA-256 over sorted filename-plus-complete-WAV bytes.
3. The Python compander round-trips every code point consistently with a Rust
   decoder oracle. Synthetic full-scale and quiet decays stay bounded, finite,
   monotonic in code magnitude, and free of clipping beyond the explicit input
   clamp. The baker rejects a source tail containing an exact-zero run of 10 ms
   or longer, and the decoded final 100 ms after its designed taper has absolute
   mean below `1e-4`, preventing silent padding from becoming a DC shelf.
4. The decimator is deterministic, has unity DC gain within 0.01, attenuates
   5.6 kHz by at least 20 dB and 6 kHz by at least 45 dB relative to 2 kHz, and
   emits exactly `ceil(input_frames / 4)` samples. A real-tail folded-energy
   report covers every zone and flags any outlier above the accepted A4/C7
   controls.
5. At 44.1, 48 and 96 kHz output, a held B1 voice in both layers, at zone roots
   and worst covered repitches, with -2/0/+2-semitone bend:
   - is identical to the current sample-only voice before tail entry;
   - has each entry/EOF seam step no larger than the local body-only
     99th-percentile step plus two PCM16 quantization steps;
   - differs by no more than 1 dB from the contiguous full-rate reference's own
     adjacent 20 ms RMS change across tail entry or body EOF;
   - remains alive beyond the old body EOF when recorded tail data exists;
   - applies one smooth 80 ms terminal taper and stops at the natural end; and
   - performs no tail-data allocation, file parsing, filtering, or logarithmic
     decode after `prewarm`.
   The body-only control is built from the same zone rather than retained
   duplicate production code.
6. Note-off before tail entry, during crossfade, and during tail playback follows
   the current register-dependent felt-damper curve within the existing oracle
   tolerance. Pitch bend changes sample read rate without a discontinuity.
7. Samples-off and non-embedded builds retain the modeled B1 fallback. All GM0
   alternate slots, their renders, and their ordering are unchanged.
8. The packaged B1 sample crate is no larger than 9.5 MiB. Its test pins the
   exact aggregate embedded byte count and tail payload count.
9. The focused Python and Rust tests pass, then the complete sample-tool Python
   suite, workspace format check, workspace clippy with warnings denied, and
   project test suite pass with stdin closed.
10. For every zone, the complete shipping crossfade is compared with its
    contiguous full-rate archival reference. Over the overlap it requires at
    least 20 dB normalized waveform SNR, no coarse frequency-band energy delta
    above 3 dB, and no spectral-centroid delta above 10%. The accepted hard A4
    and hard C7 probe paths also reproduce the four pinned PCM16 digests above;
    any digest change requires another focused listening check.
11. Render-diff reaches every catalogue/test-corpus track that uses GM0 and no
    track without GM0. Fresh Tubular Bells and dry B1 diagnostics contain the
    shipped non-looping tail and no repeating `wa-wa` fade.
12. Arthur's blind probes remain the perceptual gate: hard A4 and hard C7 showed
    no audible A/B difference between this companded tail and the full-rate
    natural reference. No parameter is changed after that accepted experiment
    without another focused listening check.

## Decision log

- Reject the direct long loop. Arthur identified a repeating quiet `wa-wa-wa-wa`
  in its fade and classified all eight blind trials correctly.
- Ship the natural tail because it removes repetition by construction. Arthur
  could not distinguish its compact form from the full-rate natural recording
  in either the common upper-middle hard A4 probe or the worst-SNR hard C7 probe.
- Preserve the exact tested representation: 1.35-second entry, 11.025 kHz,
  63-tap/4.8 kHz low-pass, mu=255 one-byte companding, linear tail interpolation,
  body-to-tail crossfade, and 80 ms terminal taper.
- Put the tail inside its existing WAV as a versioned RIFF chunk. This retains
  one asset per zone and lets every non-B1 WAV reader ignore the extension.
- Decode into `f32` during prewarm. About 13.4 MB of decoded tail memory is a
  simpler and safer trade than logarithms, allocation, or custom byte
  interpolation on the audio thread.
- Gate the real package archive, not the unpacked asset tree. The crates.io cap
  applies to the compressed `.crate`; a 5% archive margin remains mandatory.
- Measure all real payloads before runtime implementation. Fable identified
  package compression as the only remaining architectural risk. If the combined
  archive misses its margin, a second first-party tail asset crate preserves the
  exact accepted signal and avoids reopening representation design.
- Keep the natural recorded endpoint. Manufacturing an indefinite sustain would
  recreate the original problem under a different mechanism.
- The two native reviewers' findings all survived cross-refutation except the
  claim that runtime repitch changes the bake-time decimation boundary. The
  design now pins the exact accepted transform and digests, strictly validates
  RIFF structure, states per-file publication truthfully, narrows realtime work
  to tail data, tests boundary folding, retains an executable body control, and
  adds all-zone waveform and spectral splice gates.
- The single external Fable pass found no audible-fidelity defect or simpler
  shipping mechanism. Its significant package-sequencing point and its useful
  reference-relative RMS and silent-padding checks are incorporated above. No
  external finding was rejected.
