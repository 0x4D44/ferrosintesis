### `bbf122d` — the right act, the wrong subject line

This needed the hardest look, and the answer has two halves that both matter.

**It was legitimate, and I am not calling it a rule violation.** The banks were genuinely
unselectable through the synth: `sampled_drum` at `crates/ferrosintesis/src/sampler.rs:5099-5121` is a
closed static `match key` over 19 literal arms ending in `_ => return None`, with no dynamic or
name-based bank lookup and no alt-kit path into the sampled drum banks. Neither bank appears in any
arm — **no MIDI file, in-repo or foreign, could ever select them.** That is a correctness fact, not a
usage census, which is exactly the distinction CLAUDE.md's never-cull rule turns on. The scratchpad had
flagged it as unreachable on 2026-07-18, **Arthur explicitly approved the removal**
(`wrk_journals/2026.07.29 - JRN - approved scratchpad decisions.md:25`), and the render-diff proved all
124 MIDIs byte-identical. The escape hatch — *"ask Arthur rather than tidying it away"* — was used as
designed.

**But the commit subject is wrong, and the deleted code said so.** The removed `CRASH_SIZZLE` doc
comment read, verbatim:

```rust
/// Reachable through the `Bank` API but not routed by any GM channel-10 key.
/// That is deliberate: ferrosintesis is a generic GM player and this bank is
/// part of the public instrument. Do not cull it for lack of an in-repo user.
```

So "retire unreachable drum banks" is inaccurate at the crate-API level — these were `pub static`
items of library crates, reachable by any consumer. The journal body gets it right where the subject
does not (*"the public but unrouted banks"*). Two consequences: it is a **breaking public-API removal**
