## Confirmed findings

### CR-1 — Malformed Program Change data can panic rendering

- **Severity:** Medium
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\midi.rs:332-334`
- **Crash sinks:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\engine.rs:1200-1223`,
  `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\engine.rs:3814-3823`,
  and `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\voices.rs:14244-14261`
- **Tracked as:** `MM-BUG-CRUCIBLE-00003`
- **Effort:** Small

The parser accepts `C0 FF` as program 255. A melodic channel stores that value
unchanged, then the render loop indexes a 128-entry program-trim table with it.
Default rendering reaches the crash without a NoteOn because its six-second
tail produces blocks. This is a safe-Rust availability failure for corrupt or
hostile MIDI.

**Concrete fix:** enforce a consistent seven-bit channel-data policy at the
parser boundary. Mask Program Change with `& 0x7F`, matching the existing
malformed-note-key policy, or reject it with a typed error. Add parser and
public-render regressions for `C0 FF`.

### CR-2 — Equal-tick tempo changes lose authored order

- **Severity:** Medium
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\midi.rs:230-231`,
  `:270-280`, and `:361-383`
- **Affected API:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\midi.rs:416`
- **Tracked as:** `MM-BUG-CRUCIBLE-00004`
- **Effort:** Small

Tempo entries store no encounter sequence and use tuple
`sort_unstable()`. Equal-tick entries are therefore ordered by numeric
microseconds per quarter. The largest number always governs the following
interval, regardless of source order. For tick-zero changes of 1,000,000 then
500,000, the timeline renders at 60 BPM while `initial_bpm()` reports 120 BPM.

**Concrete fix:** retain encounter order, collapse duplicate ticks with
last-authored-wins semantics, and derive `initial_bpm` from the effective
tick-zero value. Test both value orders.

### CR-3 — Event reads can cross a declared `MTrk` boundary

- **Severity:** Medium
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\midi.rs:236-256`
  and `:332-358`
- **Tracked as:** `MM-BUG-CRUCIBLE-00005`
- **Effort:** Small–Medium

The parser checks only that an event starts before a track's declared end.
Reads stay bounded by the whole file, so an incomplete event can consume the
next chunk's bytes. The parser then rewinds to the declared end and parses those
bytes again. A two-byte track `00 C0` followed by a valid `MTrk` header consumes
the header's `M` as program 77 and still parses the next track.

**Concrete fix:** parse each declared track payload through a track-local
cursor. Add a two-track regression whose first track ends inside a Program
Change and require `UnexpectedEof`.

### CR-4 — Realtime voice buckets allocate above 64 same-channel voices

- **Severity:** Medium
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\engine.rs:2050-2059`,
  `:2156-2161`, `:2383-2390`, and `:3365-3387`
- **Public setup seam:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\live.rs:229-236`
- **Tracked as:** `MM-BUG-CRUCIBLE-00006`
- **Effort:** Small

`reserve_realtime_storage()` reserves the active-voice vector to the live cap
of 128, but each per-channel index bucket keeps capacity 64. Sixty-five held
voices on one channel therefore reallocate a bucket inside
`render_block_add`, contradicting the allocation-free render-path claim. This
is distinct from the accepted per-voice `Box` allocation: it is a missed
setup-time `Vec` reservation.

**Concrete fix:** reserve every bucket to the live cap and extend the
allocation oracle with 65–128 held voices on one channel.

- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260731-REV-CLA@CRUCIBLE-code-review-014814\crates\ferrosintesis\src\drums.rs:1383-1395`,

  `:5099-5128`
- **Tracked as:** `MM-REQ-CRUCIBLE-00007` (Draft, Could, heavy)
- **Effort:** Medium

Current values agree, so this is not a live bug. Routing, levels, repitch,
jitter class, hybrid body parameters, and test expectations are separate
