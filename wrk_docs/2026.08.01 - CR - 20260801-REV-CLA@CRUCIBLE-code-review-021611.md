# Code review — `crates/amp-lab/`

Date: 2026-08-01
Mode: static, read-only review
Area: `crates/amp-lab/`

## Outcome

This pass confirmed seven defects: three Medium and four Low. The two highest-value
findings are residuals in earlier realtime fixes: a recovery snapshot is not atomic to
the consumer, and a legal command backlog can exceed the synth's 128-command reservation
inside the audio callback.

Seven Open bug records were added: MM-BUG-CRUCIBLE-00012 through
MM-BUG-CRUCIBLE-00018. No source, build, manifest, or existing tracked file was changed.
The application, audio hardware, test suite, and exploratory-test harness were not run.

## Review method

Seven independent lenses reviewed the same slice: correctness, security,
performance/scale, reliability, maintainability, test coverage, and devil's advocate.
The lead re-read every cited control path and deduplicated against the bug and requirement
ledgers. Only findings that survived adversarial review appear below.

## Confirmed findings

### 1. Medium — recovery snapshots are prefix-visible

- **Confidence:** High
- **Tracked:** MM-BUG-CRUCIBLE-00012
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\outbox.rs:107`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\ring.rs:143`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\ring.rs:163`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\audio.rs:304`
- **Defect:** Capacity is preflighted, but each MIDI byte publishes a new `head`. The
  consumer can render a complete bank/program prefix before later NRPN and transport
  commands become visible. This disproves the atomic-snapshot claim made by the fix for
  MM-BUG-KILN-00083.
- **Concrete fix:** Add a bulk producer operation that fills unpublished slots and
  publishes the final head once. Batch rig + Play + Solo together. Add a forced
  producer/consumer interleaving oracle.
- **Effort:** Medium, roughly 1-2 days including concurrency regression coverage.

### 2. Medium — backlog recovery reallocates before rendering

- **Confidence:** High
- **Tracked:** MM-BUG-CRUCIBLE-00013
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\ring.rs:29`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\audio.rs:304`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\ferrosintesis\src\live.rs:188`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\ferrosintesis\src\live.rs:484`
- **Defect:** One callback can drain 4,095 ring entries into a `Vec` reserved for 128
  completed MIDI commands. More than 128 messages reallocates on the audio thread, and
  every command is processed before audio resumes. The work is bounded by the ring, but
  not by the realtime reservation or a callback budget.
- **Concrete fix:** Coalesce state commands, bound per-callback control work, and give the
  remaining MIDI batch an explicit fixed-capacity overflow policy. Add allocation and
  work-budget tests above 128 commands and at full-ring occupancy.
- **Effort:** Medium-large, roughly 2-4 days because the correct policy spans amp-lab and
  the public realtime synth surface.

### 4. Low — the sequencer uses the last scanned tempo

- **Confidence:** High
- **Tracked:** MM-BUG-CRUCIBLE-00014
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:53`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:108`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:138`
- **Defect:** Documentation promises the first Set-Tempo, but every tempo overwrites one
  variable and the final scanned value retimes the whole loop. The committed loop has one
  tempo, so current playback is unaffected.
- **Concrete fix:** Reject a second tempo, matching the declared constant-tempo subset, or
  retain only the first. Test two tempos and format-1 track-order independence.
- **Effort:** Small, under half a day.

### 5. Low — non-f32 fallback always chooses the maximum rate

- **Confidence:** High for selection; Medium for user impact
- **Tracked:** MM-BUG-CRUCIBLE-00016
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\audio.rs:263`
- **Defect:** The fallback selects the first f32 range and calls
  `with_max_sample_rate()`. A wide range therefore selects 96/192 kHz rather than a normal
  default/nearby rate. Actual xruns are unverified because this pass used no hardware.
- **Concrete fix:** Prefer the device default when supported, then 48/44.1 kHz, then the
  nearest supported rate. Unit-test the pure selection policy.
- **Effort:** Small, under one day.

### 6. Low — malformed tracks can panic or silently parse

- **Confidence:** High
- **Tracked:** MM-BUG-CRUCIBLE-00017
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:77`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:102`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:108`
- **Defect:** A declared missing track returns `Ok`; a terminal `0xFF` can index at the
  track end; and meta bounds use the file rather than track boundary. The only production
  input is embedded, so this is not an external security boundary.
- **Concrete fix:** Make every read track-bounded and fallible. Add truncated VLQ, meta,
  SysEx, terminal-status, and missing-track cases.
- **Effort:** Medium, roughly 1-2 days for systematic parser hardening.

### 7. Low — event-cap overflow permanently drops MIDI state

- **Confidence:** High
- **Tracked:** MM-BUG-CRUCIBLE-00018
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\audio.rs:141`,
  `D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\seq.rs:216`
- **Defect:** At 256 scheduled events, the emitter drops later events while the player
  permanently advances past them. A NoteOff can be lost and leave a voice sounding. The
  code comment claims it keeps the event. The current backing remains far below the cap.
- **Concrete fix:** Use a bounded fallback that preserves MIDI semantics while degrading
  offsets, or stop and reset cleanly. Test a block with more than 256 paired note events.
- **Effort:** Medium, roughly 1-2 days to choose and prove the overflow policy.

## Actionable structural debt

Amp-lab is intentionally outside the root Cargo workspace to preserve the root's offline
dependency closure, but no integration step compiles, lints, or tests it. This matters
because critical realtime allocation and scheduling oracles live only in
`D:\worktrees\ferrosintesis\20260801-REV-CLA@CRUCIBLE-code-review-021611\crates\amp-lab\src\audio.rs:399`.
The intended Draft requirement is:

> The integration policy must run an amp-lab compile/lint/test gate when
> `crates/amp-lab/` changes or when the ferrosintesis realtime API it consumes changes,
> without adding amp-lab back to the root workspace or weakening the root offline-build
> invariant.

No requirement was filed. `deltic reqs new` failed once because the sandbox cannot open
the clone-wide mint lock at `D:\language\ferrosintesis\.git\deltic-ledger-mint.lock`.
The `reqs-capture` workflow forbids hand-minting a fallback ID.

## Not reported as defects

- The current MIDI parser is not an attacker-controlled boundary: only the embedded
  `backing.mid` reaches it. Malformed-input handling remains a Low reliability bug, not a
  security vulnerability.
- The SPSC ring's unsafe memory protocol is sound under its enforced one-producer,
  one-consumer contract; endpoints are `Send` and deliberately not `Sync`.
- Large device callbacks are chunked through fixed scratch storage; no callback-size
  overflow was found.
- Per-NoteOn voice allocation is already tracked as MM-BUG-KILN-00092; it was not filed
  again.
- Amp NRPN constants/names are covered by a derived oracle in the root gated crate.
- Missing Play/Solo recovery assertions, exact `push_midi` content checks, and a semantic
  Solo audio oracle are useful coverage additions, but no separate present behavior defect
  was established. They belong with fixes to MM-BUG-CRUCIBLE-00012/00013 or a future
  focused test task.
