## Headline

**The committed music was carrying a defect for at least six days, and the oracle built to prevent
exactly that class of defect — independently two-eyes verified with a from-scratch scanner — was
sitting on top of it and could not see it.**

`3fbe77f` hardened the catalog MIDI overlap oracle. The hardened oracle immediately found
**111 zero-tick note-on/off pairs across 26 committed album MIDIs**, spanning **all five** model
directories. Every affected album was regenerated; the `.mid` files — the repo's declared source of
truth — changed.

The cause is the `_resolve_overlaps()` clamp in the Python album writers. When two note-ons share a
tick, the clamp pulls the first note's off back to that same tick, producing a zero-length note.
Serialization then emits the off *before* both ons, leaving an orphaned off/on pair and making later
re-strikes ambiguous. I read the diff at `albums/opus4-8/engine.py` and the new code collapses
simultaneous duplicate starts before clamping distinct re-strikes; 22 writer copies were changed.

**The blind spot is the finding, not the notes.** `MM-BUG-KILN-00056` (Closed 2026-07-25, `ff3928c`)
back-ported that clamp to six lagging writers *and shipped a catalog-wide SMF oracle whose stated
purpose was to prevent committed overlaps from returning*. Its closure was rigorous — an independent
verifier wrote a fresh scanner and reproduced 10,398 pre-fix overlaps and 0 after
(`bugs/MM-BUG-KILN-00056.md:21`). That oracle then ran green over 111 orphaned lifecycles for six
days, because of three predicate holes `MM-BUG-CRUCIBLE-00008` enumerates: it built note maps
per-`MTrk` (blind to cross-track overlap), it stored only ticks (blind to same-tick on-before-off),
and it **skipped any key whose on/off counts differed** — which is precisely the shape the clamp
creates.

This is CLAUDE.md's own doctrine, one level deeper than the version already written there. The repo
knows "assert against something derived from the source, never a second hand-written list", and it
knows "a derived oracle is only as good as its enumeration predicate". What it did not have written
down is the specific trap that bit here: **an oracle that skips the ambiguous case is not clean on
it.** `album_midi_overlaps.rs`'s unbalanced-key `continue` was a silent exclusion, and the fix that
created the unbalanced keys and the oracle meant to catch them landed in the same commit.
