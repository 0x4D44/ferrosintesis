## Confirmed findings

### CR-1 — CLI numeric controls accept invalid domains

- **Severity:** Medium
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\src\main.rs:49-87,125-157`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis\src\engine.rs:1295-1304,1791-1818,4123-4125`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis\src\wav.rs:91-95`
- **Tracking:** blocked; proposed title `CLI numeric options accept invalid domains and can emit invalid output`, Priority Should
- **Problem:** parsing checks syntax but not ranges or finiteness. `--rate 0`
  reaches a zero-rate WAV header; negative tail can collapse the render length;
  NaN/Inf wet, loudness, or ceiling values reach DSP/normalization; a huge finite
  delay sizes two delay-line allocations directly. The current streaming path
  preflights RIFF length, so the older claim that every extreme value allocates a
  full output buffer is no longer valid.
- **Concrete fix:** parse into a validated CLI configuration before loading the
  MIDI. Require a supported nonzero rate, finite bounded wet/delay/tail values,
  and finite sensible loudness/ceiling values. Add table tests proving rejection
  creates no output.
- **Effort:** Small to Medium.

### CR-2 — `raw_dump` can destroy its MIDI input and leave partial output

- **Severity:** Medium
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\raw_dump.rs:18-43,65-83`; safe shipping contrast at `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\src\output.rs:12-38`
- **Tracking:** blocked; proposed title ``raw_dump` can overwrite its input and publish partial WAVs`, Priority Should
- **Problem:** the example loads and renders the MIDI, then opens the requested
  path with truncating `File::create`. An identical path, hard link, or symlink
  alias therefore replaces the source MIDI. A failed write also leaves a partial
  WAV at the final path. Closed `MM-BUG-KILN-00097` fixed the shipping CLI path,
  not this example path; this is a residual at a separate writer.
- **Concrete fix:** reject input/output identity using the shipping alias rules,
  write the float WAV through a same-directory temporary file, flush/sync it, and
  rename it only after success. Add same-path, hard-link, symlink, and injected
  write-failure oracles.
- **Effort:** Medium.

### CR-3 — `raw_dump` wraps classic-RIFF lengths above 4 GiB

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\raw_dump.rs:18-27,37-40`; safe shipping contrast at `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis\src\wav.rs:27-39,91-95`
- **Tracking:** blocked; proposed title ``raw_dump` wraps WAV headers for audio above the classic RIFF limit`, Priority Could
- **Problem:** `(interleaved_stereo.len() * 4) as u32` silently narrows the data
  length. A float-stereo render longer than about 3.38 hours at 44.1 kHz writes a
  header whose RIFF and data sizes no longer describe the file. The library
  accepts MIDI durations up to 24 hours, so source contracts do not exclude this.
- **Concrete fix:** checked-compute byte rate, data bytes, and RIFF size before
  opening the output. Return `InvalidInput` above the classic-RIFF limit, or use
  RF64 deliberately. Boundary-test the largest accepted and first rejected
  sample counts without allocating the audio.
- **Effort:** Small.

### CR-4 — `calmeter` drops a valid block at accepted non-round sample rates

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\calmeter.rs:133-164,284-294`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\support\wav.rs:117-121`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis\src\loudness.rs:110-143`
- **Tracking:** blocked; proposed title ``calmeter` drops trajectory blocks at accepted sample rates`, Priority Could
- **Problem:** the loudness meter rounds its 400 ms block and 100 ms hop to
  integer frames. `calmeter` instead derives selection bounds and TSV width from
  unrounded floating-point sizes. At accepted rate 8001 Hz, the meter produces a
  valid final onset block, but `calmeter` selects indices 4 through 11 and drops
  index 12; the header also advertises only eight blocks instead of nine.
- **Concrete fix:** derive selection and schema geometry from the same rounded
  integer block/hop values as the meter. Add an 8001 Hz synthetic fixture whose
  last valid block is nonzero, plus the ordinary 44.1/48 kHz cases.
- **Effort:** Small.

### CR-5 — non-Unicode command-line paths panic before diagnostics

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\src\main.rs:46`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\raw_dump.rs:46`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\measure_wav.rs:14`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\calmeter.rs:258`
- **Tracking:** blocked; proposed title `CLI panics on non-Unicode input or output paths`, Priority Could
- **Problem:** all entry points use `std::env::args`, whose documented contract
  panics when any OS argument is not valid Unicode. The shipping CLI therefore
  cannot render an otherwise valid MIDI stored at a non-Unicode Unix path, and it
  emits a panic instead of a controlled error.
- **Concrete fix:** parse paths from `args_os`; convert only option names and
  numeric values to Unicode with explicit diagnostics. Add a Unix integration
  fixture containing invalid UTF-8 in the input and output filenames.
- **Effort:** Medium.

### CR-6 — MIDI titles can spoof terminal and log output

- **Severity:** Low
- **Confidence:** High for display/log injection; terminal-specific OSC effects unverified
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\src\main.rs:129-136`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis\src\midi.rs:298-300`
- **Tracking:** report-only; already recorded as CR-3 on 2026-07-25
- **Problem:** lossy MIDI-title decoding preserves valid ASCII control bytes, and
  verbose output prints the title verbatim. A MIDI can alter the appearance of a
  terminal or captured log. No command execution was established.
- **Concrete fix:** escape C0/C1 and other terminal control characters while
  preserving printable Unicode; add a title containing ESC and newline.
- **Effort:** Small.

### CR-7 — calibration examples silently accept malformed command lines

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\raw_dump.rs:45-63`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-193046\crates\ferrosintesis-cli\examples\calmeter.rs:257-283`
- **Tracking:** report-only; documented generated invocations are exact
- **Problem:** `raw_dump` filters every `--...` token and consumes only two
  positional arguments, so `--no-sampls` and extra positionals are ignored.
  `calmeter` accepts undocumented `mu80`, `mu50`, and `--vs`, while malformed

  can produce plausible calibration output under the wrong mode.
- **Concrete fix:** use explicit parsers that reject unknown, duplicate, missing,
  malformed, and extra arguments; keep usage text generated from the accepted
  grammar. Add negative table tests.
- **Effort:** Small.

## Test coverage assessment

sample-rate floor, but not measurement geometry, clipping, parser behavior, or
the twin comparison. `tests/output_safety.rs` gives the shipping writer meaningful
cross-platform alias coverage, and `tests/wav_reader.rs` covers the shared decoder's
core layouts and bounds.

The highest-value missing oracles travel with CR-1 through CR-5: numeric parser
tables; raw-writer identity, atomicity, and RIFF-boundary tests; an 8001 Hz
trajectory fixture; and a Unix non-Unicode-path integration test.

## Not reported as defects

- **Shipping output aliasing — refuted.** The CLI rejects canonical, hard-link,
  and symlink identity before rendering. The library writes through owned sibling
  temporary files and replaces the destination only after completion.
- **WAV chunk walking can read out of bounds — refuted.** Checked chunk offsets,
  RIFF bounds, padding, layout, and frame alignment guard every indexed read.
- **`partial_cmp(...).unwrap()` receives NaN — refuted.** Non-finite loudness
  blocks are filtered before comparison.
- **Whole-file MIDI/WAV buffering is a demonstrated supported-scale defect —
  refuted for this pass.** Calibration files are generated in bounded chunks, and
  the shipping WAV path now streams. No practical failure inside the documented
  workflow was established.
- **Per-sample `write_all` is materially slow — unverified.** `BufWriter` coalesces
  physical writes, and this static-only pass could not measure CPU overhead.
- **Float WAV NaN/Inf produces a current bad calibration — unverified.** The reader
  preserves IEEE non-finite values, but no supported producer path to such a
  calibration input was established.
- **Render-profile drift — refuted.** Both the CLI and `raw_dump` now derive their
  defaults from `Options::default()`, with a source-derived parity oracle.
