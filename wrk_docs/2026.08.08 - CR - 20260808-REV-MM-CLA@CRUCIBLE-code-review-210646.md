## Confirmed defects

### Low — The VSCO piano bank embeds and decodes unreachable sample tails

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis-samples-core\src\lib.rs:14`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\voices.rs:1369`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\voices.rs:1423`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\sampler.rs:3444`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\sampler.rs:3884`
- **Tracking:** ready to file; `deltic bugs new` could not allocate an ID
- **Problem:** every piano WAV contains 79,732 frames, about 1.808 seconds. The reviewed bank is the VSCO upright at GM0 CC0=1 and retains `PianoSampleCal::Gm0Conditioned`. That calibration retires the sample at 0.45 output-seconds. `LaVoice` rejects source/output pitch ratios above 2.05 and advances the 44.1 kHz source by `ratio * 44100 / output_sr`, so even the maximum admitted ratio can reach only about 40,683 source frames before retirement. At least 39,049 frames—about 49%—are unreachable in every piano file.
- **Impact:** the 52 physical tails consume at least about 4.06 MB of embedded PCM and 8.12 MB of decoded `f32` heap after prewarm. The two logical single-take aliases make decoded use slightly larger. This excludes any final-linker effects, which were not built and remain unverified.
- **Concrete fix:** either trim the bake to the proved maximum read position plus a cubic-interpolation guard, or preserve the public WAV payload but decode only the reachable prefix. Add a source-time reachability oracle and a bit-exact differential check across roots, sample rates, and admitted pitch ratios. Update size and provenance claims.
- **Effort:** Small/medium

The devil's advocate initially marked this `needs_reverify` after confusing the
separate B1 calibration with this crate. Re-reading the actual CC0=1 dispatch at
`D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\altbank.rs:1106`
resolved it: the route selects `GM0_SOURCES[1]`, whose calibration is
`Gm0Conditioned`, and reaches the bounded `LaVoice` path.

### Low — Core rebakes can retain obsolete WAVs while the global oracle stays green

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\tools\ferrosintesis-samples\prepare.py:5421`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\tools\ferrosintesis-samples\prepare.py:5643`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\inventory.rs:224`; `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\inventory.rs:1020`
- **Tracking:** ready to file; allocator blocked after the first required mint failed
- **Problem:** `prepare.py::main` validates Steinway, Kawai, Headroom, and the two bass families before its generic write loop, but it never validates the selected piano, violin, or flute output inventories. Under `--only=piano`, those earlier conditional validators do not execute. If a source mapping is retired or renamed, the old core WAV remains on disk and the later table generator can re-embed it.
- **Why the existing guard misses it:** `PythonBakeEffects` records only three booleans: writes, validates, and validates-before-first-write. It neither binds a validator to the family it protects nor models whether the validator's branch runs for the selected family. Consequently, the presence of an unrelated conditional validator before the generic writer satisfies `every_generated_bake_output_family_is_inventory_validated`.
- **Concrete fix:** derive each write's owned family and require a matching expected-set validation on every selector path before that family's first write. Add a negative fixture matching `main`: a `--only=piano` branch, an unrelated earlier Steinway validator, and a stale `piano_old.wav` after its source mapping is removed.
- **Effort:** Small/medium

The committed core directory is clean. The defect is the live false-negative in
the guard and regeneration path, not a claim that a stale file ships today.

### Bind each core payload and runtime root to one authoritative manifest

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis-samples-core\src\lib.rs:305`; runtime roots at `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\crates\ferrosintesis\src\sampler.rs:405`; generator source map at `D:\worktrees\ferrosintesis\20260808-REV-MM-CLA@CRUCIBLE-code-review-210646\tools\ferrosintesis-samples\prepare.py:64`

- **Gap:** the crate pins filenames, aggregate bytes, RIFF/WAVE magic, and lookup behavior, but not filename-to-payload identity or filename-to-measured-root identity. All 52 piano files have the same length. Swapping two valid payloads under their existing names preserves every crate-local assertion while the hand-written sampler roots repitch the wrong recordings.
- **Statement:** the system must non-mutatingly verify each core filename, source member, baked SHA-256, canonical PCM contract, measured root, dynamic, round-robin identity, and declared alias against one authoritative manifest.
- **Acceptance shape:** negative controls must reject a same-size note swap, a wrong in-range root, silence with a valid header, a wrong PCM format, and an undeclared duplicate take. Verification must not rewrite tracked assets.
- **Effort:** Medium; **suggested flow:** Heavy; **priority:** Could

This is prevention debt, not current corruption. Draft requirements
