## Confirmed findings

### CR-1 — Wrong-shaped archive cache manifests abort regeneration

- **Severity:** Low
- **Confidence:** High
- **Where:** `tools/ferrosintesis-samples/prepare.py:1381-1414`, called by the grand path at `tools/ferrosintesis-samples/prepare.py:1746-1752`
- **Tracked as:** `MM-BUG-KILN-00181`
- **Effort:** Small

`cached_members_match()` catches missing files and JSON syntax errors, then assumes the parsed JSON root is a mapping. Valid JSON such as `null`, an array, or a scalar reaches `manifest.get()` and raises `AttributeError` instead of returning `False`. A schema-shaped manifest can also name a directory as a cached member: `os.path.exists()` accepts it, then `sha256_file()` raises outside the guarded block.

The function's contract says any doubtful cache must answer `False` so the pinned archive can rebuild. Instead, plausible local-cache damage aborts the documented `--only=grand` workflow.

**Concrete fix:** validate that the manifest root and `members` are dictionaries; require every cached member to be a regular readable file; contain hashing/read errors as cache misses. Add negative regressions for wrong-shaped valid JSON, non-mapping member data, a directory member, and an unreadable member.

### CR-2 — Grand regeneration silently retains obsolete packaged WAVs

- **Severity:** Low
- **Confidence:** High
- **Where:** expected set at `tools/ferrosintesis-samples/prepare.py:681-686`; incomplete preflight at `tools/ferrosintesis-samples/prepare.py:5421-5431`; writes at `tools/ferrosintesis-samples/prepare.py:5629-5683`; packaging at `crates/ferrosintesis-samples-grand/Cargo.toml:10`
- **Tracked as:** `MM-BUG-KILN-00182`
- **Effort:** Small

`GRAND_SOURCES` defines the complete owned output set, but `main()` pre-validates only Steinway, Kawai, Headroom, and the bass pair. The selected grand path overwrites current names without rejecting an extra `grand_*.wav` already in `samples/`.

Cargo packages every file under `samples/**`. The inventory generator also enumerates every remaining WAV, so refreshing the table after a rename or removal can embed the obsolete file and make the generated checks self-consistent with the wrong directory.

**Concrete fix:** call `_validate_generated_output_inventory("grand", GRAND_SOURCES)` before any grand source use or write. Add stale-file and renamed-source regressions. Strengthen the source-derived inventory oracle so a multi-family writer such as `main()` is checked against each selected family's expected set, rather than passing after any earlier validator call.

## Durable technical debt

### CR-3 — The committed grand bank is not independently bound to its names or selectors

- **Severity:** Low prevention debt; a realized swap would have high audio impact
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-grand/src/lib.rs:257-296`; generated expectations at `tools/ferrosintesis-samples/gen_crate_lib.py:84-89,140-176`; selector at `crates/ferrosintesis/src/sampler.rs:1231-1239`
- **Tracked as:** Draft `MM-REQ-KILN-00183`
- **Effort:** Medium; proposed Heavy flow

The crate checks names, count, aggregate bytes, RIFF/WAVE magic, and lookup while deriving the embedded table and byte pin from the same output directory. Every current file is exactly 133,048 bytes. Swapping the C2 and C6 payloads therefore preserves all crate-local assertions while the unchanged consumer roots play both notes at the wrong pitch.

The consumer also lacks an independent assertion for the 51/52 and 95/96 velocity boundaries and the two round-robin branches. The match is correct now, so this is not a current runtime defect.

**Concrete requirement:** provide a non-mutating verifier tied to the pinned archive and recipe. Compare committed outputs per filename for exact inventory, deterministic payload identity, canonical RIFF/PCM structure, duration, and measured roots. Independently assert every dynamic boundary and round-robin selection. Include same-sized payload swaps, malformed RIFF lengths, and shifted selector boundaries as negative controls.

The prior 2026-07-26 report described the payload gap as CR-4, but no open grand-specific requirement tracked it. Draft requirements `MM-REQ-KILN-00164`, `MM-REQ-KILN-00167`, and `MM-REQ-KILN-00170` cover other banks and provide a reusable verifier shape; `MM-REQ-KILN-00033` covers only the derived Dark Salamander projection.

## Not reported as defects

- **Current inventory or container corruption — refuted.** The disk, embedded, generator, and consumer name sets agree. Every current RIFF extent and PCM format is structurally valid.
- **Missing dynamic layer or round robin — refuted.** Every C/F-sharp zone has pp, mf, and f variants with two distinct payloads.
- **Linear `get()` lookup harms realtime performance — refuted.** The scan is bounded to 54 names during cached setup. Prewarm reaches all six grand banks, and no per-frame lookup or PCM copy exists.
- **Package licence metadata mislicenses the wrapper — refuted.** `LICENSING.md:11-24` explicitly gives path-local licence statements precedence, and the sample package intentionally uses its asset licence with packaged attribution.
- **Fixed `.part` output names are a reportable concurrency defect here — refuted.** Generated outputs live in per-worktree paths and the documented workflow is single-process. The shared-cache concurrency class was separately tracked and fixed by `MM-BUG-KILN-00173`.
- **Malformed embedded WAV handling is a grand-specific bug — not reported.** The parser weakness is real, but these bytes are compile-time controlled and every current grand asset is valid. `MM-REQ-KILN-00183` captures strict asset validation; a separate parser bug needs an observed malformed asset or an explicit panic-free parser contract.
