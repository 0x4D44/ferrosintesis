## Confirmed findings

### CR-1 — Logical alias duplicates packaged and decoded PCM

- **Severity:** Low
- **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-headroom/src/lib.rs:12-229`;
  `crates/ferrosintesis/src/sampler.rs:1469-1517,3103-3118`;
  `tools/ferrosintesis-samples/prepare.py:778-785`
- **Tracked as:** Open `MM-BUG-KILN-00184`
- **Effort:** Medium

Every `headroom_*_f_rr2.wav` is byte-identical to the corresponding
`headroom_*_mf_rr2.wav`: nine duplicate pairs, as expected from both logical
cells selecting LEVEL4. The mapping is musically intentional, but the crate
stores all 54 logical names as physical files and the sampler decodes the two
identical banks independently.

The nine redundant 133,048-byte WAVs add exactly 1,197,432 packaged bytes,
16.67% of the crate's 7,184,592-byte sample payload. Their 66,502 PCM16 frames
become separate `f32` vectors, retaining about 2,394,072 avoidable decoded
bytes. `prewarm()` initializes both banks, so the memory and conversion costs
are real even if a linker deduplicates static bytes; final executable
deduplication was not measured.

**Concrete fix:** use the established Kawai/Steinway alias design. Package 45
physical WAVs, preserve all 54 exact lookup names through declared aliases,
make `headroom_f_rr2()` reuse `headroom_mf_rr2()`, and extend the generated
undeclared-duplicate oracle. Verify logical-name resolution, shared-bank pointer
identity, physical inventory, and an adversarial undeclared duplicate.

### CR-2 — Headroom assets and selectors lack an independent oracle

- **Severity:** Low prevention debt; a realized payload swap would have high audio impact
- **Confidence:** High that the gap exists; current asset correctness is not inferred from it
- **Where:** `crates/ferrosintesis-samples-headroom/src/lib.rs:239-279`;
  `crates/ferrosintesis/src/sampler.rs:1418-1530`;
  `tools/ferrosintesis-samples/gen_crate_lib.py:84-112,140-176`
- **Tracked as:** Draft `MM-REQ-KILN-00185`
- **Effort:** Medium; proposed Heavy flow

The generated crate tests prove names, count, aggregate bytes, RIFF/WAVE magic,
and lookup. They derive the table and byte pin from the output directory they
check. All 54 files have the same length, so an equal-sized C2/C6 payload swap
preserves every crate-local assertion while the unchanged root table plays both
notes at the wrong pitch. The consumer exercise sweep also uses representative
velocities without asserting the 51/52 and 95/96 boundaries.

**Concrete requirement:** provide a non-mutating verifier tied to the 45 pinned
FLAC inputs and decode/bake recipe. Compare every logical output for inventory,
payload identity, strict RIFF/PCM structure and extent, duration, measured root,
and declared aliasing. Independently assert every velocity boundary and both
round-robin branches. Negative controls must cover a same-sized note swap,
malformed chunk extent, changed source mapping, undeclared duplicate, and
shifted selector boundary. Reuse the verifier architecture requested for Kawai,
Steinway, B1, and Salamander; keep Headroom's mapping and pins bank-specific.

## Adversarial verdicts and items not reported

- **Refuted — local cache sidecars are an authentication boundary.**
  `tools/ferrosintesis-samples/prepare.py:1608-1703` uses a manifest to reject
  stale, partial, or altered decoded cache entries. A same-user process that can
  forge both the WAV and sidecar can also alter the worktree and generated
  assets. The current workflow does not claim protection from a compromised
  local account, so this is not a security defect. Closed
  `MM-BUG-KILN-00139` remains satisfied under its documented cache-integrity
  threat model.
- **Refuted — current asset corruption or inventory drift.** All 54 disk names
  match the embedded table. Static header inspection found mono, PCM16, 44.1 kHz
  files with consistent RIFF/data extents. The nine duplicate groups match the
  documented LEVEL4 alias; there were no unexplained duplicates.
- **Refuted — the linear `get()` lookup is a hot-path scale problem.** It is
  bounded to this small static inventory and runs during one-time bank
  initialization, not per audio frame.
- **Refuted — dynamic or round-robin routing is currently wrong.** The generator
  maps pp/mf/f as documented and the consumer selects 0–51, 52–95, and 96–127
  with both RR branches. CR-2 tracks missing independent assertions, not a known
  selector failure.
- **Refuted — missing package attribution.** `Cargo.toml` packages `README.md`,
  `NOTICE`, and `PROVENANCE.md`; those files identify the CC BY 4.0 source,
  author, instrument, conversion, and modification process. Exact upstream
  digests not traveling with published crates are already tracked by Draft
  `MM-REQ-KILN-00144`.
- **Needs reverify — recursively packaged nested WAVs.** `Cargo.toml` includes
  `samples/**`, while the current generated inventory reads only the immediate
  directory. A nested WAV could be packaged without being embedded or counted,
  but the current tree is flat and no supported nested layout was found. This
  remains report-only unless the packaging contract admits subdirectories.
- **Already tracked outside this slice:** `MM-BUG-KILN-00181` covers malformed
  archive-cache manifests; `MM-BUG-KILN-00182` covers stale Salamander grand
  outputs. Neither is a Headroom finding.
