## Confirmed findings

### CR-1 — The standalone NOTICE assigns the bank to GM0

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis-samples-musescore-grand\NOTICE:16`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis\src\altbank.rs:1041`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis\src\sampler.rs:1533`
- **Tracked as:** Open `MM-BUG-KILN-00187`
- **Effort:** Small

The packaged NOTICE calls this bank “GM 0 / Bright Acoustic Piano alternate.”
The shipping router selects it only for GM program 1, Bright Acoustic Piano,
at CC0=2. The module docs, manifest, README, provenance, sampler, parent README,
and parent NOTICE all identify GM1 CC0=2 correctly. A consumer of this
standalone package therefore receives one shipped document with the wrong
program identity.

Closed `MM-BUG-KILN-00149` corrected the parent README and parent NOTICE. Its
derived regression checks this package's module docs, manifest, README, and
provenance, but omits this package's own NOTICE at
`D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis\src\altbank.rs:1509`.
That coverage hole explains why the residual stayed green.

**Concrete fix:** change the package NOTICE to “GM 1 Bright Acoustic Piano
alternate, CC0=2.” Extend the source-derived GM1 package-document guard to
cover the package NOTICE, with a negative control that restores the exact stale
phrase.

### CR-2 — Asset identity and runtime roots have no independent oracle

- **Severity:** Low prevention debt; a realized swap would have high audio impact
- **Confidence:** High that the gap exists; current asset correctness is not inferred from it
- **Where:**
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis-samples-musescore-grand\src\lib.rs:135`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\tools\ferrosintesis-samples\gen_crate_lib.py:4`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-220654\crates\ferrosintesis\src\sampler.rs:1542`
- **Tracked as:** Draft `MM-REQ-KILN-00188`
- **Effort:** Medium; proposed Heavy flow

The generated tests derive filenames, count, and aggregate bytes from the same
output directory that supplies the embedded table. They check RIFF/WAVE magic
and self-consistent lookup, but do not independently bind a filename to its
source payload or measured runtime root. Every current WAV is exactly 133,048
bytes, so swapping two payloads preserves every crate-local assertion while the
unchanged sampler table plays both recordings under the wrong pitches.

The magic-only check also misses RIFF extents, chunk bounds, PCM fields, block
alignment, and data validity. Current containers satisfy those contracts; this
is prevention debt, not a current corruption bug.

**Concrete requirement:** add a non-mutating verifier tied to the pinned
MuseScore_General SF3 and bake recipe. Bind each output filename to payload
identity and measured root; validate full RIFF/PCM16 mono 44.1 kHz structure;
and compare all 25 mappings with the sampler table. Negative controls must
cover an equal-sized cross-note swap, duplicate payload, malformed extent,
changed PCM format, and changed root mapping.
