## Confirmed findings

### CR-1 — The packaged regeneration recipe rewrites a separate sample crate

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\crates\ferrosintesis-samples-musescore\PROVENANCE.md:7`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\tools\ferrosintesis-samples\prepare.py:5382`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\tools\ferrosintesis-samples\prepare.py:5581`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\tools\ferrosintesis-samples\prepare.py:5685`
- **Tracked as:** Open `MM-BUG-KILN-00190`
- **Effort:** Small–medium

The packaged provenance tells maintainers to regenerate this crate with a
selector list containing `bottle`. The generator treats that word as one global
family selector. It therefore runs both the retired MuseScore `bottle_C6.wav`
onset path and `bake_bottle_loop()`, which writes the active whole-voice asset in
`crates/ferrosintesis-samples-bottle/`. Following one independently published
crate's recipe can therefore change a second crate with different source and
ownership.

**Concrete fix:** give the retired MuseScore onset a package-scoped selector, or
split it from the active `bottle` family. Update the packaged command and add a
source-level routing oracle proving that each documented package recipe writes
only its declared output crate. Include a negative control that restores the
shared `bottle` selector.

  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\crates\ferrosintesis-samples-musescore\src\lib.rs:159`;
  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\crates\ferrosintesis-samples-musescore\src\lib.rs:183`;

  `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-231609\crates\ferrosintesis\src\sampler.rs:2822`
- **Tracked as:** Draft `MM-REQ-KILN-00189`
- **Effort:** Medium; proposed Heavy flow

The crate tests prove filename parity, RIFF/WAVE magic, and lookup
self-consistency. They do not bind a filename to a particular payload or to the
separately maintained measured root in `sampler.rs`. A valid cross-note swap can
preserve every crate-local assertion while ferrosintesis repitches both samples
from the old roots. The parent has a hard-coded brass root assertion, but it does
not independently authenticate those payloads and does not cover the other five
families.

**Concrete requirement:** build a non-mutating verifier from the pinned MS Basic
SF3 and bake recipe. Bind all 36 filenames to payload identity and measured root,
validate full RIFF/PCM16 mono 44.1 kHz structure, and compare every mapping with
the consumer. Negative controls must cover an equal-sized swap, duplicate
payload, malformed extent, changed PCM format, changed selector, and changed
root. Draft `MM-REQ-KILN-00144` remains the separate exact-source-pin concern;
Draft `MM-REQ-KILN-00188` covers the distinct MuseScore_General grand crate.

## Not reported as defects

- **Refuted — current malformed or mislabeled WAVs.** Every payload has consistent
  RIFF and chunk bounds, PCM format 1, one channel, 44,100 Hz, 16 bits, block
  alignment 2, and nonempty even-sized data. Filename pitches and consumer roots
  have no evident octave or note swap.
- **Refuted — inventory, package, or version drift.** Disk, embedded, and consumer
  inventories contain the same 36 names. Cargo packages source, samples, README,
  NOTICE, and provenance. The crate and parent dependency are both version 0.1.0.
- **Refuted — duplicate payloads.** All 36 SHA-256 payload hashes are distinct.
- **Refuted — lookup or memory scale defect.** `get()` scans 36 immutable entries
  only during one-time bank construction. The 2.81 MB embedded bank and decoded
  PCM are intentional costs of the offline, self-contained design.
- **Refuted — retired `bottle_C6.wav` is accidental dead data.** The published
  compatibility surface and prewarm path deliberately retain it. The defect is
  the shared regeneration selector, not its mere presence.
- **Refuted — unsafe, path-traversal, dependency, or build-script exposure.** The
  crate forbids unsafe code, has no dependencies or build script, and performs
  exact lookup over compile-time embedded bytes.
- **Refuted — incomplete current MIT notice or source-pin drift.** The standalone
  NOTICE carries the MIT grant and full required acknowledgement set. Packaged
  provenance and `prepare.py` name the same source revision and SHA-256.
- **Outside this slice — shared scratch names and stale tooling-guide duration.**
  Reviewers found possible concurrent generator interference and an outdated
  duration in `tools/ferrosintesis-samples/README.md`. Those are tooling-area
  leads, not confirmed findings in the assigned crate, and were not filed here.
