## Confirmed findings

### CR-1 — Orchestral2 rebakes retain obsolete packaged WAVs

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\tools\ferrosintesis-samples\prepare.py:5421`; package glob at `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis-samples-orchestral2\Cargo.toml:10`
- **Tracked as:** `MM-BUG-KILN-00191`
- **Effort:** Small

The generator's selected-family preflight validates four dedicated piano banks
and the bass pair, but none of the thirteen non-banjo families written into this
crate. A renamed or removed source therefore leaves its old family WAV on disk.
Cargo packages that extra file, and a later table refresh can embed it and make
the wrong directory self-consistent.

**Concrete fix:** validate every selected orchestral2 family against the exact
source-derived output set before any fetch or write. Strengthen the source
scanner so a validator for an unrelated family cannot satisfy a multi-family
writer. Add stale-file and renamed-source negative controls.

### CR-2 — Published provenance calls a Viola Section proxy “Solo viola”

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis-samples-orchestral2\PROVENANCE.md:30`; actual source at `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\tools\ferrosintesis-samples\prepare.py:310`
- **Tracked as:** `MM-BUG-KILN-00192`
- **Effort:** Small

The package inventory describes `viola_*` as solo-viola onsets. The generator
explicitly uses VSCO's Viola Section `susvib` bank because that source has no
solo viola. The GM 41 target is solo viola; the recording is an ensemble proxy.

**Concrete fix:** publish both facts: “Viola Section proxy for GM 41 solo viola,”
plus the exact source path and layer. Extend the provenance/source agreement
guard with the misleading current wording as a negative control.

### CR-3 — Published licence evidence link escapes the package

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis-samples-orchestral2\PROVENANCE.md:70`; package set at `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis-samples-orchestral2\Cargo.toml:10`
- **Tracked as:** `MM-BUG-KILN-00193`
- **Effort:** Small

The music-box provenance links a retained Freesound licence manifest using a
`../../tools/` path. That file exists in the repository and its hash matches,
but Cargo does not package it. The link is broken in the standalone published
crate, so the promised offline evidence does not travel with the claim.

**Concrete fix:** package a local immutable evidence file, link to it from
`PROVENANCE.md`, and add an oracle that rejects missing or escaping package-local
evidence links.

## Durable technical debt

### CR-4 — Outputs and zone mappings lack an independent identity oracle

- **Severity:** Low prevention debt; a realized payload/root swap would have high audio impact
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis-samples-orchestral2\src\lib.rs:397`; consumer roots in `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\crates\ferrosintesis\src\sampler.rs`; source maps in `D:\worktrees\ferrosintesis\20260813-REV-MM-CDX@KILN-code-review-233709\tools\ferrosintesis-samples\prepare.py`
- **Tracked as:** Draft `MM-REQ-KILN-00194`
- **Effort:** Medium; proposed Heavy flow

The crate proves name parity and RIFF/WAVE magic from the output directory, but
does not independently bind each filename to source bytes, output identity, or
the consumer's measured root. A valid same-sized payload swap stays green while
the sampler repitches the wrong recording. Current payloads are structurally
clean and unique, so this is not a current runtime defect.

**Concrete requirement:** build a non-mutating verifier tied to the exact source
and recipe. Check per-file output identity, strict PCM structure, measured roots,
and consumer mapping. Canonicalize the banjo input first because the committed
Opus archive is not the original lossless input used for the shipped bank.
