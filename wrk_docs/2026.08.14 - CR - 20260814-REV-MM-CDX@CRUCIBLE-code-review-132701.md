## Confirmed finding

### Medium — the overlap oracle ignores GM System On voice resets

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260814-REV-MM-CDX@CRUCIBLE-code-review-132701\crates\render-catalog\tests\album_midi_overlaps.rs:102-105,183-208`;
  production semantics at
  `D:\worktrees\ferrosintesis\20260814-REV-MM-CDX@CRUCIBLE-code-review-132701\crates\ferrosintesis\src\midi.rs:304-315,423-425`
  and
  `D:\worktrees\ferrosintesis\20260814-REV-MM-CDX@CRUCIBLE-code-review-132701\crates\ferrosintesis\src\engine.rs:2213-2217,2449`.
- **Tracked as:** `MM-BUG-CRUCIBLE-00034`
- **Effort:** Small–Medium

The audit skips every `F0`/`F7` SysEx payload, then keeps one active-note map for the whole
file. Production recognizes GM System On, sorts it before other events at the same tick,
and hard-resets the engine, stopping every active voice. Consequently,
`NoteOn(k) -> GM System On -> NoteOn(k) -> NoteOff(k)` is valid for the renderer but the
audit reports an overlap and unmatched lifecycle. A stale note-off after a reset can also
be harmless in production yet fail the audit.

**Concrete fix:** recognize the exact GM reset message in the audit, mirror production's
same-tick priority, and reset the active-note epoch. Add red-before-fix controls for a
held note across reset, a same-tick replacement note, and a stale post-reset note-off.

## Needs re-verification — not reported as defects

- **Encoder pipe backpressure.** `src/main.rs:861-889` pipes stdout/stderr but calls
  `wait_with_output` only after `try_wait` sees exit or after timeout kills the child. A
  child that fills either pipe will block and be killed at the deadline. This code-level
  risk is real, and the silent hanging-child test at `src/main.rs:1425-1480` cannot detect
  it. However, the pass could not establish from accessible `ropusenc` source that the
  real encoder emits enough output to fill a pipe. Per the review contract, this remains
  **UNVERIFIED**, not a confirmed shipped defect.
- **Partial final Opus output.** The caller writes directly to the final `.opus` path and
  validates only encoder success plus path existence (`src/main.rs:729-770`). Whether a
  failed encoder truncates or leaves a partial destination depends on external
  `ropusenc` behavior, which this static pass did not establish.
