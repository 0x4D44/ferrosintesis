# Code review — crates/ferrosintesis-samples-b1-upright/ (2026-08-14)

One bounded pass over the never-reviewed B1 upright sample-asset crate: the generated
`include_bytes!` inventory (52 WAVs), the handwritten `b1t ` tail validator test, the
docs (README/PROVENANCE), and its wiring into the workspace (sampler, licensing and
inventory oracles, regen tool, packaging). Lenses: correctness, packaging/licensing,
maintainability, test coverage, plus a fresh-context devil's advocate briefed to defeat
the crate's oracles rather than confirm them. Every reported finding was independently
re-verified against source by the lead; verdicts below.

## Confirmed findings

### 1. Crate-side asset validator never checks `fmt `/`data`/pad — a consumer-panicking asset publishes green
- **Severity:** Medium · **Confidence:** High (code paths traced in both crates)
- **Where:** `crates/ferrosintesis-samples-b1-upright/src/lib.rs:246` (`b1_tail`) vs
  `crates/ferrosintesis/src/sampler.rs:95` (`parse_b1_tail`), panic site
  `crates/ferrosintesis/src/sampler.rs:347-348`
- At publish time the asset crate's own tests are the only gate, and they validate only
  the tail chunk. The runtime additionally requires one strict PCM16/mono/44.1 kHz
  `fmt `, a unique even nonzero `data` matching the decoded body, zero pad bytes, and
  `entry_frame < pcm_frames` — and panics every consumer at bank build when any fails.
  A `fmt ` rewrite, a swallowed `data` chunk, or a truncation below frame 59 535 keeps
  the crate suite (including both aggregate byte pins) green. The regen tool
  (`tools/ferrosintesis-samples/regen_samples_table.py:51-99`) mirrors the same
  tail-only predicate, so tool and test are correlated-blind.
- **Fix:** give the crate test (and the shared regen predicate) the runtime's checks,
  ideally one shared strict predicate; prove by mutating an embedded WAV each way and
  watching the strengthened test fail. **Effort:** ~half a day.
- **Filed:** `bugs/MM-BUG-KILN-00195.md`.

### 2. `Cargo.toml` packages `samples/**` but the inventory oracle counts only top-level lowercase `.wav` — junk would ship unvetted
- **Severity:** Low (latent — current tree verified clean) · **Confidence:** High
- **Where:** `crates/ferrosintesis-samples-b1-upright/Cargo.toml:10` vs
  `crates/ferrosintesis-samples-b1-upright/src/lib.rs:293` and
  `tools/ferrosintesis-samples/regen_samples_table.py:106`
- `samples/extra.WAV`, `samples/notes.txt`, or any `samples/raw/` subtree ships in the
  published CC0 crate with zero oracle coverage. Likely shared by sibling sample
  crates; the fixer should enumerate all of them (the repo's own "re-read the whole
  list" rule).
- **Fix:** recursive walk asserting everything under `samples/` is a top-level
  lowercase `.wav` in the embedded set, and/or narrow the include to `samples/*.wav`.
  **Effort:** small, mechanical.
- **Filed:** `bugs/MM-BUG-KILN-00196.md`.

## Not filed (and why)

- **PCM content is uncheckummed anywhere** (size-preserving corruption ships silently
  through test, tool, and runtime). True by construction, but git protects the
  committed tree and repo policy publishes only from a clean integrated trunk, so the
  exploit path needs an uncommitted local corruption at publish — procedural guard
  accepted. Report-only, Low.
- **Aggregate tail pin can't see cross-file redistribution** (`EXPECTED_TAIL_BYTES` is
  a sum; two coordinated per-file-consistent edits cancel). Needs deliberate tampering
  or a pathological bake; the per-file `payload == div_ceil(source_frames, 4)` check
  bounds the damage. Report-only, Low.
- **Regen tool `ARRAY_RE.sub` replaces all matches without a count guard**
  (`regen_samples_table.py:138`); the marker containment check runs only for tail-pin
  crates. Unlikely state (needs a second SAMPLES-shaped array); noted for whoever next
  touches the tool.
- **Unchecked `padded_end = body_end + (len & 1)` in the test validator**
  (`lib.rs:259`): traced fail-safe — every overflow path ends in a test failure, never
  a false pass; unreachable on 64-bit. Not a defect.
- **Devil's-advocate refuted paths (clean bill):** missing/extra lowercase `.wav`,
  embedded-name drift, and count drift are all caught (`inventory_matches_packaged_wavs`
  plus the `FILE_COUNT`-typed array); duplicate/non-terminal/wrong-metadata tail chunks
  are rejected identically by test, tool, and runtime; a regen pin miscomputation is
  caught by the test's independent recomputation from embedded bytes.
