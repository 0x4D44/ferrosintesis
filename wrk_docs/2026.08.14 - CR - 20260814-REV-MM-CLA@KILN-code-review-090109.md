### 1. Dangling "`ferrosintesis`." fragment in published rustdoc — 12 sample crates
- **Severity:** Low. **Confidence:** Confirmed. **Filed:** MM-BUG-KILN-00197.
- **Where:** `crates/ferrosintesis-samples-sax/src/lib.rs:8` and 11 sibling crates
  (core, clavinet, drumkit, drumkit2, gong, bottle, fretnoise, grand, strings,
  musescore, orchestral2 — enumerated from all 25).
- **What:** the sync commit e121847 (2026-07-29) appended the oracle-required
  `legal_doc_line` (`tools/ferrosintesis-samples/gen_crate_lib.py:43`) — a
  hard-wrapped continuation line beginning "`ferrosintesis`. " — onto hand-written
  headers whose sentence was already complete. Rendered rustdoc shows a stray
  "`ferrosintesis`." sentence. The e121847 diffstat confirms the split: the 12
  pure-append (`1 +`) crates dangle, the 13 replaced (`2 +-`) headers read fine.
- **Fix:** rewrap the preceding prose in each of the 12 crates to flow into the
  required line (keep it byte-identical for
  `test_prepare.py:3040` `GeneratedCrateDocHeaderTest`); or split `legal_doc_line`
  so the required marker starts at "Licence/provenance:". **Effort:** ~1 h.

## Not reported (and why)

- **Baritone G#3 exclusion itself** — by design, tracked (MM-BUG-KILN-00178) and
  enforced by `baritone_sax_bank_rejects_the_rough_source_population_outlier`;
  only the shipped doc's silence about it is a defect (finding 2).
- **`sax_bar_p` comment says "the rough G#3 take" though only the forte take is
  rough** (`sampler.rs:2389`) — loose wording in a code comment; the guarding test
  states the p/f distinction precisely. Below the bug bar.
- **Aggregate `EXPECTED_BYTES` instead of per-file sizes** — compensating-edit
  blind spot in theory, but combined with per-file RIFF/WAVE checks and the parity
  test it is an acceptable canary; a re-cut of any file re-pins it anyway.
- **No crate-local fmt-chunk oracle** (mono/16-bit/44.1k asserted in docs, tested
  nowhere in-crate) — covered indirectly by downstream pitch/level oracles; note
  that MM-BUG-KILN-00195 already tracks the stronger crate-side-validator idea for
  b1-upright and whoever fixes it should enumerate siblings, so no separate record.
