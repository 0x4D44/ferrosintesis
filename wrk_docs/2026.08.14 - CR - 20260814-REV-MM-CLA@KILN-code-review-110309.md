## Verdict

The crate itself is in good shape — payloads verified byte-consistent, licensing
and packaging surfaces correct, alias semantics consistent across four independent
artifacts. The defects are all in the **oracle layer around it**: three filed
(MM-BUG-KILN-00199/00200/00201), the worst being that the cross-crate shadowing
oracle never learned about the ALIASES logical namespace this crate introduced,
and that the piano-family zone-root pins are an unguarded hand-transcribed list —
the repo's own self-declared recurring defect class.

## Findings

### 1. Cross-crate basename-collision oracle misses ALIASES logical names — filed MM-BUG-KILN-00200
- **Severity:** Medium. **Confidence:** Confirmed (adversarial pass found it; lead
  re-verified against source). **Effort:** Small.
- **Where:** `crates/ferrosintesis/src/payload.rs:442-498`
  (`no_two_asset_crates_ship_the_same_wav_basename`) vs
  `crates/ferrosintesis/src/sampler.rs:205-229` (`embedded_wav`) and
  `crates/ferrosintesis-samples-vcsl-steinway/src/lib.rs:157-166` (`get()` alias
  rewrite).
- **What:** the oracle enumerates physical `samples/*.wav` basenames only; the
  lookup chain's real namespace also holds 27 steinway + 16 kawai alias names. A
  same-named physical WAV in a crate earlier in the chain silently shadows an
  alias (and vice versa for later crates) with the oracle green — the exact
  wrong-timbre failure its own doc comment warns about. Clean today
  (prefix-disciplined names); latent gap.
- **Fix:** fold each crate's `ALIASES` rows into the same `owner` map the scan
  builds (details in the bug).

### 2. Piano-family zone-root pins have no oracle; equal-size payloads make swaps silent — filed MM-BUG-KILN-00201
- **Severity:** Medium. **Confidence:** Confirmed. **Effort:** Medium.
- **Where:** `crates/ferrosintesis/src/sampler.rs:1248-1301` (27 hand-transcribed
  `steinwayb_*` f0 literals; same shape in the eight sibling piano banks).
- **What:** no structural interval check (the mandolin has one —
  `sampler.rs:6721`) and no measured-pitch check (the `la_*_pitch_integrity`
  family skips every piano program and never reaches the CC0-alternate grands).
  All 27 steinway payloads are exactly 133 048 bytes, so the crate's aggregate-size
  canary cannot distinguish them: a transposed pin digit or two swapped
  `include_bytes!` paths ships a silently mispitched zone with every suite green.
- **Fix:** mandolin-style ladder assert (6.0 ± 0.6 semitones for the C/F# grid)
  plus a decoded-PCM f0 measurement against `z.root` (details in the bug).

### 3. Generated ALIASES crate test is vacuous on a dangling canonical — filed MM-BUG-KILN-00199
- **Severity:** Low. **Confidence:** Confirmed (deliberately re-scoped, see below).
  **Effort:** Small.
- **Where:** `crates/ferrosintesis-samples-vcsl-steinway/src/lib.rs:227-229`,
  `crates/ferrosintesis-samples-vcsl-kawai/src/lib.rs:237`, template at
  `tools/ferrosintesis-samples/gen_crate_lib.py:196-198`.
- **What:** `assert_eq!(get(alias), get(canonical))` is `None == None` when the
  canonical target is missing — nothing asserts aliases resolve to bytes. The
  published crates ship only this vacuous guard, and the generator emits it for
  any future ALIASES crate.
- **Fix:** one line in the template — unwrap `get(canonical)` — plus regeneration
  (details in the bug).

## Verified clean (what was checked and held)

- **Payload integrity:** 27 WAVs, all git-tracked, all exactly 133 048 bytes;
  27 × 133 048 = 3 592 296 = `EXPECTED_BYTES`. Three headers `od`-verified PCM
  mono 16-bit 44.1 kHz; data length 66 502 frames = `(0.008 + 1.5) × 44 100`,
  matching PROVENANCE's KEEP/lead-in claims and `prepare.py:1036,1208`.
- **Alias semantics:** consistent across `ALIASES`, `PROVENANCE.md:45-49`,
  `prepare.py:719` (`_STEINWAYB_VEL`), and the sampler bank fns
  (`steinwayb_mf = pp_rr2`, `f = mf_rr2`, `f_rr2 = pp_rr2`) — four independent
  artifacts agree; the ALIASES file is alias-sorted, consistent with the
  generator's `sorted()` emission, so the order-sensitive `declared == ALIASES`
  assertion is coherent.
- **Coverage:** prewarm and `exercise_every_public_bank` sweep
  `steinwayb_bank` at vel {1, 80, 127} × rr2 — all six logical banks (three
  physical OnceLocks) decode under `cargo test --workspace`; scoped
  bake-validation pinned at `inventory.rs:1039-1047`.
- **Licensing/packaging:** pure CC0 crate correctly excluded from the
  attribution-bearing set (`licensing.rs:129-137`); `LICENSE-CC0`, `ALIASES`, and
  all referenced docs in the `include` list; `=0.1.0` pin and optional-dep feature
  wiring in `crates/ferrosintesis/Cargo.toml:39,71`; ~3.6 MB, far under the
  crates.io cap; no dependencies (one of the 24 independent publishes);
  `#![forbid(unsafe_code)]`; no runtime I/O.
- **Unverifiable offline (recorded, not assumed):** upstream VCSL claims (naming,
  velocity layers, source format, the measured-f0 spot checks in PROVENANCE) and
  actual crates.io publication state.
