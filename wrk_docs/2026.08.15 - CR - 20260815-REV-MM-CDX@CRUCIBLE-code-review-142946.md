## Confirmed findings

### CR-1 — inherited probe state defeats pristine-process cache-test isolation

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260815-REV-MM-CDX@CRUCIBLE-code-review-142946\crates\ferrosintesis-samples-drumkit\src\lib.rs:986`
- **Tracking:** `MM-BUG-CRUCIBLE-00035` (new, Open)
- **Problem:** `lookup_misses_do_not_initialize_pcm_cache` treats the mere
  presence of `FERRO_DRUMKIT_PCM_MISS_PROBE` as proof that it is the re-executed
  child. If the caller or CI already supplies that variable, the outer test skips
  the re-exec and runs cold-cache assertions in the shared libtest process.
- **Impact:** parallel tests at lines 878-895 and 938-970 can initialize the same
  process-global `PCM_CACHE` first. The regression can then fail spuriously even
  though the production miss path is correct. This is a test-infrastructure
  defect, not a production cache failure.
- **Concrete fix:** move the cold-cache assertions into a separate ignored child
  test. Re-exec that exact child with `--ignored`, and require evidence that one
  child test ran before accepting its exit status. Apply the same repair to the
  companion crate's equivalent test.
- **Effort:** Small.

### CR-2 — the package allowlist is broader than its inventory gates

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260815-REV-MM-CDX@CRUCIBLE-code-review-142946\crates\ferrosintesis-samples-drumkit\Cargo.toml:13`; `D:\worktrees\ferrosintesis\20260815-REV-MM-CDX@CRUCIBLE-code-review-142946\crates\ferrosintesis-samples-drumkit\src\lib.rs:829`; `D:\worktrees\ferrosintesis\20260815-REV-MM-CDX@CRUCIBLE-code-review-142946\tools\ferrosintesis-samples\prepare_drumkit.py:351`
- **Tracking:** existing Open `MM-BUG-KILN-00196`; no duplicate minted
- **Problem:** Cargo includes recursive `samples/**`, while both the crate oracle
  and regeneration guard enumerate only immediate children ending in lowercase
  `.wav`. A nested file, uppercase `extra.WAV`, or non-WAV file can therefore
  ship without appearing in the inventory checks.
- **Impact:** unvetted content or package bloat can enter the published crate
  while the intended inventory checks remain green. The current directory is
  clean: it contains exactly the 128 expected top-level lowercase WAVs.
- **Concrete fix:** narrow the manifest to the exact intended file shape, and
  make the shared package oracle recursively reject every path outside the
  embedded allowlist. Add negative controls for nested, uppercase-extension,
  and non-WAV files. Open `MM-BUG-KILN-00196` explicitly calls for the sibling
  sample-crate sweep, so this instance belongs in that fix.
- **Effort:** Small–Medium for the class-level sweep.

## Refuted or not reported

- **Malformed private RIFF parser — refuted as a current defect.**
  `decode_wav` receives only compile-time first-party `SAMPLES` bytes, and every
  current asset has valid checked extents and canonical PCM headers. Fallible,
  bounds-checked parsing plus malformed fixtures would be defense in depth, not
  a demonstrated caller-triggerable failure.
- **Regression in today's PCM miss fix — refuted.** Lines 757-771 resolve the
  name or validate the index before `decoded_samples()`. Valid bank access still
  uses the owning source's direct index, and both drum packages remain explicitly
  prewarmed by `sampler::prewarm()`.
- **Public malformed `Bank` descriptors — hardening only.** External callers can
  construct invalid public field combinations, but every shipped descriptor
  satisfies the documented invariants and no ferrosintesis route constructs one.
- **Eager raw-plus-decoded residency — intentional.** A valid first lookup and
  `prewarm()` deliberately initialize and retain the full package cache away from
  the realtime thread.
- **Dangling generated rustdoc phrase — already tracked.** Open
  `MM-BUG-KILN-00197` covers the shared sample-crate header generator.
