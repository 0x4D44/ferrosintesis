## Confirmed findings

### CR-1 — crate-local checks do not authenticate each payload or its measured root

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis-samples-vcsl-kawai\src\lib.rs:188`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis\src\sampler.rs:6734`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\tools\ferrosintesis-samples\prepare.py:255`
- **Tracking:** existing Draft `MM-REQ-KILN-00164`; no duplicate minted
- **Problem:** the crate checks filenames, one aggregate byte count, RIFF/WAVE
  magic, lookup success, alias parity, and duplicate physical payloads. The
  generic root oracle checks the root literals against filename pitches, not the
  decoded PCM. Swapping two equal-sized Kawai payloads under unchanged names, or
  replacing one with same-sized valid PCM, leaves those predicates green.
- **Impact:** a future asset edit can preserve every current local assertion while
  making a zone play the wrong recording under the old measured root. The current
  assets are structurally valid and unique; this is prevention debt, not evidence
  of present corruption.
- **Concrete fix:** implement `MM-REQ-KILN-00164` as a non-mutating verifier bound
  to the immutable VCSL revision and bake recipe. Check each output's identity,
  strict RIFF/PCM extents, measured root, alias sharing, and deterministic bytes.
  Include equal-sized cross-zone swap, silence, malformed-RIFF, and changed-root
  negative controls.
- **Effort:** Medium.

### CR-2 — runtime zone membership and velocity boundaries lack exact contract tests

- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis\src\sampler.rs:1329`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis\src\sampler.rs:1403`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis\src\sampler.rs:6105`
- **Tracking:** fold into the Gate-1 oracle for existing Draft
  `MM-REQ-KILN-00164`; no narrower duplicate minted
- **Problem:** `exercise_every_public_bank` initializes the three velocity arms at
  representative velocities 1, 80, and 127, but it does not assert exact zone
  membership or the 51/52 and 95/96 boundaries. Removing one zone from a runtime
  table, or shifting a boundary by one, still initializes every cache and leaves
  the package/source inventory checks green. The generic root scan sees only the
  rows that remain, so it cannot detect an omitted row.
- **Impact:** a future edit can silently increase high-register repitch stretch or
  select the wrong timbre layer at a boundary. Current tables contain all eight
  expected zones, both alias delegations are correct, and all boundaries match the
  documented map.
- **Concrete fix:** extend `MM-REQ-KILN-00164`'s acceptance oracle to derive and
  compare the exact runtime filename set for every physical layer/RR bank. Assert
  eight ordered zones, intentional pointer sharing, and bank identity at velocities
  51, 52, 95, and 96 for both RR values. Prove the guard with an omitted-C6 row and
  a shifted-boundary negative control.
- **Effort:** Small when added to the shared verifier.

## Refuted or not reported

- **Malformed private WAV parser — not a current defect.** `parse_wav` can panic
  on malformed chunks, but it receives only compile-time first-party bytes. All 32
  current files have strict, complete extents and canonical PCM headers. CR-1 is
  the right defense-in-depth route.
- **Alias manifest can drift silently — refuted.**
  `test_prepare.py:3337-3354` derives Kawai aliases from the source map and compares
  them with the committed manifest; the generated Rust test separately compares
  that manifest with `ALIASES` and resolves every canonical payload.
- **Dangling or shadowed aliases — refuted.** Current aliases resolve to packaged
  bytes. The cross-crate namespace oracle at
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-001855\crates\ferrosintesis\src\payload.rs:442`
  includes logical alias names as well as physical basenames.
- **Duplicate decoded Kawai banks — refuted.** The two repeated upstream layers
  delegate to shared `OnceLock` banks, and pointer-identity assertions cover both
  pairs at `sampler.rs:7601`.
- **Linear lookup and eager bank residency — intentional.** Lookups and decoding
  happen during one-time prewarm, not per rendered sample.
- **Bake autocorrelation, warm-cache decoding, and quadratic duplicate checking —
  not reported.** No latency contract or observed failure establishes a defect;
  these are bounded offline/test costs at the current 32-file scale.
