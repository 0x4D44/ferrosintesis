## Confirmed findings

### CR-1 — YDP regeneration is not failure-atomic as a bank

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\prepare.py:4715`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\prepare.py:4773`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\prepare.py:4782`
- **Tracked as:** Open `MM-BUG-KILN-00205`
- **Effort:** Small–Medium

The preflight checks only the existing output filename set. The bake then looks
up and writes one source root at a time. A missing later root, late frame error,
or later destination-write failure occurs after earlier final paths have already
been replaced. The per-file `.part`/`os.replace()` helper prevents one WAV from
being truncated, but it does not preserve the nine-file bank as a set.

The result can contain a prefix baked by the new code or source and a suffix from
the previous bank. All nine names can remain present and all payloads can remain
valid equal-sized WAVs, so the crate's name, aggregate-size, and RIFF-magic checks
need not reject the mixed generation.

**Concrete fix:** validate all required SF2 chunks, roots, sample IDs, and frame
ranges before publication. Generate the whole bank in a temporary directory,
validate its exact inventory and WAV contracts, then publish with rollback on a
replacement failure. Negative controls should omit a late root and fail after
several staged outputs while requiring the old bank to remain byte-identical.

### CR-2 — the shared Rust-table generator overwrites before success

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\gen_crate_lib.py:240`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\gen_crate_lib.py:242`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-092455\tools\ferrosintesis-samples\gen_crate_lib.py:250`
- **Tracked as:** Open `MM-BUG-KILN-00206`
- **Effort:** Small

The generator opens the final tracked `src/lib.rs` with `"w"`, writes directly
to it, and only afterward invokes `rustfmt`. A termination or write/format error
can therefore leave the source empty, partial, or replaced by output the command
did not accept. The current YDP module is complete; the defect is the destructive
failure behavior.

**Concrete fix:** generate and format a unique sibling temporary file, then
atomically replace the final path only after both steps succeed. Injected write
and formatter failures must preserve the old file byte-for-byte and leave no
temporary artifact.
