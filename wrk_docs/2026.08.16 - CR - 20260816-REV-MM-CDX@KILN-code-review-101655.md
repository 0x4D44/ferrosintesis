## Confirmed defects

### Medium — A selective rebake no longer validates the complete shared crate

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\tools\ferrosintesis-samples\prepare.py:1196`, `:5532`, `:5733`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\tools\ferrosintesis-samples\gen_crate_lib.py:97`
- **Tracking:** `MM-BUG-KILN-00207`
- **Problem:** finger and pick outputs share one package directory, but the new derived preflight validates only the selected prefix. The later crate generator embeds every WAV in that directory. A finger-only run can therefore accept and later republish an obsolete pick file, and vice versa.
- **Concrete fix:** derive validation by destination package. Selecting either bass family must validate the union of both source maps. Add cross-family stale-file negative controls.
- **Effort:** Small–Medium

This is a confirmed regression of closed `MM-BUG-CRUCIBLE-00022`: `b9114c8`
added the combined guard, while `291ab66` replaced it with per-family checks.

### Medium — A late failure can leave a mixed-generation bass bank

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\tools\ferrosintesis-samples\prepare.py:4247`, `:5733`
- **Tracking:** `MM-BUG-KILN-00209`
- **Problem:** each WAV is atomically replaced as soon as it is generated, but the selected bank is not published atomically. A later read, transform, root-measurement, or write failure leaves a new prefix and old suffix; all files may still have valid names and RIFF headers.
- **Concrete fix:** stage and validate the complete selected bank, then publish it with rollback. Negative controls must fail late and preserve every old destination byte-for-byte.
- **Effort:** Small–Medium

### Low — `--only` fetches the unselected bass archive

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\tools\ferrosintesis-samples\prepare.py:1568`, `:5507`, `:5607`
- **Tracking:** `MM-BUG-KILN-00208`
- **Problem:** selecting either bass family calls a helper that authenticates and extracts both source archives. That contradicts the documented selector contract and lets an unavailable unselected archive block the requested bake.
- **Concrete fix:** fetch each archive only when its family is selected; keep shared-directory validation as the separate package-ownership rule.
- **Effort:** Small

## Draft technical requirement

### Independently bind each bass payload to its source and runtime root

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\crates\ferrosintesis-samples-bass\src\lib.rs:82`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-101655\crates\ferrosintesis\src\sampler.rs:935`
- **Tracking:** Draft `MM-REQ-KILN-00211`
- **Gap:** all 13 WAVs have the same size, while the generated test pins only the aggregate and container magic. A cross-note payload swap stays green, and the runtime roots are copied manually from generator output.
- **Concrete oracle:** authenticate source member and baked payload per filename; strictly validate RIFF/PCM extents; re-measure and bind every payload to its runtime root; include a same-sized swap negative control.
- **Effort:** Medium; proposed flow `heavy`

Current payloads are valid and unique. This is prevention debt, not a claim that a
wrong bass sample ships today.

## Not reported

- **Unreachable 0.9-second tails — refuted.** The initial `LA_BASS_MAX_UP_RATIO` bound alone suggests only about 8,830 frames are read during the 150 ms fade, but `LaVoice::set_pitch` can raise the read rate after construction. RPN 0 admits a 24-semitone range and portamento can start much farther from the target. Without a census over those authored pitch paths, the tail is not proved unreachable.
- **Malformed WAV panic — unverified.** The generic parser uses assertions and the crate-local test is shallow, but every reviewed runtime input is a valid compile-time embedded asset. No malformed current asset or runtime-controlled input was found; the strict-structure part is captured as prevention in `MM-REQ-KILN-00211`.
- **Generator basename injection — refuted as a security finding.** Adding a hostile repository filename already requires repository write authority, which can directly alter Rust source. It crosses no new trust boundary here.
- **Archive verification/extraction TOCTOU — refuted as a security finding.** The proposed attack requires same-user local write access that already permits direct output mutation. No distinct privilege boundary was shown.
- **Linear `get()` lookup — refuted as material performance work.** Thirteen entries are scanned only while one-time banks initialize; the cost is bounded and negligible.
- **Generated `lib.rs` whole-file overwrite — duplicate.** Open `MM-BUG-KILN-00206` already tracks it.
