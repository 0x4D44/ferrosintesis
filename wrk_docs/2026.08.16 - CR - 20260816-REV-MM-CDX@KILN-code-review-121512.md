## Confirmed findings

### CR-1 — Published regeneration command points at a nonexistent repo-root script

- **Severity:** Low
- **Confidence:** High
- **Location:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis-samples-bottle\PROVENANCE.md:29`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\tools\ferrosintesis-samples\README.md:190`
- **Tracked as:** Open `MM-BUG-KILN-00212`
- **Effort:** Trivial

The provenance publishes `python3 prepare.py --only=bottleloop`, but no `prepare.py`
exists at the supported repository-root location or in the crate. The supported tool is
`tools/ferrosintesis-samples/prepare.py`. The selector introduced by the
MM-BUG-KILN-00190 fix is correct; only its executable path is dead. The recipe oracle
at `test_prepare.py:2783-2810` validates selectors but never validates the script path,
which is why this survived the recent selector repair.

**Concrete fix:** publish the repository-root command with the full tool path and make
the recipe oracle reject a nonexistent or wrong script path.

### CR-2 — Successful sampled GM76 notes eagerly build and discard the model

- **Severity:** Low
- **Confidence:** High
- **Location:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis\src\voices.rs:15012`
- **Tracked as:** Open `MM-BUG-KILN-00213`
- **Effort:** Small

The GM76 arm constructs and double-boxes the complete modeled `Wind`/`ScaledVoice`
before calling `bottle_loop_voice(...).unwrap_or(model)`. `unwrap_or` is eager, so an
in-range sampled note immediately destroys that fallback after constructing its
oscillators, filters, envelope, RNG and resonator. This adds deterministic constructor,
allocation and deallocation work to every successful sampled NoteOn in the realtime
voice-construction path, without any possible audio effect.

**Concrete fix:** move model construction behind `unwrap_or_else` or a lazy helper.
Pin the behavior with a constructor counter for sampled success, sampled fallback and
no-samples routing.

### CR-3 — Public G3 asset key disagrees with the measured 205 Hz root

- **Severity:** Low
- **Confidence:** High for the metadata mismatch; runtime pitch is correct
- **Location:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis-samples-bottle\src\lib.rs:16`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis-samples-bottle\README.md:8`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis-samples-bottle\PROVENANCE.md:27`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-121512\crates\ferrosintesis\src\sampler.rs:4578`
- **Tracked as:** Open `MM-BUG-KILN-00214`
- **Effort:** Small for a non-breaking clarification; Medium for a rename

The exact public lookup key says G3, but the documented and runtime root is 205.0 Hz.
That is 77.7 cents sharp of G3 (196.00 Hz) and much nearer G-sharp 3. The synth correctly
repitches from 205.0 Hz; the defect is the human/public API label, which invites direct
consumers to infer the wrong root.

**Concrete fix:** retain the key for compatibility but mark it as historical and expose
or prominently state the measured root. Rename only with an intentional compatibility
decision.

## Not reported, and why

- **Malformed-WAV production failure — refuted on the current tree.** The crate-local
  test checks only RIFF/WAVE magic and the shared parser is intentionally minimal, but
  the committed asset has exact RIFF/data extents, PCM16 mono 44.1 kHz format and
  nonempty even data. It is compile-time embedded, the Python rebake pins it within 24
  LSB, and the sampler oracles exercise its active voice. This is prevention debt, not
  a present shipped failure.
- **No source-to-root oracle — held as prevention debt, not a requirement.** The
  205.0 Hz literal is independently maintained, but `bottle_loop_pitch_integrity`
  exercises four representative keys and the rebake test pins the payload. A new Draft
  would overlap the existing sample-asset verifier pattern without a current failure.
- **First NoteOn can search a cold loop — refuted as by-design.**
  `RealtimeSynth::prewarm_samples()` documents the setup-time/memory versus occasional
  first-use-stall tradeoff and explicitly permits callers to skip it. The loop result is
  memoized.
- **Retired onset bank is still prewarmed — refuted as by-design.** The code explicitly
  retains the published compatibility bank, and `prewarm()` intentionally initializes
  every bank. Removing it would weaken that contract for negligible benefit.
- **Current route, packaging, license or payload corruption — refuted.** The
  `bottleloop` selector reaches the correct crate; Cargo includes all six files; the CC0
  license matches sibling CC0 packages; the embedded/source names and pinned source
  digest agree.
