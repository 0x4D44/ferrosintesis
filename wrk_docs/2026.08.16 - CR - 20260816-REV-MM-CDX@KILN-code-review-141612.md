## Confirmed findings

### CR-1 — Most embedded PCM is unreachable after runtime looping begins

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\crates\ferrosintesis\src\sampler.rs:5518`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\crates\ferrosintesis\src\sampler.rs:5672`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\crates\ferrosintesis-samples-clavinet\src\lib.rs:78`
- **Tracked as:** Open `MM-BUG-KILN-00219`
- **Effort:** Small–Medium

The loop search permits a start no later than 0.34 seconds and a length no
greater than 0.11 seconds. Every selected loop therefore ends by 0.45 seconds.
`ClavinetSampled::sample_at` wraps all later reads into that loop, so it cannot
consume at least 50,715 frames from each 70,560-frame asset.

Across eleven zones, the shipped bank carries at least 1,115,730 unreachable
PCM bytes and decodes them into another 2,231,460 unreachable `f32` bytes. No
audible error is claimed; the confirmed defect is avoidable binary and resident
memory cost.

**Concrete fix:** trim every WAV after a proved-safe interpolation guard beyond
the maximum loop end, or make the voice consume the tail. Add a reachability
oracle and a differential check across roots, sample rates, and pitch bends.
Update the aggregate-size canary and provenance.

### CR-2 — A late failure can leave a mixed-generation bank

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\tools\ferrosintesis-samples\prepare.py:4480`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\tools\ferrosintesis-samples\prepare.py:4514`
- **Tracked as:** Open `MM-BUG-KILN-00220`
- **Effort:** Small–Medium

`_bake_clavinet()` regenerates eleven zones and replaces each final tracked WAV
immediately. The writer protects one file, not the bank. A later decode, root
measurement, allocation, or replacement failure leaves a new prefix beside an
old suffix. The mixed bank can keep valid names and RIFF headers, so the current
crate checks need not reject it.

**Concrete fix:** generate into empty staging, validate the complete inventory
and WAV/root contracts, then publish with rollback. Add late-transform and
mid-publication failure controls that require the old bank to remain byte-exact.

### CR-3 — Concurrent regenerations race fixed shared-cache intermediates

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\tools\ferrosintesis-samples\prepare.py:4497`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\tools\ferrosintesis-samples\prepare.py:5639`
- **Tracked as:** Open `MM-BUG-KILN-00221`
- **Effort:** Small–Medium

Every worktree uses the same revision-keyed system-temp directory and the same
`clavinet_<root>.ogg` / `.wav` names. One process can truncate an Ogg while a
peer decodes it, or replace a WAV while a peer reads it. This can fail a run or
feed partial intermediate data into final publication. The SF3 itself remains
SHA-256 authenticated; the race is in extraction and decode.

**Concrete fix:** isolate intermediates per process, or lock the revision cache
and publish intermediates atomically. Add a two-process overlap regression.

### CR-4 — Payload identity and runtime roots lack an independent oracle

- **Severity:** Low prevention debt
- **Confidence:** High that the gap exists; current assets are not inferred wrong
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\crates\ferrosintesis-samples-clavinet\src\lib.rs:78`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\crates\ferrosintesis\src\sampler.rs:5590`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-141612\tools\ferrosintesis-samples\prepare.py:4508`
- **Tracked as:** Draft `MM-REQ-KILN-00222`
- **Effort:** Medium; proposed Heavy flow

The crate checks filenames, aggregate size, RIFF/WAVE magic, and lookup against
the same table. All eleven files have equal size, so a cross-note swap can keep
every check green while the consumer uses the old root. The generator measures
roots but does not persist or compare them with the runtime map.

**Concrete requirement:** bind each filename to payload identity and measured
root; validate complete RIFF/PCM extents and format; compare the eleven runtime
mappings; and add adversarial swaps, duplicates, malformed chunks, source-root,
selector, and runtime-root changes. Draft `MM-REQ-KILN-00189` explicitly covers
the separate 36-file MuseScore crate, so it did not deduplicate this record.
