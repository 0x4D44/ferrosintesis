## Confirmed findings

### CR-1 — Quiet C2/G2 aliases retain duplicate decoded PCM after prewarm

- **Severity:** Low
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\crates\ferrosintesis\src\sampler.rs:325`, `:405`, `:456`, `:3104`, `:7576`
- **Tracked as:** `MM-BUG-KILN-00223`

`bank!` calls `parse_wav()` for every zone and stores the result in a new `Vec<f32>`. Both `piano_pp()` and `piano_pp_rr2()` decode `piano_C2_pp.wav` and `piano_G2_pp.wav`, and `prewarm()` initializes both banks. Each file contains 79,732 frames, so the second pair of parses retains 637,856 duplicate decoded bytes.

The current oracle compares sample contents, not allocation identity. The Kawai and Steinway banks already use accessor delegation and pointer-identity assertions for their logical aliases, which confirms the intended local pattern.

**Concrete fix:** share canonical decoded storage for these two partial-bank aliases, or introduce a canonical decode cache. Add an allocation-identity regression for C2/G2 while retaining the existing content and distinct-round-robin checks.

### CR-2 — Core regeneration has no safe complete documented path

- **Severity:** Low
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\crates\ferrosintesis-samples-core\PROVENANCE.md:7`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\tools\ferrosintesis-samples\prepare.py:5774`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\tools\ferrosintesis-samples\gen_crate_lib.py:2`, `:240`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\tools\ferrosintesis-samples\regen_samples_table.py:151`
- **Tracked as:** `MM-BUG-KILN-00224`

The package documents only `prepare.py --only=piano,violin,flute`. That command rewrites WAVs but does not refresh the core crate's `SAMPLES`, `FILE_COUNT`, or `EXPECTED_BYTES`. The generic generator says every sample crate has its emitted shape, but running it on core replaces all of `lib.rs` and drops `PIANO_SINGLE_TAKE_CELLS` plus both compatibility aliases. The region updater can preserve those custom surfaces, but the core package never names it.

The current committed inventory is correct. The defect is the workflow: after a legitimate inventory change, the documented path leaves stale pins, while the apparently generic path silently removes public API.

**Concrete fix:** document and regression-test the complete bake-then-region-update sequence. Make the generic whole-file generator reject custom crates or preserve declared extensions.

### CR-3 — Core assets and runtime roots lack an independent oracle

- **Classification:** durable prevention debt, not current corruption
- **Confidence:** High
- **Location:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\crates\ferrosintesis-samples-core\src\lib.rs:304`; consumer tables begin at `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-152412\crates\ferrosintesis\src\sampler.rs:364`
- **Tracked as:** Draft `MM-REQ-KILN-00225`

The crate checks filenames, aggregate bytes, RIFF/WAVE magic, lookups, and two aliases. It does not bind each filename to an independent payload identity or measured root, and it does not parse the full RIFF/PCM contract. All 52 piano files have the same size, as do the 17 violin/flute files. An equal-sized cross-note payload swap can therefore preserve every crate-local assertion while routing the wrong recording through unchanged runtime roots.

**Concrete action:** add a non-mutating verifier derived from the pinned source and recipe, not from the output directory. It must cover per-file identity and roots, exact RIFF extents and padding, PCM16 mono 44.1 kHz format, selector completeness, and declared aliases. Negative controls are recorded in the Draft requirement.
