## Confirmed findings

### Low — dark-Salamander regeneration can leave a mixed old/new bank

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-162512\tools\ferrosintesis-samples\prepare.py:5053`; per-file writer
  at `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-162512\tools\ferrosintesis-samples\prepare.py:4247`
- **Problem:** `_bake_darkened_grand` reads, transforms, and immediately replaces
  each final tracked WAV. `write_wav_mono` protects one destination, but the
  54-file bank has no staging or rollback. A late read, transform, allocation,
  root-measurement, or replacement failure therefore leaves a new prefix beside
  an old suffix. Every destination can remain present and structurally valid, so
  current inventory and RIFF-magic checks need not reject the mixed generation.
- **Impact:** the documented `--only=darkgrand` regeneration command can leave
  tracked source in an internally mixed
  state after failure. Git makes recovery possible, and rerunning a deterministic
  successful bake repairs it, so severity is Low.
- **Concrete fix:** validate the complete raw-grand plan first; generate all 54
  outputs in an empty staging directory; verify exact inventory and WAV
  contracts; then publish with rollback on any replacement failure. Negative
  controls should inject a late source/transform failure and a late replacement
  failure, and prove every prior destination remains byte-identical.
- **Effort:** Small–Medium
- **Tracking:** `MM-BUG-KILN-00226` (Open, Could / Low).

This is not a duplicate of `MM-BUG-KILN-00123`, which covers obsolete dark
destination names, or `MM-BUG-KILN-00182`, which covers the separately selected
raw-grand regeneration path. The ledger already treats the same failure class
in YDP, bass, and clavinet generators as path-specific defects.
