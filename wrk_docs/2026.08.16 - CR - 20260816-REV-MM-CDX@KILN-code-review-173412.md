### Low — mandatory gate can accept outputs that violate `BAKE-SHA256`

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-173412\crates\ferrosintesis-samples-fretnoise\src\lib.rs:187`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-173412\tools\ferrosintesis-samples\test_fretnoise_bake.py:18`; `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-173412\.deltic-integrate.toml:50`
- **Problem:** the Rust tests compare per-file and aggregate lengths plus RIFF/WAVE magic, not exact digests. The Python exact verifier can skip wholesale without NumPy and skips its real-bank check outside the one canonical environment. The required gate explicitly accepts those skips. A same-length PCM mutation can therefore disagree with its pin while all required predicates stay green.
- **Impact:** altered audio or a same-sized malformed embedded WAV can reach a release. The present assets are correct; this is a false-negative in future release protection.
- **Concrete fix:** add an always-on standard-library verifier that strictly parses `BAKE-SHA256`, requires exact filename-set equality, hashes every committed WAV, and fails a same-length mutation negative control. Keep the canonical re-bake as stronger optional coverage.
- **Effort:** Small
- **Tracking:** `MM-BUG-KILN-00227` (Open, Could / Low).
