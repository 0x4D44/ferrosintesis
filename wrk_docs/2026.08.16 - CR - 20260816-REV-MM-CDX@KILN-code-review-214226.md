## Confirmed findings

### Medium — a tiny header can force an enormous infallible allocation

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\src\lib.rs:334`; allocation at `:342`; late count check at `:350`; second full copy at `:374`
- **Problem:** `STREAMINFO.total_samples` is a 36-bit input field. Its maximum fits
  `usize` on 64-bit hosts, so a 42-byte FLAC-shaped input reaches
  `Vec::with_capacity(68_719_476_735)` before any frame is read. That requests about
  128 GiB and can abort or panic instead of returning the typed `Err` promised by
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\README.md:12`.
  The frame loop pushes before detecting that a block exceeds the declared total, and
  MD5 verification copies the complete PCM into another buffer.
- **Concrete fix:** enforce a supported decoded-size/input bound, reserve fallibly,
  reject a frame before pushing when it exceeds the remaining count, and update MD5
  incrementally from little-endian samples. Add a minimal maximum-count negative.
- **Effort:** Small–Medium
- **Tracking:** `MM-BUG-KILN-00232` (Open, Should / Medium).

### Medium — malformed predictors can overflow before the 16-bit range check

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\src\lib.rs:622`; LPC recurrence at `:667`; residual decode at `:680`
- **Problem:** Rice residuals are not checked against RFC 9639's signed-32-bit
  residual limit. FIXED and LPC restoration then use unchecked `i64` multiplication,
  addition, and subtraction. A small malformed LPC recurrence can overflow before the
  completed frame is narrowed to `i16`: debug builds panic; release builds wrap.
- **Concrete fix:** reject residuals outside the format limit and use checked predictor
  arithmetic. Reject an overflow or out-of-depth reconstructed sample before it feeds
  the next prediction. Add adversarial FIXED and LPC fixtures.
- **Effort:** Small–Medium
- **Tracking:** `MM-BUG-KILN-00233` (Open, Should / Medium).

### Medium — the decoder reads but ignores both frame checksums

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\src\lib.rs:514` and `:522`; zero-MD5 path at `:374`
- **Problem:** CRC-8 and CRC-16 are consumed into underscore variables. A checksum-byte
  mutation therefore returns `Ok` because the decoded PCM and STREAMINFO MD5 are
  unchanged. When the format's permitted all-zero STREAMINFO MD5 is present, corrupted
  audio can also be accepted with no integrity check. RFC 9639 classifies a frame whose
  header or footer CRC fails as invalid.
- **Concrete fix:** calculate and compare CRC-8 over the header and CRC-16 over the full
  frame. Add header/footer mutations with both populated and zero STREAMINFO MD5.
- **Effort:** Medium
- **Tracking:** `MM-BUG-KILN-00234` (Open, Should / Medium).

### Low — forbidden LPC coefficient precision is accepted

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\src\lib.rs:650`
- **Problem:** raw precision field `0b1111` becomes 16 after `+ 1`, but the guard allows
  `MAX_LPC_PRECISION + 1`. RFC 9639 explicitly forbids that field; the local comment at
  `:58` also says precision is at most 15.
- **Concrete fix:** reject raw `0b1111`, or compare the resulting precision directly
  with 15. Add the forbidden pattern as a negative fixture.
- **Effort:** Trivial
- **Tracking:** `MM-BUG-KILN-00235` (Open, Could / Low).

### Low — valid explicit 44.1 kHz frame encodings are rejected

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-214226\crates\ferrosintesis-flac\src\lib.rs:499`
- **Problem:** sample-rate codes 13 and 14 are read and rejected unconditionally.
  RFC 9639 allows code 13 to carry `44100` Hz and code 14 to carry `4410` tens-of-Hz.
  Both are valid encodings of the crate's advertised mono, 16-bit, 44.1 kHz shape.
- **Concrete fix:** normalize explicit rate values to Hz with checked arithmetic and
  compare them with both STREAMINFO and 44,100 Hz. Add positive code-13/code-14 fixtures
  and wrong-value negatives.
- **Effort:** Small
- **Tracking:** `MM-BUG-KILN-00236` (Open, Could / Low).
