## Confirmed findings

### Low — the public sample API still promises WAV keys and bytes

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\src\lib.rs:12-25`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\README.md:3-5`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\PROVENANCE.md:93-108`
- **Problem:** `get()` is documented as returning WAV bytes for case-sensitive `.wav`
  names, but its only keys and payloads are `.flac`. A caller following rustdoc receives
  `None`; a caller using the actual key while trusting the container prose feeds FLAC to
  a WAV parser. The provenance table also publishes retired `.wav` output names and the
  old 2,971,398-byte aggregate rather than the current 1,160,636-byte package.
- **Concrete fix:** choose the supported compatibility contract. Either document FLAC
  keys/bytes everywhere or intentionally retain aliases with explicit container semantics.
  Add a guard proving every documented lookup key resolves and rejecting stale format prose.
- **Effort:** Small
- **Tracking:** `MM-BUG-KILN-00238` (Open, Should / Low)

### Low — the documented regeneration command leaves the embedded bank stale

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\README.md:15-18`;
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\PROVENANCE.md:130-140`;
  output map at
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\tools\ferrosintesis-samples\prepare.py:1091-1098`;
  writer at `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\tools\ferrosintesis-samples\prepare.py:5444-5462`
- **Problem:** both package documents advertise `prepare.py --local-only` as the complete
  regeneration path. That recipe writes two `.wav` files while `src/lib.rs` continues to

  unmentioned `to_flac.py` describes itself as a one-time conversion, not part of the recipe.
- **Concrete fix:** make the selected recipe atomically produce verified FLAC outputs, or
  publish and test a complete two-step workflow. In an isolated tree, prove both embedded
  payloads change as intended and no duplicate WAV remains.
- **Effort:** Small–Medium

### Prevention debt — asset identity and runtime layer mapping are not independently bound

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis-samples-gong\src\lib.rs:43-89`;
  runtime mapping at
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-224326\crates\ferrosintesis\src\sampler.rs:5261-5284`
- **Problem:** crate tests prove directory-name parity, aggregate size, four-byte magic,
  and self-table lookup. Swapping the soft and loud `include_bytes!` paths preserves all

- **Concrete fix:** bind source IDs, output hashes, decoded format/duration, soft/loud
  distinctness, exact runtime keys, velocity routing, and onset continuity in one
  non-mutating oracle. Include payload-swap, duplicate, malformed/truncated FLAC, stale
  key, and omitted-from-sweep negatives.
- **Effort:** Medium
- **Tracking:** Draft `MM-REQ-KILN-00242` (proposed Could / heavy). Draft
  `MM-REQ-KILN-00237` covers decoder conformance, not this bank's identity or routing.
