# Code review — `crates/ferrosintesis-samples-grand/`

Read-only review of the assigned grand-piano asset crate at the fresh local baseline.
The pass inspected source, manifest, packaged documentation, provenance, the 54 asset
headers/hashes, direct runtime lookups, and only the regeneration code needed to
establish the crate's contracts. It did not run the app, tests, decoder, generators,
rendering, packaging, or the exploratory-test harness.

## Confirmed findings

### Low — public lookup contract still promises WAV after the FLAC migration

- **Confidence:** High.
- **Evidence:**
  `D:\worktrees\ferrosintesis\20260816-REV-MM-CDX@KILN-code-review-234326\crates\ferrosintesis-samples-grand\src\lib.rs:235-237`
  requires `.wav` names, while every table key at `src\lib.rs:18-231` is `.flac`.
  `README.md:3-5` repeats the wrong format. `PROVENANCE.md:9-15,51-64` also pins
  the obsolete 7,184,592-byte WAV inventory; the committed FLAC total is 2,361,631.
- **Impact:** A caller following rustdoc receives `None` for a documented real WAV
  key, and package auditors receive a false format and size record.
- **Concrete fix:** Align rustdoc, README, and provenance with FLAC; assert that a
  documented real key resolves and derive format/size claims from the inventory.
- **Effort:** Small.
- **Tracked:** `MM-BUG-KILN-00243`.

### Low — documented grand regeneration writes unconsumed WAVs and leaves FLAC stale

- **Confidence:** High.
- **Evidence:** `README.md:19-27` and `PROVENANCE.md:66-72` promise
  `prepare.py --only=grand`; `tools\ferrosintesis-samples\prepare.py:681-686`
  names WAV outputs and `prepare.py:5733-5778` writes them. The crate embeds only
  FLAC. The validator at `prepare.py:5419-5424` also ignores FLAC names.
- **Impact:** The documented command adds 54 WAVs beside 54 old FLACs, fails the
  crate's 54-file inventory check, and never refreshes what runtime consumes.
- **Concrete fix:** Make the scoped recipe own final FLAC conversion and inventory
  refresh, and reject mixed-format output before the first write.
- **Effort:** Medium.
- **Tracked:** `MM-BUG-KILN-00244`.

### Low — grand bank publication is not failure-atomic

- **Confidence:** High from control-flow inspection; no failure injection ran.
- **Evidence:** The generic loop publishes each grand file at
  `tools\ferrosintesis-samples\prepare.py:5733-5778`; `write_wav_mono` at
  `prepare.py:4247-4265` protects one file, not the 54-file generation.
- **Impact:** A late failure leaves a valid-looking mix of old and new samples.
- **Concrete fix:** Build and validate the complete final-format bank in empty
  staging, then publish with rollback. Prove late transform and replacement failures
  preserve the prior bank byte-for-byte.
- **Effort:** Small–Medium.
- **Tracked:** `MM-BUG-KILN-00245`.

### Low — dark-Salamander regeneration no longer sees its FLAC grand sources

- **Confidence:** High.
- **Evidence:** `tools\ferrosintesis-samples\prepare.py:5032-5047` selects only
  `grand_*.wav`; the reviewed grand bank contains 54 FLAC files and zero WAVs. The
  loop at `prepare.py:5051-5069` therefore has no inputs.
- **Impact:** `prepare.py --only=darkgrand` silently leaves the derived bank stale.
- **Concrete fix:** Read the current FLAC sources, require the exact non-empty source
  inventory, emit the final format, and make empty selection fail closed.
- **Effort:** Small–Medium.
- **Tracked:** `MM-BUG-KILN-00246`.
