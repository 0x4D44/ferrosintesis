its scoped regeneration path. All are Low severity because they affect package

- `MM-BUG-KILN-00256` — concurrent regenerations race fixed shared intermediates.

No new requirement was needed. Draft `MM-REQ-KILN-00144` already covers

and a nonzero MD5. Full decode, PCM identity, pitch, and audible correctness

- **Label:** Issue

  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\crates\ferrosintesis-samples-musescore-grand\PROVENANCE.md:9`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\crates\ferrosintesis-samples-musescore-grand\src\lib.rs:14`
- **Tracked as:** Open `MM-BUG-KILN-00253`
- **Effort:** Small

The README says the bank contains WAVs. The provenance repeats that claim for
the committed source and output. The package now exposes only `.flac` keys. A
standalone consumer following the published physical-format description can
derive a `.wav` lookup name that `get()` does not contain, while the package's
audit trail states the wrong shipped container.

**Concrete fix:** update README and provenance to describe the 25 final FLAC
payloads and their processing. Document the complete final-format regeneration
workflow. Add a source-derived guard that compares package format claims and a
documented real key with the embedded inventory.

Open `MM-BUG-KILN-00243` covers the separate
`ferrosintesis-samples-grand` crate. It cannot close this independently
published package's contract.

### CR-2 — Documented regeneration leaves the active FLAC bank stale

- **Label:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\crates\ferrosintesis-samples-musescore-grand\README.md:14`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:4643`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:5419`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\crates\ferrosintesis\src\sampler.rs:1572`
- **Tracked as:** Open `MM-BUG-KILN-00254`
- **Effort:** Medium

The documented `--only=musescoregrand` path validates and writes 25 `.wav`
names. Its stale-output guard examines only WAV files. The current package and
runtime consume 25 `.flac` names. Following the published command therefore
leaves playback on the old FLAC bytes, writes 25 unconsumed WAVs beside them,
and makes the crate inventory see 50 sample files against `FILE_COUNT = 25`.

**Concrete fix:** generate, encode, and verify the final FLAC set in an empty
staging directory. Reject mixed containers before publication, replace the
active bank as one scoped workflow, and refresh the generated inventory. Add a
negative fixture that begins with the current FLAC-only package.

### CR-3 — Late failure can publish a partial mixed bank

- **Label:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:4247`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:4647`
- **Tracked as:** Open `MM-BUG-KILN-00255`
- **Effort:** Medium

The bake publishes each zone directly after processing it. `write_wav_mono`
atomically replaces one file, but there is no bank-level staging, rollback, or
final transaction. A later decode, transform, measurement, allocation, or write
failure leaves the already-replaced prefix beside an old suffix. Each file can
remain individually valid while the bank combines two generations.

**Concrete fix:** stage every final-format zone, validate the complete exact
inventory there, then publish the bank with rollback. Add late-transform and
replacement-failure controls; both must preserve the previous bank byte for
byte. This remains necessary after CR-2 corrects the target container.

### CR-4 — Concurrent regenerations race fixed shared intermediates

- **Label:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:4650`;
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-030926\tools\ferrosintesis-samples\prepare.py:5695`
- **Tracked as:** Open `MM-BUG-KILN-00256`
- **Effort:** Small–Medium

Every worktree uses the same system-temp `musescore_general` directory. Each
run truncates fixed `msgrand_<root>.ogg` paths and asks ffmpeg to overwrite the
same fixed WAV paths before reading them. Concurrent scoped runs can therefore
read an intermediate while a peer truncates or replaces it, causing a spurious
failure or publishing data from a peer's partial intermediate.

**Concrete fix:** use a process-unique decode directory, or serialize access and
atomically publish authenticated intermediates. Add a two-process regression
that deliberately overlaps extraction, ffmpeg output, and WAV consumption.
Open `MM-BUG-KILN-00221` covers the distinct MS Basic clavinet function and does
not exercise this MuseScore_General route.
