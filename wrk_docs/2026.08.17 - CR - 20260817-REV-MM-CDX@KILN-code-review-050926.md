## Confirmed findings

### 1. Required preflight and non-banjo rebakes still target WAV

- **Severity:** Medium.
- **Confidence:** High.
- **Location:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\crates\ferrosintesis-samples-orchestral2\PROVENANCE.md:7`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\prepare.py:5342`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\prepare.py:5402`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\prepare.py:5733`, and
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\test_prepare.py:2823`.
- **Evidence:** the documented scoped recipes derive, validate, and write `.wav`
  names. The crate and direct consumer use only `.flac`. A rebake adds unconsumed
  WAVs while leaving runtime on stale FLACs. The required family-map preflight also
  compares WAV expectations with only on-disk WAVs, so every converted family
  disagrees with its FLAC-only directory.
- **Impact:** the committed required Python gate is deterministically red, and the
  published regeneration route cannot update the shipped sound.
- **Concrete fix:** separate source names from canonical output names; stage,
  encode, and verify the final FLAC inventory; reject mixed containers; update the
  preflight to derive the same final-format set.
- **Effort:** Medium.
- **Tracked as:** `MM-BUG-KILN-00262`.

### 2. Banjo extraction and its required tests cannot read the FLAC inventory

- **Severity:** Medium.
- **Confidence:** High.
- **Location:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\banjo_extract.py:40`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\banjo_extract.py:57`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\banjo_extract.py:83`, and
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\test_banjo_extract.py:26`.
- **Evidence:** the extractor recognizes only `.wav` names found on the same line
  as `include_bytes!`; the current crate and sampler expose 24 `.flac` names. Its
  inventory check therefore compares zero crate names with 24 sampler names and
  raises. The publication tests call that check during `setUp`, before test bodies.
- **Impact:** the published banjo command cannot produce a valid active bank, and
  its required test module errors whenever its optional NumPy dependency is present.
- **Concrete fix:** derive the inventory independently of rustfmt layout, publish
  a staged and verified FLAC bank, reject stale opposite-container files, and add
  split-layout and WAV-only negative controls.
- **Effort:** Medium.
- **Tracked as:** `MM-BUG-KILN-00263`.

### 4. Family publication is atomic per file, not per bank

- **Severity:** Low.
- **Confidence:** High.
- **Location:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\prepare.py:4247` and
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-050926\tools\ferrosintesis-samples\prepare.py:5733`.
- **Evidence:** the generic loop writes each transformed zone directly. Its `.part`
  plus `os.replace` protects one file only; there is no family staging, exact final
  inventory transaction, or rollback.
- **Impact:** a late failure leaves a valid-looking prefix from the new bake beside
  an old suffix. Correcting the FLAC target alone would still permit a mixed active
  bank.
- **Concrete fix:** build each selected family in empty staging, validate the whole
  final-format set, then publish it with rollback. Add late-transform and failed-
  replacement negative controls that preserve the old bank byte-for-byte.
- **Effort:** Medium.
- **Tracked as:** `MM-BUG-KILN-00265`.
