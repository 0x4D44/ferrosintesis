## Confirmed findings

### CR-1 — the documented sax regeneration command leaves the active FLAC bank stale

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\crates\ferrosintesis-samples-sax\README.md:21`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\crates\ferrosintesis-samples-sax\PROVENANCE.md:84`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\tools\ferrosintesis-samples\prepare.py:5220`
- **Tracking:** `MM-BUG-KILN-00269` (new, Open)
- **Problem:** the package publishes `prepare.py --sax-only` as its regeneration path.
  `_bake_mtg_sax` names and writes 74 `.wav` outputs, while the package and runtime use
  only `.flac` names. The stale-output validator at
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\tools\ferrosintesis-samples\prepare.py:5419`
  also scans only WAVs.
- **Impact:** following the documented command leaves all 74 active FLAC payloads
  unchanged and adds 74 unconsumed WAVs. The crate inventory then sees 148 sample files
  against `FILE_COUNT = 74`, so the documented workflow neither refreshes playback nor
  returns a valid package.
- **Concrete fix:** generate into empty staging, encode and independently verify the
  canonical FLAC set, reject mixed same-stem containers, atomically replace the active
  bank, and refresh the generated inventory. Add a regression starting from the current
  FLAC-only package.
- **Effort:** Medium.

### CR-2 — the published sax API and provenance still promise WAV keys and payloads

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\crates\ferrosintesis-samples-sax\src\lib.rs:314`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\crates\ferrosintesis-samples-sax\README.md:8`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-071126\crates\ferrosintesis-samples-sax\PROVENANCE.md:10`
- **Tracking:** `MM-BUG-KILN-00268` (new, Open)
- **Problem:** `get()` promises embedded WAV bytes and exact `.wav` names, but all 74
  keys are `.flac` and lookup is exact. README and provenance repeat the retired
  container. Provenance also attests 4,101,968 packaged bytes and the old
  `inventory_matches_packaged_wavs` name; the current package is 2,470,849 bytes and the
  test is `inventory_matches_packaged_samples`.
- **Impact:** a standalone caller following the Rustdoc receives `None` for every
  documented key. A package auditor receives a false container and byte attestation.
- **Concrete fix:** choose whether WAV-key compatibility is supported, then update the
  Rustdoc, README, provenance names, processing description, and byte total together.
  Add a source-derived guard proving each documented key resolves and the reported
  aggregate matches the packaged set.
- **Effort:** Small.
