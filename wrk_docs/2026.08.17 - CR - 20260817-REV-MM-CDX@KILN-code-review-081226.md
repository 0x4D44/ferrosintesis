## Confirmed findings

### CR-1 — the documented strings regeneration command leaves the active FLAC bank stale

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\crates\ferrosintesis-samples-strings\README.md:26`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\crates\ferrosintesis-samples-strings\PROVENANCE.md:7`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\tools\ferrosintesis-samples\prepare.py:5778`
- **Tracking:** `MM-BUG-KILN-00271` (new, Open)
- **Problem:** the package publishes `prepare.py --only=cellosolo,dbass,pizzbass` as
  its regeneration path. The three source tables at `prepare.py:354`, `prepare.py:372`,
  and `prepare.py:479` still own `.wav` output names, and the generic writer preserves
  that suffix. The package and runtime now use only `.flac` names. The stale-output
  validator at `prepare.py:5402` also scans only WAVs.
- **Impact:** following the documented command leaves all 40 active FLAC payloads
  unchanged and adds 40 unconsumed WAVs. The crate inventory then sees 80 sample files
  against 40 embedded entries, so the documented workflow neither refreshes playback
  nor returns a valid package.
- **Concrete fix:** generate into empty staging, encode and independently verify the
  canonical FLAC set, reject mixed same-stem containers, atomically replace the active
  bank, and refresh the embedded inventory. Add a negative regression starting from the
  current FLAC-only package.
- **Effort:** Medium.

### CR-2 — the published strings API and provenance still promise WAV keys and payloads

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\crates\ferrosintesis-samples-strings\src\lib.rs:18`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\crates\ferrosintesis-samples-strings\README.md:6`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-081226\crates\ferrosintesis-samples-strings\PROVENANCE.md:3`
- **Tracking:** `MM-BUG-KILN-00270` (new, Open)
- **Problem:** `get()` promises exact `.wav` names and embedded WAV bytes, but all 40
  keys at `src/lib.rs:23-180` are `.flac` and lookup at `src/lib.rs:190-195` is exact.
  README and provenance repeat the retired container and filename example.
- **Impact:** a standalone caller following the Rustdoc receives `None` for every
  documented WAV key. A package auditor receives a false container description.
- **Concrete fix:** choose whether WAV-key compatibility is supported, then update the
  Rustdoc, README, and provenance together. Add a source-derived guard proving each
  documented key resolves against the packaged set.
- **Effort:** Small.
