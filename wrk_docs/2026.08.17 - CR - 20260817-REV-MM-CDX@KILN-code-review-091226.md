## Confirmed findings

### CR-1 — the FLAC migration removed 27 legacy WAV lookup keys

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\crates\ferrosintesis-samples-vcsl-steinway\src\lib.rs:15`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\crates\ferrosintesis-samples-vcsl-steinway\README.md:8`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\crates\ferrosintesis-samples-vcsl-steinway\PROVENANCE.md:9`
- **Tracking:** `MM-BUG-KILN-00272` (new, Open)
- **Problem:** before migration commit `9046cd1`, `get()` accepted 54 `.wav`
  names. The migration changed the 27 physical keys to `.flac`, retained aliases
  only for the other 27 WAV names, and left `get()` exact. Published docs still
  describe WAV payloads and a 54-name logical bank.
- **Impact:** calls such as `get("steinwayb_C2_pp.wav")` now return `None`, while
  the replacement `.flac` key succeeds. In-repo playback works because the
  sampler moved to FLAC, but standalone callers lost half of the prior lookup
  surface and package auditors receive a stale container contract.
- **Concrete fix:** add compatibility aliases for all 27 former physical WAV
  names, preserve the canonical FLAC keys, update the accepted-name count and
  package documents, and derive a regression from the complete pre-migration
  logical WAV name set.
- **Effort:** Small.

### CR-2 — the documented regeneration command leaves the active FLAC bank stale

- **Type:** Issue
- **Severity:** Low
- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\crates\ferrosintesis-samples-vcsl-steinway\README.md:15`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\tools\ferrosintesis-samples\prepare.py:720`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-091226\tools\ferrosintesis-samples\prepare.py:5778`
- **Tracking:** `MM-BUG-KILN-00273` (new, Open)
- **Problem:** the published `prepare.py --only=steinwayb` path still owns and
  writes 27 `.wav` outputs. The package and runtime now use 27 `.flac` outputs,
  while the preflight scans only WAV names.
- **Impact:** the documented command adds 27 unconsumed WAVs beside 27 unchanged
  FLACs. Runtime keeps rendering the stale FLAC bank, the crate inventory sees 54
  files against 27 entries, and the source-derived alias check retains the old
  WAV target contract.
- **Concrete fix:** generate and verify the final FLAC set in empty staging,
  reject mixed same-stem containers, atomically publish the complete bank, and
  refresh the alias/Rust inventory together. Add a negative control starting
  from the current FLAC-only package.
- **Effort:** Medium.
