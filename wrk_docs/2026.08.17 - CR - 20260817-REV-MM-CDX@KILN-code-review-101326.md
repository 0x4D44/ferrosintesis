## Confirmed findings

### CR-1 — Decoded MIDI event amplification can exhaust memory

- Severity: Medium
- Confidence: High; independently found by the security, performance, and reliability lenses, then re-derived from the source.
- Evidence: `crates/ferrosintesis/src/midi.rs:303-305`, `:334-439`, `:494-501`; `crates/ferrosintesis/src/engine.rs:4268-4272`.
- Failure: a legal format-0 SMF under the 64 MiB `load()` cap can encode roughly 16–22 million zero-delta running-status channel events. Song duration remains zero, so the duration guard does not help. The raw and converted event vectors coexist, and rendering creates another complete mapping. Transient memory can exceed 1 GiB before a typed error.
- Fix: add a decoded-event/resource budget and `TooManyEvents` error before retained pushes. Bound retained marker text too. Avoid the render-time copy where practical. Add a compact event-flood regression.
- Effort: Small–Medium.
- Tracking: `MM-BUG-KILN-00274`.

### CR-2 — `ScaledVoice` allocates on first realtime render

- Severity: Medium
- Confidence: High; the allocation follows directly from `Vec::new()` then `resize()`.
- Evidence: `crates/ferrosintesis/src/voices.rs:14151-14190`, `:14255-14271`; `crates/ferrosintesis/src/live.rs:397-417`.
- Failure: each velocity-corrected wrapper starts with empty scratch and grows it inside its first render block. The documented prewarm/reserve calls do not reserve this buffer. A chord repeats the allocator entry once per corrected voice.
- Fix: use bounded inline scratch, pre-size at construction, or reuse an engine scratch pool. Add allocator-count regressions for a corrected melodic voice and drum voice.
- Effort: Small–Medium.
- Tracking: `MM-BUG-KILN-00276`. Open `MM-BUG-KILN-00216` covers the same defect shape in `LaVoice`, not this independent wrapper.

### CR-3 — Pluck articulations allocate repeatedly in the realtime callback

- Severity: Medium
- Confidence: High; both allocation sites are on accepted live event paths.
- Evidence: `crates/ferrosintesis/src/voices.rs:5437-5447`, `:5473-5512`; `crates/ferrosintesis/src/engine.rs:2671-2684`, `:2723-2735`; `crates/ferrosintesis/src/live.rs:397-414`.
- Failure: every accepted CC68 slur collects a new hammer vector. Every 10–16 Hz tremolo restrike allocates both `raw` and `exc`, then replaces `hammer`. This repeats heap work on the deadline-bearing thread.
- Fix: keep reusable raw/excitation storage on `Pluck`, reserve it before realtime use, and fill it in place. Add an allocation-count regression across repeated slurs and retriggers.
- Effort: Medium.
- Tracking: `MM-BUG-KILN-00277`.

### CR-4 — Zero Set-Tempo produces a non-finite public result

- Severity: Low
- Confidence: High; the arithmetic is deterministic.
- Evidence: `crates/ferrosintesis/src/midi.rs:358-362`, `:470-480`, `:502-519`; `crates/ferrosintesis/src/offline.rs:91-95`.
- Failure: `FF 51 03 00 00 00` is accepted as zero microseconds per quarter. Later tick-separated events all map to the same time, the duration guard passes, and public `Song::initial_bpm()` returns positive infinity.
- Fix: reject `us == 0` while decoding Set-Tempo and add a regression that asserts separated timestamps and finite BPM for every successful parse.
- Effort: Small.
- Tracking: `MM-BUG-KILN-00275`.

### CR-5 — Public payload rustdoc is stale and evades its oracle

- Severity: Low
- Confidence: High; the current payload was independently enumerated from disk.
- Evidence: `crates/ferrosintesis/src/lib.rs:51-53`; `crates/ferrosintesis/src/payload.rs:123-149`; `crates/ferrosintesis/README.md:84-96`.
- Failure: rustdoc says 111 MiB and 1156 WAVs. The current 25 sample crates contain 1080 WAV/FLAC recordings totaling 56,450,470 bytes (53.835 MiB). The size guard scans one line at a time: `compiles` is on line 51 and `MiB` on line 52, so it skips the stale paragraph and passes on another document's correct claim.
- Fix: update rustdoc to about 54 MiB and 1080 recordings; parse whole paragraphs or joined continuation lines; add a wrapped stale-claim negative fixture.
- Effort: Small.
- Tracking: `MM-BUG-KILN-00278`.

## Tracked design debt

`MM-REQ-KILN-00279` proposes one authoritative loudness-normalization policy shared by buffered and disk-backed adapters. `engine.rs:4361-4409` and `scratch.rs:147-203` duplicate the iteration and ceiling decisions, while `loudness.rs:484-540` and `scratch.rs:236-254` duplicate limiter tuning consumption. `scratch.rs:181-186` records that parity testing already missed `MM-BUG-CRUCIBLE-00031` because both copies carried the same defect. Proposed effort: Medium–Heavy.

## Report-only coverage gaps and maintainability notes

- `crates/ferrosintesis/src/sampler.rs:71-81` has no exact oracle for the FLAC-to-`f32` integration seam or `/32768.0` mapping. The existing bank checks at `:7544-7601` validate broad length/root/peak properties. Draft `MM-REQ-KILN-00237` already owns decoder conformance, so no overlapping requirement was minted. A tiny known-PCM FLAC/RIFF parity fixture would close the caller-glue gap.
- Breath-family membership is duplicated between note-on initialization and block-time updates at `crates/ferrosintesis/src/engine.rs:2864-2894` and `:3728-3763`. The current ranges agree, so this is drift risk rather than a current defect.

## Not reported

- **Refuted — 24-hour buffered render allocation.** `offline::render` can allocate tens of GiB for a very long accepted song, but `crates/ferrosintesis/src/offline.rs:138-145` explicitly documents the allocation, exposes `Song::seconds()` for preflight, and offers bounded-memory `render_to_wav`. This is an intentional lower-level API contract.
- **Refuted — zero PPQN needs a second defect.** The normal timed-event case is deliberately rejected through the finite-duration guard and pinned at `crates/ferrosintesis/src/parse_robustness.rs:425-435`. A metadata-only file can still parse, but this pass established no shipped behavioral impact beyond an imprecise error policy.
- **Refuted — realtime queue overflow is silently safe.** It is not lossless, but `crates/ferrosintesis/src/live.rs:323-347` explicitly documents drop-newest behavior and a persistent drop counter. The trigger is roughly 700 times physical MIDI wire traffic per block. Changing recovery semantics is a design choice, not a confirmed contradiction in this API.
- **Deduplicated — FLAC decoder resource/integrity candidates.** Open `MM-BUG-KILN-00232` through `MM-BUG-KILN-00236` already track allocation, arithmetic, CRC, LPC, and explicit-rate defects.
- **Out of scope as an external-input defect.** `sampler.rs` RIFF parsing receives compile-time embedded assets, not runtime attacker-controlled input.

## Verification limits

This pass was contractually static. It did not run tests, builds, renders, the app, or the exploratory harness. Every confirmed item is source-proven; runtime impact magnitude and audible dropout duration remain unverified where stated in the bug records.
