## Confirmed findings

### Medium — malformed high-bit GM payload can hide a same-pitch overlap

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-111645\crates\render-catalog\tests\album_midi_overlaps.rs:73-78,121-137,227-269`;
  production comparison at
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-111645\crates\ferrosintesis\src\midi.rs:97-104,373-382`
- **Tracked as:** `MM-BUG-KILN-00280`
- **Effort:** Small

The audit's `is_gm_system_on` wildcard accepts any device byte, including `0xFF`.
Production rejects every SysEx body containing a high-bit byte before matching the GM
message. For `NoteOn(60) -> F0 05 7E FF 09 01 F7 -> NoteOn(60) -> NoteOff(60)`, the
audit invents a reset and reports clean; production ignores the malformed message and
keeps an overlapping, unmatched first voice.

**Concrete fix:** require the message body to be seven-bit before matching it. Add a
red-before-fix negative control with this exact sequence and require one overlap plus one
unmatched note-on.

### Low — the overlap audit rejects production-valid timelines above `u32` ticks

- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-111645\crates\render-catalog\tests\album_midi_overlaps.rs:53,86-92`;
  production comparison at
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-111645\crates\ferrosintesis\src\midi.rs:303,323,340`
- **Tracked as:** `MM-BUG-KILN-00281`
- **Effort:** Small

The audit uses checked `u32` accumulation while production deliberately uses `u64`.
Seventeen maximum legal VLQ deltas total 4,563,402,735 ticks. At division 32,767 and
120 BPM, that is about 19.34 hours: below production's 24-hour limit, but above
`u32::MAX`. The renderer accepts the file while the repository oracle returns
`absolute tick overflow`.

**Concrete fix:** carry audit ticks as `u64`, matching production, and add a
red-before-fix boundary fixture with seventeen maximum deltas and a balanced note.
