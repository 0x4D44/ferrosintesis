### 1. Scoped regeneration cannot update the active FLAC bank

- **Severity:** Medium.
- **Confidence:** High.
- **Location:**
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-141930\crates\ferrosintesis-samples-orchestral\PROVENANCE.md:7`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-141930\tools\ferrosintesis-samples\prepare.py:5303`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-141930\tools\ferrosintesis-samples\prepare.py:5402`,
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-141930\tools\ferrosintesis-samples\prepare.py:5733`, and
  `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-141930\tools\ferrosintesis-samples\test_prepare.py:2823`.
- **Evidence:** the published recipe derives, validates, and writes `.wav`
  names. The package and synth use only `.flac`. A rebake creates unconsumed
  WAVs beside stale FLACs; the required family-map preflight also compares WAV
  expectations with only on-disk WAVs.
- **Impact:** the required Python gate is deterministically inconsistent with
  the committed tree, and the published regeneration route cannot update the
  shipped sound.
- **Concrete fix:** separate source names from canonical output names; stage,
  encode, and verify the final FLAC inventory; reject mixed containers; publish
  the complete validated set; update the preflight from the same source of truth.
- **Effort:** Medium.
- **Tracked as:** `MM-BUG-KILN-00287`.
