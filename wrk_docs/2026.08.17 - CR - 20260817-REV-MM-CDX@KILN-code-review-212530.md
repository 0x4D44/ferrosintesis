## Confirmed findings

### Low — public API still documents WAV keys and bytes after the FLAC migration

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\crates\ferrosintesis-samples-fretnoise\src\lib.rs:20`, `:78`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\crates\ferrosintesis-samples-fretnoise\README.md:13`, `:41`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\crates\ferrosintesis-samples-fretnoise\PROVENANCE.md:68`
- **Problem:** every lookup key now ends in `.flac`, but the public `get` contract says it returns WAV bytes and requires a `.wav` suffix. `get` compares exact strings, so a caller following the documentation and requesting `fretnoise_rr01.wav` receives `None`. The README and provenance repeat the retired container contract.
- **Concrete fix:** document the actual FLAC keys and payloads everywhere, or deliberately provide compatible aliases without labeling FLAC bytes as WAV. Add a positive test for a documented key and a source-derived documentation/API consistency guard.
- **Effort:** Small
- **Tracking:** `MM-BUG-KILN-00291` (Open, Should / Low).

### Low — reproduction recipe omits the required `ffmpeg` executable

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\crates\ferrosintesis-samples-fretnoise\README.md:27`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\tools\ferrosintesis-samples\requirements-fretnoise-bake.txt:1`; `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\tools\ferrosintesis-samples\fretnoise_bake.py:68`, `:85`
- **Problem:** the published setup installs the required Python and NumPy, then tells the user to run `--verify`. Verification now invokes `ffmpeg` unconditionally to decode committed FLAC files, and a normal bake also invokes it to encode. A machine satisfying every documented step but lacking `ffmpeg` fails with `FileNotFoundError`.
- **Concrete fix:** document the executable and PATH requirement in the crate README and provenance, add a clear preflight error, and cover the missing-executable path. The PCM pins do not require an `ffmpeg` version pin.
- **Effort:** Trivial–Small
- **Tracking:** `MM-BUG-KILN-00292` (Open, Could / Low).

### Low — a successful normal rebake retains obsolete packaged outputs

- **Confidence:** High
- **Where:** `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\tools\ferrosintesis-samples\fretnoise_bake.py:295`, `:343`, `:366`; package allowlist at `D:\worktrees\ferrosintesis\20260817-REV-MM-CDX@KILN-code-review-212530\crates\ferrosintesis-samples-fretnoise\Cargo.toml:10`
- **Problem:** `output_pin_errors` checks existing output names only when it receives `out_dir`, but normal bake mode passes `None`. The write loop encodes generated names and never detects or removes obsolete owned FLACs. Retiring a cut and updating its pin/table can therefore yield a successful bake while the retired file remains packaged; the later crate inventory test fails, and packaging without that test can carry the stale payload.
- **Concrete fix:** stage the complete bank in an empty directory, validate exact output-name equality, then publish atomically while removing only obsolete files owned by this generator. Add a removed-take negative control.
- **Effort:** Small–Medium
- **Tracking:** `MM-BUG-KILN-00293` (Open, Should / Low).
