Read-only multi-lens review. Area picked from `wrk_docs/review-coverage.md`; the assigned

## Summary

The bass crate itself is in good shape: 13 tracked FLAC assets, all structurally uniform
and distinct, byte pin current, licence and packaging clean, and the version pin consistent
with the just-published release. Four defects surfaced, and **all four are wider than this
crate** — the bass area was where they became visible, not where they live. The strongest
is a legal-instruction miscount in a crate that shipped to crates.io two commits ago.

| # | Severity | Finding | Tracking |
|---|---|---|---|
| 1 | Medium | Shipped `NOTICE` orders distributors to reproduce **ten** attribution notices; nine exist and nine are listed | `MM-BUG-CRUCIBLE-00038` |
| 2 | Medium | Packaged FLAC banks pin `EXPECTED_BYTES` to one ffmpeg build, so the documented re-bake fails the crate's own oracle | `MM-BUG-CRUCIBLE-00039` |
| 3 | Medium | The generated per-crate payload test compares `SAMPLES` to itself; nothing binds an embedded payload to its packaged file | `MM-BUG-CRUCIBLE-00040` |
| 4 | Low | `banks_parse` is a hand-written chain covering 34 of ~57 zone families; both bass banks are outside it | `MM-BUG-CRUCIBLE-00041` |

## What I measured directly

Parsed the FLAC STREAMINFO block of all 13 committed bass assets from the raw bytes:

| Property | Measured value |
|---|---|
| Sample rate | 44100 Hz — all 13 |
| Channels / depth | mono / 16-bit — all 13 |
| Decoded length | **40042 frames (908.0 ms) — identical in all 13** |
| STREAMINFO MD5 | **13 distinct values** — no duplicated payload |
| Aggregate file size | 365281 bytes — exactly matches `src/lib.rs:84` |
| Tracked in git | 18 files, 13 `.flac`, no stray `.wav` |

The sibling `crates/ferrosintesis-samples-strings/samples/pizzbass_E1.flac` is also 40042
frames, so the fixed decoded length is a repo-wide bake constant. That is the fact that
keeps `MM-REQ-KILN-00211`'s undetectable-swap concern alive across the WAV→FLAC migration:
compressed sizes differ, but a swap preserves the multiset of sizes and so preserves the
aggregate sum exactly.

## Findings

### 1. Medium — shipped NOTICE instructs distributors to reproduce ten notices; there are nine

- **Confidence:** High (counted from manifests and from the document itself)
- **Where:** `D:\worktrees\ferrosintesis\20260818-REV-MM-CLA@CRUCIBLE-code-review-003823\crates\ferrosintesis\NOTICE:7-14`;
  second site at
  `D:\worktrees\ferrosintesis\20260818-REV-MM-CLA@CRUCIBLE-code-review-003823\crates\ferrosintesis\src\licensing.rs:7`
- **Problem:** the NOTICE says a default build compiles "twenty-four" sample crates,
  "Fifteen are CC0", and "the **ten** below are not" — then repeats "ten" in the mandatory
  sentence "YOU MUST REPRODUCE THE TEN NOTICES LISTED HERE". 24 − 15 = 9. Nine crates are
  named, and a census of the manifests finds exactly nine non-CC0 licences (3 MIT, 3
  CC-BY-3.0, 2 CC-BY-4.0, 1 dual). The index's *content* is correct and complete; only the
  count word is wrong. Separately `licensing.rs:7` says the feature pulls in "twenty-five"
  crates; the list has 24, and `licensing.rs` is packaged, so it renders on docs.rs.
- **Why it matters:** these are the only sentences in the repo phrased as a legal
  instruction to a third party, and `ferrosintesis` 0.21.58 published from this tree. A
  distributor told to reproduce ten notices finds nine and cannot tell which is wrong.
- **Why nothing caught it:** `licensing.rs` derives the attribution set and proves
  *coverage*, but never reads the surrounding prose. The list is derived; the number
  describing it is not. Closed `MM-BUG-KILN-00121` deliberately declined to add a count
  assertion ("do not add another hand-maintained count") — sound as reasoning, but it left
  the existing counts unguarded and they have since drifted.
- **Concrete fix:** drop the bare numerals from the instruction, and add one derived
  assertion that any numeral the document does state equals the size of the already-derived
  set. Prove it red on a document whose count disagrees.
- **Effort:** Small–Medium

### 2. Medium — the packaged banks are pinned to one ffmpeg build

- **Confidence:** High for the embedded version string (measured); the cross-toolchain
  consequence is inference from the FLAC format, not observed on a second ffmpeg
- **Where:** `…\crates\ferrosintesis-samples-bass\src\lib.rs:84` and `:104-107`;
  `…\tools\ferrosintesis-samples\prepare.py:4335-4341`;
  `…\tools\ferrosintesis-samples\gen_crate_lib.py:113`
- **Problem:** every committed FLAC carries a VORBIS_COMMENT block holding
  `Lavf62.12.101` twice — a vendor string and an `encoder=` tag. `_encode_flac` shells out
  to whatever `ffmpeg` is on `PATH` with no version pinned or recorded, and
  `EXPECTED_BYTES` is the exact sum of the resulting container bytes. A different ffmpeg
  writes a different-length vendor string, so a re-bake on another box shifts every file
  and fails an exact-equality assertion whose message names two integers and nothing else.
  `prepare.py:4442` guarantees the decoded **PCM** is bit-exact — a real guarantee, but a
  different guarantee.
- **Failure scenario:** an agent follows the crate README's regenerate command on a box
  with a different ffmpeg. The bake succeeds, the audio is identical, `cargo test -p
  ferrosintesis-samples-bass` fails on `EXPECTED_BYTES`. The obvious repair — re-pin the
  constant — silently replaces the published bank's bytes and moves the pin to that box's
  encoder.
- **Concrete fix:** encode with `-fflags +bitexact` (or strip VORBIS_COMMENT after encode)
  so no vendor string is embedded, and prove it by re-baking one bank on two ffmpeg
  versions and `cmp`-ing. Scope is all 24 crates — `publish_pending_banks` is the single
  publication path.
- **Effort:** Small

### 3. Medium — the crate's payload test can only agree with itself

- **Confidence:** High
- **Where:** `…\crates\ferrosintesis-samples-bass\src\lib.rs:113`, with `get` at `:68-73`
- **Problem:** the loop iterates `SAMPLES`, then asserts `get(name) == Some(bytes)` — where
  `get` finds `name` in `SAMPLES` and returns that entry's bytes. It compares the array to
  itself and can fail only on a duplicate name, which the sibling test already excludes.
  Combined with a permutation-invariant aggregate and the measured fact that all 13 files
  share one decoded length, **no test anywhere compares an embedded payload to the file it
  claims to embed.** Transposing two `include_bytes!` targets leaves every guard green —
  including the per-file FLAC MD5, which checks each file against its own header — while
  `sampler.rs:967` pairs a D2 recording with a 41.22 Hz root claim.
- **Concrete fix:** in `gen_crate_lib.py`, emit
  `assert_eq!(fs::read(samples_dir.join(name)).unwrap(), bytes, "{name}")`. One line;
  `samples_dir` is already in scope. Closes the cancel-out case too — today one file
  shrinking by N bytes while another grows by N is green, despite the test being named
  `..._with_the_expected_size`.
- **Effort:** Small

### 4. Low — `banks_parse` covers 34 of ~57 zone families

- **Confidence:** High
- **Where:** `…\crates\ferrosintesis\src\sampler.rs:7420-7478`; the omitted banks at
  `:963-975` and `:985-998`
- **Problem:** the sampler's basic sanity sweep (length, root range, peak normalisation) is
  a hand-written `.chain()` list. `sampler.rs` defines 107 zone builders and 38 public
  accessors; the sweep names 34, and neither bass bank is among them. Only 4 of the 13 bass
  zones are reached by any rendering test, and that one test explicitly does not score
  pitch. So a structurally valid but silent, clipped or mis-trimmed take ships green — the
  assertion that would catch it (`peak > 0.5`) is written 20 lines away and simply not
  applied to this family. This is CLAUDE.md's *hand-maintained lists* pattern, in a test.
- **Concrete fix:** route the assertions through `exercise_every_public_bank()`, which
  already enumerates every public accessor. The thresholds are not uniform (conditioned
  pianos need a band, the tuba drove the 25 Hz floor), so the derived form needs a small
  exception table that is itself proved exhaustive — otherwise the exception table becomes
  the next hand-maintained list.
- **Effort:** Small–Medium

## Not reported (refuted, with evidence)

Five candidates were investigated and killed. Recorded so a later pass does not re-open them.

- **"The WAV→FLAC migration dropped the bass bank out of the onset-continuity sweep."**
  Refuted. `…\tools\ferrosintesis-samples\test_prepare.py:1077` filters on
  `(".wav", prepare.PACKAGED_EXT)` and `prepare.py:1225` sets `PACKAGED_EXT = ".flac"`, with
  `read_wav` dispatching on `fLaC` magic (`prepare.py:1310-1315`). This *was* real when
  `MM-BUG-KILN-00240` was raised; it has since been fixed.
- **"`test_prepare.py` is not run by any gate."** Refuted — it is, at
  `…\.deltic-integrate.toml:59` and `:71`. `MM-BUG-KILN-00062`'s note to the contrary is
  stale.
- **"The bass crate has the sax packaging problem."** Refuted. The gated test is in the
  *parent* (`sampler.rs:7989`) reaching into a sibling directory; both bass tests read only
  `CARGO_MANIFEST_DIR/samples`, which `Cargo.toml:10` packages.
- **"A version pin is inconsistent."** Refuted. All 24 sample crates are `0.2.0` except
  `-b1-upright` at `0.1.1`, and each pin in `crates/ferrosintesis/Cargo.toml` matches.
- **"`#` in filenames is unsafe somewhere in the packaging path."** Refuted. `*.flac` is
  never ignored, `.gitattributes` has no pattern touching them, and `-sax` already ships 74
  `#`-bearing FLACs at the same version.

## Observations not worth a ticket

- **Three Open bugs no longer reproduce.** `MM-BUG-KILN-00241` (generator syntactically
  invalid) was repaired by `82ccd84a`; `MM-BUG-KILN-00239` (regenerate recipe writes WAV
  while lib.rs embeds FLAC) was fixed by `55298fb1` "Bake sample banks as FLAC end to end";
  `MM-BUG-KILN-00240`'s primary defect is fixed as above. All three are still Open, so the
  fix loop will spend cycles rediscovering that. **-00240 is only partly fixed** — its
  residual ask stands: `crates\ferrosintesis-samples-gong\PROVENANCE.md:128` still names
  `test_committed_gong_bank_starts_with_continuous_pcm`, which no longer exists, and there
  is still no per-format anti-vacuity floor (the sweep's guard is a single
  `assertGreater(checked, 1000)` across all banks, which 13 vanished files would not trip).
  Recommend a human or the fix loop re-verifies and closes -00239 and -00241.
- **`MM-REQ-KILN-00211`'s Notes are factually stale.** It describes "13 WAVs, 80,128 bytes
  each"; the bank has been FLAC since 2026.08.16 at 26–30 KB. Its core claim survives —
  equal decoded length still defeats an aggregate oracle. Worth flagging: FLAC STREAMINFO
  already carries a per-payload MD5 of the decoded PCM, and `ferrosintesis-flac` already
  verifies it on load, so a meaningful part of what that req asks for is now nearly free.
  Its `Flow: heavy` rating deserves a re-read at Gate 1 in that light.
- **The bass README's regenerate command omits ffmpeg.** `README.md:11-12` presents
  `prepare.py --only=fingerbass,pickbass` as self-contained, but `prepare.py:5671` now hard-
  requires ffmpeg. Same class as Open `MM-BUG-KILN-00292` (fret-noise); recorded in
  `MM-BUG-CRUCIBLE-00039`'s Notes rather than filed as another per-crate instance.
- **`PROVENANCE.md:24`'s "finger E1–D#2"** is the upstream SFZ key span (matching
  `prepare.py:215`), while the packaged bank stops at D2. Defensible as written since the
  sentence is about where roots were measured, but the pick half (E1–E2) coincides with its
  packaged top, so the two read as parallel claims when they are not.
- **`.gitignore:89`** (`!crates/ferrosintesis-samples-bass/samples/*.wav`) is dead — the
  bank is FLAC-only and `*.flac` was never ignored. It also sits outside the grouped block
  at `:61-83`, whose own comment says these lines cover a shrinking set.
- **No `.gitattributes` rule marks the sample banks binary.** Integrity rests on git's
  NUL-byte heuristic, which FLAC almost certainly trips; a `*.flac binary` line would close
  it for free. Low real-world exposure.
- **The two pinned archive SHA-256s in `PROVENANCE.md:20-21`** duplicate
  `prepare.py:223`/`:228` with nothing binding them. They match today (checked by hand).
  `provenance.rs` pins only committed source files, and these are fetched archives.
