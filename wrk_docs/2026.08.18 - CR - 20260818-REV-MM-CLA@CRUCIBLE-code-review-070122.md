## Verdict

The crate is small and in good shape: the generated `src/lib.rs` matches the current
`gen_crate_lib.py` output exactly, the embedded byte total pins true, and the licence
evidence chain (manifest hashes, per-sound IDs, authors, tallies) checks out end to end.
Two real defects found, both filed: a stale "embedded WAVs" claim in five packaged
NOTICEs (the crate ships FLAC), and a guard gap that leaves the packaged
`licence-evidence/` copies bound to no oracle.

## Findings

### 1. Five packaged NOTICEs still call the embedded FLAC banks WAVs — MM-BUG-CRUCIBLE-00042

Severity Low, priority Could, confidence: confirmed by direct file + git inspection.

`crates/ferrosintesis-samples-ccby/NOTICE:14` says "The embedded WAVs are attack
transients…", but all 20 payloads have been `.flac` since `9046cd14` (2026-08-16) and
were published that way in 0.2.0 (`417c0b22`). The pre-release sweep `904cbe94` fixed 25
stale container claims across rustdoc, READMEs and PROVENANCE files but touched no
NOTICE — the whole document class was missed (the repo's enumerate-all-of-L pattern).
Same defect in `honkytonk/NOTICE:4`, `vcsl-kawai/NOTICE:4`, `vcsl-steinway/NOTICE:4`,
`ydp-grand/NOTICE:7`; headroom's copy is already covered by open MM-BUG-KILN-00247.
Fix: correct the five sentences (container-neutral wording preferred); effort ~15 min.

### 2. Packaged licence-evidence copies are bound to no oracle — MM-BUG-CRUCIBLE-00043

Severity Low, priority Should, confidence: confirmed by reading every oracle that could
plausibly cover them.

The KILN-00193 fix (`a6abb0c`) copied the Freesound manifests into the packages
(`crates/ferrosintesis-samples-ccby/licence-evidence/…` ×2, orchestral2 ×1) so the cited
evidence travels with the crate. But `provenance.rs` hashes only the
`tools/ferrosintesis-samples/freesound-src/` originals, `inventory.rs` checks only link
existence + `include` coverage, and `licensing.rs` never opens these files. The copy each
PROVENANCE.md links beside its recorded SHA-256 is therefore an unguarded hand-maintained
duplicate: mutate one and the workspace stays green while the next publish ships evidence
that no longer matches the hash printed next to it. Today the copies are byte-identical
to the attested originals (verified via shared git blob IDs and recomputed SHA-256), so
this is a missing guard, not present drift. Fix: extend the provenance oracle to hash
`crates/ferrosintesis-samples-*/licence-evidence/*` against the same crate's packaged
PROVENANCE.md, filesystem-enumerated, with the adversarial self-test; effort ~1–2 h.

- The per-file container test accepts RIFF *or* FLAC, so a single-file WAV regression

  if ever run against a WAV-shipping crate — currently unreachable (the WAV crates use
  `regen_samples_table.py` or bespoke lib.rs), so an observation only.

  MM-BUG-CRUCIBLE-00040; EXPECTED_BYTES re-bake fragility as MM-BUG-CRUCIBLE-00039.
  Not re-filed.
