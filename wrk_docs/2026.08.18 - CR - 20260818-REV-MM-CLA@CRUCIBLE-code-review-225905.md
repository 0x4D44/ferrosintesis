## Findings

### CR-1 — Published README examples panic as written; WAV container claims survive the FLAC migration (Low severity, confirmed → bug MM-BUG-CRUCIBLE-00046)

`crates/ferrosintesis-samples-core/README.md:22-23` — the crates.io front-page example calls
`get("flute_A4.wav").unwrap()` and asserts `&wav[..4] == b"RIFF"`. Every embedded name now ends
`.flac`; the only `.wav` spellings `get()` accepts are the two piano compatibility aliases
(`src/lib.rs:284-288`), so the example returns `None`, panics, and the RIFF assert would fail on
FLAC bytes anyway. Supporting prose at README lines 4-5, 15 and 41 still says "WAV"
(`prepare.py:1225` now sets `PACKAGED_EXT = ".flac"`). The devil's-advocate sweep found the
identical defect in `crates/ferrosintesis-samples-orchestral/README.md:22-25`
(`get("trumpet_C3_f.wav")` — orchestral has zero `.wav` names at all) plus an independent
count drift at orchestral README:76 ("six `chanter_*`" vs 15 on disk and at line 13).

These are exactly the surfaces open bug MM-BUG-CRUCIBLE-00044 (stale `.wav` rustdoc across 12
crates) does NOT enumerate: its README/PROVENANCE prose list omits both crates, and these are
the only two sample-crate READMEs with runnable example blocks. No oracle or doctest covers
README examples (neither crate has `#![doc = include_str!(...)]`), which is why both broke
silently on migration day.

**Fix** (filed as MM-BUG-CRUCIBLE-00046, to fold into the 00044 sweep): rewrite both examples
against the real `.flac` API, make prose container-neutral, fix the chanter count, and wire the
READMEs in as doctests (or extend 00044's planned container-claim oracle to README code fences).
Effort ~30 min alongside 00044.

### CR-2 — Compatibility aliases are dead weight and their spelling is a footgun (note only, not filed)

`src/lib.rs:284-288` preserves exactly two legacy `.wav` lookups (`piano_C2_pp_rr2.wav`,
`piano_G2_pp_rr2.wav`) — but the same 0.2.0 release deliberately broke the other 67 `.wav`
names (CHANGELOG: "every name its `get()` accepts changed extension"), so the two aliases buy a
0.1.x caller nothing. Meanwhile the natural post-0.2.0 spelling `piano_C2_pp_rr2.flac` returns
`None`. No in-repo exposure: `sampler.rs:490-491` requests `piano_C2_pp.flac`/`piano_G2_pp.flac`
directly, and any future missing-name regression panics loudly at `embedded_wav`
(`sampler.rs:257`), so it cannot fail silently. Disposition: when 00044/00046 are fixed, either
delete the aliases or retarget them to the `.flac` spelling and update README:26-28, which
currently advertises them as the compat story. Not a defect today.
