### The strongest genuinely-live finding

`MM-BUG-CRUCIBLE-00039` (raised today, Should/Medium) — **the released sample banks are not
reproducible, and their own oracle enforces the irreproducibility.**

Every committed FLAC embeds a VORBIS_COMMENT block naming the exact encoder build. Measured
from the raw bytes of
`D:\worktrees\ferrosintesis\20260818-OPS-CLA@CRUCIBLE-daily-report-023722\crates\ferrosintesis-samples-bass\samples\fingerbass_E1.flac`:
a 13-byte vendor string `Lavf62.12.101` and a 21-byte `encoder=Lavf62.12.101` tag. Meanwhile
`tools/ferrosintesis-samples/gen_crate_lib.py:113` pins `EXPECTED_BYTES` as the aggregate
on-disk byte total, and each crate asserts it — `crates/ferrosintesis-samples-bass/src/lib.rs:84`
holds `365281`. Re-bake on a box with any other ffmpeg and the vendor string changes length,
every file's size changes, and the crate's own size oracle goes red with a message naming
neither ffmpeg nor a version.

What makes this worth Arthur's attention: `55298fb1` **identified this exact trap and avoided
it** for the fret-noise pin — its message says "Pinning the FLAC bytes would tie a
reproducibility oracle to one ffmpeg build" — and then left the same trap in the generated
per-crate size oracle. The right lesson was learned in one place and not propagated to the
other. This is the repo's own documented "hand-maintained lists drift" failure in a new dress.

**The trap worth recording.** `MM-BUG-KILN-00257` accuses a call to `packaged_in("bottle_C6.wav")`,
and at HEAD that line still reads `packaged_in("bottle_C6.wav")` — see

  published" and with "published, tag skipped".

Meanwhile **two artifacts committed today already treat publication as settled fact**: today's
bass-crate review says the miscount is "in a crate that shipped to crates.io two commits ago",
and `bugs/MM-BUG-CRUCIBLE-00038.md` says 0.21.58 was "published from this tree". Those are
downstream agent assertions with no first-hand evidence behind them in this repo.

I tried to settle it against the crates.io API; network access is unavailable to this
non-interactive session, so it stays **UNVERIFIED**. One `cargo search ferrosintesis` or a
browser hit on crates.io answers it in seconds, and it should be answered before any further
