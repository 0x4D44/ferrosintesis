## New defect

### MM-BUG-CRU-00047 — scoped regeneration falsely claims to be pure stdlib

- **Severity:** Low
- **Confidence:** High
- **Sites:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\PROVENANCE.md:72`,
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\README.md:26`,
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:4324`,
  and `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:5669`
- **Failure:** the packaged provenance calls `prepare.py --only=grand` a “pure stdlib”
  path, but `main()` calls `_require_ffmpeg()` before it processes the selector. A host
  satisfying the documented Python-only prerequisites fails immediately because FLAC
  publication requires `ffmpeg` on `PATH`.
- **Concrete fix:** document `ffmpeg` in both packaged documents, distinguish stdlib
  `.tar.bz2` extraction from FLAC packaging, and extend the fenced-recipe documentation
  oracle to require the prerequisite next to the command.
- **Effort:** Small

This does not duplicate `MM-BUG-CRUCIBLE-00039`, which covers ffmpeg-version-dependent
compressed byte totals, or `MM-BUG-KILN-00292`, which covers a separate fret-noise verifier.

## Confirmed findings already tracked

### MM-BUG-CRUCIBLE-00040 — payload identity assertion is self-referential

- **Severity:** Medium
- **Confidence:** High
- **Site:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\src\lib.rs:257`
- **Failure:** `inventory_matches_packaged_samples` compares names, while the second test
  takes `(name, bytes)` from `SAMPLES` and asks `get(name)` to return the same tuple's
  bytes. Swapping two `include_bytes!` targets preserves names, aggregate size, FLAC magic,
  and the self-lookup assertion, but the consumer then associates each recording with the

  two include targets and observing the new assertion fail before restoring them.
- **Effort:** Small

### MM-BUG-KILN-00243 — public API and package prose promise retired WAV keys

- **Severity:** Low
- **Confidence:** High
- **Sites:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\src\lib.rs:235`,
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\README.md:3`,
  and `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\PROVENANCE.md:9`
- **Failure:** the exact-name API says callers should use `.wav` and receive WAV bytes,

  receives `None`. Provenance also reports the retired 7,184,592-byte total instead of

  then update rustdoc, README, provenance, aggregate, and test comments together. Add a
  source-derived guard binding at least one documented key and the documented container to
  the inventory.
- **Effort:** Small

### MM-BUG-KILN-00245 — late failure can publish a mixed grand bank

- **Severity:** Low
- **Confidence:** High
- **Sites:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:4372`,
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:4412`,
  and `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:5898`
- **Failure:** generation writes each logical WAV directly into the final package
  directory, and FLAC publication replaces files one at a time. A late transform or encode
  failure leaves a new prefix beside an old suffix, with no bank-level rollback.
- **Concrete fix:** build all 54 final FLACs in empty staging, validate exact inventory and
  decoded PCM there, then publish the whole bank with rollback. Add late-transform and
  late-replacement failure injections that preserve the old bank byte-for-byte.
- **Effort:** Medium

### MM-BUG-CRUCIBLE-00045 — the FLAC-only bank still accepts RIFF as green

- **Severity:** Low
- **Confidence:** High
- **Site:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\src\lib.rs:295`
- **Failure:** the test accepts either RIFF or FLAC magic although this package is
  deliberately FLAC-only. Reintroducing a WAV remains green once the mechanically updated
  aggregate pin is accepted, hiding a binary-size regression. The existing bug owns the

- **Concrete fix:** derive the expected container from the package inventory and assert
  extension/magic agreement. Keep one explicit allowlist entry for the intentional B1
  upright RIFF exception.
- **Effort:** Small

### MM-BUG-CRUCIBLE-00039 — compressed-size pin depends on the host ffmpeg build

- **Severity:** Medium
- **Confidence:** High
- **Sites:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\crates\ferrosintesis-samples-grand\src\lib.rs:254`
  and `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-113117\tools\ferrosintesis-samples\prepare.py:4335`
- **Failure:** the crate pins compressed FLAC byte count, but the documented bake uses
  whichever `ffmpeg` is on `PATH`. A bit-identical PCM rebuild can produce different
  container bytes and fail the size oracle.
- **Concrete fix:** pin decoded PCM identity and structural FLAC properties rather than
  encoder-specific aggregate bytes, or pin the encoder when container identity is truly
  required.
- **Effort:** Small–Medium
