## Newly filed bugs

### CR-1 — the regeneration instructions promise no ffmpeg, but the command requires it

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\crates\ferrosintesis-samples-ydp-grand\PROVENANCE.md:52`;
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\crates\ferrosintesis-samples-ydp-grand\PROVENANCE.md:58`;
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\tools\ferrosintesis-samples\prepare.py:5669`;
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\tools\ferrosintesis-samples\prepare.py:4412`
- **Tracked as:** Open `MM-BUG-CRU-00053`
- **Effort:** Small

`PROVENANCE.md` gives this command and immediately describes it as “Pure stdlib
(raw-PCM SF2 — no ffmpeg)”:

```text
python3 tools/ferrosintesis-samples/prepare.py --only=ydpgrand
```

That narrower statement used to describe the raw-PCM SF2 extraction correctly. It no
longer describes the complete command. `main()` now calls `_require_ffmpeg()` before it
selects the requested family because every completed bank must be FLAC. The final
`publish_pending_banks()` step also invokes ffmpeg to encode and decode-check each file.
A maintainer with Python but no ffmpeg therefore gets an immediate failure instead of the
documented rebuild.

**Concrete fix:** require ffmpeg on `PATH` in both packaged regeneration documents,
describe FLAC as the published container, and retain only the narrower claim that SF2
parsing/extraction itself uses stdlib. Add a source/documentation guard that rejects a
“no ffmpeg” claim for a recipe that reaches `_require_ffmpeg()`.

The devil's advocate rejected deduplication against `MM-BUG-CRU-00047`: that record names
the separate `ferrosintesis-samples-grand` package, and no existing record covers the YDP
instruction.

### CR-2 — concurrent cold regenerations race the shared manifest `.part`

- **Severity:** Low
- **Confidence:** High
- **Where:**
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\tools\ferrosintesis-samples\prepare.py:1601`;
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\tools\ferrosintesis-samples\prepare.py:1614`;
  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\tools\ferrosintesis-samples\prepare.py:5872`
- **Tracked as:** Open `MM-BUG-CRU-00054`
- **Effort:** Small–Medium

Every YDP run uses the process-shared OS-temp directory `<temp>/ydp_grand`. A cold or
invalid cache makes each process rebuild independently and then call
`write_member_manifest()`. That helper always writes the same `<manifest>.part` path.

Two overlapping writers can both open that path. One can rename or truncate it while the
peer still expects it. On Unix, the later `os.replace(tmp, path)` can find that the first
writer already renamed the source. On Windows, the rename can fail while the peer holds
the staging file open. The observed consequence established by source is a failed or
needlessly rebuilt regeneration. Identical current pins mean this pass did **not** claim a
silent wrong-bank result.

**Concrete fix:** use a unique same-directory temporary file for every manifest writer,
then atomically replace and revalidate the winning cache state; alternatively lock the
cache rebuild-plus-manifest transaction. Add an orchestrated two-writer regression that
forces overlap and requires both callers to succeed, a valid final manifest, and no
staging leftovers.

`MM-BUG-KILN-00205` owns failure-atomic publication of the tracked YDP bank, not this
shared-cache race. `MM-BUG-CRU-00049` is the equivalent Mandolin-specific race.

  `D:\worktrees\ferrosintesis\20260820-REV-MM-CDX@CRUCIBLE-code-review-163355\crates\ferrosintesis\CHANGELOG.md:35`
  explicitly declares `.wav` to `.flac` lookup names as the deliberate pre-1.0 breaking
  change. Stale documentation is a defect; the missing aliases are not.
- **Linear `get()` lookup is a scale problem — refuted.** It scans nine immutable names
  during one `OnceLock` bank initialization, not in the audio sample loop.
- **Current asset corruption, duplication, or routing drift — refuted.** The nine disk,
  embedded-table, and consumer names match exactly. Every committed file is distinct and
  has FLAC STREAMINFO reporting mono, 44,100 Hz, 16-bit, 66,502 frames (about 1.51 s).
- **Path traversal or caller-controlled filesystem access — refuted.** `get()` exact-matches
  static names; the YDP archive extractor writes one selected regular SF2 member to a fixed
  staging filename.

  `publish_pending_banks()` already requires decoding the staged FLAC and comparing its PCM
  with the source at `prepare.py:4442`; `test_prepare.py:3831-3845` independently checks the
  encoder/read path. An existence assertion is not the only oracle on that path.
- **Create a new YDP verification requirement — deduped.**
  `MM-BUG-KILN-00201` explicitly scopes the YDP root table,
  `MM-BUG-CRUCIBLE-00040` owns name-to-payload identity, and
