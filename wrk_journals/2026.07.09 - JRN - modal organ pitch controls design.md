# 2026.07.09 - JRN - modal organ pitch controls design

## Context

Arthur asked to tackle one or more heavy requirements. I selected
`MM-REQ-KILN-00008` because it is the highest-leverage heavy req: one pitch-control
fix applies to Modal and Organ voices across many GM programs.

## Work

- Read `reqs/README.md`, `CLAUDE.md`, and `reqs/MM-REQ-KILN-00008.md`.
- Confirmed the heavy flow requires design/sign-off before shipped synth code.
- Inspected `fable5/hollowsynth/src/voices.rs`, `engine.rs`, `testutil.rs`, and
  existing HLD style.
- Used two read-only sidecar reviews:
  - one for the Modal/Organ state that must retune while notes ring;
  - one for the rendered-audio oracle and old-album byte-identity proof.
- Ran a direct MIDI scan over `render_opus.py::ALBUMS`.

## Findings

- The engine already calls `set_pitch` for note-on bend, RPN recomposition,
  pitch-bend events, aftertouch vibrato, and portamento glide.
- `Modal` and `Organ` do not override `set_pitch`, so the trait no-op swallows
  those controls.
- `aftertouch_family` currently excludes Modal programs, so voice-side work alone
  would still leave Modal aftertouch vibrato inert.
- Full old-album byte identity is not possible under the direct fix: 13 committed
  MIDI files already author relevant controls on Modal/Organ channels.

## Output

Drafted `wrk_docs/2026.07.09 - HLD - hollowsynth modal organ pitch controls.md`.
The HLD recommends honouring existing authored controls and explicitly waiving
byte identity only for the affected tracks, but it stops before code because
Arthur needs to choose the compatibility fork.
