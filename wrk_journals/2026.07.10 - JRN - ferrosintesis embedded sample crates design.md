# Journal: ferrosintesis embedded sample crates design

## 2026-07-10

- Goal: design a crates.io-native split that keeps the current compile-time
  `include_bytes!` model and self-contained binary while putting every package
  below crates.io's 10 MB limit.
- Started from `origin/main` `d5b52a5`; current synth version is `0.12.0` and the
  latest recorded gate is 255/255 workspace tests green with four ignored
  calibration tests.
- Measured the natural bank partition: core piano/violin/flute is 71 WAVs,
  9,555,776 bytes raw and about 6.99 MiB under an in-memory gzip proxy;
  orchestral brass/reeds/nylon/drums is 107 WAVs, 6,601,544 bytes raw and about
  5.64 MiB compressed by the same proxy.
- Checked the official crates.io API: `ferrosintesis-samples-core` and
  `ferrosintesis-samples-orchestral` both returned 404 today. Availability is
  not reserved until an authorised publication.
- Chose two ordinary optional Cargo dependencies over a GitHub-fetching
  `build.rs`: Cargo supplies the global cache, offline/vendor behaviour,
  checksums, registry immutability, and docs.rs compatibility without adding a
  downloader or changing the runtime sample model.
- Identified the staged-release constraint: a verifying package/dry-run of the
  main crate cannot resolve the new exact-version dependencies until the sample
  crates have been published. The HLD separates implementation evidence from
  the final release dry-run rather than pretending `--no-verify` is sufficient.
- Draft HLD:
  `wrk_docs/2026.07.10 - HLD - ferrosintesis embedded sample crates.md`.
- Arthur approved the HLD on 2026-07-10. Marked it `SIGNED-OFF`; implementation
  may start in a dedicated DEV worktree based on this commit.

## Implementation

- Split the bank into two ordinary Rust packages: 71 piano/violin/flute WAVs in
  `ferrosintesis-samples-core` and 131 string/brass/reed/guitar/drum WAVs in
  `ferrosintesis-samples-orchestral`. Each package exposes an exact-name lookup
  over its compile-time `include_bytes!` inventory and carries the CC0 legal text.
- Added the default `embedded-samples` feature to `ferrosintesis 0.13.2`. It enables
  exact-pinned optional dependencies on both `0.1.0` asset packages. A
  `--no-default-features` build resolves neither dependency and clamps the existing
  runtime sample option off, leaving the fully modeled synth.
- Moved the provenance and preparation tooling to `tools/ferrosintesis-samples/`.
  Its four offline unit tests pass, including the 71/131 output-routing partition.
- Proved that the move did not alter any asset: 178 unique filenames total
  16,157,320 bytes before and after, with aggregate manifest SHA-256
  `81FA36FC86615A9B3EE061569DFC75969F39C839AB3965035F6D29B83562004B`.
- `cargo package` builds and verifies both asset archives. After the ensemble-string
  rebase, core is about 6.8 MiB with 71 WAVs and orchestral is about 6.7 MiB with
  131 WAVs. Each archive includes
  its declared licence file and remains below the 10 MB crates.io limit.
- The main package has an explicit source/README/licence allowlist: 17 input files,
  890,912 raw bytes, and no WAVs. As expected, Cargo cannot produce its final archive
  before the exact asset versions exist in the registry; even `--no-verify` resolves
  registry dependencies. The publication run must therefore publish both asset
  packages first, then run the main crate's verifying dry run and publish it.
- Built the default release CLI and rendered every one of the 87 MIDI files returned
  by `render_opus.py::all_midis()` against both the `0.12.0` baseline and `0.12.1`.
  All 87 WAVs were byte-identical by SHA-256.
- Final local gates: `cargo fmt --all --check`; workspace clippy with warnings denied;
  modeled-only clippy with warnings denied; workspace tests (255 synth tests passed,
  four ignored, plus two tests per asset crate); modeled-only tests (242 passed, four
  ignored); both package verifications; preparation-tool tests; and the locked release
  build all pass.
- An independent final diff review found no required changes, suggestions, or open
  questions. No crate publication, tag, release, push, or other external mutation
  occurred during implementation.
- Before integration, `origin/main` advanced by ten commits and bumped the synth from
  `0.12.0` to `0.13.0` for the cathedral-organ work. Rebased the three task commits,
  preserved the new organ/reverb behavior, and moved this task's single shipped-code
  bump to `0.13.1`. The pre-rebase 87/87 comparison remains evidence for the original
  base. A fresh comparison against that `origin/main` revision covered all 88 current
  MIDIs and was byte-identical.
- Before handoff, main advanced again with 24 cello/violin ensemble attacks for GM
  48–49. Moved those new blobs into the orchestral package, raising the complete bank
  to 202 unique WAVs and 17,487,688 bytes; updated the inventory, routing tests, and
  documentation. Both revised asset packages still verify below 10 MB. The final
  202-sample branch rendered all 88 current MIDIs byte-identically against that newer
  `origin/main`.
- Main then advanced with an unrelated cymbal-swell fix and its own `0.13.1` bump.
  Rebased once more, preserved that fix, and moved this task's single bump to `0.13.2`.
