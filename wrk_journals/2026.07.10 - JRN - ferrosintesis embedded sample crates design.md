# Journal: ferrosintesis embedded sample crates design

## 2026-07-10

- Goal: design a crates.io-native split that keeps the current compile-time
  `include_bytes!` model and self-contained binary while putting every package
  below crates.io's 10 MB limit.
- Started from `origin/main` `d5b52a5`; current synth version is `0.12.0` and the
  latest recorded gate is 255/255 workspace tests green with four ignored
  calibration tests.
- Measured the natural bank partition: core piano/violin/flute is 71 WAVs,
  9,555,776 bytes raw and about 6.99 MiB under an in-memory gzip proxy;
  orchestral brass/reeds/nylon/drums is 107 WAVs, 6,601,544 bytes raw and about
  5.64 MiB compressed by the same proxy.
- Checked the official crates.io API: `ferrosintesis-samples-core` and
  `ferrosintesis-samples-orchestral` both returned 404 today. Availability is
  not reserved until an authorised publication.
- Chose two ordinary optional Cargo dependencies over a GitHub-fetching
  `build.rs`: Cargo supplies the global cache, offline/vendor behaviour,
  checksums, registry immutability, and docs.rs compatibility without adding a
  downloader or changing the runtime sample model.
- Identified the staged-release constraint: a verifying package/dry-run of the
  main crate cannot resolve the new exact-version dependencies until the sample
  crates have been published. The HLD separates implementation evidence from
  the final release dry-run rather than pretending `--no-verify` is sufficient.

  `wrk_docs/2026.07.10 - HLD - ferrosintesis embedded sample crates.md`.
