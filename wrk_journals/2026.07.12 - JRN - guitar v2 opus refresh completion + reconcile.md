## KEY FINDING — cross-environment encoder nondeterminism (lessons-worthy)

Rendering a pure-brass, non-guitar track (Through Lines 07 German Bight) that the
brass agent had refreshed, with **my** binary at the **same** v0.15.1 code and the
same MIDI, produced a **different opus** than trunk's committed copy. Same code +
same input + different bytes ⇒ the difference is environmental (almost certainly a
different `ropusenc`/libopus build on the other agent's machine). Implication: the
repo's "deterministic render ⇒ git sees only changed tracks" invariant holds
**within one environment only**. Cross-agent byte-diffs **over-report** staleness,
and two agents refreshing the same track will ping-pong its bytes forever. Rule
for future opus refreshes: decide staleness by **synth version / render history**,
not by byte-comparing against another machine's render; leave a track alone if
trunk already has a render at the current synth version. This belongs in
lessons_learnt once that file is pruned back under its cap.
