## Key correctness catch (mine, before implementing)

**`LaVoice::kind()` is transparent** (delegates to the inner model → "wind"), so Fable's
WD-O10 sample-policy oracle as specified (kind()-based) COULD NOT WORK. Replaced with a
differential: for 74-79, samples=true and samples=false must render BIT-IDENTICAL; for
72/73 they must differ. Still fail-first (today all 8 are wrapped).

## Implementation

- One voice + a const `WindPreset` table + `wind(program)` lookup, mirroring `ReedPreset`.
  **Bore class lives in the data**: stopped pipe (pan flute) = even harmonic slots 0.0;
  Helmholtz vessel (bottle/whistle/ocarina) = one weak ladder entry. No per-instrument
  branch in `render`.
- Render path: `osc: [Sine; 7]` + `amps: [f32; 7]` (zero slots never ticked); a single
  `bright` tilt scalar (register + velocity), normalised to 1.0 at vel100/mid-register so
  the table reads off the render; a per-bore tracked breath bed (bandpass at breath_f·f0)
  with velocity² coupling; optional >8 kHz muraiki highpass (shakuhachi only, Option-gated
  so the RNG stream stays aligned for the WD-O5 seam); chiff OUTSIDE the envelope (Reed
  convention); vibrato built at `sr/CTRL` (the bug fix); an alias gate at 0.44·sr also
  re-applied on upward slurs.
- Sample policy: only 72/73 keep the flute LA bank; 74-79 model-only (removing the wrong
  transverse-flute attack smeared across a stopped pipe / vessel / bamboo / whistle).

## Oracle measurement bugs I hit and fixed (model was right each time)

1. **Absolute breath bands off by 1/0.61** — `Rng::white()` is uniform [-1,1) so its RMS is
   1/√3 = 0.577, not 1 (Fable assumed unit white). Re-pinned the bands to the true physics;
   ordering/differential clauses were always robust. **Durable repo lesson.**
2. **Harmonic ratios read inside the vibrato window under-read upper partials** (harmonic n
   carries n× the modulation index → energy spreads into FM sidebands a fixed Goertzel bin
   misses; pan-flute h3 read 0.14 not 0.39). Moved every harmonic read to a strictly
   PRE-VIBRATO window [0.10,0.17]. This was Fable's own tripwire F8.
3. **WD-O7 carrier mislocation**: under deep vibrato (shakuhachi β≈0.69) the first sideband
   rivals the carrier, so `peak_locate` locked onto the sideband and inverted the ratio
   (2.78 vs 0.74). Fixed by using the known centre pitch key_freq(key) — the carrier of an
   FM tone sits there exactly. Now 0.737 (predicted 0.74).
4. **WD-O4 hp_rms leaked the flute's own h4/h5** through a Q-0.7 skirt → switched to an exact
   DFT band (8-16 kHz); ratio 4.4× → 17×.
5. **WD-O10 release window** too short — Adsr release is exponential (~0.91 s to the 1e-4
   floor), not 0.5 s.

## Review — one R1 characterization finding to ESCALATE (correcting my own record)

Independent review: correctness fully clean (no off-by-one, alias gate correct & monotonic,
vibrato fix matches Reed byte-for-byte, RNG seam aligned, chiff convention correct,
harm:[6] right-sized, oracles honestly fail-first). But it caught that **I understated the
flute change**, and it is right:

- The OLD flute was spectrally FLAT — constant a2=0.32/a3=0.12, no velocity or register
  dependence at all. The NEW FLUTE preset carries `vel_bright=0.9` + `reg_dark=0.55` — the
  **strongest tilt in the whole family** — plus velocity-scaled breath and a reworked chiff.
- It reproduces today's accepted sound EXACTLY at the reference point (key 72, vel 100 → the
  WD-O9 canary passes), but every flute note OFF that point now renders with brightness tilt
  that did not exist before. That is the largest audible change in the rework, on the one
  voice R1 exists to protect.
- Not a code defect — it is deliberate (Fable's design, WD-O6 requires the tilt), tested, and
  policy-compliant (default-on timbre improvement + the re-render is done). But "flute moves
  as little as possible" was wrong; the flagship got the family's most aggressive tilt. This
  is Arthur's ratification call: ship the realistic tilt, or dial the flute's tilt toward the
  recorder's gentle 0.15/0.35 for a more R1-faithful "modest refinement" (a 2-number change +
  re-render). SURFACED to Arthur, not silently resolved.
- **RATIFIED (Arthur, 2026-07-12): ship the current flute** — the realistic
  velocity/register tilt stands (`vel_bright=0.9`, `reg_dark=0.55`). Rationale: a real flute
  *does* brighten when blown harder and in the low register, so the old flat spectrum was the
  less faithful rendering; this is precisely the "timbre improvements are default-on, albums
  are not frozen in older, worse renderings" policy, and the 32-opus refresh already carries
  it. No code change. R1 is therefore *consciously accepted* as "same instrument, more alive",
  not silently breached — and WD-O9 remains the canary bounding it at the reference point.
