Task: replace the Python render orchestrator (`render_opus.py`) with a Rust app so
generating the `.opus` listening copies needs no Python. Worktree:
`D:/worktrees/midi-music/20260713-DEV-HUM-rust-render-opus` (branch

## UNDERSTAND (done)

`render_opus.py` is a pure **orchestrator**, ~280 lines, stdlib-only:
- Holds the `ALBUMS` table (dir key → title/artist/genre) — repo-specific catalog data.
- Discovers `albums/**/midi/*.mid` (+ two `demos/` dirs), errors on unclaimed MIDIs.
- Derives title + track number from the filename (`03 - Foo.mid`).
- Computes tags: R128_TRACK/ALBUM_GAIN (Q7.8 from TARGET_LUFS), ENCODER_SETTINGS,
  ALBUMARTIST/COMPOSER/TRACKTOTAL, optional multiline LYRICS from a `lyrics/<stem>.txt`
  sidecar (validated: UTF-8, non-blank, no NUL; orphan sidecars rejected).
- For each MIDI: temp WAV via `ferrosintesis <mid> -o wav -q --tp-ceiling -4.5`, then
  `ropusenc --bitrate 96000 --music --vbr --comp 10 <tags> -o out.opus wav`.
- ThreadPool over tracks (`--jobs`, default 6); `--album <title>`, `--only-list <file>`.

Confirmed facts:
- `ferrosintesis::offline` public API (`load/render/normalize_loudness/normalize_to_i16/
  write_wav`) — the port can render in-process (same workspace).
- `ropusenc` CLI has every flag render_opus uses. `ropus-tools-core` is a library but
  pulls a large 3rd-party tree (symphonia/rubato/ogg/rodio/crossterm) — NOT worth linking
  into this zero-dep repo just to avoid one subprocess. Decision: keep `ropusenc` on PATH.
- `.gitignore` already drops `*.wav`/`*.opus` (except the sample banks). New crate under
  `crates/` is naturally covered.
- Many `.md` reference the scripts, but nearly all are journals/HLDs (historical,
  append-only — leave untouched). Current-guidance docs to update: root `CLAUDE.md`,
  root `README.md`, `listening/README.md`. Album-level `build.py` is the *composition*
  engine (separate Python, stays) — do NOT touch those references.

## IMPLEMENT + VALIDATE (done)

Order mattered: **captured the goldens from the real `render_opus.py` BEFORE deleting
it.** Built two throwaway stub binaries (a fake synth + a fake `ropusenc` that records
its argv length-prefixed) and ran the real Python against them, for the demo album
(`--album`) and for a single-track `--only-list`. Both goldens are committed under
`crates/render-catalog/tests/golden/`.

Surprises / gotchas worth keeping:
- **`TRACKTOTAL` is computed over the *selected* tracks, not the album's true size.**
  Confirmed empirically: the full-album run tagged `TRACKTOTAL=6`, the `--only-list`
  single-track run tagged `TRACKTOTAL=1`. Codex flagged it; the capture proved it. The
  port reproduces the quirk faithfully.
- **`core.autocrlf=true` would corrupt the length-prefixed goldens** (CRLF translation
  desyncs every length prefix from its payload). Fixed with
  `tests/golden/.gitattributes` → `*.argv -text`; verified the staged blob is
  byte-identical to the working file.
- **`listening/` holds a *tracked* `README.md`** — only the `.opus` are ignored. An
  `rm -rf listening` to clear stub output deleted it; restored with `git restore`.
- Codex's one High finding ("compute the echo delay in f64") was **rejected**: the CLI
  itself computes it in f32 (`ferrosintesis-cli/src/main.rs:115`), so f64 would *break*
  parity. Verified in source before rejecting.

Code review (built-in `/code-review`, high) found one real bug, now fixed + regression
tested: **lyrics were read inside the worker**, so an invalid sidecar became a per-track
`[FAIL]` after minutes of synthesis while every other track still rendered — whereas
render_opus.py resolved lyrics up front and rendered *nothing*. `main()` now resolves the
whole selection's lyrics before the render loop. Also replaced an
`#[allow(clippy::too_many_arguments)]` suppression with a `Tags` struct, and simplified
an obfuscated golden parser.

**Validation (all observed, not asserted):**
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings` — clean.
- `cargo test --workspace` — 376 ferrosintesis + 16 render-catalog pass, 0 fail.
- **AC3 byte-parity: the 6 demo-album `.opus` files rendered by `render-catalog` are
  byte-identical to those rendered by the old Python pipeline** — checked before *and*
  after the code-review changes. This empirically retires risk R2: the feared
  cross-binary LTO float divergence did **not** materialize (in-process render == the
  `ferrosintesis` CLI binary's render, bit for bit), and `ropusenc` is deterministic
  (fixed Ogg serial `0xC0DEC0DE`), so the whole chain reproduces exactly.
- AC2 exit codes verified live: `--help`→0, unknown album→1, unmatched `--only-list`→1,
  `--jobs 0`/`--jobs abc`/unknown flag/missing value→2.
- `--album "ferrosintesis Reference Audition"` renders just that album (Arthur's ask).
