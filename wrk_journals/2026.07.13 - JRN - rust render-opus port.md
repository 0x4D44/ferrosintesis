## UNDERSTAND (done)

`render_opus.py` is a pure **orchestrator**, ~280 lines, stdlib-only:
- Holds the `ALBUMS` table (dir key → title/artist/genre) — repo-specific catalog data.
- Discovers `albums/**/midi/*.mid` (+ two `demos/` dirs), errors on unclaimed MIDIs.
- Derives title + track number from the filename (`03 - Foo.mid`).
- Computes tags: R128_TRACK/ALBUM_GAIN (Q7.8 from TARGET_LUFS), ENCODER_SETTINGS,
  ALBUMARTIST/COMPOSER/TRACKTOTAL, optional multiline LYRICS from a `lyrics/<stem>.txt`
  sidecar (validated: UTF-8, non-blank, no NUL; orphan sidecars rejected).
- For each MIDI: temp WAV via `ferrosintesis <mid> -o wav -q --tp-ceiling -4.5`, then
  `ropusenc --bitrate 96000 --music --vbr --comp 10 <tags> -o out.opus wav`.
- ThreadPool over tracks (`--jobs`, default 6); `--album <title>`, `--only-list <file>`.

Confirmed facts:
- `ferrosintesis::offline` public API (`load/render/normalize_loudness/normalize_to_i16/
  write_wav`) — the port can render in-process (same workspace).
- `ropusenc` CLI has every flag render_opus uses. `ropus-tools-core` is a library but
  pulls a large 3rd-party tree (symphonia/rubato/ogg/rodio/crossterm) — NOT worth linking
  into this zero-dep repo just to avoid one subprocess. Decision: keep `ropusenc` on PATH.
- `.gitignore` already drops `*.wav`/`*.opus` (except the sample banks). New crate under
  `crates/` is naturally covered.
- Many `.md` reference the scripts, but nearly all are journals/HLDs (historical,
  append-only — leave untouched). Current-guidance docs to update: root `CLAUDE.md`,
  root `README.md`, `listening/README.md`. Album-level `build.py` is the *composition*
  engine (separate Python, stays) — do NOT touch those references.
