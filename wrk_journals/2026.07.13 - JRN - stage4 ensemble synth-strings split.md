# 2026.07.13 — JRN — Stage 4 (ensemble 48-51): the synth-strings string-machine split

Part of the stages-2-5 collapse sweep (HLD `2026.07.12 - HLD - stages 2-5 pad FX
ensemble and minor collapses.md`). Stage 4 = the smallest, zero-album-blast stage,
run first to establish the pattern and validate the bit-identity discipline.

## What Stage 4 fixes

GM 48/50/51 rendered byte-identically (one `SawStack`); 49 was that sound with a
slow attack. So the ensemble family was 2 sounds wearing 4 hats. GM 50 "Synth
Strings 1" being a byte-identical clone of the *acoustic* GM 48 is precisely the bug.

Fix: 50/51 become a **divide-down string machine** (Solina idiom) — no players, so
no independent per-player drift/vibrato; the ensemble width comes from one shared
BBD chorus LFO. 51 is the lush/dark variant of 50. 48/49 (the acoustic section,
99 albums between them) are **frozen**.

## The approach — safest possible freeze

I did NOT build the `EnsembleSpec` table the design sketched. A preset table that
"reproduces today's literals" is a reconstruction that can drift. Instead:

- `strings()` is left **byte-for-byte untouched** (it already handles 48/49). A
  function you don't edit can't regress.
- 50/51 route to a new `synth_strings()`; the `make` dispatch arm `50 | 51` is the
  only change there (they were already model-only, "HLD option A", so no sample
  wiring changed).

The one shared-code change is a `chorus: Option<(f32,f32,f32)>` field on `SawStack`
+ a `with_chorus` builder + a `+ cmod` term in `control_tick`. Bit-identity for
every existing SawStack caller is preserved **by construction**: `chorus == None`
→ `cmod == 0.0` → `(1.0 + vib + drift + 0.0)`, and `x + 0.0 == x` in IEEE-754 for
finite x. Not luck — the unit guards prove it (below).

Trap avoided: the chorus LFO coefficient is built at `sr` and advanced by
`CTRL as f32` per control tick (the existing sweep-LFO pattern), NOT the
MM-BUG-KILN-00003 mistake of building an `sr/CTRL` LFO and ticking it per sample.

## The allowlist / `Why::Legit` decision

Deleted the three Stage-4 entries: `(48,50)`, `(48,51)`, and `(50,51)`. The last
was `Why::Legit` ("GM defines these near-identical; forcing a difference is worse
music") — a caution the original matrix author AND the ensemble design agent both
independently preferred. I overrode it: a faithful string-machine voicing (lush-slow
51 vs tighter 50) is not a *forced* difference, it is the *correct* GM reading (50/51
are distinct patches on real hardware). Measured, they land 0.5029 apart — genuinely
distinct, not a shade. So the Legit exemption became stale and was removed.

Consequence: `Why` is now a single-variant enum (`Collapse(u8)` only). That made the
`if let Why::Collapse(..)` in `allowlisted_collapses_are_really_clones` irrefutable
(clippy `-D warnings` caught it) → changed to a plain destructuring `let`. Parked in
scratchpad: collapse `Why` to a bare stage id if it stays single-variant through the
later stages.

Guards green: `every_gm_family_is_free_of_unexpected_clones`,
`allowlisted_collapses_are_really_clones`, `sawstack_family_signatures_are_stable`

New oracles (voices::tests):
- **EN-O1** `synth_strings_50_51_are_model_only` — samples on/off render
  bit-identically (tier D; guards a future dispatch sneaking an LA layer on).
- **EN-O2** `synth_strings_2_is_the_darker_variant` — 51 passes less HF energy than
  50 (`hp_rms(2800)/rms`). *First cut used a magnitude `centroid` and failed: the
  acoustic 48 read a LOWER centroid than the brighter-cutoff machine 50, because 48's
  vibrato+drift smear each partial across bins so `mag_at` under-reads the upper
  harmonics — the Stage-1 WD-O read issue. Narrowed to a modulation-free 51-vs-50
  band-energy comparison, which is the actual design claim.*
- **EN-O3** `synth_strings_ensemble_motion_is_correlated` — the machine's envelope
  autocorrelates more strongly in the chorus band than the acoustic section's
  aperiodic per-player wander (the correlated-vs-independent identity, temporal).
