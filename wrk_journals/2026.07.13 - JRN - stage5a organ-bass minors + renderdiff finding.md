# 2026.07.13 — JRN — Stage 5a (organ 16/17, slap 36/37) + a render-diff methodology finding

Part of the stages-2-5 collapse sweep. Stage 5a = the two zero-album-blast *collapse*
fixes among the minors, each clearing an anti-clone allowlist entry.

## Scope decision

The design's "Stage 5" grouped organ 16/17, slap 36/37, AND the lead 86/87 interval
features. I split the leads out: 86/87 are a **feature add** (note structure — a
parallel fifth / sub-octave), not a preset split, and 87 is used in Heliopause (2
albums, so it carries opus blast). Those become **Stage 5b**. Stage 5a is only the two
zero-blast collapse fixes that delete allowlist entries: `(16,17)` and `(36,37)`.

## What changed

**Organ 17 (percussive).** GM 16/17 shared one `Organ::new` config. Split the arm:
16 keeps its exact args (bit-identical, 12 albums), 17 gets the Percussion tab —
a thinned drawbar registration (dropped the 4', halved the 3rd) + a decaying
3rd-harmonic tap (`Organ::with_percussion`) that pings at key-on over the sustained
tone, plus a louder key click. The tap is a new `perc_osc`/`perc_amp`/`perc_decay`
trio on `Organ`, inert (`perc_amp == 0.0`) for every other program → 16/18-23 render
bit-identically (the render block is skipped, `perc_osc` never ticks, and its
construction draws no RNG).

**Slap 37 (bridge pop).** GM 36/37 shared `SLAP`. 36 keeps `SLAP` (thumb slap; the
existing `slap_transient_and_pitch` oracle stays valid); 37 gets `SLAP_POP` — a
bridge-ward pluck position, far brighter (5200 vs 3500), thinner (sub 0.08 vs 0.15),
short ring (t60 1.8 vs 2.8). Both 36/37 are used in no album.

Both 16/17 and 36/37 are 0-album on the moving member, so **zero album blast**.

## Verification

Matrix after the splits: 16 vs 17 = 0.1612 (was 0.0000), 36 vs 37 = 0.4097 (was
0.0000). Both clear EPS=0.03. Deleted `(16,17)` and `(36,37)` from the allowlist.

Two change-detector pins tripped on the *intended* change and were updated (not
weakened): `gm_routing_pins_voice_kinds` program 37 kind SLAP → SLAP_POP; the
legacy-organ render signature for GM17 (centroid 358.6 → 330.8 Hz — darker, as
dropping the 4' drawbar and thinning the 3rd should do; GM16's signature unchanged,
confirming its freeze).

New oracle `percussive_organ_17_has_a_decaying_tap`: GM17's onset band-punch (650-950
Hz, around the 3rd harmonic) exceeds GM16's by >1.6×. *First cut measured the 3rd
harmonic with a narrowband Goertzel over an 80 ms window and failed (ratio 1.10) — a
fast-decaying tap smears its energy across sidebands a fixed bin misses (the Stage-1
WD-O read issue again). A band-energy onset/sustain punch integrates the tap.*

Full suite 352 passed, 0 failed; fmt + clippy -D warnings clean.

## The render-diff methodology finding (important, reusable)

While validating Stage 4 I ran a baseline-vs-candidate render-diff and it flagged 10
albums as DIFF — alarming, because Stage 4 is provably `+0.0`-inert for all existing
SawStack callers. **It was a false alarm, and worth recording why:**

1. **A clean isolated render of a flagged album (Sub Rosa) with both binaries is
   byte-identical** — 0 differing samples AND 0 differing bytes over 40.5 M samples.
   So ferrosintesis WAV output embeds **no version string or timestamp**: identical
   audio → identical bytes on the same machine, and **byte-`cmp` is a valid
   render-diff oracle**. (This corrects the natural worry that the WAV header might
   carry the version and defeat byte comparison — it does not.)
2. **The DIFFs came from concurrency, not the synth.** I had stopped an earlier
   render-diff run and started a second, but `TaskStop` kills the loop's bash while
   leaving (a) the in-flight `deltic timeout <binary>` child and (b) the
   `done < <(find …)` **process-substitution subshell** alive. Worse, the first run
   used `target/release/ferrosintesis.exe`, which I then **rebuilt for Stage 5a** — so
   an orphan was rendering with a *different* binary into the **shared** scratch
   filenames (`cand.wav`/`base.wav`) that the second run also used. Two writers, one
   pair of files → garbage → false DIFFs.

**Rules for the next render-diff:** (a) one run at a time; (b) a **unique** scratch
dir per invocation; (c) after stopping a render-diff, kill the orphaned child +
process-sub subshell by explicit PID (name-based `Stop-Process` is guardrail-blocked
and unsafe on a shared box) before relaunching. The Stage 4/5a album blast is **zero**
— confirmed by the clean isolated diff, not the buggy batch run.
