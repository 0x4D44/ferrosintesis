# 2026.07.14 — JRN — drum-kit polish: kick depth re-source + hi-hat decorrelation

Follow-up to the full sampled drum kit (see `2026.07.14 - JRN - full sampled drum
kit (hats-snare-kick-toms).md`), driven by Arthur's listening feedback: the kick
reads "dumpy", fast closed-hat 16ths read machine-gunny.

## Fix 1 — kick re-source (mid overhead → kickmic close mic)

Done as briefed: `prepare_drumkit.py`'s KICK entry now pulls
`Samples/kickmic/kick/kickmic_kick_snon_vl{1-4}_rr{1-4}.flac` (same pinned SHA,
same 4x4 grid, same hivel splits 31/63/95/127 — verified against
`Programs/mappings/kickmic/kick_snon_map.sfz`). While here, fixed a latent
cache-poisoning bug: the download cache was keyed by OUTPUT name
(`kick_vl1_rr1.flac`), so re-pointing a bank at another mic set would silently
reuse the old mic's FLACs. The cache is now keyed by the source URL basename.

Regenerating rewrote all 188 WAVs; git shows ONLY the 16 kick files modified —
every other bank regenerated byte-identically (pipeline determinism proven, and
the snare/toms/hats/cymbals stay untouched as required). Crate samples total
unchanged at 19.93 MiB (kick keep_s unchanged, so byte lengths match).

**But the premise failed — measured wall, reported to the lead.** The metric
(sub 30-70 Hz vs mid 140-400 Hz per-Hz spectral density, Hann window, Goertzel
over a 2 Hz grid; self-tested on a synthetic two-tone WAV):

- Virtuosity is an 18" JAZZ kick with its fundamental at ~80 Hz. Neither mic
  has meaningful 30-70 Hz content from the drum itself.
- The overhead's 30-70 Hz energy is mostly room rumble — the close mic is
  CLEANER there, so the sub/mid ratio *fell* (bank files: old 0.04-1.03,
  new 0.001-0.81; engine render at vel 60-100: old 0.07-0.19).
- What the kickmic DOES fix is the boxiness Arthur is likely hearing: at the
  identical ~80 Hz fundamental level, the 200-400 Hz shell/room ring drops by
  ~15-25 dB vs the overhead (spot spectra, vl3: 200 Hz 12.6 → −10.4 dB,
  300 Hz 20.7 → 0.4 dB).
- Reference point: the MODELED kick the samples replaced is a pure sub thump —
  sub/mid ≈ 10^4 on the same metric. That gap cannot be closed by mic choice
  or a "+3-5 dB shelf below 80 Hz" (boosting a band with no signal); it needs
  either a shelf hinged ~100 Hz (lifts the 80 Hz fundamental, not 30-70) or a
  modeled-sub layer under the sampled attack (the synth's own LA philosophy).
  Left as the lead's call; the re-source is committed as a net improvement
  (kills the boxy mids) that is trivially droppable.

## Fix 2 — hi-hat decorrelation profile

`sampler.rs` grows per-bank `DrumJitter` profiles. Pitched/tonal drums keep the
exact old numbers (rate ±2.5 %, gain ±6 %, no onset delay) — byte-identical
renders, verified end-to-end (see below). The hats (42/44/46) get:

- **Stratified rate offsets**: 5 slots over ±8 % (`hit_index % 5`), white ±0.8 %
  on top. Analysis first, params second: white jitter alone can NEVER pass a
  tight correlation bound on 16 fast hits — some same-take pair always draws
  nearly equal rates and re-correlates the transient. 5 strata are coprime with
  the 4-take round robin (same take + same stratum only at hit distance 20),
  and adjacent strata guarantee ≥2.4 % rate separation for every same-take pair.
- **Onset jitter**: U(0, 1 ms) of leading silence (new `delay` field in
  `SampledDrum::render`) — shifts the transient off the grid.
- **Gain jitter** widened to ±10 %.

RNG draw order (rate, gain, onset) keeps zero-onset profiles bit-identical to
the pre-profile voice.

Oracle: `sampled_fast_closed_hats_do_not_machine_gun` worst-pair NCC threshold
0.97 → **0.35**. Fail-first proven: threshold tightened BEFORE the profile —
old jitter reads worst 0.705 (in-oracle measure; the lead's external measure of
the same render path read 0.494), red. With the profile: **0.280**, green;
same-take diff/rms 1.243 (was 1.290) — still a coherent hat, not a wash.

Clippy pushed `SampledDrum::new` past 7 args; grouped the per-strike values
into a `DrumHit` struct rather than allowing the lint.
