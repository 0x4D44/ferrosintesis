## What's worth keeping: the `DrumGlue` bus compressor

The same uncommitted diff also added a **feed-forward peak compressor on the channel-10
drum bus** — an idea that does not exist anywhere else in the repo's history (`git log
--all -S "DrumGlue"` turns up nothing but this one working tree). Recovered here verbatim
from the diff before the branch is deleted:

**Rationale (from the diff's own comments):** raising a flat drum-bus fader doesn't work
in this master — the −18 LUFS loudness normalize pulls the whole mix back down (a +6.8 dB
drum-bus boost moved the delivered master only ~0.4 dB RMS), and the −1 dBTP true-peak
limiter clamps the now-peak-driving drum transients (drum true-peak jumped 0.6→5.8 dBTP
at 2.2×) — so the extra loudness gets clipped straight back off. The fix on offer: convert
drum **crest** into drum **body** with a bus compressor, so the kit gets louder/denser in
RMS *without* a taller true peak, and that loudness rides through the limiter instead of
being shaved off it. Level-aware by construction — a delicate kit whose bus peaks sit
under the threshold gets pure makeup gain and zero gain reduction, so brushwork isn't
squashed.

**Design, as drafted (never committed, never gated):**
- New `DrumGlue` struct, structurally a sibling of the existing `BusGlue` (engine.rs) —
  stereo-linked envelope/gain follower (detector = `max(|L|,|R|)`), but 3:1 ratio (not
  2:1), no low-shelf detector weighting (glues the whole kit wideband), no tape
  saturation (drum transients stay linear).
- Constants: `DRUM_COMP_THR = 0.35` (linear detector threshold on the g9-scaled bus),
  `DRUM_COMP_MAKEUP = 1.5` (+3.5 dB, the dominant prominence knob), `DRUM_COMP_ATK_S =
  0.008` (8 ms — lets the transient crack through first), `DRUM_COMP_REL_S = 0.140`
  (140 ms — adds density without pumping the sustain).
- Wired in right after `kit_balance()` panning and before the reverb/room sends, which
  are fed from the *dry* (pre-compression) drum signal — so the glue changes the kit's
  punch, not how wet it sits.
- Two env-var escape hatches for tuning (`FERRO_DRUM_MAKEUP`, `FERRO_DRUM_THR`),
  explicitly commented "throwaway; strip the env reads before commit" — i.e. the author
  intended these as a pre-commit A/B ladder, not shipped surface.
- Verified only that it **compiles clean** (`cargo check -p ferrosintesis --lib`, this
  session). Never run against a real render, never gated (`fmt`/`clippy`/`test`), no
  render-diff, no A/B listen.

**Where it would slot in:** `crates/ferrosintesis/src/engine.rs`, next to the existing
`BusGlue` struct (the main bus-glue compressor already in the engine) and the ch10 mix
loop around the `DRUM_HALL_SEND_MULT` / `kit_balance()` code.
