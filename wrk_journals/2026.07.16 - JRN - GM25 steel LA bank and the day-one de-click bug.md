# 2026.07.16 — JRN — GM25 steel LA bank, and the de-click fade bug it exposed

## What this was

Arthur asked which instruments still lacked an LA sample layer, then followed a hunch:
"I believe there is a steel-string guitar CC0 samples — Emily guitar. And also bagpipes
too. Can you go have a dig?"

The dig found more than the guitar.

## The Emily lead — real, CC0, wrong instrument

`sfzinstruments/karoryfer.emilyguitar` exists and its licence is impeccable: verbatim
CC0-1.0 in a LICENSE file, committed by D. Smolken (the rightsholder) on 2022-11-04,
pinnable at `b4920dc`. Adversarial verification could not break it.

But "Emily" names the *guitar*, not the strings or the author: an Epiphone "Emily the
Strange" SG. Its readme is decisive — *"The strings are d'Addario Chromes flatwounds, 11
gauge. All samples recorded direct, using both pickups and all knobs on ten."* Electric,
DI'd, flatwound. For a GM 25 attack transient that is the worst possible source: no mic,
no body, no air. Rejected on instrument, not rights. (Would serve GM 27/28 someday.)

**Karoryfer licence trap, recorded for the next session:** the shop page and 2014-era
readmes still say *"Royalty-free ... Copyright 2014 Karoryfer Lecolds"*, which FAILS our
bar. Smolken relicensed all the *freebies* to CC0 in Nov 2022; the LICENSE file is
authoritative and newer. But Karoryfer also SELLS libraries. The brand is not a licence —
same lesson FreePats teaches from the other end (CC0 bagpipe, GPL guitar, one project).
Our existing `karoryfer.big-rusty-drums` provenance was verified from the LICENSE file at
a pinned SHA, so nothing is retro-exposed.

Also checked and rejected: `karoryfer.shinyguitar` (CC0 confirmed, but an archtop — a
warm jazz box, not a flat-top steel; the sampled part IS the attack, so a mismatched
onset makes identity worse, not better).

## What we took: a 2017 Martin HD-28

`sfzinstruments/Discord-SFZ-GM-Bank`, instrument `026-Acoustic Guitar (steel)`. Recorded
and CC0-dedicated by Jeff Learman in the instrument's own `.sfz` header (read at source,
not taken on a search result's word). 15 WAVs, E2–B5, already mono 16-bit 44.1 kHz.

**The licence evidence is weaker than our other sources and Arthur made the call
knowingly.** The dedication is a header comment, not a repo LICENSE file, and that repo is
a deliberately mixed CC0/CC-BY aggregation with no repo-level licence — so CC0 cannot be
inferred repo-wide and **the SHA pin is load-bearing, not a convenience**. The bank's own
README designates the `.sfz` as the authoritative per-instrument licence location, which is
what makes the header a mechanism rather than a stray comment. `STEEL_REV` must never track
`master`.

Took 8 zones at ~6-semitone spacing mirroring nylon (max repitch ±3.5 st): E2, A#2, E3,
A#3, E4, B4, F5, B5. Bank 202 → 210 files, 16.68 → ~17.3 MiB. Binary grew 626 KB against
a predicted 641 KB.

Two gotchas: the source spells accidentals as FLATS (`Bb2`, `Db3`) and our note parser
speaks sharps, so destinations are respelled. And the Martin is tuned 3–16 cents flat —
a non-issue by existing design, because `prepare.py` stores the MEASURED f0 as the zone
root, so the flatness never reaches the render.

## The bug this exposed — and how I nearly shipped a worse one

`prepare.py` applies a 2 ms de-click fade-in, sized to run over the 8 ms `PRE_S` pad. The
Martin takes start within 0.6 ms, so the fade would have run straight over the pick
transient — dulling exactly what the LA layer exists to capture.

**My first fix was wrong.** I padded the shortfall to a full `PRE_S`, wrote a differential
test against the old algorithm, watched it pass, and called it "provably inert". It was
not. The test fed inputs with 8–300 ms of lead-in — I had tested my *assumption*, not
reality. Regenerating the bank showed the truth: **131 committed WAVs changed**. The real
sources are trimmed far tighter than 8 ms (median onset: piano 120 samples, violin 3,
steel 8), so the pad shifted every layered attack up to 7 ms later. `git status` caught
what the green test could not.

The measurement that followed is the real finding:

- **74 of 210 sources have their onset INSIDE the 2 ms fade window.**
- Every source begins at near-silence (max |x[0]| across the bank = 0.015) — **so no
  de-click was ever needed.** Where onset < 2 ms the fade is pure damage.

Correct fix: cap the fade at the lead-in that actually exists (`fin = min(2 ms, onset -
start)`). Exactly inert for the 136 sources with more lead-in; fixes the rest. Blast
radius measured, then confirmed by regeneration: **66 existing WAVs + 8 new steel**, which
matched the prediction exactly.

## Provenance of the bug: it is as old as LA synthesis here

`git log -L` on those lines returns **one commit**: `ce99cda`, 2026-07-02 22:52 BST, "Add
hollowsynth v0.3 — zero-dep Rust MIDI-to-WAV synth with LA sample layer". Fourteen days,
zero modifications; it survived the repo restructure, drums, brass, reeds, guitar, strings
and the crate split untouched.

Day one, `SOURCES` held **violin only** — and violin's min onset is 3 samples. So it was
already wrong on the first render, and 6 of 12 violin samples are in today's 66. The
constant never drifted; the material underneath it moved as families were added and nobody
re-measured. Arthur: *"It's just a bug, isn't it"* — yes, and every sampled attack
ferrosintesis has ever rendered has carried it.

## Alt bank: already done by a past session

Arthur asked to preserve the pure-model steel on the alt bank. No code needed —
`altbank.rs` already had `24..=25 => voices::make(..., samples: false)`, placed for nylon
with the comment *"25 has no layer yet ... but is pinned too so it stays frozen if one
lands."* One landed. The pin became load-bearing today, so I added the two oracles that
keep it honest: `altbank_guitars_skip_sample_layer` (on/off bit-identical) and
`altbank_steel_differs_from_the_layered_default` (the alt is a real alternative, not a
copy). Before today the first would have been vacuous — 25 had no layer to skip.

## Also found (logged to scratchpad, not fixed)

The 8 `drum_*` WAVs in `ferrosintesis-samples-orchestral` are **dead weight**: referenced
only by the crate's own inventory array, loaded by no synth code. Pre-drumkit VSCO
overlays, superseded when the Virtuosity kit landed. ~400 KB of payload in every binary.
They were 8 of the 66 re-cut files — and provably could not have moved a single render.
