# 2026.07.17 — JRN — GM0 Salamander grand LA bank

## Task

Arthur: "pianos 000 & 001 sound the same. Can we find different CC samples to get a
bit more variety?"

## Diagnosis

GM 0 (Acoustic Grand), GM 1 (Bright Acoustic) and GM 3 (Honky-tonk) all draw the
**same** VSCO 2 CE *upright* recording — `piano_bank(vel, rr2)` (`sampler.rs`) selects
by velocity only, no program dimension. The only differentiation:

- GM 1: a +5 dB high-shelf @ 1.8 kHz on the shared sample (`LA_BRIGHT_SHELF`).
- GM 3: a ±7-cent detune (`LA_HONKY_DETUNE`).
- The modelled bodies (`acoustic_piano` / `bright_acoustic_piano`) mostly supply the
  *tail*; the README notes the recording "carries most of the note."

So GM 1 was literally GM 0's recording with a treble lift → they sound the same.

## Decision (Arthur chose)

Source a genuinely different **grand** for GM 0 rather than push DSP harder. Research
found no clean **CC0** bright grand (the CC0 sets are uprights); every bright grand is
CC-BY. Arthur picked **Salamander Grand Piano V3** (Yamaha C5, Alexander Holm,
**CC BY 3.0**). Redistribution of the data is permitted with attribution — precedent:
the gong crate is already CC BY 3.0 with a `NOTICE`.

Mapping: **GM 0 → Salamander grand**; **GM 1 → VSCO upright + its bright shelf**;
**GM 3 → upright + detune** (unchanged). Now each recording matches its GM name and
GM 0/1 are different instruments.

## Architecture

- New crate **`ferrosintesis-samples-grand`** (not added to core): core is already
  9.55 MiB, right under the crates.io 10 MiB cap; the grand bank is 6.85 MiB, so it
  needs its own crate. Follows the `-gong`/`-drumkit` precedent. Wired as an optional
  `=0.1.0` dep in the `embedded-samples` feature; added to the `embedded_wav` resolver
  chain.
- Bank: 9 zones C2–C6 (F# stands in for each G — nearest sampled pitch), 3 dynamics,
  **2 round robins**. Salamander has no true RR, so RR2 = an adjacent velocity layer;
  `trim_to_onset` peak-normalizes every file to 0.9, so RR1/RR2 land at the same level
  and differ only in harder-strike timbre — real RR variation, no machine-gun on
  repeated notes (GM 0 keeps 1.5 s of sample, so repeats matter).
- `prepare.py`: `.tar.bz2` decoded by stdlib `tarfile` (no 7z); pinned by SHA-256
  `fe595c…62892`; streamed once, 54 members pulled; routed to the -grand crate via a
  new `FAMILY_PACKAGE` map. KEEP_FAM grand = (1.5, 0.6).

## Surprise — the harpsichord oracle used GM 0 as a control

`harpsichord_jangles_with_a_four_foot_choir` compared the harpsichord's sustain
centroid / 2f0-f0 against a **GM 0** render (`stats(0)`, samples on). With GM 0 now the
brighter, 2f0-rich grand (centroid 561 Hz / choir 2.00 at key 55 vs the old upright's
~470 / ~0.2), both clauses broke — the exact "oracle encodes GM 0's timbre" hazard in
`lessons_learnt` (harp_46 / choir CH2-O2 / recorder WD-O1). Fix, in this commit: point
the control at **GM 1** (the same upright, the timbre the oracle was calibrated on).
GM 1 carries the +5 dB shelf so it reads a touch brighter than the retired bare-upright
control; the centroid bar drops 1.75× → 1.6× to match (measured 1.76×/1.68× at 55/67),
and the strong 4′-choir clause (3–14× the control) is untouched. Not a weakening — a
recalibration against the correct reference.
