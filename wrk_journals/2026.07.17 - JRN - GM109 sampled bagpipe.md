## UNDERSTAND

Two verification helpers, both returned solid:

- **Source (FreePats, measured from the archive):** take the WAV archive
  `Bagpipe-SFZ-20221204.7z` (18,887,910 B, sha256 6f25f232…256066), 44.1k/24-bit
  mono, stdlib-`wave`-decodable. 26 files = 24 chanter (F4–G5) + 2 drones (G2
  98.19 Hz, G3 196.18 Hz, separate mono, one drone each). CC0 with cc0.txt.
  Sustains stable (<6 c drift), dry, no reverb. **Key measured fact:** a plain

  25/26 files; crossfade moves it <1 dB, not needed). Corrections to the prior
  dig: WAV archive is "SFZ" not "SFZ+WAV"; range is F4–G5 not F4–G6; 26 files not
  30; one upstream loop (D#5) is broken; drones carry −35/−41 dB DC.
- **Code map:** the drone already has a full engine-side lifecycle
  (`ensure_bagpipe_drone`, latch, 1 s bag-empty release). `Voice` trait needs 4
  methods. THE TRAP: `altbank.rs` fall-through `_ => make(…, samples)` will
  forward `samples:true` into a new 109 arm and make the model unreachable — the
  alt-bank 109 arm is REQUIRED. Every existing 109 oracle runs `samples=false`,
  so a sampled default lands unguarded (BP-O1/BP-O2 need sampled siblings).
  `set_pitch`'s absence on the drone is load-bearing (CC1 warble). `trim_to_onset`
  is hostile to loops. `EXPECTED_BYTES`/`FILE_COUNT` pins in the orchestral crate.

Spot-checked the 3 load-bearing code claims myself (altbank fall-through, the
`64..=67 | 109 | 111` reed arm, 109 absent from `LA_PROGRAMS`) — all confirmed.

## DESIGN

Key simplification the measurements unlocked: **bake the loop offline, runtime =
plain modulo wrap.** Kills the "biggest structural gap" (Zone has no loop
metadata) — we never need it; `bank!`/`parse_wav`/`Zone` untouched. `LoopVoice`
~40 lines with its own Adsr(sustain=1.0) → correct released()/alive() by
construction. Drone = bass+tenor octave stack from the two real drone files,
key-relative by repitch. Model stays on the alt bank via the required 109 arm.

Self-flagged before review (crux): my doc justified "repitch preserves the seam"
via period-exactness, which is imprecise. The real reason: the baked seam is
waveform-CONTINUOUS (data[L-1]→data[0]), a property of the DATA, independent of
playback rate — so repitch preserves it trivially. The implementation
consequence the doc must state explicitly: the linear-interp neighbour must WRAP,
`hi = (floor(pos)+1) % L`, or the last sample of the loop interpolates against an
out-of-bounds / wrong neighbour and clicks every wrap. Will fix in the fold.
