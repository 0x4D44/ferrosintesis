# JRN — CC84 portamento + CC32 XG bank-LSB (investigation)

## CC84 (portamento control) — found low value for THIS file
- ch10 is the only channel sending CC84 (6 events, source keys 32/37). NO channel sends
  CC5 (porta time) or CC65 (porta on) anywhere → glide falls back to the 5 ms default =
  ~instant. So implementing CC84 correctly changes 6 note-ons by an inaudible scoop.
  Legit MIDI-correctness fix for the general player; ~no effect on Incantations.

## CC32 (XG bank-LSB variations) — premise appears largely FALSE
- File's LSB values: 96,112,113,115,117,3,19,41,45,65,98 — scattered/high, per channel.
- XG voice list (Bank MSB=0) I could access: these LSBs "not listed" for these programs.
- Yamaha/community docs: **an XG synth falls back to the BASIC (GM) voice for undefined
  banks.** ferrosintesis already plays the basic GM voice → **for these channels we are
  very likely ALREADY rendering exactly what a real XG synth would.** The "fidelity gap"
  is largely illusory.
- Corollary (correctness): modeling "variations" for UNDEFINED banks would make
  ferrosintesis DIVERGE from a real XG synth (which plays base GM) — i.e. LESS faithful.
  So the correct behavior for undefined banks is precisely what we already do.
- Could not get a definitive complete XG voice map cheaply: angelfire host unreachable,
  manualowl 403, official Yamaha PLG100XGE.pdf won't parse via WebFetch and this box has
  no poppler to render it. A few LSB-96/98 banks *might* be real ethnic/synth voices; not
  confirmed.

## Decision needed (surfaced to Arthur)
- Premise ("this file needs XG variation voices") is mostly false; ferrosintesis already
  matches real XG for undefined banks. Options: drop; or get a reliable XG voice map and
  model only the confirmed-real variations (likely a small handful, if any); or build the
  CC32 dispatch infra anyway (but with no real variations it's a no-op = premature).

## Implementation log

### Unit 1 — CC32 infra + CC84 (DONE, green)
- engine.rs: `Strip.bank_lsb: u8` + `Strip.porta_control: Option<u8>` (init 0 / None).
- CC handlers: `32 => s.bank_lsb = val`, `84 => s.porta_control = Some(val)`.
- note_on dispatch (the `!is_drum && !alt_bank` else branch) now calls
  `voices::make_variation(prog, bank_lsb, …).unwrap_or_else(|| voices::make(prog, …))`
  — same `seed` on both paths, so an undefined pair is bit-identical to base.
- CC84 consumption: `let porta_ctrl = self.strips[ci].porta_control.take();` hoisted to
  after the bagpipe/legato/tremolo early-returns (consumes only when a voice actually
  spawns), before the `let s = &self.strips[ci]` borrow. Glide source merged:
  `porta_ctrl.map(key_freq).or(if s.porta_on { porta_from } else { None })` — CC84 glides
  regardless of CC65, honoring CC5 porta_time; falls through to the CC65 path otherwise.
- RAC (CC121) clears `porta_control`; `bank_lsb` PERSISTS (bank select is not a RAC controller).
- voices.rs: `pub fn make_variation(program, bank_lsb, key, vel, sr, seed, samples) ->
  Option<Box<dyn Voice>>` — skeleton returns None (RNG-pure); variation arms land per-unit.
- Tests (engine::tests): `cc32_undefined_bank_falls_back_byte_identical` (LSB 113 undefined
  for all progs -> byte-identical to no-CC32, forward-safe as variations get added);
  `cc84_glides_from_source_without_porta_on_and_is_consumed_once` (source-pitch `mag_at`
  energy: note-1 scoops from key 48 without CC65, note-2 doesn't -> consumed once).
- Green: 2 tests pass; `clippy -p ferrosintesis --all-targets -D warnings` clean; fmt clean.

### Unit 2 — Ukulele (24, 96) (DONE, green)
- `UKULELE` PluckPreset from `..NYLON`: t60 3.8->1.8, bright 3800->4800, pick_lp 2500->3400,
  rel_t60 1.1->0.55, body raised (260/520/900 Hz — tiny soundbox), click_hp 1000->1100.
- make_variation arm `(24, 96) => Pluck::new(&UKULELE, …)`. Modeled-only (no uke sample bank;
  base 24's LA guitar layer would sound like a guitar, so the variation is pure model).
- Oracle `ukulele_variation_is_brighter_and_shorter_than_nylon` (koto-test idiom, 3 seeds):
  centroid(UKU) > 1.10*centroid(NYLON) AND t60_of(UKU) < 0.80*t60_of(NYLON); + dispatch pins
  (24,96)->Some, (24,113)->None. Green; clippy/fmt clean.

### Unit 3 — Oud (105, 98) (DONE, green)
- `OUD` PluckPreset from `..NYLON` (its timbral base is nylon/gut, NOT the banjo drumhead):
  bright 3800->2200, pick_lp 2500->1500, out_lp 3200 (mellow rolloff), low warm bowl body
  (90/160/300 Hz), + the dulcimer double-course params (detune 1.0042, course_t60 0.85,
  course_mix .56/.44, couple 0.002, wound_key_split false).
- make_variation arm `(105, 98) => Pluck::new(&OUD, …)`.
- Oracle `oud_variation_is_warmer_than_nylon` (3 seeds): centroid(OUD) < 0.90*centroid(NYLON).
  First pass came in at ~0.91 (only 9% warmer) — deepened the model (lower pick_lp + out_lp
  3200) to clear the 10% bar rather than weaken the oracle; the oud is genuinely mellow. Green.

### Unit 4 — Gran Cassa (116, 96) (DONE, green)
- `GRAN_CASSA_MODES` (fundamental-dominated, one faint fast 2nd mode; no 3rd mode) + `gran_cassa`
  fn beside taiko_drum: darker soft strike (noise 0.45, lp120 vs taiko 0.95/lp260), longer
  release (8.5 vs 6.0), gentle pitch drop (1.0 vs 2.8). make_variation arm `(116, 96)`.
- Oracle `gran_cassa_variation_is_darker_and_longer_than_taiko` (3 seeds, model-vs-model):
  t60_of(cassa) > 1.15*t60_of(taiko) AND upper-mode band [2f,6f]/fundamental < 0.60*taiko's.
  METRIC LESSON: a log-binned centroid could NOT separate two bass-dominated drums (262 vs 260 Hz)
  — both floored near the fundamental; nor could hp_rms(200)/rms (soft-skirt fundamental leakage,
  only 0.31 vs 0.40). The taiko's ringing 3rd mode (2.14f) is the real difference, so measure the
  2f..6f band relative to the fundamental. Deepened the model too (killed noise>120Hz). Green.

### Unit 5 — Slow Strings (48, 3) (DONE, green)
- make_variation arm `(48, 3) => strings(49, …)` — reuses the existing program-49 slow voicing
  (attack 0.45, darker cutoff) verbatim; no new preset, no change to the base voice.
- Oracle `slow_strings_variation_has_longer_attack_than_base` (3 seeds, model-vs-model): a
  late-steady-window attack-rise metric (0.9..1.3s reference, NOT the built-in attack_rise_s's
  0.25-0.45s window — too early for a 0.45s attack). slow > 2.0*fast AND slow > fast+0.05s.
  NOTE: attack is velocity-scaled, so measured at vel 64 (a fortissimo hit shortens every
  attack); at vel 64 slow~0.12s vs fast~0.04s (3x). Reused strings(49) as designed (can't
  alter the base voice), so the gap is what the slow path gives — a real, audible 3x. Green.
