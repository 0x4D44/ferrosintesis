# JRN — CC84 portamento + CC32 XG bank-LSB (investigation)

## CC84 (portamento control) — found low value for THIS file
- ch10 is the only channel sending CC84 (6 events, source keys 32/37). NO channel sends
  CC5 (porta time) or CC65 (porta on) anywhere → glide falls back to the 5 ms default =
  ~instant. So implementing CC84 correctly changes 6 note-ons by an inaudible scoop.
  Legit MIDI-correctness fix for the general player; ~no effect on Incantations.

## CC32 (XG bank-LSB variations) — premise appears largely FALSE
- File's LSB values: 96,112,113,115,117,3,19,41,45,65,98 — scattered/high, per channel.
- XG voice list (Bank MSB=0) I could access: these LSBs "not listed" for these programs.
- Yamaha/community docs: **an XG synth falls back to the BASIC (GM) voice for undefined
  banks.** ferrosintesis already plays the basic GM voice → **for these channels we are
  very likely ALREADY rendering exactly what a real XG synth would.** The "fidelity gap"
  is largely illusory.
- Corollary (correctness): modeling "variations" for UNDEFINED banks would make
  ferrosintesis DIVERGE from a real XG synth (which plays base GM) — i.e. LESS faithful.
  So the correct behavior for undefined banks is precisely what we already do.
- Could not get a definitive complete XG voice map cheaply: angelfire host unreachable,
  manualowl 403, official Yamaha PLG100XGE.pdf won't parse via WebFetch and this box has
  no poppler to render it. A few LSB-96/98 banks *might* be real ethnic/synth voices; not
  confirmed.

## Decision needed (surfaced to Arthur)
- Premise ("this file needs XG variation voices") is mostly false; ferrosintesis already
  matches real XG for undefined banks. Options: drop; or get a reliable XG voice map and
  model only the confirmed-real variations (likely a small handful, if any); or build the
  CC32 dispatch infra anyway (but with no real variations it's a no-op = premature).
