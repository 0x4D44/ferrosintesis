# JRN — GS rhythm-part drum routing

Task: `task/20260718-TSK-HUM-gs-rhythm-part-drum-routing` (follow-up to the XG CC0=127 fix)

## Understand
- Corpus scan (all 24 reference MIDIs): **zero** use GS "Use for Rhythm Part". Two use
  GS Reset + other part params (Oxygene Pt IV: addr 40 1x 1C; While My Guitar: reset
  only). So no real file to validate against → synthetic validation. Flagged.
- Parser drops ALL SysEx (`midi.rs` 0xF0/0xF7 arm skips). GS needs new parser plumbing.
- Verified GS format (Roland F-20 impl + Wikipedia): "Use for Rhythm Part" = DT1 addr
  `40 1x 15`, val 0=off/1=MAP1/2=MAP2. Block quirk: block 0→ch10(idx9), 1-9→ch1-9(idx0-8),
  A-F→ch11-16(idx10-15). Confirmed the `40 1x` part-addressing against real corpus GS msgs.
- Reuses the XG `is_drum` machinery: minimal change = detect one SysEx → new
  `EvKind::DrumMode` → set strip `drum_part` (renamed from `xg_drum`).

## Design
- Wrote HLD `wrk_docs/2026.07.18 - HLD - GS rhythm-part drum routing (...).md` (DRAFT).
- Non-goals: general SysEx framework; GS ch10→melodic; GS map/kit selection; checksum check.

## Reviews (2 adversarial + Codex external) — survivors folded
- **MAJOR (2 reviewers cross-refuted the rename):** XG's flag is CC0-driven; a GS rhythm
  part still sends CC0=0 (bank select) → a single merged flag would be clobbered. → keep
  `xg_drum`, ADD separate `gs_drum`; `is_drum = ch==9 || xg_drum || gs_drum`.
- **MAJOR:** mask nibble inside `gs_block_to_channel` (`block & 0x0F`) so a bad address
  can't panic `strips[]` (16-elem).
- Require the high-nibble==1 check (`payload[5]&0xF0==0x10`) — else `40 2n 15` false-positives.
- **Codex High (folded):** reject `mm>2`; handle GS Reset `40 00 7F` → clear all gs_drum
  (byte-safe; a real correctness gap I'd missed).
- **Codex declined (documented):** full Roland checksum (address match already specific +
  mm≤2); MAP1/MAP2→bool (non-goal). Running-status-after-SysEx: my change is neutral;
  pre-existing → verify at impl, scratchpad if a real bug.
- Test set hardened: middle block arm (0x11→ch0), truncated payload, near-miss 0x16,
  non-part nibble 0x20, CC0-clobber regression, GS-Reset regression.
- Confirmed by reviewers+Codex: block map correct for all 16 nibbles; ordering via
  (tick,seq) stable sort; EvKind is crate-private (no semver break); byte-identity holds
  by construction (render-diff to confirm). Live path offline-only (documented).
