# 2026.07.18 — JRN — harpsichord level + sax holds audit

Arthur flagged two things about the recent LA-layer work: the **harpsichord sounds
quiet**, and the **saxophone holds sound wrong** (asking whether holds need samples,
a sample/model mix, or something else, and what SoTA does).

## Method

Built ferrosintesis, rendered isolated probes through it and a Roland SC-55mkII
(`mdmidiemu`, ROMs at `D:/language/mdsc55/roms/sc55`), and measured. Because
ferrosintesis normalises the whole mix to −18 LUFS, single-instrument files can't be
compared in absolute terms — so each probe carries a **piano anchor (GM0, untrimmed)**
present in both engines, and the *ratio* to that anchor is what's compared cross-engine.
Probe MIDIs + WAVs + analysis in `target/holds_audit/` (git-ignored).

## Harpsichord (GM6) — confirmed quiet, fixed this branch

- ferro harpsi/piano: **−11.9 dB attack** (fair early-window RMS), **−18.6 dB sustain**.
  SC-55: −1.8 / +0.8. Relative to the *guitar* it's balanced fine — the whole plucked
  family reads low beside ferro's deliberately-hot piano onset (`LA_PIANO=0.90`).
- `PROGRAM_TRIM_DB[6]` was 0.0 (lumped in the "piano untouched" row; never SC-55-trimmed).
  The `HARPSICHORD` Pluck also damped far faster than the SC-55 (sustain died 19 dB vs
  the SC-55's still-ringing tone).
- Fix (Arthur chose "+6 dB trim + lengthen decay"): `PROGRAM_TRIM_DB[6]=+6` (documented
  plucked exception — genuinely low by early-window RMS, and the trim lifts sampled onset
  + modeled body uniformly post-wrap, so the onset/body ratio is untouched); `t60` 1.9→3.0,
  `course_t60` 0.7→1.1 (keep the 4′-choir balance). `LA_HARPSICHORD` stayed 0.28 — even
  with the slower decay a high string damps its treble fast, so 0.42 still steps the C5
  seam past `la_level_continuity`.
- After: attack −7.6, sustain −9.6, ring late/early −11.7 (was −19.3). Moves toward the
  SC-55 without overshooting the +6 dB choice. Suite 487✓; render-diff = 1 GM6 album
  changed, 0 contamination.

## Sax holds (GM 64-67) — diagnosed; rework approved, separate branch

- Past 0.24 s `LaVoice` gates the sample off (`sampler.rs:1599`), so the hold is 100%
  modeled reed. Confirmed on the current binary: attack differs samples (1167 Hz) vs
  no-samples (1397 Hz), sustain identical (1607 Hz both). The modeled sustain is a static
  drone — liveness (framewise RMS CoV) **0.024 vs the SC-55's 0.050** (~2.3× less movement).
- We already own ~0.4 s of real, breathing sustain in every 0.628 s sample (discarded at
  0.24 s; liveness ~0.5).
- SoTA research (4-angle web sweep, adversarially verified — verdicts in the workflow
  journal): the fix is **attack sample → pitch-synchronous looped real sustain, model
  demoted to a modulator** (vibrato on read-rate, brightness LP on CC11×vel, additive
  breath noise) — never summed as a second tonal oscillator (same-f0 comb trap the
  attack seam already sidesteps with sum-to-one). Reuses `LoopVoice`/`extract_loop`/the
  seam oracle. Arthur approved this (option ①). Feasibility risk: the MTG takes are short
  and not perfectly steady, so the clean loopable region per zone may be tight — the
  offline seam oracle proves it before shipping.
- Decision brief artifact: measured levels + liveness + ranked options + DSP plan.

## Surprise / dead end

- **Stale-baseline trap** (now a lesson): the first build silently no-op'd (a wrong
  `mdtimeout` path → cargo never ran → `ls && echo` found a *previous session's* binary and
  printed a false "BINARY READY"). The stale binary predated the sax LA layer, so the first
  render-diff reported 107 non-GM6 albums as contamination for a GM6-only change. Rebuilt a
  true `origin/main` baseline → 0 contamination. Also re-verified the sax probe on the correct
  binary (the first sax measurement had been on the pre-layer binary).
