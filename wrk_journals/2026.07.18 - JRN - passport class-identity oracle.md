## The bug (MM-BUG-KILN-00006, Severity High)

No oracle asserts a voice belongs to its instrument CLASS — only pairwise difference is
checked. Timbre quality is unverified; a voice could rot toward a buzz yet stay "distinct"
and green. The HLD §5 Passport class-range oracles were designed but never built. This is
the leverage item: it would have caught the viola clone automatically.

## Design (settled — see the workflow plan; execute it)

**Location:** INSIDE `mod perceptual_distinctness` in `crates/ferrosintesis/src/testutil.rs`
(~line 1570), next to the pair oracles. MUST be same-module — every `Passport` field is
private, only a same-module test can read them and call `passports()`.

**Reuse verbatim (no second renderer):** `passports()[prog as usize][k]` — memoized
`&'static [[Passport;2]]` over programs 0-127 × keys {48=C3 idx0, 72=C5 idx1}
(testutil.rs:2087). Protocol is frozen: samples-on (`render3s` asserts
`embedded_samples_available()`, :1780), 3.0 s, no note-off, VEL=100, SEED=7, SR=44100.
Aggregate the two probe keys by **mean** (§2.1: mean not max).

**Shape — one table + one iterating test:**
```rust
// key idx 0=C3(48), 1=C5(72); mean per §2.1
fn field_mean(prog: u8, f: impl Fn(&Passport) -> f32) -> f32 {
    let p = &passports()[prog as usize];
    0.5 * (f(&p[0]) + f(&p[1]))
}
struct ClassRange { label:&'static str, programs:&'static [u8], field:&'static str,
                    get: fn(&Passport)->f32, lo:f32, hi:f32 }
#[test] fn class_identity_ranges_hold() {
    for r in CLASS_RANGES { for &prog in r.programs {
        let v = field_mean(prog, r.get);
        assert!((r.lo..=r.hi).contains(&v),
            "{}: GM{prog} {} = {v:.4}, out of class range [{}, {}]", r.label, r.field, r.lo, r.hi);
    }}
}
```
Two-sided absolute range on the key-mean of ONE named field. Per-view fields select the
view in the closure (`|p| p.flat[V_LONG]`, V_LONG=1). Panic string prints prog/field/value
(self-diagnosing).

**Fields the oracle MAY assert (physically-scaled class axes only):** `sustain_db` (D1 —
strongest axis), `attack_log10` (D1), `flat[V_LONG]` / `harm_frac[V_LONG]` (D4), `fm_depth`
(D5). `cent_log2` is EQ-not-identity (coarse JND) → secondary only, never a sole anchor.
Pair-only quantities (d_i, D7 gestalt, is_shared_onset) do NOT belong here.

**LA-wrapped guard:** for programs in the LA set (0,1,3,24,40,41,42,43,48,49,56..61,68..71,
72,73,110), a range is only valid if the sample layer engaged at the probe key (reuse the
`sample_layer_engaged_at_probe_keys` / test-6 guard); skip a non-engaged member rather than
measure the bare model.

**CRITICAL calibration truth (do not skip):** the EXISTING class-oracle numbers (organ
sub/fund, nylon attack, clarinet h2/h1, etc.) are measured with *voices.rs* primitives
(mag_at ratios, hand-picked settled windows) — a DIFFERENT space from Passport fields. They
calibrate only the **direction/sign** (organ sustains ~0, nylon attacks fast, strings
vibrate). The **number on the Passport field is `needs-measurement`** — get it from the U1
dumper. Pasting survey-3 numbers as Passport ranges would be wrong by construction.

## Calibration procedure (RED-before / GREEN-after — NO tune-to-green)

1. **Dump (U1):** `cargo test print_passport_fields -- --ignored --nocapture` on HEAD; read
   the real per-program key-mean of each field.
2. **RED-before:** prove the range REJECTS a wrong-class member (e.g. organ `sustain_db≥−4`
   must FAIL on GM0 piano; guitar `attack_log10≤−1.9` must FAIL on GM19 organ). Point the
   rule at the wrong program temporarily, confirm the panic, revert. Discriminating power
   proven before trust.
3. **GREEN-after:** widen each bound only to the geometric-mean gap between in-scope members
   and the nearest OTHER family on that field. Good voices pass; wrong-class control fails.
4. **Freeze:** record observed numbers + date in a module comment (mirror the line-1673
   frozen-calibration block), citing the print run.

**Hard rule:** never widen a range purely to green a failing GOOD voice. Either (a) a
physical rationale for the wider range (document it), or (b) it's a real voice bug (F4).

## Forks (defaults chosen; escalate only F4)

- **F1 (default: SKIP lead/pad 80-95):** genuinely ear-only; no envelope/spectral range spans
  a plucky square lead and an evolving sweep pad. Stay silent by design. Do NOT add a heuristic.
- **F3 (default: fm_depth PRESENCE, not rate):** the Passport has `fm_depth` (D5 depth), not
  FM rate. Asserting the §5 "4-7 Hz" band would need a NEW `fm_rate` field on the shared
  struct + memoized render → beyond test-only scope. v1 asserts presence (`fm_depth ≥ floor`);
  `fm_rate` is a separate discussable follow-up.
- **F4 (STOP and ask Arthur):** a GOOD voice that fails a physically-correct range is a real
  voice bug, not a range to relax. File it in `bugs/` and either scope the member out WITH A
  CITED REASON, or leave it and stop-and-ask (leaving the test RED fails the build). This is a
  genuine architectural fork — surface it, don't guess.
- F2 (mechanical, see U6): reed↔flute overlap → land what separates, report what doesn't.
- F5 (minor): piano `sustain_db` floor is soft (reverb/resonance tail lifts it); U1 sets it;
  an implausibly-high measured floor is a scratchpad note, not a blocker.
