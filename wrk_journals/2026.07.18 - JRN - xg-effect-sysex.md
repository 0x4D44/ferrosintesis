## Current parser (midi.rs)
- SysEx handled at parse():198-232. Decodes ONLY two GS messages (DrumMode, GsReset); **every
  other SysEx is ignored** (comment at :201). XG effect SysEx (0x43…) is dropped.
- Clean precedent: a recognized SysEx pattern → a specific `EvKind` (DrumMode/GsReset), consumed
  by the engine. XG effect SysEx follows the same shape.

## Current engine effect architecture (engine.rs)
- THREE fixed global buses: hall reverb (Freeverb), stereo chorus, tempo-derived ping-pong echo.
  Reverb is CC91-authored per-channel (`reverb_send`); chorus/echo sends per-program via
  `fx_profile` (:383). Global amounts: `Options.wet` (reverb), `Options.delay_s` (echo) — set by
  the CLI/render-catalog, NOT by SysEx.
- Reverb *type* is effectively hard-coded (one Freeverb config); only wet + sends vary.
- **No "variation effect" / insertion-effect concept at all.**

## Reuse story (the key finding — the variation effect is mostly REUSE)
- `reverb::Reverb::new(sr, room, damp, wet)` + `with_predelay(...)` is FULLY parameterized →
  mapping XG Reverb Type (Hall 1) onto room/damp/predelay is a bounded param mapping, not new DSP.
- `Chorus` struct (engine.rs:483) is tunable (rate/depth) → Chorus 1 is a param mapping.
- **`struct Drive` (engine.rs:275) IS an amp simulator already**: pre-HPF, voicing peak EQ, two
  biased-tanh gain stages (g1/g2 + bias, asymmetric), tilt EQ, DC blocker, and a **5-biquad
  cabinet** (`cab_biquads`), all at 2× oversampling. Currently applied per-VOICE for the
  distortion-guitar programs 29/30 (via `needs_drive`). The XG Amp Simulator variation = a
  parameterized, per-PART (channel insert) version of this same DSP. So the variation effect is
  largely REUSE + a new routing (channel insert vs program-gated), not a from-scratch effect.

## Design shape (pre-decode, to firm up once the spec returns)
- Parser: decode the XG Effect1 SysEx → new `EvKind`(s) (reverb type, chorus type, variation
  type + params, returns, connection, part). Follow the GS DrumMode precedent.
- Engine: map reverb/chorus type → the existing Freeverb/Chorus params; add a variation
  insertion effect = a parameterized `Drive`-style insert on the target part's voices.
- Byte-identity invariant (as with CC32/CC84): NO album sends XG effect SysEx, so the change must
  be inert without it → render-diff over all albums must stay 0. Confirm.
- Open architectural questions for the checkpoint: (a) insertion routing (per-channel insert on
  the variation Part) vs system-send; (b) how SysEx effect settings interact with the
  CLI's `Options.wet`/`delay_s`; (c) how faithfully to model the Amp-Sim LSB 0x11 variant.
