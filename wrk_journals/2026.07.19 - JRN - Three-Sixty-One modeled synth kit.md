# 2026.07.19 - JRN - Three-Sixty-One modeled ("synth") drum kit

## Ask
Arthur: Three-Sixty-One's drums sounded better with the old **synth'd** kit than
with the newer **realistic (sampled)** kit. Restore the synth kit for this track,
adding it as a selectable alternate. Reference point: the kit as it was in the repo
on **Sunday 12 July 2026**.

## Diagnosis (git archaeology + numeric render comparison)
- Last commit on/before Sun 12 Jul: `cc8768f` (2026-07-12 23:31).
- On 12 Jul the ch-10 kit was **modeled V3 voices + a light sampled *attack* overlay**
  on kick/snare/crash (`SampleOverlay::wrap`, orchestral-crate `drum_*` WAVs).
- The **full sample-replacement kit** (the "realistic" one) landed **14 Jul+**
  (`ferrosintesis-samples-drumkit`, 188 files; `32bf3df` "route the full sampled drum kit").
- Rendered Three-Sixty-One's drum channel (`--solo 9`) three ways and compared
  (diff-signal RMS, lower = more identical):

  | vs | diff | note |
  |----|------|------|
  | July-12 kit vs today's **sampled** kit | **-18.4 dB** | huge — the complaint |
  | July-12 kit vs today's **no-samples modeled** | **-33.3 dB** | close, not identical |

  So the modeled path already recovers almost all of the July-12 character; the
  sampled kit is the outlier.
- **Byte-exact July-12 is disproportionate:** the 3 drum WAVs all changed, `dsp.rs`
  drifted (+230 lines), and the old `drum_kick_bank`/`SampleOverlay` machinery was
  *removed*. Reproducing exact bits = vendoring a frozen old drum subsystem.

## Decision (asked Arthur — chose "Modeled synth kit")
Add a selectable **modeled synth kit** = V3 voices with the sampled-replacement
layer switched off. Not byte-exact to 12 Jul (uses today's *improved* modeled
voices) but unambiguously the synth kit in character, and keeps the album's melodic
LA sample layers (steel drums, saw lead, choir, guitar) untouched. Small, no vendored code.

## Design
- `Kit::Synth` (new enum arm, crate-private — `pub(crate) mod drums`, so no semver hit).
  Realized in `make()` by forcing `samples=false` and voicing exactly as V3 (a two-line
  shadow), so every modeled arm is shared and no `matches!` site can be missed.
  Provably identical to `make(.., Kit::V3, samples=false, ..)` = the `--no-samples` render.
- Selected by ch-10 **Program Change 24** (GM2 "Electronic" slot → our modeled synth
  kit), mirroring the existing `40 → Brush`. `24` is free: keep-V3 test only pins
  {0,8,16}; no album authors ch-9 prog 24.
- Album: `program_changes` `(CH_KIT, 0.0, 1)` → `(CH_KIT, 0.0, 24)`; rebuild `.mid`.

## Verification plan
1. `Synth == V3+no-samples` and `Synth != V3+samples` (kick/snare/crash) — drums.rs diff test.
2. engine: prog-24 selects Synth (differs from default sampled kit); keep-V3 test unchanged.
3. Album `build.py --verify` oracles green; solo-9 md5 of new render == the `--no-samples` target.
4. render-diff across all albums: ONLY Three-Sixty-One moves.
5. cargo test / clippy -D warnings / fmt.

## Implementation (done)
- `drums.rs`: `Kit::Synth` enum arm; two lines at the top of `make()` force
  `samples=false` for Synth and collapse it to V3 voicing (shared arms, byte-identical
  to `make(.., V3, samples=false)`); three `| Kit::Synth` groupings for match
  exhaustiveness. New oracle `synth_kit_is_modeled_v3_never_sampled`.
- `engine.rs`: ch-10 `match prog { 40=>Brush, 24=>Synth, _=>V3 }`. New test
  `channel_10_program_24_selects_the_synth_kit`; keep-V3 test unchanged.
- Album: `t16_three_sixty_one.py` kit label + `program_changes` `1 -> 24`; `.mid` rebuilt.
- Doc: `wrk_docs/2026.07.19 - HLD - modeled synth drum kit (ch10 PC 24).md`.

## Verification (done)
- End-to-end **byte-identical**: rebuilt T16 MIDI (PC 24) rendered with samples ON,
  soloed to ch-10 == the same notes rendered `--no-samples` (md5 `93481ed3…`). The
  album now plays exactly the modeled synth kit; melodic LA layers untouched.
- Inertness (exhaustive): proper-parse of all 114 committed album MIDIs — ch-10 uses
  only programs {0,1,16,40}; **none use 24**. The byte-naive scan's other hits were
  false positives. Code is gated on `prog==24`/`kit==Synth`, so no other album moves.
- New unit oracles pass; keep-V3 test green; `build.py --verify` all T16 oracles green;
  `cargo fmt --check` clean.
- (running) focused render-diff (baseline vs new binary, V3+Brush+drum-heavy albums);
  clippy `-D warnings` + full ferrosintesis test suite.

## Surprises
- 12-Jul kit was modeled + a **sampled attack overlay**, not pure-modeled; and every
  dependency (3 drum WAVs, dsp.rs, the overlay machinery) drifted since — so byte-exact
  restore was ruled disproportionate. Modeled path recovers ~all the character (see HLD).
- A byte-naive `0xC9 0x18` MIDI scan false-positived T10 as "PC 24"; a real MIDI parse
  (running-status aware) is required to read ch-10 program selection.
