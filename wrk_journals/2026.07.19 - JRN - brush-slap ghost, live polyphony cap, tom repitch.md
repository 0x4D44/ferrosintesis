## MM-BUG-KILN-00001 — ghost brush slap re-strike dominance

**Investigate.** Added a regression oracle `brush_slap_reexcite_tracks_velocity`
(drums.rs) measuring the second/first-contact hp_win(800Hz) ratio at velocity 30
vs 100. Baseline (pre-fix): **ghost(30)=2.336, loud(100)=1.590** — reproduces the
ledger's 2.336× exactly.

**Diagnose (root cause).** `brush_slap` calls `.with_bursts(&[(0.012, 0.50)])`.
In `Drum::render` the burst does `band.amp = band.amp.max(0.50)` — an **absolute**
level, independent of note velocity. But the first-contact noise bands are
velocity-scaled by `membrane_velocity`'s law `nf(vn) = 0.5 + 0.5·vn²`. So the
second/first energy ratio ∝ `0.50 / nf(vn)`, which **blows up as vn→0**. At vel 30
nf=0.528, so the fixed burst overpowers the shrunken first contact; at high
velocity nf→1 and the ratio is bounded — which is why the vel-100 oracle and the
frozen render never caught it. Every fact fits: fails only at low velocity, was
calibrated/frozen only at vel 100, always been this way.

**Design (minimal fix).** Scale the burst by the SAME velocity law as the noise it
re-excites. Extracted `fn noise_vel_gain(vn) = 0.5 + 0.5·vn·vn`, used by both
`membrane_velocity` (numerically identical → byte-clean for all other drums) and
`brush_slap` (`reexcite = 0.50 * noise_vel_gain(velnorm)`). Anchored so full
velocity (vn=1) keeps the calibrated 0.50 (loud end unchanged, never hotter). This
makes the second/first ratio velocity-invariant.

**Result.** ghost(30) 2.336→**1.238**, loud(100) 1.590→**1.290** — now
velocity-invariant, ghost no longer an outlier. Regression test passes;
`brush_slap_accent_and_double_contact` still green (slap 1.290 vs tap 0.376);
all 549 ferrosintesis lib tests pass. Re-froze the key-39 signature in
`brush_render_signatures_are_stable` (rms −19.795→−19.909, centroid 582.26→552.96,
late_early −35.83→−36.99 — modest, quieter/darker, expected direction).

**Verification.** Committed `7328c70`. Render-diff (baseline binary built at the
pinned base `0cc8e7f`, not `origin/main`): **1 expected change** (GM40 + key39),
**zero contamination** (exit 0) → the `noise_vel_gain` extraction is byte-clean for
every other drum. Adversarial 3-skeptic panel: diagnosis + velocity-scaling logic
confirmed 3-of-3. Skeptic 1 caught a REAL defect I'd missed — I inserted the helper
+ its `///` doc between `#[allow(clippy::type_complexity)]` and `membrane_velocity`,
so the allow bound to the trivial helper and `clippy -D warnings` broke at the
complex return type. Repaired (helper moved above the doc block) and re-ran clippy
green BEFORE committing. Parked (scratchpad): a 3rd hand-inlined copy of the same
law at drums.rs:1597 (snare-wire `d1_noise`) — byte-identical to fold into
`noise_vel_gain`, but touches the snare path so kept out of this surgical commit.
Final gate: fmt + clippy --all-targets + 549 lib tests all green.

## MM-BUG-KILN-00013 — live global polyphony cap  (design locked, impl pending)

Root cause: `EngineCore.active` is unbounded; the only steal is per-channel driven
guitar (limit 8). A dense live stream stacks un-released voices and can blow the
audio-callback deadline. Offline has no deadline and must stay byte-identical.

Design (minimal, live-only): add `pub(crate) fn enforce_voice_cap(&mut self, cap)`
to `EngineCore` (steal victims = first released voice, else oldest — released is
the "quietest" proxy since the `Voice` trait has no level query, and `active` is
push-ordered so index 0 is oldest). Call it ONLY from `RealtimeSynth::fill_ring`
(live.rs), after draining pending commands and before `render_block_add`. Offline
never calls it → goldens untouched by construction. `LIVE_MAX_VOICES` const in
live.rs.

## MM-BUG-KILN-00009 — sampled-tom repitch cap  (investigating)

Mapping (sampler.rs:3148-3153): keys 48/50 play TOM_HI (181 Hz root) at
1.619×/1.945× (~+8.4/+11.5 st) — the chipmunk/thin top-of-fill. Cheap mitigation

whether a cap is a clean win or trades one artifact for another; PARK + report if
