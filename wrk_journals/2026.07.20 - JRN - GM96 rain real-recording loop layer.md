# 2026.07.20 — JRN — GM 96 rain: real-recording loop layer

**Task:** item 4 of "do 1 and then 4" — improve the weak GM 96 (FX 1 "rain") voice using
Arthur's own 2017 rain field recording (`S4320004.mp4`, window 00:31→00:36). A Build/timbre
change, not a ledger bug.

## What the rain voice was

`Fx::from_spec(&FX_RAIN, …)`: a crystal bell (`core_gain 0.35`, a faint pitched sparkle) +
a **synthetic** wash — bandpass white noise (`noise_amp 0.20`, `noise_fc 4800`) gated by a
`GrainGate` at 380 grains/s. Arthur's verdict: "our current rain isn't very good." A
bandpass-noise model is a poor rain; a real downpour recording is far better.

## What I did — model-to-alt, applied to a timbre layer

New CC0 asset crate **`ferrosintesis-samples-rain`** holding one seamless ~4.6 s mono
16-bit/44.1 kHz loop (owner-recorded 2017, CC0; source not committed — 157 MB personal video;
`PROVENANCE.md` has the two deterministic processing steps: extract 00:31–00:36, crossfade
~0.4 s tail→head, normalise). 405764 bytes, pinned in the crate's own inventory test.

Wired like the other `-samples-*` crates: `.gitignore` allowlist, workspace member,
`ferrosintesis` optional dep + `embedded-samples` feature, `sampler::embedded_wav` chain.
New `sampler::rain_loop() -> &'static [f32]` (feature-gated `OnceLock`, decoded once).

`Fx` voice changes (`voices.rs`):
- `from_spec` gains `samples: bool, load_rain: bool`. `load_rain` is set **only** for the
  GM 96 preset (caller passes `program == 96`); the `(99,19)` alt caller passes `false,false`.
- When `samples && load_rain`: load the loop, and **mute the synthetic wash**
  (`noise_amp = 0`). The real rain *replaces* the model wash; the 0.35 crystal sparkle stays.
- Samples-**off** (or any non-96 program) loads no rain and leaves `noise_amp` at the spec
  value → the modeled synth is **byte-identical to before** (the model-to-alt discipline).
- Loop read cyclically in the per-sample post-chain, `FX_RAIN_LOOP_GAIN = 0.7`, behind an AR
  envelope (`FX_RAIN_ATK_S 0.02`, `FX_RAIN_REL_S 0.4`): short fade-in kills the onset click,
  fade-out after `note_off` lets the voice die instead of looping forever. Aliveness now
  `core_alive || echo_tail>0 || rain_alive`, so the bed sustains while the key is held (rain
  as a texture that follows key hold) and terminates cleanly on release.

Gain and envelope times are gut-feel — this box has no ears; Arthur auditions and tunes.

## Oracle

**FX-O7** (`fx_o7_rain_96_real_recording_bed`): (a) samples-on differs materially from
samples-off (2.26× steady-wash RMS diff → bed engaged); (b) the real bed is a fused wash
(gaps 0.000, crest 1.31 — no deep inter-grain gaps, no loop-seam periodic click in-window);
(c) sustains a 5 s hold, then dies within 4 s of `note_off`. FX-O5 (GM 98 crystal freeze,
bit-exact) still passes → the other seven FX presets are provably untouched.
