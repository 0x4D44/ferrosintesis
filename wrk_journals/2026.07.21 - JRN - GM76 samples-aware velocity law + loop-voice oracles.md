# 2026.07.21 — JRN — GM76 samples-aware velocity law + loop-voice oracles

Investigation of the velocity-law work's two remaining "bits" (harpsichord
MM-BUG-KILN-00030, GM76 exemption), which turned into a small cleanup Build.

## Headline

The velocity-law task was already done and well-contained. But the GM76 exemption
commit (`f7d585a`) had introduced a **confirmed latent regression**: removing
`VEL_LEVEL_EXP[76]=1.450` (correct for the self-compensating `BottleLoopVoice`)
also dropped the compensation the **modeled** Wind bottle still needs — because
`VEL_LEVEL_EXP` is program-indexed, not samples-aware. Fixed + pinned; no album
is affected (GM76 is authored by 0 of 124 committed MIDIs).

## The finding (measured, not asserted)

- `make()` early-returns without a `ScaledVoice` wrap when the exponent is 2.0, and
  removing GM76's entry set it to the table default 2.0. So the modeled GM76 renders
  its raw curve.
- Probe (throwaway modeled-only build, same `level_db`/`fit_k`/`FIT_VELS` harness as
  the oracles): modeled GM76 fits **k = 2.421 (key48), 2.555 (key60)** — off the
  square law by +0.4..+0.56. Controls GM73/GM75 (no table entry) landed 2.04/2.09,
  validating the harness. Predicted k≈2.55 from the mechanism before measuring; matched.
- Blast radius is NOT just `--no-samples`: the `76 =>` arm falls back to the model
  via `unwrap_or(model)` for any GM76 note >~1 octave from the bottle sample root
  (below ~C#5), in ANY build. Those notes rendered ~6.6 dB too quiet at v32.
- Invisible because the whole velocity sweep runs `samples=true` (HLD §5), where
  GM76 is the exempted loop.

## The fix — track the VOICE, not the flag

First attempt keyed the compensation on the `samples` flag in `make()`
(`melodic_vel_level_exp`). **The `wd_o10` routing oracle caught it**: it asserts
GM76 renders identically at C5 with samples on/off (both fall back to the bare model
there), and the flag-keyed version made them diverge — AND left the samples-on
fallback model uncompensated. The compensation must track WHICH voice was built.

Correct fix: wrap the model — and only the model — in `ScaledVoice(1.512)` inside
the `76 =>` arm. The `BottleLoopVoice` (a real recording carrying its own dynamic)
stays bare. So a C5 fallback in a samples-on build is now compensated identically to
`--no-samples`, and `wd_o10` passes naturally. GM76 keeps NO `VEL_LEVEL_EXP` entry —
the table can't express "model yes, loop no"; the comp is voice-intrinsic, like the
loop's own taper. 1.512 = census-derived midpoint of the valid range [1.379, 1.645].
