## THE PIPELINE IS PROVEN — exact chain (all four stages work)
1. **Probe:** `python tools/instrument-balance/mkprobe.py <set>` → `_cal/probe_<set>.mid` +
   `_cal/plan_<set>.tsv`. Sets: smoke(4) / preflight(12) / hot / velcurve / full(128) /

2. **ferro render:** `./target/release/ferrosintesis.exe _cal/probe_<set>.mid -o
   _cal/ferro_<set>.wav --peak-normalize -q`. **`--peak-normalize` is LOAD-BEARING** — it is
   a single LINEAR per-track scale (no nonlinear −18 LUFS limiter), so relative per-program

   non-uniformly bite hot programs and corrupt the differential.
3. **SC-55 render:** `/c/apps/mdmidiemu.exe _cal/probe_<set>.mid --wav _cal/sc55_<set>.wav
   --synth sc55 --roms /d/language/mdsc55/roms/sc55`. **ROM PATH IS THE GOTCHA** — mdmidiemu
   defaults to `roms/sc55` relative to CWD (absent here); the ROMs live in the sibling

4. **Meter:** `./target/release/examples/calmeter.exe _cal/<engine>_<set>.wav
   _cal/plan_<set>.tsv <ferro|sc55> > _cal/<engine>.levels.tsv`. Emits per-note
   `max_m` (max momentary block), `peak_block`, `clipped`, `sounded`.
   Build both: `cargo build --release -p ferrosintesis-cli` AND
   `... -p ferrosintesis-cli --example calmeter` (the `--example` flag builds ONLY the
   example; the main binary needs its own build).

### As-built note that supersedes the HLD
The HLD called the statistic **S95** (active-block 95th percentile). The as-built (calmeter.rs
doc §"The level statistic") is **max momentary block**, and it explains why: over ~9 blocks in
a 1.2 s window, nearest-rank p95 == max at n≤19, and max is correct for a single isolated
note. So "implement S95" is DONE (as max-momentary); do not re-add a percentile. (Do NOT reuse
`voices.rs::percentile` — its body returns the 2nd-largest at n=9; documented in calmeter.rs.)

### Derivation (proven on smoke; `_cal/an.py` is the throwaway prototype)
Per engine, level(p) = median over the program's notes; D_p = (ferro_p − ferro_median) −
(sc55_p − sc55_median); trim_p = round(clamp(−0.70·D_p, −6, 6)) with a 1 dB dead-band. For
percussive-family targets trim is currently 0.0, so a trims-ON render gives their raw level
directly (no CLI trim-disable flag needed). For the sustained cross-check, subtract the known
`PROGRAM_TRIM_DB[p]` to recover raw level.
