# 2026.07.22 — JRN — M-CAL certified full-128 derivation (instrumented dry run)

Follows the M-CAL v2 tooling landing on trunk (`2f2a274`). Task: run the full-128 derivation
as an **instrumented, report-only** dry run with certificates attached, per a Fable consult
that Arthur asked me to agree the next step with.

## The decision (Fable consult, verified by me before acting)

**Verdict: derive now — "timbre bugs first" is obsolete as a global ordering.** It existed
because a level pass on a broken voice is wasted work; but the v2 guard now auto-excludes the
envelope/register pathologies, and the derivation is a re-runnable pipeline, so a wasted trim
costs one probe re-run rather than a hand-audit. Its cost (deferring balance for ~115 healthy
programs behind 6 ear-gated fixes) is the whole schedule. It survives only as (a) a blocklist
for the known-6 timbre bugs and (b) strict admission to the anchor cohort — the anchor being
the ONLY coupling between programs, so one bad member contaminates every derived trim.

**Claims I verified in code before building on them** (the collaboration rule is verify by
understanding, not blind-apply):

- `BusGlue`: `thr = 0.32`, gain `(thr/env).sqrt()` (2:1), 15 ms/250 ms, plus a 95 Hz peak EQ
  that IS in the signal path (`l[i]` derives from the shelf-filtered `xl`), not just the
  sidechain. All as described.
- **The certificate identity**: above threshold the output envelope is `sqrt(thr*env)`, and
  `sqrt(thr*env) > thr <=> env > thr`. Since the envelope follower is a one-pole smoother
  toward the instantaneous peak, `env <= max|x|` — so **`max|sample| < thr` over a note proves
  the compressor never engaged**, observable from the output alone. No API knob needed.
- Saturation `y = g + 0.12*(tanh(1.4g)/1.4 - g)` expands to a relative gain `1 - 0.0784 g^2`
  = -0.070 dB at g = 0.32, -0.007 dB at g = 0.1 — an order inside the 1 dB dead-band.
- CC7 is exactly `(cc/127)^2` (`volume_target = v*v`), so a drive change is an exact
  `40*log10(c/100)` dB and, being uniform across programs, is absorbed by the anchor.

**And Fable caught a real defect in my harness**: I had metered CLI-rendered WAVs, which are
loudness-normalized to -18 LUFS. That does NOT void the earlier relative results (one constant
gain per render, absorbed by the anchor) but it makes absolute level — hence the certificate —
impossible. The fix was already in the repo: the `raw_dump` example renders pre-normalization
f32; calmeter just had to learn to read 32-bit float WAVs.

## What I built

- **calmeter**: reads 32-bit IEEE float (raw renders); emits `peak_abs` + `glue_ok` per note
  (certificate 1) and a `sampled` flag via a new `--vs <wav>` twin comparison (certificate 3).
- **raw_dump**: `--no-samples` flag, so the probe can be rendered twice.
- **derive_trims**: the glue certificate report; the **residual oracle** (certificate 2); and a
  **two-pass strict anchor** (certificate 4) — provisional frame, then admission by measurement
  quality (nonzero ear-vetted shipped trim, tilt < 3 dB, no unmetrable key, |residual| <= 2 dB),
  reporting cohort size and MAD.
- **mkprobe**: `PROBE_CC7 = 50`.

## Findings

- **Glue: the assumption was WRONG at CC7=100 — 23/128 programs (107/1536 notes) exceeded the
  ceiling**, worst 1.196 (GM127). This is exactly Fable's ">15% => the CC7-reduction path
  becomes the norm" tripwire, and it means the earlier guardcheck numbers were taken through a
  partly-compressed chain. Dropping the probe to **CC7=50** (amplitude x0.25) certifies every
  consumed program; the only survivor is GM127 Gunshot at 0.314, which is in the `never`-trim
  SoundFX family and is neither trimmed nor anchored, so it cannot reach a shipped number.
  **100% of notes still sound** after the drop (the silence floor moved by the matching 12 dB).
  No calibration API knob was needed — Codex's open precondition is closed empirically.
- **Sampled/fallback ground truth, derived by DIFF rather than by re-implementing the routing.**
  The sampler applies its repitch cutoff at three separate call sites, so a re-implementation
  would silently drift; instead the probe is rendered twice (`--no-samples`) and diffed per
  note. Result: **41 programs fully sampled, 16 MIXED, 71 fully modelled.** "Fully modelled" is
  usually fine (many GM programs have no bank — the model IS the voice); **MIXED is the real
  risk**, because different keys then measure different instruments. This independently
  confirms Codex's code-read: GM10 music box (4/12) and GM76 blown bottle (4/12) do straddle,
  as does GM15 dulcimer (11/12). Those trims are now flagged low-confidence from measurement,
  not guessed by family.
- **A real bug I found while writing the selftest**: the trim damped the TOTAL
  (`-DAMP * D_p`) rather than the CHANGE. For a program already correctly trimmed
  (residual 0) that drags its trim 30% toward zero — for GM6 (+6 dB shipped) a spurious
  -1.8 dB. Programs derived from scratch carry shipped = 0, where the two forms coincide,
  which is why it only bites the ear-vetted entries. Fixed to `shipped + DAMP * residual`,
  with the dead-band applied to the change; guarded by a selftest case.

## Result of the certified full-128 run (`_cal/derivation_v3.txt`)

All four certificates green: glue inert for every consumed program; anchor **8.13 dB over a
15-member cohort (organ/strings/reed/pipe/lead) with MAD 0.49 dB** — comfortably inside the
"single-scalar engine offset" model (the redesign tripwire was MAD > 1.5). The anchor also
cross-checks against the raw data: the global per-key ferro-SC gap in the normal register
(keys 48-85) is flat at +7.2..+9.0 dB, i.e. the anchor IS that gap.

**Headline finding — this is voice work, not trim work.** 37 programs fail the shape/short
guard, concentrated in the plucked families: **Guitar 8/8**, Percussive 6, Bass 5, Ethnic 5.
Fable verified it directly from the TSVs: GM24 nylon guitar at key 68 is **-42 dB by block 8
while the SC-55 is still at -11 dB**; GM32 bass -18 vs -9; GM112 -30 vs -13. Ferro's plucked
decays are 2-4x faster than the SC-55's. No scalar reconciles a gap that grows 30 dB over
900 ms — any fitted number is a duty-cycle artifact, which is precisely candidate-1's
wrong-sign mechanism. So the plucked families need ENVELOPE work, then a re-derive with this
same machinery.

**The addressable surface is bigger than the proposal count suggests** (Fable's framing fix,
adopted): of 123 measured programs ~57 measure clean, and ~40 of those sit inside the 1 dB
dead-band — they are *confirmed correctly balanced*, not unaddressable. So level calibration
is ~95% settled (40 confirmed + 8 corrected); the ~30 shape-fails are a voice-work backlog.

Proposed: **8 trim changes** (GM5 +1, GM8 +2, GM9 -1, GM11 +6, GM12 -1, GM14 -6, GM38 -6,
GM110 -5), plus **7 ear-vet candidates** held back by moderate tilt.

**Bass-band slope.** Keys 24-49 (the -24 transposed family) decline ~10.5 dB in the ferro-SC
gap while the normal register is flat. Fable checked the knee-free part: keys 39/44/49 have
fundamentals at 78-139 Hz where the RLB high-pass is within ~1 dB of flat, and the decline
persists (-1.8 -> -3.6 -> -6.5), so ~5 dB of it is REAL and only keys 24-34 are knee-polluted.
Do NOT re-probe the basses higher — that re-introduces candidate-1's measure-out-of-register
defect by another route, and the family fails on envelope anyway. It is a fact about ferro's
bass voices; it belongs in the voice-work notes.

**Metric vs ear conflict to settle:** the derivation wants GM0/GM1/GM3 pianos DOWN 4-6 dB,
where Arthur's earlier audition notes called GM000/001/003 "slightly quiet". Both can hold —
his ear judged them inside ferro's own mix, the metric judges them against the SC-55 — but it
is a genuine "which reference wins" question. The tilt guard already withheld all three from
auto-ship, so nothing acts on it unreviewed.

## Review (Fable, as reviewer) — adopted

- Framing fix on the addressable surface (above).
- Keep `PITCH_TILT_DB = 6` for AUTO-ship and add an **ear-vet lane** for the 6-10 dB band,
  rather than loosening: the sensitivity table shows 6->10 buys only +7 trims, and the
  residual oracle shows the metric disagreeing with vetted ears by 4-7 dB on the slow-attack
  families, so metric confidence alone does not justify shipping +-4-5 dB of register error.
- Ship 7 of the 8; **GM11 +6 first in the ear queue** (largest boost, shape_dev 9.2 near the
  12 limit). Fable projected post-trim peaks against the glue ceiling — worst is GM11 at
  0.076, 4x under — so a re-run will re-certify.
- Two tool defects fixed: the main table printed a computed `new` on FROZEN rows (invites
  reading it as a proposal — now a dash), and GM6's 9.6 dB velocity-guard failure needed
  recording (-> `scratchpad.md`, with the residual watchlist).
- CC7 reasoning independently verified: uniform per-channel `(v/127)^2` gain, so it shifts
  every g and the anchor identically and the residual is invariant; `raw_dump`'s path carries
  no other nonlinearity.

**Decisive tripwire for whoever applies the trims:** a closed-loop re-run. Apply, re-render,
re-derive; expect proposals "(none)", anchor 8.13 +-0.1, MAD <= 1.0, glue all-inert. Any
proposal on a just-trimmed program is a sign/linearity bug.

## Second reference: the S-YXG50 panel (Arthur's steer)

Arthur made the load-bearing point that SC-55 matching is only ONE axis — internal
self-consistency is another — and asked for the S-YXG50 as a second reference (explicitly not
the MU80, which is broken). He also ruled: ONE table as the compromise, not one per axis.

**Agreed, and one table is the stronger position anyway.** If two tables were genuinely
needed that would be evidence the calibration is wrong, not that there are two right answers:
the gap between "what foreign files expect" and "what our albums want" is made of reference
quirks plus real ferro defects, and fixing those converges the axes. Two tables would
institutionalise the disagreement and freeze the defects in.

**The second reference is better than the internal axis I had proposed.** My internal axis is
self-referential — blind to common-mode error, and "median over 128 programs" is not a musical
truth. Two independent references convert an INFERENCE into a MEASUREMENT: for the piano I had
to infer the SC-55 was the outlier (because ferro sits at its own median); with Yamaha I can
decide it 2-to-1. Internal balance drops to a third, weaker signal — still valuable for
defects the panel cannot see (GM7 clavinet sits 18.3 dB below ferro's own median; the bass
family spans 20.9 dB internally vs the SC-55's 8.9).

**New gate:** target = panel CONSENSUS; auto-ship only where the two references agree within
`PANEL_AGREE_DB = 3.0` and both sets of guards are clean. The measured distribution splits
cleanly there — agreeing programs land at 0.2-1.3 dB, disagreeing ones at 5-10 dB, nothing in
between.

**It immediately paid for itself.** Auto-ship fell from 8 to 5. Withheld: **GM11 vibraphone,
where the references split 10.8 dB (SC-55 +6, S-YXG50 -2)** — single-reference evidence would
have shipped a 6 dB boost on the patch Fable had already flagged as riskiest — and GM38 synth
bass (9.2 dB split), GM9, GM12.

Applied (all agreed within 0.3-2.9 dB): GM5 +1, GM8 +2, GM14 -6, GM110 -5, GM119 +1.

**I had to correct myself on the piano.** With only the SC-55 I told Arthur his ear was
vindicated. The S-YXG50 ALSO places its piano below its own median (-3.4 to -6.6 vs the
SC-55's -8.9), so "piano below the 128-program median" is a shared GM-era convention, not
purely a Roland quirk — and for GM1 the two references agree to **0.01 dB** that ferro is ~7 dB
hot. What still stands for Arthur: ferro's pianos sit at ferro's own median, every piano is
pitch-tilt excluded on BOTH references (so a single number is unreliable for them anyway), and
"median over 128 programs" is not what he was judging — he judged the piano against its FRA
neighbours. So no piano is trimmed, and the conflict is unresolved rather than settled. The
FRA A/B render is the next evidence.

**Scope oracle updated deliberately, not weakened.** `program_trim_scope_and_calibration`
pins that the trim table leaves struck/plucked voices untouched — it correctly caught that the
5 panel entries widen that scope. Rather than relax the assertion I widened the contract
explicitly (the panel-admitted set is enumerated, its values are pinned with the agreement
that admitted them, and GM11 is pinned at 0.0 with the reason), so nothing else can still be
trimmed silently.

## Arthur's ruling on the pianos, and what it exposed

**Decision (2026.07.22):** ferro's pianos stay at ferro's median; both modules are wrong here.
That is his call to make — ears are the final authority and the panel only sets the default —
and it is a defensible one: the acoustic grand is the most-played program in GM, a 4-6 dB cut
on module authority alone is a bad trade, and all three pianos are pitch-tilt excluded on BOTH
references, so no single number was reliable for them anyway.

**What it exposed:** a trim of `0.0` was ambiguous — it could mean "nobody has looked at this"
or "someone listened and ruled 0.0 is right". The residual oracle only watched programs with a
NONZERO trim, so his ruling would have gone unmonitored, and worse, a future panel run where
the references happened to agree would have silently auto-shipped a piano cut and overturned
it. Fixed by making recorded decisions first-class:

- `EAR_DECIDED = {0, 1, 3, 11}` in `derive_trims.py`, with the reason for each.
- The residual oracle now treats a recorded 0.0 as ear-vetted and watches it.
- A recorded decision **blocks auto-ship** regardless of panel agreement.
- The report gains a HELD section that still prints what the panel WOULD have said
  (GM1 -5, GM3 -4), so the disagreement stays visible instead of being buried.
- The engine-side scope oracle pins GM0/1/3/11 at 0.0 with the same reasoning, so the
  decision is guarded from the code side too.

That is the ear-anchored-override half of the "one table" design working as intended: the
panel is the default, ear judgments outrank it, and every override is recorded, guarded, and
permanently monitored for drift.
