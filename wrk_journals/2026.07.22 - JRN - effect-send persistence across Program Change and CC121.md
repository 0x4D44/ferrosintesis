# 2026.07.22 — JRN — effect-send persistence across Program Change and CC121 (MM-BUG-KILN-00033)

## What the bug was

Effect send levels are persistent **channel** state. GM / MMA RP-015 keeps CC91/93/94
across a Program Change, and Reset-All-Controllers does not reset them at all.
ferrosintesis violated this in two places in `crates/ferrosintesis/src/engine.rs`:

1. `program_change` unconditionally overwrote `chorus_send`/`delay_send` from
   `fx_profile(prog, bank)` **and cleared** `chorus_authored`/`delay_authored`. So a file
   that authored CC93/CC94 and then changed program mid-song silently lost its sends.
   The inconsistency was already visible in the code: the CC0 **bank** arm guards on the
   same two flags; Program Change did not.
2. `reset_all_controllers` (CC121) reset the sends via `rederive_program_defaults`, and
   reset several other things RP-015 explicitly preserves.

## What I changed

**Program Change** — the program's `fx_profile` is now a *default* that fills an
UNauthored send only, exactly mirroring the CC0 bank arm. The authored flags are no
longer cleared.

**CC121** — brought in line with RP-015's actual (short) reset list. Stopped resetting:

| field | controller | why it must survive |
|---|---|---|
| `chorus_send` / `delay_send` (+ flags) | CC93 / CC94 | effects levels are outside the RAC set |
| `bend_range` | RPN 0,0 value | RAC nulls the RPN *selector*, not what it wrote |
| `fine` | RPN 0,1 value | same |
| `porta_time` | CC5 | only the CC65 *switch* resets; the TIME is setup state |
| `vowel_*` | CC70 | CC70-79 sound controllers are preserved |
| `res`, `res_target` | CC71 | same |
| `wah*`, `cutoff*` | CC74 | same — and the filters that realise the value must survive with it |

Two consequences that are easy to miss and worth calling out:

- **`bend` must reset to `s.fine`, not `1.0`.** The old `s.bend = 1.0` was only correct
  because `s.fine` was illegally clobbered on the next line. Now that fine tuning
  survives, centre *is* `fine`. The active-voice loop's `set_pitch(1.0)` became
  `set_pitch(bend)` for the same reason.
- The choir re-vowel at the end of the function applied `vowel_at(0.0)`; it now applies
  `vowel_at(vowel_cur)`, since the vowel controller is preserved.

`rederive_program_defaults` lost its send-resetting half; what remains is a drive-insert
rebuild, so it was renamed `rederive_program_drive`. CC121 changes neither program nor
bank, so that rebuild only returns the insert's internal sag/filter memory to spawn
state — historical behaviour, deliberately kept.

Deliberately **not** changed, though RP-015 does not enumerate them either: `legato`
(CC68), `breath_*` (CC2), `expr_authored`, `mod_authored`. These reset to neutral values
and an independent spec audit classified them as defensible internal state rather than
violations. `expr_authored` in particular is *not* inert — the cathedral-organ reed-rasp
swell reads it (`engine.rs`, `ORGAN_SWELL_KNEE`) — so flipping it would have been an
audio change with no spec mandate behind it. Out of scope.

## The test that failed, and why it was the interesting part

`gm22_cc1_is_harmonica_vibrato_not_leslie` broke on the `reset` case:

    GM reset leaked CC1 into GM22: AM 0.00->6.00, spread 3.11

It looked like my change had leaked modulation through CC121. It had not. The test's own
setup authors **CC93=0** to kill chorus for a clean measurement — and the old engine was
silently discarding that the moment the sequence hit its Program Change, restoring
chorus 0.20. With the fix, the setup finally does what its author intended.

I measured against the right control instead of guessing:

    plain_am 0.00->6.00   reset_am 0.00->6.00   plain_spread 3.11   reset_spread 3.11

Identical. The post-reset channel behaves *exactly* like a GM22 that never received CC1.
The 6 Hz AM is GM22's own delayed-onset harmonica vibrato; the previously-restored chorus
wash had been suppressing the envelope detector, so the absolute bound
`reset_late <= reset_early + 2.0` had been passing for the wrong reason.

So the oracle was measuring the harmonica's voice, not a Leslie leak. I replaced the
absolute bound with a comparison against the never-modulated control — which is
**stricter**, not weaker: the old form would accept a reset signal that differed from
plain as long as its AM stayed under a threshold; the new one pins reset *to* the
un-modulated voice.

This is the `lessons_learnt.md` "canary in a golden fixture" failure mode again: an
absolute threshold that holds only because of an unrelated masking signal.

Every one of the ten was predicted by the pre-implementation census, and **every
non-diff is explained too** — which is the part worth recording, because five files
carry the clobbering pattern and did *not* move:

- `ferrosintesis_reference` **01-04** author 36/43/32/40 Program Changes onto a channel
  with authored sends — but each PC is followed **48 ticks later** by a re-authored
  CC93/CC94, with **zero note-ons in the gap**. The send differs only across a sliver of
  silence, so the render is byte-identical. (06 moves for the CC121 reason, not this one.)
- `ferrosintesis_reference` **05 - Kit Roll-Call** has 2 never-re-authored PCs with 29
  note-ons in the gap, yet is identical: it authors `CC93=0`/`CC94=0` on **ch9**, and the
  drum default is also `(0.0, 0.0)`. Preserving 0.0 and re-deriving 0.0 agree, and ch9
  never feeds the legacy/cathedral organ buses, so the surviving flags are inert there.

Note the report labels all ten as "CONTAMINATION". That is an artifact of the harness,
not a finding: `render_diff.py` classifies by *touched GM program / drum key*, and this
change is not a voice change, so with no `--program`/`--key` declared everything that
moves lands in that bucket. The census was the prediction; the inventory confirmed it.
**Zero unexplained diffs.**

## Album impact — the part that needs an ear

A census of every committed MIDI for the exact pattern the fix changes (a Program Change
or CC121 landing on a channel that has already authored CC93/CC94) found **four album
tracks**. All four change only on the **echo/delay** bus: none of them contains a single
CC93, so the chorus delta is exactly zero.

| track | change |
|---|---|
| Big Weather 01 - First Light Freeway | ch2 lead guitar: echo send 0.30 → 0.00 from 3:02.9 to 3:55.2 (52 s) |
| Big Weather 03 - Run the Rooftops | ch2 lead guitar: 0.30 → 0.00 from 3:09.1 to 4:25.7 (77 s) |
| Big Weather 05 - Static & Sparks | ch2 lead guitar: 0.30 → 0.00 from 0:15.0 to the end (3 m 34 s, ~93% of the track) |
| The Signal Fire 01 | ch14 violin +3.9 dB echo (5:27.6→8:18.2), flute/whistle −2.9 dB (8:25.4→16:16.6); ch2 glockenspiel +5.3 dB (12:35.0→15:49.0) |

The direction is worth noting: in all three Big Weather tracks the composer **ramps CC94
down to zero** and the Program Change was silently restoring 0.30 a fraction of a second
later. Static & Sparks is the starkest — the ramp completes at 0:14.91 and the PC lands at
0:15.00, 0.09 s later. So the fix *honours* authored intent the engine had been undoing.

That is an argument for the change, not a proof it sounds better. These albums were
composed and auditioned against the current engine, so the artistic result of three frozen
fable5 tracks changes. **This box has no ears** — that call is Arthur's, and integration
is held pending it.

No album contains a CC121 at all (0 events across all 124 album MIDIs), so the entire
Reset-All-Controllers half of this fix cannot affect any album render. Its only in-repo
reach is `demos/ferrosintesis_reference/06 - Controllers and Effects.mid` (19 CC121
events on ch0) — a demo whose job is exactly to exercise controllers.

## Gotcha for whoever runs the next render-diff here

`render-catalog`'s `ALBUMS` table includes the two **demo** directories
(`demos/synth_feature_showcase`, `demos/ferrosintesis_reference`), so a catalogue-wide
diff is never "albums only". An adversarial verifier caught me about to report a
four-file expected set when the real expected set is four album tracks plus most of the
eleven demo tracks. Anyone reading the inventory without knowing that will see a wall of
apparently-unexplained diffs.
