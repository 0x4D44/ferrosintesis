# 2026.07.24 — JRN — GM 32–35 bass regression: the LA seam mutes the model it replaces

Task: Arthur A/B'd a *Tubular Bells (Part One)* render at HEAD against one made
2026-07-19 07:07 and reported the bass guitar was "better — and louder" on the old one.
Investigate, then (his call, same session) restore it.

## What it was

Not a preset drift. The `BASS` / `PICK` `PluckPreset` constants are numerically
IDENTICAL between the 19 July baseline `196e552` and HEAD — the only textual delta on
`BASS` is an added `damper_hold: DamperHold::Off`.

The cause was `dbef98a` (2026-07-20), which made the LA sampled onset the **default**
bank for GM 32/33/34/35. `LaVoice::render` is a **sum-to-one crossfade, not an additive
layer**:

```rust
let u = smooth((t - fade_start) / fade_len);    // 0 until fade.0, 1 at fade.1
let mut s = self.buf[i] * u;                    // the MODEL, faded IN
s += v * (1.0 - u) * self.gain * self.rel_gain; // the SAMPLE, faded OUT
```

With `LA_EBASS = (0.42, (0.05, 0.35))` the modeled bass is **fully muted for the first
50 ms** and only sole owner at **350 ms** — while the flat wrap gain sits the sampled
onset ~15–18 dB UNDER the model it displaces. Sum-to-one means nothing fills the gap.

The killer is the interaction with real material: this part's **median bass note is
146 ms and 90% of its notes are shorter than the 350 ms handover**, so the model never
speaks. `BASS`'s `kick: 3.9` low thump (`KICK_T60_S` 75 ms) fires entirely inside the
muted window and is erased.

## Measuring it — what worked, and one trap

**The trap: the CLI always normalises.** Default is −18 LUFS integrated; `--peak-normalize`
is peak-to-−1 dBFS. Neither gives raw audio, so a naive RMS comparison of two renders
measures nothing about level. Recovery: run `--peak-normalize` *without* `-q` (verbose is
the default; there is no `-v` flag — passing one just prints usage) and read the printed
`peak P`; the written wav is `raw * 0.891 / P`, so rescale by `P / 0.891` before comparing.

**What made it tractable was a synthetic probe, not the song.** A generated MIDI of
GM33/34 single notes over keys E1..D3 × vel 32..127 isolates the voice completely and
renders in seconds. Crucially I built it **twice** — once with 1.5 s notes, once with
146 ms notes (the song's measured median). That comparison is what exposed the real
defect size:

| GM33 @ vel 64 | 1.5 s notes | 146 ms notes |
|---|---|---|
| total loss vs baseline | −7.7 dB | **−18.2 dB** |
| …the LA sample layer | −4.5 dB | −14.8 dB |
| …the k=2 velocity law | −3.2 dB | −3.4 dB |

A sustained-note probe **flatters a crossfaded sample layer by an order of magnitude**,
because the model gets to full level and dominates the average. Had I only run the first
probe I would have called this a 4 dB annoyance.

**The velocity split was the discriminator.** Binning the delta by velocity separates the
two causes without any code change: the LA layer's loss is FLAT across velocity (a gain
change), the velocity law's grows as velocity falls (−0.4 dB at v127 → −7.6 dB at v32).
GM34 corroborated it — it has no `VEL_LEVEL_EXP` entry (2.0) where GM33 has 2.320, and
its velocity-dependent component was correspondingly smaller.

**`--no-samples` is a free ablation.** HEAD with `--no-samples` lands within 1.4–3.0 dB of
the baseline in EVERY band, which isolates the sample layer as the cause with no build.
For GM32 and GM35 it restores the baseline raw peak *exactly*.

## Why no oracle caught it

`la_level_continuity` lists fiddle, flute, piano, brass, reeds, guitars, harpsichord,
dulcimer, strings, cello, contrabass — **no bass program at all**. It also measures
continuity between adjacent windows, not parity against the model, so a *uniform*
under-level passes even with a bass row present. The two oracles that do test parity
(`la_steel_high_key_level_parity`, `la_strings_seam_level_parity`) cover GM25 and GM48/49
only. `LA_EBASS` / `LA_PIZZBASS` are commented "Ear-tunable" and were never calibrated.

Same defect class as **KILN-00046** (GM48/49 strings, fixed the previous day) with the
sign reversed: there the sample sat +1..+6 dB *over* the model, here ~15–18 dB *under*.
A fix that lands as "tune this per-program constant by ear" leaves the next program in the
family unguarded — the oracle is what generalises, not the taper.

## Aggravating factor found on the way

`finger_bass` covers E1–D2 (6 zones), `pick_bass` E1–E2 (7), but **68% of this part's bass
notes play above the top zone**. `LaVoice::build`'s guard admits `step` in `0.5..=2.05`
(≈ +13.8 semitones at 48 kHz), so onsets are repitched up to **+12 semitones**; the 2.7%
that exceed it fall back to the **full-level bare model**, so level jumps note to note.
That guard's `44100.0/sr` factor also makes eligibility rate-dependent — already filed as
KILN-00061.

## What shipped

Arthur's call: option 1 — restore the modeled bass as the DEFAULT for GM 32–35 and move
the sampled onset to the CC0!=0 alt (`voices::bass_la_alt`). The seam mismatch itself is
NOT fixed, only moved off the default path; it is filed as **KILN-00075** with the
KILN-00046-style taper + oracle as the suggested fix.

Two implementation notes worth keeping:

- The `VEL_LEVEL_EXP` correction had to be factored out of `make` into
  `apply_vel_correction` so `bass_la_alt` applies the identical law. Skipping that would
  have made the alt bank a differently-*scaled* instrument rather than a different timbre.
- The alt bank had to route through `bass_la_alt`, not `make(.., true)`. `make` no longer
  wraps 32–35 at all, so the generic fall-through would have silently handed the alt bank
  the default model and made the LA layer unreachable — exactly the trap the GM 7 and
  GM 109 arms already document in comments.

**A test-helper trap cost a cycle:** `render_make` in `altbank.rs`'s test module
**hardcodes bank=1**. It reads like a default-bank helper and is not one. My first re-pin
of `altbank_sampled_programs_preserve_pure_model_and_default_layers` used it for the
"default" side and failed with a message accusing the default bank of being sampled — when
it was rendering the alt bank. The default side has to come from `voices::make` directly.
The silver lining: that accident proved half (a) of the oracle is non-vacuous.
