# 2026.07.24 — JRN — KILN-00075: the bass seam, and the window that hid it

Fourth bug of the fixing pass, and the first one that came from Arthur's ears rather than
a code review. He A/B'd a Tubular Bells render against a 19 July one and said the bass was
quieter and worse. He had already shipped the mitigation (LA bass off the default bank);
what remained was the seam mismatch itself.

## The mistake I made first, because it is the instructive part

I copied the measurement window from KILN-00046, the GM48/49 string-seam fix — the
obvious, precedented thing to do. It measures the wrapped/model RMS ratio over the
crossfade span, `[0.05, 0.35]` s here.

Measured that way this bug reads **−2 to −5 dB**. The report said 15–18 dB. I nearly
fitted a taper 10 dB short.

The reason is structural. `LaVoice`'s crossfade is **sum-to-one**, and the model is muted
outright until `fade.0`:

```
output = model*u + sample*(1-u)*gain      u = 0 before fade.0, 1 at fade.1
```

So `[0, 50 ms]` is the only window where the wrap gain *is* the output level. Across the
fade span the model term progressively takes over, and the gain barely moves it — by
`fade.1` the ratio is exactly 1.0 by construction, no matter how wrong the gain is.
Measuring the span therefore averages the defect together with the region the knob cannot
affect.

Decomposing the window made it obvious:

| window | geomean | worst |
|---|---|---|
| `[0, 50 ms]` sample-owned | **0.389 (−8.2 dB)** | −19 dB |
| `[50, 150]` | 0.480 (−6.4 dB) | |
| `[150, 350]` | 0.746 (−2.5 dB) | |

**The lesson generalises past this bug: fit a knob on the window where that knob is the
whole story.** The precedent's window was right for the precedent — the strings mismatch
really did live across its fade — and wrong here, because the two crossfades mute
differently. Inheriting a metric with the technique is how you get a confidently wrong
number. This is a cousin of the existing lesson "a metric whose lowest band sits ABOVE what
you changed reads your fix as a no-op — check its support first."

The printer now prints all three windows plus the peak ratio, precisely so the next person
to touch this sees the trap instead of stepping in it.

## Where a scalar ran out

Fitted on the sample-owned window, GM33/34/35 land at parity (1.002 / 0.998 / 0.997).
GM32 does not: it reaches onset parity and then runs **+6 to +10 dB OVER** the model
through `[50, 350]`.

That is not a fitting error. The real pizzicato contrabass recording rings on while
`Pluck(&UPRIGHT)`'s deliberately short `t60` has already decayed — a decay-**shape**
mismatch, and the same mechanism KILN-00045 documents for UPRIGHT. One scalar multiplies
the whole curve; it cannot change its slope. Buying GM32 onset parity would have shipped
the KILN-00046 defect with the sign flipped.

So GM32 alone is fitted on the whole handover, leaving its onset ~3.7 dB under. That is
the smallest residual a gain can leave, and I said so rather than hiding it in an average.

## Peak, not just level

An RMS match is not a peak match when the sample and the model have different crest
factors. A level-only oracle would happily license a taper that restores RMS by shipping a
transient spike, so the oracle bounds both. Measured peak ratio 0.80 geomean / 1.40 max,
and the largest absolute peak (2.55 at GM33 key 34 vel 120) sits against a model already
peaking at 2.16 there — the same regime, not a new one.

## Two things I did not do, and did not pretend to

**"Add bass rows to `la_level_continuity`."** Not possible as written: that helper routes
through `voices::make`, which since Arthur's reversal returns the *bare model* for GM
32–35 — the LA bass lives on the alt bank. Rows there would exercise no wrap and pass
vacuously. That is exactly the silently-shrinking-oracle failure KILN-00059/00060/00069
shared, so adding them would have been worse than nothing. Reaching it needs
`assert_wrap_seam` generalised to take a constructor, a refactor of a helper three tests
share.

**Items 3 and 4 — the crossfade shape and the banks' repitch reach.** Split to
MM-BUG-KILN-00085. The 50 ms mute still erases the `BASS` preset's 75 ms `kick` thump, the
350 ms handover still outlasts 90% of a bass line's notes, and the banks still repitch up
to +12 semitones. None of those is a gain, and all are listening calls on a part Arthur has
already reversed once.

**So this does not clear the LA bass to return to the default bank**, and I left that
instruction standing in both entries. Fixing the gain is not fixing the shape.

## Method note for the next four bugs

Four passes in, the pattern holds and has now taken a second form. Passes 1–3 found the
*reported scope* too narrow (a copied guard, a shared code path, a crash count that missed
silent wraps). This one found the *inherited metric* wrong. Same root discipline: do not
take the previous fix's enumeration — or its measurement — on faith just because it was
right last time.
