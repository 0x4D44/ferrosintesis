# 2026.07.24 — JRN — mallet bus-echo send (GM 8/9/10)

## What prompted it

Arthur, listening to `test-corpus/reference-midi/mike-oldfield/01-tubular-bells-part-one.mid`:
the glockenspiel entry early on has "a strange echoy shimmer". Is it intentional, or ours?

It was ours, and it was intentional — which is why it took measuring to settle.

## Diagnosis

The file asks for nothing. On the glockenspiel channel (ch 1, GM 9, first note at
6.200 s) the transcription authors **no CC93, no CC94**, and no CC91 until beat 775.
A bare program change and notes.

The effect came from `fx_profile` in `crates/ferrosintesis/src/engine.rs`, which gave
GM 8–10 an unauthored echo send of **0.15** into the ping-pong bus. Three facts had to
line up for it to sound wrong here:

1. **The echo time is tempo-derived** — a dotted quaver at the opening tempo
   (`crates/ferrosintesis-cli/src/main.rs`, clamped 0.20–0.62 s). This file opens at
   150 bpm, so **300 ms**.
2. **The line is a metronomic quaver ostinato** — every glockenspiel onset is exactly
   200 ms apart, all at velocity 64. A dotted quaver is 1.5 slots, so every repeat lands
   dead on the off-beat, carrying the wrong pitch for its position.
3. **Nothing else in the opening is echoed.** Piano (GM 0) and bass (GM 33) profile to
   `(0.0, 0.0)`; the reed and attack organs (GM 20/17) take chorus but no echo. GM 9 was
   the only voice in a different space.

Together: a ghost line a beat-and-a-half behind the tune, ping-ponged hard L/R and
darkened by the bus's 3.2 kHz one-pole. That is the shimmer.

## Evidence (measured — this box has no ears)

Glockenspiel soloed, first 60 s, rendered four ways:

| render | side/mid energy |
|---|---|
| fully dry (`--delay 0 --wet 0`) | 0.000 — perfectly mono |
| reverb only (`--delay 0`) | 0.033 |
| default | **0.092** |

The echo bus is the *only* thing making the glockenspiel stereo. Cross-correlating the
stereo side signal against the dry render peaks at **0.299 s (r = 0.86)**, with the
repeat train at 0.501 / 0.700 / 0.900 / 1.100 s.

Inside the ostinato the echo is only about −21 dB against the programme and lifts the
off-beats by ~0.14 dB — it is spatial detection, not loudness, which is exactly why it
reads as "strange" rather than as an obvious delay. On an **isolated** strike it is
unmissable: at 0.55 s the left channel sits **14 dB above** the natural decay, and L−R
swings +20.7 dB (left) at 0.55 s then −10.5 dB (right) at 0.75 s.

## The change

Arthur's call: trace for the neighbours, nothing for the glockenspiel.

```rust
8 | 10 => (0.0, 0.06), // celesta / music box: a trace of slap
9  => (0.0, 0.0),      // glockenspiel: brightest and fastest — no bus echo
```

Rationale for the split: celesta and music box are *sprinkled*, so a repeat lands in an
empty slot and reads as space. The glockenspiel is the brightest of the three and gets
*run* in fast lines, where the same repeat becomes a competing voice.

## Oracle

`engine::tests::mallet_bus_echo_is_off_for_glockenspiel_and_a_trace_for_its_neighbours`.

Deliberately **derived, not a constant pin**. The send scales a linear bus, so the echo's
energy is exactly proportional to it. Each voice is rendered twice — echo bus on, echo bus
off, `wet: 0.0` — and the difference is the bus echo and nothing else. GM 9's difference
must be bit-zero. GM 8 and GM 10 are then rendered a *second* time authoring CC94 = 19
(0.1496, the retired default), and the unauthored render must sit at 0.06/0.1496 of it.
Editing either number silently moves the ratio and fails the test.

Calibrated against the old code: with `8..=10 => (0.0, 0.15)` restored, the oracle fails
on the first assertion (GM 9 difference rms 9.978e-4 against a 1e-9 bound).

## Validation

- `cargo test -p ferrosintesis --release` — 667 passed, 0 failed (plus 4 doc-tests).
- `cargo clippy --workspace --all-targets -- -D warnings` — clean.
- Direct proof the symptom is gone: with the new binary the glockenspiel stem's DEFAULT
  render is **byte-identical** to the old binary's `--delay 0` render (`cmp`, both the
  60 s ostinato stem and the isolated-strike probe). The echo is fully off and nothing
  else about the voice moved. Side/mid drops 0.092 → 0.033; the isolated strike's L−R
  swing collapses from +20.7/−10.5 dB to the ±1–6 dB the reverb alone produces.

### Render-diff inventory

All 141 catalog MIDIs (`albums/` + `demos/`) rendered with both binaries and `cmp`'d;
baseline built at `2b38cc3`. **52 DIFF, 89 SAME, 0 unexpected diffs.**

The first-cut expected set was 61 — every MIDI that issues a Program Change to GM 8/9/10
on a non-drum channel. That over-approximates, and the 9-file gap is fully explained by
two mechanisms, both correct:

- **2 files never sound the program.** `The Burning Meridian/02 - Lanterns on the Water`
  (ch 8) and `gpt5-3-spark/11 - Chamber of Witness` (ch 6) issue the program change but
  play no note under it, so the send never reaches audio.
- **7 files AUTHOR CC94**, so the program default is never applied at all — the
  MM-BUG-KILN-00033 rule that an authored send survives a Program Change. Four gpt5-6
  tracks and both demos author CC94 at tick 0 (the reference demo authors CC94 = 0, the
  dry discipline from the 2026.07.12 audition HLD §3.5). `The Signal Fire/01` is the
  interesting one: it authors CC94 from tick 14400 and only reaches PROG 9 at tick
  590400, so `delay_authored` has been latched for the whole piece by then.

So the reachable set is exactly the 52 that moved. Nothing outside it changed.
