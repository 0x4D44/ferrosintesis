# 2026.07.26 — Bounded-memory offline rendering

## Objective

Replace the shipping offline buffer-first path with scratch-backed streaming so track
duration no longer multiplies RAM use, while retaining current audio and atomic output
semantics.

## Confirmed diagnosis

The buffered loudness phase holds about 40 bytes per stereo frame across the original
render, normalization clone, de-interleaved channels, and filtered `f64` channels. A
60-minute 44.1 kHz track therefore needs about 5.9 GiB before smaller caches. The live
11.025 kHz render of the same hour track peaked at 1.55 GiB against a 1.51 GiB
track-buffer prediction. This is bounded whole-track storage, not an unbounded leak.

## Decisions

- Preserve buffered public APIs.
- Preserve the limiter/dither operation order with disk-backed passes.
- Stream both default loudness and legacy peak CLI modes.
- Make the new high-level library render atomic and return `io::Result<Stats>`.
- Reject output beyond classic RIFF's 32-bit limit before synthesis; RF64 is out of scope.
- Re-sum streaming BS.1770 windows in the existing forward `f64` order.
- Measure true peak after `f32` scalar multiplication; do not branch on raw peak times
  gain.
- Do not bump versions on the task branch.

## Design review

Two independent reviewers completed and refuted each other's findings once. Surviving
corrections were RIFF preflight, an explicit atomic public API contract, and exact
BS.1770 accumulation order. The raw-peak shortcut was unverified from the draft, so the
design now explicitly forbids it. Findings about the bounded energy table, duplicated
engine invariants, prescribed randomized/fault-injection mechanics, and adaptive worker
limits did not survive refutation.

A third replacement review was started only because the original audio reviewer ignored
two bounded-return requests. The original later returned; the replacement did not run
mutual refutation, so its output is unverified and not counted.

The one Claude Opus review completed. It challenged whether retaining the 1.2 GiB
hour-track render buffer would be sufficient; that conflicts with Arthur's confirmed
write/read/write goal and was rejected. Useful findings were folded in: quantify the
16-byte-per-frame disk budget; move catalog scratch beside the Opus destination; specify
seek/read/flush/sync behavior; cover repeated normalization/limiter passes and degenerate
lengths; fix RIFF sizing in the old writer too; and use a sealed normalization type.

The design is now `Status: SELF-APPROVED`. Residual risks are heavy disk I/O on
pathological high-crest inputs and identifiable scratch orphans after hard process
termination.

## Implemented units

### Streaming numerical meters

`crates/ferrosintesis/src/loudness.rs` now has bounded incremental BS.1770 and
true-peak meters. The loudness meter retains the current independent forward `f64`
sum for every overlapping 400 ms window; the true-peak meter retains the causal
12-sample history and exact FIR operation order. Differential tests split a composite
signal across irregular one-to-1024-frame chunks and require bit-identical results from
both old and streaming meters.

### Streaming render blocks and incremental WAV output

`crates/ferrosintesis/src/engine.rs` now shares one event/render loop between the
published buffered renderer and an internal 64-frame sink. A differential test requires
the streamed samples and `Stats` to equal the buffered result exactly. The dither RNG is
now a persistent small state object so later disk chunks retain the current sample order.

`crates/ferrosintesis/src/wav.rs` now validates classic RIFF limits before creating the
file and writes PCM through a fixed 4096-sample byte buffer. Split incremental writes are
byte-identical to the published one-shot writer. Tests also cover odd/oversized counts
and declared-count underflow/overflow.
