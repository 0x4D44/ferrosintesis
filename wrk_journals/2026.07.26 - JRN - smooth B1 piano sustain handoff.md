# Smooth B1 piano sustain handoff

## 2026-07-26 — diagnosis and design

Arthur asked to replace the Yamaha B1 default piano's unnatural sustain shimmer
with the first alternate VSCO piano's better handoff mechanism.

Confirmed:

- Both banks use the same acoustic-piano model, CC64 handling, and felt-damper curve.
- VSCO's PCM is envelope-conditioned at bake time and uses the ordinary 180–450 ms
  complementary sample-to-model crossfade.
- B1 PCM is independently peak-normalised and uses a special runtime path: sample
  polarity inversion, early modeled overlap, 20 ms adaptive power/correlation
  compensation, and frozen crossfade weights on key-up.
- The special path fixed a measured dip/rebound but is the leading cause of the
  synthetic shimmer. Natural unison beating in individual B1 recordings may remain.

Design scope and acceptance criteria are in
`wrk_docs/2026.07.26 - HLD - smooth B1 piano sustain handoff.md`.

## 2026-07-26 — adversarial design review

Three independent reviewers covered conditioner math, runtime/audio behavior, and
reproducibility, then each refuted the combined finding set. All eight findings
survived all three checks; none was Critical.

The important correction is that the existing VSCO conditioner is not sufficient:
it rejects five actual B1 zones, becomes a constant gain before the handoff, and
cannot repair the B1's faster decay or changing negative phase correlation. The
design now uses a bounded B1 envelope through 450 ms and makes static-handoff
feasibility a measured implementation point. It will stop rather than restore
adaptive runtime gain if no static solution passes.

The review also found an existing reproducibility defect: `_bake_b1upright` accepts
the assigned retired soft pass. The implementation will reject anything other than
the exact 25-normal/27-hard inventory before writing.

## 2026-07-26 — external design review

One read-only Claude Opus pass found a Critical acceptance-test loophole: retiring
the B1 sample earlier would improve the modulation metric while erasing the recorded
piano identity. The design now pins both established fade windows and guards the old
first-180-ms waveform correlation and K-weighted level.

Useful Major findings also added a frozen pre-deletion baseline, independent layer
conditioning plus K-weighted seam calibration, high-entropy model seeds, separate
tail-gain and hiss bounds, and an output inventory derived from the clean committed
bank. The suggested calibration-enum rename was rejected as unrelated churn; B1
still needs its own calibration policy.

The one targeted critical-item re-review found that a sparse level fixture could
miss per-take attenuation and that signed waveform correlation contradicted an
allowed static polarity flip. The final identity guard covers all 52 zones and uses
absolute normalized correlation. The design is SELF-APPROVED; no unresolved
Critical finding remains.

## 2026-07-26 — implementation feasibility fork

The first static implementation removed the B1-only adaptive/frozen runtime path and
routed B1 through the ordinary sum-to-one piano wrapper. The bake now rejects the
retired soft layer and any inventory other than 25 normal plus 27 hard zones before
writing. It derives a smooth, bounded offline tail gain from the acoustic model's
expected power across randomized phases. Positive gain is reduced per zone when
needed to preserve 0.9 peak headroom; the first 180 ms remains sample-identical.

The proposed 3–4.5 Hz Tubular Bells metric was invalid. The pinned excerpt contains
140 note-ons in its first 35 seconds at exactly 250 ms intervals, so its 4 Hz peak is
authored articulation rather than an isolated shimmer measure. The misleading Rust
oracle and analysis script were removed before commit.

The raw B1 re-bake completed with the new inventory, identity, headroom, late-peak,
tail-gain, and high-frequency-energy guards. The ordinary runtime handoff then failed
the existing macro-envelope oracle at MIDI key 21, velocity 50, seed `0x13579BDF`:
3.09 dB rebound versus 0.52 dB in the bare model, above the 1.50 dB limit. The prior
adaptive implementation measured 3.40 dB on the same case, so offline conditioning
improved but did not solve it.

This is the design's declared architectural stop. A B1-only static constant-power
law is the smallest next experiment, but it is no longer an exact copy of the VSCO
alternate's sum-to-one mechanism. No alternate law has been implemented pending
Arthur's choice.

## 2026-07-27 — constant-power experiment

The first-stop oracle improved from the ordinary law's 3.09 dB rebound at key 21 to

code remains uncommitted for inspection and has not been treated as a solution.

## 2026-07-27 — human audition rejects the short conditioned handoff

Arthur found that the shimmer was gone but the hammer action sounded cut off and
the result no longer resembled a real piano. The numerical pass therefore did not
meet the musical acceptance criterion; commit `edcd116` must not integrate as the
solution.

Direct asset comparison explains the complaint. Relative to the exact-parent B1
at its corresponding runtime gain, the new conditioner changes median zone RMS by
+1.40 dB at 30–40 ms, +5.45 dB at 40–50 ms, +7.16 dB at 50–60 ms, and +10.93 dB
at 60–75 ms. The runtime simultaneously fades that raised recording to zero by
75 ms. It preserves the literal first 30 ms but compresses and removes the longer
string/soundboard response that makes the hammer sound physical.

A read-only Fable 5 partner consult independently diagnosed the same architectural
problem. It recommended making the recording the whole samples-on B1 voice, with a
late same-recording continuation rather than a generic randomized model. Its
preferred final candidate is a long loop plus measured decay; phase-continuous
offline additive continuation is the fallback if loops freeze the beating.

Verification refined that advice: the archival slicer retains up to eight seconds
per note, but the present baker truncates to 1.5 seconds and applies a 600 ms fade
over the end. A loop experiment must use the archival body before that fade, not
search the already-tapered 0.9–1.5 second region.

Arthur authorised the first causal experiment: remove both conditioner and model,
retain the existing 1.5-second asset size with only a 10 ms terminal taper, and
audition the B1 recording as the whole samples-on voice. This is intentionally not
a shippable sustain path; long held notes expose the asset boundary. The design and
acceptance criteria are in
`wrk_docs/2026.07.27 - HLD - B1 recorded-body sample-only experiment.md`.

The adversarial design review found that a normal engine render is not a true
sample-only oracle: every acoustic piano still feeds the engine's synthetic
sympathetic comb bank. Both reviewers retained that finding after refutation.
The corrected experiment therefore judges a direct/dry three-stage ladder first
(archival slice, baked root WAV, dry sample voice), then uses Tubular Bells only as
the musical-context audition.

Other surviving review findings now pin a common unbent 0-1.0 second body window,
first-30-ms parity through the requantized/new voice path, fixed-gain renders without
per-file loudness normalization, and separate held-body, terminal-boundary, and
note-off/damper judgments. The inference is deliberately narrower: a poor dry result
implicates the retained capture-to-playback chain, not automatically the microphone
capture. Root-table and CC68 concerns were refuted because the tables do not change
and neither old nor proposed acoustic voice supports legato reuse. No critical
finding remains after adding the direct control.

The one external Claude design review found three more blocking defects in the
written criteria rather than the architecture. First, the parent's 30 ms identity
window is measured in source position; repitched notes traverse it in a different
amount of output time. Second, raw archival, baked, and runtime rungs were not
level-comparable. Third, a seed-invariance test could accidentally choose xorshift
seeds that barely move the parent.

The design now bounds parity by source read position, peak-aligns and reports each
direct stage's pure scalar before fixed-gain audition, and requires the seed pair to
prove parent sensitivity before child identity. It also names the direct renderer
as a deliberately ignored test-only path that bypasses `EngineCore`, `BusGlue`, all
sends, and normalization. The localization claim now admits that committed Opus
decode and channel-L selection are common-mode and cannot diagnose the original
recording without an off-repo pre-Opus master. An intermediate repitch control,
catalogue-wide exact-parent diff, and no-default-features check were added.

The one targeted re-review passed the level-aligned direct ladder and found two
remaining edge conditions. The parity window must bound cubic interpolation's
furthest `floor(position) + 2` read, not just nominal source position. Seed
calibration also needs a quantitative floor, not merely non-identity. The final
criteria use the cubic support bound and require at least 5% normalized RMS
difference over the model-owned 100-500 ms window before the experimental outputs
must become bit-identical. No critical design defect remains; the targeted
re-review allowance is exhausted.
