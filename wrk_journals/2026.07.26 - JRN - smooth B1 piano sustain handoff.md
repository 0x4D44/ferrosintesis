# Smooth B1 piano sustain handoff

## 2026-07-26 — diagnosis and design

Arthur asked to replace the Yamaha B1 default piano's unnatural sustain shimmer
with the first alternate VSCO piano's better handoff mechanism.

Confirmed:

- Both banks use the same acoustic-piano model, CC64 handling, and felt-damper curve.
- VSCO's PCM is envelope-conditioned at bake time and uses the ordinary 180–450 ms
  complementary sample-to-model crossfade.
- B1 PCM is independently peak-normalised and uses a special runtime path: sample
  polarity inversion, early modeled overlap, 20 ms adaptive power/correlation
  compensation, and frozen crossfade weights on key-up.
- The special path fixed a measured dip/rebound but is the leading cause of the
  synthetic shimmer. Natural unison beating in individual B1 recordings may remain.

Design scope and acceptance criteria are in
`wrk_docs/2026.07.26 - HLD - smooth B1 piano sustain handoff.md`.

## 2026-07-26 — adversarial design review

Three independent reviewers covered conditioner math, runtime/audio behavior, and
reproducibility, then each refuted the combined finding set. All eight findings
survived all three checks; none was Critical.

The important correction is that the existing VSCO conditioner is not sufficient:
it rejects five actual B1 zones, becomes a constant gain before the handoff, and
cannot repair the B1's faster decay or changing negative phase correlation. The
design now uses a bounded B1 envelope through 450 ms and makes static-handoff
feasibility a measured implementation point. It will stop rather than restore
adaptive runtime gain if no static solution passes.

The review also found an existing reproducibility defect: `_bake_b1upright` accepts
the assigned retired soft pass. The implementation will reject anything other than
the exact 25-normal/27-hard inventory before writing.

## 2026-07-26 — external design review

One read-only Claude Opus pass found a Critical acceptance-test loophole: retiring
the B1 sample earlier would improve the modulation metric while erasing the recorded
piano identity. The design now pins both established fade windows and guards the old
first-180-ms waveform correlation and K-weighted level.

Useful Major findings also added a frozen pre-deletion baseline, independent layer
conditioning plus K-weighted seam calibration, high-entropy model seeds, separate
tail-gain and hiss bounds, and an output inventory derived from the clean committed
bank. The suggested calibration-enum rename was rejected as unrelated churn; B1
still needs its own calibration policy.

The one targeted critical-item re-review found that a sparse level fixture could
miss per-take attenuation and that signed waveform correlation contradicted an
allowed static polarity flip. The final identity guard covers all 52 zones and uses
absolute normalized correlation. The design is SELF-APPROVED; no unresolved
Critical finding remains.

## 2026-07-26 — implementation feasibility fork

The first static implementation removed the B1-only adaptive/frozen runtime path and
routed B1 through the ordinary sum-to-one piano wrapper. The bake now rejects the
retired soft layer and any inventory other than 25 normal plus 27 hard zones before
writing. It derives a smooth, bounded offline tail gain from the acoustic model's
expected power across randomized phases. Positive gain is reduced per zone when
needed to preserve 0.9 peak headroom; the first 180 ms remains sample-identical.

The proposed 3–4.5 Hz Tubular Bells metric was invalid. The pinned excerpt contains
140 note-ons in its first 35 seconds at exactly 250 ms intervals, so its 4 Hz peak is
authored articulation rather than an isolated shimmer measure. The misleading Rust
oracle and analysis script were removed before commit.

The raw B1 re-bake completed with the new inventory, identity, headroom, late-peak,
tail-gain, and high-frequency-energy guards. The ordinary runtime handoff then failed
the existing macro-envelope oracle at MIDI key 21, velocity 50, seed `0x13579BDF`:
3.09 dB rebound versus 0.52 dB in the bare model, above the 1.50 dB limit. The prior
adaptive implementation measured 3.40 dB on the same case, so offline conditioning
improved but did not solve it.

This is the design's declared architectural stop. A B1-only static constant-power
law is the smallest next experiment, but it is no longer an exact copy of the VSCO
alternate's sum-to-one mechanism. No alternate law has been implemented pending
Arthur's choice.

## 2026-07-27 — constant-power experiment

Arthur authorised the narrow B1-only constant-power experiment. The implementation
used fixed sine/cosine weights over the existing fade windows. It retained the same
conditioned PCM, gain, damper, release, and model, and introduced no signal
measurement or adaptive gain.

The first-stop oracle improved from the ordinary law's 3.09 dB rebound at key 21 to
a later 2.19 dB failure at key 30, but that was misleadingly optimistic. The test
was changed to finish all 1,408 key/velocity/seed cases and report the global worst.
It found key 94, velocity 59, seed `0x6A09E667`: 9.78 dB rebound versus -2.22 dB
model-only, 8.28 dB over the permitted limit. Its 50 ms RMS sequence was
`[0.09283, 0.06343, 0.01287, 0.01012, 0.02666, 0.03119, ...]`.

The static constant-power law therefore creates a severe treble trough and swell;
it is not shippable. Both approved static mechanisms are now exhausted. Continuing
would require relaxing the recorded-identity/fade constraint, redesigning moving
runtime control, or changing the sustain model. The experimental constant-power
code remains uncommitted for inspection and has not been treated as a solution.

## 2026-07-27 — authorised short static handoff

Arthur authorised relaxing the first-180-ms constraint while preserving the first
100 ms recorded hammer. The ordinary VSCO sum-to-one law was retried with shorter
windows. A 100–250 ms handoff failed by 7.08 dB at key 80; 100–180 ms reduced the
global miss to 0.72 dB at key 102; 100–150 ms passed the full 1,408-case sweep.

The constant-power experiment and all associated state were deleted. The final
B1 uses the ordinary release wrapper with fixed gain 1.30 and fade `(0.10, 0.15)`.
A structural oracle independently reconstructs those literal values and matches
production sample-for-sample through hold and note-off.

The offline tail conditioner was also deleted. It started after 180 ms, when the
new runtime handoff has already made the sample inaudible, so retaining it would
change 52 source assets for no audible purpose. A raw re-bake restored every WAV
to the task parent's bytes. A second complete bake produced the same 52 SHA-256
hashes and the stricter pre-write inventory guard rejected the retired soft layer.

Focused evidence is green:

- the exact-inventory Python unit test;
- the literal static-handoff equality test;
- all 1,408 rebound cases; and
- note-off at 100, 312.5, and 550 ms across velocities 59/60.

## 2026-07-27 — critical implementation review

The independent code review found that the rebound test's 50 ms scan began at
150 ms, immediately after the new 100–150 ms seam. The reported 1,408-case pass
therefore proved only the post-handoff model, not the handoff. This was a Blocker.
The reviewer also found that 125 ms was missing from the release probes and that
the inventory unit test checked only layer counts, not exact generated names.

The release test now includes 125 ms. Exact generated-versus-committed inventory
comparison is a testable helper, with missing, extra, retired, and same-count
substitution cases. Both focused tests pass.

The rebound oracle now uses 25 ms windows beginning at 100 ms. It invalidated all
tested static endpoints that preserve sample-only ownership through 100 ms:

- 100–125 ms: key 22, velocity 100, seed `0x13579BDF` was 4.77 dB over limit;
- 100–150 ms: key 99, velocity 100, seed `0x6A09E667` was 10.05 dB over limit;
- 100–250 ms: key 92, velocity 100, seed `0x6A09E667` was 12.56 dB over limit.

At 100 ms the treble recording can already be several times quieter than the
modeled sustain. A later endpoint only spreads that level step; it cannot remove
it. The build is paused at a new architectural fork: either permit the static
handoff to begin before 100 ms, or permit static/offline level shaping within the
protected 100 ms. No targeted re-review ran because the Blocker cannot be resolved
without Arthur choosing which identity premise may move.

## 2026-07-27 — authorised 50 ms timing calibration

Arthur authorised a static per-register handoff beginning at 50 ms. The ordinary
50–150 ms window failed the seam-inclusive sweep at key 91, velocity 60, seed
`0x6A09E667`: 10.24 dB rebound, 8.74 dB over the model-relative allowance.
Note-off exactly at the 50 ms seam also rose 2.26 dB, above the 1.5 dB release bar.

A diagnostic treble-only 20–100 ms window still failed by 7.23 dB at key 87.
Shortening that treble seam to 20–50 ms moved the global failure to the unchanged
50–150 ms midrange: key 67 missed by 6.08 dB. The earlier treble diagnostic exceeded
Arthur's 50 ms boundary and was reverted; it is evidence only.

Fade timing alone is exhausted down to the authorised 50 ms hammer boundary.
The remaining static option is bounded level shaping during the seam, after the
hammer transient, so sample and model owners meet at comparable energy. The other
options are model phase alignment/decorrelation or a new signal-dependent control.
No targeted re-review ran because the critical finding remains unresolved.

## 2026-07-27 — static conditioner resolves the handoff

Arthur authorised the remaining changes needed to finish. A deterministic offline
conditioner now keeps the first 30 ms waveform unchanged, raises the recorded body
smoothly from 30 ms, fits the 50–75 ms handoff against the acoustic model's expected
modal power, and relaxes by 125 ms. The bank is stored at 0.25 scale and restored
with fixed runtime gain 5.20, preserving the previous audible hammer gain
(`0.25 × 5.20 = 1.30`) while leaving enough PCM headroom for static shaping.

The corrected 1,408-case oracle passes. Its worst render is MIDI key 24, velocity
60, seed `0x9E3779B9`: the wrapped and model-only signals both rebound 3.07 dB, so
the B1 adds no rebound and remains 0.50 dB inside the model-relative allowance.

The one targeted implementation re-review resolved the critical seam exclusion,
exact-inventory coverage, and conditioner coverage. It found one remaining Issue:
the release test began at the 50 ms boundary rather than strictly before the seam.
A 40 ms note-off initially appeared to rise, but comparison with an identical held
voice showed the rise was the normal ownership transfer, not a key-up effect. The
final oracle probes 40, 50, 62.5, 75, 100, 312.5, and 550 ms across keys 60/91 and
velocities 59/60. Every released window stays below its held control; from the seam
onward the worst absolute rise is 1.39 dB, under the 1.5 dB cap.

The bake validates the exact committed 25-normal/27-hard filename set before any
write. Unit tests cover missing, retired extra, and same-count substituted names.
A second full bake reproduced all 52 SHA-256 hashes exactly. The full 84-test
Python suite, Rust workspace tests, clippy with warnings denied, formatting, and
the Rust 1.87 workspace check are green.

The samples-on perceptual-class control formerly used GM0 as a “no vibrato” wrong
class. With the B1's natural recorded beating exposed by the static handoff, that
premise is no longer true. GM8 celesta now serves as the intended stable
no-vibrato control; its measured `fm_depth` is 0.0005 against the bowed floor 0.1.
