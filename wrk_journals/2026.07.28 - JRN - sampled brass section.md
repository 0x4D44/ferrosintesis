# Sampled brass section

## 2026-07-28 — scope and evidence

Arthur rejected the modeled GM 61 candidate because it still sounds synthetic
and authorized the sampled-section route.

The exact MuseScore MS Basic source already pinned by
`tools/ferrosintesis-samples/prepare.py` contains a dedicated bank-0 preset 61.
Its ten sample zones have distinct offsets from the soundfont's trumpet,
trombone, horn, and tuba presets. The zone roots span MIDI 41-84 and therefore
cover the useful brass-section register without relying on a solo instrument.

The implementation will use the repository's established `LaVoice` replacement
handover: sample attack and early body, then the existing modeled GM 61 sustain.
No new source, dependency, feature flag, or public API is needed. GM 56-60,
GM 62/63, alternate-bank brass, and modeled-only builds remain outside the
audible blast radius.

The current bug ledger is **Blocked** after the modeled candidate passed its
engineering checks but failed Arthur's listening judgment. This build will move
MM-BUG-KILN-00038 only to **Fixed** after regression and render-diff evidence;
independent listening remains the closure gate.

## 2026-07-28 — adversarial design review

Three bounded reviewers independently examined routing, the sample pipeline,
and oracle adequacy, then each performed one refutation pass across the combined
findings.

The important correction was source-duration math. A one-second zone consumed
at the LA wrapper's accepted 2.05x upward ratio can end in under 0.5 seconds.
The design now retains 1.2 seconds, caps the handover at 0.42 seconds, and
requires every engaging key to prove that its actual source lasts through the
fade.

The review also exposed a latent mismatch in `LaVoice::legato_to`: its comment
says a slur retires the transient and glides the model, but the blend clock can
leave the model suppressed while the sample releases. The design corrects that
shared invariant and pins early/mid/late slurs.

Other surviving items strengthen direct bank isolation, ten-zone/root binding,
fine-window seam checks, samples-off base parity, public documentation, and a
bank-aware census over the exact render catalog. No unresolved critical finding
or architectural fork remains.

## 2026-07-28 — cross-family design review

The required single Claude Opus review ran read-only without subagents. It
confirmed the architecture and found three important omissions.

First, GM61's current velocity correction was measured on the pure model. The
sampled composite needs its own measurement, while no-samples and out-of-range
fallbacks need an explicit `modeled_vel_level_exp(61)` preserving the old law.

Second, the generic SF3 onset baker names outputs by root. Duplicate-root stereo
or velocity zones could overwrite each other while a set-based inventory still
reported ten files. The brass recipe now asserts the exact ten unique roots and
mono sample type before writing.

Third, the shared legato correction expands the potential render blast radius
beyond GM61. The catalog census must therefore include early CC68 slurs on all
LA-wrapped programs. The handover itself must stay sum-to-one; an abrupt model
promotion could replace the dropout with a level step or overlap bump.

Useful additions cover short staccato notes, the exact bake fade budget,
scientific-pitch filenames, public hand-maintained surfaces, and the superseded
ledger decision. A speculative per-key gain table was rejected: exhaustive seam
measurements will decide whether a single scalar is sufficient.

## 2026-07-28 — implementation and calibration

The SF3 guard first failed on source type 17. That is the expected SF3 encoding:
mono type 1 plus the Vorbis-compressed bit 0x10. The validator now checks the
channel-type nibble, accepting compressed mono while still rejecting linked or
stereo zones.

The pinned preset baked ten 1.208-second mono WAVs at 44.1 kHz. Measured roots
were 87.28, 130.93, 185.54, 234.59, 262.50, 350.88, 441.64, 524.46, 700.31,
and 1049.46 Hz. Every root is within 12 cents of nominal. The exact filenames
run from `brasssection_F2.wav` through `brasssection_C6.wav`; package and runtime
oracles bind both the ten-file inventory and measured root table.

GM61 now owns the recorded ensemble through 120 ms and crossfades to its model
by 420 ms at gain 0.45. The source-duration oracle proves every note inside the
wrapper's 0.5-2.05x repitch window reaches the handover endpoint before PCM
dry-out. Alternate banks and runtime sample opt-out remain byte-identical pure
model routes.

The shared LA slur path now uses a smooth transient-handover weight:
sample weight falls as model weight rises. It no longer exponentially releases
the sample while leaving the replacement model suppressed. An early-20 ms GM61
slur has no 10 ms dropout, and staccato key-up probes at 110, 130, 410, and
430 ms stay below the fine-window step bound.

The sampled composite's raw velocity exponents measured 2.552 at key 48 and
2.673 at key 60. The census-derived correction is therefore 1.387. The model-only
route retains its prior 1.380 correction. Both the all-program square-law oracle
and the runtime sample-opt-out oracle pass.

The worktree now contains 1,156 WAVs / 110.8 MiB, up from the base tree's
1,146 WAVs / 109.8 MiB. The README's existing 1,156 / approximately 111 MiB
inventory is therefore accurate after this addition.

## 2026-07-28 — code review and simplicity pass

The single independent code-review pass found two actionable defects. The slur
handover length was initially derived from each wrapper's note-off T60. Piano
dampers can last seconds, so that coupling could leave an old-pitch transient
audible far too long if a long-release wrapper ever accepts legato. Slurs now
use one bounded 60 ms handover independent of note-off damping. The regression
changes pitch twice during that handover and verifies the tail reaches the new
pitch without a level gap.

The source-duration oracle also counted the 200 ms baked fade-out as usable PCM.
It now subtracts that fade before proving the worst eligible repitch reaches the
420 ms runtime handover endpoint.

The simplicity pass removed an out-of-scope retrigger behavior change, keeps the
non-slur render path bit-identical, does not restart an in-progress handover on a
second rapid slur, and drops the handover state after the normal fade endpoint.
No new dependency, feature flag, public API, or per-key gain table remains.
