# B1 regeneration preserves tail validation

MM-BUG-KILN-00169 found that the B1 crate advertised the whole-file sample
generator even though its Rust library contains a handwritten natural-tail
oracle. Following that marker deleted the oracle, while the safe region updater
did not refresh either aggregate byte pin.

The B1 library now marks only its generated inventory and points at
`regen_samples_table.py`. That updater refreshes `FILE_COUNT` and
`EXPECTED_BYTES`; when `EXPECTED_TAIL_BYTES` is present, it first validates every
WAV's single terminal `b1t ` chunk against the same version, divisor, reserved
field, entry-frame, and payload-length contract enforced by Rust. It then reports
and refreshes the tail aggregate without rewriting the bespoke test module.

Fail-before evidence: the focused Python regression refreshed the sample name but
left `EXPECTED_BYTES` at its stale value of 1. Pass-after evidence:

- the focused regression refreshed 1 → 34 total bytes and retained the complete
  synthetic `b1_tail` assertion block;
- the real 52-file refresh reported 10,271,480 → 10,271,480 total bytes and
  3,351,922 → 3,351,922 tail bytes;
- all 129 `test_prepare` tests passed;
- both `ferrosintesis-samples-b1-upright` Rust tests passed;
- `cargo fmt --all --check` passed.
