# Steinway stale output inventory

MM-BUG-KILN-00166 showed that `prepare.py --only=steinwayb` could retain a WAV
whose physical source-table entry had been removed. The direct-source writer
used `STEINWAYB_SOURCES` without first validating that family’s packaged output.

The regression removes one physical entry from `STEINWAYB_SOURCES`, leaves that
WAV in a temporary packaged output, and proves the rebake fails before fetching,
reading, or writing. `main()` now validates `("steinwayb", STEINWAYB_SOURCES)`
before using the table, and the Rust source oracle requires that exact pair.

Fail-before: the test reached `read_wav` instead of raising the expected stale
output `ValueError`. Pass-after: 4 focused Steinway Python tests, all 22 Rust
inventory tests, formatting, and focused clippy pass.
