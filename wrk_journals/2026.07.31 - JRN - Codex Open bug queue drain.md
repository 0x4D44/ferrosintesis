# 2026.07.31 — Open bug queue drain

## MM-BUG-CRUCIBLE-00008 — catalog MIDI overlap oracle

The old oracle paired note timestamps inside each `MTrk`. It therefore missed
cross-track overlaps, same-tick on-before-off ordering, and overlaps when note
counts differed. Three adversarial controls reproduced those false negatives;
the existing balanced repeated-note control stayed clean.

A file-wide ordered lifecycle audit exposed a second cause in the committed
catalog. The copied album writers clamped simultaneous starts to zero-length
notes. Serialization then placed the off before both ons, leaving an orphan
off/on pair and making later re-strikes ambiguous. All 22 writer copies now
collapse simultaneous duplicate starts before clamping distinct re-strikes.
Regeneration removed 111 zero-tick note-on/off pairs from 26 committed MIDIs.
The only other MIDI event changes were three synchronized Burning Meridian
comment metadata updates already present in its generator source.

Every affected album was rebuilt before verification. All available composition
oracles passed. `cargo test -p render-catalog --test album_midi_overlaps` then
passed all four controls plus the full committed catalog.
