## Worth remembering

**A throwaway scratch test that PANICS on success is the cheapest way to ask "what
actually happens?"** The report inferred that a later Set-Tempo silently wins. With
the rejection reverted I added a temporary test that parses a two-tempo file and
panics with the note's frame number either way. It printed `note frame =
Some(26460)` — 0.600 s, the second tempo, where the documented first tempo would
have given 22050. One throwaway test turned an inference into a number, and it was
deleted with the rest of the revert.

Corollary from the same experiment: check the struct field names before writing the
scratch test — mine referenced `len_frames` where `Loop` exposes `frames`, and the
compile error cost a whole build cycle.
