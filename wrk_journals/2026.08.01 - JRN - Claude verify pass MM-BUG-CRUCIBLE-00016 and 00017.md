## Worth remembering

**When a fix rewrites a whole function, splice the new TESTS onto the old CODE.**
00017 rewrote most of `Loop::parse`, so reverting the commit would have taken the
six new regressions with it. Instead I took `35ccafa^:crates/amp-lab/src/seq.rs`,
spliced the new test block in at a stable anchor comment, and ran that. The
terminal-`0xFF` case then panicked with `index out of bounds: the len is 24 but the
index is 24` — the reported crash, reproduced rather than reasoned about. A ~15-line
Python splice does what a git revert cannot.

**Don't start a background `cargo test` and then edit the same crate.** My revert
build died on `LINK : fatal error LNK1104: cannot open file amp_lab-….exe` because
the background run still held the test binary. On Windows the linker cannot replace
a running executable. Either wait for the background job (`TaskOutput` blocks) or
keep the experiment in a different crate.
