# 2026.08.17 — JRN — code-review pass over `crates/ferrosintesis-cli/`

Read-only review pass. Area assigned: `crates/ferrosintesis-cli/`. No source touched, app not
run, no build executed.

## What I did

Read the whole crate first — 1,330 lines across ten files — rather than sampling, because at
that size a full read is cheaper than deciding what to skip. Then fanned out four agents:
three refuters, each briefed to *defeat* a specific batch of candidate findings and to
default to "refuted" when uncertain, plus a standing devil's advocate on packaging, MSRV and
test quality. Everything reported survived that pass; four candidates did not and are
recorded in the CR report with the reason.

## Decisions and why

**Read the whole crate instead of running `deep-review`.** The skill costs 15–37 agents and
is sized for a diff or a subsystem. For 1,330 lines already in context, the marginal value
was in *attacking* my findings, not in re-finding them — so the budget went to refuters.

**Checked prior bug records before writing anything up.** That turned the pass's best finding
from a duplicate into a residual. MM-BUG-KILN-00120 fixed the Windows identity probe's
*output* side and closed on the reasoning that the blast radius was narrow because "ordinary
players and editors share read". That reasoning inverts on the *input* side, where the guard
is opened with `share_mode(0)` — read sharing is precisely what collides. Without reading
00120 I would have filed a duplicate or, worse, dismissed the finding on its author's own
argument.

**Grouped three CLI-convention defects into one bug (00297).** `--help` to stderr, no
`--version`, and unknown flags becoming the input path are three symptoms of one missing
concept: the arg loop has no help-vs-error distinction and no unknown-flag arm. One small
pass fixes all three. Kept the alias-check path-loss (00298) separate — different root, one
line of fix, independently landable.

**Filed the weak oracle as a bug rather than a report note.** `the_cli_help_text_states_the_
real_defaults` passes on a doc-comment with every default attached to the wrong flag, and
never reads the help text at all. CLAUDE.md says to mint a bug for an assertion that no
longer proves anything, and this one is in the module whose entire purpose is stopping that
class of drift.

**One Draft req, not four.** Resisted turning findings 2 and 3 into a "give the CLI a real
argument layer" requirement — that would duplicate two bugs that each already carry a
concrete fix. The req captures the one thing no bug covers: nothing derives the *documented*
flag set from the loop, and it has already drifted (`--out`, `--quiet`, `-h`, `--help`
undocumented in the README table).

**The devil's advocate earned its seat, and it ran last.** I had already written the report
when it landed with three findings none of the refuters or I had reached — the missing CLI
`NOTICE`, the gate never running the example tests, and the byte-rate assertion that can only
agree with itself. All three are about checks *around* the code rather than the code, which
is the blind spot a lens briefed on "what did everyone miss" is for. I re-verified each
myself before filing (directory listing, `licensing.rs`'s predicate, `.deltic-integrate.toml`
lines 53-72, and counting WAV header offsets by hand for the byte-rate one) rather than
filing on its say-so — and that mattered: it also claimed renaming a function in
`calmeter.rs` would go unnoticed, which I could not confirm, since the gate does pass
`--all-targets` to clippy. I recorded that sub-claim as unmeasured in the bug instead of
repeating it as fact.

**Left MM-BUG-KILN-00300 explicitly needing a human.** Whether attribution must travel inside
the CLI *package* is a licensing judgement, not an engineering one. The bug says so in the
Fix section so the autonomous fix loop does not invent an answer and ship it.

## Surprises

The library's `Options` doc-comment explicitly delegates the clamp-reporting duty to the
caller — `engine.rs:1760-1761`, "The accessors report the clamped value, so a caller that
cares can see what it actually got." The CLI never calls a single accessor. The contract was
written down and then not honoured by its own shipping consumer; that is a sharper framing of
bug 00296 than "the CLI should warn".

Similarly, `error.rs:172` asserts `"song.mid: no such file"` under the comment "Display keeps
the path, which is what the CLI prints". Inserting the alias check ahead of `offline::load`
made that comment false without touching the test — the CLI simply stopped reaching the code
the test describes. A green test can go stale by having its *caller* move.

## Dead ends

Chased whether the library's scratch files could clobber something beside the output. They
cannot — `create_new(true)` at `scratch.rs:463`, with sequence-bump-on-collision. Also chased
loudness-target drift between the CLI and `render-catalog`; already pinned by
`the_loudness_target_is_stated_consistently`. Both are recorded in the CR report so the next
pass does not re-chase them.

## Limits of this pass

Nothing here was reproduced by executing the binary — this pass does not run the app, and
every bug says so. The Windows sharing-violation finding (00294) rests on the documented
`CreateFile` sharing rule and on statement order in `output.rs`/`main.rs`, not on an observed
failure. My attempt to probe the sharing semantics directly was blocked by the sandbox, so it
stays labelled as inference. Reproduce before fixing.

Two other things the sandbox stopped me measuring, both recorded as unverified rather than
quietly asserted: `cargo +1.87 check -p ferrosintesis-cli --all-targets` (so the MSRV
conclusion is read-based), and whether clippy's `--all-targets` type-checks the
`#[cfg(test)]` block inside an example. The 16-vs-21 test counts in 00301 *are* measured.
