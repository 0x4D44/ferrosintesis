## How it went

The assigned area is tiny — one 117-line `lib.rs`, three documents, 13 FLAC files — so the
interesting question was never "is this crate wrong" but "what does this crate assume, and
who checks it". Three fan-out lenses (bake path, consumer binding, devil's advocate) plus
lead verification. Every finding that survived is wider than the crate.

## The thing worth remembering

**Shell scripting was denied for most of the session** — no `python -c`, no heredocs, no
PowerShell scripts, no loops. Plain single commands (`od`, `grep`, `ls`, `git log`) were
allowed. That nearly cost the pass its only hard measurements.

The workaround was to batch 13 separate `od -A n -t x1 -j 8 -N 34 <file>` calls in one
message and parse FLAC STREAMINFO by hand. That produced the three facts the pass turned
on:

- all 13 assets are 44.1 kHz / mono / 16-bit and **exactly 40042 frames** — an identical
  decoded length, which is what keeps the "aggregate byte sum cannot detect a swap" problem
  alive after the WAV→FLAC migration;
- 13 distinct STREAMINFO MD5s, so nothing is duplicated today;
- every file embeds `Lavf62.12.101` twice in a VORBIS_COMMENT block — which is
  `MM-BUG-CRUCIBLE-00039` in its entirety, and would never have been found by reading Rust.

Reading committed bytes beat reading code here. Worth doing early on any asset-crate review
rather than trusting labels — which is the standing 2026.07.23 lesson, hit again.

## Dead ends, recorded so they are not re-run

Two hypotheses looked strong and both died, in the good way:

1. *"The FLAC migration silently dropped the bass bank out of the onset-continuity sweep,
   disarming the regression guard for closed MM-BUG-CRUCIBLE-00021."* The old per-bank test
   really is gone, and `MM-BUG-KILN-00240` really did report exactly this. But
   `test_prepare.py:1077` now filters on `PACKAGED_EXT` and `read_wav` dispatches on `fLaC`
   magic. Fixed, not closed.
2. *"`test_prepare.py` is not gated."* `MM-BUG-KILN-00062`'s note says so and is stale —
   `.deltic-integrate.toml:59,71` run it.

Both cost ~10 minutes each and both were worth it: the first is how I noticed that three
Open bugs (`-00239`, `-00240`, `-00241`) raised on 2026-08-16 were substantially fixed by
`82ccd84a` and `55298fb1` on 2026-08-17 without being closed. The fix loop will rediscover
that. `-00240` is genuinely only half done — the stale gong PROVENANCE reference and the
missing per-format anti-vacuity floor both stand.

## Judgement calls

**Filed four bugs, no reqs.** The two prevention-debt findings (roots have no derivation
link to the audio; a payload swap is undetectable) are already `MM-REQ-KILN-00211`, so
capturing them again would have been duplication. What I filed instead is the narrow,
one-line half that req did not spot: the crate's payload assertion is a tautology
(`MM-BUG-CRUCIBLE-00040`). That is a test-quality defect in shipped code, which CLAUDE.md
says to ticket, not a design question for Gate 1.

I did note in the report that REQ-00211's Notes are now factually stale ("13 WAVs, 80,128
bytes each") and — more usefully — that FLAC STREAMINFO already carries a per-payload MD5
that `ferrosintesis-flac` verifies on load, so a good part of what that req asks for is
nearly free now. Its `heavy` Flow deserves a re-read on that basis. I could not update the
req itself; this pass writes only new files.

**Did not file** the `PROVENANCE.md` "E1–D#2" wording or the dead `.gitignore:89` line.
Both are defensible as written and the report carries them.
