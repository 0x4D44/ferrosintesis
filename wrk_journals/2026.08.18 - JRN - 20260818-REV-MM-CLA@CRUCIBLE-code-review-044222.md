# 2026.08.18 — JRN — code-review pass on `crates/ferrosintesis-samples-bottle/`

Read-only review pass. Area assigned by deltic: `crates/ferrosintesis-samples-bottle/` —
a 4-file crate (`Cargo.toml`, `src/lib.rs` at 91 lines, `README.md`, `PROVENANCE.md`) plus
one bank file, `samples/bottleloop_G3.flac`.

## How the pass went

The area is tiny, so the interesting surface was never the code volume — it was the crate's
**contract with everything around it**: the key its `get()` publishes, the container its docs
claim, the generator that should own its `lib.rs`, and the `.gitignore` rule that decides
whether a stray bake artifact is committable. Fanned out two lenses (a sibling-crate census
and a standing devil's advocate) and verified every returned claim against the files myself
before reporting. Both fan-outs paid for themselves; the census in particular *corrected* my
initial framing.

## Decisions and surprises

**The census refuted my first read.** I opened with "bottle is the straggler" on the stale
`.wav` rustdoc. The census showed 12 of 23 migrated crates carry the same stale wording and 11
have been reworded — so bottle is in a cluster, not alone. That reframing was the useful part:
cross-referencing the cluster against the filed bugs showed a 12-bug crate-by-crate sweep had
covered 8 of the 12 and **missed four** (`-bottle`, `-core`, `-clavinet`, `-drumkit2`). The
reportable defect was the gap in the sweep, not the single crate.

**Root cause found, which changed the recommended fix.** `tools/ferrosintesis-samples/gen_crate_lib.py`
is the generator for every sample crate's `lib.rs` and already emits the correct wording
(`:150`), a `FILE_COUNT`-bound array length (`:139`) and a generator header (`:120`). Bottle's
`lib.rs` is hand-written from 2026.07.20 and has none of them — it is the only crate of 24
whose array length is a literal. So the fix is regeneration, not another prose edit, and the
durable fix is a parity oracle. Only 11 crates carry the generator header, so most of the
cohort is un-regenerated.

**Devil's advocate found the one thing the surface review would have missed.** No sample-crate
test compares the embedded bytes to the packaged file — `get(name) == Some(bytes)` is a
tautology over the same array. A swapped `include_bytes!` argument passes every oracle, and in
`-orchestral` (158 files) that ships one instrument playing another's recording. One line in
the generator closes it. Judged this the most serious finding of the pass despite bottle itself
being nearly immune (one file).

**Dead ends worth not repeating.** Four angles came back clean and are recorded in the report
so a later pass does not re-spend them: the family-count oracle survived the FLAC migration
(`inventory.rs:654` counts both containers); licensing correctly excludes CC0 and fails closed
on a mistyped SPDX id; bottle does *not* have the sibling "regeneration leaves the bank stale"
defect because `publish_pending_banks()` runs on every bake path; and the pinned CC0 source
needs no `-text` because it is binary.

**One caveat that changed a recommendation.** I nearly filed "bottle is missing the
`EXPECTED_BYTES` pin that 20 of 24 crates have". Reading `MM-BUG-CRUCIBLE-00039` first showed
that pin encodes the ffmpeg vendor-string length and breaks documented re-bakes — so bottle's
omission is arguably correct, and propagating the pin would have been the wrong advice.

**Possible false positive in the ledger.** `MM-BUG-KILN-00257` (Priority Must) claims the
mandatory Python gate is red on a retired `.wav` lookup. `test_prepare.py:2753` applies
`packaged_name()` before the lookup, so the described failure should not occur. Flagged for
confirmation rather than asserted — I could not run the suite.

## What blocked

`Bash` and `PowerShell` were both denied this session. That meant no `deltic bugs new` /
`deltic reqs new`, so **no ledger records were minted** — four ready-to-mint defects (CR-1,
CR-2, CR-3, CR-9) are fully written up in the CR report but reach no queue. It also meant no
`cargo test`, no `git`, and no byte-level probe: the whole pass is static reading, and the
report labels it as such. A follow-up pass with shell access should mint the four records
first.
