## Decisions and surprises

**The interesting defect was in prose, not code.** The 2026-08-16 WAV→FLAC migration
converted the payload and the runtime, and left the documentation behind. The rustdoc on
`get()` — the crate's *entire* public API — still tells a caller to pass `.wav` names that
return `None`. Twelve crates carry the same two lines. I enumerated the whole set before
writing the ticket, per CLAUDE.md's "enumerate all of L", and the enumeration was the work:
the reported site was one row of twelve.

**I nearly filed a false bug.** `_bake_clavinet` writes `.wav` into a bank directory that
holds `.flac`, which reads as an unfixed retarget miss. It isn't: `write_wav_mono` registers
the directory and `publish_pending_banks` converts, round-trip-verifies and deletes the WAV
at end of run. Reading the generator's second phase before writing the ticket is what saved
it. Two other candidates died the same way (the regen guard normalises both sides through
`packaged_name`; the NOTICE oracle is far stronger than `contains(crate_name)`).

**The devil's advocate demoted one finding and that was correct.** I had "no oracle ties an
embedded file to a zone table" as a fileable gap. It confirmed the gap is real and
unguarded, but also that all eleven clavinet names *do* match today — so it is a systemic
risk, not a live defect. Reported, not ticketed.

**Deliberate non-capture.** `MM-REQ-KILN-00222` already asks for exactly the oracle that
would close finding 3 for this crate, so a new req would have been ledger noise. But
reading it turned up something better: it was raised at 13:45Z on 2026-08-16, about six
hours *before* the banks became FLAC at 20:49 BST, and it now specifies validating "RIFF and
PCM16" structure over "eleven packaged clavinet WAVs". An implementer following it would
build a RIFF oracle for a FLAC bank. I can't edit tracked files this pass, so it's flagged
as Finding 4 for the human. Worth sweeping the sibling per-crate reqs raised before that
timestamp for the same staleness.

**Wider observation, not actioned.** There are ~15 near-identical per-crate "assets must be
independently verifiable" reqs. One generic derived oracle would discharge most of them.
That per-crate proliferation is the same hand-maintained-list pattern CLAUDE.md calls the
repo's recurring defect — but consolidating it is a human's call, not a sixteenth ticket
from me.
