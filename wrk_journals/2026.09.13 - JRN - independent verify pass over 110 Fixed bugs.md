# 2026.09.13 — JRN — Independent verify pass over 110 Fixed bugs

Manual `/loop` verification drain (Claude Opus 5 lead, eight Opus verifier agents), run
alongside a Codex verifier and the fix drain on the same box.

## What was done

- Queue at start: 110 `Fixed` records, every one fixed by `deltic:auto`, so all eligible.
- Full integration gate run once on trunk `8b6a6f86`, then eight verifier agents took
  ~14 bugs each by area, each in its own clean worktree. Per bug: original observation
  re-run or re-derived, regression test selected and green, fails-before by pre-fix bytes
  (method A), a reversed root-cause hunk (method B) or an adversarial input; verdict only.
- The lead claimed every bug with `deltic bugs claim --role verify`, wrote the ledger and
  landed closures on the docs lane in six batches.

## Outcome

- Closed with evidence in each record; three reopened where the original symptom persists
  or the regression does not cover the fix: CRUCIBLE-00037 (archive-boundary guard misses the
  exact recorded escape), KILN-00278 (rustdoc still says 1080 recordings against 1026),
  KILN-00229 (tests stay green with `main()`'s root-cause fix reverted).
- Seven bugs were claimed or closed first by the concurrent Codex verifier and skipped.

## The trunk is red, and every cause is now an Open Must record

The gate on `8b6a6f86` failed clippy (four lints), three Rust tests and one Python test.
Each traced to a fix in this very queue that landed with `gate=manual`, i.e. without the
suite: CRU-00055 (repeat_n), CRU-00057 (link oracle keeps `#fragment`), CRU-00058 (Steinway
legacy aliases vs dedup oracle), CRU-00062 (GM76 test not feature-gated), CRU-00063 (dead
probe without samples), CRU-00064 (clavinet trim vs `banks_parse` floor), CRU-00065
(bake-inventory oracle pins literal loop text); KILN-00278's `filter_next` rides its reopen.

Classification rule used: original defect verified gone but the landing broke a required
gate step -> close and split the gate break to its own record; symptom persists or the
test cannot fail -> reopen the same ID.

## Surprises

- **Manual verifiers on one host are indistinguishable by host.** Codex runs here under the
  same `deltic:manual` principal and `Owner host`, so an apply step keyed on host wrote a
  closure over Codex's claim on CRUCIBLE-00038 (caught as a rebase conflict, resolved by
  keeping its closure). Key ownership on the `Owner run` your own `claim` printed.
- **Claims queue behind landings.** A claim is an ff-push through landing admission: the
  first took 5 minutes, then about one a minute, so 107 claims took ~2 hours. Verification
  ran ahead of claims; verdicts were applied only once the matching claim had landed.
- **`prepare.py --help` starts a real networked bake** (unknown flags are ignored); two
  verifiers hit it. Logged in `scratchpad.md`.
